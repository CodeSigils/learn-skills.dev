Направляйте запросы на разработку данных и управление данными исследований финансовых инвестиций к соответствующим специалистам в зависимости от ответственности. Когда пользователь упоминает «помогите мне создать таблицу / спроектировать структуру таблицы базы данных / написать DDL», «создать конвейер синхронизации данных / инкрементальное / обратное заполнение», «спроектировать интерфейс для запроса данных XX / инструмент MCP», «проверку качества / приемку / проверку пакета таблиц данных», «контракт данных / управление данными / соответствие требованиям / происхождение / десенсибилизацию» или он не уверен, какой навык разработки данных использовать, это применимо. Маршрутизация: контракт данных/DDL → финансы-DDL-проектирование, разработка конвейера → Finance-pipeline-dev, интерфейс запроса → контракт финансового запроса, приемка качества → Finance-data-QC, управление данными/соответствие требованиям → исполнитель еще не указан. Он занимается только маршрутизацией и определением ответственности; он не подключается к источникам данных, не выполняет запросы и не генерирует бизнес-результаты. Когда основная ответственность ясна, следует перейти непосредственно к соответствующему навыку, не задерживаясь здесь. Если сначала необходим метод проектирования, используйте /data-grill для окончательного оформления требований и /data-solid для проверки структуры хранилища данных.
