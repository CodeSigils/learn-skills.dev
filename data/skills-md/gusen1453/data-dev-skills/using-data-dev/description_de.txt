Leiten Sie Engineering- und Governance-Anfragen für Finanzforschungsdaten je nach Verantwortung an die entsprechenden Fähigkeiten weiter. Verwenden Sie dies, wenn der Benutzer „Helfen Sie mir, eine Tabelle zu erstellen / eine Datenbanktabellenstruktur zu entwerfen / DDL zu schreiben“, „eine Datensynchronisierungspipeline erstellen / inkrementell / Backfill erstellen“, „eine Schnittstelle zum Abfragen von XX-Daten / MCP-Tool entwerfen“, „Qualitätsprüfung / Akzeptanz / Überprüfung eines Stapels von Datentabellen“, „Datenvertrag / Datengovernance / Compliance / Abstammung / Desensibilisierung“ erwähnt oder sich nicht sicher ist, welche Datenentwicklungskompetenz er verwenden soll. Routing: Datenvertrag/DDL → Finance-DDL-Design, Pipeline-Entwicklung → Finance-Pipeline-Dev, Abfrageschnittstelle → Finance-Query-Contract, Qualitätsakzeptanz → Finance-Data-QC, Daten-Governance/Compliance → Executor noch nicht bereitgestellt. Es ist nur für die Weiterleitung und Festlegung der Zuständigkeit zuständig; Es stellt keine Verbindung zu Datenquellen her, führt keine Abfragen aus und generiert keine Geschäftsergebnisse. Wenn die Hauptverantwortung klar ist, sollte sie direkt zur entsprechenden Fähigkeit gehen, ohne hier zu bleiben. Wenn zunächst eine Entwurfsmethode benötigt wird, können Sie /data-grill verwenden, um die Anforderungen festzulegen, und /data-solid, um die Data-Warehouse-Struktur zu überprüfen.
