Leiten Sie Anfragen zu Finanzinvestitionsforschung, Datentechnik und Governance je nach Verantwortung an die entsprechenden Fähigkeiten weiter. Wenn ein Benutzer „Helfen Sie mir, eine Tabelle zu erstellen / eine Datenbanktabellenstruktur zu entwerfen / DDL zu schreiben“, „eine Datensynchronisierungspipeline erstellen / inkrementell / Backfill erstellen“, „eine Schnittstelle zum Abfragen von XX-Daten / MCP-Tool entwerfen“, „Qualitätsprüfung / Akzeptanz / Überprüfung eines Stapels von Datentabellen“, „Datenvertrag / Datengovernance / Compliance / Herkunft / Desensibilisierung“ erwähnt oder sich nicht sicher ist, welche Datenentwicklungsfähigkeiten er verwenden soll, trifft dies zu. Routing: Datenvertrag/DDL → Finance-DDL-Design, Pipeline-Entwicklung → Finance-Pipeline-Dev, Abfrageschnittstelle → Finance-Query-Contract, Qualitätsakzeptanz → Finance-Data-QC, Daten-Governance/Compliance → Executor noch nicht bereitgestellt. Es übernimmt lediglich die Routing- und Verantwortlichkeitsbestimmung; Es stellt keine Verbindung zu Datenquellen her, führt keine Abfragen aus und generiert keine Geschäftsergebnisse. Wenn die Hauptverantwortung klar ist, sollte es direkt zur entsprechenden Fähigkeit gehen, ohne hier zu verweilen. Wenn zunächst eine Entwurfsmethode benötigt wird, verwenden Sie /data-grill, um die Anforderungen festzulegen, und /data-solid, um die Data-Warehouse-Struktur zu überprüfen.
