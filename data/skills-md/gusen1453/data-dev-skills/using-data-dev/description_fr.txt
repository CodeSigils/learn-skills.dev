Acheminer les demandes d'ingénierie des données et de gouvernance de la recherche sur les investissements financiers vers la compétence appropriée en fonction de la responsabilité. Lorsqu'un utilisateur mentionne « aidez-moi à créer une table / concevoir une structure de table de base de données / écrire du DDL », « créer un pipeline de synchronisation de données / incrémental / remplissage », « concevoir une interface pour interroger XX données / outil MCP », « inspection qualité / acceptation / examen d'un lot de tables de données », « contrat de données / gouvernance des données / conformité / lignage / désensibilisation » ou ne sait pas quelle compétence de développement de données utiliser, cela s'applique. Routage : contrat de données/DDL → finance-ddl-design, développement de pipeline → finance-pipeline-dev, interface de requête → finance-query-contract, acceptation de la qualité → finance-data-qc, gouvernance/conformité des données → exécuteur non encore fourni. Il gère uniquement le routage et la détermination des responsabilités ; il ne se connecte pas aux sources de données, n'exécute pas de requêtes et ne génère pas de livrables commerciaux. Lorsque la responsabilité première est claire, elle doit aller directement à la compétence correspondante sans s'attarder ici. Si une méthode de conception est nécessaire en premier, utilisez /data-grill pour finaliser les exigences et /data-solid pour examiner la structure de l'entrepôt de données.
