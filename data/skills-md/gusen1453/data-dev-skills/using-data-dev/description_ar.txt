توجيه طلبات هندسة بيانات وأبحاث الاستثمار المالي والحوكمة إلى المهارة المناسبة على أساس المسؤولية. عندما يذكر المستخدم "ساعدني في إنشاء جدول / تصميم هيكل جدول قاعدة البيانات / كتابة DDL"، أو "إنشاء خط أنابيب لمزامنة البيانات / تزايدي / إعادة التعبئة"، أو "تصميم واجهة للاستعلام عن بيانات XX / أداة MCP"، أو "فحص الجودة / القبول / مراجعة مجموعة من جداول البيانات"، أو "عقد البيانات / إدارة البيانات / الامتثال / السلالة / إزالة التحسس"، أو غير متأكد من مهارة تطوير البيانات التي يجب استخدامها، ينطبق هذا. التوجيه: عقد البيانات/DDL → تصميم تمويل-ddl، تطوير خطوط الأنابيب → تطوير خط أنابيب التمويل، واجهة الاستعلام → عقد استعلام التمويل، قبول الجودة → تمويل بيانات مراقبة الجودة، إدارة البيانات/الامتثال → المنفذ لم يتم توفيره بعد. فهو يعالج فقط التوجيه وتحديد المسؤولية؛ ولا يتصل بمصادر البيانات أو ينفذ الاستعلامات أو ينشئ مخرجات الأعمال. عندما تكون المسؤولية الأساسية واضحة، يجب أن تذهب مباشرة إلى المهارة المقابلة دون الإطالة هنا. إذا كانت هناك حاجة إلى طريقة تصميم أولاً، فاستخدم /data-grill لإنهاء المتطلبات و/data-solid لمراجعة هيكل مستودع البيانات.
