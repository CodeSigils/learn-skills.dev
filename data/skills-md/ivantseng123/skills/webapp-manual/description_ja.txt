Web システムの操作マニュアル (操作說明書/操作手冊/ユーザー ガイド) を .docx として最初から構築するか、既存のマニュアルを維持して、ライブ実行中のアプリ上のすべてのページを基盤にして OOXML を直接編集します。ユーザーが Web システムの操作マニュアル / ユーザー ガイド .docx で作業する場合は常に、これを使用します。つまり、新しいマニュアルを作成する (ナビゲーション バーを目次に列挙し、機能の説明、注釈付きスクリーンショット、およびフィールド仕様表を使用して各画面を文書化する)、章を再作成または追加する、古いスクリーンショットを更新する、実際のシステムに対して目次を監査する、またはフィールド / ドロップダウン / メニューのドキュメントをアプリが実際に表示する内容と同期させる場合に使用します。ユーザーが「操作マニュアルを最初から作成する」、「目次としてメニューをリストし、各ページを文書化する」、「マニュアルを更新する」、「セクション X を作り直す」、「目次をシステムと比較する」、「スクリーンショットが古い」、または「この新しいページを文書化する」とだけ言った場合でもトリガーされます。ドキュメントがライブの認証済みシングルページ アプリと一致する必要がある場合はいつでもトリガーされます。ライブ検証とキャプチャにはブラウザの自動化、つまりバンドルされた Playwright スクリプト (Node + `playwright`) またはエージェント内の Playwright MCP が必要です。ライブ検証、スクリーンショットの注釈、およびソースに基づいたコンテンツを追加することで、 document-skills:docx スキル (生の解凍/編集/パックの仕組みを処理する) を補完します。
