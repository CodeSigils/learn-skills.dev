Exécutez et contrôlez l'application d'un utilisateur sur un simulateur iOS/Android distant hébergé sur le cloud EAS. Lisez toujours avant d'exécuter des commandes `eas Simulator:*` — il a la syntaxe actuelle de cette API expérimentale. À utiliser chaque fois que l'utilisateur a besoin d'un simulateur qu'il ne peut pas exécuter localement : "exécuter mon application sur un simulateur cloud", "utiliser le simulateur eas pour exécuter/installer/faire une capture d'écran de mon application", "Je suis sous Linux/Curseur et j'ai besoin d'un appareil iOS", "pas de carte SIM sur cette boîte / CI sans tête", "laisser un agent cliquer sur mon application et en faire une capture d'écran", "tester ma version de développement sur une carte SIM distante avec rechargement en direct", "diffuser l'écran d'une carte SIM vers mon navigateur », même s'ils ne disent pas « EAS Simulator » ou « cloud ». Sur un hôte SANS simulateur local (Linux, CI, cloud sandbox), c'est la valeur par défaut : utilisez-le simplement ; sur macOS, ne déclenchez PAS automatiquement une simple « exécution sur le simulateur » : utilisez-le uniquement pour une simulation cloud/à distance/partageable, une version iOS qui leur manque ou une session pilotée par un agent. PAS pour les simulations locales (expo run :ios, Xcode, Android Studio), la construction/mise à jour EAS, l'aperçu Web ou les appareils physiques.
