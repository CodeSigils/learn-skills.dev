Führen Sie die App eines Benutzers auf einem Remote-iOS/Android-Simulator aus, der in der EAS-Cloud gehostet wird, und steuern Sie sie. Lesen Sie es immer, bevor Sie `eas simulator:*`-Befehle ausführen – es enthält die aktuelle Syntax für diese experimentelle API. Verwenden Sie es immer dann, wenn der Benutzer einen Simulator benötigt, den er nicht lokal ausführen kann – „Führen Sie meine App auf einem Cloud-Simulator aus“, „verwenden Sie den EAS-Simulator zum Ausführen/Installieren/Screenshoten meiner App“, „Ich verwende Linux/Cursor und benötige ein iOS-Gerät“, „Keine Sim auf dieser Box / Headless CI“, „Lassen Sie einen Agenten durch meine App klicken und einen Screenshot machen“, „Testen Sie meinen Entwickler-Build auf einer Remote-Sim mit Live-Neuladen“, „Streamen Sie den Bildschirm einer Sim in meinen Browser“ – selbst wenn Sie sagen nicht „EAS Simulator“ oder „Cloud“. Auf einem Host OHNE lokalen Simulator (Linux, CI, Cloud-Sandbox) ist dies die Standardeinstellung – verwenden Sie sie einfach; Lösen Sie unter macOS NICHT automatisch eine einfache „Ausführung auf dem Simulator“ aus – verwenden Sie es nur für eine Cloud-/Remote-/gemeinsam nutzbare Sim, eine fehlende iOS-Version oder eine agentengesteuerte Sitzung. NICHT für lokale Sims (expo run:ios, Xcode, Android Studio), EAS Build/Update, Webvorschau oder physische Geräte.
