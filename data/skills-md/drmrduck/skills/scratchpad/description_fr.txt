Créez (ou étendez) un bloc-notes / banc de test interne réservé à l'opérateur - une page interne unique qui réutilise les composants réels et les fonctions de bibliothèque du projet afin que vous puissiez juger du travail en cours à l'oeil nu : visuels générés par le globe oculaire (OG/cartes sociales, e-mails, avatars, états vides), comparer les variantes côte à côte ou avec des curseurs en direct, vérifier l'état de préparation de la configuration/de l'environnement et exercer de véritables flux d'effets secondaires avec de fausses données - sans envoyer quoi que ce soit aux utilisateurs ni cliquer sur l'ensemble. produit. Les cartes et les panneaux de configuration disposent d'un bouton « Copier en tant que JSON » afin qu'un résultat ajusté à l'œil nu revienne directement dans le code ou vers un agent pour l'appliquer. S'amorce dans la pile existante de l'utilisateur : détecte les conventions de framework, d'authentification et d'environnement, écrit d'abord une porte d'accès fermée en cas de panne, puis une route avec un commutateur de section ensemencé à partir de son propre code. À utiliser lorsqu'un utilisateur dit "faire tourner un bloc-notes", "banc de test interne / terrain de jeu de développement / page bac à sable", "une page de prévisualisation d'opérateur/administrateur", "une page pour observer mon travail", "prévisualiser mes cartes OG/e-mails/variantes de composants", "ajouter une page de test pour ces composants" ou "une page interne pour exercer un flux avec de fausses données". PAS pour les fonctionnalités publiques / destinées aux utilisateurs, PAS un remplacement pour les tests (réussite/échec vérifiable par machine → écrire un test), PAS un livre d'histoires (cela vit à l'intérieur de la vraie application) et PAS un endroit pour effectuer des opérations de production lourdes.
