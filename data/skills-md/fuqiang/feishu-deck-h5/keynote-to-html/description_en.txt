Convert Apple Keynote (`.key`) presentations into `deck.json` + HTML deck: iterate page by page, reconstruct each page as absolutely positioned HTML—images remain `<img>`, text is editable HTML text, videos are `<video>`. Used together with the `feishu-deck-h5` skill: this skill produces `deck.json`, and `feishu-deck-h5/deck-json/render-deck.py` wraps it into the final HTML with a presentation-mode chrome (← → page turn / F fullscreen / progress bar / mobile scrolling mode).

Trigger phrases: “convert Keynote to HTML”, “import keynote”, “.key to deck”, “.pptx to HTML” (just open the PPTX in Keynote and save as .key), or the user provides a `.key` file path / an already opened document in Keynote.

Processing flow for each page:
  1. AppleScript iterates over all iWork elements on the page, outputting (type, position, size, filename, text, font / font size / color).
  2. Image file references are resolved according to the .key bundle’s Data/ directory: first exact prefix matching; for ambiguous cases like “pasted-image.pdf”, fall back to size / aspect‑ratio matching.
  3. Each non‑text element becomes an `<img>` / `<video>` at its original (x, y, w, h); each text element becomes a real HTML element with the original font and font size.
  4. The page is written into deck.json with `layout: "raw"`.
  5. `feishu-deck-h5/deck-json/render-deck.py` wraps it into HTML with presentation-mode chrome.

Acceptable distortions (do not let them block the process):
  • Custom Keynote fonts (HarmonyOS / Alibaba PuHui / Founder LanTing) fall back to a web‑safe Chinese font stack (PingFang SC, Microsoft YaHei).
  • One or two ambiguous pasted‑image files may be matched to the wrong source — log it and continue.
  • Master‑slide background gradients are not yet parsed (best‑effort).
  • Animations / entrance effects are discarded (by design — HTML does not need them).
