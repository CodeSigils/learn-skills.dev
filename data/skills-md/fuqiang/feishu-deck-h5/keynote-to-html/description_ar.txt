تحويل العروض التقديمية لـ Apple Keynote ‏(`.key`) إلى `deck.json` + مجموعة HTML: كرر صفحة تلو الأخرى، وأعد بناء كل صفحة باعتبارها HTML ذات موضع مطلق - تظل الصور `<img>`، والنص هو نص HTML قابل للتحرير، ومقاطع الفيديو هي `<video>`. تستخدم مع مهارة `feishu-deck-h5`: تنتج هذه المهارة `deck.json`، ويقوم `feishu-deck-h5/deck-json/render-deck.py` بتغليفها في HTML النهائي باستخدام chrome في وضع العرض التقديمي (← → قلب الصفحة / F ملء الشاشة / شريط التقدم / وضع التمرير المحمول).

عبارات التشغيل: "تحويل Keynote إلى HTML"، أو "استيراد الكلمة الرئيسية"، أو ".key tock"، أو ".pptx إلى HTML" (فقط افتح PPTX في Keynote واحفظه كـ .key)، أو يوفر المستخدم مسار ملف ".key" / مستند مفتوح بالفعل في Keynote.

تدفق المعالجة لكل صفحة:
  1. يتكرر AppleScript على جميع عناصر iWork الموجودة في الصفحة، ويخرج (النوع والموضع والحجم واسم الملف والنص والخط / حجم الخط / اللون).
  2. يتم حل مراجع ملفات الصور وفقًا لدليل البيانات/ الخاص بحزمة المفاتيح.: أول مطابقة تامة للبادئة؛ بالنسبة للحالات الغامضة مثل "pasted-image.pdf"، ارجع إلى مطابقة الحجم/نسبة العرض إلى الارتفاع.
  3. يصبح كل عنصر غير نصي `<img>` / `<video>` في أصله (x, y, w, h); يصبح كل عنصر نص عنصر HTML حقيقي بالخط الأصلي وحجم الخط.
  4. تتم كتابة الصفحة في Deck.json باستخدام `التخطيط: "خام".
  5. يقوم `feishu-deck-h5/deck-json/render-deck.py` بتحويله إلى HTML باستخدام وضع العرض التقديمي chrome.

التشوهات المقبولة (لا تدعها تعيق العملية):
  • تعود خطوط Keynote المخصصة (HarmonyOS / Alibaba PuHui / Founder LanTing) إلى مجموعة الخطوط الصينية الآمنة على الويب (PingFang SC، وMicrosoft YaHei).
  • قد يكون هناك ملف واحد أو اثنين من ملفات الصور الملصقة الغامضة متطابقة مع مصدر خاطئ - قم بتسجيله وتابع.
  • لم يتم بعد تحليل تدرجات خلفية الشريحة الرئيسية (أفضل جهد).
  • يتم تجاهل الرسوم المتحركة / تأثيرات الدخول (حسب التصميم — لا يحتاج HTML إليها).
