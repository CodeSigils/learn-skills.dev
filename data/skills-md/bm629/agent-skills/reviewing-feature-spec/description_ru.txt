Используйте при просмотре или оценке готовой спецификации функции, чтобы решить, могут ли инженеры планировать и строить на ее основе — ворота приемки, а не разработки. Спецификация функции — это уровень ниже PRD — она описывает, как ведет себя каждая функция, достаточно подробно для создания и тестирования. Оценивает его по шкале реализуемости + тестируемости: каждая функция соответствует потребностям восходящего PRD (нет сирот, нет пробелов в охвате), поведение однозначно и наблюдаемо, входы/выходы/состояния полны, каждый крайний случай называет ожидаемый ответ, критерии приемки поддаются независимому тестированию (Дано/Когда/Тогда или на основе правил), и всплывают открытые вопросы. Выдает именно «ВЕРДИКТ: утвердить|пересмотреть» плюс выводы, требующие принятия мер (неудачное условие + способы исправления). Утверждает спецификацию, соответствующую планке (без ложных изменений), и вносит изменения только в случае реального, названного пробела. Ни для создания спецификации, ни для восходящего PRD (используйте навыки проверки PRD), ни для документов инженерного проектирования, таких как ADR/RFC (используйте проверку дизайна), ни для других типов документов.
