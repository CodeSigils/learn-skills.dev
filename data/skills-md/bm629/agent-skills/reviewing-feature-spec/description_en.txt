Use when reviewing or judging a finished feature specification to decide whether engineering can plan and build from it — an acceptance gate, not authoring. The feature spec is the layer below the PRD — it says how each feature behaves, in enough detail to build and test. Judges it against an implementability + testability bar: every feature traces to an upstream PRD need (no orphans, no coverage gaps), behavior is unambiguous and observable, inputs/outputs/states are complete, every edge case names its expected response, acceptance criteria are independently testable (Given/When/Then or rule-based), and open questions are surfaced. Emits exactly `VERDICT: approve|revise` plus actionable findings (failed condition + how to fix). Approves a spec that meets the bar (no false-revise) and revises only on a real, named gap. Not for authoring a spec, not for the upstream PRD (use a PRD-review skill), not for engineering design docs like ADRs/RFCs (use design-review), and not for other document types.
