完成した機能仕様をレビューまたは判断するときに使用して、エンジニアリングがそれに基づいて計画および構築できるかどうかを判断します。これは、作成ではなく承認ゲートです。機能仕様は PRD の下のレイヤーです。機能仕様には、各機能がどのように動作するかが、構築してテストできるほど詳細に記載されています。実装可能性 + テスト可能性の基準に照らして判断します。すべての機能が上流の PRD のニーズをトレースし (孤立がなく、カバレッジ ギャップがない)、動作が曖昧でなく観察可能で、入力/出力/状態が完全で、すべてのエッジ ケースに予想される応答の名前が付けられ、受け入れ基準が独立してテスト可能 (指定/いつ/その後、またはルール ベース)、未解決の疑問が表面化します。正確に「評決: 承認|改訂」と実用的な結果 (失敗した条件 + 修正方法) を出力します。基準を満たす仕様を承認し (誤った改訂はしない)、実際の名前付きギャップにのみ改訂します。仕様の作成、上流の PRD (PRD レビュー スキルを使用)、ADR/RFC などのエンジニアリング設計ドキュメント (デザイン レビューの使用)、およびその他の種類のドキュメントには使用できません。
