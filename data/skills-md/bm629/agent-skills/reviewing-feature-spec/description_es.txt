Úselo al revisar o juzgar una especificación de característica terminada para decidir si la ingeniería puede planificar y construir a partir de ella: una puerta de aceptación, no una creación. La especificación de característica es la capa debajo del PRD: dice cómo se comporta cada característica, con suficiente detalle para construirla y probarla. Lo juzga en función de una barra de implementabilidad + comprobabilidad: cada característica se remonta a una necesidad PRD ascendente (sin huérfanos, sin brechas de cobertura), el comportamiento es inequívoco y observable, las entradas/salidas/estados están completos, cada caso límite nombra su respuesta esperada, los criterios de aceptación son comprobables de forma independiente (Dado/Cuándo/Entonces o basados ​​en reglas) y surgen preguntas abiertas. Emite exactamente "VEREDICTO: aprobar|revisar" más resultados procesables (condición fallida + cómo solucionarlo). Aprueba una especificación que cumple con el estándar (sin revisión falsa) y revisa solo una brecha real con nombre. No para crear una especificación, no para el PRD ascendente (use una habilidad de revisión de PRD), no para documentos de diseño de ingeniería como ADR/RFC (use revisión de diseño) y no para otros tipos de documentos.
