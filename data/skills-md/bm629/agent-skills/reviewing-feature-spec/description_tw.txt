在審查或判斷已完成的功能規格時使用，以決定工程是否可以根據它進行規劃和建造 - 驗收門，而不是創作。功能規格是 PRD 之下的一層——它描述了每個功能的行為方式，並提供足夠詳細的資訊以供建置和測試。根據可實施性+可測試性欄來判斷：每個功能都追蹤上游 PRD 需求（沒有孤兒，沒有覆蓋差距），行為明確且可觀察，輸入/輸出/狀態完整，每個邊緣案例命名其預期響應，驗收標準可獨立測試（給定/何時/然後或基於規則），並且開放問題浮出水面。準確發出“VERDICT：批准|修訂”加上可操作的結果（失敗的情況+如何修復）。批准符合標準的規範（無錯誤修訂），並且僅針對真實的、指定的差距進行修訂。不適用於編寫規範，不適用於上游 PRD（使用 PRD 審核技能），不適用於 ADR/RFC 等工程設計文件（使用設計審核），不適用於其他文件類型。
