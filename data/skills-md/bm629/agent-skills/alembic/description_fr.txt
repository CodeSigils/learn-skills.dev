À utiliser lors de l'exécution de migrations de bases de données Alembic au-dessus d'une couche de données SQLAlchemy 2.x qui cible plusieurs dialectes (SQLite, PostgreSQL et MySQL) à partir d'un seul historique de migration. Couvre le câblage env.py / alembic.ini vers Base.metadata de vos modèles (obtention de l'URL de base de données à partir de l'environnement, synchronisation d'abord avec une courte note asynchrone run_async_migrations), la révision complète -> génération automatique -> révision -> flux de travail de mise à niveau/rétrogradation, le branchement (historique/actuel/têtes/fusion pour plusieurs têtes) et le piège multidialecte porteur : SQLite ne peut pas MODIFIER la plupart des schémas, alors écrivez les migrations dans BATCH style (déplacer et copier) — le même code batch_alter_table émet un ALTER simple sur PG/MySQL. Possède également la décision create_all-vs-Alembic et le chemin du tampon de base à partir d'une base de données create_all'd. Multi-dialecte, portable, synchronisé d'abord. Pas de création de modèle/moteur SQLAlchemy (voir sqlalchemy), pas de modèles de file d'attente/de bail (voir sql-job-queue).
