Verwenden Sie diese Option, wenn Sie Alembic-Datenbankmigrationen auf einer SQLAlchemy 2.x-Datenschicht ausführen, die auf mehr als einen Dialekt – SQLite, PostgreSQL und MySQL – aus einem einzigen Migrationsverlauf abzielt. Behandelt die Verbindung von env.py/alembic.ini mit den Base.metadata Ihrer Modelle (Beziehen der DB-URL aus der Umgebung, sync-first mit einem kurzen asynchronen run_async_migrations-Hinweis), die vollständige Revision -> automatische Generierung -> Überprüfung -> Upgrade-/Downgrade-Workflow, Verzweigung (Verlauf/aktuell/Köpfe/Zusammenführung für mehrere Köpfe) und das tragende Problem mit mehreren Dialekten: SQLite kann die meisten Schemata nicht ÄNDERN, also schreiben Sie Migrationen in BATCH (Verschieben-und-Kopieren)-Stil – derselbe Batch_alter_table-Code gibt einfaches ALTER auf PG/MySQL aus. Besitzt außerdem die Entscheidung „create_all-vs-Alembic“ und den Baseline-Stamp-Pfad einer „create_all“-Datenbank. Multi-Dialekt, tragbar, Sync-First. Keine SQLAlchemy-Modell-/Engine-Erstellung (siehe SQLalchemy), keine Job-Warteschlangen-/Lease-Muster (siehe SQL-Job-Warteschlange).
