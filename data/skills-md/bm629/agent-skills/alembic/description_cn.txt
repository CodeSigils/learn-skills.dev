当在 SQLAlchemy 2.x 数据层之上运行 Alembic 数据库迁移时使用，该数据层针对单个迁移历史记录中的多种方言（SQLite、PostgreSQL 和 MySQL）。涵盖将 env.py / alembic.ini 连接到模型的 Base.metadata （从环境中获取数据库 URL，使用简短的异步 run_async_migrations 注释同步优先）、完整修订版 -> 自动生成 -> 审查 -> 升级/降级工作流程、分支（多个头的历史/当前/头/合并）以及承载多方言陷阱：SQLite 无法更改大多数模式，因此在 BATCH 中编写迁移（移动和复制）风格——相同的batch_alter_table代码在PG/MySQL上发出简单的ALTER。还拥有 create_all-vs-Alembic 决策和 create_all'd 数据库的基线标记路径。多方言、便携、同步优先。不是 SQLAlchemy 模型/引擎创作（请参阅 sqlalchemy），也不是作业队列/租赁模式（请参阅 sql-job-queue）。
