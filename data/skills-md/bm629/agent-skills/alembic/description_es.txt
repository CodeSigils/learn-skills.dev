Úselo cuando ejecute migraciones de bases de datos de Alembic sobre una capa de datos SQLAlchemy 2.x que apunta a más de un dialecto (SQLite, PostgreSQL y MySQL) desde un único historial de migración. Cubre el cableado de env.py/alembic.ini a los Base.metadata de sus modelos (obteniendo la URL de la base de datos del entorno, sincronización primero con una breve nota asíncrona run_async_migrations), la revisión completa -> generación automática -> revisión -> flujo de trabajo de actualización/degradación, bifurcación (historial/actual/cabezas/fusión para múltiples cabezas) y el problema multidialecto de carga: SQLite no puede ALTERAR la mayoría de los esquemas, así que escriba las migraciones en BATCH Estilo (mover y copiar): el mismo código batch_alter_table emite ALTER simple en PG/MySQL. También posee la decisión create_all-vs-Alembic y la ruta del sello de línea base de una base de datos create_all. Multidialecto, portátil, sincronización primero. No es la creación de modelos/motores de SQLAlchemy (ver sqlalchemy), ni los patrones de cola de trabajos/arrendamiento (ver sql-job-queue).
