يُستخدم عند تشغيل عمليات ترحيل قاعدة بيانات Alembic أعلى طبقة بيانات SQLAlchemy 2.x التي تستهدف أكثر من لهجة واحدة - SQLite، وPostgreSQL، وMySQL - من سجل ترحيل واحد. يغطي توصيل env.py / alembic.ini إلى Base.metadata لنماذجك (مصدر عنوان URL لقاعدة البيانات من البيئة، والمزامنة أولاً مع ملاحظة قصيرة غير متزامنة run_async_migrations)، والمراجعة الكاملة -> الإنشاء التلقائي -> المراجعة -> سير العمل الترقية/الرجوع إلى إصدار سابق، والتفرع (التاريخ / التيار / الرؤوس / الدمج لرؤوس متعددة)، ومسكتك متعددة اللهجات الحاملة: لا يمكن لـ SQLite تغيير معظم المخططات، لذلك كتابة عمليات الترحيل بأسلوب BATCH (النقل والنسخ) - نفس كود Batch_alter_table يصدر ALTER عاديًا على PG/MySQL. يمتلك أيضًا قرار create_all-vs-Alembic ومسار الطابع الأساسي من قاعدة بيانات create_all'd. متعدد اللهجات، محمول، متزامن أولاً. ليس نموذج SQLAlchemy/تأليف المحرك (انظر sqlalchemy)، وليس أنماط قائمة انتظار المهام/التأجير (راجع قائمة انتظار المهام SQL).
