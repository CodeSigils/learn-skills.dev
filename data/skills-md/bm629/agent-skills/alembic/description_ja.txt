単一の移行履歴から複数の言語 (SQLite、PostgreSQL、MySQL) をターゲットとする SQLAlchemy 2.x データ レイヤー上で Alembic データベース移行を実行する場合に使用します。 env.py / alembic.ini をモデルの Base.metadata に接続する方法 (環境から DB URL を取得し、短い非同期 run_async_migrations メモを使用して最初に同期)、完全なリビジョン -> 自動生成 -> レビュー -> アップグレード/ダウングレードのワークフロー、分岐 (履歴 / 現在 / ヘッド / 複数のヘッドのマージ)、および負荷のかかる複数の方言の落とし穴: SQLite ではほとんどの ALTER を実行できないことについて説明します。スキーマを使用するため、移行は BATCH (移動とコピー) スタイルで記述します。同じ batch_alter_table コードが PG/MySQL 上でプレーンな ALTER を発行します。また、create_all-vs-Alembic の決定と、create_all の DB からのベースライン スタンプ パスも所有します。複数の方言、ポータブル、同期優先。 SQLAlchemy モデル/エンジン オーサリング (sqlalchemy を参照) ではなく、ジョブキュー/リース パターン (sql-job-queue を参照) ではありません。
