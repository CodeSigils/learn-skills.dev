Используйте при выполнении миграции базы данных Alembic поверх уровня данных SQLAlchemy 2.x, который ориентирован на более чем один диалект — SQLite, PostgreSQL и MySQL — из одной истории миграции. Охватывает подключение env.py / alembic.ini к Base.metadata вашей модели (источник URL-адреса базы данных из среды, первая синхронизация с коротким асинхронным примечанием run_async_migrations), полная версия -> автогенерация -> обзор -> рабочий процесс обновления/понижения, ветвление (история / текущие / головы / слияние для нескольких голов) и несущая нагрузку многодиалектная ошибка: SQLite не может ИЗМЕНИТЬ большую часть схемы, поэтому пишите миграции в ПАКЕТЕ. (перемещение и копирование) — тот же код patch_alter_table выдает простой ALTER в PG/MySQL. Также владеет решением create_all-vs-Alembic и путем базовой отметки от базы данных create_all'd. Многодиалектный, портативный, с приоритетом синхронизации. Не создание модели/движка SQLAlchemy (см. sqlalchemy), а не шаблоны очереди заданий/аренды (см. sql-job-queue).
