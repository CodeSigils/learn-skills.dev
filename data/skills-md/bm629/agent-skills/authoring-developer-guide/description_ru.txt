Используйте при создании или изменении документации по инструментам разработчика — описание внедрения и интеграции для SDK, библиотеки, интерфейса командной строки, платформы или платформы API: руководство, которое разработчик читает для установки, интеграции и эксплуатации инструмента. Направляет МЕТОД, а не схему: ЦЕЛИ разработчика, а не конечные точки; обозначенное начало здесь + быстрый и поддающийся проверке первый успех; концепции важнее рецептов; работоспособные рецепты с названием цели; сквозное руководство; обоснованные лучшие практики; путь устранения неполадок; акцент на учете архетипов (API/SDK/CLI/framework); УКАЗАНИЯ на ссылку API — никогда не на копию; и изменение руководства в виде дельта-версии, которая учитывает изменения инструмента для устаревших образцов. Полный диатаксис набран правильно, каждый образец работоспособен + с точностью до инструмента, ничего не сфабриковано. Составляет с помощью шаблонного инструмента + глубокие исследования. Потребляет переданную спецификацию функции + ссылку на API + PRD — никогда не оставляет пустую страницу. Не каталог справок по API, руководство пользователя для конечного пользователя, инженерную документацию или ее обзор.
