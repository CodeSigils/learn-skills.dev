À utiliser lors de la création ou de la modification de la documentation de l'outil de développement : le récit d'adoption et d'intégration pour un SDK, une bibliothèque, une CLI, un framework ou une plate-forme API : le guide qu'un développeur lit pour installer, intégrer et utiliser l'outil. Guide la MÉTHODE, pas les grandes lignes : les OBJECTIFS du développeur et non les points finaux ; un départ balisé ici + un premier succès rapide et vérifiable ; les concepts avant les recettes ; recettes exécutables nommées par objectif ; un tutoriel de bout en bout ; les meilleures pratiques fondées ; un chemin de dépannage ; accentuation de la prise en compte des archétypes (API/SDK/CLI/framework) ; POINTEURS vers - jamais une copie de - la référence API ; et modifier un guide en tant que delta versionné qui balaie les modifications de l'outil pour les échantillons obsolètes. Diataxie complète correctement typée, chaque échantillon exécutable + précis pour l'outil, rien de fabriqué. Compose avec un outil de modèle + recherche approfondie. Consomme la spécification de fonctionnalité remise + la référence api + PRD – jamais une page vierge. Pas le catalogue de référence de l'API, le guide de l'utilisateur final, les documents d'ingénierie ou leur révision.
