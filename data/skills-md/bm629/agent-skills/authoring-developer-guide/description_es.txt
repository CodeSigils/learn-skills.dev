Úselo al crear o modificar la documentación de la herramienta para desarrolladores: la narrativa de adopción + integración para un SDK, biblioteca, CLI, marco o plataforma API: la guía que lee un desarrollador para instalar, integrar y operar la herramienta. Guía el MÉTODO, no el esquema: METAS del desarrollador, no puntos finales; un inicio-aquí señalizado + un primer éxito rápido y verificable; conceptos antes que recetas; recetas ejecutables con nombres de objetivos; un tutorial de principio a fin; mejores prácticas fundamentadas; una ruta de solución de problemas; énfasis en el arquetipo (API/SDK/CLI/framework); PUNTEROS hacia (nunca una copia) de la referencia de API; y modificar una guía como un delta versionado que barre los cambios de la herramienta en busca de muestras obsoletas. Diataxis completa escrita correctamente, cada muestra ejecutable + precisa para la herramienta, nada fabricado. Redacta con una herramienta de plantilla + investigación profunda. Consume la especificación de característica entregada + referencia de API + PRD, nunca una página en blanco. No el catálogo de referencia de API, la guía del usuario final, los documentos de ingeniería ni la revisión de uno.
