Úselo al crear una guía para el usuario final: la ayuda orientada al consumidor que la persona (generalmente no técnica) que USA un producto lee para lograr sus objetivos: un tutorial de introducción, guías prácticas orientadas a tareas, explicación conceptual, una referencia de configuración/funciones para el usuario final (funciones, configuraciones, comandos CLI, no la API HTTP) y solución de problemas/Preguntas frecuentes. Guía el MÉTODO, no el esquema: derivar un procedimiento por objetivo de usuario a partir de los pasos previos entregados (nunca inventar pasos), mantener distintos los cuatro modos de Diataxis y mantener cada paso preciso para el comportamiento real del producto. Se compone de una herramienta de plantilla de guía de usuario separada (que proporciona la estructura de la sección) y una capacidad de investigación. Asume los documentos anteriores entregados (normalmente una especificación de características + flujos de usuario + estructuras alámbricas), nunca una página en blanco. No para la narrativa de adopción de herramientas para desarrolladores (una guía para desarrolladores separada), no para el catálogo de puntos finales HTTP/SDK (una referencia de API separada) y no para revisar una guía de usuario terminada.
