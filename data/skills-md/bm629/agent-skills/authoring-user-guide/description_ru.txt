Используйте при написании руководства для конечного пользователя — ориентированная на потребителя помощь (обычно нетехнического) человека, ИСПОЛЬЗУЮЩЕГО продукт, который читает для достижения своих целей: руководство по началу работы, ориентированные на задачи практические руководства, концептуальные объяснения, справочник по функциям/конфигурациям для конечного пользователя (функции, настройки, команды CLI, а не HTTP API) и устранение неполадок/часто задаваемые вопросы. Направляет МЕТОД, а не схему: выводит одно практическое руководство для каждого пользователя на основе переданных восходящих потоков (никогда не изобретая шаги), сохраняя различие между четырьмя режимами Диатаксиса и обеспечивая точность каждого шага в соответствии с фактическим поведением продукта. Состоит из отдельного инструмента шаблона руководства пользователя (который обеспечивает структуру разделов) и возможностей исследования. Предполагается, что исходная документация (обычно спецификация функций + пользовательские потоки + каркасы) — никогда не пустая страница. Ни для рассказа о внедрении инструментов разработчика (отдельное руководство для разработчиков), ни для каталога конечных точек HTTP/SDK (отдельный справочник по API), ни для обзора готового руководства пользователя.
