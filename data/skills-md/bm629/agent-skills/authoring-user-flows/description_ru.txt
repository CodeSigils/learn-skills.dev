Используйте при создании документа пользовательских потоков — карту путей, которые пользователь проходит через продукт для достижения каждой цели: точки входа, счастливый путь, ветви решений, пути ошибок/восстановления, пройденные экраны/состояния и критерии успеха, каждый поток прослеживается до цели/персонажа продукта. Направляет МЕТОД, а не схему: выводит потоки из вышестоящих целей + персон (никогда их не изобретая), перечисляя все ветки и пути ошибок, чтобы путь не заходил в тупик, и визуализируя каждый поток как синхронизированную диаграмму + пронумерованное повествование. Состоит из отдельного инструмента шаблонов пользовательских потоков (который обеспечивает структуру разделов) и возможностей исследования. Предполагается, что в качестве входных данных используется утвержденный PRD, а не пустая страница. Не для проверки готового документа о пользовательских потоках, не для макета экрана/каркасов и не для создания самого PRD.
