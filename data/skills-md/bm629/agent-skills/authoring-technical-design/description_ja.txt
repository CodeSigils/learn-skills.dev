1 つの機能またはコンポーネント (既存のシステム内に構築するための詳細な実装設計) の技術設計文書 (TDD / エンジニアリング設計文書 / 設計 RFC) を作成 (または修正) するときに使用します。概要ではなく方法を通してプロデューサーをガイドします。確立された設計文書の実践とプロジェクトの実際の制約に基づいて設計を基礎にし、要件に合わせてすべての決定を双方向に追跡し、少なくとも 1 つの実際の (ストローマンではない) 代替案を規定の決定基準と比較し、アーキテクチャ文書 / API 仕様 / データモデルを複製するのではなく参照し、障害モード、可観測性シグナル、テスト、およびロールアウトに名前を付け、承認された設計を修正します。バージョン管理され、リップル分析されたデルタ — エンジニアが設計を再導出することなく機能を実装できるバーまで。個別の技術設計テンプレート ツール (セクション構造) と詳細な調査機能で構成されます。承認された PRD + 機能仕様をアップストリーム入力として想定します。決して空白ページではありません。システム全体のアーキテクチャ、API コントラクトやデータ スキーマ、完成した TDD のレビューのためではありません。
