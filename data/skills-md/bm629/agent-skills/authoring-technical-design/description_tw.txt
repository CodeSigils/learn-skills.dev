在為某個功能或元件編寫（或修改）技術設計文件（TDD/工程設計文件/設計 RFC）時使用 - 在現有系統中建構它的詳細實現設計。指導生產者通過方法，而不是大綱：將設計植根於既定的設計文檔實踐和項目的實際約束，雙向跟踪每個決策到需求，將至少一個真實的（非稻草人）替代方案與規定的決策標準進行比較，引用架構文檔/API規範/數據模型而不是重複它們，命名故障模式，可觀察性信號，測試和推出 - 增量已批准的設計版本——在增量的情況下可以實現修改由單獨的技術設計模板工具（剖面結構）和深度研究能力組成。假設已核准的 PRD + 功能規格作為上游輸入 - 絕不是空白頁。不適用於系統範圍的架構，不適用於 API 合約或資料模式，也不適用於審查已完成的 TDD。
