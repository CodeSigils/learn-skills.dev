하나의 기능이나 구성요소(기존 시스템 내에서 이를 구축하기 위한 세부 구현 설계)에 대한 기술 설계 문서(TDD/엔지니어링 설계 문서/설계 RFC)를 작성(또는 수정)할 때 사용합니다. 개요가 아닌 방법을 통해 생산자를 안내합니다. 확립된 디자인 문서 관행과 프로젝트의 실제 제약 조건에 디자인을 기반으로 하고, 모든 결정을 요구사항에 대해 양방향으로 추적하고, 적어도 하나의 실제(비스트로맨) 대안을 명시된 결정 기준과 비교하고, 아키텍처 문서/API 사양/데이터 모델을 복제하는 대신 참조하고, 실패 모드, 관찰 가능성 신호, 테스트 및 롤아웃의 이름을 지정하고, 승인된 디자인을 다음과 같이 수정합니다. 버전이 지정되고 리플 분석된 델타 - 엔지니어가 설계를 다시 파생하지 않고도 기능을 구현할 수 있는 막대로 변환됩니다. 별도의 기술설계 템플릿툴(섹션구조)과 심층적인 연구능력으로 구성됩니다. 승인된 PRD + 기능 사양을 업스트림 입력으로 가정하며 결코 빈 페이지가 아닙니다. 시스템 전체 아키텍처, API 계약 또는 데이터 스키마, 완성된 TDD 검토용이 아닙니다.
