À utiliser lors de la création (ou de la modification) d'un document de conception technique (un document TDD / conception technique / RFC de conception) pour une fonctionnalité ou un composant - la conception de mise en œuvre détaillée pour sa construction dans un système existant. Guide le producteur à travers la MÉTHODE, et non les grandes lignes : fonder la conception sur la pratique établie du document de conception et les contraintes réelles du projet, tracer chaque décision de manière bidirectionnelle vers une exigence, comparer au moins une alternative réelle (non-homme de paille) avec un critère de décision déclaré, référencer le document d'architecture / la spécification API / le modèle de données plutôt que de les dupliquer, nommer les modes de défaillance, les signaux d'observabilité, les tests et le déploiement - et modifier une conception approuvée en version versionnée, Delta analysé par ondulation - jusqu'à une barre où un ingénieur peut implémenter la fonctionnalité sans re-dériver la conception. Compose avec un outil de modèle de conception technique distinct (structure de section) et une capacité de recherche approfondie. Suppose la spécification de fonctionnalité PRD + approuvée comme entrée en amont – jamais une page vierge. Pas pour l'architecture à l'échelle du système, ni pour le contrat API ou le schéma de données, ni pour la révision d'un TDD terminé.
