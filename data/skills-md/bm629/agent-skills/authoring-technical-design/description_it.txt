Da utilizzare quando si crea (o si modifica) un documento di progettazione tecnica (un TDD/documento di progettazione tecnica/RFC di progettazione) per una funzionalità o componente: il progetto di implementazione dettagliato per costruirlo all'interno di un sistema esistente. Guida il produttore attraverso il METODO, non lo schema: basando il progetto sulla pratica consolidata della documentazione di progettazione e sui vincoli reali del progetto, riconducendo ogni decisione bidirezionalmente a un requisito, confrontando almeno un'alternativa reale (non di paglia) con un criterio decisionale dichiarato, facendo riferimento alla documentazione dell'architettura / alle specifiche API / al modello di dati piuttosto che duplicarli, nominando le modalità di guasto, i segnali di osservabilità, i test e il lancio - e modificando un progetto approvato come una versione, delta con analisi dell'ondulazione: a una barra in cui un ingegnere può implementare la funzionalità senza ridirigere il progetto. Si compone con uno strumento di modello di progettazione tecnica separato (struttura di sezione) e una capacità di ricerca approfondita. Presuppone il PRD + le specifiche delle funzionalità approvate come input upstream, mai una pagina vuota. Non per l'architettura a livello di sistema, non per il contratto API o lo schema dei dati e non per la revisione di un TDD finito.
