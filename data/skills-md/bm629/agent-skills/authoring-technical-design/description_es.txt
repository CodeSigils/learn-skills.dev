Úselo al crear (o modificar) un documento de diseño técnico (un TDD / documento de diseño de ingeniería / RFC de diseño) para una característica o componente: el diseño de implementación detallado para construirlo dentro de un sistema existente. Guía al productor a través del MÉTODO, no del esquema: fundamentar el diseño en la práctica establecida del documento de diseño y las limitaciones reales del proyecto, rastrear cada decisión bidireccionalmente hasta un requisito, comparar al menos una alternativa real (no de paja) con un criterio de decisión establecido, hacer referencia al documento de arquitectura / especificación API / modelo de datos en lugar de duplicarlos, nombrar los modos de falla, las señales de observabilidad, las pruebas y la implementación, y modificar un diseño aprobado como versionado. delta analizado por ondulación: a una barra donde un ingeniero puede implementar la función sin volver a derivar el diseño. Se compone de una herramienta de plantilla de diseño técnico independiente (estructura de secciones) y una capacidad de investigación profunda. Asume la especificación de función PRD + aprobada como entrada ascendente, nunca una página en blanco. No para la arquitectura de todo el sistema, ni para el contrato API o el esquema de datos, ni para revisar un TDD terminado.
