Используется при создании (или внесении изменений) в документ технического проекта (TDD/документ инженерного проектирования/проект RFC) для одной функции или компонента — детальный проект реализации для его построения в существующей системе. Направляет производителя через МЕТОД, а не схему: основывает проект на устоявшейся практике проектной документации и реальных ограничениях проекта, двунаправленно отслеживает каждое решение до требования, сравнивает по крайней мере одну реальную (нестандартную) альтернативу с установленным критерием решения, ссылается на архитектурный документ / спецификацию API / модель данных, а не дублирует их, называет режимы отказа, сигналы наблюдаемости, тестирование и развертывание - и вносит поправки в утвержденный проект как дельта с версионированием и анализом пульсаций — до панели, где инженер может реализовать функцию без повторной разработки проекта. Состоит из отдельного инструмента шаблонов технического проектирования (структура разделов) и возможностей глубокого исследования. Предполагается, что утвержденная спецификация функций PRD + в качестве входных данных — никогда не пустая страница. Ни для общесистемной архитектуры, ни для контракта API или схемы данных, ни для проверки готового TDD.
