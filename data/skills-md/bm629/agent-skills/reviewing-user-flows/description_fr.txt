À utiliser lors de l'examen/de l'évaluation d'un document de flux d'utilisateurs terminé pour décider si une passe de wireframing en aval peut énumérer tous les écrans de celui-ci - une porte d'acceptation, pas de création. Un document sur les flux d'utilisateurs est le graphique de navigation/interaction : les chemins qu'un utilisateur emprunte pour atteindre chaque objectif, avec les points d'entrée, les branches de décision, les chemins d'erreur/récupération et les écrans traversés. Le juge par rapport à une barre d'exhaustivité + de possibilité de marche : chaque objectif/personne PRD correspond à un flux (pas d'orphelins), chaque flux a une entrée + une sortie définie, chaque branche se résout, chaque état d'erreur a une récupération (pas d'impasse), les étapes sont praticables, le diagramme Sirène et le récit numéroté restent synchronisés, et l'index des écrans est énumérable. Émet exactement « VERDICT : approuver | réviser » avec des résultats exploitables (condition d'échec + correctif). Approuve un document répondant à la barre (pas de fausse révision), révise uniquement sur une lacune nommée. Pas pour la création d'un document de flux d'utilisateurs, pas pour la disposition d'écran/les wireframes (utilisez une compétence de révision de wireframes), pas pour le PRD en amont (utilisez une compétence de révision de PRD).
