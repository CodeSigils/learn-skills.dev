Úselo al revisar/juzgar un documento de flujos de usuarios terminado para decidir si un paso posterior de estructura alámbrica puede enumerar todas las pantallas del mismo: una puerta de aceptación, no una autoría. Un documento de flujos de usuario es el gráfico de navegación/interacción: las rutas que sigue un usuario para lograr cada objetivo, con puntos de entrada, ramas de decisión, rutas de error/recuperación y pantallas atravesadas. Lo juzga en función de una barra de integridad + caminabilidad: cada objetivo/persona del PRD se asigna a un flujo (sin huérfanos), cada flujo tiene una entrada + salida definida, cada rama se resuelve, cada estado de error tiene una recuperación (sin callejones sin salida), los pasos son transitables, el diagrama de sirena y la narrativa numerada permanecen sincronizados, y el índice de pantallas es enumerable. Emite exactamente "VEREDICTO: aprobar|revisar" con resultados procesables (condición fallida + solución). Aprueba un documento que cumple con los requisitos (sin revisión falsa), revisa solo una brecha nombrada. No para crear un documento de flujos de usuario, no para diseño de pantalla/estructuras alámbricas (use una habilidad de revisión de estructuras alámbricas), no para el PRD ascendente (use una habilidad de revisión de PRD).
