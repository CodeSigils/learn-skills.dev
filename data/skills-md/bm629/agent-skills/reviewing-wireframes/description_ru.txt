Используйте при просмотре/оценке готового (или измененного) документа с каркасами — ворота приемки: могут ли последующие инженеры Hi-Fi + пользовательского интерфейса построить на его основе структуру экрана. Сравнивает каркас TEXTUAL markdown с возможностью сборки из одного источника + покрытие + панель композиции: каждый экран/состояние с именем потока покрыто состояниями качества; однозначный макет в сетке + общая оболочка приложения, соответствующая объективной шкале качества макета; реальные + непротиворечивые компоненты; возможности + отображение данных с аннотациями; цель микрокопии (отсутствие утечки модели данных на этикетках); screen-composition a11y (ориентиры/фокус-порядок/целевой размер) — контрастность пикселей/фокус-внешний вид определяются дизайн-системой и здесь не оцениваются; отзывчивый; появились пробелы; структурный не hi-fi; поправка рассматривается как дельта с ограниченной областью действия. Выдает `VERDICT: утвердить|пересмотреть` + выводы, требующие принятия мер; утверждает документ, соответствующий полосе (без ложных изменений на тонком экране), вносит изменения только в случае именованного пробела. Не для авторинга, графа навигации (пользовательские потоки), визуальных токенов (дизайн-система) или Hi-Fi.
