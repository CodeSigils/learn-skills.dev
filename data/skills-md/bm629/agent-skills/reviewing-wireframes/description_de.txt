Wird bei der Überprüfung/Beurteilung eines fertigen (oder geänderten) Wireframes-Dokuments verwendet – ein Akzeptanztor: Kann die nachgelagerte Hi-Fi- und UI-Technik daraus die Bildschirmstruktur aufbauen? Bewertet ein TEXTUAL-Markdown-Drahtmodell anhand einer aus einer einzigen Quelle stammenden Baubarkeits-, Abdeckungs- und Kompositionsleiste: jeder flussbenannte Bildschirm/Zustand wird mit Qualitätszuständen abgedeckt; Eindeutiges Layout auf einem Raster + gemeinsame App-Shell, die eine objektive Layout-Qualitätsleiste erfüllt; echte + konsistente Komponenten; Angebote + Datenanzeige mit Anmerkungen; Mikrokopieabsicht (kein Datenmodellleck in Etiketten); Bildschirmzusammensetzung a11y (Sehenswürdigkeiten/Fokusreihenfolge/Zielgröße) – Pixelkontrast/Fokusaussehen sind Sache des Designsystems und werden hier nicht beurteilt; reaktionsschnell; Lücken traten auf; strukturell, nicht Hi-Fi; eine Änderung, die als bereichsbasiertes versioniertes Delta überprüft wurde. Gibt „URTEIL: genehmigen|überarbeiten“ + umsetzbare Ergebnisse aus; Genehmigt ein Dokument, das die Messlatte erfüllt (keine falsche Überarbeitung auf einem dünnen Bildschirm), überarbeitet nur eine benannte Lücke. Nicht für die Erstellung, das Navigationsdiagramm (Benutzerflüsse), die visuellen Token (Designsystem) oder Hi-Fi.
