Используйте при проверке/оценке плана тестирования/плана проверки качества — решаете, сможет ли тестировщик выполнить его, и охвачено ли каждое поведение. Ворота, не авторские. Сравнивает это с полосой из 10 условий из одного источника: каждое переданное вышестоящее поведение (спецификация функций/спецификация API+ошибки, иначе PRD) имеет >=1 случай TRACEABLE; функциональные уровни соответствуют; вход/выход проверяемый (минимальный уровень покрытия + порог открытого дефекта); среды + указанные тестовые данные; в каждом случае есть предварительные условия + шаги + наблюдаемый результат (порог метрики в наборе данных для ML) + трассировка; каталог УЧЕТ РИСКА (пробел в покрытии, расширенный/тонкий, ИЛИ комбинаторное увеличение = обнаружение); каждый гарантированный нефункциональный тип (perf/security/WCAG 2.2 AA/compat/i18n) несет в себе цель; поправка рассматривается на уровне дельты; ничего выдуманного. Выдает именно «ВЕРДИКТ: утвердить|пересмотреть» + выводы, требующие принятия мер; утверждает план пропорционального размера, вносит изменения только в связи с указанным пробелом. Не для его разработки, сборника выпусков, проверки дизайна или тестовых сценариев.
