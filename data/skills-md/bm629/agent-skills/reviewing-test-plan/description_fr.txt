À utiliser lors de l'examen/jugement d'un plan de test/plan de vérification d'assurance qualité : décider si un testeur peut l'exécuter et si chaque comportement est couvert. Une porte, pas une création. Le juge par rapport à une barre de 10 conditions provenant d'une source unique : chaque comportement en amont transmis (opérations de spécification de fonctionnalité/spécification d'api + erreurs, sinon PRD) a >=1 cas TRAÇABLE ; les niveaux fonctionnels correspondent ; entrée/sortie testable (plancher de couverture + seuil de défaut ouvert) ; environnements + données de test spécifiées ; chaque cas a des conditions préalables + des étapes + un résultat observable (un seuil de métrique sur un ensemble de données pour le ML) + des traces vers ; le catalogue est PONDÉRÉ EN FONCTION DES RISQUES (écart de couverture, rembourré/mince, OU agrandissement combinatoire = un constat) ; chaque type non fonctionnel garanti (perf/security/WCAG 2.2 AA/compat/i18n) porte une cible ; une mise à jour est examinée selon la portée delta ; rien de fabriqué. Émet exactement « VERDICT : approuver | réviser » + des conclusions exploitables ; approuve un plan de taille proportionnelle, révise uniquement sur un écart nommé. Pas pour sa création, le runbook de la version, la révision de la conception ou les scripts de test.
