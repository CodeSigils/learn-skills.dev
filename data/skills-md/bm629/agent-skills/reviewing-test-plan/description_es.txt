Úselo al revisar/juzgar un plan de prueba/plan de verificación de control de calidad: decidir si un evaluador puede ejecutarlo y si se cubren todos los comportamientos. Una puerta, no una autoría. Lo juzga en función de una barra de 10 condiciones de fuente única: cada comportamiento ascendente entregado (funciones-especificaciones/operaciones de especificaciones de API+errores, de lo contrario PRD) tiene >=1 caso TRAZABLE; los niveles funcionales encajan; entrada/salida comprobable (piso de cobertura + umbral de defectos abiertos); entornos + datos de prueba especificados; cada caso tiene condiciones previas + pasos + resultado observable (un umbral de métrica en un conjunto de datos para ML) + seguimientos hasta; el catálogo está PONDERADO POR RIESGO (brecha de cobertura, acolchado/delgado, O ampliación combinatoria = un hallazgo); cada tipo no funcional garantizado (perf/security/WCAG 2.2 AA/compat/i18n) lleva un objetivo; una enmienda se revisa con alcance delta; nada fabricado. Emite exactamente `VEREDICTO: aprobar|revisar` + hallazgos procesables; aprueba un plan de tamaño proporcional, revisa solo una brecha nombrada. No para su creación, el runbook de lanzamiento, la revisión del diseño o los scripts de prueba.
