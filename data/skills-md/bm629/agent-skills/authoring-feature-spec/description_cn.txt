在编写功能规范（功能规范）时使用 - 将 PRD 命名的功能细化为可实现、可测试的细节。指导生产者完成方法，而不是大纲：将每个功能追溯到 PRD 目标，指定可观察的行为和交互，枚举输入/输出 + 状态，用预期的处理方式覆盖边缘情况和错误处理，并编写可测试的给定/何时/然后验收标准 - 到一个栏，工程师可以在其中构建每个功能，测试人员可以在不询问作者的情况下对其进行验证。由单独的功能规范模板工具（提供部分结构）和深入研究功能（为 PRD 和域中的每个功能奠定基础）组成。假设已批准的 PRD 作为上游输入——绝不是空白页。不适用于创作 PRD 本身，不适用于审查完成的功能规范，也不适用于工程设计文档 (ADR/RFC)。
