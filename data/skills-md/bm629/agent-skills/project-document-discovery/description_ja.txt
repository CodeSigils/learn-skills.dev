ソフトウェアまたは製品プロジェクトが本番環境に出荷するためにどのドキュメントを作成する必要があるかを決定するときに使用します。つまり、プロジェクトのアイデアを、どのドキュメント、誰が、または何を作成するか、およびそれらが依存する順序など、比例したドキュメント計画に変換します。完全な SDLC ドキュメント領域 (計画、分析、製品/要件、設計/UX、アーキテクチャ/エンジニアリング、デリバリー/本番環境への移行、ユーザー向けドキュメント) に加えてドメイン オーバーレイ (データ/ML、セキュリティ/コンプライアンス、法務/ガバナンス、規制/検証) をカバーし、セットをプロジェクトのアーキタイプにキー設定するため、シン CLI ツールは少数で、UI 製品は多数になります。ディスカバリーのみ: どのドキュメントを作成するか、またその作成に何が必要かを決定します。ドキュメントの作成方法は決定しません (これは、ドキュメントごとの作成に関する別の懸念事項です)。キーワード: 私のプロジェクトに必要なドキュメント、ドキュメントの発見、ドキュメント計画、SDLC ドキュメント、ドキュメントマニフェスト、プロジェクトドキュメントの範囲、比例ドキュメント。
