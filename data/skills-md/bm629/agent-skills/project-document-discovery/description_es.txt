Úselo para decidir qué documentos debe producir un proyecto de software o producto para enviarlos a producción, convirtiendo una idea de proyecto en un plan de documentos proporcional: qué documentos, quién o qué produce cada uno y el orden del que dependen. Cubre todo el universo de documentos SDLC (planificación, análisis, producto/requisitos, diseño/UX, arquitectura/ingeniería, entrega/salida a producción, documentos orientados al usuario) además de superposiciones de dominio (datos/ML, seguridad/cumplimiento, legal/gobernanza, regulado/validación) y claves el conjunto para el arquetipo del proyecto, de modo que una herramienta CLI delgada tenga un puñado y un producto UI tenga muchos. Solo descubrimiento: decide qué documentos y qué se necesita para producirlos, no cómo crearlos (esa es una preocupación separada sobre la creación de cada documento). Palabras clave: qué documentos necesita mi proyecto, descubrimiento de documentos, plan de documentación, documentos SDLC, manifiesto de documentos, alcance de la documentación del proyecto, documentos proporcionales.
