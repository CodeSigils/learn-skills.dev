RTL + MSW + vitest-axe Komponententestebene für ein Vite + React + TypeScript SPA unter Vitest. Verwenden Sie diese Option beim Schreiben oder Einrichten von Komponententests, die einen echten Komponentenbaum rendern, ihn wie ein Benutzer steuern (React Testing Library + Benutzerereignis), die NETZWERK-Grenze verspotten (Mock Service Worker v2 – nicht das Modul) und sicherstellen, dass auf die gerenderte Ausgabe zugegriffen werden kann (vitest-axe toHaveNoViolations). Deckt die jsdom-Testumgebung ab (ausdrücklich nicht Happy-Dom, was Axe kaputt macht), die Priorität zugänglicher Abfragen, die Regel „Immer wartendes Benutzerereignis v14“, asynchrones findBy/waitFor, den MSW-setupServer-Lebenszyklus, das Abfangen eines generierten @hey-api/openapi-ts-Clients auf der Abrufebene, eine TanStack-Abfrage QueryClientProvider pro Test mit retry:false und form + request-body + a11y Behauptungen. Die Mitte der Testpyramide: oben Vitest Unit Tests, unten Playwright e2e.
