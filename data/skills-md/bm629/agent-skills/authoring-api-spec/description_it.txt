Da utilizzare durante la creazione di una specifica API: il contratto tecnico di una superficie API: operazioni/endpoint, schemi di richiesta + risposta (campi, tipi, obbligatori/facoltativi, vincoli), autenticazione, un modello di errore completo, limiti di impaginazione/velocità, controllo delle versioni ed esempi pratici. Guida il produttore attraverso il METODO, non lo schema: rendendo il contratto nello stile del progetto (OpenAPI per REST, SDL per GraphQL, proto per RPC), digitando ogni campo, enumerando i CASI DI ERRORE (non solo il percorso felice), tracciando ogni operazione a un comportamento specifico della funzionalità e facendo riferimento al modello di dati anziché ridefinirlo, a una barra in cui un client può chiamare ogni operazione e un server può implementarla solo dal contratto. Si compone con uno strumento modello API separato e una capacità di ricerca approfondita. Presuppone le specifiche delle funzionalità upstream (+ architettura-doc + modello dati dove presente) - mai una pagina vuota. Non il modello di dati di persistenza, il riferimento API rivolto al consumatore, l'implementazione o la revisione di una specifica API finita.
