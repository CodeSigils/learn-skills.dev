À utiliser lors de la création d'une spécification d'API : le contrat de fil d'ingénierie d'une surface d'API : opérations/points de terminaison, schémas de demande + réponse (champs, types, obligatoires/facultatifs, contraintes), authentification, un modèle d'erreur complet, pagination/limites de taux, gestion des versions et exemples concrets. Guide le producteur à travers la MÉTHODE, pas le plan : rendre le contrat dans le style du projet (OpenAPI pour REST, SDL pour GraphQL, proto pour RPC), taper chaque champ, énumérer les CAS D'ERREUR (pas seulement le chemin heureux), tracer chaque opération à un comportement de spécification de fonctionnalité et référencer le modèle de données plutôt que de le redéfinir - dans une barre où un client peut appeler chaque opération et un serveur peut l'implémenter à partir du contrat seul. Compose avec un outil de modèle API-spec distinct et une capacité de recherche approfondie. Suppose la spécification de fonctionnalité en amont (+ document d'architecture + modèle de données le cas échéant) - jamais une page vierge. Pas le modèle de données de persistance, la référence d'API destinée au consommateur, l'implémentation ou la révision d'une spécification d'API terminée.
