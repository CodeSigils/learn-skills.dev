Úselo al crear una especificación de API: el contrato de ingeniería de una superficie de API: operaciones/puntos finales, esquemas de solicitud + respuesta (campos, tipos, obligatorios/opcionales, restricciones), autenticación, un modelo de error completo, límites de paginación/velocidad, control de versiones y ejemplos resueltos. Guía al productor a través del MÉTODO, no del esquema: representar el contrato en el estilo del proyecto (OpenAPI para REST, SDL para GraphQL, proto para RPC), escribir cada campo, enumerar los CASOS DE ERROR (no solo el camino feliz), rastrear cada operación hasta un comportamiento de especificación de característica y hacer referencia al modelo de datos en lugar de redefinirlo, hasta una barra donde un cliente puede llamar a cada operación y un servidor puede implementarla solo desde el contrato. Se compone con una herramienta de plantilla de especificaciones de API separada y una capacidad de investigación profunda. Asume la especificación de características ascendentes (+ documento de arquitectura + modelo de datos cuando esté presente): nunca una página en blanco. No el modelo de datos de persistencia, la referencia de API orientada al consumidor, la implementación o la revisión de una especificación de API terminada.
