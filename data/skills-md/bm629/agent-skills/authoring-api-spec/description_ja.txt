API 仕様を作成するときに使用します。API サーフェスのエンジニアリング ワイヤ コントラクト: 操作/エンドポイント、リクエスト + レスポンス スキーマ (フィールド、タイプ、必須/オプション、制約)、認証、完全なエラー モデル、ページネーション/レート制限、バージョン管理、および実際に動作するサンプル。アウトラインではなくメソッドを通じてプロデューサーをガイドします。プロジェクトのスタイル (REST の場合は OpenAPI、GraphQL の場合は SDL、RPC の場合は proto) でコントラクトをレンダリングし、すべてのフィールドを入力し、エラー ケース (ハッピー パスだけでなく) を列挙し、機能仕様の動作まで各操作をトレースし、再定義するのではなくデータ モデルを参照します。クライアントがすべての操作を呼び出し、サーバーがコントラクトのみからそれを実装できるバーまで表示されます。個別の API 仕様テンプレート ツールと詳細な調査機能で構成されます。上流の機能仕様 (+ アーキテクチャ ドキュメント + 存在する場合はデータ モデル) を前提とします。空白ページは決してありません。永続化データモデル、消費者向け API リファレンス、実装、または完成した API 仕様のレビューではありません。
