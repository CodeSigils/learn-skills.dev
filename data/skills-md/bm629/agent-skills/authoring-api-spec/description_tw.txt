在編寫 API 規格時使用 - API 表面的工程線合約：操作/端點、請求 + 回應模式（欄位、類型、必要/可選、約束）、身份驗證、完整的錯誤模型、分頁/速率限制、版本控制和工作範例。指導生產者完成方法，而不是大綱：以專案風格（用於 REST 的 OpenAPI、用於 GraphQL 的 SDL、用於 RPC 的 proto）渲染合約，鍵入每個字段，枚舉錯誤案例（不僅僅是快樂路徑），將每個操作跟踪到功能規範行為，並引用它可以單獨定義它 - 到一個客戶端可以從每個操作伺服器的單獨列表中實現它可以單獨調用服務器數據 - 到一個客戶端可以從每個操作伺服器的列表中單獨調用模型由單獨的 api-spec 模板工具和深入研究功能組成。假設上游功能規格（+架構文件+資料模型（如果存在））－絕不是空白頁面。不是持久性資料模型、面向消費者的 API 參考、實作或審查已完成的 api 規格。
