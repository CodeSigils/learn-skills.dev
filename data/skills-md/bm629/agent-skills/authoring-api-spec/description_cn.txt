在编写 API 规范时使用 - API 表面的工程线合同：操作/端点、请求 + 响应模式（字段、类型、必需/可选、约束）、身份验证、完整的错误模型、分页/速率限制、版本控制和工作示例。指导生产者完成方法，而不是大纲：以项目风格（用于 REST 的 OpenAPI、用于 GraphQL 的 SDL、用于 RPC 的 proto）渲染合约，键入每个字段，枚举错误案例（不仅仅是快乐路径），将每个操作跟踪到功能规范行为，并引用数据模型而不是重新定义它 - 到一个客户端可以调用每个操作并且服务器可以单独从合约实现它的栏。由单独的 api-spec 模板工具和深入研究功能组成。假设上游功能规范（+架构文档+数据模型（如果存在））——绝不是空白页面。不是持久性数据模型、面向消费者的 API 参考、实现或审查已完成的 api 规范。
