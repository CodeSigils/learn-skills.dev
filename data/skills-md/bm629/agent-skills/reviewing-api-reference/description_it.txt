Da utilizzare quando si esamina/giudica un riferimento API pubblicato e rivolto al consumatore da cui uno sviluppatore che si integra chiama un'API, per decidere se è possibile integrarlo. Un cancello, non una creazione. Giudica contro un'usabilità a 11 condizioni da un'unica fonte + barra di coerenza del contratto: inizio + autenticazione raggiungono una prima chiamata; ogni operazione API-spec (inclusi eventi/webhook) è documentata con scopo + parametri digitati + un esempio funzionante + errori; errori di prima classe; limiti di velocità + impaginazione documentata ove applicabile; controllo delle versioni + deprecazione/tramonto dichiarato; il riferimento è COERENTE CON LE specifiche api consegnate (nessuna deriva, nessun punto finale fabbricato - controllo della portanza); campioni eseguibili; una modifica si risincronizza con il contratto modificato. Emette esattamente "VERDETTO: approva | revisiona" più risultati utilizzabili; approva un riferimento di dimensioni proporzionali, rivede una lacuna denominata. Non la sua creazione, non la guida per l'utente finale, non la guida all'adozione da parte degli sviluppatori, non le specifiche API di ingegneria (reviewing-api-spec).
