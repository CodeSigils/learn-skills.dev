統合開発者が API を呼び出す公開済みの消費者向け API リファレンスをレビュー/判断するときに使用し、そこから統合できるかどうかを判断します。オーサリングではなくゲートです。単一ソースの 11 条件のユーザビリティ + 契約の一貫性の基準に基づいて判断します。開始 + 認証が最初の呼び出しに達します。すべての API 仕様操作 (イベント/Webhook を含む) は、目的 + 型指定されたパラメータ + 動作例 + エラーとともに文書化されています。第一級のエラー。レート制限とページネーションは該当する場合は文書化されます。バージョン管理 + 非推奨/サンセットが記載されています。参照は、ハンドリングされた API 仕様と一致しています (ドリフトや作成されたエンドポイントはありません - 耐荷重チェック)。サンプルは実行可能です。修正は、変更された契約に再同期されます。正確に「評決: 承認|改訂」と実用的な調査結果を出力します。比例したサイズの参照を承認し、名前付きギャップを修正します。それを作成していない、エンドユーザー向けのユーザーガイド、開発者採用ガイド、エンジニアリング API 仕様 (API 仕様のレビュー) も作成していません。
