À utiliser lors de l'examen/de l'évaluation d'une référence d'API publiée destinée au consommateur à partir de laquelle un développeur intégrateur appelle une API - en décidant s'il peut l'intégrer. Une porte, pas une création. Juge contre une convivialité à 11 conditions d'une source unique + barre de cohérence du contrat : démarrage + authentification pour atteindre un premier appel ; chaque opération de spécification d'API (y compris les événements/webhooks) est documentée avec un objectif + des paramètres saisis + un exemple concret + des erreurs ; erreurs de première classe ; limites de débit + pagination documentées le cas échéant ; versioning + dépréciation/sunset déclaré ; la référence est CONFORME À LA spécification API REMISE (pas de dérive, pas de point final fabriqué - le contrôle de portance) ; échantillons exécutables ; un amendement est resynchronisé avec le contrat modifié. Émet exactement « VERDICT : approuver | réviser » ainsi que des conclusions exploitables ; approuve une référence de taille proportionnelle, révise sur un écart nommé. Pas de création, pas de guide de l'utilisateur final, pas de guide d'adoption par le développeur, pas de spécification d'API d'ingénierie (reviewing-api-spec).
