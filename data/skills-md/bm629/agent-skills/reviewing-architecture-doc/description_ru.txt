Используйте при просмотре/оценке готового документа об архитектуре всей системы (+ связанных с ним файлов ADR), чтобы решить, сможет ли инженер понять систему и разместить в ней TDD функции — ворота приемки, а не разработки. Судит по шкале из 10 условий из одного источника: граница + внешние ограничения + проблемы; единая ответственность компонентов на уровне всей системы (не API-спецификация/модель данных или детали функционального TDD); диаграммы ⇄ повествование согласен; каждое важное решение представляет собой отдельную СВЯЗАННУЮ неизменяемую ADR (по одной на файл, индекс синхронизируется, заменяет, а не редактирует); решения прослежены + обоснованы; Цели НФР реализованы + названы компромиссы; рассмотрены сквозные вопросы (устойчивость/безопасность/конфиденциальность/наблюдаемость); покрыты ASR; ничего сфабрикованного, претензии соответствуют кодексу; изменить дельта-область. C4/arc42/ATAM/4+1 — это средства, оцениваемые по результату. Выдает именно «ВЕРДИКТ: утвердить|пересмотреть» (в тонком документе ложной проверки нет). Не для разработки, PRD, API-спецификации/модели данных, TDD функции или общих проектных документов/RFC/автономных ADR (используйте Design-Review).
