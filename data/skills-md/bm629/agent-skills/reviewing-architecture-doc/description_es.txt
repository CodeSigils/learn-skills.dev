Úselo al revisar/juzgar un documento de arquitectura de todo el sistema terminado (+ sus archivos ADR vinculados) para decidir si un ingeniero puede comprender el sistema y colocar el TDD de una característica dentro de él: una puerta de aceptación, no una autoría. Juzga una barra de 10 condiciones de una sola fuente: límites + departamentos externos + preocupaciones; responsabilidad única de los componentes a la altitud de todo el sistema (no detalles de especificaciones de API/modelo de datos ni de características TDD); diagramas ⇄ narrativa concuerdan; cada decisión importante es un ADR independiente, VINCULADO e inmutable (uno por archivo, índice sincronizado, reemplaza, no edita); decisiones rastreadas + justificadas; Objetivos de NFR realizados + compensaciones nombradas; se abordan aspectos transversales (resiliencia/seguridad/privacidad/observabilidad); ASR cubiertos; nada inventado, afirmaciones consistentes con el código; modificar con alcance delta. C4/arc42/ATAM/4+1 son ayudas que se juzgan por el resultado. Emite exactamente `VEREDICTO: aprobar|revisar` (sin revisión falsa en un documento delgado). No para la creación, el PRD, la especificación de API/modelo de datos, el TDD de una característica o los documentos de diseño genéricos/RFC/ADR independientes (use revisión de diseño).
