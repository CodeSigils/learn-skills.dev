À utiliser lors de l'examen/de l'évaluation d'un document d'architecture complet du système terminé (+ ses fichiers ADR liés) pour décider si un ingénieur peut comprendre le système et y placer le TDD d'une fonctionnalité - une porte d'acceptation, pas de création. Juge une barre de 10 conditions provenant d'une source unique : limite + dépôts externes + préoccupations ; composants à responsabilité unique à l'altitude de l'ensemble du système (pas de détails API-spec/data-model ou fonctionnalité-TDD) ; diagrammes ⇄ récit d'accord ; chaque décision importante est un ADR autonome, LIÉ et immuable (un par fichier, index synchronisé, remplacement et non modification) ; décisions tracées + justifiées ; Objectifs NFR atteints + compromis nommés ; transversal (résilience/sécurité/vie privée/observabilité) abordé ; ASR couverts ; rien de fabriqué, affirmations conformes au code ; modifier la portée delta. C4/arc42/ATAM/4+1 sont des aides jugées en fonction du résultat. Émet exactement « VERDICT : approuver|réviser » (pas de fausse révision sur un document léger). Pas pour la création, le PRD, l'api-spec/data-model, le TDD d'une fonctionnalité ou les documents de conception génériques/RFC/autonomes-ADR (utilisez la révision de conception).
