Verwenden Sie diese Methode, wenn Sie eine Reihe abgeschlossener Projektdokumente als einen Korpus beurteilen, um zu entscheiden, ob sie untereinander kohärent sind und für die Planung bereit sind – das Analogon auf Korpusebene einer Entwurfsprüfung für ein einzelnes Dokument. Geht davon aus, dass jedes Dokument sein eigenes Tor passiert hat; Beurteilt nur, wie sie zueinander in Beziehung stehen, anhand einer achtdimensionalen Messlatte: dokumentübergreifende Konsistenz (einschließlich eines Namens pro Entität); Vollständigkeit/Rückverfolgbarkeit vom vorgelagerten Dokument (keine gelöschten/verwaisten Elemente oder TBDs); Widersprüche; Abhängigkeitsintegrität; abweichende Vervielfältigung; Planungsbereite Suffizienz (Definition von „Bereit“ + ein referenziertes, aber fehlendes Dokument); Änderung/Delta-bezogene Neuüberprüfung, wenn sich ein Dokument geändert hat (Übertragung auf seine abhängigen Dokumente); und version-skew (ein Dokument, das eine veraltete Version eines anderen Dokuments zitiert). Gibt genau ein Terminal „VERDICT: genehmigt|überarbeiten“ für den gesamten Satz aus, wobei jedem Ergebnis die ID(s) des betroffenen Dokuments vorangestellt wird. Genehmigt einen kohärenten Korpus (keine falsche Überarbeitung); Überarbeitet nur eine echte, benannte dokumentenübergreifende Lücke. Nicht für die interne Qualität eines Dokuments, noch für dessen Erstellung oder Korrektur.
