在將一組已完成的專案文件判斷為語料庫時使用，以確定它們是否相互一致並準備好進行計劃 - 單文檔設計審查的語料庫層級模擬。假設每個文件都通過了自己的大門；僅根據八維條判斷它們之間的關係：跨文檔一致性（包括每個實體一個名稱）；最上游文檔的完整性/可追溯性（無丟棄/孤立項目或 TBD）；矛盾；依賴性完整性；不同的重複；準備好計劃的充分性（準備好定義+引用但不存在的文檔）；當文檔更改版本的增量對其版本的增量對其版本（另一個版本）對其進行了增量更改；為整個集合發出一個終端“VERDICT：批准|修訂”，每個結果都以受影響的文檔 ID 為前綴。批准一個連貫的語料庫（無錯誤修改）；僅針對真實的、命名的跨文檔間隙進行修改。不是為了一份文件的內部質量，也不是為了創作或修復它們。
