À utiliser lors de la création d'une file d'attente de tâches/planificateur de tâches basée sur une base de données sur SQLAlchemy 2.x dont la préparation est basée sur les dépendances, dont les tâches sont de longue durée et avec état, et dont le seul substrat durable est la base de données relationnelle - boîte unique, intégrable, sans courtier, multi-dialecte (SQLite / PostgreSQL / MySQL). Couvre le modèle générique jobs/job_deps, la requête prête à l'emploi, le bail atomique par dialecte (FOR UPDATE SKIP LOCKED sur PostgreSQL + MySQL 8 vs BEGIN IMMEDIATE sur SQLite, avec détection de dialecte), la reprise en panne via heartbeat + expiration du bail + récupération de bail périmé, le délai d'attente par envoi bloqué mais vivant, la part équitable pondérée sur group_key, le scan → classement → location → répartition → persistance → récupération de la boucle de tick, interrogation vs réveil LISTEN/NOTIFY et le contrat d'idempotence au moins une fois. Mots-clés : file d'attente de tâches, planificateur de tâches, prêt à l'emploi, SKIP LOCKED, bail, reprise sur incident, multi-dialecte, SQLAlchemy, tâches en arrière-plan. Synchronisez d'abord. Pas la couche de données SQLAlchemy ou la primitive de verrouillage (sqlalchemy), pas les migrations (alambic).
