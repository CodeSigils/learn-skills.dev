Úselo al revisar/juzgar un diseño de interfaz de usuario de alta fidelidad terminado (o modificado) producido COMO CÓDIGO: una puerta de aceptación: ¿es el equipo de alta fidelidad renderizado una semilla de construcción de sonido? El revisor REPRESENTA el código en sí (navegador sin cabeza) y revisa visualmente las capturas de pantalla nuevas, sin confiar nunca en las imágenes entregadas. Juzga una barra de fuente única: cobertura completa frente a estructuras alámbricas; alta fidelidad + semilla no sobreconstruida; ejecución visual + pulido objetivo + heurística estética nombrada (el gusto subjetivo nunca es un vacío); respaldado por tokens/sin deriva de DS; contenido real (sin lorem); estados prestados; reflujo receptivo; NUMÉRICO WCAG 2.2 AA en el render (axe-core + visión, ninguna regla deshabilitada); surgieron huecos; una enmienda como un delta versionado con alcance. Emite `VEREDICTO: aprobar|revisar` + hallazgos procesables; aprueba una semilla que cumple con el estándar (sin revisión falsa en una pantalla delgada), revisa solo en una brecha renderizada con nombre. Requiere un tiempo de ejecución con capacidad de visión. No para la creación de alta fidelidad, la estructura (wireframes), el sistema de tokens (sistema de diseño) o el código final.
