Wird zur Überprüfung/Beurteilung eines fertigen (oder geänderten) High-Fidelity-UI-Designs verwendet, das ALS CODE erstellt wurde – ein Akzeptanztor: Ist das gerenderte Hi-Fi ein Sound-Build-Samen? Der Prüfer RENDET den Code selbst neu (Headless-Browser) und überprüft die frischen Screenshots visuell – ohne dabei auf eingereichte Bilder zu vertrauen. Bewertet einen Balken aus einer einzigen Quelle: vollständige Abdeckung im Vergleich zu den Wireframes; Hi-Fidelity + Saatgut, nicht überbaut; visuelle Umsetzung + objektiver Schliff + benannte ästhetische Heuristiken (subjektiver Geschmack nie eine Lücke); tokengestützt/kein DS-Drift; echter Inhalt (kein Lorem); gerenderte Zustände; reaktionsschnelles Reflow; NUMERISCHE WCAG 2.2 AA auf dem Render (Axtkern + Sicht, keine Regel deaktiviert); Lücken traten auf; eine Änderung als bereichsbasiertes versioniertes Delta. Gibt „URTEIL: genehmigen|überarbeiten“ + umsetzbare Ergebnisse aus; Genehmigt einen Seed, der die Messlatte erreicht (keine falsche Revision auf einem dünnen Bildschirm), revidiert nur eine benannte, gerenderte Lücke. Erfordert eine visionfähige Laufzeit. Nicht für die Erstellung von Hi-Fi, der Struktur (Wireframes), dem Token-System (Design-System) oder dem endgültigen Code.
