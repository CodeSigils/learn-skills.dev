Verwenden Sie diese Option, wenn Sie einen GitHub-Vorgang programmgesteuert ausführen – ein Problem oder eine Pull-Anfrage erstellen, Repos, Releases, Labels, Aktionsausführungen, Projekte, Geheimnisse oder eine beliebige github.com-Aufgabe verwalten – wobei Sie die „gh“-CLI bevorzugen und nur dann auf „gh api“ (REST) ​​oder „gh api graphql“ zurückgreifen, wenn kein Befehl vorhanden ist. Jeder Anruf wird pro Aufruf mit „GH_TOKEN“ authentifiziert; Es führt niemals „gh auth switch“ aus und druckt niemals das Token. Verwendet die High-Level-Befehle von „gh“ (die auch Geheimnisse auf der Clientseite verschlüsseln) für Abdeckung und Ergonomie; Für den REST Long Tail wird ein „gh api“-Aufruf aus einer gebündelten OpenAPI-Spezifikation über einen Endpunktindex + einen „$ref“-Resolver erstellt. github.com Cloud; verbraucht vom Anrufer injizierte Anmeldeinformationen (Host + ein durch den Variablennamen aufgelöstes Token) – sie werden nicht bereitgestellt oder aufgelöst.
