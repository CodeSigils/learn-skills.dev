1 つの機能またはコンポーネントの完成した技術設計文書 (TDD / エンジニアリング設計文書 / 設計 RFC) をレビュー/判断するときに使用し、エンジニアが設計を再導出することなく実装できるかどうかを判断します。つまり、オーサリングではなく承認ゲートです。機能仕様の下。単一ソースの 11 条件の実装可能性バーに照らして判断します。すべての決定は要件に双方向に追跡されます (孤立/ギャップなし)。アーキテクチャ内の 1 つの機能に限定されます。アプローチ + コンポーネントの分解は、同期された図 + ナレーションで実装可能です。 API 仕様/データモデルが所有するインターフェイス/スキーマは重複せずに参照されます (SSOT)。決定基準を備えた少なくとも 1 つの実際の代替案。障害モードには処理が含まれます。可観測性信号の名前。テストは障害と契約への適合をカバーします。測定可能なトリガーによるロールアウト/移行/ロールバック。仮定は明示的であり、捏造はありません。デルタスコープで修正をレビューしました。 FMEA/RTM/C4 は結果によって判断されるオーサリング支援であり、要求されることはありません。正確に「VERDICT:approve|revise」と結果を出力します。基準を満たす TDD を承認し (薄いものについては誤った修正はありません)、実際の名前付きギャップのみを修正します。オーサリング、アップストリームの PRD/機能仕様、API 仕様/データモデル、または汎用設計ドキュメント/RFC/ADR (設計レビューを使用するもの) 用ではありません。
