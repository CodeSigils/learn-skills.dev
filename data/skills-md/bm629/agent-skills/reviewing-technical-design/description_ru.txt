Используйте при проверке/оценке готового технического проекта (TDD/документ инженерного проекта/RFC проекта) для одной функции или компонента, чтобы решить, может ли инженер реализовать его без повторной разработки проекта — ворота приемки, а не авторская работа. Ниже характеристики. Оценивает это по шкале реализуемости из 11 условий из одного источника: каждое решение двунаправленно отслеживается до требования (без сирот/пробелов); ограничено одной функцией в архитектуре; подход + декомпозиция компонентов реализуются с помощью синхронизированной диаграммы + повествования; интерфейсы/схемы, принадлежащие API-спецификации/модели данных, ссылаются на них, а не дублируются (SSOT); хотя бы одна реальная альтернатива с критерием принятия решения; режимы отказа переноса обработки; сигналы наблюдаемости названы; тестирование охватывает сбои + соответствие контракту; развертывание/миграция/откат с измеримыми триггерами; предположения явные + ничего выдуманного; поправка рассмотрена в дельта-области. FMEA/RTM/C4 — это авторские средства, которые оцениваются по результату и никогда не востребованы. Выдает ровно `VERDICT: Approv|Revise` плюс выводы — утверждает TDD, соответствующий планке (без ложной проверки на тонком), пересматривает только при реальном, именованном пробеле. Не для разработки, исходных PRD/спецификаций функций, API-спецификаций/модели данных или общих проектных документов/RFC/ADR (те, которые используют проверку дизайна).
