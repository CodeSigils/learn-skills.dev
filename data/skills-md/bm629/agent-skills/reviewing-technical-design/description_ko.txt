하나의 기능이나 구성 요소에 대해 완성된 기술 설계 문서(TDD/엔지니어링 설계 문서/설계 RFC)를 검토/판단할 때 엔지니어가 설계를 다시 파생하지 않고 이를 구현할 수 있는지 결정하는 데 사용합니다. 즉, 저작이 아닌 승인 게이트입니다. 기능 사양 아래. 단일 소스의 11가지 조건 구현 가능성 기준에 따라 판단합니다. 모든 결정은 요구 사항(고아/갭 없음)을 양방향으로 추적합니다. 아키텍처 내의 하나의 기능으로 범위가 지정됩니다. 접근 방식 + 구성 요소 분해는 동기화된 다이어그램 + 설명으로 구현 가능합니다. API 사양/데이터 모델이 소유한 인터페이스/스키마는 중복되지 않고 참조됩니다(SSOT). 결정 기준이 있는 적어도 하나의 실제 대안; 실패 모드에서는 처리가 수행됩니다. 관측 가능성 신호 명명; 테스트에는 실패 + 계약 준수가 포함됩니다. 측정 가능한 트리거를 사용한 롤아웃/마이그레이션/롤백 명시적인 가정 + 조작된 것이 없음; 수정 사항은 델타 범위를 검토했습니다. FMEA/RTM/C4는 결과에 따라 판단되는 저작 보조 도구이며 결코 요구되지 않습니다. 정확히 `VERDICT: 승인|수정`과 결과를 내보냅니다. 기준을 충족하는 TDD를 승인하고(얇은 항목에 대한 허위 수정 없음) 실제 명명된 간격만 수정합니다. 업스트림 PRD/기능 사양, API 사양/데이터 모델 또는 일반 디자인 문서/RFC/ADR(디자인 검토를 사용하는) 작성용이 아닙니다.
