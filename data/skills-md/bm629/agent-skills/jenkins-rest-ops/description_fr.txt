À utiliser lors du pilotage de l'API REST (accès à distance) d'un serveur Jenkins directement avec curl (pas de SDK) : déclenchement d'une build, interrogation de l'élément de file d'attente vers une build, lecture de l'état de la build + journal de la console, liste/inspection des tâches, CRUD du travail (createItem/copy/delete/enable/disable via config.xml) et gestion des builds (arrêt/suppression). Jenkins est authentifié REST par chemin avec le nom d'utilisateur HTTP Basic : API_TOKEN. Un déclencheur de build est ASYNC — il renvoie un élément de file d'attente, pas une build, vous interrogez donc queue/item/<id>/api/json vers l'exécutable. L'authentification par jeton API est exemptée de la miette CSRF (Jenkins 2.96/2.107+) ; une miette n'est qu'une solution de repli 403. Il n'existe pas d'OpenAPI Jenkins officielle, donc la table des chemins CORE est basée sur la documentation officielle d'accès à distance (la spécification swaggy-jenkins fournie est une vérification croisée non officielle). Consomme les informations d'identification injectées par l'appelant (base_url + nom d'utilisateur + un jeton résolu par nom de variable) — il ne les fournit ni ne les résout ; la valeur du jeton est lue uniquement par curl, jamais imprimée.
