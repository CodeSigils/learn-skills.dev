Wird verwendet, wenn die REST-API (Remote Access) eines Jenkins-Servers direkt mit Curl (kein SDK) gesteuert wird – Auslösen eines Builds, Abfragen des Warteschlangenelements für einen Build, Lesen des Build-Status + Konsolenprotokolls, Auflisten/Inspizieren von Jobs, Job-CRUD (createItem/copy/delete/enable/disable über config.xml) und Build-Verwaltung (stoppen/löschen). Jenkins ist eine pfadadressierte REST-Authentifizierung mit HTTP Basic-Benutzername: API_TOKEN. Ein Build-Trigger ist ASYNC – er gibt ein Warteschlangenelement und keinen Build zurück, sodass Sie queue/item/<id>/api/json an die ausführbare Datei abfragen. Die API-Token-Authentifizierung ist vom CSRF-Krümel ausgenommen (Jenkins 2.96/2.107+); Ein Krümel ist nur ein 403-Fallback. Es gibt keine offizielle Jenkins OpenAPI, daher basiert die CORE-Pfadtabelle auf den offiziellen Remote Access-Dokumenten (die gebündelte Swaggy-Jenkins-Spezifikation ist eine inoffizielle Gegenprüfung). Verbraucht vom Anrufer injizierte Anmeldeinformationen (Basis-URL + Benutzername + ein durch den Variablennamen aufgelöstes Token) – sie werden nicht bereitgestellt oder aufgelöst; Der Tokenwert wird von Curl nur gelesen und nie gedruckt.
