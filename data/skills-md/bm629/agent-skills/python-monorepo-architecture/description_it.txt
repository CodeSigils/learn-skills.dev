Da utilizzare quando si progetta o si suddivide un repository Python in un monorepo uv-workspace multi-pacchetto - una libreria interna condivisa più una o più app o membri CLI che dipendono da essa - e sono necessari i giusti limiti tra pacchetti: quale codice diventa una libreria condivisa rispetto a un membro dell'app, la direzione di dipendenza aciclica verso l'interno (le app dipendono dalla libreria principale, mai l'una dall'altra), la disciplina di isolamento dell'importazione che uv non può applicare, l'API pubblica di ciascun membro al limite del pacchetto, test tra membri layout ed estrazione sicura del codice condiviso da un pacchetto esistente. Copre il cablaggio dell'area di lavoro uv (membri, tool.uv.sources, lockfile singolo, --package) e si compone con le competenze uv e python-project-structure. Parole chiave: monorepo, spazio di lavoro uv, multipacchetto, libreria condivisa, limiti dei pacchetti, direzione delle dipendenze, importazione circolare, import-linter.
