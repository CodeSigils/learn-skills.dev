À utiliser lors de l'architecture ou de la division d'un référentiel Python en un monorepo uv-workspace multi-packages - une bibliothèque interne partagée plus un ou plusieurs membres d'application ou CLI qui en dépendent - et vous avez besoin des bonnes limites entre les packages : quel code devient une bibliothèque partagée par rapport à un membre d'application, la direction de dépendance acyclique vers l'intérieur (les applications dépendent de la bibliothèque principale, jamais les unes des autres), la discipline d'isolation d'importation que uv ne peut pas appliquer, l'API publique de chaque membre à la limite du package, la disposition des tests entre membres, et extraire en toute sécurité le code partagé d'un package existant. Couvre le câblage de l'espace de travail uv (membres, tool.uv.sources, fichier de verrouillage unique, --package) et compose avec les compétences uv et python-project-structure. Mots clés : monorepo, espace de travail uv, multi-package, bibliothèque partagée, limites des packages, direction des dépendances, importation circulaire, import-linter.
