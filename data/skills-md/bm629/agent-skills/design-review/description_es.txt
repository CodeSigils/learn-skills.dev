Utilícelo cuando esté a punto de aprobar un documento de diseño (una especificación, un plan, un documento de diseño, un RFC o un ADR) y desee una revisión previa a la aprobación contradictoria que muestre las lagunas antes de la aprobación. Busca una rúbrica de categorías de brechas recurrentes (arranque y propiedad, honestidad de nomenclatura, escala, suposiciones ocultas, coherencia con el código enviado, idempotencia/fallo, seguridad, necesidad, integridad) y, cuando el documento es un plan, una lente del plan (granularidad de la tarea, dependencia-DAG, cobertura versus especificación, capacidad de prueba de criterios de salida). Verifica cada afirmación sobre el comportamiento existente con respecto al código base real (citando archivo: línea, nunca inventando); devuelve hallazgos (categoría, ubicación, gravedad, brecha, solución, evidencia) más un veredicto listo para aprobación/bloqueadores. Solo revisión: nunca edita el documento y nunca lo aprueba: el humano decide, el autor corrige. Palabras clave: revisión de diseño, revisión de especificaciones, revisión de planos, revisión de RFC, ADR, análisis de brechas, verificación previa a la aprobación.
