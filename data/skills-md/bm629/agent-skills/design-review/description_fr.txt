À utiliser lorsque vous êtes sur le point d'approuver un document de conception (une spécification, un plan, un document de conception, une RFC ou un ADR) et que vous souhaitez un examen contradictoire de pré-approbation qui fait apparaître les lacunes avant l'approbation. Recherche une rubrique de catégories de lacunes récurrentes (amorçage et propriété, honnêteté de la dénomination, échelle, hypothèses cachées, cohérence avec le code expédié, idempotence/échec, sécurité, nécessité, exhaustivité) et, lorsque le document est un plan, une lentille de plan (granularité des tâches, dépendance-DAG, couverture par rapport aux spécifications, testabilité des critères de sortie). Vérifie chaque affirmation concernant le comportement existant par rapport à la base de code réelle (en citant file:line, sans jamais fabriquer) ; renvoie les résultats (catégorie, emplacement, gravité, lacune, correctif, preuves) ainsi qu'un verdict prêt à être approuvé/has-blockers. Révision uniquement : ne modifie jamais le document et ne l'approuve jamais : l'humain décide, l'auteur corrige. Mots clés : revue de conception, revue de spécifications, revue de plan, revue RFC, ADR, analyse des écarts, contrôle de pré-approbation.
