在编写或修改测试计划/QA 验证计划时使用 - 测试什么、在什么级别、达到什么完成标准以及要运行的案例。指导方法，而不是大纲：从功能规范行为/AC 或 API 规范操作/错误中派生出每种情况（从不发明一个）；项目所需的功能级别；风险加权目录规模（BVA/等价/决策表/状态转换/成对，而不是叉积）；非功能性分类法（性能/安全性/可访问性 WCAG 2.2 AA/compat/i18n），每个分类法在必要时都有一个数字目标； ML/概率行为的命名数据集度量阈值案例；并修改为具有影响+风险回归选择的版本化增量 - 到测试人员毫无疑问地执行它的栏，并跟踪每个行为。模板工具+深度研究撰写；消耗上交的上游（feature-spec/api-spec/PRD/NFR），而不是空白页面。指定案例，而不是脚本；不是操作手册，不是行为契约，也不是审查手册。
