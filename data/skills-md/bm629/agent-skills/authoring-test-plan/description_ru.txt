Используйте при разработке или изменении плана тестирования/плана проверки качества — что тестировать, на каком уровне, по каким критериям выполнено и кейсы для запуска. Направляет МЕТОД, а не схему: выводит каждый случай из поведения/AC спецификации функции или операции/ошибки спецификации API (никогда не изобретая ее); функциональные уровни, которые гарантирует проект; Определение размеров каталога с учетом риска (BVA/эквивалентность/таблица решений/переход состояний/парные, а не перекрестное произведение); нефункциональная таксономия (perf/security/accessibility WCAG 2.2 AA/compat/i18n), каждая из которых имеет числовой целевой показатель, если это оправдано; случаи метрического порога для именованного набора данных для ML/вероятностного поведения; и внесение поправок в виде версионной дельты с выбором регрессии воздействия + риска — до панели, где тестировщик выполняет ее без вопросов, отслеживая каждое поведение. Составляет с помощью шаблонного инструмента + глубокие исследования; использует переданные исходные данные (feature-spec/api-spec/PRD/NFR), а не пустую страницу. Описывает случаи, а не сценарии; ни runbook, ни контракт на поведение, ни его проверка.
