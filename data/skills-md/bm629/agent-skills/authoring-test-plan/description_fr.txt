À utiliser lors de la création ou de la modification d'un plan de test/plan de vérification d'assurance qualité : que tester, à quel niveau, selon quels critères effectués et les cas à exécuter. Guide la MÉTHODE, pas les grandes lignes : dériver chaque cas d'un comportement/AC de spécification de fonctionnalité ou d'une opération/erreur de spécification d'API (sans jamais en inventer) ; les niveaux fonctionnels que le projet justifie ; Dimensionnement du catalogue PONDÉRÉ EN RISQUE (BVA/équivalence/table de décision/transition d'état/par paire, pas le produit croisé) ; une taxonomie non fonctionnelle (perf/sécurité/accessibilité WCAG 2.2 AA/compat/i18n) chacune avec une cible numérique lorsque cela est justifié ; cas de seuil métrique sur un ensemble de données nommé pour le comportement ML/probabiliste ; et modification en tant que delta versionné avec sélection de régression impact + risque - jusqu'à une barre où un testeur l'exécute sans questions, chaque comportement étant tracé. Compose avec un outil de modèle + recherche approfondie ; consomme les amonts remis (feature-spec/api-spec/PRD/NFRs), jamais une page blanche. Spécifie les cas, pas les scripts ; pas le runbook, pas le contrat de comportement, pas de révision.
