Úselo al escribir o revisar comentarios de documentos TSDoc en una base de código TypeScript: la gramática de comentarios estandarizada /** ... */ (@microsoft/tsdoc de Microsoft) que analizan TypeDoc, API Extractor y los editores. Cubre qué documentar (la superficie pública/exportada: funciones, clases, tipos, componentes de React + accesorios, ganchos) versus qué omitir (privado/interno, código generado, casos triviales, prosa que reafirma un tipo); la taxonomía de etiquetas categorizada en etiquetas de bloque (@param, @returns, @remarks, @example, @defaultValue, @typeParam, @see, @throws, @deprecated), etiquetas en línea ({@link}, {@inheritDoc}, {@label}) y etiquetas modificadoras (@public, @internal, @beta, @alpha, @readonly, @override); la estructura resumen-luego-@comentarios; y la regla clave TSDoc-vs-JSDoc: NO repetir tipos en los comentarios (los tipos TS ya los tienen), documentar la intención/comportamiento. Úselo al establecer una convención de comentarios de documentos, decidir qué y cómo documentar o corregir anotaciones de tipo estilo JSDoc en TS. De forma predeterminada, la aplicación se realiza únicamente mediante convenciones; eslint-plugin-tsdoc es un puntero CI opcional. No es la configuración del sitio TypeDoc o Storybook (solo sugerencias).
