À utiliser lors de l'écriture ou de la révision de commentaires de document TSDoc sur une base de code TypeScript - la grammaire de commentaire standardisée /** ... */ (@microsoft/tsdoc de Microsoft) que TypeDoc, API Extractor et les éditeurs analysent. Couvre ce qu'il faut documenter (la surface exportée/publique : fonctions, classes, types, composants React + accessoires, hooks) par rapport à ce qu'il faut ignorer (privé/interne, code généré, cas triviaux, prose qui reformule un type) ; la taxonomie des balises classée en balises de bloc (@param, @returns, @remarks, @example, @defaultValue, @typeParam, @see, @throws, @deprecated), balises en ligne ({@link}, {@inheritDoc}, {@label}) et balises de modification (@public, @internal, @beta, @alpha, @readonly, @override) ; la structure résumé-puis-@remarques ; et la règle clé TSDoc-vs-JSDoc — ne répétez PAS les types dans les commentaires (les types TS les ont déjà), documentez l'intention/le comportement. À utiliser pour établir une convention doc-commentaire, décider quoi/comment documenter ou corriger les annotations de type JSDoc dans TS. Par défaut, l'application s'effectue uniquement par convention ; eslint-plugin-tsdoc est un pointeur CI facultatif. Pas de configuration du site TypeDoc ou du Storybook (pointeurs uniquement).
