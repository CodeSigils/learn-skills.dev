Используйте при создании документа модели данных — модель персистентности/домена хранимых данных: типизированные сущности, отношения + кардинальность, ключи/ограничения, индексы, нормализация, выбор хранилища и жизненный цикл. Помогает производителю использовать МЕТОД, а не схему: выведение сущностей из существительных спецификации функции + шаблоны доступа, определение парадигмы и моделирование в ней (реляционный, документ/NoSQL-шаблон доступа, граф, широкий столбец, ключ-значение), явное определение правил целостности (ключи, ограничения, количество элементов + ссылочное правило), обоснование каждого индекса шаблоном доступа и внесение поправок в утвержденную модель в виде дельта-версии с запланированной миграцией - так инженер может построить + запросить схему. Составляет с помощью инструмента шаблонов моделей данных + возможность глубокого исследования. Предполагается, что исходная спецификация функций (+ документация по архитектуре) — никогда не пустая страница. Ни проводной контракт API (спецификация API ссылается на эти объекты в одном направлении), ни реализация/DDL, ни проверка готовой модели данных.
