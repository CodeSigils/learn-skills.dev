يُستخدم عند تأليف مستند نموذج بيانات - نموذج الثبات/المجال للبيانات المخزنة: الكيانات المكتوبة، والعلاقات + العلاقة الأساسية، والمفاتيح/القيود، والفهارس، والتسوية، واختيار التخزين، ودورة الحياة. يرشد المنتج من خلال الطريقة، وليس المخطط التفصيلي: اشتقاق الكيانات من أسماء مواصفات الميزات + أنماط الوصول، واكتشاف النموذج والنمذجة فيه (نمط الوصول العلائقي للمستند/NoSQL أولاً، الرسم البياني، العمود العريض، القيمة الرئيسية)، جعل قواعد التكامل واضحة (المفاتيح، القيود، العلاقة الأساسية + القاعدة المرجعية)، تبرير كل فهرس من خلال نمط وصول، وتعديل النموذج المعتمد باعتباره دلتا تم إصدارها وتخطيطها للترحيل - حتى يتمكن المهندس من إنشاء المخطط + الاستعلام عنه. يتم التأليف باستخدام أداة قالب نموذج البيانات + إمكانية البحث العميق. يفترض مواصفات الميزات الأولية (+ architecture-doc) - وليس صفحة فارغة أبدًا. ليس عقد API السلكي (تشير مواصفات API إلى هذه الكيانات النهائية، أحادية الاتجاه)، وليس التنفيذ/DDL، وعدم مراجعة نموذج البيانات النهائي.
