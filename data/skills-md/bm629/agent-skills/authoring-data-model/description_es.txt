Utilícelo al crear un documento de modelo de datos: el modelo de persistencia/dominio de datos almacenados: entidades tipificadas, relaciones + cardinalidad, claves/restricciones, índices, normalización, elección de almacenamiento y ciclo de vida. Guía al productor a través del MÉTODO, no del esquema: derivar entidades a partir de los sustantivos de la especificación de característica + patrones de acceso, detectar el paradigma y modelar en él (relacional, documento/patrón de acceso NoSQL primero, gráfico, columna ancha, clave-valor), hacer explícitas las reglas de integridad (claves, restricciones, cardinalidad + regla referencial), justificar cada índice mediante un patrón de acceso y modificar un modelo aprobado como un delta versionado y planificado para la migración, como lo dice un ingeniero. Puede construir + consultar el esquema. Redacta con una herramienta de plantilla de modelo de datos + una capacidad de investigación profunda. Asume la especificación de características ascendentes (+ documento de arquitectura): nunca una página en blanco. Ni el contrato de conexión API (la especificación de API hace referencia a estas entidades en sentido descendente, unidireccional), ni la implementación/DDL, ni la revisión de un modelo de datos terminado.
