在創作資料模型文件時使用 - 儲存資料的持久性/領域模型：類型化實體、關係+基數、鍵/約束、索引、規範化、儲存選擇和生命週期。指導生產者完成方法，而不是大綱：從功能規範的名詞+訪問模式中派生實體，檢測其中的範式和建模（關係、文檔/NoSQL訪問模式優先、圖形、寬列、鍵值），使完整性規則明確（鍵、約束、基數+引用規則），透過訪問模式證明每個索引工程師的合理性，並將批准的模型修改為增量模型——以便構建模型的增量。由資料模型範本工具+深度研究能力組成。假設上游功能規格（+架構文件）－絕不是空白頁面。不是 API 線合約（API 規範引用這些下游實體，單向），不是實作/DDL，也不是審查完成的資料模型。
