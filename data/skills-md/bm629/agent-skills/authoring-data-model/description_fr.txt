À utiliser lors de la création d'un document de modèle de données : le modèle de persistance/domaine des données stockées : entités typées, relations + cardinalité, clés/contraintes, index, normalisation, choix de stockage et cycle de vie. Guide le producteur à travers la MÉTHODE, et non les grandes lignes : dériver des entités à partir des noms de spécification de fonctionnalité + modèles d'accès, détecter le paradigme et le modéliser (relationnel, modèle d'accès au document/NoSQL en premier, graphique, colonne large, valeur-clé), rendre explicites les règles d'intégrité (clés, contraintes, cardinalité + règle référentielle), justifier chaque index par un modèle d'accès et modifier un modèle approuvé en tant que delta versionné et planifié pour la migration - afin qu'un ingénieur puisse créer + requête le schéma. Compose avec un outil de modèle de modèle de données + une capacité de recherche approfondie. Suppose la spécification de fonctionnalité en amont (+ architecture-doc) - jamais une page blanche. Pas le contrat de fil API (la spécification API fait référence à ces entités en aval, unidirectionnelle), pas l'implémentation/DDL, et pas de révision d'un modèle de données fini.
