Da utilizzare durante la creazione di un documento di modello dati: il modello di persistenza/dominio dei dati archiviati: entità tipizzate, relazioni + cardinalità, chiavi/vincoli, indici, normalizzazione, scelta di archiviazione e ciclo di vita. Guida il produttore attraverso il METODO, non lo schema: derivare entità dai nomi delle specifiche della funzionalità + modelli di accesso, rilevare il paradigma e modellarlo in esso (relazionale, modello di accesso NoSQL/documento prima, grafico, colonna ampia, valore-chiave), rendere esplicite le regole di integrità (chiavi, vincoli, cardinalità + regola referenziale), giustificare ciascun indice con un modello di accesso e modificare un modello approvato come delta con versione e pianificazione della migrazione, quindi un ingegnere può creare + interrogare lo schema. Compone con uno strumento di modelli di modelli di dati + una capacità di ricerca approfondita. Presuppone le specifiche delle funzionalità upstream (+ architettura-doc) - mai una pagina vuota. Non il contratto API (le specifiche API fanno riferimento a queste entità a valle, unidirezionali), non l'implementazione/DDL e non la revisione di un modello di dati finito.
