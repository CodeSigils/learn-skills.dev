데이터 모델 문서를 작성할 때 사용합니다. 즉, 저장된 데이터의 지속성/도메인 모델(유형화된 엔터티, 관계 + 카디널리티, 키/제약 조건, 인덱스, 정규화, 저장소 선택 및 수명 주기)을 사용합니다. 개요가 아닌 METHOD를 통해 생산자를 안내합니다. 기능 사양의 명사 + 액세스 패턴에서 엔터티 파생, 패러다임 감지 및 그 안에서 모델링(관계형, 문서/NoSQL 액세스 패턴 우선, 그래프, 와이드 컬럼, 키-값), 무결성 규칙 명시(키, 제약 조건, 카디널리티 + 참조 규칙), 액세스 패턴으로 각 인덱스 정당화, 버전이 지정된 마이그레이션 계획 델타로 승인된 모델 수정 — 엔지니어가 스키마를 구축하고 쿼리할 수 있습니다. 데이터 모델 템플릿 도구 + 심층 연구 기능으로 구성합니다. 업스트림 기능 사양(+ 아키텍처 문서)을 가정합니다. 결코 빈 페이지가 아닙니다. API 와이어 계약(API 사양은 이러한 엔터티 다운스트림, 단방향 참조)도 아니고 구현/DDL도 아니며 완성된 데이터 모델을 검토하지도 않습니다.
