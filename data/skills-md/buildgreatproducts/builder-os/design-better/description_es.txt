Úselo cuando el usuario esté creando o refactorizando la interfaz de usuario en el código base de su producto y desee un código de interfaz con calidad de diseñador, no solo un código funcional. Activadores de frases como "diseñar mejor", "hacer que esta interfaz de usuario se sienta más diseñada", "elevar la calidad del diseño", "construir esto con las mejores prácticas de diseño", "seguir heurísticas de UX", "hacer que esto se sienta profesional", "aplicar pulido de diseño", "revisar esto para manualidades" o cualquier solicitud para aplicar heurísticas artesanales de UX/UI a la generación o revisión de código. Se combina con `docs/design.md` cuando existe: el archivo del sistema de diseño posee **estilo** (colores, tipografía, tokens de espaciado, componentes), esta habilidad posee **artesanía** (jerarquía, interacción, accesibilidad, movimiento, pulido). Haga referencia a los tokens `docs/design.md` por nombre para cada decisión visual; aplique el catálogo de heurísticas de 50 elementos y el catálogo de Leyes de UX a continuación para cada decisión artesanal. Cuando `docs/design.md` esté ausente, recurra a las convenciones de diseño existentes del código base y recomiende la habilidad **Sistema de diseño**. Cuando una heurística implica un token que el sistema de diseño no tiene, márquelo como un Nuevo patrón para agregar mediante la habilidad **Sistema de diseño**; nunca invente un valor en línea. Totalmente independiente.
