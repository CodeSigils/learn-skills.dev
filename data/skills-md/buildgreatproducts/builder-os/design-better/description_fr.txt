À utiliser lorsque l'utilisateur crée ou refactorise l'interface utilisateur dans la base de code de son produit et souhaite un code frontal de qualité concepteur, pas seulement du code fonctionnel. Déclencheurs sur des expressions telles que « mieux concevoir », « rendre cette interface utilisateur plus conçue », « élever la qualité de la conception », « construire ceci avec les meilleures pratiques de conception », « suivre l'heuristique UX », « rendre cela professionnel », « appliquer le polissage de la conception », « réviser ceci pour l'artisanat » ou toute demande d'application de l'heuristique artisanale UX/UI à la génération ou à la révision de code. S'associe à `docs/design.md` lorsqu'il existe — le fichier du système de conception possède le **style** (couleurs, typographie, jetons d'espacement, composants), cette compétence possède le **craft** (hiérarchie, interaction, accessibilité, mouvement, polissage). Référencez les jetons `docs/design.md` par leur nom pour chaque décision visuelle ; appliquez le catalogue heuristique de 50 éléments et le catalogue des lois de l'UX ci-dessous pour chaque décision artisanale. Lorsque `docs/design.md` est absent, revenez aux conventions de conception existantes de la base de code et recommandez la compétence **Design System**. Lorsqu'une heuristique implique un jeton que le système de conception ne possède pas, signalez-le comme un nouveau modèle à ajouter via la compétence **Design System** — n'inventez jamais de valeur en ligne. Entièrement autonome.
