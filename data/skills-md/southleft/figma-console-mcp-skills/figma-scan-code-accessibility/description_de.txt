Scannen Sie generiertes/verfasstes HTML auf Barrierefreiheitsverletzungen mit axe-core (Deque), das über JSDOM ausgeführt wird – strukturelle und semantische Regeln: ARIA-Attribute und -Rollen, zugängliche Namen, Alternativtext, Formularbeschriftungen, Überschriftenreihenfolge, Orientierungspunkte, semantisches HTML, Tabindex, doppelte IDs, lang-Attribut und ~50 mehr. Verwendung auf der CODE-Seite eines Figma-to-Code-Workflows: Trigger „diesen HTML-Code auf Barrierefreiheit scannen“, „Ax auf meiner Komponente ausführen“, „den generierten Code auf a11y überprüfen“, „Axe-Core-Scan“, „Barrierefreiheit lint mein Markup“, „WCAG-Code prüfen“, „ist dieser HTML-Code barrierefrei“. Dies ist ein eigenständiges Node-Skript – KEINE Figma-Verbindung erforderlich. Visuelle Regeln (Farbkontrast, Fokus-sichtbar, Link-in-Text-Block, Zielgröße) sind DEAKTIVIERT, da JSDOM kein Layout hat – verwenden Sie figma-lint-design für visuelle Elemente auf der Designseite. Beides zusammen ergibt eine vollständige Design- und Codeabdeckung.
