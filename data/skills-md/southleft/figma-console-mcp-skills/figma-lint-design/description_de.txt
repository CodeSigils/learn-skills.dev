Flusen Sie einen Figma-Knotenbaum für WCAG 2.2-Barrierefreiheit UND Qualität des Designsystems – Kontrast, Zielgröße, Fokusindikatoren, Nur-Farb-Signalisierung, fest codierte Farben, fehlende Textstile, getrennte Komponenten und mehr. Verwenden Sie diese Option, wenn der Benutzer VOR der Übergabe eine designseitige Prüfung wünscht: löst „Diesen Frame linten“, „Barrierefreiheit prüfen“, „WCAG-Prüfung“, „Ist mein Design barrierefrei“, „Kontrastprobleme finden“, „Farbkontrast prüfen“, „hartcodierte Farben finden“, „Verwenden meine Komponenten Token“, „Design-QA“, „A11y-Überprüfung auf dieser Seite“, „Mein Design auf Probleme prüfen“. Durchläuft den Baum von einem Knoten (oder der gesamten Seite) und gibt Ergebnisse mit Schweregrad (kritisch/Warnung/Info) und WCAG-Stufe (A/AA/AAA/Best-Practice) zurück. Das native Figma MCP weist KEINE designseitigen Flusen auf – das ist einzigartig in dieser Kollektion. Für die umfassende a11y-Scorecard pro Komponente verwenden Sie figma-audit-accessibility; Für CODE-seitige (HTML) Prüfungen verwenden Sie figma-scan-code-accessibility.
