Методология оценки одного совместимого со sklearn учащегося (в частности, SkrubLearner, созданного с помощью build-ml-pipeline). Владеет: какую точку входа вызывать (сначала `score.evaluate`, явные классы отчетов при необходимости), какой перекрестный валидатор выбрать из каталога scikit-learn, как использовать структурные метаданные (`groups`, `times`, …), прикрепленные во время сборки через `.skb.mark_as_X(split_kwargs=...)`. Останавливается на «что говорится в отчете». Значения по умолчанию (показатели, графики) берутся из счета; переопределять только по явному запросу пользователя.
TRIGGER, когда: код вызывает `cross_val_score`, `cross_validate`, `classification_report` или любую рукописную метрику print (`print(mean_squared_error(...))`); код вызывает `.skb.cross_validate(...)` (маршрутизация через score для более богатого вывода); пользователь спрашивает, как выставить баллы, оценить или сравнить одного учащегося; пользователь спрашивает, как выбрать перекрестный валидатор; пользователь хочет видеть отчет/показатели/диагностические графики для подходящего учащегося.
ПРОПУСТИТЕ, когда: объявляете конвейер (используйте `build-ml-pipeline`); поиск гиперпараметров/моделей (отдельный навык); подгонка, сохранение или обслуживание окончательной модели; отслеживание или сравнение экспериментов в ходе нескольких прогонов с течением времени (отдельный навык).
КАК ИСПОЛЬЗОВАТЬ: вызывать перед любым оценочным вызовом. **Сначала прочитайте блок «Условия остановки» в верхней части тела и отправьте предполетный контрольный список в виде видимого текста в свой ответ — оба обязательны перед написанием любого оценочного кода.** Структурные факты о данных (групповые ключи, порядок времени) уже должны быть закодированы в маркере X с помощью `split_kwargs` — если это не так, и вы не можете определить это по данным, вернитесь к `build-ml-pipeline` и спросите пользователя.
