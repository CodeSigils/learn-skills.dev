*インストールされているバージョン*に対して Python パッケージのパブリック API を検索し、保持する価値のあるものをキャッシュします。質問タイプ別の 4 つの形状: (0) `scratch/api/<lib>/<version>/` でキャッシュ ヒット。 (1) シンボルの場合は `inspect.signature` + `pydoc.render_doc`。 (2) モジュール表面の `dir` / `pkgutil.iter_modules`。 (3) 説明 (「どのように」、「どれ」、「Y のときに X が何を返すか」) 用のバージョン付きドキュメントの WebSearch + WebFetch。決してトレーニング データ メモリからシンボルを書き込まないでください。認識は検索ではありません。
TRIGGER — 次のいずれか - コード内でシンボル (関数 / クラス / メソッド / 引数) に名前を付けようとしています。 - ユーザーが「X の署名は何ですか?」、「モジュール Y には何が入っていますか?」と尋ねます。
  「Xに電話するにはどうすればいいですか？」、「A/Bのどちらを使用すればよいですか？」。
- ユーザーは「<条件> の場合、X は何を返しますか?」と尋ねます。 (形状 3 — を参照
  決定表）。
- 別のワークフロー スキル (`build-ml-pipeline`、
  `evaluate-ml-pipeline`、`iterate-from-skore`、
  `smoke-test-ml-pipeline`) は「API スキルを調べてください」と述べています。
- 記憶から図書館の「明白な」パターンに到達しようとしています。
次の場合はスキップしてください: このターンで読んだばかりの呼び出しサイトから署名が明らかである場合。作業はファイルシステム/シェルのみです (Python シンボルはありません)。 `scratch/api/<lib>/<version>/<topic>.md` キャッシュ ファイルがすでに質問に答えています (まだ Shape 0 の相談です。フェッチしないだけです)。
使用方法: 最初にスクラッチ ファイル (`scratch/<ts>_version_<pkg>.py` with `import <pkg>; print(<pkg>.__version__)` — `pixi run pythonScratch/<ts>_version_<pkg>.py` で実行) を介してパッケージのバージョンを解決します。次に、`scratch/api/<lib>/<version>/` をリストします。次に、「どのような質問ですか?」から形を選択します。テーブル。物語の発見はキャッシュバックされます。 **すべての Python の実行は `scratch/<ts>_*.py` ファイルを経由します。インラインの `python -c` は長さに関係なく禁止されています。** スタック固有の方向は `references/stack_orientation.md` にあります。 — オンデマンドでロードされます。
