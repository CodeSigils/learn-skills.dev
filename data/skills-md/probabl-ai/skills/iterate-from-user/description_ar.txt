احصل على اقتراح تجربة تعلم الآلة التالي من المستخدم عبر إحدى نقاط الإدخال الثلاثة المحددة بواسطة "AskUserQuestion": (أ) عنوان URL لمقالة علمية يجب على الوكيل قراءته وتوليفه، (ب) رابط المورد أو المسار (إصدار GitHub / ملف المواصفات / الريبو المرجعي)، أو (ج) النص الحر الذي يكتبه المستخدم مباشرة. في كل فرع، يقرأ الوكيل المصدر، ويجمع فهمه لما يجب تنفيذه، ويؤكد مع المستخدم *قبل* إعادة كتلة الاقتراح. قم بتسليم الاقتراح المؤكد مرة أخرى إلى `iterate-ml-experiment`، الذي يكتبه في `journal/NN_short_name.md` ويطلب موافقة المستخدم على مذكرة التصميم. يتوقف عند "تم إرجاع الاقتراح، وتم تأكيده من قبل المستخدم"؛ لا يكتب أبدًا مذكرة تصميم، ولا معايير قبول المؤلفين أبدًا.
يتم تشغيله عندما: `iterate-ml-experiment` يختار استراتيجية المصادر ويختار المستخدم `user` من القائمة؛ يتطوع المستخدم بفكرة محددة ("أريد تجربة X")؛ يقوم المستخدم بلصق أو ربط مقالة علمية أو مشكلة GitHub أو ملف المواصفات أو الريبو المرجعي ويطلب منا قراءتها.
تخطي عندما: يريد المستخدم استخراج التقرير السابق (استخدم `iterate-from-skore`)؛ يطلب المستخدم بحثًا عن رمز أو ميكانيكا خطوط الأنابيب (استخدم مهارة `python-api`)؛ العمل عبارة عن آليات تقييم في تقرير واحد (الطريق إلى "تقييم-مل-خط الأنابيب").
كيفية الاستخدام: افتح باستخدام "AskUserQuestion" لنقطة الإدخال - رابط المقالة / رابط المورد / النص الحر. في كل فرع: اجمع المادة المصدر باستخدام الأداة المناسبة (`WebFetch`، و`عرض مشكلة gh`، و`Read`)، وقم بتجميع ما تفهمه في أسئلة التشكيل الثلاثة، و**التأكيد مع المستخدم عبر نص عادي** (جملة أو جملتين: "ترغب في تنفيذ X عن طريق تغيير src/<pkg>/<file>.py - أليس كذلك؟") قبل إعادة الاقتراح. لا تكتب أي مذكرة التصميم. لا تضع معايير القبول.
