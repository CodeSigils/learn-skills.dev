「AskUserQuestion」で選択した 3 つのエントリ ポイントのいずれかを介して、ユーザーから次の ML 実験提案を入手します: (a) エージェントが読んで合成する必要がある科学論文の URL、(b) リソース リンクまたはパス (GitHub の問題 / 仕様ファイル / 参照リポジトリ)、または (c) ユーザーが直接入力するフリーテキスト。すべてのブランチで、エージェントはソースを読み、何を実装するかを総合的に理解し、提案ブロックを返す「前に」ユーザーに確認します。確認されたプロポーザルを `iterate-ml-experiment` に返します。プロポーザルはそれを `journal/NN_short_name.md` に書き込み、ユーザーのデザインノートの承認を求めます。 「プロポーザルが返され、ユーザーが確認しました」で停止します。設計ノートを書くことも、受け入れ基準を作成することもありません。
トリガーは次の場合に発生します: 「iterate-ml-experiment」がソーシング戦略を選択し、ユーザーがメニューから「user」を選択したとき。ユーザーは具体的なアイデアを自発的に出します (「X を試してみたい」)。ユーザーは科学論文、GitHub の問題、仕様ファイル、またはリファレンス リポジトリを貼り付けるかリンクし、それを読むよう当社に依頼します。
次の場合はスキップします: ユーザーが前のレポートをマイニングしたい場合 (`iterate-from-skore` を使用)。ユーザーはシンボルの検索またはパイプラインの仕組みを求めています (`python-api` スキルを使用します)。この作業は、単一レポートの評価メカニズムです (「evaluate-ml-pipeline」へのルート)。
使用方法: エントリ ポイント (記事リンク / リソースリンク / フリーテキスト) の「AskUserQuestion」で開きます。各ブランチで: 適切なツール (「WebFetch」、「gh issue view」、「Read」) を使用してソース資料を収集し、理解した内容を 3 つの形成質問にまとめ、**プレーン テキストでユーザーに確認します** (1 つまたは 2 つの文: 「src/<pkg>/<file>.py を変更して X を実装したいのですが、そうですか?」) プロポーザルを返す前に。デザインノートは書かないでください。受け入れ基準を作成しないでください。
