データ サイエンス / ML 作業用の独自の Python スタック — ジョブごとに 1 つのライブラリがあり、階層 (必須 / ユーザーの選択 / オプション / 推移的) に編成されています。 SKILL.md はインデックスです。ライブラリごとの `references/<library>.md` ファイルには、スコープ、「いつこれを選択する」/「いつ他のものを選択する」、およびペアが含まれます。
(これらのいずれか) 場合にトリガーされます: (1) このスタックのドメインで **ライブラリのインポートが失敗**します。答えは置換ではなくインストールです (「依存関係の欠落」を参照)。 (2) **ライブラリを選択する必要があります** — 明示的 (ユーザーが「X にどのライブラリを使用しますか?」と尋ねる) または暗黙的 (コードに新しい依存関係が導入されようとしている、またはプロジェクトがスキャフォールディングされており、表形式のライブラリがまだ選択されていない)。 (3) 新しい Python データサイエンス / ML プロジェクトを開始する。 (4) ユーザーまたは現在のコードがスタックの外の代替コード (xgboost、lightgbm、black、isort、flake8、poetry、hatch) に到達するか、パラメーター/メトリクスを記録するための `mlflow` に到達するか、または `cross_val_score` + 手書きのレポートに到達する — リダイレクト: 追跡 → `skore` プロジェクト API、評価/レポート → `skore` レポート クラス、`mlflow` はモデル提供/レジストリのみに留まります。
次の場合はスキップします: プロジェクトが Python 以外である場合。仕事はデータサイエンスとは関係のないWeb/バックエンド/インフラです。ライブラリはすでに選択されてインストールされており、タスクはその内部での実装 (バグ修正、機能作業、リファクタリング) であり、新たな依存関係はありません。
使用方法: **何かを推奨したりインストールしたりする前に、この SKILL.md を最初から最後まで読んでください** — 単一のインデックス エントリから選択すると、層 (ライブラリが必須か、ユーザーの選択か、オプションか、または既に推移的に存在するか) とペアが隠蔽され、両方が重要になります。次に、リンクされた `references/<library>.md` を読み、選択したライブラリのスコープとトレードオフを確認します。あるライブラリを別のライブラリに黙って置き換えないでください。適合するエントリがない場合は、そのギャップをユーザーに明らかにします。
