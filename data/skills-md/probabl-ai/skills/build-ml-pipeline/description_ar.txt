قم بتعريف المسار من مصدر البيانات إلى المتنبئ باعتباره **رسم بياني skrub DataOps** (وليس باعتباره `sklearn.Pipeline` فقط). كل خطوة هي إما دالة بايثون خالصة (عديمة الحالة) مرفقة عبر `.skb.apply_func`، أو مُقدِّر متوافق مع sklearn (ذو حالة) مرفق عبر `.skb.apply`. يتوقف عند الكائن المعلن - لا يوجد ملاءمة أو تقسيم أو ضبط أو استمرار أو تقييم.
TRIGGER — أي من: - كتابة أو تحرير التعليمات البرمجية التي تعلن عن أي رابط في السلسلة
  *مصدر البيانات → المتنبئ*: أدوات التحميل والمعالجة المسبقة وأجهزة التشفير /
  أجهزة الكمبيوتر / أدوات القياس، خطوات الميزة، كائنات التركيب
  (`خط الأنابيب`، `محول الأعمدة`، سكروب `خط_الأنابيب` الجدولي`،
  `nn.Module`)، أو المقدر النهائي.
- وظيفة معالجة بيانات بيثون خالصة مخصصة لـ
  مسار خط الأنابيب (ينظف / يشتق / يعيد تشكيل) - سواء كان ملفوفًا
  عبر `FunctionTransformer`، `skrub.@deferred` / `skrub.var`،
  فئة فرعية مخصصة `BaseEstimator`، أو تم استدعاؤها للتو في ملف
  مسار التدريب قبل المقدر.
- تتم إضافة خطوة أو إزالتها أو تبديلها أو إعادة ترتيبها داخل
  إعلان خط الأنابيب الحالي.
- يتم استخدام `sklearn.Pipeline` / `make_pipeline` كـ
  المستوى الأعلى - أطلق النار لإعادة التوجيه إلى الرسم البياني DataOps skrub.
- يطلب المستخدم إنشاء / إعلان / إعداد خط أنابيب /
  المصنف/التراجع لـ X.

تخطي عندما: `.fit(...)` المكالمات / حلقات التدريب / `Trainer.fit` / حلقات العصر؛ تقسيم التدريب/الاختبار أو تقسيم التحقق المتبادل؛ البحث عن المعلمات الفائقة؛ المثابرة (`joblib.dump`، نقطة التفتيش)؛ التقييم / المقاييس / التسجيل؛ الاستدلال على نموذج تم تدريبه مسبقًا؛ إيدا نقية؛ أسئلة اختيار المكتبة مع عدم وجود إعلان ملموس في اللعب.
كيفية الاستخدام: استشر قبل السطر التعريفي الأول وفي كل تعديل هيكلي (خطوة مضافة/مبادلة، أعمدة إدخال متغيرة، عائلة تقدير متغيرة). لا تقم بإعادة التشاور بشأن التعديلات التجميلية. **أولاً، اقرأ شروط الإيقاف وأصدر قائمة التحقق قبل الرحلة كنص مرئي قبل أي رمز. ** قم دائمًا باستدعاء `python-api` لتأكيد أسماء رموز skrub / sklearn وتوقيعاتها قبل الكتابة - لا تقم بالتخمين من الذاكرة.
