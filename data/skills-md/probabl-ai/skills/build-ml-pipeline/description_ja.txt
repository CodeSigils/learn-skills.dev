データ ソースから予測子までのパイプラインを **skrub DataOps グラフ** (裸の `sklearn.Pipeline` としてではなく) として宣言します。すべてのステップは、`.skb.apply_func` を介してアタッチされた純粋な Python 関数 (ステートレス)、または `.skb.apply` を介してアタッチされた sklearn 互換の推定器 (ステートフル) のいずれかです。宣言されたオブジェクトで停止します。適合、分割、調整、永続化、評価は行われません。
TRIGGER — 次のいずれか - チェーン内のリンクを宣言するコードの作成または編集
  *データ ソース → プレディクター*: ローダー、前処理、エンコーダー /
  インピューター/スケーラー、フィーチャーステップ、合成オブジェクト
  (`Pipeline`、`ColumnTransformer`、スクラブ `tabular_pipeline`、
  `nn.Module`)、または最終推定量。
- 向けの純粋な Python データ処理関数
  パイプライン パス (クリーン/派生/再形成) - ラップされているかどうか
  `FunctionTransformer`、`skrub.@deferred` / `skrub.var` 経由、
  カスタム `BaseEstimator` サブクラス、または単に
  推定器の前のトレーニング パス。
- ステップ内でステップが追加、削除、交換、または並べ替えられます。
  既存のパイプライン宣言。
- 裸の `sklearn.Pipeline` / `make_pipeline` が次のように使用されています。
  最上位 — スクラブ DataOps グラフにリダイレクトするために起動します。
- ユーザーはパイプラインの構築 / 宣言 / セットアップ / を要求します。
  X の分類子/リグレッサー。

SKIP の場合: `.fit(...)` 呼び出し / トレーニング ループ / `Trainer.fit` / エポック ループ;トレーニング/テスト分割または相互検証分割。ハイパーパラメータ検索。永続性 (`joblib.dump`、チェックポイント作成);評価/指標/スコアリング;事前トレーニングされたモデルに対する推論。純粋なEDA。具体的な宣言が行われていない図書館選択の質問。
使用方法: 最初の宣言行の前と、すべての構造編集 (ステップの追加/交換、入力列の変更、推定器ファミリーの変更) のたびに確認してください。表面的な編集については再相談しないでください。 **まず、コードの前に停止条件を読み、プリフライト チェックリストを表示テキストとして出力します。** 入力する前に必ず `python-api` を呼び出して skrub / sklearn シンボルの名前と署名を確認してください。記憶から推測しないでください。
