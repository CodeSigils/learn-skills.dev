将从数据源到预测器的管道声明为 **skrub DataOps 图**（而不是裸露的“sklearn.Pipeline”）。每个步骤要么是通过“.skb.apply_func”附加的纯Python函数（无状态），要么是通过“.skb.apply”附加的与sklearn兼容的估计器（有状态）。停在声明的对象上——不适合、分割、调整、持久性或评估。
触发器 — 以下任意一项： - 编写或编辑声明链中任何链接的代码
  *数据源→预测器*：加载器、预处理、编码器/
  计算器/缩放器、特征步骤、合成对象
  (`Pipeline`、`ColumnTransformer`、skrub `tabular_pipeline`、
  `nn.Module`)，或最终的估计器。
- 一个纯Python数据处理函数，用于
  管道路径（清理/导出/重塑）-是否包装
  通过 `FunctionTransformer`, `skrub.@deferred` / `skrub.var`,
  自定义的“BaseEstimator”子类，或者只是在
  估计器之前的训练路径。
- 在某个步骤中添加、删除、交换或重新排序步骤
  现有管道声明。
- 裸露的“sklearn.Pipeline”/“make_pipeline”被用作
  顶层 — 触发重定向到 skrub DataOps 图表。
- 用户要求构建/声明/设置管道/
  X 的分类器/回归器。

跳过以下情况： `.fit(...)` 调用 / 训练循环 / `Trainer.fit` / epoch 循环；训练/测试分割或交叉验证分割；超参数搜索；持久性（`joblib.dump`，检查点）；评估/指标/评分；对预先训练的模型进行推理；纯EDA；没有具体声明的图书馆选择问题。
如何使用：在第一个声明行之前和每次结构编辑（添加/交换步骤、更改输入列、更改估计器系列）时进行咨询。不要再次咨询外观编辑。 **首先，阅读停止条件并在任何代码之前将飞行前检查表作为可见文本发出。** 在键入之前始终调用“python-api”来确认 skrub / sklearn 符号名称和签名 - 不要凭记忆猜测。
