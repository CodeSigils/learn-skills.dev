“此项目使用哪个 Python 环境管理器，以及如何使用它安装包？”的单一事实来源。拥有检测表（pixi/uv/poetry/hatch/conda+mamba/pip+venv）、每个管理器的安装/删除/升级命令，以及没有管理器时的引导路径（默认推荐：pixi）。停止在“安装命令是由正确的管理器发出的，并且包是可导入的”。
当（其中任何一个）触发：(1) **即将安装/添加/固定/升级/删除Python
    package** — `pip install`, `pixi add`, `uv add`, `poetry add`,
    `conda install` 等 - 在任何框架下；
(2) `data-science-python-stack` § “缺少依赖关系”浮出水面
    缺少导入和安装是下一步；
(3) 工作流程技能的停止条件因缺失而触发
    依赖项（`build-ml-pipeline`、`evaluate-ml-pipeline`、
    `组织-ml-工作空间`、`审核-ml-管道`);
(4) 开始一个新的Python项目并且还没有经理就位
    （除非用户另有选择，否则使用 pixi 进行引导）；
(5) `audit-ml-pipeline`（或另一个仅代理的消费者）需要
    **代理功能**（`ipython` + `pyright`），但还没有
    存在于项目清单中 - 请参阅§“代理功能”。

跳过以下情况：该项目是非 Python 的； install/add 命令适用于非 Python 工具（npm、brew、apt、cargo、gem）；依赖项已安装并且可以导入；这项工作纯粹是编辑现有的源代码，没有新的依赖关系。
如何使用：**先检测，然后安装**。在发出任何安装命令之前，请在项目根目录运行§“检测”表。如果未检测到管理器，请在引导之前询问用户。切勿使用与项目使用的管理器不同的管理器进行安装（例如，切勿将“pip install”安装到 pixi 管理的项目中）——这会造成清单无法跟踪的环境状态分歧。 **阅读“停止条件”块并在响应中以可见文本形式发出飞行前检查表 - 在发出任何命令之前两者都是强制性的。**
