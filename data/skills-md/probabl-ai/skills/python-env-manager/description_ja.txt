「このプロジェクトではどの Python 環境マネージャーが使用されているか、またそれを使用してパッケージをインストールするにはどうすればよいですか?」に関する唯一の信頼できる情報源。検出テーブル (pixi / uv / tongue/hatch / conda+mamba / pip+venv)、マネージャーごとのインストール / 削除 / アップグレード コマンド、およびマネージャーが存在しない場合のブートストラップ パス (デフォルトの推奨事項: pixi) を所有します。 「正しいマネージャーでインストール コマンドが発行され、パッケージはインポート可能です」で停止します。
(これらのいずれか) 場合にトリガーします: (1) **Python をインストール / 追加 / ピン留め / アップグレード / 削除しようとしている場合
    package** — `pip install`、`pixi add`、`uv add`、`poetry add`、
    「conda install」など — 任意のフレームの下で。
(2) `data-science-python-stack` § 「依存関係の欠落」が表面化
    インポートが不足している場合は、インストールが次のステップです。
(3) ワークフロー スキルの停止条件が欠落しているときに起動される
    依存関係 (`build-ml-pipeline`、`evaluate-ml-pipeline`、
    `organize-ml-workspace`、`audit-ml-pipeline`);
(4) 新しい Python プロジェクトを開始するが、マネージャーがまだ配置されていない
    (ユーザーが別の方法を選択しない限り、pixi でブートストラップします);
(5) 「audit-ml-pipeline」 (または別のエージェント専用コンシューマー) には、
    **エージェント機能** (`ipython` + `pyright`)、まだありません
    プロジェクトのマニフェストに存在します。§「エージェント機能」を参照してください。

次の場合はスキップします: プロジェクトが Python 以外である場合。 install/add コマンドは、Python 以外のツール (npm、brew、apt、cargo、gem) 用です。依存関係はすでにインストールされており、インポート可能です。作業は純粋に既存のソース コードを編集するだけであり、新たな依存関係はありません。
使用方法: **最初に検出し、次にインストールします**。インストール コマンドを発行する前に、プロジェクト ルートで §「検出」テーブルを実行します。マネージャーが検出されない場合は、ブートストラップする前にユーザーに問い合わせてください。プロジェクトで使用されているマネージャーとは異なるマネージャーを使用してインストールしないでください (たとえば、Pixi 管理プロジェクトに「pip install」しないでください)。これにより、マニフェストが追跡できない環境状態の相違が生じます。 **「停止条件」ブロックを読み、応答内の表示テキストとして飛行前チェックリストを出力します。どちらもコマンドを発行する前に必須です。**
