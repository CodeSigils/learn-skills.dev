「此專案使用哪個 Python 環境管理器，以及如何使用它來安裝套件？」的單一事實來源。擁有檢測表（pixi/uv/poetry/hatch/conda+mamba/pip+venv）、每個管理器的安裝/刪除/升級命令，以及沒有管理器時的引導路徑（預設建議：pixi）。停止在「安裝命令是由正確的管理器發出的，並且包是可導入的」。
當（其中任何一個）觸發：(1) **即將安裝/新增/固定/升級/刪除Python
    package** — `pip install`, `pixi add`, `uv add`, `poetry add`,
    `conda install` 等 - 在任何框架下；
(2) `data-science-python-stack` § 「缺少依賴關係」浮出水面
    缺少導入和安裝是下一步；
(3) 工作流程技能的停止條件因缺失而觸發
    依賴項（`build-ml-pipeline`、`evaluate-ml-pipeline`、
    `組織-ml-工作空間`、`審核-ml-管道`);
(4) 開始一個新的Python專案並且還沒有經理就位
    （除非使用者另有選擇，否則使用 pixi 進行引導）；
(5) `audit-ml-pipeline`（或另一個僅代理的消費者）需要
    **代理功能**（`ipython` + `pyright`），但還沒有
    存在於項目清單中 - 請參閱§「代理功能」。

跳過以下情況：該專案是非 Python 的；install/add 命令適用於非 Python 工具（npm、brew、apt、cargo、gem）；依賴項已安裝並且可以導入；這項工作純粹是編輯現有的源代碼，沒有新的依賴關係。
使用方法：**先檢測，然後安裝**。在發出任何安裝命令之前，請在項目根目錄中執行§「檢測」表。如果未偵測到管理器，請在引導之前詢問使用者。切勿使用與專案使用的管理器不同的管理器進行安裝（例如，切勿將「pip install」安裝到 pixi 管理的專案中）—這會造成清單無法追蹤的環境狀態分歧。 **閱讀「停止條件」區塊並在回應中以可見文字形式發出飛行前檢查表 - 在發出任何命令之前兩者都是強制性的。 **
