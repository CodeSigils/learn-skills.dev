このスタックの Python コード スタイルを所有します。lint + format の場合は ruff、docstring の場合は numpydoc です。 3 つの責任 — (1) スタックとワークスペースが準備できたら、バンドルされたテンプレートからプロジェクトの `ruff.toml` を配置する、(2) クロードが生成または編集したばかりの Python ファイルに対して ruff を実行する、(3) タッチされた各ファイルのコメントをデータ サイエンスの問題に文脈化する — 残ったテンプレート / ワークフローの文章 (スキル名、ゲート、ランナー、ダイジェスト、ガードレール) を簡潔で問題固有のドキュメントに書き換えて、ユーザーがコミットしたファイルが生成された足場のように読むのではなく、同僚が書いたように読んでください。 「タッチされたファイルは「ラフチェック」に合格し、プロセスではなく問題を文書化します。」で停止します。
(これらのいずれか) 場合にトリガーします: (1) Python ファイルが作成されたばかり、または書き込み / 編集 / 経由で編集されたばかり
    MultiEdit — タスクの完了を宣言する前にこのスキルを呼び出します。
    ruff が実行され、かつファイルのコメントがコンテキストに合わせて解釈されます。
    問題;
(2) 新しい ML ワークスペースが次のように足場を構築されました。
    `organize-ml-workspace` であり、プロジェクトには `ruff.toml` がありません
    ルートはまだです — バンドルされたテンプレートを削除します。
(3) ユーザーが lint、フォーマット、docstring スタイル、またはリーチについて質問する
    `black` / `isort` / `flake8` / `pydocstyle` の場合 (へリダイレクト
    ruff — スタックの正規リンター、所有者
    `data-science-python-stack` 層 1)。

次の場合はスキップします: プロジェクトが Python 以外である場合。このターンでの編集は Markdown / TOML / JSON / YAML のみです。ファイルは、ユーザーが所有していないサードパーティ製のディレクトリに存在します。
使用方法: 先ほど触れたファイルに対して ruff を手動で実行します。このために PostToolUse フックを設定しないでください。 **「停止条件」ブロックを読み、応答内の表示テキストとして飛行前チェックリストを出力します。どちらも ruff を実行する前に必須です。**
