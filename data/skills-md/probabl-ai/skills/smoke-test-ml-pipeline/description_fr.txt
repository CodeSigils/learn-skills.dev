Possède le contrat de test de fumée pour une expérience ML : un petit pytest de diagnostic par construction qui adapte l'apprenant de l'expérience sur une partie de la source réelle de « données/ » et prédit sur une partie *disjointe* qui ne contient délibérément **aucun tampon pré-historique**. L'affirmation est structurelle : le nombre de prédictions doit être égal au nombre de lignes dans la grille de prédiction. Un pipeline qui charge puis divise les fonctionnalités supprimera silencieusement les lignes de démarrage à froid de la tranche de prédiction et le test échouera avec une inadéquation du nombre de lignes ; un pipeline qui marque X tôt et fait référence aux nœuds d'historique en amont à partir des étapes de fonctionnalité passera de manière triviale. Le test de fumée est la preuve exécutable de la règle de placement du marqueur X de `build-ml-pipeline`.
DÉCLENCHEMENT lorsque : `test-ml-pipeline` a été envoyé ici pour écrire le test de fumée pour une expérience approuvée ; `pytest tests/smoke/` échoue sur le nombre de lignes ; l'utilisateur demande « pourquoi le test de fumée échoue-t-il ? » ; une modification de pipeline dans `build-ml-pipeline` nécessite une preuve exécutable ; un script d'expérimentation modifie la forme du pipeline et le test de fumée correspondant doit être revu.
SAUTER lorsque : la note de conception n'existe pas ou n'est pas encore approuvée (route vers `iterate-ml-experiment`) ; l'utilisateur pose des questions sur un test de régression ou un invariant de schéma (route vers `regression-test-ml-pipeline` / `distribution-test-ml-pipeline` une fois que ceux-ci existent) ; la question est l'*interprétation* des métriques CV, et non l'exactitude du temps de prévision (route vers `evaluate-ml-pipeline`).
COMMENT UTILISER : lisez d'abord les fichiers `journal/NN_*.md` et `experiments/NN_*.py` de l'expérience correspondante pour comprendre la liaison source du pipeline (à quelles clés env-dict `build_learner` s'attend-il ?). Ensuite, construisez deux env-dicts à partir de la **vraie `data/` source** — un env de train et un env de prédiction — de telle sorte que l'env de prédiction transporte *uniquement les lignes pour lesquelles nous voulons des prédictions* et *aucun tampon de pré-historique*. L'affirmation difficile est que le nombre de prédictions correspond exactement au nombre de lignes de prédiction-env. L'affirmation douce est que le MAE de l'ensemble de fumée se situe dans « 3 × CV_mean » (ou l'analogue approprié à la tâche). **N'écrivez pas de note de conception et n'exécutez pas de CV : c'est le travail d'autres compétences.**
