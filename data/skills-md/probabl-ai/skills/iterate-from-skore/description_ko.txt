`scratch/audit/<stem>/audit.md`(§ 4 ​​기록 결과에서 `audit-ml-pipeline`에 의해 생성됨)에서 **감사 다이제스트를 읽어** 다음 ML 실험 제안을 소싱합니다. '심각도'가 '문제' 또는 '팁'인 다이제스트의 '## 검사 요약'의 모든 행에 대해 행의 'documentation_url'을 따라 '항목'이 문서에서 권장하는 완화인 백로그 행의 초안을 작성하세요. `## Metrics summary`는 휴먼 요약 단락에 대한 컨텍스트를 제공하지만 자체적으로 백로그 행을 구동하지는 않습니다. 보강된 백로그 행 + 한 단락 요약을 다시 'iterate-ml-experiment'로 반환합니다. 이 경우 행을 'JOURNAL.md'에 기록하고 사용자가 'B<N>' 행을 승격할 수 있도록 소싱 메뉴를 다시 표시합니다. "백로그 강화, 요약 반환"에서 중지됩니다. 실험별로 설계 노트를 작성하지 않으며 "승리" 결과를 선택하지도 않습니다. 사용자는 `B<N>`을 통해 선택합니다.
TRIGGER 언제: `iterate-ml-experiment`가 소싱 전략을 선택하고 사용자가 메뉴에서 `skore`를 선택합니다. 사용자가 "보고서 마이닝", "skore에서 무엇을 볼 수 있나요?", "진단에서 백로그를 채우세요"라고 말합니다. 이전 실험이 완료되었으며 사용자는 보고서를 실행 가능한 백로그 항목으로 변환하기를 원합니다.
다음의 경우 건너뛰기: 이전 실험이 아직 실행되지 않았습니다(디스크에 감사 다이제스트가 없음). 사용자에게 구체적인 모델링 아이디어가 있습니다('사용자로부터 반복' 사용). 작업은 보고서 실행/열기의 *역학*입니다. `evaluate-ml-pipeline`으로 경로를 지정합니다. 사용자는 보고서의 특정 섹션에 대한 설명 읽기를 원합니다(`evaluate-ml-pipeline`으로 경로 지정).
사용 방법: 기존 `scratch/audit/<stem>/audit.md` 다이제스트를 텍스트로 읽습니다. skore 프로젝트를 다시 열지 말고 `report.*` 접근자를 호출하지 마세요. 심각도가 `issue` 또는 `tip`인 `## Checks summary` 섹션의 각 행에 대해 `documentation_url`(WebFetch를 통해)을 따르고 `audit:<stem>:checks.<code>`를 인용하는 하나의 백로그 행 초안을 작성합니다. 소스 인용을 기준으로 이미 'JOURNAL.md' 백로그에 있는 행에 대해 중복 제거를 수행합니다. 후보 행 + 한 문단으로 된 인간 요약을 반환합니다. 상위 기술은 'JOURNAL.md'에 행을 쓰고 소싱 메뉴를 다시 표시합니다.
