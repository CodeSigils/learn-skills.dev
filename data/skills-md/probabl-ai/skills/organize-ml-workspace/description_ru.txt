Решите, где будут храниться файлы в проекте эксперимента ML: многоразовый код в `src/<pkg>/`, один сценарий `# %%` на каждый эксперимент в `experiments/`, примечания к проектированию + индекс в `journal/`, отчеты в `reports/`, зонды только для агентов в `scratch/`. Владеет макетом, правилами создания файлов (один файл на эксперимент, уточняйте перед редактированием) и соглашением о сценариях jupytext `# %%`. Никогда не навязывает `data/` — этим владеет пользователь.
ТРИГГЕР — любое из следующих действий: — Запуск нового проекта машинного обучения или создание рабочего пространства. - Собираемся создать первый файл эксперимента в проекте. - Собираемся создать `src/<pkg>/data.py`/`features.py`/
  `pipeline.py` / `evaluate.py` впервые.
- Собираюсь написать `.ipynb` для экспериментов — перенаправить на
  Сценарий `# %%` в разделе `experiments/`.
- Пользователь спрашивает, где что-то должно находиться, как организовать
  проект или как настроить рабочее пространство.
- Собирается добавить новую итерацию эксперимента — решите, новый файл или
  редактировать существующие (спрашивать у пользователя).

ПРОПУСКАТЬ, когда: файл явно является частью уже заполненного модуля (например, добавление функции к существующему `features.py`); чистый рефакторинг внутри одного существующего файла; механика объявления конвейера (`build-ml-pipeline`); механика оценки (evavalate-ml-pipeline); Поиск символа оценки (`python-api`).
