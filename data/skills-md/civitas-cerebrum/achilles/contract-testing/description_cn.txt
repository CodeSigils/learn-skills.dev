每当测试中使用后端 HTTP 端点时使用 - 编写、运行、审查或只是调用。该技能拥有每个 API 交互应产生的结构化形状：状态代码期望、响应模式断言、错误信封验证、标头覆盖。它会在显式意图触发器（合同测试、模式测试、契约、OpenAPI 一致性、锁定 API 合同、验证 API 形状、破坏性变更检测、消费者驱动合同、提供者验证、API 兼容性、规范一致性、确保 API 未更改）以及调用“steps.apiGet”、“steps.apiPost”、“steps.apiPut”、“steps.apiDelete”、“steps.apiPatch”的任何测试或计划测试上自动激活， `steps.apiHead`、`steps.verifyApiStatus` 或 `steps.verifyApiHeader` — 即使在 UI 流规范中也是如此。基本原理：每个后端调用至少应该有一个状态代码+错误信封断言；如果没有这些，当端点回归时，测试会默默地通过。还会在表示后端交互即将落地的短语上激活：“在测试中调用 API”、“针对后端进行测试”、“使用 API”、“验证响应”、“断言 JSON 形状”、“验证 API 响应”、“锁定后端的响应”、“端点应该返回”以及针对规范上下文内的项目 URL 的任何 HTTP 动词提及。真实路由：element-interactions 的伴随技能表（在此处路由契约意图）、直接用户意图和 test-composer 的 Step-3 实现规则，每当变体发出“steps.api*”行时，该规则就会通过技能工具调用此技能，而不是将契约形状视为可选。不适合：纯粹的 UI 流断言、旅程范围的覆盖范围扩展、页面级别的错误搜索或失败测试诊断 - 这些都取决于他们自己的技能。
