**WORKFLOW-FÄHIGKEIT** – Verknüpfen Sie einen Aspire AppHost, nachdem „aspire init“ ein Skelett abgelegt hat. Scannt das Repo, schlägt ein Ressourcendiagramm vor, bearbeitet den AppHost (C#, dateibasiertes C# oder TypeScript), verbindet „Aspire.ServiceDefaults“ + OTel, validiert mit „aspire start“ und deaktiviert sich dann selbst. VERWENDUNG FÜR: AppHost verkabeln, Ressourcendiagramm gerüsten, Postgres/Redis/Rabbit/Mongo zu Aspire hinzufügen, Frontend mit API verbinden, nach „aspire init“ was kommt als nächstes, AddNextJsApp, AddViteApp, WithBrowserLogs, dateibasiertes apphost.cs, apphost.ts, mit der Umgebung vereinheitlicht, .aspire/modules-Bearbeitung verweigern, .env-Dateien migrieren, Benutzergeheimnisse migrieren. NICHT VERWENDEN FÜR: Skeleton Drop (verwenden Sie aspire-init), Starten/Stoppen/Warten/Neustarten (verwenden Sie aspire-orchestration), Veröffentlichen/Bereitstellen/Zerstören (verwenden Sie aspire-deployment), Protokolle/Traces (verwenden Sie aspire-monitoring). AUFRUFE: Aspire CLI (Hinzufügen, Starten, Warten, Beschreiben, Dokumenten-API-Suche, Stopp), AppHost-Quellenbearbeitung, ServiceDefaults-Verkabelung. FÜR EINZELNE VORGÄNGE: Führen Sie „aspire add PACKAGE“ direkt für eine einmalige Integration aus.
