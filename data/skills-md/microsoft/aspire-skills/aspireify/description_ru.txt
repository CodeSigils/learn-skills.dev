**НАВЫКИ РАБОЧЕГО ПРОЦЕССА**. Подключайте Aspire AppHost после того, как `aspire init` удаляет скелет. Сканирует репозиторий, предлагает граф ресурсов, редактирует AppHost (C#, файловый C# или TypeScript), подключает `Aspire.ServiceDefaults` + OTel, проверяет с помощью `aspire start`, а затем самодеактивируется. ИСПОЛЬЗОВАНИЕ ДЛЯ: подключения AppHost, графа ресурсов scaffold, добавления Postgres/Redis/Rabbit/Mongo в Aspire, подключения внешнего интерфейса к API, после `aspire init` что дальше, AddNextJsApp, AddViteApp, WithBrowserLogs, файлового apphost.cs, apphost.ts, унифицированного withEnvironment, отказа от редактирования .aspire/modules, переноса файлов .env, переноса пользовательских секретов. НЕ ИСПОЛЬЗУЙТЕ ДЛЯ: удаления скелета (используйте aspire-init), запуска/остановки/ожидания/перезапуска (используйте aspire-orchestration), публикации/развертывания/уничтожения (используйте aspire-deployment), журналов/трассировок (используйте aspire-monitoring). ВЫЗОВЫ: aspire CLI (добавление, запуск, ожидание, описание, поиск API документации, остановка), редактирование исходного кода AppHost, подключение ServiceDefaults. ДЛЯ ОДИНОЧНЫХ ОПЕРАЦИЙ: запустите `aspire add PACKAGE` напрямую для одноразовой интеграции.
