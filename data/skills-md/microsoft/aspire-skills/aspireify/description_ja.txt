**ワークフロー スキル** - 「aspire init」がスケルトンをドロップした後、Aspire AppHost を接続します。リポジトリをスキャンし、リソース グラフを提案し、AppHost (C#、ファイルベースの C#、または TypeScript) を編集し、`Aspire.ServiceDefaults` + OTel を接続し、`aspire start` で検証し、その後自己非アクティブ化します。用途: AppHost の接続、リソース グラフのスキャフォールディング、Aspire への Postgres/Redis/Rabbit/Mongo の追加、API へのフロントエンドの接続、「aspire init」の後の次の処理、AddNextJsApp、AddViteApp、WithBrowserLogs、ファイルベースの apphost.cs、apphost.ts、withEnvironment の統合、.aspire/modules の編集の拒否、.env ファイルの移行、ユーザー シークレットの移行。次の用途には使用しないでください: スケルトンのドロップ (aspire-init を使用)、開始/停止/待機/再起動 (aspire-orchestration を使用)、パブリッシュ/デプロイ/破棄 (aspire-deployment を使用)、ログ/トレース (aspire-monitoring を使用)。呼び出し: aspire CLI (追加、開始、待機、説明、ドキュメント API 検索、停止)、AppHost ソース編集、ServiceDefaults ワイヤリング。単一操作の場合: 1 回限りの統合の場合は、「aspire add PACKAGE」 を直接実行します。
