**COMPÉTENCE DE FLUX DE TRAVAIL** - Câblez un Aspire AppHost après que `aspire init` ait laissé tomber un squelette. Analyse le dépôt, propose un graphique de ressources, édite l'AppHost (C#, C# basé sur des fichiers ou TypeScript), connecte `Aspire.ServiceDefaults` + OTel, valide avec `aspire start`, puis s'auto-désactive. UTILISER POUR : câbler AppHost, graphique de ressources d'échafaudage, ajouter Postgres/Redis/Rabbit/Mongo à Aspire, connecter l'interface frontale à l'API, après `aspire init` et ensuite, AddNextJsApp, AddViteApp, WithBrowserLogs, apphost.cs basé sur des fichiers, apphost.ts, unifié avec l'environnement, refuser la modification .aspire/modules, migrer les fichiers .env, migrer l'utilisateur secrets. NE PAS UTILISER POUR : le dépôt de squelette (utilisez aspire-init), le démarrage/arrêt/attente/redémarrage (utilisez aspire-orchestration), la publication/déploiement/destroy (utilisez aspire-deployment), les journaux/traces (utilisez aspire-monitoring). INVOKES : aspire CLI (ajouter, démarrer, attendre, décrire, recherche d'API dans la documentation, arrêter), modifications de la source AppHost, câblage ServiceDefaults. POUR DES OPÉRATIONS UNIQUES : exécutez `aspire add PACKAGE` directement pour une intégration unique.
