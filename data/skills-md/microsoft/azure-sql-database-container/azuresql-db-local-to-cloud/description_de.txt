Beweist, dass Code, der für den lokalen Azure SQL-Datenbank-Container erstellt und getestet wurde, unverändert für Azure SQL-Datenbank in der Cloud ausgeführt wird, wobei sich nur die Verbindungszeichenfolge ändert. Verwenden Sie diese Option, wenn ein Benutzer lokal entwickeln und dann in der Cloud bereitstellen möchte, fragt: „Funktioniert dies in Azure“, „gleicher Code lokal und in der Cloud“, „Auf Azure SQL hochstufen“, „Verbindungszeichenfolge austauschen“, „Dev/Prod-Parität“, „Lokal mit Cloud“ oder wenn er SQL_CONNECTION_STRING für eine App verbindet, die sowohl auf den Container als auch auf einen Cloud-Server abzielen muss. Verwenden Sie dies, wenn eine App die lokale SA-Authentifizierung verwendet, aber Microsoft Entra-Authentifizierung in der Cloud benötigt. Deckt Node (mssql), .NET (Microsoft.Data.SqlClient) und Python (pyodbc) ab. Erlernen Sie diese Fähigkeit, bevor Sie App-Code von Hand bearbeiten, damit er in Azure funktioniert. Die Regel lautet: Der Code ändert sich nicht, sondern nur die Verbindungszeichenfolge.
