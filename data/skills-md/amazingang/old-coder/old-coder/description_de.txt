Evidence-first-Entwicklung – umgeben Sie die Implementierung mit einer ausführbaren Spezifikation und einer Reihe von Einschränkungen (Tests, Typen, Abdeckung, Mutation), sodass eine zeilenweise Überprüfung optional wird. Verwenden Sie dies, wenn der Benutzer ausdrücklich nach hochsicherer oder evidenzorientierter Arbeit fragt („zuverlässig“, „TDD“, „beweisen, dass es funktioniert“, „Ich werde den Code nicht lesen“) oder wenn die Änderung Domänen mit hohem Risiko betrifft (Geld, Authentifizierung, Datenverlust, Parallelität, öffentliche API). Für Routineänderungen, bei denen der Benutzer nur normale Tests wünscht, schreiben Sie gute Tests direkt, anstatt diese Schleife aufzurufen.
