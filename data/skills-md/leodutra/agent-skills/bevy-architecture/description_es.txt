Método de arquitectura para proyectos de juegos Bevy (Rust ECS), basado en cómo funciona realmente Bevy 0.18+ en lugar de forzar DDD/Clean Architecture en un ECS. Utilice esta habilidad siempre que diseñe, estructure, refactorice o revise cualquier código base de Bevy; decidir dónde debe vivir un sistema/componente/recurso; elegir entre Mensajes, Observadores o mutación directa; componentes de modelado y estado del juego; configurar horarios, estados, activos, configuraciones, guardados, determinismo, redes o IA. Actívelo para preguntas como "¿cómo debo estructurar mi juego de Bevy?", "¿a dónde va este sistema?", "¿este código de Bevy está sobrediseñado" o cualquier decisión sobre el diseño de carpeta/módulo/complemento de Bevy, incluso cuando no se utiliza la palabra "arquitectura".
