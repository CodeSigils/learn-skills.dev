Aplique el Modern Architecture Blueprint (2026), un método pragmático centrado en el dominio para diseñar sistemas de software de larga duración. Cubre monolitos modulares, carpetas de características de corte vertical, modelado de dominio basado en tipos (nuevos tipos, objetos de valor, analizar-no-validar, hacer-estados-ilegales-unrepresentables), políticas, eventos de dominio, modelos de consistencia explícitos, idempotencia, núcleo funcional/shell imperativo, funciones de idoneidad de la arquitectura y ADR. Utilice esta habilidad siempre que el usuario esté diseñando, realizando andamios, estructurando, refactorizando o revisando la arquitectura de un sistema backend o full-stack; decidir el diseño de carpetas o módulos; sopesar abstracciones como repositorios, CQRS, microservicios o abastecimiento de eventos; modelar un dominio empresarial; o decidir cómo deben comunicarse los módulos. Actívelo para preguntas como "¿cómo debería estructurar este servicio?", "dónde debería residir este código" o "¿está sobredimensionado?", incluso cuando la palabra arquitectura nunca se use. Especialmente relevante para los servicios TypeScript/Node, Rust y Python.
