Appliquez le Modern Architecture Blueprint (2026), une méthode pragmatique axée sur le domaine pour concevoir des systèmes logiciels à long terme. Couvre les monolithes modulaires, les dossiers de fonctionnalités à tranches verticales, la modélisation de domaine basée sur le type (nouveaux types, objets de valeur, analyse sans validation, rendre les états illégaux non représentables), les politiques, les événements de domaine, les modèles de cohérence explicites, l'idempotence, le noyau fonctionnel/coquille impérative, les fonctions d'adéquation de l'architecture et les ADR. Utilisez cette compétence chaque fois que l'utilisateur conçoit, échafaude, structure, refactorise ou révise l'architecture d'un système backend ou full-stack ; décider de la disposition des dossiers ou des modules ; peser les abstractions telles que les référentiels, les CQRS, les microservices ou le sourcing d'événements ; modéliser un domaine métier ; ou décider comment les modules doivent communiquer. Déclenchez-le pour des questions telles que « comment dois-je structurer ce service », « où ce code doit-il résider » ou « est-ce sur-conçu », même lorsque le mot architecture n'est jamais utilisé. Particulièrement pertinent pour les services TypeScript/Node, Rust et Python.
