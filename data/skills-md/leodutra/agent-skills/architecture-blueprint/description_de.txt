Wenden Sie den Modern Architecture Blueprint (2026) an, eine pragmatische domänenorientierte Methode zum Entwerfen langlebiger Softwaresysteme. Behandelt modulare Monolithe, Vertical-Slice-Feature-Ordner, typgesteuerte Domänenmodellierung (neue Typen, Wertobjekte, Parse-Don't-Validate, Make-Illegal-States-Unrepresentable), Richtlinien, Domänenereignisse, explizite Konsistenzmodelle, Idempotenz, Functional-Core/Imperative-Shell, Architektur-Fitnessfunktionen und ADRs. Verwenden Sie diese Fähigkeit immer dann, wenn der Benutzer die Architektur eines Backend- oder Full-Stack-Systems entwirft, ein Gerüst baut, strukturiert, umgestaltet oder überprüft. Festlegung des Ordner- oder Modullayouts; Abwägen von Abstraktionen wie Repositories, CQRS, Microservices oder Event Sourcing; Modellierung einer Geschäftsdomäne; oder entscheiden, wie Module kommunizieren sollen. Lösen Sie es bei Fragen aus wie „Wie soll ich diesen Dienst strukturieren“, „Wo soll dieser Code leben“ oder „Ist das überentwickelt?“, auch wenn das Wort „Architektur“ nie verwendet wird. Besonders relevant für TypeScript/Node-, Rust- und Python-Dienste.
