Applicare il Modern Architecture Blueprint (2026), un metodo pragmatico basato sul dominio per progettare sistemi software di lunga durata. Copre monoliti modulari, cartelle di funzionalità a porzioni verticali, modellazione di domini basata sul tipo (newtype, oggetti valore, parse-don't-validate, make-illegal-states-unrepresentable), policy, eventi di dominio, modelli di coerenza espliciti, idempotenza, core funzionale/shell imperativa, funzioni di idoneità dell'architettura e ADR. Utilizzare questa competenza ogni volta che l'utente progetta, esegue l'impalcatura, la strutturazione, il refactoring o la revisione dell'architettura di un sistema backend o full-stack; decidere il layout di cartelle o moduli; valutare astrazioni come repository, CQRS, microservizi o sourcing di eventi; modellare un dominio aziendale; o decidere come i moduli dovrebbero comunicare. Attivalo per domande come "come dovrei strutturare questo servizio", "dove dovrebbe vivere questo codice" o "è troppo ingegnerizzato" anche quando la parola architettura non viene mai utilizzata. Particolarmente rilevante per i servizi TypeScript/Node, Rust e Python.
