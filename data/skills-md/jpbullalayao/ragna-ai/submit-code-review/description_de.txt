Veröffentlichen Sie die Ergebnisse aus der /self-code-review-Ausgabe der aktuellen Konversation als GitHub PR-Kommentare zum Pull-Request des aktuellen Zweigs. Verwenden Sie NACH dem Ausführen von /self-code-review, wenn der Benutzer /submit-code-review eingibt oder auffordert, „die Bewertung einzureichen“, „die Kommentare auf GitHub zu posten“ oder „die Bewertung an die PR zu senden“. Analysiert den Unterschied NICHT erneut, sondern liest die bereits im Gespräch vorhandenen Erkenntnisse. Filtert optional nach einem vom Benutzer bereitgestellten Fokusbereich. Priorisiert Inline-PR-Überprüfungskommentare (angehängt an die spezifische Datei und Zeile), bei denen ein file:line-Zitat vorhanden ist; greift auf normale PR-Gesprächskommentare zurück, wenn kein Zitat verfügbar ist oder der Inline-Beitrag fehlschlägt. Jeder Kommentar beginnt mit „_Comment from Claude Code agent · [Model]_“ in Kursivschrift (wobei [Model] der Kurzname des aktuell ausgeführten Claude-Modells ist, z. B. „Sonnet 4.6“, „Opus 4.7“, „Haiku 4.5“), zwei Leerzeilen, dann „non-blocking“ (Standard) oder „blocking“ (nur wenn der Benutzer dies ausdrücklich angibt) und dann das Ergebnis in einer neuen Zeile. Erfordert bei GitHub authentifizierte „gh“-CLI.
