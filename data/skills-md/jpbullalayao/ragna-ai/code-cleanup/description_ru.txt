Анализируйте разницу текущей ветки с ее базовой веткой (веткой, указанной пользователем, если она указана, в противном случае — базовой веткой открытого PR, в противном случае веткой по умолчанию репозитория) и автоматически исправляйте возможности очистки в трех областях: краткость и качество кода, потенциальные регрессии и работоспособность CI/сборки. Используйте, когда пользователь запускает /code-cleanup [<ветвь>] или просит «очистить код», «упростить эти изменения» или «доработать эту ветку». Перед применением исправлений пользователю сообщается о результатах по каждой области. Автоматические исправления соответствуют той планке, которую одобрил бы штатный инженер: консервативны, сохраняют поведение и четко мотивированы. Для больших различий (>300 строк или >15 файлов) сначала вызывается /simplify. Для файлов React в diff вызывает /react-doctor перед применением исправлений.
