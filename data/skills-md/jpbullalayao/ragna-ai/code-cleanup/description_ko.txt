현재 브랜치의 기본 브랜치(제공된 경우 사용자 지정 브랜치, 그렇지 않은 경우 공개 PR의 기본 브랜치, 그렇지 않은 경우 저장소의 기본 브랜치)에 대한 차이점을 분석하고 코드 간결성 및 품질, 잠재적인 회귀, CI/빌드 상태 등 세 가지 영역에 걸쳐 자동 수정 정리 기회를 제공합니다. 사용자가 /code-cleanup [<branch>]를 실행하거나 "코드 정리", "이 변경 사항 단순화" 또는 "이 분기 개선"을 요청할 때 사용합니다. 수정 사항을 적용하기 전에 영역별 결과를 사용자에게 설명합니다. 자동 수정은 직원 수준의 엔지니어가 승인하는 기준, 즉 보수적이고 행동을 보존하며 명확한 동기를 충족합니다. 큰 차이점(>300줄 또는 >15개 파일)의 경우 먼저 /simplify를 호출합니다. diff에 있는 React 파일의 경우 수정 사항을 적용하기 전에 /react-doctor를 호출합니다.
