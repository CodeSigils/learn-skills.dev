ベース ブランチ (指定されている場合はユーザー指定のブランチ、それ以外の場合はオープン PR のベース ブランチ、それ以外の場合はリポジトリのデフォルト ブランチ) に対する現在のブランチの差分を分析し、コードの簡潔さと品質、潜在的な回帰、CI/ビルドの健全性の 3 つの領域にわたる自動修正クリーンアップの機会を分析します。ユーザーが /code-cleanup [<branch>] を実行する場合、または「コードをクリーンアップする」、「これらの変更を簡素化する」、または「このブランチを洗練する」ように要求する場合に使用します。修正を適用する前に、領域ごとの結果の概要をユーザーに示します。自動修正はスタッフレベルのエンジニアが承認する基準を満たしており、保守的で行動を維持し、明確に動機付けられています。大きな差分 (>300 行または >15 ファイル) の場合は、最初に /simplify を呼び出します。 diff 内の React ファイルの場合、修正を適用する前に /react-doctor を呼び出します。
