Analice la diferencia de la rama actual con su rama base (una rama especificada por el usuario, si se proporciona; de lo contrario, la rama base del PR abierto; de lo contrario, la rama predeterminada del repositorio) y corrija automáticamente las oportunidades de limpieza en tres áreas: brevedad y calidad del código, regresiones potenciales y CI/salud de la compilación. Úselo cuando el usuario ejecuta /code-cleanup [<branch>], o solicita "limpiar el código", "simplificar estos cambios" o "pulir esta rama". Describe los hallazgos por área para el usuario antes de aplicar las correcciones. Las reparaciones automáticas cumplen con el estándar que aprobaría un ingeniero a nivel de personal: conservadoras, preservadoras del comportamiento y claramente motivadas. Para diferencias grandes (>300 líneas o >15 archivos), primero invoca /simplify. Para archivos React en la diferencia, invoca /react-doctor antes de aplicar las correcciones.
