Golang-Refactoring – der sichere, maßstabsgetreue Prozess zur Umstrukturierung vorhandener Go-Codes: ein an die Abdeckung anpassbares Sicherheitsnetz, werkzeuggesteuerte verhaltenserhaltende Transformationen (gopls Rename/Inline/Extract, „gofmt -r“, „eg“, „gopatch“, „go/analysis“-Fixer), der auf Go abgebildete Fowler-Katalog, Unterbrechen von Importzyklen, Verschieben von Typen über Pakete hinweg und ein kleiner Human-in-the-Loop-Workflow gestapelte PRs auf einem Refactoring-Zweig. Wenden Sie es an, wenn Code schwer zu warten ist, eine Funktion/ein Typ zu groß geworden ist, ein Codegeruch behoben werden muss, das Hinzufügen einer Funktion durch die aktuelle Struktur blockiert wird oder der Benutzer Go-Code bereinigen, umgestalten oder verbessern möchte – auch zum Umbenennen in großem Maßstab, zum Extrahieren von Funktionen/Schnittstellen, zum Verschieben von Code zwischen Paketen, zum Aufteilen von Paketen oder zum Planen eines mehrstufigen Refaktors. Zielstile, die sich an anderer Stelle befinden → Siehe „samber/cc-skills-golang@golang-naming“ (umbenannt), „@golang-project-layout“ (Splits), „@golang-modernize“ (Redewendungen), „@golang-code-style“ (Kontrollfluss), „@golang-design-patterns“ (Muster/DI).
