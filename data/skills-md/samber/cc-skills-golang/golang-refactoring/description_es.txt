Refactorización de Golang: el proceso seguro a escala para reestructurar el código Go existente: una red de seguridad que se adapta a la cobertura, transformaciones impulsadas por herramientas que preservan el comportamiento (gopls Rename/Inline/Extract, `gofmt -r`, `eg`, `gopatch`, `go/analysis` fixers), el catálogo de Fowler asignado a Go, rompiendo los ciclos de importación, moviendo tipos entre paquetes y un flujo de trabajo humano en el bucle de pequeños apilados RP en una rama de refactorización. Aplicar cuando el código es difícil de mantener, una función/tipo ha crecido demasiado, es necesario corregir un olor a código, la estructura actual bloquea la adición de una característica o el usuario solicita limpiar, refactorizar o mejorar el código Go; también para cambiar el nombre a escala, extraer funciones/interfaces, mover código entre paquetes, dividir paquetes o planificar una refactorización de varios pasos.
