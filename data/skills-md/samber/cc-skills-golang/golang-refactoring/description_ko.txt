Golang 리팩토링 — 기존 Go 코드를 재구성하기 위한 안전한 규모에 맞는 프로세스: 적용 범위 적응형 안전망, 도구 기반 동작 보존 변환(gopls Rename/Inline/Extract, `gofmt -r`, `eg`, `gopatch`, `go/analytic` 수정 프로그램), Go에 매핑된 Fowler 카탈로그, 가져오기 주기 중단, 패키지 간 유형 이동, 작은 스택 PR의 인간 참여 루프 워크플로 리팩토링 지점에서. 코드를 유지 관리하기 어렵거나, 함수/유형이 너무 커졌거나, 코드 냄새를 수정해야 하거나, 기능 추가가 현재 구조에 의해 차단되거나, 사용자가 Go 코드 정리, 리팩터링 또는 개선을 요청하는 경우에 적용하세요. 또한 대규모 이름 변경, 함수/인터페이스 추출, 패키지 간 코드 이동, 패키지 분할 또는 다단계 리팩터링 계획에도 적용됩니다. 다른 곳에서 소유한 스타일 대상 지정 → `samber/cc-skills-golang@golang-naming`(이름 변경), `@golang-project-layout`(분할), `@golang-modernize`(관용구), `@golang-code-style`(제어 흐름), `@golang-design-patterns`(패턴/DI)를 참조하세요.
