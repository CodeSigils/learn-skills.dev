内部 — スタッフのツールを回収します。顧客対応やアーティストからのリクエストには決して使用しないでください。シグナルの高い GitHub の問題、特に複数 PR や複数リポジトリの取り組みを調整する長期にわたる追跡問題を、Recoup ハウス スタイルで作成して保守します。ユーザーが「問題を書く」、「追跡問題を作成する」、「この作業について問題を開く」、「問題を更新する」、「項目をチェックオフ/クローズする」、「問題に何が出荷されたかを記録する」、「問題を保守する」と言う場合、または複数の PR にまたがる計画、カットオーバー、移行、またはクリーンアップをキャプチャする場合に使用します。構造、Open→Done ライフサイクル、証拠/リンク ルール、および承認基準について説明します。
