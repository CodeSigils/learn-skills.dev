Impalcatura ed esecuzione del "sistema operativo dell'azienda musicale" autogestito di un'etichetta all'interno del proprio repository git: l'intero spazio di lavoro di intelligenza dell'etichetta (cartelle, un CLAUDE.md autogestito rispecchiato su AGENTS.md, un medico di sola lettura + bidello mai obsoleto, cicli di apprendimento composto e auto-miglioramento, un plug-in sul posto) seminato con le convenzioni di Recoup (livello superiore artisti/{slug}/RECOUP.md file di identità, releases/{slug}/RELEASE.md) e supportati dall'API Recoup come sistema di registrazione. Utilizzare per "configurare il nostro sistema operativo dell'etichetta", "costruire l'area di lavoro dell'organizzazione", "trasformare questo repository nel nostro cervello dell'etichetta" o per l'onboarding di un nuovo repository dell'organizzazione/etichetta. Estrae il roster reale dall'account live (autenticazione tramite recoup-platform-connect-account), inserisce prima l'API degli artisti tramite recoup-roster-add-artist e chiama le altre abilità di recupero-* (ricerca/contenuto/rilascio/canzone/catalogo) invece di reinventarle. Il builder di area di lavoro/sistema operativo singolo: copre anche il caso leggero "basta eseguire il mirroring del mio elenco nelle cartelle".
