Аудит поверхности библиотеки, CLI, SDK или npm, обращенной к разработчику, по эргономике API и SDK, сообщениям об ошибках, которые видят разработчики, пользовательскому интерфейсу CLI, эргономике типов, установке и первому запуску, а также эргономике настройки. 27 правил, отправляемых по префиксу; сообщает о результатах по файлам и местоположениям с указанием уровней воздействия и конкретных исправлений. Используйте, когда вас просят «проверить мой CLI», «эргономичен ли этот API», «просмотреть опыт разработчика», «улучшить эти сообщения об ошибках», «легко ли внедрить этот SDK», «легко ли установить этот пакет» или «проверить DX моей библиотеки». Для качества пользовательского интерфейса конечного пользователя и пользовательского интерфейса React/Next используйте ui-audit, для пользовательского интерфейса агентского приложения используйте ax-audit, для написания документации используйте docs-writing, для README используйте readme-creator, для AGENTS.md используйте агенты-md, а для структуры репо используйте define-architecture.
