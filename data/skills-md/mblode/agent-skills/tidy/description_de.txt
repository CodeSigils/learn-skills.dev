Verteilt vier gleichzeitige Überprüfungsagenten über das aktuelle Diff, wendet dann Korrekturen direkt auf den Arbeitsbaum an und überprüft den Build. Mutiert Code; Es wird kein Bericht erstellt. Behandelt Wiederverwendung (doppelte Logik, handgerollte stdlib, neu erfundene Plattformfunktionen), Qualität (hackige Muster, React/TypeScript-Hygiene, übermäßige Memoisierung, erschöpfende Deps, „beliebig“, toter Code, „CLAUDE.md“/„AGENTS.md“-Verstöße), Effizienz (unnötige Arbeit, verpasste Parallelität, Hot-Path-Bloat) und Testdisziplin (Fehlerbehebungen ohne Repro-Test, nutzlose Tests). löschen, fehlende Tests nur, wenn sie einen benannten Fehler verhindern). Wird verwendet, wenn der Benutzer „Aufräumen“, „Vereinfachen“, „Diesen Unterschied bereinigen“, „Meine Änderungen aufpolieren“, „Auf Duplikate prüfen“ oder „Wiederverwendungsmöglichkeiten?“ sagt, d. h. wenn die Absicht besteht, die Änderungen automatisch vorzunehmen. Für einen schreibgeschützten Bericht, der Ergebnisse auflistet, ohne Dateien zu berühren, verwenden Sie stattdessen „pr-reviewer“.
