Crée des requêtes pull GitHub avec des descriptions courtes à consonance humaine. Ajoute un préfixe d'ID de problème linéaire lorsqu'il est disponible, conserve les titres sous 60 caractères et utilise par défaut un court paragraphe au lieu de résumés générés ou de sections de plan de test. Restructure l'historique des validations bruyantes dans un ordre révisable et ajoute des conseils aux réviseurs pour les différences importantes. À utiliser lorsque « créer un PR », « faire un PR », « ouvrir une pull request », « PR ceci », « l'expédier », « rendre ce PR facile à réviser », « peaufiner ce PR », « ranger le PR », « nettoyer les commits », « restructurer les commits » ou « diviser ce PR ». Pour examiner une différence à la recherche de bogues, utilisez pr-reviewer. Pour surveiller un PR après sa création, utilisez pr-babysitter. Pour les versions npm, utilisez la livraison automatique.
