Erstellt GitHub-Pull-Requests mit kurzen, menschlich klingenden Beschreibungen. Fügt ein lineares Issue-ID-Präfix hinzu, sofern verfügbar, hält Titel unter 60 Zeichen und verwendet standardmäßig einen kurzen Absatz anstelle generierter Zusammenfassungen oder Testplanabschnitte. Strukturiert den verrauschten Commit-Verlauf in eine überprüfbare Reihenfolge um und fügt Prüferanleitungen für große Unterschiede hinzu. Wird verwendet, wenn „eine PR erstellen“, „eine PR erstellen“, „eine Pull-Anfrage öffnen“, „diese PR erstellen“, „versenden“, „diese PR leicht überprüfen lässt“, „diese PR aufpolieren“, „die PR aufräumen“, „Commits bereinigen“, „Commits neu strukturieren“ oder „diese PR aufteilen“. Um ein Diff auf Fehler zu überprüfen, verwenden Sie PR-Reviewer. Um eine PR nach der Erstellung zu überwachen, verwenden Sie pr-babysitter. Verwenden Sie für NPM-Releases Autoship.
