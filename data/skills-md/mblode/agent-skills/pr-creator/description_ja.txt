人間らしい短い説明を含む GitHub プル リクエストを作成します。利用可能な場合はリニア問題 ID プレフィックスを追加し、タイトルを 60 文字未満に保ち、生成された概要やテスト計画セクションの代わりに 1 つの短い段落をデフォルトにします。ノイズの多いコミット履歴をレビュー可能な順序に再構築し、大きな差分に対するレビュー担当者のガイダンスを追加します。 「PR を作成する」、「PR を作成する」、「プル リクエストを開く」、「これを PR する」、「出荷する」、「この PR をレビューしやすくする」、「この PR を磨き上げる」、「PR を整理する」、「コミットをクリーンアップする」、「コミットを再構築する」、または「この PR を分割する」場合に使用します。バグの差分をレビューするには、pr-reviewer を使用します。作成後に PR を監視するには、pr-babysitter を使用します。 npm リリースの場合は、autoship を使用します。
