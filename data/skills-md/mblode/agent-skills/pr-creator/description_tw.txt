建立帶有簡短、簡單易懂的描述的 GitHub 拉取請求。添加線性問題 ID 前綴（如果可用），將標題保持在 60 個字元以內，並預設為一小段而不是產生的摘要或測試計劃部分。將嘈雜的提交歷史重組為可審查的順序，並為大差異添加審查者指導。在「建立 PR」、「製作 PR」、「打開拉取請求」、「PR 這個」、「傳送它」、「讓這個 PR 易於審查」、「完善這個 PR」、「整理 PR」、「清理提交」、「重組提交」或「拆分這個 PR」時使用。若要檢查差異是否有錯誤，請使用 pr-reviewer。若要在建立 PR 後監控 PR，請使用 pr-babysitter。對於 npm 版本，請使用 autoship。
