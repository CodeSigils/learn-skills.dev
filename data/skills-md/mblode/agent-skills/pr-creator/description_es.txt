Crea solicitudes de extracción de GitHub con descripciones breves y que suenan humanas. Agrega un prefijo de ID de problema lineal cuando está disponible, mantiene los títulos con menos de 60 caracteres y utiliza de forma predeterminada un párrafo corto en lugar de resúmenes generados o secciones de planes de prueba. Reestructura el historial de confirmaciones ruidosas en un orden revisable y agrega orientación para el revisor para diferencias grandes. Úselo cuando "cree un PR", "haga un PR", "abra una solicitud de extracción", "PR esto", "envíelo", "haga que este PR sea fácil de revisar", "pulir este PR", "ordenar el PR", "limpiar confirmaciones", "reestructurar confirmaciones" o "dividir este PR". Para revisar una diferencia en busca de errores, utilice pr-reviewer. Para monitorear un PR después de su creación, use pr-babysitter. Para lanzamientos de npm, utilice el envío automático.
