创建带有简短、通俗易懂的描述的 GitHub 拉取请求。添加线性问题 ID 前缀（如果可用），将标题保持在 60 个字符以内，并默认为一小段而不是生成的摘要或测试计划部分。将嘈杂的提交历史重组为可审查的顺序，并为大差异添加审查者指导。在“创建 PR”、“制作 PR”、“打开拉取请求”、“PR 这个”、“发送它”、“使这个 PR 易于审查”、“完善这个 PR”、“整理 PR”、“清理提交”、“重组提交”或“拆分这个 PR”时使用。要检查差异是否存在错误，请使用 pr-reviewer。要在创建 PR 后监控 PR，请使用 pr-babysitter。对于 npm 版本，请使用 autoship。
