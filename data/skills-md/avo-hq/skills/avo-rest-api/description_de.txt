Stellen Sie mit dem Add-on „avo-api“ eine JSON-REST-API für jede Avo-Ressource bereit – Auflisten/Lesen/Erstellen/Aktualisieren/Löschen plus schreibgeschütztes Assoziations-Traversal, wobei die Felder, die Ansichtssichtbarkeit und die Autorisierung jeder Ressource ohne Controller pro Ressource wiederverwendet werden. Inhabertoken werden über die Avo-Benutzeroberfläche verwaltet (erstellen, einmal offenlegen, deaktivieren, widerrufen) und durch eine Opt-in-Berechtigungsmatrix pro Token gesteuert; Ein Code-Hook („setup_authentication“) deckt HTTP-Basic-/API-Key-/öffentliche Schemata ab. Verwenden Sie diese Option, wenn der Benutzer eine JSON-API für eine mobile App verfügbar machen, einem externen Dienst oder SPA Datensätze über HTTP lesen/schreiben lassen möchte, eine REST-API hinzufügen möchte, ohne Controller zu schreiben, API-Tokens für den Zugriff Dritter oder Server-zu-Server ausgeben, dem Frontend eine vom Administrator unterstützte API geben, eine öffentliche schreibgeschützte API für eine Ressource bereitstellen oder einen Webhook/eine Integration erstellen möchte, die Datensätze abruft – egal, ob sie es in Avo-Begriffen sagen („mount_avo_api“, „avo-api“, „avo_api_tokens“, „setup_authentication“, Berechtigungsgewährung, Token Pepper) oder einfache Begriffe („programmgesteuerter Zugriff auf meine Modelle“, „Server-zu-Server-Zugriff auf Verwaltungsdaten“, „eine API für die mobile App“).
