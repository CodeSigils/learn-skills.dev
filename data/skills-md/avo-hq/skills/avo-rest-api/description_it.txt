Esponi un'API REST JSON su ogni risorsa Avo con il componente aggiuntivo `avo-api`: elenca/leggi/crea/aggiorna/elimina più associazione trasversale di sola lettura, riutilizzando i campi di ciascuna risorsa, visualizza la visibilità e l'autorizzazione, senza controller per risorsa. I token al portatore sono gestiti dall'interfaccia utente di Avo (crea, rivela una volta, disabilita, revoca) e controllati da una matrice di autorizzazione opt-in per token; un hook di codice (`setup_authentication`) copre gli schemi HTTP Basic/chiave API/pubblici. Da utilizzare quando l'utente desidera esporre un'API JSON per un'app mobile, consentire a un servizio esterno o una SPA di leggere/scrivere record su HTTP, aggiungere un'API REST senza scrivere controller, emettere token API per l'accesso di terze parti o da server a server, fornire al frontend un'API supportata dall'amministratore, fornire un'API pubblica di sola lettura per una risorsa o creare un webhook/integrazione che estragga i record, indipendentemente dal fatto che lo dicano in termini Avo (`mount_avo_api`, `avo-api`, `avo_api_tokens`, `setup_authentication`, concessioni di autorizzazioni, token pepper) o termini semplici ("accesso programmatico ai miei modelli", "accesso da server a server ai dati di amministrazione", "un'API per l'app mobile").
