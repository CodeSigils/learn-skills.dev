Exponga una API REST JSON sobre cada recurso de Avo con el complemento `avo-api`: enumerar/leer/crear/actualizar/eliminar más recorrido de asociación de solo lectura, reutilizar los campos de cada recurso, ver visibilidad y autorización, sin controladores por recurso. Los tokens de portador se administran desde la interfaz de usuario de Avo (crear, revelar una vez, deshabilitar, revocar) y están controlados por una matriz de permisos por token de participación voluntaria; un enlace de código (`setup_authentication`) cubre esquemas HTTP básico/clave API/público. Úselo cuando el usuario quiera exponer una API JSON para una aplicación móvil, permitir que un servicio externo o SPA lea/escriba registros a través de HTTP, agregue una API REST sin controladores de escritura, emita tokens de API para acceso de terceros o de servidor a servidor, proporcione a la interfaz una API respaldada por el administrador, envíe una API pública de solo lectura para un recurso o cree un webhook/integración que extraiga registros, ya sea que lo digan en términos de Avo (`mount_avo_api`, `avo-api`, `avo_api_tokens`, `setup_authentication`, concesiones de permisos, token pepper) o términos simples ("acceso programático a mis modelos", "acceso de servidor a servidor a datos administrativos", "una API para la aplicación móvil").
