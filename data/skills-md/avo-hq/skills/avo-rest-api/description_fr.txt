Exposez une API JSON REST sur chaque ressource Avo avec le module complémentaire `avo-api` — list/read/create/update/delete plus traversée d'association en lecture seule, en réutilisant les champs, la visibilité et l'autorisation de chaque ressource, sans contrôleurs par ressource. Les jetons du porteur sont gérés à partir de l'interface utilisateur d'Avo (créer, révéler une fois, désactiver, révoquer) et sont contrôlés par une matrice d'autorisation opt-in par jeton ; un hook de code (`setup_authentication`) couvre les schémas HTTP Basic/API-key/public. À utiliser lorsque l'utilisateur souhaite exposer une API JSON pour une application mobile, laisser un service externe ou un SPA lire/écrire des enregistrements via HTTP, ajouter une API REST sans écrire de contrôleurs, émettre des jetons d'API pour un accès tiers ou de serveur à serveur, donner au frontend une API soutenue par l'administrateur, expédier une API publique en lecture seule pour une ressource ou créer un webhook/intégration qui extrait des enregistrements - qu'ils le disent en termes Avo (`mount_avo_api`, `avo-api`, `avo_api_tokens`, `setup_authentication`, autorisations accordées, token pepper) ou des termes simples ("accès par programmation à mes modèles", "accès de serveur à serveur aux données d'administration", "une API pour l'application mobile").
