「avo-api」アドオン - list/read/create/update/delete に加えて読み取り専用の関連付けトラバーサルを使用して、すべての Avo リソース上で JSON REST API を公開し、リソースごとのコントローラーを使用せずに、各リソースのフィールド、ビューの可視性、および承認を再利用します。ベアラー トークンは Avo UI から管理され (作成、1 回だけ公開、無効化、取り消し)、オプトインのトークンごとの許可マトリックスによってゲート制御されます。コードフック (`setup_authentication`) は HTTP 基本 / API キー / 公開スキームをカバーします。ユーザーがモバイル アプリの JSON API を公開する場合、外部サービスまたは SPA に HTTP 経由でレコードの読み取り/書き込みを許可する場合、コントローラーを作成せずに REST API を追加する場合、サードパーティまたはサーバー間アクセス用の API トークンを発行する場合、管理者がサポートする API をフロントエンドに提供する場合、リソース用のパブリック読み取り専用 API を配布する場合、またはレコードをプルする Webhook/統合を構築する場合に使用します (Avo 用語 (`mount_avo_api`、 `avo-api`、`avo_api_tokens`、`setup_authentication`、権限付与、トークン ペッパーなど)、または単純な用語 (「モデルへのプログラムによるアクセス」、「管理データへのサーバー間アクセス」、「モバイル アプリの API」)。
