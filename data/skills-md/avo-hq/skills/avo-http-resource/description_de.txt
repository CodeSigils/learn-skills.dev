Sichern Sie eine Avo-Ressource mit einer externen HTTP/REST-API anstelle eines Active Record-Modells – Listen, Anzeigen, Erstellen, Aktualisieren und Löschen von Datensätzen direkt über die API ohne Datenbanktabelle über „self.http_adapter“. Verwenden Sie diese Option, wenn der Benutzer ein Admin-Panel für eine externe/Drittanbieter-/SaaS-REST-API erstellen, Datensätze anzeigen möchte, die von einer API statt aus der Datenbank stammen, einen Remote-Dienst über Avo ohne lokale Tabelle CRUDen, Avos Sortier-/Filter-Benutzeroberfläche API-Abfrageparametern zuordnen, Authentifizierungsheader bei jeder Anfrage senden, eine verpackte JSON-Antwort (Ergebnisse/Meta/Daten) analysieren, API-Fehler mit „Avo::HttpError“ aufdecken und anpassen möchte Erstellen/Aktualisieren/Zerstören Sie anhand einer maßgeschneiderten API, verschleiern Sie Datensatz-IDs in URLs oder debuggen Sie genau das, was eine Ressource über die HTTP-Debug-Konsole sendet und empfängt. Kostenpflichtiges Add-on-Gem (`avo-http_resource`), offene Beta.
