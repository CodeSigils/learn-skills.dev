Configurez de manière autonome un bot OpenClaw sur une nouvelle VM Yandex Cloud au Kazakhstan (kz1-a, Karaganda). Demande à l'utilisateur exactement deux choses – un jeton de bot Telegram et l'une des trois options d'accès LLM (clé API Anthropic, clé API OpenRouter ou OpenAI Codex OAuth via l'abonnement ChatGPT Plus/Pro) – puis gère la création de VM, le renforcement, l'installation d'OpenClaw, l'amorçage de l'espace de travail CEO AI OS, le couplage Telegram, la détection automatique chat_id et la vérification des réponses du bot par lui-même. Les seules autres actions effectuées par l'utilisateur consistent à appuyer une fois sur /start dans Telegram et (si Codex) à confirmer un code d'appareil sur auth.openai.com. À utiliser lorsque l'utilisateur dit d'installer OpenClaw sur Yandex Cloud, de déployer OpenClaw sur YC Kazakhstan, de configurer mon bot PDG dans YC KZ, je suis à l'atelier OpenClaw et j'ai besoin de mon propre bot, de créer une machine virtuelle Yandex Cloud pour OpenClaw ou toute autre paraphrase proche. Cible une exécution de bout en bout d'environ 15 minutes pour les utilisateurs non DevOps (fondateurs, PDG, responsables marketing). Prend en charge deux modes d'accès à Yandex Cloud : Plan A (le compte YC Kazakhstan de l'utilisateur via OAuth) et Plan B (un ensemble de clés d'atelier fourni par l'organisateur de l'atelier, pour les participants sans leur propre compte YC). Le mode est automatiquement détecté à partir des entrées. Pour l'installation d'OpenClaw sur une machine locale, utilisez plutôt openclaw/install.sh dans ce dépôt. La compétence de compagnon openclaw-guide est requise ; prepare-yc-workshop est la compétence correspondante côté organisateur qui produit les lots consommés dans le Plan B ; openclaw-user-onboarding est invoqué automatiquement après l'étape 5 pour collecter les cinq informations de base sur l'utilisateur (identité, focus, style, outils, anti-modèles) et les écrire dans USER.md afin que le bot soit utile dès le premier message.
