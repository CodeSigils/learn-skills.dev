カザフスタン (kz1-a、カラガンダ) の新しい Yandex Cloud VM 上に OpenClaw ボットを自律的にセットアップします。ユーザーに正確に 2 つのこと、つまり Telegram ボット トークンと 3 つの LLM アクセス オプション (Anthropic API キー、OpenRouter API キー、または ChatGPT Plus/Pro サブスクリプション経由の OpenAI Codex OAuth) の 1 つを要求し、VM の作成、強化、OpenClaw のインストール、CEO AI OS ワークスペースのシード、Telegram ペアリング、chat_id 自動検出、およびボット応答の検証を独自に処理します。ユーザーが実行する他のアクションは、Telegram で /start を 1 回押すことと、(Codex の場合) auth.openai.com でデバイス コードを確認することだけです。ユーザーが、Yandex Cloud に OpenClaw をインストールする、YC カザフスタンに OpenClaw をデプロイする、YC KZ に CEO ボットをセットアップする、OpenClaw ワークショップに参加しているので独自のボットが必要である、OpenClaw 用の Yandex Cloud VM を作成する、またはそれに近い言い換えをする場合に使用します。 DevOps 以外のユーザー (創業者、CEO、マーケティング リーダー) を対象としたエンドツーエンドの実行時間は 15 分程度を目標としています。 Yandex Cloud にアクセスする 2 つのモードをサポートします。プラン A (OAuth を介したユーザー自身の YC カザフスタン アカウント) とプラン B (独自の YC アカウントを持たない参加者向けに、ワークショップ主催者によって提供されるワークショップ キー バンドル) です。モードは入力から自動検出されます。ローカル マシンの OpenClaw インストールの場合は、代わりにこのリポジトリの openclaw/install.sh を使用してください。コンパニオン スキル openclaw-guide が必要です。 prepare-yc-workshop は、プラン B で消費されるバンドルを生成する、対応する主催者側のスキルです。 openclaw-user-onboarding はステップ 5 の後に自動的に呼び出され、ユーザーに関する 5 つの基本的な事実 (アイデンティティ、フォーカス、スタイル、ツール、アンチパターン) を収集し、それらを USER.md に書き込むため、ボットはメッセージ 1 から役に立ちます。
