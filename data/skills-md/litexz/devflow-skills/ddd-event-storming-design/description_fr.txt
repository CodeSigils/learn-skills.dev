使用事件风暴和 CQRS 思想进行纯 DDD 领域建模。Utilisez cette compétence lorsque le Codex doit analyser les exigences commerciales, faire évoluer un modèle de domaine persistant, identifier les acteurs et la collaboration multi-rôles, les événements de domaine, les commandes, les politiques, les agrégats, les services de domaine, lire des modèles, produire des Markdown structurés ou des diagrammes Mermaid/PlantUML facultatifs, et examiner les conceptions qui peuvent être basées sur CRUD, une base de données, une structure de package ou une terminologie DDD au lieu d'être basées sur le domaine du problème. À utiliser particulièrement pour les exigences administratives de type CRUD, telles que la gestion de l'entreprise, du service, du poste, de l'employé, du compte, du rôle ou des autorisations, qui nécessitent une modélisation axée sur le comportement au lieu d'agrégats de noms plats.
