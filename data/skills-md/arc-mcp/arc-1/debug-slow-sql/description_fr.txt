Trouver la cause profonde d’une requête ABAP SQL ou OData Fiori‑Elements lente et proposer la solution la moins coûteuse — sans interface graphique via ARC‑1 (splitting de timing odata_perf sap‑statistics, cds_sql « Show SQL », métriques d’exécution SAPQuery, contrôle du trace SQL ST05, traces du profileur ABAP), en escaladant vers SAP GUI/HANA uniquement pour les enregistrements de trace et les plans d’exécution. À utiliser lorsqu’un rapport, une transaction, une liste Fiori, une vue CDS ou une entité OData est lent, qu’une requête dépasse le délai sous charge, ou que quelqu’un demande « pourquoi ce SQL/OData est‑il si lent » ou « où le temps est‑il dépensé ».
