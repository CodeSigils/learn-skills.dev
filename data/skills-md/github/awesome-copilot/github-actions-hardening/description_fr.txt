Réviseur de renforcement de la sécurité pour les fichiers de workflow GitHub Actions (.github/workflows/*.yml). Raisons du modèle de menace Actions qui manquent aux modèles de correspondance et aux linters de code généraux : injection de scripts d'entrée non fiables, déclencheurs privilégiés exécutant du code fork, références d'action mutables et jetons à portée excessive. Utilisez cette compétence lorsqu'on vous demande d'examiner, d'auditer, de renforcer ou de sécuriser un workflow GitHub Actions, lors de l'écriture d'un nouveau workflow, ou pour toute demande telle que « ce workflow est-il sûr ? », « examiner mon CI pour des problèmes de sécurité », « pourquoi pull_request_target est-il dangereux ici ? », « épingler mes actions » ou « verrouiller les autorisations GITHUB_TOKEN ». Couvre l'injection de script via l'interpolation ${{ }}, l'élévation de privilèges pull_request_target / workflow_run, l'épinglage SHA d'actions tierces, les autorisations de moindre privilège, l'injection GITHUB_ENV/GITHUB_OUTPUT, l'exposition secrète, l'OIDC sur les informations d'identification de longue durée et l'exposition des coureurs auto-hébergés sur les référentiels publics.
