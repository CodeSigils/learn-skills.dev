Finding.json へのあらゆる入力を正規化します。これは、レビュー ノートを GitHub Issues バックログに変換するための最初のステップです。 Excel/CSV/TSV 監査シート、Word/PDF/Markdown 仕様、または会話に貼り付けられたチャット/テキストなど、誰かが問題、矛盾、ギャップ、レビューメモ、または対処したい監査結果のリストを渡すときはいつでも使用します。ユーザーが「抽出」と言わなくてもトリガーされます。 「これが命名監査です」、「見つかった問題は次のとおりです」、「このスプレッドシートを GitHub の問題に変換します」、「コードをレビューし、これらのギャップに気づきました」、「このドキュメントからバックログを作成します」。最終的に GitHub の問題を解決することが目標の場合、これが最初に実行されます。 github-triage-findings に手を渡します (その後、github-issues を分類し、github-create-issues を実行します)。結果から github の問題までのオーケストレーターによってエンドツーエンドで駆動されます。
