Normalisieren Sie JEDE Eingabe in „fundings.json“ – der erste Schritt, um Überprüfungsnotizen in ein GitHub Issues-Backlog umzuwandeln. Verwenden Sie es immer dann, wenn Ihnen jemand eine Liste mit Problemen, Unstimmigkeiten, Lücken, Überprüfungsnotizen oder Prüfungsergebnissen überreicht, auf die er reagieren möchte: ein Excel-/CSV-/TSV-Prüfungsblatt, eine Word-/PDF-/Markdown-Spezifikation oder einen Chat/Text, der in die Konversation eingefügt wird. Wird auch dann ausgelöst, wenn der Benutzer NICHT „Extrahieren“ sagt – z. B. „Hier ist eine Namensprüfung“, „Das sind die Probleme, die wir gefunden haben“, „Umwandlung dieser Tabelle in GitHub-Probleme“, „Ich habe den Code überprüft und diese Lücken festgestellt“, „Erstelle einen Rückstand aus diesem Dokument“. Wenn das Ziel schließlich GitHub Issues ist, wird dieses zuerst ausgeführt. Hände weg von der Github-Triage-Ergebnisse (dann Github-Probleme klassifizieren, Github-Probleme erstellen). Durchgängig gesteuert durch den Orchestrator, der Erkenntnisse zu Github-Problemen führt.
