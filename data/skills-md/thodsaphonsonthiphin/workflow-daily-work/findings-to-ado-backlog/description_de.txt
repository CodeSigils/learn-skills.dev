End-to-End-Orchestrator, der Erkenntnisse aus JEDEM Input (Audit-Tabelle, Code-/Sicherheitsüberprüfung, QA-Bericht, Besprechungsnotizen, eine eingefügte Liste von Problemen) in einen Azure DevOps-Backlog verknüpfter Arbeitselemente umwandelt. Bringt die Ado-Backlog-Fähigkeiten der sechs Geschwister mit Sicherheitstoren in Ordnung. Wird immer dann ausgelöst, wenn der Benutzer sagt: „Diese Prüfung/Tabelle/Überprüfung/Problemliste in ADO-Arbeitselemente umwandeln“, „einen Rückstand aus diesen Ergebnissen erstellen“, „diese als ADO-Tickets/Fehler/Storys ablegen“, „diese XLSX/CSV-Datei in Azure DevOps importieren“, „Arbeitselemente aus diesem Bericht erstellen“ oder Ihnen ein Quelldokument überreicht und darum bittet, dass es in ADO landet. Dies ist die Schlagzeile, ein einmaliger Einstiegspunkt (/ado-backlog:run umschließt ihn). Dies ist der schrittweisen Ausführung der Teilkompetenzen vorzuziehen, wenn der Benutzer die gesamte Pipeline haben möchte. Nicht zum individuellen Bearbeiten vorhandener Elemente – verwenden Sie ado-create-work-items.
