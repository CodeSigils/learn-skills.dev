Créez des problèmes GitHub à partir d'un github_backlog_input.json (la sortie de classify-github-issues) via le script create_github_issues.py fourni. Affiche toujours un tableau visuel d'essai en premier et ne crée de vrais problèmes qu'après l'approbation explicite de l'utilisateur. Utilisez-le chaque fois qu'il y a un github_backlog_input.json ou tout fichier d'éléments à classer dans GitHub, ou lorsque l'utilisateur dit « créer ces problèmes GitHub », « classer le backlog », « les transmettre à GitHub » ou « créer les problèmes ». C'est l'étape qui écrit réellement dans le dépôt, alors préférez-la aux appels d'API lancés manuellement. Après la création, il écrit github_backlog_result.json pour github-writeback-tracking.
