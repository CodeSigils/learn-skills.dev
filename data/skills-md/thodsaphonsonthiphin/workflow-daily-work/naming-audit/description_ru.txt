Проверьте исходный список заявленных меток/значений/сопоставлений (аудит имен, словарь данных, файл перевода/i18n, руководство по стилю, конфигурацию или любой список результатов «X должно быть Y») с АВТОРИТАТИВНЫМ источником записи системы — по одному элементу за раз. Для каждого утверждения проследите метку реализации до фактического поля/записи, к которой оно привязано, извлеките авторитетное значение из системы LIVE (а не из исходного документа, который часто неверен или принадлежит не тому объекту), сравните формулировку и выработайте правило: побеждает источник истины. Независимость от стека — реализация = веб/приложение/код; полномочия = CRM/Dataverse, схема БД, контракт API, токены проектирования, наборы опций. Выходные данные — это фиксированная карточка для каждого элемента с вердиктом и точным путем к приложению и коду для проверки. Запуск по аудиту именования, аудиту меток, проверке формулировок/терминологии, «соответствует ли метка портала CRM», «сравните эти метки с источником истины», «проверьте эту таблицу именования», сверку имен полей, CRM-выигрыши / проверки канонических меток. НЕ используйте для широкого охвата возможностей («насколько далеко мы от X», паритета функций) — это анализ соответствия; или для превращения результатов в заявки — это плагины отставания.
