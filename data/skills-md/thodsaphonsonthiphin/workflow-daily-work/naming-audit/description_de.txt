Überprüfen Sie eine Quellliste der beanspruchten Labels/Werte/Zuordnungen (eine Benennungsprüfung, ein Datenwörterbuch, eine Übersetzungs-/i18n-Datei, einen Styleguide, eine Konfiguration oder eine beliebige Liste von „X sollte Y sein“-Ergebnissen) anhand der autoritativen Datensatzquelle eines Systems – jeweils ein Element nach dem anderen. Verfolgen Sie für jeden Anspruch das Implementierungsetikett auf das tatsächliche Feld/den tatsächlichen Datensatz, an den es bindet, ziehen Sie den maßgeblichen Wert aus dem LIVE-System (nicht aus dem Quelldokument, das oft falsch ist oder von der falschen Entität stammt), vergleichen Sie die Formulierungen und stellen Sie fest: Die Quelle der Wahrheit gewinnt. Stack-agnostisch – Implementierung = Web/App/Code; Autorität = CRM/Dataverse, DB-Schema, API-Vertrag, Design-Tokens, Optionssätze. Die Ausgabe ist eine feste Karte pro Element mit einem Urteil und dem genauen zu überprüfenden App- und Codepfad. Auslöser für Benennungsprüfung, Etikettenprüfung, Formulierungs-/Terminologieprüfung, „Entspricht das Portal-Label CRM“, „Vergleichen Sie diese Etiketten mit der Quelle der Wahrheit“, „Überprüfen Sie diese Benennungstabelle“, Abgleich von Feldnamen, CRM-Gewinne/kanonische Etikettenprüfungen. NICHT für eine breite Funktionsabdeckung verwenden („Wie weit sind wir von X entfernt“, Feature-Parität) – das ist eine Fit-Gap-Analyse; oder um Erkenntnisse in Tickets umzuwandeln – das sind die Backlog-Plugins.
