Créez des éléments de travail Azure DevOps à partir d'un backlog_input.json (la sortie de classify-work-items) via le script create-backlog.cs fourni. Effectue toujours une validation à sec en premier et ne crée de vrais éléments qu'après l'approbation explicite de l'utilisateur. Utilisez-le chaque fois qu'il y a un backlog_input.json ou tout fichier d'éléments à classer dans ADO, ou lorsque l'utilisateur dit « créer ces éléments de travail », « classer le backlog », « les transmettre à Azure DevOps », « créer les tickets/bugs/histoires », « créer les éléments de travail » ou demande de transformer une liste classifiée de résultats en un véritable backlog ADO. Il s'agit de l'étape qui écrit réellement dans l'organisation, préférez-la donc aux appels REST/MCP lancés manuellement lorsqu'un backlog_input.json existe. Après la création, il écrit backlog_result.json pour le suivi ado-writeback-tracking.
