Создайте рабочие элементы Azure DevOps из файла backlog_input.json (выходные данные classify-work-items) с помощью встроенного сценария create-backlog.cs. Всегда сначала выполняет пробную проверку и создает реальные элементы только после явного одобрения пользователя. Используйте это всякий раз, когда есть backlog_input.json или любой файл элементов для хранения в ADO, или когда пользователь говорит «создать эти рабочие элементы», «сохранить невыполненную работу», «отправить их в Azure DevOps», «создать заявки/ошибки/истории», «создать рабочие элементы» или попросить превратить классифицированный список результатов в настоящий невыполненной работы ADO. Это шаг, который фактически записывает данные в организацию, поэтому предпочтите его ручному вызову REST/MCP, когда существует backlog_input.json. После создания он записывает backlog_result.json для отслеживания ado-writeback-tracking.
