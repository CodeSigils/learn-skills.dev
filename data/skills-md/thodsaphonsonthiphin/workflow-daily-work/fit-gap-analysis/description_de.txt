Vergleichen Sie ein Ziel (Spezifikation, Produktvision, Mitbewerber, RFP oder „zukünftiges“ Design) mit einem System, wie es tatsächlich gebaut wurde, und erstellen Sie eine Evidenz-zuerst-Fit-Gap – eine Fähigkeitsmatrix plus einen schrittweisen Benutzer-Journey-Vergleich, der anhand des LIVE-Systems (Schema + Code, keine Dokumente) überprüft und in Entscheidungen umgesetzt wird. Stack-agnostisch (Web-Apps, APIs, ERPs, Low-Code/CRM, Pipelines, Infrastruktur). Verwenden Sie es immer dann, wenn der Benutzer eine Spezifikation/Vision/einen Mitbewerber mit einem bestehenden System vergleichen möchte, fragt „Wie weit sind wir von Triggern Sie auf Fit-Gap, Gap-Analyse, Fähigkeitsvergleich, Ist- und Ist-Zustand, Systemvergleich, Feature-Parität, Migrationsbewertung – auch wenn der Benutzer nie „Fit-Gap“ sagt. NICHT verwenden für: die Überprüfung eines einzelnen Diffs/PR, eine generische Codeüberprüfung/-prüfung ohne Vergleichsziel oder den Vergleich zweier Prosadokumente zur Formulierung.
