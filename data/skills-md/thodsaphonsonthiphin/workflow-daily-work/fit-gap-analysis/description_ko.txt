대상(스펙, 제품 비전, 경쟁사, RFP, 또는 “향후” 설계)을 실제 구축된 시스템과 비교하고, 증거 기반 피트‑갭을 생성합니다 — 기능 매트릭스와 단계별 사용자 여정 비교를 포함하고, LIVE 시스템(스키마 + 코드, 문서 아님)과 검증한 뒤 의사결정에 통합합니다. 스택에 구애받지 않음(웹 앱, API, ERP, 저코드/CRM, 파이프라인, 인프라). 사용자가 스펙/비전/경쟁사를 기존 시스템과 비교하고 싶을 때, “우리는 X와 얼마나 차이가 나는가” 또는 “Y를 지원하려면 무엇이 필요한가”라고 물을 때, 갭 분석이나 COTS/패키지/벤더 평가를 수행하거나 마이그레이션/재플랫폼/기능 동등성 작업의 범위를 정의할 때 사용합니다. 피트‑갭, 갭 분석, 기능 비교, 현행 대 향후, 시스템 비교, 기능 동등성, 마이그레이션 평가 등으로 트리거합니다 — 사용자가 “피트‑갭”이라고 직접 말하지 않아도 적용됩니다. 다음 경우에는 사용하지 마세요: 단일 diff/PR 검토, 비교 대상이 없는 일반 코드 리뷰/감사, 혹은 두 문서의 문구만 비교하는 경우.
