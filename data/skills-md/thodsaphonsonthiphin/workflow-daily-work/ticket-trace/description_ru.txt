Двусторонняя отслеживаемость между коммитами и заявками. (A) При фиксации любого изменения убедитесь, что сообщение о фиксации содержит номер заявки/рабочего элемента — извлеките его из слов пользователя, имени ветки или текущей задачи, спросите, если неизвестно (перехватчик commit-msg входит в комплект, но устанавливайте его только по явному запросу). (Б) Когда пользователь спрашивает, ПОЧЕМУ код такой, какой он есть — «почему это было изменено», «кто так решил», «этот жесткий код намеренно», «намеренно», «почему это было изменено», «кто так решил», «มีเหตุผลป่าว» — проследить строку через git обвинять/журнал до фиксации, извлечь номер заявки из сообщения, получить заявку с трекера (Azure DevOps, GitHub Issues, JIRA), ВКЛЮЧАЯ загрузку и чтение прикрепленных изображений (требования часто отображаются только на аннотированном снимке экрана) и ответить коммитом + заявкой. доказательства. Запускается при любом запросе на фиксацию в репозитории с билетами, при «установке фиксации фиксации» и при любом вопросе «почему этот код похож на этот» / «археология изменений» — даже если пользователь не упоминает билеты.
