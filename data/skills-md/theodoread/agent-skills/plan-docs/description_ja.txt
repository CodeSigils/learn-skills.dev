アイデアの取得、デザインの草案作成、またはリポジトリの plan/ ディレクトリでの進行中の作業の追跡に使用します。plans/YYYY-MM-DD-topic.md ファイル (偶然判明したバグ、アイデア、またはリスクを含む) の作成または更新、ここまたはすべてのリポジトリにわたって、どのような計画が存在するか、次に何を取り組むべきかを尋ね、ステータスを選択または進め、コンテンツが別の場所に永続的なホームを持ったときに着陸/放棄された計画をリタイアし、リポジトリのレガシーを移行するときに使用します。モノリシック計画ファイル (PLAN.md、DESIGN.md、...) をこの規則に準拠させるか、代わりに plans/ に流れ込んで所属する計画/ステータス/今後の作業内容について AGENTS.md/README.md/docs を監査します。また、プラン ファイルが存在する場所とそこに書き込まれる内容も所有します。plans/ ディレクトリを取得できない職場、クライアント、または雇用主のリポジトリは、そのプランをすべての作業ツリーの外側のストア ($PLANS_HOME) に保持し、構成によってリポジトリごとにルーティングされます。まだリポジトリのないアイデアはスコープなしでファイルされ、後で卒業されます。また、公開するリポジトリにコミットされた計画には、クライアント、雇用主、または内部プロジェクトの名前を付けることはできません。
