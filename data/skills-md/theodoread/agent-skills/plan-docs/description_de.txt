Wird verwendet, wenn Sie eine Idee erfassen, einen Entwurf entwerfen oder laufende Arbeiten im Verzeichnis plans/ eines Repos verfolgen – Erstellen oder Aktualisieren einer plans/YYYY-MM-DD-topic.md-Datei (einschließlich eines zufällig aufgetauchten Fehlers, einer Idee oder eines Risikos), Fragen, welche Pläne existieren oder woran als Nächstes gearbeitet werden soll, hier oder in jedem Repo, Auswählen oder Vorrücken eines Status, Zurückziehen eines gelandeten/abgebrochenen Plans, sobald sein Inhalt woanders ein dauerhaftes Zuhause hat, Migrieren eines repos alte monolithische Plandatei (PLAN.md, DESIGN.md, ...) auf diese Konvention oder prüfen Sie AGENTS.md/README.md/docs auf Planning/Status/Future-Work-Inhalte, die eingedrungen sind und stattdessen in Plans/ gehören. Besitzt auch, wo sich eine Plandatei befinden kann und was darin geschrieben sein kann: Ein Arbeits-, Kunden- oder Arbeitgeber-Repository, das kein Pläne-/Verzeichnis annehmen kann, behält seine Pläne im Speicher außerhalb jedes Arbeitsbaums ($PLANS_HOME), weitergeleitet per Repository per Konfiguration; Eine Idee, für die es noch kein Repo gibt, wird ohne Umfang abgelegt und später abgeändert. und kein Plan, der an ein von Ihnen veröffentlichtes Repo gebunden ist, darf einen Kunden, Arbeitgeber oder ein internes Projekt nennen.
