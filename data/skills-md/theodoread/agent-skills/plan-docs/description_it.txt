Da utilizzare quando si cattura un'idea, si disegna un progetto o si tiene traccia del lavoro in corso nella directory/piani di un repository: creazione o aggiornamento di un file plans/YYYY-MM-DD-topic.md (incluso un bug, un'idea o un rischio emerso accidentalmente), chiedendo quali piani esistono o su cosa lavorare successivamente, qui o in ogni repository, scegliendo o avanzando uno stato, ritirando un piano atterrato/abbandonato una volta che il suo contenuto ha una sede permanente altrove, migrando un il file di piano monolitico legacy del repository (PLAN.md, DESIGN.md, ...) su questa convenzione o controllando AGENTS.md/README.md/docs per il contenuto di pianificazione/stato/lavoro futuro che è entrato e appartiene invece a plans/. Possiede anche dove può risiedere un file di piano e cosa può essere scritto in esso: un repository di lavoro, cliente o datore di lavoro che non può accettare una directory plans/ mantiene i suoi piani nell'archivio all'esterno di ogni albero di lavoro ($PLANS_HOME), instradati per repository dalla configurazione; un'idea senza repository ancora viene archiviata senza ambito e successivamente graduata; e nessun piano impegnato in un repository pubblicato può nominare un cliente, un datore di lavoro o un progetto interno.
