個人/エージェントが管理するプロジェクトで Python コードを作成、レビュー、またはリファクタリングするときに使用します。データ モデリング (Pydantic 対データクラス対 NamedTuple 対 TypedDict 対 attrs 対 msgspec)、日付/時刻/タイムゾーン (認識専用、境界の UTC、DST フォールドとギャップ)、設定/シークレット管理、早期返品/ガード句/フェイルファスト/EAFP、モジュール性/DRY/可読性/カプセル化、モジュールシングルトン + レイジープロパティパターン、ステートレス/不変性、テスト構造 (DAMP vs DRY、フィクスチャスコープ)、例外階層、タイプ無視の衛生管理、`src/`-レイアウトパッケージ構造、非同期/同時実行、および HTTP クライアント/再試行規約に加えて、MCP サーバー固有の規約 (stdio ログ記録規則、ツール境界エラー処理、 *-polite-mcp ファミリの LLM 対応ツール docstrings)。信頼できる情報源やコミュニティの先例に基づいて調査された、トピックごとのデフォルトの回答が提供されるため、セッションごとに選択肢が変動するのではなく、プロジェクト間で一貫性が保たれます。各トピックでは、モデル自体のデフォルトの本能をオーバーライドするのか、それともすでに健全な本能を文書化するだけなのかをメモしているため、スキルは通常のエージェントの動作と戦うのではなく方向性を示します。設計/スタイルのガイダンスのみをカバーしています。type-checker/linter/formatter/shell-check *ツール設定* については、代わりに power-user-linux-setup の Contributing/quality-tooling.md を参照してください。
