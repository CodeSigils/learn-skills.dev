Rédigez des histoires techniques au format Jira (sous-types d'infrastructure et d'application) avec des critères d'acceptation, pour les éléments de backlog qui décrivent un problème de système ou d'ingénierie plutôt qu'une expérience utilisateur. Utilisez cette compétence chaque fois que l'utilisateur souhaite écrire, créer, rédiger, affiner ou améliorer une histoire technique, une histoire de catalyseur, une histoire d'ingénierie, une histoire d'infra ou tout autre PBI décrivant le provisionnement IaC, les actions GitHub/les workflows CI-CD, Cloud Run ou tout autre déploiement de ressources cloud, la configuration IAM/compte de service, la publication d'Artifact Registry ou la logique de service/fonction backend. Déclenchez même pour des formulations informelles telles que « écrire une histoire pour le provisionnement d'un service Cloud Run », « créer un ticket pour le workflow d'application OpenTofu », « une histoire pour les liaisons IAM » ou « transformer cette tâche infra en une histoire ». Utilisez plutôt la compétence de user-story lorsque le PBI décrit une fonctionnalité, une interface utilisateur ou une expérience utilisateur classique. En cas de doute sur le type d’histoire qui s’applique, cette compétence inclut des conseils pour prendre une décision.
