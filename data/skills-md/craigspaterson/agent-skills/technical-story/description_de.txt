Entwerfen Sie in Jira formatierte technische Geschichten (Untertypen „Infrastruktur“ und „Anwendung“) mit Akzeptanzkriterien für Backlog-Elemente, die ein System- oder Technikproblem und nicht eine Benutzererfahrung beschreiben. Verwenden Sie diese Fähigkeit immer dann, wenn der Benutzer eine technische Story, Enabler-Story, Engineering-Story, Infra-Story oder eine beliebige PBI schreiben, erstellen, entwerfen, verfeinern oder verbessern möchte, die IaC-Bereitstellung, GitHub-Aktionen/CI-CD-Workflows, Cloud Run oder andere Cloud-Ressourcenbereitstellung, IAM/Dienstkontokonfiguration, Artifact Registry-Veröffentlichung oder Backend-Dienst-/Funktionslogik beschreibt. Triggern Sie sogar für lockere Formulierungen wie „Schreiben Sie eine Story für die Bereitstellung eines Cloud Run-Dienstes“, „Erstellen Sie ein Ticket für den OpenTofu-Anwendungsworkflow“, „Story für die IAM-Bindungen“ oder „Verwandeln Sie diese Infra-Aufgabe in eine Story“. Verwenden Sie stattdessen die User-Story-Fähigkeit, wenn der PBI eine Funktion, eine Benutzeroberfläche oder ein klassisches Benutzererlebnis für den Menschen beschreibt. Wenn Sie sich nicht sicher sind, welche Art von Geschichte zutrifft, bietet diese Fähigkeit eine Entscheidungshilfe.
