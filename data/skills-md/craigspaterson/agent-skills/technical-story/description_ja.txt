ユーザー エクスペリエンスではなくシステムまたはエンジニアリング上の懸念事項を説明するバックログ項目用の、受け入れ基準を含む、Jira 形式のドラフト テクニカル ストーリー (インフラストラクチャおよびアプリケーションのサブタイプ)。ユーザーが技術ストーリー、イネーブラー ストーリー、エンジニアリング ストーリー、インフラ ストーリー、または IaC プロビジョニング、GitHub Actions / CI-CD ワークフロー、Cloud Run またはその他のクラウド リソース デプロイメント、IAM / サービス アカウント構成、Artifact Registry 公開、またはバックエンド サービス/機能ロジックを説明する PBI を作成、作成、草案、改良、改善したい場合は常に、このスキルを使用します。 「Cloud Run サービスをプロビジョニングするためのストーリーを書く」、「OpenTofu 適用ワークフローのチケットを作成する」、「IAM バインディングのストーリー」、「このインフラ タスクをストーリーに変える」などのカジュアルなフレーズでもトリガーされます。 PBI が人間向けの機能、UI、または従来のユーザー エクスペリエンスを説明する場合は、代わりにユーザー ストーリー スキルを使用します。どの種類のストーリーが適用されるかわからない場合、このスキルには決定のためのガイダンスが含まれています。
