Составляйте проекты технических историй в формате Jira (подтипы инфраструктуры и приложений) с критериями приемки для элементов невыполненной работы, которые описывают системную или инженерную проблему, а не взаимодействие с пользователем. Используйте этот навык всякий раз, когда пользователь хочет написать, создать, набросать, усовершенствовать или улучшить техническую историю, историю реализации, инженерную историю, инфраструктурную историю или любой PBI, описывающий подготовку IaC, действия GitHub / рабочие процессы CI-CD, развертывание Cloud Run или других облачных ресурсов, настройку IAM / сервисной учетной записи, публикацию реестра артефактов или логику внутренней службы/функции. Используйте даже случайные фразы, такие как «напишите историю для предоставления службы Cloud Run», «создайте заявку для рабочего процесса применения OpenTofu», «историю для привязок IAM» или «превратите эту инфраструктурную задачу в историю». Вместо этого используйте навык пользовательской истории, когда PBI описывает функцию, пользовательский интерфейс или классический пользовательский интерфейс, ориентированный на человека. Если вы не уверены, какой тип истории применим, этот навык включает в себя рекомендации по принятию решения.
