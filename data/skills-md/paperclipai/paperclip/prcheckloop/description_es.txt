De forma iterativa, las comprobaciones de una solicitud de extracción de GitHub se ponen en verde. Detecta el PR de la rama actual o utiliza un número de PR proporcionado, espera a que aparezca y finalice cada verificación en el SHA principal más reciente, investiga las comprobaciones fallidas, corrige el código procesable o los problemas de prueba, empuja y repite. Se intensifica con un bloqueador preciso cuando las fallas son externas, inestables o no se pueden solucionar de manera segura. Úselo cuando un PR todavía tiene comprobaciones fallidas después de las correcciones de revisión, incluso después de greploop.
