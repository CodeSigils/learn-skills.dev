Scannen Sie GitHub Actions-Workflowdateien auf Sicherheitslücken, indem Sie die YAML lesen und Ergebnisse direkt melden – keine externen Tools, keine Installation, keine Shell-Ausführung. Verwenden Sie diesen Skill immer dann, wenn der Benutzer eine „.github/workflows/“-Datei teilt, Workflow-YAML einfügt, eine CI/CD-Sicherheitsüberprüfung anfordert, „pull_request_target“, „workflow_run“, Aktionspinning, „GITHUB_TOKEN“-Berechtigungen, PWN-Anfragen, Vorlageninjektion, Cache-Poisoning, geheime Exfiltration, Lieferkettenrisiko oder ein beliebiges Thema zur Härtung von GitHub-Aktionen erwähnt. Wird auch ausgelöst, wenn der Benutzer ein OSS-Repository härtet, eine CI/CD-Red-Team-Bewertung durchführt, ein Ziel für das Scannen der Lieferkette evaluiert oder öffentlich über CI/CD-Sicherheit schreibt. Tendenz, diese Fähigkeit auszulösen, anstatt aus dem Gedächtnis zu antworten – CI/CD-Sicherheitsstandards sind fast überall falsch und die Regeln sind nicht intuitiv.
