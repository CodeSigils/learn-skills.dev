Richten Sie Sentry-Releases ein und stellen Sie die Nachverfolgung bereit – kennzeichnen Sie Ereignisse mit einer Version und Umgebung, erstellen Sie das Release in CI mit seinen Commits und verknüpfen Sie verdächtige Commits und Codezuordnungen, damit Sentry anzeigen kann, welches Release ein Problem verursacht hat, welches Commit dafür verantwortlich ist, und den Release-Zustand anzeigen kann. Verwenden Sie diese Option, wenn Sie aufgefordert werden, Releases einzurichten, Bereitstellungen zu verfolgen, zu sehen, was sich geändert hat, oder wenn Probleme ein unbekanntes Release oder keinen verdächtigen Commit anzeigen.
