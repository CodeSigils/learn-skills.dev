Richten Sie Sentry-Releases ein und stellen Sie Tracking bereit — markieren Sie Ereignisse mit einer Version und einer Umgebung, erstellen Sie das Release im CI mit seinen Commits und verkabeln Sie verdächtige Commits und Codezuordnungen, damit Sentry anzeigen kann, welche Release ein Problem verursacht hat, welches Commit verantwortlich ist, und geben Sie die Integrität frei. Verwenden Sie diese Option, wenn Sie aufgefordert werden, Releases einzurichten, Deployes zu verfolgen, zu sehen, was sich geändert hat, oder wenn Probleme eine unbekannte Version oder keinen verdächtigen Commit anzeigen.
