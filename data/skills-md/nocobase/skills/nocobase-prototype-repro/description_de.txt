Verwenden Sie es, wenn die Aufgabe einen Prototyp zur Reproduktion in NocoBase übergibt – eine HTML-Datei, ein Bild oder einen Link, EINSCHLIESSLICH des veröffentlichten Formulars „Erstellen Sie eine NocoBase-App – Ein vorhandener Prototyp/eine vorhandene URL löst diesen Skill aus, AUCH WENN in derselben Eingabeaufforderung auch „App erstellen“ steht – das Verb „Build“ bricht den Prototyp nicht ab. Überspringen Sie es nur, wenn es überhaupt KEINEN Prototyp gibt: eine bloße „Erstellen Sie mir ein CRM/eine App“ → Nocobase-App- Disziplin; ein Ein-Feld-Bearbeiten/Umbenennen → nocobase-ui-builder. Es verwandelt „Hier ist der Prototyp, bauen Sie ihn“ in eine originalgetreue App – Analyse des Prototyps, natives CRUD, der richtige native Block pro Region, dann eine visuelle Schleife zwischen Screenshot und Prototyp. Native-first; JS nur innerhalb eines nativen Containers; niemals ein ganzseitiger JS-Block. Mechaniker leben in Nocobase-UI-Builder, Nocobase-Data-Modeling und Nocobase-App-Discipline.
