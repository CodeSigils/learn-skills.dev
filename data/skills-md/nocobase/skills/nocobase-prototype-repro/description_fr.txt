À utiliser lorsque la tâche remet un prototype à reproduire dans NocoBase — un fichier HTML, une image ou un lien, Y COMPRIS le formulaire publié « Créer une application NocoBase — X… Faites correspondre la mise en page et les visuels de signature de ce prototype de référence : <url> » – ou lorsque quelqu'un dit qu'une page construite « ne correspond pas au prototype/a l'air monotone/est moche ». Un prototype/URL présent est ce qui déclenche cette compétence, MÊME QUAND la même invite indique également « créer une application » — le verbe « construire » n'annule pas le prototype. Sautez-le uniquement lorsqu'il n'y a AUCUN prototype du tout : un simple "créez-moi un CRM/une application" → nocobase-app-discipline ; une édition/renommage d'un champ → nocobase-ui-builder. Il transforme « voici le prototype, construisez-le » en une application fidèle : analysez le prototype, le CRUD natif, le bon bloc natif par région, puis une boucle visuelle capture d'écran contre prototype. Les autochtones d'abord ; JS uniquement dans un conteneur natif ; jamais un bloc JS pleine page. La mécanique réside dans nocobase-ui-builder, nocobase-data-modeling, nocobase-app-discipline.
