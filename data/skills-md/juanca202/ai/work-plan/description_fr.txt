Planifiez un travail de types distincts sans générer de code ni d'essais. Deux types de plan : (1) les tâches techniques (TK-XXX) ont une histoire d'utilisateur existante ; (2) tâches de gestion (WI-XXX) sans histoire associée — bugs, refactor, deuda técnica, actualisation des dépendances, tâches opérationnelles. Activer toujours que l'utilisateur planifie la mise en œuvre, décompose le travail, définit l'expertise technique, documente les spécifications techniques ou planifie la maintenance / la technique / le refactor, même sans nom «tarea», «TK» ou «WI». Activer également — par défaut — lorsqu'il n'y a qu'une référence à une histoire (p. ex. «US-004», «planifica US-007», «tareas para esta historia») : les talons des promoteurs sont agrégés au référentiel qui comprend les critères d'acceptation (AC-XXX). Sélectionnez le type en fonction de l'histoire associée et chargez votre définition des références/.
