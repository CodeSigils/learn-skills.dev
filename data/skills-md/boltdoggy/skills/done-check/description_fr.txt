Compétence d’acceptation d’achèvement du développement. Lorsque l'agent estime qu'une tâche de développement (développement de fonctionnalités, correction de bug, refactoring, changement de configuration, etc.) est terminée, une acceptation systématique doit être effectuée avant de soumettre ou de déclarer l'achèvement, confirmant la qualité du code, la réussite des tests, le respect des exigences, la synchronisation de la documentation et l'absence de risque de régression élément par élément. Les méthodes d'acceptation sont différenciées par type de projet (CLI / Web / Serveur), chacune avec sa propre liste de contrôle. Cette compétence s'applique à l'étape finale de toute tâche impliquant des modifications de code. Critère de jugement : lorsque l'agent est sur le point de dire « terminé » ou de soumettre du code, cette compétence doit être activée.
