Flux de travail de développement piloté par documents (DDD) : lorsqu'un utilisateur fait une demande impliquant des modifications de code, cette fonctionnalité doit être déclenchée immédiatement. Les scénarios de déclenchement incluent, sans s'y limiter : « ajouter une fonctionnalité », « modifier le code », « implémenter X », « ajouter un nouveau », « modifier », « refactoriser », « développer », « corriger un bug », « optimiser », « mettre à niveau », « améliorer », « ajouter », « ajuster », « écrire du code », etc. Même si la demande semble être une simple modification de code, l'état de la documentation du projet doit d'abord être vérifié. Cette fonctionnalité applique le principe « la documentation d'abord, le code ensuite » : les nouvelles fonctionnalités doivent passer par un processus complet « exigence → conception → confirmation → mise en œuvre » ; Les corrections de bugs et les petites modifications doivent au moins mettre à jour la documentation pertinente ; même si l'utilisateur demande explicitement d'ignorer le processus, la documentation obsolète doit d'abord être mise à jour. De plus, lorsque le projet est utilisé pour la première fois, la fonctionnalité initialisera automatiquement la structure de la documentation DDD (créant un répertoire docs/ et CLAUDE.md). Si votre réponse implique de générer du code ou de modifier des fichiers, vérifiez immédiatement si cette fonctionnalité doit être déclenchée.
