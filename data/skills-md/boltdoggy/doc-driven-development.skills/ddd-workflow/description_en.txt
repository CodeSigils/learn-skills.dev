Document-Driven Development (DDD) workflow — when a user makes any request involving code changes, this capability must be triggered immediately. Trigger scenarios include but are not limited to: “add feature,” “modify code,” “implement X,” “add new,” “change,” “refactor,” “develop,” “fix bug,” “optimize,” “upgrade,” “improve,” “add,” “adjust,” “write code,” etc. Even if the request appears to be a simple code modification, the project documentation status must be checked first. The capability enforces the “documentation first, code later” principle: new features must go through a complete “requirement → design → confirmation → implementation” process; bug fixes and small changes must at least update the relevant documentation; even if the user explicitly requests to skip the process, outdated documentation must be updated first. Additionally, when the project is used for the first time, the capability will automatically initialize the DDD documentation structure (creating a docs/ directory and CLAUDE.md). If your response involves generating any code or modifying files, immediately check whether this capability should be triggered.
