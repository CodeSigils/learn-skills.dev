Document-Driven Development (DDD)-Workflow – wenn ein Benutzer eine Anfrage stellt, die Codeänderungen beinhaltet, muss diese Funktion sofort ausgelöst werden. Zu den Auslöseszenarien gehören unter anderem: „Funktion hinzufügen“, „Code ändern“, „X implementieren“, „Neu hinzufügen“, „Ändern“, „Umgestalten“, „Entwickeln“, „Fehler beheben“, „Optimieren“, „Upgrade“, „Verbessern“, „Hinzufügen“, „Anpassen“, „Code schreiben“ usw. Auch wenn es sich bei der Anfrage um eine einfache Codeänderung zu handeln scheint, muss zunächst der Status der Projektdokumentation überprüft werden. Die Fähigkeit erzwingt das Prinzip „Dokumentation zuerst, Code später“: Neue Funktionen müssen einen vollständigen „Anforderung → Entwurf → Bestätigung → Implementierung“-Prozess durchlaufen; Fehlerbehebungen und kleine Änderungen müssen mindestens die entsprechende Dokumentation aktualisieren; Selbst wenn der Benutzer ausdrücklich darum bittet, den Vorgang zu überspringen, muss die veraltete Dokumentation zunächst aktualisiert werden. Wenn das Projekt zum ersten Mal verwendet wird, initialisiert die Funktion außerdem automatisch die DDD-Dokumentationsstruktur (Erstellung eines docs/-Verzeichnisses und CLAUDE.md). Wenn Ihre Reaktion das Generieren von Code oder das Ändern von Dateien umfasst, prüfen Sie sofort, ob diese Funktion ausgelöst werden soll.
