Flujo de trabajo de desarrollo basado en documentos (DDD): cuando un usuario realiza cualquier solicitud que implique cambios de código, esta capacidad debe activarse de inmediato. Los escenarios desencadenantes incluyen, entre otros: "agregar característica", "modificar código", "implementar X", "agregar nuevo", "cambiar", "refactorizar", "desarrollar", "corregir error", "optimizar", "actualizar", "mejorar", "agregar", "ajustar", "escribir código", etc. Incluso si la solicitud parece ser una simple modificación del código, primero se debe verificar el estado de la documentación del proyecto. La capacidad aplica el principio de “documentación primero, código después”: las nuevas funciones deben pasar por un proceso completo de “requisito → diseño → confirmación → implementación”; las correcciones de errores y pequeños cambios deben actualizar al menos la documentación relevante; Incluso si el usuario solicita explícitamente omitir el proceso, primero se debe actualizar la documentación obsoleta. Además, cuando el proyecto se utiliza por primera vez, la capacidad inicializará automáticamente la estructura de documentación DDD (creando un directorio docs/ y CLAUDE.md). Si su respuesta implica generar algún código o modificar archivos, verifique inmediatamente si esta capacidad debe activarse.
