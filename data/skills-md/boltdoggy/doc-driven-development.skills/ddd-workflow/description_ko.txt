DDD(문서 기반 개발) 워크플로 — 사용자가 코드 변경과 관련된 요청을 하면 이 기능이 즉시 트리거되어야 합니다. 트리거 시나리오에는 "기능 추가", "코드 수정", "X 구현", "새 추가", "변경", "리팩터링", "개발", "버그 수정", "최적화", "업그레이드", "개선", "추가", "조정", "코드 작성" 등이 포함되지만 이에 국한되지는 않습니다. 요청이 간단한 코드 수정으로 보이더라도 프로젝트 문서 상태를 먼저 확인해야 합니다. 이 기능은 "문서화 우선, 코드 나중에" 원칙을 시행합니다. 새로운 기능은 완전한 "요구 사항 → 설계 → 확인 → 구현" 프로세스를 거쳐야 합니다. 버그 수정 및 작은 변경 사항은 최소한 관련 문서를 업데이트해야 합니다. 사용자가 프로세스를 건너뛰도록 명시적으로 요청하더라도 오래된 문서를 먼저 업데이트해야 합니다. 또한 프로젝트를 처음 사용할 때 이 기능은 DDD 문서 구조(docs/ 디렉터리 및 CLAUDE.md 생성)를 자동으로 초기화합니다. 응답에 코드 생성이나 파일 수정이 포함되는 경우 이 기능이 트리거되어야 하는지 즉시 확인하세요.
