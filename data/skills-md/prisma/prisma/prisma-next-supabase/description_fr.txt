Utilisez Prisma Next avec un projet Supabase via `@internal/extension-supabase` — câblez `extensions: [supabasePack]`, déclarez les FK inter-espaces à `supabase:auth.AuthUser`, créez des politiques RLS (`policy_select` / `policy_update` / `@@rls`, `auth.uid()` prédicats), construisez `db.ts` avec l'usine `supabase()`, liez les rôles par requête (`asUser(jwt)` / `asAnon()` / `asServiceRole()`), interrogez `auth.*` / `storage.*` via la racine d'administrateur `db.asServiceRole().supabase` et validez les JWT (`jwksUrl` pour les projets en cours / `jwtSecret` pour l'ancien HS256). Utiliser pour supabase, RLS, sécurité au niveau des lignes, politique, liaison de rôle, anon, authentifié, service_role, auth.users, auth.uid(), JWT, JWKS, SUPABASE_JWKS_URL, SUPABASE_JWT_SECRET, SUPABASE.JWT_INVALID, SUPABASE.CONFIG_INVALID, RoleBoundDb, pooler de sessions, supabase:auth.AuthUser, @internal/extension-supabase.
