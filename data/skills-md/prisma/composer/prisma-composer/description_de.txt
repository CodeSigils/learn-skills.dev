So schreiben, testen und implementieren Sie eine App mit Prisma Composer („@prisma/composer“): Deklarieren Sie Dienste mit „compute()“ und typisierten Abhängigkeiten, definieren Sie RPC-Verträge, erstellen Sie Module, deklarieren Sie die Diensteingabe (Konfiguration und Geheimnisse als ein Schema, lesen Sie sie mit „input()“ zurück), erstellen Sie die vorgefertigten Cron-/Storage-/Streams-Module, stellen Sie einen rohen S3-kompatiblen Objektspeicher-Bucket mit „bucket()“ bereit, finden Sie Erweiterungen (npm-Pakete mit dem Namen „prisma-composer-*“), testen Sie mit „mockService“/„bootstrapService“, führen Sie die gesamte App lokal mit „prisma-composer dev“ aus und ergänzen Sie ihre Protokolle mit „prisma-composer log“ und stellen Sie sie mit „prisma-composerploy“ bereit (Stufen, zerstören). Verwenden Sie diese Option, wenn Sie eine Prisma-App erstellen, eine Dienstabhängigkeit verknüpfen, eine Postgres-Datenbank hinzufügen, geplante Jobs/Blobspeicher/Ereignisströme/einen Raw-Bucket hinzufügen, Tests für zusammengesetzte Dienste schreiben, eine App lokal ausführen, ihre Protokolle lesen oder eine Umgebung bereitstellen/abbauen. Löst auf „prisma Composer“, „@prisma/composer“, „prisma app“, „compute()“, „service.load()“, „module()“, „contract()“, „mockService“, „bootstrapService“, „prisma-composer dev“, „prisma-composer log“, „prisma-composerploy“, „--stage“, „--fresh“, „--tail“, „prisma-composer destroy“ aus. „prisma-composer-“, „bucket()“.
