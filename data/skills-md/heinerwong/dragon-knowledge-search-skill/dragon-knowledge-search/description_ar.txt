عندما يقوم المستخدم بتطوير مشاريع داخلية لـ dida (تقنية DaoTravel) - كتابة التعليمات البرمجية أو الوثائق أو فحص الواجهات أو استكشاف مشكلات النشر أو العمليات وإصلاحها - ابحث تلقائيًا في قاعدة معارف Dragon الخاصة (باستخدام أداة KnowledgePlugin__knowledge_base_search من Dragon-knowledge_base_search من Dragon-knowledges MCP) لاسترداد المستندات الفنية الداخلية وتصميمات الهندسة المعمارية ومواصفات API وتعريفات الحقول والعمليات التجارية وأكواد الأخطاء والتكوين والمواد التشغيلية. يجب أن يحدث هذا المشغل الاستباقي في السيناريوهات التالية دون أن يقول المستخدم صراحةً "استخدم Dragon" أو "ابحث في قاعدة المعرفة":

- يشير المستخدم إلى "شركتنا/شركتنا/الداخلية/هذا المشروع/عبر الإنترنت" وما إلى ذلك، مع الإشارة إلى الأصول الداخلية.
- يذكر المستخدم أي اسم نظام داخلي لـ dida (على سبيل المثال، Beaver، Phoenix، LionKing، Shopping، EBooking، Wolf، Wolf2.0، AngryBirds، CRM، Analysis، Whale، Admin، Marketing، Tiger، Bingo، Kangaroo، Finance، Content، Dolphin، Grafana، Penguin، Panda، AutoLine، FalconService، f‑operating، f‑supplier، f‑ana Analysis، f-order، f-policy، f-profit، f-monitor، EBookingBookingAPI، Wuying/无影، نظام خدمة العملاء، نظام قناة API، نظام مورد API، خدمة الموردين/SS، BDS).
- يسأل المستخدم عن قواعد العمل أو منطق المنتج أو تدفقات الموافقة أو حدود التنبيه أو معنى رموز الخطأ.
- يسأل المستخدم عن حقل API معين، أو بنية رد الاتصال، أو استخدام SDK الداخلي حيث لا يشبه اسم الحقل إطار عمل مفتوح المصدر.
- يسأل المستخدم عن الإصدار أو الإصدار الرمادي أو النشر أو التكوين أو المراقبة المرتبطة ببيئة داخلية محددة.
- يقوم المستخدم بكتابة التعليمات البرمجية، أو إصلاح الأخطاء، أو إضافة التعليقات، أو كتابة الوثائق في مستودع التعليمات البرمجية الداخلي للشركة.
- يذكر المستخدم النطاق didainternal.com أو النطاقات الداخلية المشابهة.

عندما تكون غير متأكد، اتجه نحو البحث - فتكلفة البحث الداخلي الواحد أقل بكثير من تكلفة الإجابة بشكل غير صحيح أو عام للغاية. استخدم هذه المهارة بقوة عندما ينخرط المستخدم في أعمال تطوير داخلية لشركة dida، حتى بدون الإشارة بشكل صريح إلى Dragon أو قاعدة المعرفة.
