Cadres de décision pour la modélisation de contenu DatoCMS : forme du schéma, choix des champs, réutilisation du contenu, taxonomies, contenu par rapport à la présentation, organisation de l'interface utilisateur d'administration. À utiliser pour la modélisation des *décisions*, pas pour la mise en œuvre : modèle vs bloc ; single_block vs contenu modulaire vs texte structuré ; références vs blocs intégrés ; forme de taxonomie (plat/arbre/facette) ; refactoriser des schémas en forme de page en contenu réutilisable ; adapter les limites d'enregistrement de 300 Ko / 500 blocs / 5 niveaux ; comportement du modèle (singleton, mode brouillon, all_locales_required, sortable/tree/ordering_field, présentation_title_field, collection_lessly, inverse_relationships_enabled) ; configuration du champ (validateur + apparence - enum + string_select, remplissage automatique de slug, require_alt_title, listes autorisées de texte structuré, single_block encadré ou sans cadre). Egalement revue de schéma (réutilisation, ergonomie éditeur, omnicanal). *Création* d'un schéma → `datocms-cli` ou `datocms-cma`. Requête/rendu → `datocms-cda` + `datocms-frontend-integrations`. Validateurs + cascade : `datocms-cma/references/schema.md`.
