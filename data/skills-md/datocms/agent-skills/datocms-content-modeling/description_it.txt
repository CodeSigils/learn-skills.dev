Strutture decisionali per la modellazione dei contenuti DatoCMS: forma dello schema, scelta dei campi, riutilizzo dei contenuti, tassonomie, contenuto vs presentazione, organizzazione dell'interfaccia utente di amministrazione. Utilizzare per modellare le *decisioni*, non per l'implementazione: modello vs blocco; blocco_singolo vs contenuto modulare vs testo strutturato; riferimenti vs blocchi incorporati; forma tassonomica (piatta/ad albero/sfaccettata); refactoring di schemi a forma di pagina in contenuti riutilizzabili; adattando i limiti di registrazione di 300 KB / 500 blocchi / 5 livelli; comportamento del modello (singleton, modalità bozza, all_locales_required, sortable/tree/ordering_field, Presentation_title_field, collection_appearance, inverse_relationships_enabled); configurazione del campo (validatore + aspetto: enum + string_select, riempimento automatico slug, titolo_alt_richiesto, liste consentite testo_strutturato, blocco singolo con cornice o senza cornice). Anche revisione dello schema (riutilizzo, ergonomia dell'editor, omnicanale). *Creazione* di schema → `datocms-cli` o `datocms-cma`. Query/render → `datocms-cda` + `datocms-frontend-integrations`. Validatori + cascata: `datocms-cma/references/schema.md`.
