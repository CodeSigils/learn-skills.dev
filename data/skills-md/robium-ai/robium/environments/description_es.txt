Configuración de entorno virtual primero para proyectos de robótica: decida uv/venv versus Docker, haga que las ejecuciones de servidores locales y remotos se reproduzcan de manera idéntica, maneje el paso de GPU y el reenvío de pantalla/sin cabeza. Úselo cuando: configure cualquier entorno de proyecto de robótica nuevo; 'uv', 'venv', 'virtualenv', 'docker para este proyecto', 'entorno reproducible', 'funciona localmente pero no en el servidor', 'GPU en contenedor', 'este proyecto debe usar uv o Docker'. Cargue temprano en cualquier construcción de robium, justo después del arquitecto. Regla general de decisión: pilas de ML de Python puro → uv; cualquier cosa que necesite ROS 2 o departamentos del sistema → Docker. No apto para: Dockerfiles de aplicaciones de múltiples módulos y cableado de composición (habilidad de integración) o aprovisionamiento y resolución de problemas de recursos RunPod (habilidad runpod).
