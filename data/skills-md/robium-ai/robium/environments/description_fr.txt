Configuration axée sur l'environnement virtuel pour les projets de robotique : choisissez uv/venv par rapport à Docker, faites en sorte que les exécutions de serveurs locaux et distants se reproduisent de manière identique, gérez le relais GPU et le transfert sans tête/affichage. À utiliser lors de : la configuration de tout nouvel environnement de projet robotique ; 'uv', 'venv', 'virtualenv', 'docker pour ce projet', 'environnement reproductible', 'fonctionne localement mais pas sur le serveur', 'GPU dans le conteneur', 'ce projet devrait-il utiliser uv ou Docker'. Chargez tôt dans toute construction de Robium, juste après l'architecte. Règle empirique de décision : piles ML purement Python → uv ; tout ce qui nécessite ROS 2 ou des services système → Docker. Pas pour : les fichiers Docker d'applications multimodules et la composition du câblage (compétence d'intégration), ou le provisionnement et le dépannage des ressources RunPod (compétence runpod).
