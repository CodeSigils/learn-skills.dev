Créez et remplissez .agents/qa-project-context.md avec la pile technologique du projet, les cadres de test, le pipeline CI/CD, les environnements, les objectifs de qualité, les zones à risque, la structure de l'équipe et les conventions. Il s'agit du fichier que toutes les autres compétences d'assurance qualité lisent en premier, elles évitent donc les découvertes redondantes et donnent des conseils contextuels. À utiliser lorsque : "configurer le contexte d'assurance qualité", "configurer les tests", "initialiser le projet", première utilisation d'une compétence d'assurance qualité. Pas pour : amorcer le contrôle qualité d'un tout nouveau projet de bout en bout — utilisez qa-start (qui appelle cette compétence comme sa première étape). Connexes : qa-start, tests basés sur les risques, stratégie de test, qa-metrics, dramaturge-automatisation.
