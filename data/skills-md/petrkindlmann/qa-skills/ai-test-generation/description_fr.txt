Utilisez l'IA pour écrire un NOUVEAU code de test à partir de spécifications, de PRD, de user stories, de différences de code, de rapports de bogues ou de spécifications OpenAPI. Pipeline par étapes : extraction des exigences → analyse des risques → matrice de couverture → génération de scénarios → conception Oracle → code de test → examen humain, avec garde-fous contre les API hallucinées et les assertions faibles. À utiliser lorsque : "générer des tests à partir des spécifications", "tests à partir du PRD", "tests à partir d'une user story", "générer automatiquement des cas de test", "L'IA écrit des tests pour moi". Pas pour : tester les fonctionnalités AI/LLM de votre produit – utilisez ai-system-testing. Pas pour : auditer une suite de tests préexistante que vous n'avez pas simplement générée - utilisez ai-qa-review (l'étape 7 ici examine uniquement les tests produits par CE pipeline). Connexes : automatisation du dramaturge, tests unitaires, tests api, contexte de projet qa.
