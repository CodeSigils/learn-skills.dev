AI を使用して、仕様、PRD、ユーザー ストーリー、コードの差分、バグ レポート、または OpenAPI 仕様から新しいテスト コードを作成します。段階的なパイプライン: 要件抽出 → リスク分析 → カバレッジ マトリックス → シナリオ生成 → オラクル設計 → テスト コード → 人間によるレビュー。幻覚 API や弱いアサーションに対するガードレールが付いています。 「仕様からテストを生成する」、「PRD からテストを生成する」、「ユーザー ストーリーからテストを生成する」、「テスト ケースを自動生成する」、「AI がテストを作成する」場合に使用します。製品の AI/LLM 機能のテストには適していません。ai-system-testing を使用してください。適さない: 生成したばかりではない既存のテスト スイートを監査する場合 — ai-qa-review を使用します (ここのステップ 7 では、このパイプラインが生成したテストのみをレビューします)。関連: playwright-automation、単体テスト、api-testing、qa-project-context。
