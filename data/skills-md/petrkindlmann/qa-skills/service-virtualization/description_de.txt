Entscheidungsrahmen zum Isolieren aller externen Abhängigkeiten in einer Testsuite: Wann werden In-Process-Mocks, HTTP-Stubs (MSW, WireMock), Record-Replay, Fault-Injection (Toxiproxy) oder kurzlebige reale Dienste (Testcontainer) verwendet und wie kann man erzwingen, dass in CI keine echten Aufrufe entkommen. Verwendung bei: „Mock-Service“, „Stub-API“, „Fake-Service“, „WireMock“, „MSW“, „Toxiproxy“, „Testisolation“, „Abhängigkeitsmanagement“, „Stub einer externen API in CI“. Nicht für: verbraucherorientierte Vertragsüberprüfung (Pakt, Makler) – Vertragstests verwenden; Erstellen einer vollständigen Docker Compose-Umgebung oder Seed-Daten – Testumgebungen verwenden; Umfassende Resilienz-/Spieltagsfehlerkampagnen – nutzen Sie Chaos-Engineering. Verwandte Themen: Vertragstests, Testumgebungen, API-Tests, Testdatenmanagement, Chaos-Engineering.
