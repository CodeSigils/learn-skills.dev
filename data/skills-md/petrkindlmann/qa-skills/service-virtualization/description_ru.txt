Структура принятия решений для изоляции каждой внешней зависимости в наборе тестов: когда использовать внутрипроцессные макеты, HTTP-заглушки (MSW, WireMock), воспроизведение записей, внедрение ошибок (Toxiproxy) или эфемерные реальные службы (Testcontainers), а также как обеспечить, чтобы ни один реальный вызов не ускользал в CI. Используйте, когда: «фиктивный сервис», «заглушка API», «поддельный сервис», «WireMock», «MSW», «Toxiproxy», «тестовая изоляция», «управление зависимостями», «заглушка внешнего API в CI». Не для: проверки контракта по инициативе потребителя (Пакт, брокер) — используйте тестирование контракта; создание полной среды Docker Compose или исходных данных — используйте тестовую среду; широкие кампании по обеспечению устойчивости/ошибок игрового дня — используйте хаос-инжиниринг. Связано: контрактное тестирование, тестовые среды, API-тестирование, управление тестовыми данными, хаос-инжиниринг.
