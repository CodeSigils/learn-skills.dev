Testez les flux de paiement et de paiement de bout en bout par rapport aux bacs à sable PSP – Stripe d'abord, avec le modèle général pour Adyen/Braintree/PayPal. Couvre les numéros de carte en mode test Stripe et leurs codes de refus, le flux de défi 3DS/SCA et sa gestion des iframes imbriquées dans Playwright, les horloges de test pour la simulation du cycle d'abonnement/de facturation, les tests de webhook (écoute/déclenchement de Stripe, vérification de signature, idempotence), les paiements et remboursements ayant échoué/réessayés, et ne jamais utiliser de vraies cartes. À utiliser lorsque : "tester le paiement Stripe", "test de paiement", "test 3DS", "tester la signature du webhook", "tester le renouvellement de l'abonnement", "tester l'horloge", "test de remboursement", "test de refus de carte", "paiement E2E". Pas pour : Tests généraux des contrats d'API des points de terminaison de non-paiement – tests d'API. Audit de conformité PCI-DSS/réglementaire — tests de conformité. Connexes : tests API, automatisation de dramaturge, tests de conformité, gestion des données de test, contexte de projet qa.
