Transformez un vague rapport de bug en une reproduction minimale VÉRIFIÉE, puis en un test de régression échoué, piloté par un agent de bout en bout. Couvre l'extraction de la repro implicite à partir d'un rapport léger (env, build, steps, data), la boucle reproduire-minimiser-isoler-capture, git bisect pour trouver le commit d'introduction, la construction d'une repro minimale déterministe (graines fixes, temps gelé, réseau stubbed), l'écriture du test de régression défaillant AVANT le correctif (rouge) et la confirmation que le correctif le retourne en vert, et l'écriture des preuves de repro dans le ticket. Distingue les feuilles feuilletées non reproductibles et spécifiques à l'environnement. À utiliser lorsque : "reproduire ce bug", "reproduction minimale", "étapes de repro", "trouver le commit qui l'a cassé", "git bisect", "rendre la repro déterministe", "écrire un test d'échec pour ce bug", "test de régression pour un défaut", "impossible de reproduire ce bug". Pas pour : classer/dédupliquer/acheminer par gravité les pannes existantes sans les reproduire — c'est le triage des bogues par ai. Générer des tests à partir de spécifications plutôt qu'à partir d'un défaut : c'est la génération de tests ai. Connexes : triage de bogues ai, génération de tests ai, fiabilité des tests, débogage systématique, contexte de projet qa.
