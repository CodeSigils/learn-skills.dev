Превратите расплывчатый отчет об ошибке в ПРОВЕРЕННУЮ минимальную копию, а затем в неудачный регрессионный тест, управляемый агентом. Охватывает извлечение неявного воспроизведения из тонкого отчета (окружающая среда, сборка, шаги, данные), цикл воспроизведения-минимизации-изолирования-захвата, git bisect для поиска вводящего коммита, построение детерминированного минимального воспроизведения (фиксированные начальные значения, замороженное время, заглушенная сеть), написание неудачного регрессионного теста ПЕРЕД исправлением (красный) и подтверждение исправления, переворачивающее его зеленым, и запись доказательства воспроизведения обратно в заявку. Отличает шелушащиеся-невоспроизводимые от специфичных для окружающей среды. Используйте, когда: «воспроизвести эту ошибку», «минимальное воспроизведение», «шаги воспроизведения», «найти коммит, который ее нарушил», «git разделить пополам», «сделать воспроизведение детерминированным», «написать неудачный тест для этой ошибки», «регрессионный тест на дефект», «невозможно воспроизвести эту ошибку». Не для: классификации/дедупликации/маршрутизации существующих сбоев без их воспроизведения — это сортировка ошибок. Генерация тестов на основе спецификаций, а не дефектов — это генерация ИИ-тестов. Связано: ai-bug-triage, ai-test-generation, test-liability, систематическая отладка, qa-project-context.
