Based on the requirements specification, write software high‑level design and detailed design documents. Read business objects, interfaces, use cases, and other information from the requirement metadata and each system’s requirement specifications, and generate engineering‑level design documents such as database design, API design, and module design. Use a three‑phase architecture: Phase 0 generates design metadata, Phase 1 creates high‑level design per system, Phase 2 creates detailed design per submodule. Core features: automatic splitting of large documents, hierarchical processing based on system size (small/medium/large) to avoid overly large single outputs. Triggered when the user requests software design, high‑level design, detailed design, database design, or API design. It also supports a repair mode: triggered when the user requests to fix or supplement design documents. Prerequisite: the bid‑requirements must have already generated the requirements specification file.
