Audite una base de código para módulos poco profundos: lugares donde la interfaz es casi tan compleja como la implementación, donde comprender un concepto requiere rebotar entre muchos archivos pequeños, donde las funciones puras se extrajeron solo para comprobarlas pero los errores reales se esconden en cómo se llaman, o donde los módulos estrechamente acoplados se filtran entre sí. Muéstrelos como oportunidades de profundización (refactorizaciones que convierten módulos poco profundos en profundos), aplique la prueba de eliminación y recorra el árbol de diseño con el usuario. Admite distribución paralela de subagentes para exploración de interfaz estilo 'Design It Twice'. Úselo siempre que el usuario quiera mejorar la arquitectura, encontrar oportunidades de refactorización, consolidar módulos estrechamente acoplados, identificar abstracciones superficiales, hacer que una base de código sea más comprobable o le responda con frases como "dónde podemos refactorizar", "encontrar fricción en la arquitectura", "este código se siente demasiado abstracto", "ayúdame a profundizar los módulos" o "auditar mi base de código".
