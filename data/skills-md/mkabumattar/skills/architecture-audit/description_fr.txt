Auditez une base de code pour les modules superficiels - des endroits où l'interface est presque aussi complexe que l'implémentation, où la compréhension d'un concept nécessite de rebondir entre de nombreux petits fichiers, où les fonctions pures ont été extraites juste à des fins de test, mais les vrais bugs se cachent dans la façon dont ils sont appelés, ou là où des modules étroitement couplés fuient à travers leurs coutures. Présentez-les comme des opportunités d'approfondissement (refactors qui transforment des modules superficiels en modules profonds), appliquez le test de suppression et parcourez l'arbre de conception avec l'utilisateur. Prend en charge la diffusion parallèle de sous-agents pour l'exploration d'interface de style « Design It Twice ». À utiliser chaque fois que l'utilisateur souhaite améliorer l'architecture, trouver des opportunités de refactorisation, consolider des modules étroitement couplés, identifier des abstractions superficielles, rendre une base de code plus testable ou vous frapper avec des phrases telles que « où pouvons-nous refactoriser », « trouver des frictions architecturales », « ce code semble trop abstrait », « aidez-moi à approfondir les modules » ou « auditer ma base de code ».
