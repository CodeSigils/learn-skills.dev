Überprüfen Sie eine Codebasis auf flache Module – Orte, an denen die Schnittstelle fast so komplex ist wie die Implementierung, an denen das Verständnis eines Konzepts das Hin- und Herwechseln zwischen vielen kleinen Dateien erfordert, an denen reine Funktionen nur aus Gründen der Testbarkeit extrahiert wurden, die wahren Fehler jedoch in der Art ihrer Bezeichnung verborgen sind oder an denen eng verbundene Module über ihre Grenzen hinweg lecken. Stellen Sie sie als Möglichkeiten zur Vertiefung dar (Refaktoren, die flache Module in tiefe Module umwandeln), wenden Sie den Löschtest an und gehen Sie mit dem Benutzer durch den Designbaum. Unterstützt paralleles Subagenten-Fanout für die Schnittstellenerkundung im „Design It Twice“-Stil. Verwenden Sie es immer dann, wenn der Benutzer die Architektur verbessern, Refactoring-Möglichkeiten finden, eng gekoppelte Module konsolidieren, flache Abstraktionen identifizieren, eine Codebasis testbarer machen möchte oder Sie mit Phrasen wie „Wo können wir umgestalten“, „Architekturkonflikte finden“, „Dieser Code fühlt sich überabstrahiert“, „Helfen Sie mir, Module zu vertiefen“ oder „Überprüfen Sie meine Codebasis“ konfrontiert.
