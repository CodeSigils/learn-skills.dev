Úselo al diagnosticar problemas con el estado del clúster de Kubernetes: plano de control no disponible, plano de control lento, bloqueo de reconciliación, fallas de nodo o bloqueo de admisión. Consulta Netdata a través de MCP para conocer el estado del servidor API, la existencia del líder etcd, la latencia de solicitud del servidor API (p99), la latencia wal fsync de etcd, los cambios del líder etcd, aplica el árbol de diagnóstico del manual del operador de Netdata y recomienda soluciones.
