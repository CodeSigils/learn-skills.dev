Lors de l'identification des tâches de développement telles que les fonctionnalités frontales TRS, les nouvelles pages, les interactions commerciales, l'intégration d'API, les formulaires, les autorisations, le Store, le fractionnement des composants, la refactorisation commerciale, etc., il est obligatoire de l'utiliser avant d'écrire du code ; il est utilisé pour déterminer d'abord si le travail relève d'un processus complet, d'un processus léger ou d'un processus de correction de bogues, empêchant le codage direct simplement parce que les exigences sont claires, que les modifications sont mineures ou qu'il existe une implémentation proactive par défaut.
