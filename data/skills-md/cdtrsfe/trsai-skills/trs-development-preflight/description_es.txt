Cuando se identifican tareas de desarrollo como funciones de interfaz de usuario de TRS, nuevas páginas, interacciones comerciales, integración de interfaces, formularios, permisos, almacenamiento, división de componentes o refactorización comercial, esto debe usarse antes de escribir cualquier código; sirve para determinar primero si el trabajo cae dentro de un límite de flujo de trabajo de proceso completo, liviano o de corrección de errores, evitando así la codificación directa simplemente porque el requisito es claro, el cambio es menor o existe una suposición predeterminada para continuar.
