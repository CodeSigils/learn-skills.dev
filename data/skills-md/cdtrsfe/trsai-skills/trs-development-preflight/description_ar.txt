قبل كتابة التعليمات البرمجية لمهام التطوير مثل تحديد وظائف الواجهة الأمامية لـ TRS، أو الصفحات الجديدة، أو تفاعلات الأعمال، أو تكامل الواجهة، أو النماذج، أو الأذونات، أو المتجر، أو تقسيم المكونات، أو إعادة بناء الأعمال، يجب عليك أولاً استخدام هذا لتحديد ما إذا كانت العملية عبارة عن تدفق كامل، أو تدفق خفيف الوزن، أو حد تدفق لإصلاح الأخطاء، وذلك لتجنب الترميز المباشر بسبب متطلبات واضحة أو تغيير بسيط أو تنفيذ استباقي افتراضي.
