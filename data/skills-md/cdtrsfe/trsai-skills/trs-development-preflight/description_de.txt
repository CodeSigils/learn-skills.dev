Bei der Identifizierung von Entwicklungsaufgaben wie TRS-Frontend-Funktionen, neuen Seiten, Geschäftsinteraktionen, API-Integration, Formularen, Berechtigungen, Store, Komponentenaufteilung, Geschäfts-Refactoring usw. ist es zwingend erforderlich, diese vor dem Schreiben von Code zu verwenden; Es wird verwendet, um zunächst zu bestimmen, ob die Arbeit unter einen vollständigen Prozess, einen leichtgewichtigen Prozess oder eine Prozessgrenze zur Fehlerbehebung fällt, wodurch eine direkte Codierung einfach deshalb verhindert wird, weil die Anforderungen klar sind, die Änderungen geringfügig sind oder eine standardmäßige proaktive Implementierung vorliegt.
