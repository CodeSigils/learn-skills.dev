Validieren, reparieren und veröffentlichen Sie Fertigkeiten als GitHub-Repos. Strukturiert Workflow-Fähigkeiten für Ausführungstreue. Registriert Fähigkeiten plattformübergreifend über Symlinks und leitet das Onboarding bei der ersten Nutzung an. Wird verwendet, wenn der Benutzer sagt: „Eine Fertigkeit erstellen“, „Eine Fertigkeit schmieden“, „Dieses Fertigkeits-Repository überprüfen“, „Diese Fertigkeit prüfen“, „Alle meine Fertigkeiten prüfen“, „Dieses Projekt prüfen“, „Meine Fertigkeiten bereinigen“, „Meinen Fertigkeit überprüfen“, „Diese Fertigkeit veröffentlichen“, „Auf GitHub übertragen“, „Meinen Workflow-Fertigkeit strukturieren“, „Eine Fertigkeit aus diesem Ordner extrahieren“, „Meinen Prototyp in eine Fertigkeit umwandeln“ oder auf ein Projektverzeichnis mit gemischten Fertigkeiten und Regeln oder auf einen Engineering-Ordner zeigt, in dem sich eine Fertigkeit befand Prototyp. Forge: Triage → Entdecken → Klassifizieren → Validieren → Reparieren → Lokal bereit. Workshop-Input → Triage extrahiert Fertigkeiten vor dem Audit. Nichts gefunden → Onboard-Benutzer, Gerüst, dann dieselbe Pipeline. Auf Anfrage auf GitHub veröffentlichen (Schritt 4).
