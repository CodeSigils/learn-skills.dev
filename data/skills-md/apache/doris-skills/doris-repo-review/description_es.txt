Dada una URL de PR (`/doris-repo-review https://github.com/apache/doris/pull/66807`), primero verifique si la rama y la confirmación del directorio actual coinciden con ese PR y, si no es así, alinee el directorio actual con el encabezado de PR sin perturbar el trabajo local (niegue a cambiar cuando se modifiquen los archivos rastreados y devuelva la decisión al usuario); luego revíselo con las mismas ejecuciones de CI de apache/doris (Code Review Runner): escaneo de riesgos del agente principal, 1-3 subagentes de revisión completa más subagentes centrados en el riesgo, convergencia de libro mayor compartido (como máximo 3 rondas) y un documento de revisión en inglés más uno en chino escrito en review-docs/. Una ejecución local no tiene comentarios en línea de GitHub, por lo que cada hallazgo debe incluir una ruta: ancla de línea y un fragmento textual, verificado mediante un script. Cuando se aprueba la revisión (sin Bloqueador ni Mayor), también publica un comentario PASS fuertemente formateado y legible por máquina sobre el PR de la cuenta local de gh (fecha de revisión, sha de compromiso revisado, estado, modelo y notas para los mantenedores) después de mostrar el cuerpo exacto al usuario para su confirmación. Úselo cuando el usuario diga "/doris-repo-review <URL de PR>", "revise este PR", "revíselo como lo hace la canalización de CI" o "revise este PR localmente como CI". Sólo lectura en comparación con el código fuente: sin compilación, sin pruebas, sin cambios en los archivos del repositorio; el comentario PASS es la única escritura en GitHub y una revisión REQUEST_CHANGES no publica nada en absoluto.
