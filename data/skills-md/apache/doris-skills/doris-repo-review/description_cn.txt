给定一个PR URL（`/doris-repo-review https://github.com/apache/doris/pull/66807`），首先检查当前目录的分支和提交是否与该PR匹配，如果不匹配，则将当前目录与PR头对齐，而不干扰本地工作（当跟踪文件被修改时拒绝切换，并将决定权交还给用户）；然后使用相同的管道 apache/doris CI 运行（Code Review Runner）对其进行审查 - 主代理风险扫描，1-3 个全面审查子代理加上以风险为中心的子代理，共享账本收敛（最多 3 轮），以及写入 review-docs/ 的一份英文加一份中文审查文档。本地运行没有 GitHub 内联注释，因此每个发现都必须带有路径：行锚点和逐字片段，并由脚本验证。当审核通过（没有 Blocker 且没有 Major）时，它还会从本地 gh 帐户对 PR 发布一条强格式的、机器可读的 PASS 评论 - 审核日期、审核的提交 sha、状态、模型和维护人员注释 - 在向用户显示确切的正文以供确认之后。当用户说“/doris-repo-review <PR URL>”、“查看此 PR”、“以 CI 管道的方式查看它”或“像 CI 一样在本地查看此 PR”时使用。对源代码只读 - 无需构建、无需测试、无需更改存储库文件； PASS 评论是唯一的 GitHub 评论，而 REQUEST_CHANGES 评论根本没有发布任何内容。
