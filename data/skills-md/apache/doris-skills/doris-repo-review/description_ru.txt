Учитывая URL-адрес PR (`/doris-repo-review https://github.com/apache/doris/pull/66807`), сначала проверьте, соответствуют ли ветка и фиксация текущего каталога этому PR, и если они не совпадают, согласуйте текущий каталог с заголовком PR, не нарушая локальную работу (откажитесь от переключения при изменении отслеживаемых файлов и передайте решение обратно пользователю); затем просмотрите его с помощью того же конвейера apache/doris CI (Code Review Runner) - сканирование рисков основного агента, 1-3 субагента полной проверки плюс субагенты, ориентированные на риски, конвергенция общего реестра (максимум 3 раунда) и один документ проверки на английском и одном китайском языке, записанный в review-docs/. Локальный запуск не имеет встроенных комментариев GitHub, поэтому каждый результат должен содержать привязку path:line и дословный фрагмент, проверенный сценарием. Когда проверка проходит (без Blocker и Major), она также публикует один строго отформатированный, машиночитаемый комментарий PASS к PR из локальной учетной записи gh — дату проверки, проверенный коммит-ша, статус, модель и примечания для сопровождающих — после показа точного тела пользователю для подтверждения. Используйте, когда пользователь говорит «/doris-repo-review <URL-адрес PR>», «просмотрите этот PR», «проверьте его так, как это делает конвейер CI» или «проверьте этот PR локально, как CI». Только чтение исходного кода — без сборки, без тестов, без изменений в файлах репозитория; комментарий PASS — единственная запись на GitHub, а обзор REQUEST_CHANGES вообще ничего не публикует.
