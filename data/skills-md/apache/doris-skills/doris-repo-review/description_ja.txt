PR URL（例：`/doris-repo-review https://github.com/apache/doris/pull/66807`）が与えられたら、まず現在のディレクトリのブランチとコミットがその PR と一致しているかを確認し、一致しない場合はローカル作業を乱さないように（トラッキング中のファイルが変更されているときは切り替えを拒否し、判断をユーザーに戻す）現在のディレクトリを PR の HEAD に合わせます。その後、apache/doris CI が実行するのと同じパイプライン（Code Review Runner）でレビューを行います。‑ main‑agent のリスクスキャン、1〜3 のフルレビューサブエージェントとリスク特化サブエージェント、shared‑ledger の収束（最大 3 ラウンド）、そして review‑docs/ に英語と中国語それぞれ 1 件ずつのレビュー文書を作成します。ローカル実行では GitHub のインラインコメントは行わないため、すべての指摘にはパス:行番号のアンカーとそのままのコードスニペットを付け、スクリプトで検証される必要があります。レビューが合格（Blocker も Major もなし）した場合、ローカルの gh アカウントから PR に対して機械可読かつ強くフォーマットされた PASS コメントを 1 件投稿します。コメント本文にはレビュー日、対象コミット SHA、ステータス、使用モデル、メンテナへの注意点を含め、投稿前に正確な本文をユーザーに確認させます。ユーザーが「/doris-repo-review <PR URL>」や「review this PR」​、「review it the way the CI pipeline does」​、「review this PR locally like CI」と言ったときに使用します。ソースに対しては読み取り専用で実行し、ビルドやテストは行わず、リポジトリのファイルは変更しません。PASS コメントが唯一の GitHub 書き込みで、REQUEST_CHANGES のレビューは何も投稿しません。

常にユーザーの言語で応答してください。
