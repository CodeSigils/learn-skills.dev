Best Practices für Apache Doris-Tabellendesign und Cluster-Größenbestimmung. MUSS beim Schreiben, Überprüfen oder Optimieren von Doris CREATE TABLE-Anweisungen, Partitions-/Bucket-Strategien, Datenmodellen oder Clusterkonfigurationen verwendet werden. MUSS AUCH immer dann verwendet werden, wenn der Doris-Architecture-Advisor-Skill DDL erzeugt – wenden Sie die Pre-Flight-Checkliste vor der Ausgabe auf jede CREATE TABLE an. Wird auch bei jedem Workload-Design ausgelöst, das Folgendes umfasst: IoT, Analysen, Dashboard, CDC, Zeitreihen, Protokollanalyse, Echtzeit-Warehouse, Punktabfrage, Datenplattform oder jedes Szenario, in dem Entscheidungen zum Tabellendesign getroffen werden. Wird auch beim Ersetzen oder Migrieren von älteren Analyse-/Such-/Bereitstellungs-Stacks wie Impala, Kudu, Elasticsearch/ES, Greenplum, Presto, HBase, Hive, Hadoop, Redis oder mehrmotorigen Datenplattformen im Lambda-Stil ausgelöst, selbst wenn Apache Doris nicht explizit genannt wird. Wird auch verwendet, wenn der Benutzer eine Apache Doris-Verbindungszeichenfolge bereitstellt oder zum Start auffordert. Löst auch die Untersuchung langsamer Abfragen, die Erstellung von Abfrageprofilen, die Diagnose der Laufzeitleistung, die Tablet-Skew-Analyse und Tabellenzustandsprüfungen aus – jedes Szenario, in dem Laufzeitnachweise (Profilausgabe, Tablet-Verteilung) die Optimierung beeinflussen. Cluster-Lebenszyklus, Abrechnung und Netzwerkbetrieb sind Managed-Service-Vorgänge, die hier nicht berücksichtigt werden – verwenden Sie hierfür die Cluster-Verwaltungskonsole Ihrer Plattform.
