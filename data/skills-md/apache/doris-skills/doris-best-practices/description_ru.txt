Рекомендации по проектированию таблиц Apache Doris и определению размера кластера. НЕОБХОДИМО ИСПОЛЬЗОВАТЬ при написании, проверке или оптимизации операторов Doris CREATE TABLE, стратегий разделов/корзин, моделей данных или конфигураций кластеров. ТАКЖЕ НЕОБХОДИМО ИСПОЛЬЗОВАТЬ всякий раз, когда навык doris-architecture-advisor создает DDL — применяйте предполетный контрольный список к каждому CREATE TABLE перед выводом. Также срабатывает при любом проектировании рабочей нагрузки, включая: Интернет вещей, аналитику, панель мониторинга, CDC, временные ряды, анализ журналов, хранилище в реальном времени, точечный запрос, платформу данных или любой сценарий, в котором принимаются решения по проектированию таблиц. Также срабатывает при замене или миграции с устаревших стеков аналитики/поиска/обслуживания, таких как Impala, Kudu, Elasticsearch/ES, Greenplum, Presto, HBase, Hive, Hadoop, Redis или многосистемных платформ данных в стиле Lambda, даже если Apache Doris не указан явно. Также используйте, когда пользователь предоставляет строку подключения Apache Doris или просит начать работу. Также срабатывает при исследовании медленных запросов, профилировании запросов, диагностике производительности во время выполнения, анализе искажений планшетов и проверках работоспособности таблиц — в любом сценарии, в котором данные времени выполнения (вывод профиля, распределение планшетов) влияют на оптимизацию. Жизненный цикл кластера, выставление счетов и работа в сети — это операции управляемого сервиса, которые здесь выходят за рамки — для этого используйте консоль управления кластером вашей платформы.
