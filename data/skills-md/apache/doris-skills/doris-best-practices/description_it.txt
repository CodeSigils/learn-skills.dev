Best practice per la progettazione delle tabelle Apache Doris e il dimensionamento dei cluster. DEVE UTILIZZARE durante la scrittura, la revisione o l'ottimizzazione delle istruzioni Doris CREATE TABLE, delle strategie di partizione/bucket, dei modelli di dati o delle configurazioni dei cluster. DEVE UTILIZZARE ANCHE ogni volta che l'abilità doris-architecture-advisor produce DDL: applica la lista di controllo pre-volo a ogni CREATE TABLE prima dell'output. Si attiva anche su qualsiasi progettazione del carico di lavoro che coinvolga: IoT, analisi, dashboard, CDC, serie temporali, analisi dei log, magazzino in tempo reale, query di punti, piattaforma dati o qualsiasi scenario in cui vengono prese decisioni sulla progettazione delle tabelle. Si attiva anche in caso di sostituzione o migrazione da stack di analisi/ricerca/serving legacy come Impala, Kudu, Elasticsearch/ES, Greenplum, Presto, HBase, Hive, Hadoop, Redis o piattaforme dati multi-motore in stile Lambda, anche quando Apache Doris non viene nominato esplicitamente. Da utilizzare anche quando l'utente fornisce una stringa di connessione Apache Doris o chiede di iniziare. Si attiva anche in caso di indagini lente sulle query, profilazione delle query, diagnosi delle prestazioni di runtime, analisi di disallineamento dei tablet e controlli di integrità delle tabelle: qualsiasi scenario in cui le prove di runtime (output del profilo, distribuzione dei tablet) informano l'ottimizzazione. Il ciclo di vita, la fatturazione e la rete del cluster sono operazioni di servizi gestiti, che non rientrano nell'ambito di questa sezione: utilizza la console di gestione del cluster della tua piattaforma per tali operazioni.
