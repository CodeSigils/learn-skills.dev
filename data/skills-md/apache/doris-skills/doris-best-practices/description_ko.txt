Apache Doris 테이블 디자인 및 클러스터 크기 조정 모범 사례. Doris CREATE TABLE 문, 파티션/버킷 전략, 데이터 모델 또는 클러스터 구성을 작성, 검토 또는 최적화할 때 반드시 사용해야 합니다. 또한 doris-architecture-advisor 기술이 DDL을 생성할 때마다 사용해야 합니다. 출력 전에 모든 CREATE TABLE에 비행 전 체크리스트를 적용해야 합니다. 또한 IoT, 분석, 대시보드, CDC, 시계열, 로그 분석, 실시간 웨어하우스, 포인트 쿼리, 데이터 플랫폼 또는 테이블 디자인 결정이 이루어지는 모든 시나리오와 관련된 모든 워크로드 디자인에서 트리거됩니다. 또한 Apache Doris가 명시적으로 이름이 지정되지 않은 경우에도 Impala, Kudu, Elasticsearch/ES, Greenplum, Presto, HBase, Hive, Hadoop, Redis 또는 Lambda 스타일 다중 엔진 데이터 플랫폼과 같은 레거시 분석/검색/서빙 스택을 교체하거나 마이그레이션할 때 트리거됩니다. 사용자가 Apache Doris 연결 문자열을 제공하거나 시작을 요청할 때도 사용합니다. 또한 느린 쿼리 조사, 쿼리 프로파일링, 런타임 성능 진단, 태블릿 편향 분석, 테이블 상태 확인 등 런타임 증거(프로필 출력, 태블릿 배포)가 최적화를 알리는 모든 시나리오에 대해 트리거됩니다. 클러스터 수명 주기, 청구 및 네트워킹은 관리형 서비스 작업이므로 여기 범위를 벗어납니다. 이를 위해서는 플랫폼의 클러스터 관리 콘솔을 사용하세요.
