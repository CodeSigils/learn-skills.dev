أفضل ممارسات تصميم جدول Apache Doris وتحجيم المجموعة. يجب استخدامه عند كتابة أو مراجعة أو تحسين عبارات Doris CREATE TABLE أو إستراتيجيات القسم/المجموعة أو نماذج البيانات أو تكوينات المجموعة. يجب استخدامه أيضًا عندما تنتج مهارة doris-architecture-advisor DDL - قم بتطبيق قائمة التحقق قبل الرحلة على كل جدول إنشاء قبل الإخراج. يتم تشغيله أيضًا في أي تصميم لأحمال العمل يتضمن: إنترنت الأشياء، أو التحليلات، أو لوحة المعلومات، أو مراكز السيطرة على الأمراض (CDC)، أو السلاسل الزمنية، أو تحليل السجل، أو المستودعات في الوقت الفعلي، أو الاستعلام عن النقاط، أو منصة البيانات، أو أي سيناريو يتم فيه اتخاذ قرارات تصميم الجدول. يتم تشغيله أيضًا عند الاستبدال أو الترحيل من مجموعات التحليلات/البحث/الخدمة القديمة مثل Impala، أو Kudu، أو Elasticsearch/ES، أو Greenplum، أو Presto، أو HBase، أو Hive، أو Hadoop، أو Redis، أو منصات البيانات متعددة المحركات بنمط Lambda، حتى عندما لا يتم تسمية Apache Doris بشكل صريح. يُستخدم أيضًا عندما يقدم المستخدم سلسلة اتصال Apache Doris أو يطلب البدء. يتم تشغيله أيضًا عند التحقيق البطيء في الاستعلامات، وملفات تعريف الاستعلامات، وتشخيص أداء وقت التشغيل، وتحليل انحراف الكمبيوتر اللوحي، وفحوصات سلامة الجدول - أي سيناريو حيث تشير أدلة وقت التشغيل (إخراج ملف التعريف، وتوزيع الكمبيوتر اللوحي) إلى عملية التحسين. تعتبر دورة حياة المجموعة والفوترة والشبكات بمثابة عمليات خدمة مُدارة، وهي خارج النطاق هنا - استخدم وحدة تحكم إدارة المجموعة الخاصة بالنظام الأساسي الخاص بك للقيام بذلك.
