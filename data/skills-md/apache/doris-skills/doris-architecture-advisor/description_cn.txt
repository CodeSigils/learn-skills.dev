Apache Doris 的工作负载感知架构设计。在设计数据架构、选择数据模型、规划摄取策略、调整集群大小或将业务需求转换为 Apache Doris 系统设计时必须使用。通过决策框架和规模优先工作流程补充 doris 最佳实践。当用户描述涉及以下内容的工作负载时使用：IoT、传感器数据、遥测、实时分析、仪表板、日志分析、日志搜索、CDC 同步、时间序列、设备监控、点查询服务、临时分析、lakehouse 联合、ETL/ELT 管道、报告分析、点击流、用户行为、可观察性、指标、车队跟踪或任何需要从头开始设计表的 OLAP 工作负载。还会触发以下提示：“为……设计一个表”、“我应该如何存储……”、“为……构建一个架构”、“我们有 X 台设备每 Y 秒发送数据”、“为……推荐一个集群大小”、“我应该使用什么数据模型……”、“我们每天需要摄取 X GB”、“从 MySQL/PostgreSQL 迁移到 Apache Doris”。即使未明确命名 Apache Doris，也可用于遗留分析/搜索/服务堆栈整合提示，包括替换或迁移 Impala、Kudu、Elasticsearch/ES、Greenplum、Presto、HBase、Hive、Hadoop、Redis 或 Lambda 式多引擎数据平台。
