Проектирование архитектуры с учетом рабочей нагрузки для Apache Doris. НЕОБХОДИМО ИСПОЛЬЗОВАТЬ при проектировании архитектур данных, выборе между моделями данных, планировании стратегий приема, определении размера кластеров или переводе бизнес-требований в проекты систем Apache Doris. Дополняет лучшие практики doris структурами принятия решений и рабочим процессом, ориентированным на определение размера. Используйте, когда пользователь описывает рабочую нагрузку, включающую: Интернет вещей, данные датчиков, телеметрию, аналитику в реальном времени, панель мониторинга, анализ журналов, поиск по журналам, синхронизацию CDC, временные ряды, мониторинг устройств, службу точечных запросов, специальную аналитику, объединение озер, конвейер ETL/ELT, аналитику отчетов, поток кликов, поведение пользователей, наблюдаемость, метрики, отслеживание парка или любую рабочую нагрузку OLAP, требующую разработки таблиц с нуля. Также срабатывает на такие запросы, как: «создать таблицу для...», «как мне хранить...», «построить архитектуру для...», «у нас есть X устройств, отправляющих данные каждые Y секунд», «рекомендовать размер кластера для...», «какую модель данных мне следует использовать для...», «нам нужно принимать X ГБ/день», «перейти с MySQL/PostgreSQL на Apache Doris». Также используйте для запросов консолидации стека устаревшей аналитики/поиска/обслуживания, даже если Apache Doris не указан явно, включая замену или миграцию с многомашинных платформ данных в стиле Impala, Kudu, Elasticsearch/ES, Greenplum, Presto, HBase, Hive, Hadoop, Redis или Lambda.
