Apache Doris 的工作負載感知架構設計。在設計資料架構、選擇資料模型、規劃攝取策略、調整叢集大小或將業務需求轉換為 Apache Doris 系統設計時必須使用。透過決策框架和規模優先工作流程補充 doris 最佳實踐。當使用者描述涉及以下內容的工作負載時使用：IoT、感測器資料、遙測、即時分析、儀表板、日誌分析、日誌搜尋、CDC 同步、時間序列、設備監控、點查詢服務、臨時分析、lakehouse 聯合、ETL/ELT 管道、報告分析、點擊流、用戶行為、可觀察性、指標、車隊或任何需要從頭開始追蹤工作表的 OLAP 工作負載。也會觸發以下提示：「為…設計一個表」、「我應該如何儲存…」、「為…建立一個架構」、「我們有 X 台設備每 Y 秒發送資料」、「為…推薦一個群集大小」、「我應該使用什麼資料模型…」、「我們每天需要攝取 X GB」、「從 MySQL/PostgreSQL 遷移到 Apacheris Do」。即使未明確命名 Apache Doris，也可用於遺留分析/搜尋/服務堆疊整合提示，包括替換或遷移 Impala、Kudu、Elasticsearch/ES、Greenplum、Presto、HBase、Hive、Hadoop、Redis 或 Lambda 式多引擎資料平台。
