Apache Doris のワークロードを意識したアーキテクチャ設計。データ アーキテクチャの設計、データ モデルの選択、取り込み戦略の計画、クラスターのサイジング、またはビジネス要件の Apache Doris システム設計への変換を行うときに使用する必要があります。 doris のベスト プラクティスを意思決定フレームワークとサイジング優先のワークフローで補完します。ユーザーが、IoT、センサー データ、テレメトリ、リアルタイム分析、ダッシュボード、ログ分析、ログ検索、CDC 同期、時系列、デバイス モニタリング、ポイント クエリ サービス、アドホック分析、レイクハウス フェデレーション、ETL/ELT パイプライン、レポート分析、クリックストリーム、ユーザー行動、可観測性、メトリクス、フリート トラッキング、またはゼロからのテーブル設計を必要とする OLAP ワークロードを含むワークロードを説明する場合に使用します。また、「... のテーブルを設計する」、「... をどのように保存すればよいか」、「... のアーキテクチャを構築する」、「Y 秒ごとにデータを送信する X 台のデバイスがある」、「... のクラスター サイズを推奨する」、「... にはどのデータ モデルを使用する必要があるか」、「X GB/日を取り込む必要がある」、「MySQL/PostgreSQL から Apache Doris に移行する」などのプロンプトでもトリガーされます。また、Apache Doris が明示的に指定されていない場合でも、Impala、Kudu、Elasticsearch/ES、Greenplum、Presto、HBase、Hive、Hadoop、Redis、または Lambda スタイルのマルチエンジン データ プラットフォームからの置き換えまたは移行を含め、従来の分析/検索/サービス スタックの統合プロンプトにも使用できます。
