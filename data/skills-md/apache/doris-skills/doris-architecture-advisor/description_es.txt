Diseño de arquitectura consciente de la carga de trabajo para Apache Doris. DEBE UTILIZARSE al diseñar arquitecturas de datos, elegir entre modelos de datos, planificar estrategias de ingesta, dimensionar clústeres o traducir requisitos comerciales en diseños de sistemas Apache Doris. Complementa las mejores prácticas de Doris con marcos de decisión y un flujo de trabajo que prioriza el tamaño. Úselo cuando el usuario describe una carga de trabajo que involucra: IoT, datos de sensores, telemetría, análisis en tiempo real, panel, análisis de registros, búsqueda de registros, sincronización CDC, series temporales, monitoreo de dispositivos, servicio de consulta puntual, análisis ad-hoc, federación Lakehouse, canalización ETL/ELT, análisis de informes, flujo de clics, comportamiento del usuario, observabilidad, métricas, seguimiento de flotas o cualquier carga de trabajo OLAP que requiera un diseño de tabla desde cero. También se activa en mensajes como: "diseñar una tabla para...", "cómo debo almacenar...", "construir una arquitectura para...", "tenemos X dispositivos que envían datos cada Y segundos", "recomendar un tamaño de clúster para...", "para qué modelo de datos debo usar...", "necesitamos ingerir X GB/día", "migrar de MySQL/PostgreSQL a Apache Doris". También se utiliza para solicitudes de consolidación de pila de servicios/búsqueda/análisis heredados incluso cuando Apache Doris no se menciona explícitamente, incluido el reemplazo o la migración desde Impala, Kudu, Elasticsearch/ES, Greenplum, Presto, HBase, Hive, Hadoop, Redis o plataformas de datos multimotor estilo Lambda.
