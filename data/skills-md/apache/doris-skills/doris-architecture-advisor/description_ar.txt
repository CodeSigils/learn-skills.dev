تصميم معماري مدرك لأعباء العمل لـ Apache Doris. يجب استخدامه عند تصميم بنيات البيانات، أو الاختيار بين نماذج البيانات، أو تخطيط استراتيجيات الاستيعاب، أو تحديد حجم المجموعات، أو ترجمة متطلبات العمل إلى تصميمات نظام Apache Doris. يكمل أفضل ممارسات دوريس مع أطر اتخاذ القرار وسير عمل تحديد الحجم أولاً. يُستخدم عندما يصف المستخدم عبء عمل يتضمن: إنترنت الأشياء، وبيانات الاستشعار، والقياس عن بعد، والتحليلات في الوقت الفعلي، ولوحة المعلومات، وتحليل السجل، والبحث في السجل، ومزامنة CDC، والسلاسل الزمنية، ومراقبة الجهاز، وخدمة استعلام النقاط، والتحليلات المخصصة، واتحاد البحيرة، وخط أنابيب ETL/ELT، وتحليلات التقارير، وتدفق النقر، وسلوك المستخدم، وقابلية الملاحظة، والمقاييس، وتتبع الأسطول، أو أي حمل عمل OLAP يتطلب تصميم جدول من البداية. يتم تشغيله أيضًا على مطالبات مثل: "تصميم جدول لـ..."، "كيف يمكنني تخزين..."، "إنشاء بنية لـ..."، "لدينا X من الأجهزة التي ترسل البيانات كل Y ثانية"، "التوصية بحجم كتلة لـ..."، "ما نموذج البيانات الذي يجب أن أستخدمه من أجل..."، "نحن بحاجة إلى استيعاب X جيجابايت/يوم"، "الترحيل من MySQL/PostgreSQL إلى Apache Doris". يُستخدم أيضًا لمطالبات دمج مكدس التحليلات/البحث/الخدمة القديمة حتى عندما لا يتم تسمية Apache Doris بشكل صريح، بما في ذلك الاستبدال أو الترحيل من منصات البيانات متعددة المحركات على طراز Impala أو Kudu أو Elasticsearch/ES أو Greenplum أو Presto أو HBase أو Hive أو Hadoop أو Redis أو Lambda.
