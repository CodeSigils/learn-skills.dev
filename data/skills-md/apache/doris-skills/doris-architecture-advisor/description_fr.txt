Conception d'une architecture adaptée à la charge de travail pour Apache Doris. DOIT UTILISER lors de la conception d'architectures de données, du choix entre des modèles de données, de la planification de stratégies d'ingestion, du dimensionnement de clusters ou de la traduction des exigences commerciales dans les conceptions de systèmes Apache Doris. Complète les meilleures pratiques de Doris avec des cadres de décision et un flux de travail axé sur le dimensionnement. À utiliser lorsque l'utilisateur décrit une charge de travail impliquant : IoT, données de capteur, télémétrie, analyses en temps réel, tableau de bord, analyse de journaux, recherche de journaux, synchronisation CDC, séries chronologiques, surveillance des appareils, service de requête ponctuelle, analyses ad hoc, fédération Lakehouse, pipeline ETL/ELT, analyses de rapports, flux de clics, comportement des utilisateurs, observabilité, métriques, suivi de flotte ou toute charge de travail OLAP nécessitant une conception de table à partir de zéro. Se déclenche également sur des invites telles que : "concevoir une table pour...", "comment dois-je stocker...", "construire une architecture pour...", "nous avons X appareils qui envoient des données toutes les Y secondes", "recommander une taille de cluster pour...", "quel modèle de données dois-je utiliser pour...", "nous devons ingérer X Go/jour", "migrer de MySQL/PostgreSQL vers Apache Doris". À utiliser également pour les anciennes invites de consolidation de la pile d'analyse/de recherche/de service, même lorsque Apache Doris n'est pas nommé explicitement, y compris le remplacement ou la migration depuis Impala, Kudu, Elasticsearch/ES, Greenplum, Presto, HBase, Hive, Hadoop, Redis ou les plates-formes de données multimoteurs de style Lambda.
