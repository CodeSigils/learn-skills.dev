Workload-bewusstes Architekturdesign für Apache Doris. MUSS verwendet werden, wenn Sie Datenarchitekturen entwerfen, zwischen Datenmodellen wählen, Aufnahmestrategien planen, Cluster dimensionieren oder Geschäftsanforderungen in Apache Doris-Systemdesigns übersetzen. Ergänzt doris-best-practices mit Entscheidungsrahmen und Sizing-First-Workflow. Wird verwendet, wenn der Benutzer eine Arbeitslast beschreibt, die Folgendes umfasst: IoT, Sensordaten, Telemetrie, Echtzeitanalysen, Dashboard, Protokollanalyse, Protokollsuche, CDC-Synchronisierung, Zeitreihen, Geräteüberwachung, Punktabfragedienst, Ad-hoc-Analysen, Lakehouse-Föderation, ETL/ELT-Pipeline, Berichtsanalysen, Clickstream, Benutzerverhalten, Beobachtbarkeit, Metriken, Flottenverfolgung oder jede OLAP-Arbeitslast, die ein Tabellendesign von Grund auf erfordert. Löst auch auf Eingabeaufforderungen aus wie: „Entwerfen Sie eine Tabelle für …“, „Wie soll ich speichern …“, „Erstellen Sie eine Architektur für …“, „Wir haben Wird auch für Eingabeaufforderungen zur Konsolidierung älterer Analyse-/Such-/Bereitstellungsstacks verwendet, selbst wenn Apache Doris nicht explizit genannt wird, einschließlich der Ersetzung oder Migration von Impala, Kudu, Elasticsearch/ES, Greenplum, Presto, HBase, Hive, Hadoop, Redis oder mehrmotorigen Datenplattformen im Lambda-Stil.
