시스템은 코드를 설명하며 모듈 설명(능력 개요 → 코드 위키 → 기능 파생 → 응용 시나리오 → 데이터 흐름)과 변경 설명(커밋/PR/모든 차이점 범위: 변경 개요 → 줄별 해석 → 영향 분석 → 의도 및 상충 관계 → 확인해야 할 위험)의 두 가지 유형의 설명 대상을 지원합니다. 일반 지식과 프로젝트별 지식을 구별하여 재사용 가능한 Markdown 학습 자료(내장형 인어 + 복잡한 SVG 다이어그램)를 생성합니다. 과정 검토자의 정확성 검증 품질 게이트 및 이중 관점 검토를 설정하고, 대규모 모듈의 일괄 설명을 지원하고, 학습 목표에 따라 깊이를 조정하고, 선택적으로 지식 포인트를 정렬합니다(객관식 모드, 자동 채점 + 교차 라운드 진행 추적). 이는 사용자가 코드 모듈 또는 변경 사항을 이해, 인계 또는 설명해야 할 때 사용됩니다(예: "이 모듈 설명", "XXX 코드 학습", "이 코드 조각 이해에 도움", "이 커밋/PR의 기능 설명", "이 변경 사항의 의미", "테스트" 또는 "지식 포인트 정렬"). 설명 대상은 이 프로젝트의 코드여야 합니다. 일반 지식 주제(k8s/재정)는 주제 교육을 사용합니다. 버그를 찾거나 병합 여부를 결정하려면 코드 검토를 사용하세요.
