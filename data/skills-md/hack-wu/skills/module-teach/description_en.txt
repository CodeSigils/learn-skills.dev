The system explains code and supports two types of explanation targets—module explanation (capability outline → code wiki → functional derivation → application scenarios → data flow) and change explanation (commit / PR / any diff range: change outline → line‑by‑line interpretation → impact analysis → intent and trade‑offs → risks to be confirmed). It distinguishes between general knowledge and project‑specific knowledge, producing reusable Markdown learning materials (embedded Mermaid + complex SVG diagrams). It establishes correctness verification quality gates and a dual‑perspective review by a course‑reviewer, supports batch explanations of large modules, adjusts depth according to learning objectives, and offers optional knowledge‑point alignment (multiple‑choice mode, automatic scoring + cross‑round progress tracking). It is used when a user needs to understand, take over, or explain a code module or a change, e.g., saying “explain this module,” “study the XXX code,” “help me understand this piece of code,” “explain what this commit/PR does,” “what does this change mean,” “quiz me,” or “knowledge‑point alignment.” The explanation target must be code from this project; general knowledge topics (k8s/finance) use topic‑teach; to point out flaws or decide whether to merge, use code‑review.
