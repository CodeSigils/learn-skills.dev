The system explains code, supporting two types of explanation targets—module explanation (capability outline → code wiki → functional derivation → application scenarios → data flow) and change explanation (commit / PR / any diff range: change outline → line-by-line interpretation → impact analysis → intent and trade‑offs → risks to be confirmed). It distinguishes between generic knowledge and project‑specific knowledge, producing reusable Markdown learning materials (embedded Mermaid + complex SVG diagrams). It establishes correctness verification quality gates and dual‑perspective review by a course reviewer, supports batch explanation of large modules, adjusts depth according to learning objectives, and optionally aligns knowledge points (multiple‑choice mode, automatic scoring + cross‑round progress tracking). It is used when users need to understand, take over, or explain a code module or a change, e.g., “explain this module,” “learn the XXX code,” “help me understand this piece of code,” “explain what this commit/PR does,” “what does this change mean,” “test me,” or “knowledge point alignment.” The explanation target must be code from this project; generic knowledge topics (k8s/finance) use topic‑teach; for bug‑finding or deciding whether to merge, use code‑review.
