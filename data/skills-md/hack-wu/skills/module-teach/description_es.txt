El sistema explica el código y admite dos tipos de objetivos de explicación: explicación del módulo (esquema de capacidad → código wiki → derivación funcional → escenarios de aplicación → flujo de datos) y explicación de cambio (compromiso / PR / cualquier rango de diferencia: esquema de cambio → interpretación línea por línea → análisis de impacto → intención y compensaciones → riesgos por confirmar). Distingue entre conocimiento genérico y conocimiento específico del proyecto, produciendo materiales de aprendizaje Markdown reutilizables (sirena integrada + diagramas SVG complejos). Establece puertas de calidad para la verificación de la corrección y una revisión en perspectiva dual por parte de un revisor del curso, admite la explicación por lotes de módulos grandes, ajusta la profundidad según los objetivos de aprendizaje y, opcionalmente, alinea los puntos de conocimiento (modo de opción múltiple, puntuación automática + seguimiento del progreso en varias rondas). Se utiliza cuando los usuarios necesitan comprender, hacerse cargo o explicar un módulo de código o un cambio, por ejemplo, "explicar este módulo", "aprender el código XXX", "ayúdame a comprender este fragmento de código", "explica qué hace esta confirmación/PR", "qué significa este cambio", "ponme a prueba" o "alineación de puntos de conocimiento". El objetivo de la explicación debe ser el código de este proyecto; temas de conocimiento genérico (k8s/finanzas) utilizan tema-enseñanza; Para encontrar errores o decidir si fusionar, utilice la revisión de código.
