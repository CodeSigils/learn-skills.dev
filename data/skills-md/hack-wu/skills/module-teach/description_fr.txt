Le système explique le code, prenant en charge deux types de cibles d'explication : l'explication du module (aperçu des capacités → wiki du code → dérivation fonctionnelle → scénarios d'application → flux de données) et l'explication du changement (validation / PR / toute plage de diff : aperçu du changement → interprétation ligne par ligne → analyse d'impact → intention et compromis → risques à confirmer). Il fait la distinction entre les connaissances génériques et les connaissances spécifiques au projet, produisant du matériel d'apprentissage Markdown réutilisable (Sirène intégrée + diagrammes SVG complexes). Il établit des critères de qualité pour la vérification de l'exactitude et un examen à double perspective par un évaluateur de cours, prend en charge l'explication par lots de modules volumineux, ajuste la profondeur en fonction des objectifs d'apprentissage et aligne éventuellement les points de connaissances (mode à choix multiples, notation automatique + suivi des progrès croisés). Il est utilisé lorsque les utilisateurs ont besoin de comprendre, de reprendre ou d'expliquer un module de code ou un changement, par exemple « expliquer ce module », « apprendre le code XXX », « m'aider à comprendre ce morceau de code », « expliquer ce que fait cette validation/PR », « que signifie ce changement », « me tester » ou « alignement des points de connaissance ». La cible de l'explication doit être le code de ce projet ; les sujets de connaissances génériques (k8s/finance) utilisent l'enseignement thématique ; pour rechercher des bogues ou décider de fusionner, utilisez la révision de code.
