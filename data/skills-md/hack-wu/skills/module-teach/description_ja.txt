システムはコードを説明し、モジュールの説明 (機能の概要 → コード Wiki → 機能派生 → アプリケーション シナリオ → データ フロー) と変更の説明 (コミット / PR / 任意の差分範囲: 変更の概要 → 行ごとの解釈 → 影響分析 → 意図とトレードオフ → 確認すべきリスク) の 2 種類の説明ターゲットをサポートします。一般的な知識とプロジェクト固有の知識を区別し、再利用可能な Markdown 学習教材 (埋め込まれた Mermaid + 複雑な SVG 図) を生成します。正しさ検証の品質ゲートとコース査読者による二重視点レビューを確立し、大規模なモジュールのバッチ説明をサポートし、学習目的に応じて深さを調整し、オプションで知識ポイントを調整します (多肢選択モード、自動採点 + クロスラウンド進行状況追跡)。これは、ユーザーがコード モジュールや変更を理解し、引き継ぎ、または説明する必要がある場合に使用されます。たとえば、「このモジュールについて説明する」、「XXX コードを学習する」、「このコード部分を理解するのを手伝ってください」、「このコミット/PR が何をするのか説明してください」、「この変更は何を意味するのか」、「テストしてください」、「知識ポイントの調整」などです。説明のターゲットはこのプロジェクトのコードである必要があります。一般知識トピック (k8s/金融) は topic-teach を使用します。バグの発見やマージするかどうかの決定には、コードレビューを使用してください。
