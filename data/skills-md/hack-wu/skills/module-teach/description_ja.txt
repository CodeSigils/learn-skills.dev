システムはコードを説明し、モジュールの説明 (機能の概要 → コード wiki → 機能派生 → アプリケーション シナリオ → データ フロー) と変更の説明 (コミット / PR / 任意の差分範囲: 変更の概要 → 行ごとの解釈 → 影響分析 → 意図とトレードオフ → 確認すべきリスク) の 2 種類の説明対象をサポートします。一般的な知識とプロジェクト固有の知識を区別し、反復可能な Markdown 学習教材 (埋め込まれた Mermaid + 複雑な SVG 図) を生成します。正確性検証の品質ゲートとコース査読者による二重視点のレビューを確立し、大規模なモジュールのバッチ説明、学習目的に応じた深さの調整、オプションの知識ポイントの調整 (多肢選択モード、自動採点 + クロスラウンド進行状況追跡) をサポートします。ユーザーがコード モジュールや特定の変更を理解、引き継ぎ、または説明する必要がある場合、または「このモジュールについて説明してください」、「XXX コードを学習してください」、「このコード部分を取得するのを手伝ってください」、「このコミット/PR が何をするのか説明してください」、「この変更は何を意味しますか」、「クイズしてください」、「知識ポイントの調整」などと言うときに、これが使用されます。説明のターゲットはこのプロジェクトのコードである必要があります。一般知識トピック (k8s/金融) は topic-teach を使用します。バグを見つけたり、マージするかどうかを決定するには、コードレビューを使用します。
