Indique si un commentaire de code doit exister et oblige ceux qui restent à expliquer pourquoi, pas quoi. Utilisez TOUJOURS avant d'écrire ou de modifier un commentaire dans n'importe quel langage (Python, TypeScript, Go, Rust, SQL) et lors de la révision d'une différence qui ajoute des commentaires. Supprime les types de commentaires qui encombrent la base de code : narration qui reformule le code, notes d'historique des modifications et de contexte de discussion ("précédemment fait X", "selon PR #123", "AI :"), mesures périssables et tampons de l'état actuel ("~ 20 min de construction", "actuellement", "aujourd'hui"), code commenté et docstrings redondants. Conserve ceux qui méritent leur place : un pourquoi non évident, un avertissement sur une conséquence non locale, un pointeur vers un contexte qu'un futur lecteur ne peut pas reconstruire. Pas pour la copie destinée à l'utilisateur (voir `/writing-user-facing-copy`) ou les messages de validation.
