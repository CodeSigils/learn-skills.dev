Flusso di lavoro per l'ottimizzazione delle query ClickHouse e HogQL. Da utilizzare quando una query HogQL, un query runner, un insight o un report è troppo lento; quando una query ClickHouse scritta a mano (tramite `sync_execute` o in una migrazione) è troppo lenta; quando ClickHouse va in timeout o raggiunge i limiti di memoria; durante l'analisi di una riga `system.query_log` lenta; o quando si esamina una proposta di modifica della stampante HogQL per quanto riguarda le prestazioni. Riguarda l'estrazione dell'SQL di ClickHouse, gli odori comuni ("FROM ... FINAL", "JSONExtract" sulle proprietà, gli indici di salto mancanti, i self-join, l'espansione CTE), la misurazione rispetto a un cluster reale e l'applicazione della correzione al livello giusto (stampante, query runner o migrazione). NON copre le query Postgres/Django ORM/app-database; quelli necessitano di pganalyze e della sezione Postgres di "query-performance-optimization.md".
