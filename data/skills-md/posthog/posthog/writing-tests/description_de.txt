Gibt an, ob ein neuer Test vorhanden sein sollte, und erzwingt dessen Effizienz, wodurch CI vor einer Aufblähung von Tests mit geringem Wert geschützt wird. Verwenden Sie diese Option, bevor Sie einen Pytest-, Jest- oder Playwright-Test hinzufügen oder wesentlich ändern – immer dann, wenn ein Agent oder Ingenieur Tests für eine neue Funktion, Fehlerbehebung oder PR schreiben möchte. Lädt die Wertleiste (jeder Test muss eine realistische Regression abfangen, die kein vorhandener Test bereits abfängt; Testverhalten über die öffentliche Schnittstelle, nicht Implementierungsdetails; Reduziert Beinahe-Duplikate in parametrisierte Fälle) und die Effizienzleiste (deterministisch, isoliert, schnell; wählt die günstigste Teststufe aus; Django TestCase über TransactionTestCase; keine Schlafphasen, kein echtes Netzwerk). Enthält einen „Nicht schreiben“-Entscheidungsbaum. Um einen vorhandenen Flaky-Test zu reparieren, verwenden Sie „/fixing-flaky-tests“; Nachdem dieses Tor besagt, dass ein Playwright-Test gerechtfertigt ist, verwenden Sie „/playwright-test“ für die Mechanik.
