Stellen Sie einen frisch erstellten Git-Arbeitsbaum bereit, damit sein Entwicklungsserver genau wie der aktive Trunk läuft. ZUERST wird der Arbeitsbaum schnell bis zum aktiven Stamm vorgespult (ein Arbeitsbaum ist an seinen eigenen eingefrorenen Zweig angeheftet, so dass er stillschweigend hinter jedem Trunk-Commit zurückbleibt – „fehlende Commits“), kopiert dann gitignorierte env-Dateien (.env.local, .env) aus dem Haupt-Checkout, installiert node_modules mit dem Paketmanager des Repos (pnpm/npm/yarn/bun) und überprüft – für Next.js – das Turbopack Workspace-Root + AllowedDevOrigins-Pins, die ein Einfrieren des Nested-Worktree-Dev-Servers und portlose HMR-Blöcke verhindern. Verwenden Sie es direkt nach dem Erstellen eines Arbeitsbaums (git worktree add oder „claude --worktree“) oder immer dann, wenn einem Arbeitsbaum aktuelle Commits fehlen, er mit fehlenden Umgebungsvariablen, „nächster: Befehl nicht gefunden“, einem „node_modules-missing“-Fehler oder einer Warnung „abgeleiteter Arbeitsbereichsstamm“ fehlschlägt. Auslöser: Einrichten / Bootstrap / Bereitstellen / Vorbereiten / Aufholen eines Arbeitsbaums, „Ich habe gerade einen Arbeitsbaum erstellt“, „Arbeitsbaum fehlen Commits / hinter Trunk“, „Arbeitsbaum fehlt seine .env / node_modules“, „diesen Arbeitsbaum wie den Hauptbaum ausführen lassen“, „Entwicklungsserver im Arbeitsbaum kaputt“. Funktioniert für jedes JS/TS-Repo. Handbuch: /worktree-bootstrap.
