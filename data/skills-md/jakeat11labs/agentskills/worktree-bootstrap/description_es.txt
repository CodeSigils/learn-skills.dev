Aprovisione un árbol de trabajo git recién creado para que su servidor de desarrollo se ejecute exactamente como el tronco activo. PRIMERO avanza rápidamente el árbol de trabajo hasta el tronco activo (un árbol de trabajo está anclado a su propia rama congelada, por lo que silenciosamente se queda atrás de cada confirmación del tronco - "compromisos faltantes"), luego copia los archivos env ignorados por git (.env.local, .env) de la caja principal, instala node_modules con el administrador de paquetes del repositorio (pnpm/npm/yarn/bun) y, para Next.js, verifica el Turbopack raíz del espacio de trabajo + pines permitidos de DevOrigins que evitan que el servidor de desarrollo del árbol de trabajo anidado se congele y se bloquee el HMR sin puerto. Úselo justo después de crear un árbol de trabajo (git worktree add, o `claude --worktree`), o cuando a un árbol de trabajo le falten confirmaciones recientes, falle porque faltan variables de entorno, "siguiente: comando no encontrado", un error de node_modules-missing o una advertencia de "raíz del espacio de trabajo inferida". Activadores: configurar/arrancar/aprovisionar/preparar/poner al día un árbol de trabajo, "Acabo de crear un árbol de trabajo", "al árbol de trabajo le faltan confirmaciones/detrás del tronco", "al árbol de trabajo le falta su .env/node_modules", "hacer que este árbol de trabajo se ejecute como principal", "servidor de desarrollo roto en el árbol de trabajo". Funciona para cualquier repositorio JS/TS. Manual: /worktree-bootstrap.
