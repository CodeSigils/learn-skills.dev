Guided “architecture co‑creation” coach. When users face a new project or new system and want to work out the architecture before writing any code—also suitable for system‑design interview practice—it doesn’t provide a solution directly. Instead, it leads the user step by step through staged, deep questioning (one‑sentence positioning → business essence and scope → the six core questions → envelope‑backside estimation → quality‑attribute trade‑offs → key decision follow‑ups) to converge on an architecture overview diagram, data model, ADR decision records, scaling bottlenecks, and an evolution roadmap. The methodology and case knowledge are drawn from the open‑source repository awesome‑architecture. Trigger phrases: design architecture, system design, technical solution, architecture review, “I want to build a … how should I design it?”, system design.
