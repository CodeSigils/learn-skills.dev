À utiliser lors de la refactorisation d'un code existant qui a un Big-O médiocre : boucles imbriquées, analyses O(n^2)+, travail répété, allocations redondantes, mémoire saturée ou symptômes déclarés tels que "cela est lent sur les entrées volumineuses", "dépassement de délai", "MOO", "trop ​​de mémoire", "réduire la complexité", "optimiser cet algorithme". Cible la complexité temporelle et spatiale du code déjà existant. Pour éviter une mauvaise complexité avant l'écriture du code, utilisez lemmaly. Pour les optimisations au niveau mathématique (projection Bloom, HLL, FFT, JL), passez à mathguard.
