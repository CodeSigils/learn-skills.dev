パブリック ApplicantWorkflow API (App Token auth) を介して Sumsub 申請者ワークフローを作成します。ユーザーが「Sumsub ワークフローの作成 / 構築 / 追加」を要求したとき、検証ルーティング (レベル + ブランチ + アクション) のフローチャート形式の説明を提供したとき、国ベースのルーティング / エージ ルーティング / 再試行ロジックを配線したいとき、フロー内で最終拒否または手動レビューのステップを設定するよう要求したとき、またはアクション ワークフロー (タグ付け、メモ、ソース キーの変更などの検証後の自動化) をモデル化したいときにトリガーします。結果のリビジョン (`/revisionStatus`) の公開についても説明します。既存のワークフロー リビジョンの任意のフィールドを編集する場合、またはより広範な製品構成フロー (アンケート、レベル - これらは別のスキルでカバーします) を編集する場合はスキップします。
