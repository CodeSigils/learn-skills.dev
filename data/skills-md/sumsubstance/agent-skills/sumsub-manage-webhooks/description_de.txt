Verwalten Sie Sumsub „clientWebhooks“ (Veranstaltungsabonnements für BewerberReviewed / BewerberPending / KytTxn / etc.) über „/resources/clientWebhooks“. **Nur Sandbox** – Produktions-Webhooks müssen von einem Menschen direkt im Sumsub-Dashboard erstellt werden. TRIGGER, wenn der Benutzer „Webhooks auflisten/abrufen/anzeigen“, „einen Webhook erstellen/hinzufügen/registrieren“, „ein Webhook-Ziel/eine Ereignisliste/ein Geheimnis/einen Signaturalgorithmus aktualisieren/bearbeiten/ändern“ oder „einen Webhook deaktivieren/erneut aktivieren“ für seinen Sandbox-Mandanten auffordert. SKIP für die Einrichtung von Produktions-Webhooks (verweisen Sie den Benutzer auf das Dashboard), für nicht verwandte Webhook-Oberflächen (Stripe/videoIdent/Fireblocks/NFC/partnerspezifische Empfangspfade unter „/resources/webhooks/...“), zum Testen einer einmaligen Zustellung (verwenden Sie den Endpunkt „inspectionCallbacks/testWebhook“ direkt) und für reines KYT-Webhook-Routing (das im KYT-Abschnitt des Sumsub-Dashboards verwaltet wird). Die öffentliche API stellt keine Lösch- oder Webhook-Zustellungsstatistiken zur Verfügung – verweisen Sie den Benutzer für diese auf die Benutzeroberfläche des Sumsub-Dashboards.
