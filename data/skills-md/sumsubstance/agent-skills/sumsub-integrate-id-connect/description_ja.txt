Sumsub ID Connect を統合するためのエンドツーエンドのレシピ — ユーザーが以前に検証された ID クレームをアプリと共有できるようにする OIDC ベースの「Sumsub ID で検証」フロー。ユーザーが「Sumsub ID Connectの統合」、「Sumsub IDで検証ボタンを追加」、「OIDC経由でSumsub KYCを再利用」、「Sumsub認証コードの交換」、「Sumsub ID共有トークンの作成」を要求したとき、または`@sumsub/id-connect`、OIDC `code → access_token`交換の接続方法を尋ねたときにトリガーされます。 (`/api/snsId/oauth/token`)、共有トークン / パートナー同意フロー、または共有リンク リダイレクト。前提条件のチェックリスト、自動化されたプリフライト、フロントエンド ボタン (ライブラリ ボタン + 生のリダイレクト代替)、バックエンドのコードとトークンの交換、共有トークンのミント、パートナー同意の shareLink フロー、および `/resources/api/reusableIdentity/reuse` を介した申請者の具体化をカバーします。スタンドアロン WebSDK / KYC ウィジェット (`sumsub-integrate-websdk` を使用) の場合、またはユーザー仲介の OIDC ステップなしで提供者と受信者が両方とも独自のテナントであるプレーンな Reusable-KYC-via-API の場合はスキップします。
