Директивы по проектированию кода, применяемые по умолчанию при написании, проверке или рефакторинге кода — охватывают самодокументируемый код (без комментариев), именование, плоский поток управления (защитные предложения / максимум 2 уровня вложенности), композицию вместо наследования, внедрение зависимостей, избежание преждевременной оптимизации, избежание чрезмерной абстракции и прагматизм в отношении парадигм. Используйте, когда пользователь просит написать, просмотреть, очистить или провести рефакторинг кода или проверить изменение на соответствие рекомендациям по дизайну/стилю.
