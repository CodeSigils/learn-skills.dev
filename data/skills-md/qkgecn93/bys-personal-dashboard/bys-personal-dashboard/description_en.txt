Bys Personal Dashboard Generator. Through a guided interview, help users (including those who know nothing about coding) create their own mobile personal dashboard—a permanent function bar on the left and a card stream on the right; opening it shows today’s plan, check‑ins, accounting, weight, schedule, vocabulary, a “tree‑hole”, and other things the user truly needs every day. It can be deployed, published, and added to the phone’s home screen, used like an app. When the user says “initialize Bys Personal Dashboard Generator”, “initialize bys‑personal‑dashboard”, “I want to make my own personal dashboard”, “I want the kind of personal dashboard I saw on Douyin”, or “turn my daily schedule into a mobile page”, it must be triggered; even if the user just drops a screenshot of someone else’s dashboard and says “I want this too”, it should also be triggered. After a dashboard already exists, if the user says “add an XX feature to my dashboard”, “change the dashboard’s color scheme”, or “modify the dashboard”, follow an iteration process instead of re‑initializing.  

If the user doesn’t use the word “dashboard”, judge by three characteristics: ① used on a mobile phone, ② opened every day, ③ stores the user’s own private data (weight, accounts, check‑ins, to‑do, diary). If all three are true, trigger it—for example, “I want to consolidate my weight, accounting, and to‑do list in one place that I can open on my phone”—that is a dashboard, even if the user doesn’t know the term. If any of the three is missing, do not trigger. Even a single function counts—“I keep forgetting to take my medicine, I want to tick it off every day on my phone” is a seed requirement; don’t ignore it because “it sounds like a small feature”.  

The criterion is who owns the data, not where the data is stored: the user’s own accounting Excel that they want to turn into a daily‑view page on the phone is a dashboard; company sales data for a report is not.  

Not applicable: disposable small‑tool pages that don’t store personal data (lottery wheel, calculator, countdown placed on a large screen or live broadcast for others), backend management systems, multi‑user collaboration tools for a team, personal blog/portfolio/personal website for external display (those are for others, not for daily personal use), company or business data dashboards (built with XLSX or similar), ordinary HTML coding questions unrelated to a personal dashboard.
