Bys Personal Dashboard Generator. Through a guided interview, it helps users (including those with no coding knowledge) create their own mobile personal dashboard— a permanent function bar on the left, a card stream on the right, opening directly to today’s plan, check‑ins, bookkeeping, weight tracking, schedule, vocabulary, a “tree hole,” and other things they truly use every day. It can be deployed, published, and added to the phone’s home screen, functioning like an app.

When a user says “initialize Bys Personal Dashboard Generator,” “initialize bys‑personal‑dashboard,” “I want to make my own personal dashboard,” “I want the kind of personal dashboard I saw on Douyin,” or “turn my daily schedule into a mobile page,” the system must trigger. Even if the user just shares a screenshot of someone else’s dashboard and says “I want something like that,” it should still trigger.

If the user already has a dashboard and says “add an XX feature to my dashboard,” “change the dashboard’s color scheme,” or “modify the dashboard,” follow the iteration workflow rather than re‑initializing.

When the user does not use the word “dashboard,” decide based on three characteristics: ① used on a phone, ② opened every day, ③ stores the user’s private data (weight, finances, check‑ins, to‑dos, diary). If all three are true, trigger the process—for example, “I want to consolidate my weight, bookkeeping, and to‑dos in one place that I can open on my phone.” That is a dashboard, even if the user doesn’t know the term. If any of the three is missing, do not trigger.

A single function also counts— “I keep forgetting to take my medicine, I want to tick it off on my phone each day” is a seed need; don’t skip it just because it sounds like a small feature.

The criterion is who owns the data, not where the data resides: a user’s personal bookkeeping Excel sheet that they want to view daily on their phone is a dashboard; a company’s sales data used for reporting is not.

Not applicable to: disposable tools that don’t store personal data (lottery wheel, calculator, countdown timers displayed on event screens or livestreams), backend admin systems, multi‑user collaboration tools for teams, personal blogs/portfolios/personal websites meant for public display, corporate or business KPI dashboards (built with Excel, etc.), or ordinary HTML coding questions unrelated to a personal dashboard.
