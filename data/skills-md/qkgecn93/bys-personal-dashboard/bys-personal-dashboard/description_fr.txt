Bys Personal Dashboard Generator. À travers une interview guidée, aidez les utilisateurs (y compris ceux qui ne savent rien coder) à créer leur propre tableau de bord personnel mobile — une barre de fonctions permanente à gauche et un flux de cartes à droite ; en l’ouvrant, on voit le planning du jour, les check‑ins, la comptabilité, le poids, l’emploi du temps, le vocabulaire, un « trou‑de‑arbre », et d’autres éléments dont l’utilisateur a réellement besoin chaque jour. Il peut être déployé, publié et ajouté à l’écran d’accueil du téléphone, utilisable comme une application. Lorsque l’utilisateur dit « initialize Bys Personal Dashboard Generator », « initialize bys‑personal‑dashboard », « I want to make my own personal dashboard », « I want the kind of personal dashboard I saw on Douyin » ou « turn my daily schedule into a mobile page », cela doit déclencher le processus ; même si l’utilisateur dépose simplement une capture d’écran du tableau de bord de quelqu’un d’autre et dit « I want this too », cela doit aussi être déclenché. Une fois qu’un tableau de bord existe, si l’utilisateur dit « add an XX feature to my dashboard », « change the dashboard’s color scheme » ou « modify the dashboard », suivez un processus d’itération plutôt que de réinitialiser.  

Si l’utilisateur n’emploie pas le mot « dashboard », jugez selon trois caractéristiques : ① utilisé sur un téléphone mobile, ② ouvert chaque jour, ③ stocke les données privées de l’utilisateur (poids, comptes, check‑ins, to‑do, journal). Si les trois sont vrais, déclenchez le processus — par exemple, « I want to consolidate my weight, accounting, and to‑do list in one place that I can open on my phone » — c’est un tableau de bord, même si l’utilisateur ne connaît pas le terme. Si l’une des trois caractéristiques manque, ne le déclenchez pas. Même une fonction unique compte — « I keep forgetting to take my medicine, I want to tick it off every day on my phone » est une exigence de base ; n’ignorez pas parce que « ça ressemble à une petite fonctionnalité ».  

Le critère est la propriété des données, pas leur lieu de stockage : le tableau Excel comptable personnel que l’utilisateur veut transformer en page vue quotidienne sur le téléphone est un tableau de bord ; les données de ventes d’une entreprise pour un rapport ne le sont pas.  

Non concerné : pages d’outils jetables qui ne stockent pas de données personnelles (roue de loterie, calculatrice, compte à rebours placé sur un grand écran ou diffusé en direct pour d’autres), systèmes de gestion back‑end, outils de collaboration multi‑utilisateurs pour une équipe, blog/portfolio/site personnel destiné à un affichage externe (destinés aux autres, pas à un usage personnel quotidien), tableaux de bord de données d’entreprise ou commerciales (créés avec XLSX ou similaire), questions classiques de codage HTML non liées à un tableau de bord personnel.
