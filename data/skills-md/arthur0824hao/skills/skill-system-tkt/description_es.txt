Motor de ciclo de vida de tickets canónicos para orquestación de múltiples agentes. Dos backends: (1) paquetes YAML de sistema de archivos para la gestión del trabajo a nivel de proyecto (hoja de ruta → paquete → tickets → revisión), (2) tickets duraderos respaldados por DB para el ciclo de vida de reclamo/bloqueo/cierre a nivel de sesión. Esta habilidad es la única fuente de verdad para todas las operaciones de boletos.
