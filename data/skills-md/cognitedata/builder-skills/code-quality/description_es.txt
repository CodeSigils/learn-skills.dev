DEBE usarse siempre que se revise una aplicación Flows en busca de problemas de calidad del código, mantenibilidad o código limpio: antes de una revisión de relaciones públicas, después de completar una función o cuando el usuario solicita una revisión del código. NO omita los pasos para quitar pelusa. Desencadenantes: calidad del código, revisión del código, código limpio, refactorización, mantenibilidad, deuda técnica, cualquier tipo, denominación, código inactivo, duplicación, DRY, responsabilidad única, tamaño del componente, pelusa, linting, TypeScript estricto, inyección de dependencia, estructura de archivos.
