Exécute le rituel de migration de schéma Drift/SQLite en avant uniquement — l'opération déterministe la plus dangereuse dans une application hors ligne : une mauvaise migration détruit silencieusement les lignes sur l'appareil qui n'existent nulle part ailleurs. Applique la séquence ordonnée exacte : prendre un instantané du fichier de pré-migration avant l'ouverture de la base de données, augmenter schemaVersion d'exactement un, écrire une étape avant étape par étape avec ajout uniquement (ne jamais modifier une étape expédiée, ne jamais écrire une migration vers le bas), valider l'instantané du schéma drift_dev make-migrations, régénérer, puis le prouver avec des tests couvrant chaque chemin de → à (y compris les sauts multi-versions), un test de contenu write-at-v(n)/read-at-v(n+1), PRAGMA Integrity_check + Foreign_key_check et un lancement forcé à mi-migration qui restaure l'instantané. Flux de travail manuel à effets secondaires. À utiliser lors de l'ajout ou de la modification d'une table, d'une colonne, d'un index ou d'un CHECK Drift ; supplanter la version de schéma ; édition onUpgrade/stepByStep ; ou rédiger des tests de migration.
