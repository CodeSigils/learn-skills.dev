运行只进的 Drift/SQLite 模式迁移仪式——离线优先应用程序中最危险的确定性操作：错误的迁移会默默地破坏设备上不存在于其他地方的行。强制执行精确的排序顺序：在打开数据库之前拍摄预迁移文件快照，将 schemaVersion 精确提高 1，编写仅追加的逐步前进步骤（从不编辑已发布的步骤，从不编写向下迁移），提交drift_dev make-migrations 架构快照，重新生成，然后通过覆盖每个 from→to 路径（包括多版本跳转）的测试来证明它，write-at-v(n)/read-at-v(n+1) 内容测试、PRAGMAintegrity_check +foreign_key_check，以及恢复快照的强制迁移中期抛出。手动的、有副作用的工作流程。添加或更改 Drift 表、列、索引或 CHECK 时使用；碰撞 schemaVersion；编辑 onUpgrade/stepByStep；或编写迁移测试。
