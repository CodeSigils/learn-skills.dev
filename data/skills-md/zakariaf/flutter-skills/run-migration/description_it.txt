Esegue il rituale di migrazione dello schema Drift/SQLite forward-only: l'operazione deterministica più pericolosa in un'app offline-first: una migrazione errata distrugge silenziosamente le righe sul dispositivo che non esistono altrove. Applica l'esatta sequenza ordinata: acquisisci uno snapshot del file pre-migrazione prima che il database venga aperto, aumenta schemaVersion esattamente di uno, scrivi un passo avanti stepByStep di sola aggiunta (non modificare mai un passaggio inviato, non scrivere mai una migrazione verso il basso), esegui il commit dello snapshot dello schema make-migrations drift_dev, rigenera, quindi dimostralo con test che coprono ogni percorso da→a (inclusi i salti multi-versione), un contenuto write-at-v(n)/read-at-v(n+1) test, PRAGMA Integrity_check + foreign_key_check e un lancio forzato a metà migrazione che ripristina lo snapshot. Flusso di lavoro manuale con effetti collaterali. Da utilizzare quando si aggiunge o si modifica una tabella, una colonna, un indice o un CHECK Drift; schema di bumpingVersione; modifica suAggiornamento/passo passo; o scrivere test di migrazione.
