Führt das Nur-Vorwärts-Drift/SQLite-Schemamigrationsritual aus – den gefährlichsten deterministischen Vorgang in einer Offline-First-App: Eine fehlerhafte Migration zerstört stillschweigend Zeilen auf dem Gerät, die nirgendwo anders vorhanden sind. Erzwingt die genaue geordnete Reihenfolge: Erstellen Sie einen Datei-Snapshot vor der Migration, bevor die Datenbank geöffnet wird, erhöhen Sie schemaVersion um genau eins, schreiben Sie einen nur anhängenden StepByStep-Vorwärtsschritt (bearbeiten Sie niemals einen ausgelieferten Schritt, schreiben Sie niemals eine Down-Migration), schreiben Sie den drift_dev Make-Migrations-Schema-Snapshot fest, generieren Sie ihn neu und beweisen Sie ihn dann mit Tests, die jeden Von→Bis-Pfad abdecken (einschließlich Sprünge mit mehreren Versionen), einen Inhalt, der bei V(n) schreibt/bei V(n+1) liest Test, PRAGMA Integrity_Check + Foreign_Key_Check und ein erzwungener Mid-Migration-Wurf, der den Snapshot wiederherstellt. Manueller, nebensächlicher Arbeitsablauf. Wird zum Hinzufügen oder Ändern einer Drift-Tabelle, -Spalte, eines Index oder eines CHECK verwendet. stoßende schemaVersion; Bearbeiten von onUpgrade/stepByStep; oder Migrationstests schreiben.
