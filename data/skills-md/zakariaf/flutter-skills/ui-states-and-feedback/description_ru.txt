Обеспечивает несчастливые пути, которые каждый экран должен пользователю — загрузка/пустота/ошибка/контент разрешаются в ОДНОМ переключении через AsyncValue или запечатанное состояние просмотра, а не тройку isLoading+error+data bool; отложенный скелет в форме результата вместо мигающего счетчика; обновление, которое сохраняет устаревший контент на экране; «пока ничего» отличается от «данному фильтру ничего не соответствует», каждый со своим действием; текст ошибки из введенного кода ошибки (никогда не e.toString()) плюс повторная попытка, которая делает поставщика недействительным; встроенная поверхностная лестница, закусочная, баннер, диалог с модальным окном, зарабатываемым только решением, которое должно быть решено сейчас; мягкое удаление + Отмена после подтверждения; Отмена значения showDialog обрабатывается как отдельный результат; ScaffoldMessenger захватывается перед ожиданием; и объявления об изменениях, доступных только для глаз. Используйте при написании пользовательского интерфейса загрузки, пустого, ошибочного или автономного пользовательского интерфейса, вызова AsyncValue.when, showDialog, showModalBottomSheet, showSnackBar или showMaterialBanner, а также при добавлении подтверждения, отмены или повторной попытки.
