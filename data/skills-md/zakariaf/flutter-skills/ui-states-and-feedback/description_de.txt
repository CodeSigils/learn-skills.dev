Erzwingt die unzufriedenen Pfade, die jeder Bildschirm dem Benutzer schuldet – Laden/Leer/Fehler/Inhalt wird in EINEM Wechsel über einen AsyncValue- oder versiegelten Ansichtszustand aufgelöst, niemals ein isLoading+error+data bool-Triple; ein verzögertes Skelett in Form des Ergebnisses anstelle eines blinkenden Spinners; eine Aktualisierung, die veraltete Inhalte auf dem Bildschirm behält; „noch nichts“ unterscheidet sich von „nichts entspricht diesem Filter“, jeweils mit eigener Aktion; Fehlertext aus einem eingegebenen Fehlercode (niemals e.toString()) plus einem Wiederholungsversuch, der den Anbieter ungültig macht; die Oberflächenleiter Inline, Snackbar, Banner, Dialog, mit einem Modal, das nur durch eine Entscheidung verdient wird, die jetzt gelöst werden muss; Soft-Delete + Rückgängig machen über eine Bestätigung; Die Nullentlassung von showDialog wird als eigenes Ergebnis behandelt. ScaffoldMessenger wurde vor einem Warten gefangen genommen; und Ankündigungen für sichtbare Änderungen. Verwenden Sie diese Option, wenn Sie eine Lade-, Leer-, Fehler- oder Offline-Benutzeroberfläche schreiben, AsyncValue.when, showDialog, showModalBottomSheet, showSnackBar oder showMaterialBanner aufrufen oder eine Bestätigung, ein Rückgängigmachen oder einen erneuten Versuch hinzufügen.
