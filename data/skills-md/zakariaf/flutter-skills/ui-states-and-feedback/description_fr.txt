Applique les chemins non satisfaits que chaque écran doit à l'utilisateur - chargement/vide/erreur/contenu résolu en UN seul commutateur sur un état d'affichage AsyncValue ou scellé, jamais un triple booléen isLoading+error+data ; un squelette retardé en forme de résultat au lieu d'une roulette qui clignote ; une actualisation qui maintient le contenu obsolète à l'écran ; « rien pour l'instant » se distingue de « rien ne correspond à ce filtre », chacun avec sa propre action ; texte d'erreur provenant d'un code d'échec saisi (jamais e.toString()) plus une nouvelle tentative qui invalide le fournisseur ; l'échelle de surface en ligne, le snack-bar, la bannière, le dialogue, avec un modal gagné uniquement par une décision qui doit être résolue maintenant ; soft-delete + Annuler sur une confirmation ; Le licenciement nul de showDialog est traité comme son propre résultat ; ScaffoldMessenger capturé avant une attente ; et des annonces pour les changements visuels uniquement. À utiliser lors de l'écriture d'une interface utilisateur de chargement, vide, d'erreur ou hors ligne, en appelant AsyncValue.when, showDialog, showModalBottomSheet, showSnackBar ou showMaterialBanner, ou en ajoutant une confirmation, une annulation ou une nouvelle tentative.
