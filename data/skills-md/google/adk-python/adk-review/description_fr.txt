Examine les modifications non validées dans un arbre de travail adk-python et signale l'exactitude, la conception, la stabilité de l'API publique, les tests, les échantillons et les lacunes dans la documentation sous la forme d'un rapport de résultats hiérarchisé, en les corrigeant uniquement lorsque cela est demandé. À utiliser lorsque l'utilisateur demande à examiner les modifications locales, souhaite une auto-évaluation avant d'ouvrir une pull request, demande si une modification interrompt l'API publique ou nécessite des tests, des échantillons ou des documents, ou demande ce qui ne va pas avec la différence actuelle. Requis pour les modifications des API publiques, de l'architecture de base (Runner, Workflow, BaseNode), des nouvelles fonctionnalités et des refactors majeurs. Ne pas utiliser pour un seul style (utilisez le style adk), pour diagnostiquer un test défaillant ou un agent qui se comporte mal au moment de l'exécution (utilisez adk-debug), ou pour rédiger un message de validation ou une description de PR (utilisez adk-git).
