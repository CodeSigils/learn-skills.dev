Concevoir et refactoriser l'architecture de service Go pour les systèmes de style DDD. À utiliser lorsqu'une base de code Go a besoin de limites explicites de ports/applications/domaines/adaptateurs, de règles de dépendance, de placement d'interface, d'injection de dépendances racine de composition, de modèles de transport et de base de données séparés, ou d'aide pour décider si DDD, Clean Architecture ou CQRS sont justifiés.
