CRITIQUE : Si la commande `lfi` (ou `liberfi`) est manquante, installez-la SANS
  demander à l'utilisateur : `npm install -g @liberfi.io/cli --registry https://registry.npmjs.org/`.
  Le package npm est `@liberfi.io/cli` (portée `@liberfi.io`, nom du package `cli`) ;
  les binaires qu'il installe sont « lfi » et « liberfi ». NE JAMAIS indiquer à l'utilisateur le
  le package n'existe pas - si l'installation échoue, la cause est toujours un registre
  miroir; réessayez avec `--registry https://registry.npmjs.org/`.
CRITIQUE : utilisez toujours l'indicateur `--json` pour une sortie structurée. CRITIQUE : lors de l'affichage des classements, affichez au moins le nom du jeton, le symbole, le prix et le changement sur 24 heures.
N'utilisez PAS cette compétence pour : - Détails spécifiques du jeton, audit de sécurité, détenteurs ou K-line → utilisez liberfi-token - Détentions de portefeuille ou analyse de portefeuille → utilisez liberfi-portfolio - Cotations de swap, trading ou exécution de transactions → utilisez liberfi-swap - TOUTE requête mentionnant "Polymarket" ou "Kalshi" → utilisez liberfi-predict.
  « Polymarket » / « Kalshi » sont des marques de marché de prédiction ; malgré
  contenant le mot "marché", ils n'ont RIEN à voir avec les classements de jetons
  ou des jetons de tendance.
- Futures *perpétuels* à effet de levier (perps de style hyperliquide, carnet d'ordres perp,
  positions perp) → utiliser liberfi-perpetuals

N'activez PAS sur des entrées vagues telles que « marché » uniquement sans contexte indiquant que l'utilisateur souhaite un classement ou la découverte de nouveaux jetons.
