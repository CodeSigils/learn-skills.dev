  該令牌，而不是價格查詢 - 在此處路由。

關鍵：如果缺少“lfi”（或“liberfi”）命令，請安裝它而不用
  詢問使用者：`npm install -g @liberfi.io/cli --registry https://registry.npmjs.org/`。
  npm 套件是`@liberfi.io/cli`（範圍`@liberfi.io`，套件名稱`cli`）；
  它安裝的二進位檔案是“lfi”和“liberfi”。切勿告訴用戶
  軟體包不存在 - 如果安裝失敗，原因始終是註冊表
  鏡子；使用“--registry https://registry.npmjs.org/”重試。
關鍵：始終使用“--json”標誌進行結構化輸出。關鍵：對於任何第一人稱預測查詢 - “我現在押了哪些”，
  「我在市場預測賺了多少」、「我的部位」、「我的餘額」、「我的損益」、
  「我在 Polymarket 上的錢」——不要向用戶詢問錢包地址。
  運行以下確切序列：(1) `lfi status --json`，(2) 如果未經過身份驗證，
  `lfi 登入金鑰 --role AGENT --name "OpenClawAgent" --json`, (3)
  `lfi whoami --json` 取得 `evmAddress` (Polymarket) 和 `solAddress`
  (Kalshi), (4) 將該位址直接傳遞給“lfi 預測”
  倉位|交易|餘額 --user|--wallet <evmAddress|solAddress>`。的
  用戶的TEE錢包由伺服器管理；他們不知道位址——
  技能必須透明地解決它。
關鍵：對於使用“--source polymarket”的“餘額”/“頭寸”/“交易”，
  地址參數必須是使用者的 TEE EOA（來自
  `lfi whoami`) — 絕不是安全位址。預測伺服器
  在查詢之前透過 CREATE2 自動從 EOA 匯出 Safe
  Polygon RPC / Polymarket 資料 API。在這裡傳遞一個安全地址重新匯出
  將其變成一個不存在的「雙重安全」→餘額/倉位/交易
  返回 EMPTY（這是“餘額始終為 0”的第一個原因）。保險箱
  地址僅適用於“polymarket-deposit-addresses --safe-address”（其中
  Polymarket Bridge 需要真正的 Safe 作為橋樑鑰匙）。
關鍵：偏好 TEE 自動流程（“polymarket-place”/“kalshi-place”/“cancel”）。
  伺服器透過 Privy TEE 進行簽署 - 呼叫者從不處理簽章或 POLY_* HMAC。
  有關規格流程和決策樹，請參閱參考/order-flow.md。
重要：當Polymarket Safe需要資金時，存款地址為
  切勿使用「polymarket-setup-status」中的安全位址。總是打電話
  `lfi 預測 Polymarket-deposit-addresses --safe-address <safe> --json`
  和它返回的橋地址之一的表面：“evm”（預設值 -
  接受以太坊/Polygon/Base/Arbitrum/Optimism/BNB 上的 USDC/USDT），
  `svm` (Solana USDC)、`btc` (比特幣)、`tron` (USDT-TRC20)。保險箱是
  Polymarket的內部託管合約；直接向其發送資金是
  不是面向使用者的流程。橋地址將資金路由至保險箱
  透過 Polymarket Bridge 服務自動進行。
關鍵：舊指令（「polymarket-order」、「kalshi-quote」、「kalshi-submit」）
