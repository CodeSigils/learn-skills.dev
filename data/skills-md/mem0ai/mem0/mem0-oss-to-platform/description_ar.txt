قم بتخطيط ثم تنفيذ ترحيل مشروع من mem0 مفتوح المصدر / SDK مستضاف ذاتيًا (فئة "الذاكرة" المحلية) إلى منصة mem0 / SDK المستضافة / المُدارة (فئة "MemoryClient"). استخدم هذا عندما يريد أحد المطورين نقل استخدام mem0 الخاص به أو تبديله أو ترحيله من OSS/المستضاف ذاتيًا إلى واجهة برمجة التطبيقات المستضافة - على سبيل المثال. "ترحيل إعداد mem0 الخاص بي إلى النظام الأساسي"، أو "التبديل من mem0 المستضاف ذاتيًا إلى MemoryClient"، أو "استخدم مفتاح mem0 API الخاص بي بدلاً من Qdrant المحلي"، أو "انقل mem0 إلى الخدمة السحابية/المستضافة/المدارة"، أو "استبدل مخزن ناقل mem0 المحلي + تكوين التضمين بالنظام الأساسي". ينطبق على Python (`من mem0 استيراد الذاكرة` → `من mem0 استيراد MemoryClient`) وTypeScript/JavaScript (`استيراد { Memory } من "mem0ai/oss"` → `استيراد MemoryClient من "mem0ai"`). يتم التشغيل حتى عندما لا يقول المستخدم كلمة "ترحيل" ولكنه يريد بوضوح أن يتم تشغيل تكامل mem0 الحالي الخاص به مع النظام الأساسي المستضاف. فهو يقوم أولاً بإعداد خطة ترحيل قابلة للمراجعة، ثم ينفذها بعد موافقة المطور. تم تحديد نطاقه بشكل صارم لتكامل mem0 - فهو لا يعيد بناء أو إعادة هيكلة أو "تحسين" أي تعليمات برمجية غير ذات صلة.
