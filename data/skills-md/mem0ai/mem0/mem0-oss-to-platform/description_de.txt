Planen Sie eine Migration eines Projekts vom mem0-Open-Source-/selbstgehosteten SDK (die lokale „Memory“-Klasse) zum mem0-Plattform-/gehosteten/verwalteten SDK (die „MemoryClient“-Klasse) und führen Sie sie dann aus. Verwenden Sie dies immer dann, wenn ein Entwickler seine Mem0-Nutzung von OSS/selbst gehostet auf die gehostete API verschieben, umstellen oder migrieren möchte – z. B. „Migrieren Sie mein Mem0-Setup auf die Plattform“, „Wechseln Sie von selbst gehostetem Mem0 zu MemoryClient“, „verwenden Sie meinen Mem0-API-Schlüssel anstelle eines lokalen Qdrant“, „verschieben Sie Mem0 in die Cloud/den gehosteten/verwalteten Dienst“ oder „ersetzen Sie meine lokale Mem0-Vektorspeicher- + Embedder-Konfiguration durch die Plattform“. Gilt für Python („from mem0 import Memory“ → „from mem0 import MemoryClient“) und TypeScript/JavaScript („import { Memory } from „mem0ai/oss““ → „import MemoryClient from „mem0ai““). Wird auch dann ausgelöst, wenn der Benutzer das Wort „migrieren“ nicht sagt, aber eindeutig möchte, dass seine vorhandene mem0-Integration auf der gehosteten Plattform ausgeführt wird. Es erstellt zunächst einen überprüfbaren Migrationsplan und führt ihn dann aus, nachdem der Entwickler die Genehmigung erteilt hat. Streng auf die mem0-Integration beschränkt – es wird kein nicht verwandter Code umgestaltet, umstrukturiert oder „verbessert“.
