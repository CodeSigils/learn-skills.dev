Запланируйте, а затем выполните миграцию проекта из SDK с открытым исходным кодом / локального размещения mem0 (локальный класс «Memory») на платформу mem0 / размещенный / управляемый SDK (класс «MemoryClient»). Используйте это всякий раз, когда разработчик хочет переместить, переключить или перенести использование mem0 с OSS/самостоятельного размещения на размещенный API — например. «перенести мою настройку mem0 на платформу», «переключиться с локального mem0 на MemoryClient», «использовать мой API-ключ mem0 вместо локального Qdrant», «переместить mem0 в облачную/размещенную/управляемую службу» или «заменить локальное векторное хранилище mem0 + конфигурацию встраивания на платформу». Применяется к Python (`from mem0 import Memory` → `from mem0 import MemoryClient`) и TypeScript/JavaScript (`import { Memory } из "mem0ai/oss"` → `import MemoryClient из "mem0ai"`). Срабатывает, даже если пользователь не произносит слово «мигрировать», но явно хочет, чтобы существующая интеграция mem0 работала на размещенной платформе. Сначала он составляет проверяемый план миграции, а затем выполняет его после одобрения разработчиком. Строго ограничен интеграцией с mem0 — он не выполняет рефакторинг, реструктуризацию или «улучшение» какого-либо несвязанного кода.
