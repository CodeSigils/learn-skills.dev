Planifiez puis exécutez une migration d'un projet depuis le SDK mem0 open source/auto-hébergé (la classe `Memory` locale) vers le SDK mem0 Platform/hébergé/géré (la classe `MemoryClient`). Utilisez-le chaque fois qu'un développeur souhaite déplacer, changer ou migrer son utilisation de mem0 hors OSS/auto-hébergé vers l'API hébergée - par exemple. "migrer ma configuration mem0 vers la plate-forme", "passer de mem0 auto-hébergé à MemoryClient", "utiliser ma clé API mem0 au lieu d'un Qdrant local", "déplacer mem0 vers le service cloud/hébergé/géré", ou "remplacer mon magasin de vecteurs mem0 local + configuration d'intégration par la plate-forme". S'applique à Python (`from mem0 import Memory` → `from mem0 import MemoryClient`) et TypeScript/JavaScript (`import { Memory } from "mem0ai/oss"` → `import MemoryClient from "mem0ai"`). Déclenchez-le même lorsque l'utilisateur ne prononce pas le mot « migrer », mais souhaite clairement que son intégration mem0 existante s'exécute sur la plate-forme hébergée. Il produit d’abord un plan de migration révisable, puis l’exécute après approbation du développeur. Strictement limité à l'intégration mem0 - il ne refactorise, ne restructure ni "améliore" aucun code sans rapport.
