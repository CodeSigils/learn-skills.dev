Дополните проект Wren бизнес-контекстом, который не может нести схема БД — значения перечисляемых значений, единицы измерения (доллары США против центов, мс против секунд), семантика NULL, магические датчики (-1 = неизвестно), фильтры по умолчанию с мягким удалением, бизнес-синонимы, соглашения о временной разбивке / TZ, межсистемные идентификаторы, валютные правила, предпочтения канонических таблиц и именованные метрики агрегирования (ARR, отток, DAU, WAU, NRR), предложенные как кубики. Работает в одном из двух режимов, выбранных в начале сеанса: «гриль» (по одному вопросу за раз, по инициативе пользователя) или «автопилот» (агент делает выводы и применяет, обостряет только конфликты и важные дополнения, такие как новые кубы/представления/отношения). Считывает все в <project>/raw/ (PDF-файлы, глоссарии, справочники, код, словари данных) и, при необходимости, выбирает столбцы с низкой мощностью из активной базы данных (режим гриля), сравнивает с текущими парами MDL/cubes/instructions.md/queries.yml/memory, затем заполняет пробелы с помощью каталога пробелов из десяти категорий и потока предложений куба. Подтвержденные результаты записываются обратно в правый приемник. Используйте, когда: пользователь говорит «обогатить контекст», «дополнить мой проект», «поджарить меня по этому проекту», «автозаполнить мой контекст», «агент не понимает наши документы/значения перечисления/единицы/нулевые значения», «бизнес-контекст отсутствует», «что означает status=A», «эта сумма в долларах США или центах», «мы продолжаем получать неправильные агрегаты», «добавьте кубы для ARR / DAU / оттока», «у нас есть справочник/глоссарий/словарь данных, который должен знать агент'; или после создания MDL и обнаружения, что агенту не хватает бизнес-семантики.
