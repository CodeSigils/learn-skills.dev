À utiliser lorsque le travail de l'API Java XML-RPC nécessite des décisions contractuelles pour la signalisation des erreurs et l'interopérabilité, notamment la définition d'échecs basés sur XmlRpcException, le remplacement des retours vides par des résultats d'opération explicites, la révision des gestionnaires pour les anti-modèles de code de retour et la migration des DTO de Serialisable vers JAXB.
