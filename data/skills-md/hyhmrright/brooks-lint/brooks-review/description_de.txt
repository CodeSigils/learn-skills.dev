PR-Codeüberprüfung, die Fäulnisrisiken, Designgerüche und Wartbarkeitsprobleme mit Beton aufdeckt. Symptom → Quelle → Konsequenz → Abhilfe-Ergebnisse, basierend auf zwölf klassischen Ingenieurbüchern. Wird ausgelöst, wenn: Der Benutzer darum bittet, den Code zu überprüfen, eine PR zu überprüfen, einen Unterschied zu teilen oder Code einzufügen und fragt: „Sieht das richtig aus?“ / „Gibt es hier Probleme?“ / „Bereit zum Zusammenführen?“ oder bittet um Feedback zu einer Funktion, Klasse oder Datei. Wird auch ausgelöst, wenn der Benutzer Folgendes erwähnt: Code-Smells / Refactoring / saubere Architektur / DDD / domänengesteuertes Design / SOLID-Prinzipien / Hyrums Gesetz / tiefe Module / taktische Programmierung / konzeptionelle Integrität / Brooks-Gesetz / Mythischer Mann-Monat / zweiter Systemeffekt. NICHT auslösen bei: Fragen zum Schreiben von Code von Grund auf, Fragen zur Sprachsyntax oder Fragen zu Frameworks/Tools, bei denen kein vorhandener Code geteilt wird.
