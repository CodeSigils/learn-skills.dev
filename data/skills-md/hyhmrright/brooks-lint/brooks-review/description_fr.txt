Examen du code PR qui fait apparaître les risques de pourriture, les odeurs de conception et les problèmes de maintenabilité du béton Symptôme → Source → Conséquence → Remède, s'appuyant sur douze livres d'ingénierie classiques. Se déclenche lorsque : l'utilisateur demande à réviser le code, vérifie un PR, partage une différence ou colle le code en demandant "est-ce que cela semble correct ?" / "des problèmes ici ?" / "Prêt à fusionner ?", ou demande des commentaires sur une fonction, une classe ou un fichier. Se déclenche également lorsque l'utilisateur mentionne : odeurs de code / refactoring / architecture propre / DDD / conception axée sur le domaine / principes SOLID / loi d'Hyrum / modules profonds / programmation tactique / intégrité conceptuelle / loi de Brooks / mois-homme mythique / deuxième effet système. Ne déclenchez PAS pour : des questions sur la façon d'écrire du code à partir de zéro, des questions sur la syntaxe du langage ou des questions sur le cadre/outil pour lesquelles aucun code existant n'est partagé.
