Revisión del código PR que resalta los riesgos de deterioro, los olores del diseño y los problemas de mantenimiento con los hallazgos de Síntomas → Fuentes → Consecuencias → Remedios concretos, basándose en doce libros de ingeniería clásicos. Se activa cuando: el usuario solicita revisar el código, verifica un PR, comparte una diferencia o pega el código y pregunta "¿se ve bien?" / "¿algún problema aquí?" / "¿Listo para fusionar?", o solicita comentarios sobre una función, clase o archivo. También se activa cuando el usuario menciona: olores de código / refactorización / arquitectura limpia / DDD / diseño impulsado por dominio / principios SOLID / Ley de Hyrum / módulos profundos / programación táctica / integridad conceptual / Ley de Brooks / Mes del Hombre Mítico / efecto del segundo sistema. NO active esta opción para: preguntas sobre cómo escribir código desde cero, preguntas sobre la sintaxis del lenguaje o preguntas sobre marcos/herramientas en las que no se comparte ningún código existente.
