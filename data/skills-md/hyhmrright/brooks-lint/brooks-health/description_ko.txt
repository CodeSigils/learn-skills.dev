PR 품질, 아키텍처, 기술 부채, 테스트 품질 등 4가지 품질 차원 모두에서 단일 패스로 프로젝트의 점수를 매기는 결합된 코드베이스 상태 대시보드로, 12권의 고전 엔지니어링 서적을 활용합니다. 트리거되는 경우: 사용자가 전반적인 품질 평가를 원할 때, "이 코드베이스가 얼마나 건강한가요?", "모든 검사를 실행하세요", "큰 그림의 품질 보고서를 제공하세요", "릴리스 전에 상태 점수가 필요합니다", "우리 코드의 전반적인 상태는 어떻습니까?"라고 묻거나, 품질 개요를 통해 새 팀을 온보드하기를 원합니다. 서버 상태 확인, HTTP 상태 엔드포인트, Kubernetes 활성/준비 프로브, 데이터베이스 상태 또는 애플리케이션 가동 시간에 대해 트리거하지 마십시오. 또한 사용자가 구체적으로 하나의 차원만 요청하는 경우에도 트리거하지 마십시오. 대신 해당하는 집중 기술을 사용하십시오(brooks-review / brooks-audit / brooks-debt / brooks-test).
