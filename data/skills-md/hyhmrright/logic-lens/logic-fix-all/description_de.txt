Autonome, Repository-weite Audit-and-Fix-Pipeline: Zustand → Überprüfung → Lokalisieren/Erklären → Korrigieren → Diff-Überprüfung → Iterieren, bis es sauber ist. Beginnt mit einer obligatorischen Einwilligungsaufforderung (Token-intensiv); nach Zustimmung läuft freihändig. Wird ausgelöst, wenn der Benutzer möchte, dass ALLE Logikprobleme gefunden und behoben werden – „Alles beheben“, „Alle Logikprobleme beheben“, „Alle Logikprobleme in diesem Code beheben“, „Alle Logikprobleme bereinigen“, „Das gesamte Repo prüfen und beheben“, „Alle Fehler automatisch beheben“ oder wenn er wegen wiederkehrender Fehler frustriert ist und eine einmalige Lösung wünscht. SCOPE-REGEL: Standardmäßig Repo-weit; löst auch ein eingefügtes Code-Snippet aus, wenn der Benutzer „Alle reparieren“ sagt – erstellt den vollständigen Fix-Bericht (Fix-Protokoll, vor/nach Logic Score). Reine Analyseanfragen verwenden „Logic-Health“ oder „Logic-Review“. Bei einem einzelnen Fehler wird die logische Lokalisierung verwendet. Zwei Versionen verwenden Logic-Diff. Eine Pfaderklärung verwendet Logic-Explain. NICHT auslösen für: Nur Analyse („Zeige mir die Fehler“), Stil-/Lint-/Formatprobleme oder die Behebung eines einzelnen benannten Ergebnisses.
