Pipeline d'audit et de correction autonome à l'échelle du référentiel : santé → examen → localiser/expliquer → réparer → vérifier la différence → itérer jusqu'à ce qu'il soit propre. Commence par une invite de consentement obligatoire (à forte intensité de jetons) ; après consentement, fonctionne en mains libres. Déclenchez lorsque l'utilisateur souhaite que TOUS les problèmes de logique soient trouvés et corrigés : "tout réparer", "réparer tous les problèmes de logique", "réparer tous les problèmes de logique dans ce code", "nettoyer tous les problèmes de logique", "auditer et corriger l'ensemble du dépôt", "réparer tous les bogues automatiquement" ou frustration face aux bogues récurrents souhaitant une passe unique. RÈGLE DE PORTÉE : à l'échelle du dépôt par défaut ; déclenche également un extrait de code collé lorsque l'utilisateur dit « tout réparer » – produit le rapport de correctif complet (journal des correctifs, score logique avant/après). Les requêtes d’analyse uniquement utilisent Logic-Health ou Logic-Review. Une défaillance unique utilise la localisation logique. Deux versions utilisent la logique-diff. Une explication de chemin utilise l'explication logique. Ne déclenchez PAS pour : une analyse uniquement ("montrez-moi les bogues"), des problèmes de style/peluche/format ou la correction d'un seul résultat nommé.
