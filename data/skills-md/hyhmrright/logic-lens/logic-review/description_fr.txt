Recherchez les bogues logiques dans un seul fichier ou une seule fonction via le traçage d'exécution semi-formel (Prémisses → Trace → Divergence → Déclencheur → Remède). Se déclenche lorsqu'un utilisateur partage du code et soupçonne que quelque chose ne va pas sans nommer un échec concret - des expressions telles que "revoir ceci", "est-ce que cela semble correct", "vérifier cette fonction", "auditer ce code", "les tests réussissent mais la production échoue". RÈGLE DUR DE PORTÉE : un fichier ou une fonction uniquement. Pour un répertoire ou un module entier, utilisez logic-health ; pour un échec confirmé (trace de pile, test échoué, valeur incorrecte spécifique), utilisez la localisation logique ; pour deux versions, utilisez logic-diff ; pour une réparation autonome à l'échelle du dépôt, utilisez logic-fix-all. Ne déclenchez PAS pour : des questions de style/formatage, d'analyse de sécurité, de performances, de génération de tests, d'architecture ou de conception.
