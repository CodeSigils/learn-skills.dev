Comparez deux versions de code pour l'équivalence sémantique via le traçage semi-formel des deux versions côte à côte. Déclenchez lorsque l'utilisateur partage une implémentation de refactor, de réécriture, de migration ou A/B et souhaite confirmer que le comportement est inchangé : "ai-je cassé quelque chose", "est-ce équivalent", "sont-ils équivalents", "sémantiquement équivalents", "ces deux implémentations sont-elles sémantiquement équivalentes", "vérifier mon refactor", "même comportement après le changement ?", "ma réécriture produit-elle le même résultat", "passé de X à Y - mêmes résultats ?" RÈGLE DUR DE PORTÉE : nécessite deux versions de code (A et B). Une version unique pour la recherche de bogues utilise la révision logique ; une version + un test échoué utilise la localisation logique ; expliquer ce que fait un morceau de code utilise logic-explain ; L'audit de la base de code utilise la santé logique. Ne déclenchez PAS : l'examen d'une version unique, la comparaison des performances, la comparaison de la qualité de la conception ou les questions « quelle est la meilleure rédaction ».
