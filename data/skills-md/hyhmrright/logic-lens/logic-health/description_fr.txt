Balayez un répertoire, un module ou une base de code complète pour vérifier l'exactitude logique et produisez un tableau de bord de santé noté avec des modèles systémiques. Déclenchez lorsque l'utilisateur demande une vue de l'état — « auditer l'ensemble de la base de code », « contrôle de l'état », « aperçu de l'état », « aperçu de l'état de la logique », « audit src/ », « auditer les modules d'authentification et de paiement », « où dois-je concentrer les tests », « examen d'intégration », « aperçu de la logique avant l'expédition », « donnez-moi un aperçu de l'état de ce module ». RÈGLE DE PORTÉE : préférez le multi-fichier ; se déclenche également pour un seul module lorsque l'utilisateur utilise explicitement « vérification de l'état », « aperçu de l'état » ou « état de santé logique » – un échec concret utilise la localisation logique ; deux versions utilisent logic-diff ; expliquer un chemin utilise la logique-expliquer ; "Tout réparer" utilise la logique-réparer tout. Ne déclenchez PAS pour : les audits de style/architecture uniquement, les analyses de sécurité uniquement, les audits de performances uniquement.
