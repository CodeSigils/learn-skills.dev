Localisez la cause première d’un échec CONFIRMÉ via un traçage semi-formel en arrière puis en avant. Déclenchement lorsque l'utilisateur fournit une trace de pile, une assertion défaillante, un message d'erreur ou une observation spécifique de valeur incorrecte : "trouver le bogue", "ce test échoue", "traquer ce crash", "pourquoi ce test échoue-t-il", "KeyError à la ligne 89", "attendu 70, obtenu 100", "NoneType n'a pas d'attribut X", "le panier se vide à l'ouverture du deuxième onglet". RÈGLE DUR DE PORTÉE : nécessite un échec concret (exception, échec d'un test ou sortie incorrecte spécifique). De vagues soupçons sans preuves utilisent l’examen logique ; behavior explanation uses logic-explain; refactor comparison uses logic-diff; L'audit de la base de code utilise la santé logique. Ne déclenchez PAS pour : un vague « qu'est-ce qui ne va pas » sans symptôme concret, questions de style ou problèmes de performances.
