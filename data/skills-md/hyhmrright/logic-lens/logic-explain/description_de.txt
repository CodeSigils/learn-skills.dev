Erklären Sie, was ein bestimmter Codeabschnitt tatsächlich für eine bestimmte Eingabe tut, indem Sie einen schrittweisen Ausführungs-Trace erstellen (interprozedural, mit Namensauflösung und Typübergängen). Wird ausgelöst, wenn der Benutzer über das Verhalten verwirrt ist oder fragt, warum der Code X anstelle von Y erzeugt – „Führen Sie mich hier durch“, „verfolgen Sie X mit der Eingabe Y“, „warum gibt dies X zurück“, „was macht yield-from hier“, „erklären Sie den Ausführungspfad“. SCOPE HARD RULE: eine bestimmte Funktion + ein bestimmtes Eingabeszenario. Wenn der Benutzer Fehler finden möchte, ohne ein Szenario im Kopf zu haben, verwenden Sie Logic-Review. Der Zwei-Versions-Vergleich verwendet Logic-Diff. Konkrete Fehler verwenden Logic-locate; Die codebasisweite Prüfung verwendet Logic-Health. NICHT auslösen für: das Finden von Fehlern ohne eine Verhaltensfrage, Stil- oder Designdiskussion oder Konzepterklärungen, die nicht an einen bestimmten Code gebunden sind.
