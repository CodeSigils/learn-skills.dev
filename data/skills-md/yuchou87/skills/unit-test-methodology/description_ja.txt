完全な範囲をカバーするテスト方法を適用することにより、単体テストを体系的に生成します。ユーザーが「単体テストを書く」、「テストを追加する」、「テスト ケースを生成する」、「テスト カバレッジ」、「これをテストするにはどうすればいいですか」、「テストを書く」、「补充测试」、「帮我写单元测试」、「生成测试用例」、「这个関数怎么测」、と言うとトリガーされます。 「测试被盖率不够」、「写試」、「给这个方法加测试」、「单测」。アドホックなテスト生成とは異なり、このスキルは分析と導出を強制します。パラメータごとに同値クラスを体系的に分割し、範囲指定された入力に境界値を適用し、ペアワイズを使用して 4 つ以上のパラメータの組み合わせを圧縮し、複数条件分岐にデシジョン テーブルを使用します。重要な境界シナリオを見逃すことなく体系的なカバレッジを保証するには、すべてのテスト ケースにソース テクニックの注釈を付ける必要があります。 Go / Python / Java / TypeScript / Rust をサポートします。ユーザーが「テストを書いて」と言うだけでもトリガーされます。
