Definieren Sie einen gesamten Cargo-Arbeitsbereich im Code – Konnektoren, Modelle, Spiele, Tools, Agenten, MCP-Server, Kontext, Kapazitäten, Gebiete, Segmente, Ordner, Dateien, Worker, Apps – und stellen Sie ihn deklarativ mit „cargo-ai cdk“ (Init → Typen → Plan → Bereitstellen) bereit, so wie Sie Cloud-Infrastruktur mit Pulumi oder dem AWS CDK verwalten würden. Verwenden Sie diese Option, wenn der Benutzer Cargo-Ressourcen als Code verwalten möchte: reproduzierbar, versioniert, in Git, aus einer Vorlage oder umgebungsübergreifend. Routen zu Erstellungs-/Bereitstellungs-/Eingabehandbüchern (Stufe 2), Rezepten (Stufe 2.5) und Referenzen. Für einmalige zwingende Vorgänge (Erstellen eines Connectors, Lesen eines Modells, Ausführen eines Workflows) verwenden Sie stattdessen die Fertigkeit „Matching-Fähigkeit“.
