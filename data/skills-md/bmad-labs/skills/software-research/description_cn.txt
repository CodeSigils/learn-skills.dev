当有人要求通过经过验证的多视角镜头研究软件工程问题时使用 - “我们应该使用 X 还是 Y”、“评估库/框架/数据库 Z”、“研究我们是否应该采用……”、“为……编写 ADR”、“对……进行尖峰”或“从 X 迁移到 Y/升级路径”。运行专用于软件的 STORM 风格管道：自动检测五种研究模式之一（库评估、深度研究、架构、峰值、迁移），并行生成该模式的专家视角，映射它们的矛盾，合成 HTML 简报和 Markdown/ADR 记录，然后对抗性地验证针对主要软件源的每项声明（官方文档、RFC、GitHub 版本、OSV/CVE、OpenSSF 记分卡、基准）与版本意识。最适合多种观点和版本正确、经过事实核查的声明很重要的决策；对于快速 API 查找来说太过分了。对于非软件主题，请进行深入研究；对于纯评分决策矩阵，请使用权衡分析。
