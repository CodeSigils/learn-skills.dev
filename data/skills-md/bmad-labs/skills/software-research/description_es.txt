Úselo cuando alguien solicite investigar una pregunta de ingeniería de software a través de una lente verificada y de múltiples perspectivas: "deberíamos usar X vs Y", "evaluar biblioteca/marco/base de datos Z", "investigar si deberíamos adoptar...", "escribir un ADR para...", "aumentar..." o "migrar de X a Y/ruta de actualización". Ejecuta un canal de estilo STORM especializado para software: detecta automáticamente uno de los cinco modos de investigación (evaluación de biblioteca, investigación profunda, arquitectura, pico, migración), genera lentes expertos de ese modo en paralelo, mapea sus contradicciones, sintetiza un informe HTML y un registro Markdown/ADR, luego verifica de manera adversa cada reclamo contra fuentes de software PRINCIPALES (documentos oficiales, RFC, lanzamientos de GitHub, OSV/CVE, OpenSSF Cuadro de mando, puntos de referencia) con reconocimiento de versiones. Lo mejor para decisiones en las que importan múltiples puntos de vista y afirmaciones con versiones correctas y verificadas; exagerado para una búsqueda rápida de API. Para temas que no sean de software, utilice una investigación profunda; para una matriz de decisión puramente puntuada, utilice el análisis de compensación.
