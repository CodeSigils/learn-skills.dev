「X と Y を使用するべきか」、「ライブラリ/フレームワーク/データベース Z を評価する」、「…を採用すべきかどうかを調査する」、「… の ADR を作成する」、「… にスパイクする」、または「X から Y への移行 / アップグレード パス」など、検証済みの複数の観点からソフトウェア エンジニアリングの質問を調査するように依頼された場合に使用します。ソフトウェアに特化した STORM スタイルのパイプラインを実行します。5 つのリサーチ モード (ライブラリ評価、ディープリサーチ、アーキテクチャ、スパイク、移行) の 1 つを自動検出し、そのモードのエキスパート レンズを並行して生成し、それらの矛盾をマッピングし、HTML ブリーフィングとマークダウン/ADR レコードを合成して、プライマリ ソフトウェア ソース (公式ドキュメント、RFC、GitHub リリース、 OSV/CVE、OpenSSF スコアカード、ベンチマークなど）バージョンを認識します。複数の視点と、バージョンを正確にし、事実確認された主張が重要となる意思決定に最適です。素早い API ルックアップには過剰です。ソフトウェア以外のトピックについては、詳細な調査を使用します。純粋なスコア付き決定行列の場合は、トレードオフ分析を使用します。
