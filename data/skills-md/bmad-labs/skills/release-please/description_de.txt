Richten Sie Googles Release-Please für die automatische Versionierung, Änderungsprotokollgenerierung und Veröffentlichung über GitHub Actions ein und konfigurieren Sie sie. Behandelt die Pipeline-Erstellung, konventionelle Commits-Formatierung, Vorab-Release-Workflows, Monorepo-Konfiguration und Fehlerbehebung bei Release-Pipelines. Verwenden Sie diesen Skill immer dann, wenn der Benutzer Releases automatisieren, CI/CD für die Veröffentlichung einrichten, Versions-Bumping konfigurieren, Release-Please-Compatible-Commit-Nachrichten schreiben, Versionen automatisch markieren, auf npm/PyPI/crates.io/Maven/Docker veröffentlichen oder Fehler beheben möchte, warum kein Release-PR erstellt wurde. Aktivieren Sie diese Fähigkeit, auch wenn der Benutzer „Release-Please“ nicht namentlich erwähnt – Ausdrücke wie „Meine NPM-Releases automatisieren“, „GitHub-Aktionen für die Veröffentlichung einrichten“, „Wie tagge ich Versionen automatisch“, „Änderungsprotokollgenerierung“, „Semver-Automatisierung“ oder „Vorab-Release-Workflow“ weisen alle auf diese Fähigkeit hin. Speziell für die Anleitung zum Festschreiben von Nachrichten konzentriert sich dieser Skill auf Konventionen, die mit der Freigabe bitte kompatibel sind. Für umfassendere Multi-Repo-Git-Operationen mit Submodulen verwenden Sie stattdessen Multi-Repo-Git-Ops.
