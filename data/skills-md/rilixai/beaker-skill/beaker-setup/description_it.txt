Imposta, configura o esegui l'onboarding di un repository Python per l'ottimizzazione dell'agente Beaker isolando gli strumenti di valutazione in .beaker, lasciando invariato il normale comportamento di runtime e senza mai aggiungere o modificare test o automazione CI/CD. Utilizzare quando si aggiunge Beaker, si esegue un'impalcatura o si completa una factory Beaker @spec, selezionando i file del repository che Beaker può ottimizzare, configurando beaker.yaml o spec.required_env, collegando set di dati etichettati reali e un agente o un percorso di valutazione LLM, connettendo l'app Beaker GitHub, convalidando con beaker run smoke o avviando la prima esecuzione di ottimizzazione dell'agente ospitato. Da utilizzare anche per preservare una specifica di destinazione logica esistente che utilizza esplicitamente @spec(repository=None).
