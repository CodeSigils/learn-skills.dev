Richten Sie ein Python-Repository für die Beaker-Agentenoptimierung ein, konfigurieren oder integrieren Sie es, isolieren Sie dabei die Evaluierungstools unter .beaker, lassen Sie das normale Laufzeitverhalten unverändert und fügen Sie niemals Tests oder CI/CD-Automatisierung hinzu oder ändern Sie sie. Verwenden Sie diese Funktion, wenn Sie Beaker hinzufügen, ein Gerüst erstellen oder eine Beaker @spec-Fabrik vervollständigen, die Repository-Dateien auswählen, die Beaker optimieren kann, beaker.yaml oder spec.required_env konfigurieren, real gekennzeichnete Datensätze und einen Agenten- oder LLM-Bewertungspfad verbinden, die Beaker GitHub-App verbinden, mit Beaker Run Smoke validieren oder den ersten gehosteten Agentenoptimierungslauf starten. Wird auch verwendet, wenn eine vorhandene Spezifikation für ein logisches Ziel beibehalten wird, die explizit @spec(repository=None) verwendet.
