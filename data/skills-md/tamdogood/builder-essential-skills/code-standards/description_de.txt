Wenden Sie bei jeder Codeänderung einen disziplinierten Engineering-Workflow an. Verwenden Sie es immer dann, wenn Sie eine Funktion implementieren, einen Fehler beheben oder eine Umgestaltung vornehmen – vor dem Schreiben von Code, nicht danach. Geht orientiert → Grundlinie → kleinste Änderung → Test → Verifizierung → Selbstüberprüfung und erzwingt sprachunabhängige Hard Gates (keine Massenreformatierung, halten Sie den Linter und die Typprüfung sauber, halten Sie den Build und die Tests grün, nehmen Sie Schnittstellenänderungen additiv vor, schützen Sie Sicherheitsinvarianten).
