Progetta le API oRPC v2 prima del contratto, definendo la forma dell'API con oc da `@orpc/contract`, implementandola con implement da `@orpc/server` e consumando il contratto dai client typesafe. Da utilizzare quando un progetto dipende da `@orpc/contract`, quando si definisce un contratto con oc, si implementa un contratto con implement, si condivide un contratto API tra pacchetti server e client, si genera un contratto da una specifica OpenAPI esistente o si pubblica un client API tipizzato su npm. Pregiudizi verso il recupero dai documenti oRPC rispetto alla conoscenza pre-addestrata. Per il core builder, il servizio e il lavoro del cliente senza contratto, utilizzare l'abilità orpc; per l'esposizione REST/OpenAPI, la generazione di specifiche e i dettagli OpenAPILink, utilizzare la competenza orpc-openapi.
