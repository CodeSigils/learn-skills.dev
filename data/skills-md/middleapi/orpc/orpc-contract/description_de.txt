Entwerfen Sie orRPC v2-APIs zunächst vertragsorientiert, definieren Sie die API-Form mit oc aus „@orpc/contract“, implementieren Sie sie mit „implementieren“ aus „@orpc/server“ und nutzen Sie den Vertrag von typsicheren Clients. Verwenden Sie diese Option, wenn ein Projekt von „@orpc/contract“ abhängt, wenn Sie einen Vertrag mit oc definieren, einen Vertrag mit „implementieren“ implementieren, einen API-Vertrag zwischen Server- und Client-Paketen teilen, einen Vertrag aus einer vorhandenen OpenAPI-Spezifikation generieren oder einen typisierten API-Client in npm veröffentlichen. Bevorzugen Sie den Abruf aus den orRPC-Dokumenten gegenüber vorab trainiertem Wissen. Für Core-Builder-, Service- und Kundenarbeiten ohne Vertrag verwenden Sie die orpc-Fähigkeit; Für die REST/OpenAPI-Bereitstellung, Spezifikationsgenerierung und OpenAPILink-Details verwenden Sie den Skill orpc-openapi.
