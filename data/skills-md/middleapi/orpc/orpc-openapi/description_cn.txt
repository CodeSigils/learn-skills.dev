将 oRPC 路由器公开为符合规范的 OpenAPI HTTP API。当项目依赖于 @orpc/openapi 时使用，或者在 oRPC 过程上定义 REST 风格的路由（openapi() 元数据或带有方法、路径、successStatus 的 .route），使用 OpenAPIHandler 与 RPCHandler 一起提供服务，使用智能强制强制查询和路径字符串，使用 OpenAPILink 调用 OpenAPI 型 API，使用 OpenAPIGenerator 生成 OpenAPI 3.1 文档，或者使用 OpenAPI Reference 插件提供 Scalar 或 Swagger 文档。偏向于从 oRPC 文档中检索而不是预先训练的知识。对于契约优先的工作（使用 oc 定义契约，使用 Implement 实现它们，或者从现有 OpenAPI 规范生成契约），请使用 orpc-contract 技能；对于没有 REST 暴露的普通 RPC 服务、核心构建器、中间件或客户端工作，请改用 orpc 技能。
