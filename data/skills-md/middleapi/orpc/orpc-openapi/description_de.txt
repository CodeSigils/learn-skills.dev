Stellen Sie einen orRPC-Router als spezifikationskonforme OpenAPI-HTTP-API bereit. Wird verwendet, wenn ein Projekt von @orpc/openapi abhängt, oder zum Definieren von Routen im REST-Stil für oRPC-Prozeduren (openapi()-Metadaten oder .route mit Methode, Pfad, successStatus), zum Bereitstellen dieser Routen mit OpenAPIHandler neben RPCHandler, zum Erzwingen von Abfrage- und Pfadzeichenfolgen mit Smart Coercion, zum Aufrufen einer OpenAPI-förmigen API mit OpenAPILink, zum Generieren eines OpenAPI 3.1-Dokuments mit OpenAPIGenerator oder zum Bereitstellen von Scalar- oder Swagger-Dokumenten mit der OpenAPI-Referenz Plugin. Bevorzugen Sie den Abruf aus den orRPC-Dokumenten gegenüber vorab trainiertem Wissen. Für vertragsorientierte Arbeiten (Verträge mit oc definieren, mit implementieren implementieren oder einen Vertrag aus einer vorhandenen OpenAPI-Spezifikation generieren) verwenden Sie den Skill „orpc-contract“; Für einfache RPC-Bereitstellung, Core Builder, Middleware oder Client-Arbeit ohne REST-Belastung verwenden Sie stattdessen die orpc-Fähigkeit.
