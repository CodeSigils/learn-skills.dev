Esporre un router oRPC come API HTTP OpenAPI conforme alle specifiche. Da utilizzare quando un progetto dipende da @orpc/openapi o per definire percorsi in stile REST su procedure oRPC (metadati openapi() o .route con metodo, percorso, successStatus), servirli con OpenAPIHandler insieme a RPCHandler, forzare stringhe di query e percorso con Smart Coercion, chiamare un'API a forma di OpenAPI con OpenAPILink, generare un documento OpenAPI 3.1 con OpenAPIGenerator o servire documenti scalari o Swagger con il plug-in di riferimento OpenAPI. Pregiudizi verso il recupero dai documenti oRPC rispetto alla conoscenza pre-addestrata. Per il lavoro basato sul contratto (definire contratti con oc, implementarli con implement o generare un contratto da una specifica OpenAPI esistente), utilizzare la competenza orpc-contract; per il semplice servizio RPC, core builder, middleware o lavoro client senza esposizione REST, utilizzare invece la competenza orpc.
