Предоставьте маршрутизатор oRPC как HTTP API OpenAPI, соответствующий спецификации. Используйте, когда проект зависит от @orpc/openapi или для определения маршрутов в стиле REST для процедур oRPC (метаданные openapi() или .route с методом, путем, SuccessStatus), их обслуживания с помощью OpenAPIHandler вместе с RPCHandler, приведения строк запроса и пути с помощью Smart Coercion, вызова API в форме OpenAPI с помощью OpenAPILink, создания документа OpenAPI 3.1 с помощью OpenAPIGenerator или обслуживания Scalar или Документы Swagger с плагином OpenAPI Reference. Склонность к извлечению из документов oRPC, а не к предварительно обученным знаниям. Для работы с контрактом (определение контрактов с помощью oc, реализация их с помощью реализации или создание контракта на основе существующей спецификации OpenAPI) используйте навык orpc-contract; для простого обслуживания RPC, сборки ядра, промежуточного программного обеспечения или работы с клиентом без использования REST вместо этого используйте навык orpc.
