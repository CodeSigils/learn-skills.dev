Exposez un routeur oRPC en tant qu'API HTTP OpenAPI conforme aux spécifications. À utiliser lorsqu'un projet dépend de @orpc/openapi, ou pour définir des routes de style REST sur des procédures oRPC (métadonnées openapi() ou .route avec méthode, chemin, successStatus), les servir avec OpenAPIHandler aux côtés de RPCHandler, forcer les chaînes de requête et de chemin avec Smart Coercion, appeler une API de type OpenAPI avec OpenAPILink, générer un document OpenAPI 3.1 avec OpenAPIGenerator ou servir des documents Scalar ou Swagger avec le Plugin de référence OpenAPI. Biais en faveur de la récupération des documents oRPC par rapport aux connaissances pré-entraînées. Pour le travail axé sur le contrat (définir des contrats avec oc, les implémenter avec Implement ou générer un contrat à partir d'une spécification OpenAPI existante), utilisez la compétence orpc-contract ; pour un service RPC simple, un générateur de noyau, un middleware ou un travail client sans exposition REST, utilisez plutôt la compétence orpc.
