oRPC v2 を使用して、エンドツーエンドのタイプセーフ API を構築、提供、呼び出します。 `@orpc/*` パッケージに依存するプロジェクト内のあらゆるタスクに使用します。1 つのプロシージャの変更であっても、OS ビルダー (.input/.output/.handler、任意の標準スキーマ検証ツール) によるプロシージャの定義、ルーター、ミドルウェア、コンテキストのアセンブル、ORPCError によるタイプセーフ エラー、任意のランタイム アダプター上の RPCHandler を介したサービス、サーバー側クライアント (呼び出し、createRouterClient) またはクライアント側クライアントからの呼び出しに使用します。 (RPCLink を使用して ORPCClient を作成)、TanStack Query の統合、または SSE 経由のストリーミング。事前トレーニングされた oRPC の知識は v1 について説明しており、v2 については間違っているため、変更が些細に見える場合でもこのスキルをロードします。事前にトレーニングされた知識よりも、oRPC ドキュメントからの検索に偏りがある。 REST/OpenAPI を公開する場合は、orpc-openapi スキルを推奨します。コントラクトファースト設計の場合は、orpc-contract スキル。 tRPC または oRPC v1 移行の場合は、orpc-merge スキル。
