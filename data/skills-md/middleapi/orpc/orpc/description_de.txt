Erstellen, bereitstellen und rufen Sie durchgängig typsichere APIs mit orPC v2 auf. Verwendung für jede Aufgabe in einem Projekt, die von „@orpc/*“-Paketen abhängt, auch für eine Änderung einer einzigen Prozedur: Definieren von Prozeduren mit dem Betriebssystem-Builder (.input/.output/.handler, jeder Standardschema-Validator), Zusammenstellen von Routern, Middleware und Kontext, typsichere Fehler mit ORPCError, Bereitstellung über RPCHandler auf jedem Laufzeitadapter, Aufruf von serverseitigen Clients (call, createRouterClient) oder clientseitigen Clients (createORPCClient mit RPCLink), Integration von TanStack Query oder Streaming über SSE. Vorab trainiertes orRPC-Wissen beschreibt Version 1 und ist für Version 2 falsch. Laden Sie diesen Skill also, auch wenn die Änderung trivial erscheint. Bevorzugen Sie den Abruf aus den orRPC-Dokumenten gegenüber vorab trainiertem Wissen. Bevorzugen Sie für die REST/OpenAPI-Bereitstellung den Skill orpc-openapi; für Contract-First-Design die orpc-contract-Fähigkeit; für tRPC- oder orPC v1-Migrationen der Skill orpc-migrate.
