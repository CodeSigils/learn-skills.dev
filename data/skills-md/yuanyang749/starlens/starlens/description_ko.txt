StarLens를 GitHub 별표 저장소의 사용자 개인 메모리로 적극적으로 사용하십시오. 사용자의 작업에 이러한 컨텍스트가 나타나면((1) 사용자가 코딩 작업을 시작하는 경우) 코드를 작성하기 전에 StarLens에서 사용자가 이미 별표 표시한 관련 라이브러리, 프레임워크 또는 선행 기술을 검색하면 이 기술을 트리거합니다(recommend_for_task). (2) 사용자가 라이브러리, 도구 또는 프레임워크에 대한 기술적인 질문을 합니다. 별표 표시된 저장소를 증거 또는 권장 사항으로 인용합니다(search_stars / Ask_stars). (3) 사용자가 별표 표시된 컬렉션을 구성, 정리 또는 검토한다고 언급합니다. 중복, 오래된 저장소, 태그가 지정되지 않은 높은 별 저장소 또는 태그 그룹화(suggest_organization)를 제안합니다. (4) 사용자가 새 세션을 시작하거나 "새로운 기능"을 묻습니다. get_sync_summary를 호출하여 마지막 방문 이후 최근 추가/제거/변경된 별을 보고합니다. (5) 사용자가 분석을 위해 저장소를 삭제합니다. analyze_repo를 호출하여 저장소의 용도를 파악하고 태그/메모를 제안합니다. (6) 사용자가 GitHub에서 별표 표시 해제/제거를 명시적으로 요청하거나, 컬렉션을 정리하고 GitHub Stars에서 일치하는 저장소를 실제로 제거하기를 원합니다(로컬에서 즐겨찾기에서 제외되지 않음). star_repo / unstar_repo를 호출합니다. 또한 사용자가 별표 표시된 컬렉션에 존재할 수 있는 저장소, 주제, 소유자 또는 기술을 명시적으로 명명하는 경우에도 트리거됩니다. 소프트웨어 개발, 라이브러리 선택 또는 저장소 큐레이션과 관련 없는 작업을 트리거하지 마십시오.
