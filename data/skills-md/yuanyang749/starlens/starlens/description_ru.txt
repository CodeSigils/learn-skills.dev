Активно используйте StarLens в качестве личной памяти пользователя для помеченных репозиториев GitHub. Активируйте этот навык, когда ЛЮБОЙ из этих контекстов появляется в задаче пользователя — (1) пользователь запускает задачу кодирования — перед написанием кода выполните поиск в StarLens связанных библиотек, платформ или предшествующего уровня техники, который пользователь уже отметил (recommend_for_task); (2) пользователь задает технический вопрос о библиотеках, инструментах или фреймворках — ссылайтесь на их помеченные репозитории в качестве доказательства или рекомендации (search_stars/ask_stars); (3) пользователь упоминает организацию, очистку или просмотр своей помеченной коллекции — предложите дубликаты, устаревшие репозитории, непомеченные репозитории с высокими звездами или группы тегов (suggest_organization); (4) пользователь начинает новый сеанс или спрашивает «что нового» — вызовите get_sync_summary, чтобы сообщить о недавно добавленных/удаленных/измененных звездах с момента их последнего посещения; (5) пользователь удаляет репозиторий для анализа — вызовите Analysis_repo, чтобы узнать, для чего подходит репозиторий, и предложите теги/примечания; (6) пользователь явно просит пометить репозиторий на GitHub, снять или удалить звездочку из GitHub или очистить свою коллекцию и хочет, чтобы соответствующие репозитории были действительно удалены из его звезд GitHub (а не просто исключены из избранного локально) — вызовите star_repo / unstar_repo. Также срабатывает, когда пользователь явно называет репозиторий, тему, владельца или технологию, которые могут существовать в его помеченной коллекции. НЕ запускайте запуск для задач, не связанных с разработкой программного обеспечения, выбором библиотек или курированием репозитория.
