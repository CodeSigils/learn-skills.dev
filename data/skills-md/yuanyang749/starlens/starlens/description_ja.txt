GitHub のスター付きリポジトリのユーザーの個人的な記憶として StarLens を積極的に使用します。これらのコンテキストのいずれかがユーザーのタスクに表示されたときにこのスキルをトリガーします。(1) ユーザーがコーディング タスクを開始しているとき。コードを記述する前に、StarLens で関連するライブラリ、フレームワーク、またはユーザーがすでにスターを付けている先行技術を検索します (recommend_for_task)。 (2) ユーザーがライブラリ、ツール、またはフレームワークに関する技術的な質問をします。証拠または推奨事項としてスター付きリポジトリを引用します (search_stars / ask_stars)。 (3) ユーザーがスター付きコレクションの整理、クリーンアップ、またはレビューについて言及します。重複、古いリポジトリ、タグのない高スターのリポジトリ、またはタグのグループ化 (suggest_organization) を提案します。 (4) ユーザーが新しいセッションを開始するか、「最新情報」を尋ねます。get_sync_summary を呼び出して、前回の訪問以降に最近追加/削除/変更されたスターを報告します。 (5) ユーザーは分析のためにリポジトリをドロップします。analyze_repo を呼び出して、リポジトリが何に適しているかを明らかにし、タグ/メモを提案します。 (6) ユーザーが、GitHub 上のリポジトリにスターを付けるか、GitHub からスターを外す/削除するか、コレクションをクリーンアップして、一致するリポジトリを GitHub スターから実際に削除することを明示的に要求します (ローカルでお気に入りを解除するだけでなく) — star_repo / unstar_repo を呼び出します。また、ユーザーがスター付きコレクションに存在する可能性のあるリポジトリ、トピック、所有者、またはテクノロジーに明示的に名前を付けたときにもトリガーされます。ソフトウェア開発、ライブラリの選択、リポジトリのキュレーションに関係のないタスクをトリガーしないでください。
