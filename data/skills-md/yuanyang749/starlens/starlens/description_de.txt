Nutzen Sie StarLens proaktiv als persönlichen Speicher des Benutzers für mit GitHub markierte Repositorys. Lösen Sie diesen Skill aus, wenn IRGENDWELCHER dieser Kontexte in der Aufgabe des Benutzers erscheint – (1) der Benutzer startet eine Codierungsaufgabe – bevor Sie Code schreiben, durchsuchen Sie StarLens nach verwandten Bibliotheken, Frameworks oder dem Stand der Technik, den der Benutzer bereits markiert hat (recommend_for_task); (2) Der Benutzer stellt eine technische Frage zu Bibliotheken, Tools oder Frameworks – nennen Sie deren markierte Repos als Beweis oder Empfehlung (search_stars / ask_stars); (3) der Benutzer erwähnt das Organisieren, Bereinigen oder Überprüfen seiner markierten Sammlung – schlägt Duplikate, veraltete Repos, nicht getaggte High-Star-Repos oder Tag-Gruppierungen vor (suggest_organization); (4) Der Benutzer startet eine neue Sitzung oder fragt „Was ist neu?“ – rufen Sie get_sync_summary auf, um kürzlich hinzugefügte/entfernte/geänderte Sterne seit seinem letzten Besuch zu melden; (5) Der Benutzer legt ein Repository zur Analyse ab – rufen Sie „analysate_repo“ auf, um herauszufinden, wozu das Repo gut ist, und schlagen Sie Tags/Notizen vor; (6) Der Benutzer bittet ausdrücklich darum, ein Repo auf GitHub zu markieren, einen Stern von GitHub zu entfernen oder seine Sammlung zu bereinigen und möchte, dass passende Repos tatsächlich von seinen GitHub-Sternen entfernt werden (nicht nur lokal als unfavorisiert) – rufen Sie star_repo / unstar_repo auf. Wird auch ausgelöst, wenn der Benutzer explizit ein Repository, ein Thema, einen Eigentümer oder eine Technologie benennt, die möglicherweise in seiner markierten Sammlung vorhanden sind. NICHT für Aufgaben auslösen, die nichts mit Softwareentwicklung, Bibliotheksauswahl oder Repository-Kuratierung zu tun haben.
