Générez une suite de documentation de projet complète et cohérente en interne : huit fichiers de démarques standardisés écrits dans un dossier docs/ (PRD, architecture logicielle, spécifications fonctionnelles, architecture de base de données, spécifications du panneau d'administration, spécifications de l'API REST, directives d'ingénierie, plan de projet). Utilisez-le chaque fois que l'utilisateur souhaite documenter un projet logiciel, amorcer des documents pour une base de code nouvelle ou existante, ou produire l'un de ces documents : un PRD, un document d'architecture, une spécification d'API, une conception de base de données, des directives d'ingénierie, un plan de projet. Déclenchez des expressions telles que « documentation du projet », « documents de conception », « documents de spécifications », « suite de documentation », « écrire les documents », « documenter cette application/service/système » ou une demande pour un seul des huit documents (la suite est conçue pour être générée ensemble afin que les documents restent cohérents les uns avec les autres). Déclenchez également lorsque l'utilisateur a construit ou décrit un projet logiciel dans la conversation et souhaite maintenant qu'il soit rédigé officiellement.
