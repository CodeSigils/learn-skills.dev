Generieren Sie eine vollständige, intern konsistente Projektdokumentationssuite – acht standardisierte Markdown-Dateien, die in einen docs/-Ordner geschrieben werden (PRD, Softwarearchitektur, Funktionsspezifikation, Datenbankarchitektur, Admin-Panel-Spezifikation, REST-API-Spezifikation, technische Richtlinien, Projektentwurf). Verwenden Sie dies immer dann, wenn der Benutzer ein Softwareprojekt dokumentieren, Dokumente für eine neue oder vorhandene Codebasis booten oder eines dieser Dokumente erstellen möchte – ein PRD, ein Architekturdokument, eine API-Spezifikation, ein Datenbankdesign, technische Richtlinien, einen Projektentwurf. Lösen Sie auf Phrasen wie „Projektdokumentation“, „Entwurfsdokumente“, „Spezifikationsdokumente“, „Dokumentationssuite“, „Schreiben Sie die Dokumente“, „Dokumentieren Sie diese App/diesen Dienst/dieses System“ oder eine Anfrage für nur eines der acht Dokumente aus (die Suite ist so konzipiert, dass sie gemeinsam generiert wird, sodass die Dokumente untereinander konsistent bleiben). Wird auch ausgelöst, wenn der Benutzer im Gespräch ein Softwareprojekt erstellt oder beschrieben hat und es nun formell aufgeschrieben haben möchte.
