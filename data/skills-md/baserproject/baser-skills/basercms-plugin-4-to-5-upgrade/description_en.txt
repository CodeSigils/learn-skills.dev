A collection of concrete rewrite patterns for Controllers, Tables, Entities, Views, Helpers, forms, Vue/JS when migrating internal plugin code from baserCMS 4 (based on CakePHP 2) to baserCMS 5 (based on CakePHP 5). Includes patterns such as “migrate plugin from 4 to 5,” “admin_ methods to Controller/Admin,” “public $belongsTo/$hasMany to initialize(),” “ClassRegistry/TableRegistry,” “find(all/first/list, array) to query builder,” “$this->Model (null) to fetchTable,” “getControlSource singular → plural,” “$this->Form to BcAdminForm·control(),” “search form searches/ → search/,” “FormHelper::create string model → null,” “FormHelper::year()/month()/domId() deprecated,” “Time::format ICU patterns,” “Number::format/Text::truncate cannot be null,” “array condition IN not auto‑added; null becomes IS,” “Vue/JS admin URL to $.bcUtil.adminBaseUrl + webpack rebuild,” “$this->data / $View->request causing helper misloading,” “MissingTableClassException / MissingHelperException / No context provider found,” “App::import external libraries bundled as Vendor (leafo/scssphp, etc.) not ported to version 5 and thus dead,” “PHP 8 removal of each() and improper regex escaping, etc., old bundled libraries incompatible with PHP 8,” etc., to be consulted while fixing each error in a plugin’s UI, model, template, and front‑end display one by one. This skill focuses on detecting and converting 4.x idioms; the definitive guide for correct 5.x coding is basercms5-plugin-development. Whole‑site migration steps from 4 to 5 (installation/DB migration/theme & plugin conversion/Git workflow) are in basercms4-to-5-upgrade, theme (templates‑centric) migration in basercms-theme-4-to-5-upgrade, plugin migration from 5.2 → 5.3 in basercms-plugin-5x-update, CakePHP‑core issues in cakephp-migration, PHP‑core issues in php-migration, test execution in basercms-unittest, and if migrating custom‑field add‑on plugins for blogs etc. to bc‑custom‑content, refer to basercms5-custom-content-development.
