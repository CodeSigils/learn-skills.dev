Procedure for promoting a “regular plugin (third‑party / standalone distribution)” of baserCMS to a “core plugin” in a monorepo. Refer to this when you need to “change to core plugin”, “core‑ify a plugin”, “promote a regular plugin to core”, “incorporate into monorepo”, etc. It covers changing the plugin‑name convention (adding the bc‑ prefix, converting CamelCase to hyphen‑separated), removing .git/symbolic‑link/standalone test infrastructure, registering the root phpunit.xml.dist, tests/bootstrap.php, composer.json, and .gitignore, adding the plugin to baser‑core’s setting.php (corePlugins/defaultInstallCorePlugins), phpdoc.dist.xml, and split_monorepo.yml, aggregating dependencies with monorepo‑builder merge, confirming execution in the overall test suite, and checking the read‑only repository used for monorepo split. The plugin’s version deprecation handling (5.2→5.3) is covered by the basercms‑plugin‑5x‑update skill, and the test execution procedure is in the basercms‑unittest skill.
