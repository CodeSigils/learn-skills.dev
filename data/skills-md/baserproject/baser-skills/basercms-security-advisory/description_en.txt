Procedures and scripts that handle baserCMS repository security advisories (including GHSA and triage) end‑to‑end: retrieve the list → verify the findings → fix per issue → create a private fork/branch/PR → perform local verification. Used for tasks such as “check security advisories,” “verify triage vulnerabilities,” “create a fork and PR for each advisory,” and “bundle vulnerability fixes into a pull request.” Because Copilot/GHA cannot be used on advisory forks, the workflow treats local verification (/code‑review, basercms‑unittest) as the authoritative step; it also includes retrying until a push is reflected, splitting shared files into hunks, and the standard resolution of base‑tracking merge conflicts.
