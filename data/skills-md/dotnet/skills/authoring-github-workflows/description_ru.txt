Создавайте и проверяйте YAML рабочего процесса GitHub Actions безопасно, чтобы синтаксически допустимый YAML не мог отправить рабочий процесс, который GitHub Actions отказывается запускать. ИСПОЛЬЗОВАНИЕ ДЛЯ: редактирования, добавления или проверки любого файла в .github/workflows/, записи значений имени запуска/имя/if/env/run, содержащих выражения ${{ }}, диагностики запуска, который завершился неудачно с сообщением «Этот запуск, вероятно, завершился неудачей из-за проблемы с файлом рабочего процесса» и не запускается ни одного задания, принятия решения о том, когда скаляр рабочего процесса должен быть заключен в кавычки, проверки рабочих процессов с помощью actionlint. НЕ ИСПОЛЬЗУЙТЕ ДЛЯ: создания YAML-файла приложения, не связанного с GitHub Actions, Azure Pipelines, GitLab CI или YAML, не относящимся к рабочему процессу. ОБЛАСТЬ ПРИМЕНЕНИЯ: этот навык охватывает *синтаксическую/структурную* корректность рабочего процесса YAML (цитирование, синтаксический анализ, actionlint); для *семантического и функционального* проектирования рабочего процесса (что должен делать рабочий процесс, поведение агентного рабочего процесса) см. .github/agents/agentic-workflows.agent.md — эти два понятия дополняют друг друга. ВЫЗЫВАЕТ: actionlint (загруженный закрепленный двоичный файл) плюс git/grep для проверки.
