Guida per l'ottimizzazione delle build incrementali di MSBuild. Attivare solo nel contesto di compilazione MSBuild/.NET. UTILIZZARE PER: build più lente del previsto nelle esecuzioni successive, "non è cambiato nulla ma si ricostruisce comunque", diagnosticare il motivo per cui gli obiettivi vengono rieseguiti inutilmente, correggere build no-op non funzionanti. Copre 8 cause comuni: input/output mancanti su destinazioni personalizzate, proprietà volatili nei percorsi di output (timestamp/GUID), scritture di file all'esterno di output tracciati, registrazione FileWrite mancante, modifiche glob, problemi di controllo rapido aggiornamento rapido (FUTDC) di Visual Studio. Diagnostica chiave: cerca "Creazione target completamente" vs "Salta target" in binlog. NON UTILIZZARE PER: lentezza della compilazione iniziale (utilizzare build-perf-baseline), problemi di parallelismo (utilizzare build-parallelism), lentezza della fase di valutazione (utilizzare eval-performance), sistemi di compilazione non MSBuild. RICHIAMA: dotnet build /bl, riproduzione binlog con verbosità diagnostica.
