Руководство по оптимизации параллелизма сборки MSBuild и планирования нескольких проектов. Активируйте только в контексте сборки MSBuild/.NET. ИСПОЛЬЗОВАНИЕ ДЛЯ: сборки, не использующие все ядра ЦП, ускорение многопроектных решений, оценка режима построения графа (/graph), время сборки, не улучшающееся с помощью флага -m, понимание топологии зависимостей проекта. Примечание. /maxcpucount по умолчанию — 1 (последовательный) — всегда используйте -m для параллельных сборок. Охватывает /maxcpucount, построение графиков для лучшего планирования и изоляции, BuildInParallel в задаче MSBuild, сокращение ненужных ссылок ProjectReferences, фильтры решений (.slnf) для построения подмножеств. НЕ ИСПОЛЬЗУЙТЕ ДЛЯ: сборок одного проекта, проблем с инкрементальной сборкой (используйте инкрементальную сборку), медленной компиляции внутри проекта (используйте диагностику производительности сборки), систем сборки, отличных от MSBuild. ВЫЗЫВАЕТ: dotnet build -m, dotnet build /graph, анализ binlog.
