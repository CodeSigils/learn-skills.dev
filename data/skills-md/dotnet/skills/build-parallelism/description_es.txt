Guía para optimizar el paralelismo de compilación de MSBuild y la programación de múltiples proyectos. Activar solo en el contexto de compilación de MSBuild/.NET. USO PARA: compilaciones que no utilizan todos los núcleos de CPU, acelerar soluciones de múltiples proyectos, evaluar el modo de compilación de gráficos (/graph), el tiempo de compilación no mejora con el indicador -m, comprender la topología de dependencia del proyecto. Nota: /maxcpucount el valor predeterminado es 1 (secuencial); utilice siempre -m para compilaciones paralelas. Cubre /maxcpucount, creación de gráficos para una mejor programación y aislamiento, BuildInParallel en la tarea MSBuild, lo que reduce ProjectReferences innecesarias, filtros de solución (.slnf) para crear subconjuntos. NO LO UTILICE PARA: compilaciones de un solo proyecto, problemas de compilación incremental (use compilación incremental), lentitud de compilación dentro de un proyecto (use build-perf-diagnostics), sistemas de compilación que no sean MSBuild. INVOCA: dotnet build -m, dotnet build /graph, análisis binlog.
