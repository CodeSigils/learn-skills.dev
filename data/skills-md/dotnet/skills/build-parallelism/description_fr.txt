Guide pour optimiser le parallélisme de build MSBuild et la planification multi-projets. Activez uniquement dans le contexte de build MSBuild/.NET. UTILISER POUR : les builds n'utilisant pas tous les cœurs de processeur, l'accélération des solutions multi-projets, l'évaluation du mode de construction de graphiques (/graph), le temps de construction ne s'améliorant pas avec l'indicateur -m, la compréhension de la topologie des dépendances du projet. Remarque : /maxcpucount par défaut est 1 (séquentiel) — utilisez toujours -m pour les builds parallèles. Couvre /maxcpucount, la création de graphiques pour une meilleure planification et une meilleure isolation, BuildInParallel sur la tâche MSBuild, réduisant les ProjectReferences inutiles, les filtres de solution (.slnf) pour la création de sous-ensembles. NE PAS UTILISER POUR : les builds pour un seul projet, les problèmes de build incrémentiels (utiliser la construction incrémentielle), la lenteur de la compilation au sein d'un projet (utiliser les diagnostics de performances de construction), les systèmes de build non MSBuild. INVOKES : dotnet build -m, dotnet build /graph, analyse binlog.
