Guida per l'ottimizzazione del parallelismo delle build di MSBuild e della pianificazione multiprogetto. Attivare solo nel contesto di compilazione MSBuild/.NET. UTILIZZARE PER: build che non utilizzano tutti i core della CPU, accelerazione di soluzioni multi-progetto, valutazione della modalità di creazione del grafico (/graph), tempo di creazione che non migliora con il flag -m, comprensione della topologia delle dipendenze del progetto. Nota: il valore predefinito di /maxcpucount è 1 (sequenziale): utilizzare sempre -m per build parallele. Copre /maxcpucount, creazione di grafici per una migliore pianificazione e isolamento, BuildInParallel sull'attività MSBuild, riduzione di ProjectReferences non necessari, filtri della soluzione (.slnf) per la creazione di sottoinsiemi. NON UTILIZZARE PER: build di progetti singoli, problemi di build incrementali (usare incremental-build), lentezza di compilazione all'interno di un progetto (usare build-perf-diagnostics), sistemi di build non MSBuild. RICHIAMA: dotnet build -m, dotnet build /graph, analisi binlog.
