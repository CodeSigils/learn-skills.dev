Leitfaden zum Organisieren der MSBuild-Infrastruktur mit Directory.Build.props, Directory.Build.targets, Directory.Packages.props und Directory.Build.rsp. Nur im MSBuild/.NET-Buildkontext aktivieren. VERWENDUNG FÜR: Strukturieren von Repos für mehrere Projekte, Zentralisieren von Build-Einstellungen, Implementieren von NuGet Central Package Management (CPM) mit ManagePackageVersionsCentrally, Konsolidieren duplizierter Eigenschaften über .csproj-Dateien hinweg, Einrichten einer mehrstufigen Directory.Build-Hierarchie mit GetPathOfFileAbove, Verstehen der Auswertungsreihenfolge (Directory.Build.props → SDK .props → .csproj → SDK .targets → Directory.Build.targets). Kritischer Fallstrick: $(TargetFramework)-Bedingungen in .props schlagen bei Einzel-Targeting-Projekten stillschweigend fehl – ​​es muss .targets verwendet werden. NICHT VERWENDEN FÜR: Nicht-MSBuild-Buildsysteme, Migration von Legacy-Projekten zum SDK-Stil (verwenden Sie msbuild-modernization), Einzelprojektlösungen ohne gemeinsame Einstellungen. AUFRUF: keine Werkzeuge – reine Wissenskompetenz.
