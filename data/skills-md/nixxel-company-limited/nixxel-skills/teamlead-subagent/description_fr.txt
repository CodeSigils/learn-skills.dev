Orchestration TeamLead — utilisée lorsqu'un humain souhaite une implémentation/délégation coordonnée pour le code produit, les tests, la configuration, l'infrastructure, les fonctionnalités, les corrections de bogues, les refactors ou les changements de comportement/interface utilisateur/API. Il n'est pas nécessaire de le déclencher pour une inspection/un statut/une explication/un résumé léger/une révision/une recherche sans modification, à moins que l'humain ne demande explicitement que l'orchestration ou la délégation de TeamLead soit bénéfique. Le travail qui crée ou modifie un comportement doit toujours invoquer d'abord « superpuissances : brainstorming », puis le responsable crée des portes de spécification/plan avant de déléguer ; il est interdit au Lead d'écrire lui-même le code du produit.
