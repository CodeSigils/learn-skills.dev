A skill for making design decisions regarding software functional boundaries, responsibility separation, module partitioning, and abstraction. Use it as an internal thought process when receiving design consultations. Always refer to this skill for any consultation concerning design structure, such as “How should this feature be designed?”, “How should responsibilities be divided?”, “I want to refactor”, “I want to consider module partitioning”, “I want to determine if an abstraction is correct”, “I want to revisit class design”, “The code is hard to follow”, “What should be placed where?”, etc. It also applies to design reviews, architecture deliberations, and proposals for improving code structure.
