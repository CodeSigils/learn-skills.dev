A skill that accepts multiple bug reports and feature requests from non‑engineer reporters, conducts parallel investigations for each case with sub‑agents, groups them by overlapping anticipated change areas, and creates new GitHub issues or merges them into existing ones. Its purpose is to organize issues into units that will not conflict during parallel work‑tree development. It gathers information using only plain language, obtains approval for the registration plan, and then writes the issue with the gh CLI. It does not decide on solutions or implementation specifications. When engineers file an issue themselves, they use issue‑report‑dev.
