يُستخدم فقط عندما يستدعي المستخدم صراحةً /issue-report-user (أو $issue-report-user في Codex). عدم الاستدعاء التلقائي مطلقًا. هي مهارة تتلقى تقارير أخطاء متعددة وطلبات ميزات من مراسلين غير مهندسين، وتجري تحقيقات متوازية مع الوكلاء الفرعيين لكل حالة، وتجميعها عن طريق تداخل مناطق التغيير المتوقعة، وتسجيل مشكلات GitHub الجديدة أو دمجها في المشكلات الحالية. والغرض منه هو تنظيم القضايا في وحدات لا تتعارض مع تطوير شجرة العمل الموازية. فهو يجمع المعلومات باستخدام لغة واضحة فقط، ويحصل على الموافقة على خطة التسجيل، ثم يكتب المشكلة مع gh CLI. ولا تقرر الحلول أو مواصفات التنفيذ. عندما يقوم المهندس بإنشاء المشكلة بنفسه، يجب عليه استخدام Issue-report-dev.

يرجى الرد دائمًا بلغة المستخدم.
