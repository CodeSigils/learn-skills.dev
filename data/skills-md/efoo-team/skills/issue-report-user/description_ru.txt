Навык, который принимает многочисленные отчеты об ошибках и запросы функций от журналистов, не являющихся инженерами, проводит параллельные расследования каждого случая с субагентами, группирует их по перекрывающимся областям ожидаемых изменений и создает новые проблемы GitHub или объединяет их с существующими. Его цель — организовать проблемы в блоки, которые не будут конфликтовать во время параллельной разработки рабочего дерева. Он собирает информацию, используя простой язык, получает одобрение плана регистрации, а затем записывает проблему с помощью gh CLI. Он не принимает решения по решениям или спецификациям реализации. Когда инженеры сами сообщают о проблеме, они используют отчет о проблеме-dev.
