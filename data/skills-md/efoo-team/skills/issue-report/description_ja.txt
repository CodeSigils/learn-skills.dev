ユーザーが明示的に /issue-report (または Codex の $issue-report) を呼び出す場合にのみ使用します。決して自動呼び出ししないでください。複数のバグレポートと機能リクエストを一度に受け入れ、サブエージェントを使用してケースごとに並行調査を実施し、予想される変更の重複領域ごとにそれらをグループ化し、新しい GitHub 問題を作成するか、既存の問題に統合するスキル。その目的は、並列ワークツリー開発中に競合しない単位に問題を整理することです。エンジニア以外の記者から平易な言葉で情報を収集し、登録計画の承認を得て、gh CLI を使用して問題を作成します。ソリューションや実装仕様を決定するものではありません。常にユーザーの言語で応答してください。
