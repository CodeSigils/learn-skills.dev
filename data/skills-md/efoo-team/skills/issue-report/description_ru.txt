Используйте только тогда, когда пользователь явно вызывает /issue-report (или $issue-report в Кодексе). Никогда не вызывайте автоматически. Навык, позволяющий одновременно получать несколько отчетов об ошибках и запросы на добавление функций, проводить параллельные исследования каждого случая с помощью субагентов, группировать их на основе перекрытия областей ожидаемых изменений и регистрировать новые проблемы GitHub или объединять их с существующими. Его цель — организовать проблемы в блоки, которые не конфликтуют при параллельной разработке рабочего дерева. Он проводит интервью с журналистами, не являющимися инженерами, используя простой язык, получает одобрение плана регистрации, а затем пишет проблему, используя gh CLI. Он не принимает решения по решениям или спецификациям реализации.
