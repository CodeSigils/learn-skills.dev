Skill for making design decisions about UI, screens, and user flows. It can be applied to UI design and action placement when creating new screens or adding features, to organizing and simplifying existing UI, to screen transition and information design at the requirements stage, and to UI design reviews—even without an explicit request to “design the UI.” It provides the deliberation process (object → structure → flow → data state → UI) and criteria for decisions on entry integration, staged disclosure, and layout. Detailed visual expressions such as color and typography are out of scope. For code boundary design, use module‑boundary‑design; for API design, use restful‑api‑design.
