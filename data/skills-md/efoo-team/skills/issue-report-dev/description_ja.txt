ユーザーが明示的に /issue-report-dev (または Codex の $issue-report-dev) を呼び出す場合にのみ使用します。決して自動呼び出ししないでください。 GitHub の課題を自ら作成するエンジニアのスキル。ログ、スタック トレース、失敗したテストを組み込み、サブエージェントを使用してファイル/シンボル レベルまで根本原因を調査し、原因の仮説、提案された修復計画、および受け入れ基準を含む問題の草案を作成します。技術的な質問や想定仕様の検証を無制限に実施し、重複する想定変更箇所に基づいてグループ化して登録・統合します。エンジニア以外からレポートを受け取るには、issue-report-user を使用します。常にユーザーの言語で応答してください。
