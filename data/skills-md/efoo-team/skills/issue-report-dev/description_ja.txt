ユーザーが明示的に /issue-report-dev (または Codex の $issue-report-dev) を呼び出す場合にのみ使用します。決して自動呼び出ししないでください。エンジニア自身が作成した GitHub イシューを作成するスキル。ログ、スタック トレース、失敗したテストを組み込み、サブエージェントを使用して根本原因をファイル/シンボル レベルまで調査し、原因の仮説、提案された修復計画、および受け入れ基準を含む問題の草案を作成します。技術的な質問や予想仕様の検証を制限なく実施し、重複する予想変更箇所に基づいてグループ化して登録・統合します。エンジニア以外からのレポートは、issue-report-user を使用して受信する必要があります。
