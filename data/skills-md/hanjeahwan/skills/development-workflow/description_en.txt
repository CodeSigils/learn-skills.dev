For development collaboration processes that require reading repository context and completing multi-step engineering tasks: code modifications, bug debugging, involving multiple modules, state flows, external contracts, side effects, permission/data flow or user-visible behavior refactoring, code review, TDD/test‑first, delivery verification, and technical documentation updates. Low‑risk local implementations follow a lightweight path, while high‑risk tasks go through an advanced risk gate. It should be used when the user mentions implementation, fixing, review, refactoring, troubleshooting, verification, documentation changes, or needs to determine a solution from existing code; single‑command, pure conceptual explanations, or one‑step Q&A that does not require repository context need not be used.
