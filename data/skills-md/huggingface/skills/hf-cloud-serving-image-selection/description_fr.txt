Choisissez le bon conteneur de service pour un déploiement de modèle SageMaker et recherchez son URI d'image actuel. Utilisez cette compétence chaque fois que vous êtes sur le point de déployer un modèle sur un point de terminaison SageMaker et qu'un URI d'image doit être choisi, y compris lorsque l'utilisateur dit « déployer ce LLM », « héberger ce modèle HuggingFace », « servir ce modèle affiné », « déployer ce modèle d'intégration », « héberger un reranker », « servir un modèle de transformation de phrases » ou lorsque vous êtes sur le point de coder en dur n'importe quel URI de conteneur dans le code de déploiement. Les conteneurs d'apprentissage profond organisés par HuggingFace sont TOUJOURS préférés : HuggingFace vLLM (LLM et rerankers génératifs), HuggingFace vLLM-Omni (multimodal), TEI (embeddings/rerankers d'encodeurs croisés), HF Inference Toolkit (autres transformateurs). Les images génériques (AWS vLLM, DJL-LMI, SGLang) ne sont utilisées que lorsqu'aucune image HuggingFace n'est compatible, jamais simplement parce qu'elles contiennent une version plus récente. Ne codez jamais en dur un URI de conteneur à partir de la mémoire et ne définissez jamais par défaut la valeur TGI. Empêche les échecs d’images obsolètes et les URI de mauvaise région.
