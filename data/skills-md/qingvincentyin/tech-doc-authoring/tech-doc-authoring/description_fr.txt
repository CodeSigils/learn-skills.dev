Règles de création pour la rédaction et l'édition de la documentation technique Markdown — l'équivalent du tech-doc-consistency-check (qui audite les documents existants). Utilisez cette compétence chaque fois que vous écrivez ou modifiez un document Markdown, en particulier les documents du guide de l'utilisateur ("Infra Guide to GCP AI Agents.md", "DevOps Guide to agents-cli.md"), ou chaque fois que vous ajoutez un titre, une référence croisée de section (§X.Y), un lien, une image, une entrée de table des matières ou une ancre HTML en ligne. Déclenchez sur : « écrire cette section », « ajouter un titre », « créer un lien vers la section X », « croiser l'autre guide », « ajouter une ancre », « insérer une image », « éditer le doc ». Couvre les règles d'enveloppement dur, la construction de liens in-doc et cross-doc, les ancres de slug GFM, les ancres sans titre et d'image, les références de figure/diagramme/tableau d'hyperliens, les liens croisés bidirectionnels, les en-têtes de casse de titre, la numérotation des en-têtes frères et sœurs, la tolérance de préambule de section vide, l'énumération liste/inline, l'économie de couleur et de palette de diagramme sans danger pour les daltoniens, la fragilité des références avancées et l'impression jolie d'une chaîne JSON intégrée. Ne l'utilisez PAS pour auditer un document terminé (utilisez tech-doc-consistency-check) ou pour un style de prose général (qui reste dans le CLAUDE.md global de l'utilisateur).
