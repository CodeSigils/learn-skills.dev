Consulte openai/gpt-5.4 (u otro modelo) a través de OpenCode CLI para obtener una segunda opinión. Admite preguntas únicas, sesiones de diálogo de varios turnos y consultas con agentes de BMAD. Utilice esta habilidad DE FORMA PROACTIVA: no espere a que el usuario solicite explícitamente una segunda opinión. Actívelo al tomar decisiones arquitectónicas o compensaciones de diseño, cuando el usuario parezca inseguro acerca de un enfoque, durante una depuración compleja donde sería útil una nueva perspectiva, al revisar rutas de código críticas (seguridad, integridad de datos, concurrencia), cuando hay múltiples soluciones válidas y la mejor opción no está clara, o al validar decisiones técnicas importantes antes de la implementación. Incluso si el usuario no menciona una "segunda opinión" o "GPT", invoque esta habilidad siempre que una perspectiva externa pueda mejorar materialmente el resultado, especialmente para decisiones irreversibles como el diseño de esquemas, contratos de API o elecciones de arquitectura. Utiliza el indicador --variant para hacer coincidir el esfuerzo de razonamiento con la complejidad de la tarea (xhigh para arquitectura, low para comprobaciones rápidas).
