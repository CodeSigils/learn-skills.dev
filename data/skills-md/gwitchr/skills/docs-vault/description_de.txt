Erstellen Sie einen Obsidian-Tresor mit Projektdokumenten, die von Menschen und LLMs auf die gleiche Weise gelesen werden, acht flache Top-Level-Domain-Dokumente (PRODUCT/RUNTIME/ARCHITECTURE/DATA/AUTH/ENGINEERING/TESTING/DESIGN) über tiefe Spezifikationen auf Ordnerebene, einen einzigen Einstiegspunkt, bidirektionale Wikilinks, die ein echtes Abhängigkeitsdiagramm bilden, und eine „DESIGN.md“, die mit Tokens der google-labs-code/design.md-Spezifikation entspricht abgeleitet aus den vorhandenen Designquellen des Projekts. Die progressive Offenlegung regelt den Tresor (jede Ebene enthält eine Zusammenfassung und verknüpft eine Ebene tiefer, sodass ein Agent nur den Kontext lädt, den seine Aufgabe benötigt). Die Struktur wird skizziert, bevor Prosa geschrieben wird. Links dürfen nur auf vorhandene Dateien verweisen. In einem zweiten Durchgang werden Budgets und Links überprüft. Verwenden Sie diese Option, wenn Sie aufgefordert werden, „Projektdokumente einzurichten“, „Projektdokumentation zu schreiben“, „einen Obsidian-Tresor aus diesem Repo zu erstellen“, „diese Codebasis für Agenten zu dokumentieren“, „eine DESIGN.md hinzuzufügen“ oder „das Designsystem maschinenlesbar zu machen“.
