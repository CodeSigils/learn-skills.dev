Leitfaden für Microsoft Entra-Workload-Identitäten – verwaltete Identitäten, Dienstprinzipale und Workload-Identitätsverbund. Deckt vom System zugewiesene vs. vom Benutzer zugewiesene verwaltete Identität, föderierte Anmeldeinformationen (GitHub Actions, Azure DevOps, Kubernetes, andere OIDC-Herausgeber) zur Eliminierung von Geheimnissen, Workload Identities Premium (bedingter Zugriff für Workloads, Risikoerkennung, Lebenszyklusüberprüfungen), Anmeldeinformationshygiene (keine Clientgeheimnisse, wenn die Föderation funktioniert), RBAC mit geringsten Berechtigungen und Integration mit Defender für Cloud/Microsoft Entra Permissions Management ab. WANN: verwaltete Identität, vom System zugewiesene Identität, vom Benutzer zugewiesene Identität, Dienstprinzipalhärtung, Workload-Identitätsföderation, GitHub OIDC zu Azure, Azure DevOps OIDC, AKS-Workload-Identität, Clientgeheimnisse töten, föderierte Anmeldeinformationen, Workload Identities Premium, bedingter Zugriff für Workloads, nicht-menschliche Identitätsgovernance, NHI, App-Registrierungshärtung. NICHT für Benutzer-/Menschenidentität (verwenden Sie entra-id), Berechtigungserkennung über Clouds (verwenden Sie entra-permissions-management) oder durchgängige NHI-Governance (verwenden Sie agent-identity-governance) verwenden.
