Guía para identidades de cargas de trabajo de Microsoft Entra: identidades administradas, entidades de servicio y federación de identidades de cargas de trabajo. Cubre identidad administrada asignada por el sistema versus asignada por el usuario, credenciales federadas (GitHub Actions, Azure DevOps, Kubernetes, otros emisores de OIDC) para eliminar secretos, Workload Identities Premium (acceso condicional para cargas de trabajo, detección de riesgos, revisiones del ciclo de vida), higiene de credenciales (sin secretos de cliente donde funciona la federación), RBAC con privilegios mínimos e integración con Defender for Cloud/Microsoft Entra Permissions Management. CUÁNDO: identidad administrada, identidad asignada por el sistema, identidad asignada por el usuario, protección de la entidad de servicio, federación de identidades de cargas de trabajo, OIDC de GitHub para Azure, OIDC de Azure DevOps, identidad de cargas de trabajo de AKS, eliminación de secretos de clientes, credencial federada, identidades de cargas de trabajo Premium, acceso condicional para cargas de trabajo, gobernanza de identidades no humanas, NHI, protección del registro de aplicaciones. NO UTILIZAR para identidad de usuario/humano (use entra-id), descubrimiento de permisos a través de nubes (use entra-permissions-management) o gobernanza NHI de extremo a extremo (use agente-identity-governance).
