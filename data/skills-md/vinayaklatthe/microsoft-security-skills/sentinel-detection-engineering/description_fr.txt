Conseils pour l’ingénierie de détection dans Microsoft Sentinel : création, test, déploiement et maintenance de règles d’analyse, recherche de requêtes et automatisation SOAR. Couvre le modèle de solution Content Hub, le mappage MITRE ATT&CK, les analyses planifiées vs quasi-temps réel (NRT) vs Fusion vs anomalies, les modèles de détection KQL (jointures, résumés, bin, matérialisation), le mappage d'entités et l'enrichissement des incidents, les détections personnalisées de Defender XDR vs Sentinel uniquement, les règles d'automatisation, les playbooks (Logic Apps), les listes de surveillance, la correspondance des informations sur les menaces, le contenu en tant que code avec l'intégration des référentiels Azure DevOps / GitHub et le cycle de vie de la détection (valider → régler → version). QUAND : règle d'analyse Sentinel, détection KQL, mappage MITRE, hub de contenu Sentinel, analyses planifiées, règle NRT, requête de chasse, règle d'automatisation Sentinel, playbook Logic App, détection personnalisée, référentiels Sentinel CI/CD, détection en tant que code, liste de surveillance, analyses de correspondance d'informations sur les menaces, alertes de fusion, anomalies, enrichissement des incidents, cartographie des entités. NE PAS UTILISER pour l'architecture/l'intégration Sentinel (utiliser Sentinel), les détections personnalisées Defender XDR uniquement (chevauchement : utilisez le côté qui possède les données) ou la formation KQL générique.
