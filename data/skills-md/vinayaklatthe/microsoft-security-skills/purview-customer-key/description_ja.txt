Microsoft Purview 顧客キーおよび二重キー暗号化 (DKE) に関するガイダンス — サービス側データの顧客制御暗号化 (Exchange/SharePoint/OneDrive/Teams/Purview の顧客キー) および機密性の高いドキュメントのクライアント側二重暗号化 (機密ラベルと顧客ホスト型キー サービスによる DKE)。 Azure Key Vault のセットアップ (HSM ベース、回復可能、論理的な削除、パージ保護、冗長リージョン)、M365 サービスのデータ暗号化ポリシー (DEP)、キーのローテーションと取り消し、DKE サービスの展開 (コンテナー化されたキー リリース サービス)、DKE ラベルの作成、エンド ユーザー エクスペリエンスのトレードオフ (DKE コンテンツへの電子情報開示なし)、および Microsoft 管理の暗号化に対する意思決定基準について説明します。時期: 顧客キー M365、BYOK Exchange、DKE Microsoft、二重キー暗号化、顧客管理キー SharePoint OneDrive Teams、キー ローテーション顧客キー、HYOK 代替、主権暗号化、規制当局が管理する暗号化、機密ラベル DKE。 Azure リソース CMK (azure-key-vault を使用)、一般的な機密ラベル (purview-information-governance を使用)、または非暗号化コンプライアンス (compliance-manager を使用) には使用しないでください。
