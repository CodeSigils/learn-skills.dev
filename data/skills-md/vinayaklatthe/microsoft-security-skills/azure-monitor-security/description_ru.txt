Руководство по использованию Azure Monitor и Log Analytics со стороны безопасности — разработка стратегии рабочей области, которая обеспечивает Microsoft Sentinel и Defender для облака, выбор аналитики вместо базового и вспомогательного уровней журналов, хранение и архивирование, преобразования на уровне таблиц для снижения предварительного приема шума, правила сбора данных (DCR) и агент Azure Monitor (AMA), топология рабочей области (единая, региональная или суверенная), уровни обязательств и контроль затрат, ключи, управляемые клиентом для рабочей области, включая RBAC RBAC на уровне таблицы, интеграция с Sentinel (требования к рабочему пространству) и вывод из эксплуатации устаревшего MMA. КОГДА: проектирование рабочей области Log Analytics, данные безопасности Azure Monitor, рабочая область Sentinel, базовый вспомогательный уровень уровня журнала, агент AMA Azure Monitor, правило сбора данных DCR, преобразование приема столбцов удаления, архив хранения журналов, рабочая область CMK, RBAC на уровне таблицы, контроль затрат на прием журналов. НЕ ИСПОЛЬЗУЙТЕ для разработки средств обнаружения Sentinel (используйте Sentinel-detection-engineering), инструментов App Insights (используйте appinsights-tools) или наблюдения, не связанного с безопасностью.
