Anleitung für die sicherheitsseitige Verwendung von Azure Monitor und Log Analytics – Entwerfen der Arbeitsbereichsstrategie, die Microsoft Sentinel und Defender für Cloud speist, Auswahl von Analysen vs. grundlegender vs. zusätzlicher Protokollebenen, Aufbewahrung und Archivierung, Transformationen auf Tabellenebene, um Rauschen vor der Aufnahme zu vermeiden, Datenerfassungsregeln (DCRs) und Azure Monitor Agent (AMA), Arbeitsbereichstopologie (einzeln vs. regional vs. souverän), Verpflichtungsebenen und Kostenkontrolle, vom Kunden verwaltete Schlüssel für den Arbeitsbereich, RBAC einschließlich Tabellenebene RBAC, Integration mit Sentinel (Arbeitsbereichsanforderungen) und Außerbetriebnahme von Legacy-MMA. WANN: Log Analytics-Arbeitsbereichsdesign, Azure Monitor-Sicherheitsdaten, Sentinel-Arbeitsbereich, grundlegende Hilfsfunktion für die Protokollebene, AMA Azure Monitor-Agent, DCR-Datenerfassungsregel, Transformation zur Erfassung von Drop-Spalten, Protokollaufbewahrungsarchiv, Arbeitsbereichs-CMK, RBAC auf Tabellenebene, Kostenkontrolle für die Protokollerfassung. NICHT für die Sentinel-Erkennungserstellung (verwenden Sie sentinel-detection-engineering), die App Insights-Instrumentierung (verwenden Sie appinsights-instrumentation) oder nicht sicherheitsrelevante Beobachtbarkeit verwenden.
