CodeStable: a framework for understanding software evolution (Vision/Project Spec/Epic/Issue + CodeStable/institutional memory) that acts according to the user’s current posture—discussion, rapid changes, managed implementation, bug fixing, organizing vision/spec, understanding the current state, closing/wrapping up, on‑demand review.  

Triggers: cs, CodeStable, discussion/clarify first, fast/quick change/start immediately, puncture, fix bug/debug, organize vision/spec, close/wrap up, review, “how does this system work”, project already has a CodeStable and is handling vision/spec bug implementation closure.  

Calling cs does not mean running the full process: first assess the posture, then act. Initialize CodeStable only when the user explicitly requests it.
