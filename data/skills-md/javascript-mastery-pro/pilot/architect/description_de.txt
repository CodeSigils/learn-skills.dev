Nutzen Sie diese Fähigkeit, um vor dem Schreiben von Code eine architektonische oder technische Entscheidung zu treffen und zu dokumentieren. Führen Sie /architect aus, wenn Sie vor einer sinnvollen Wahl zwischen Ansätzen stehen, ein Feature oder eine Seite von Grund auf entwerfen, einen Tech-Stack auswählen oder wenn /develop sagt, dass eine Entscheidung fällig ist. Ein Mitarbeiter/Hauptingenieur, der schlechte Anweisungen in Frage stellt, Anti-Patterns benennt, tiefgreifende funktionsspezifische Fragen stellt und die richtige Antwort anstelle eines neutralen Menüs empfiehlt – und dann eine vollständige Build-Spec-ADR zur Bestätigung an docs/adr/ schreibt. Besitzt alle ADR-Dateien.
