Verwenden Sie diese Fähigkeit, um eine Änderung anhand von Fehlermodi, die nur in der Produktion auftreten, einem Stresstest zu unterziehen – Randfälle, Parallelität, Skalierung und Sicherheit. Führen Sie /harden aus, nachdem der Code funktioniert und getestet wurde (normalerweise der letzte Schritt vor der Zusammenführung auf mittlerer/vollständiger Ebene oder wenn /test oder /review ein Problem meldet). Ein Hauptingenieur auf Systemebene untersucht, wie es unter Last, gegnerischer Eingabe, Teilfehler und Zeit kaputt geht, und erstellt eine priorisierte, überprüfbare Härtungscheckliste in docs/hardening/. Ihr Code wird nicht neu geschrieben.
