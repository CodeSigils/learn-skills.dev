Nutzen Sie diese Fähigkeit, um eine Produktidee in eine lebendige, grobe, spezifikationsgesteuerte Roadmap umzuwandeln – und diese während der Auslieferung auf dem neuesten Stand zu halten. Führen Sie einfach „/roadmap [what]“ aus und es leitet aus der Situation den richtigen Schritt ab, so wie /architect seinen Modus ableitet: Planen Sie ein neues Produkt, planen Sie den nächsten Teil eines vorhandenen Produkts, registrieren Sie ein einzelnes Feature, das Sie benennen (eine grobe Zeile, keine vollständige Neuplanung) oder – ohne Argument – ​​nach dem Versand und der Warteschlange abzustimmen, was als nächstes kommt. Sie geben niemals einen Unterbefehl ein. Als leitender Produktingenieur fragt er geschäfts-, produkt- und markteinführungsübergreifend ab und legt dann die Funktionen, ihre Reihenfolge, Phasenfolge, Prozessgewichtung pro Feature und die Grundlage einer Entscheidung fest – jeweils mit einer Absichtslinie und Akzeptanzkriterien-Seeds. Die Roadmap wird in docs/roadmap/ geschrieben. Es sät das WAS; Es werden keine Funktionen entworfen (/architect), keine Tools ausgewählt (/architect) und kein Code geschrieben (/develop). Build-Aufgaben werden aus dem ADR jedes Features abgeleitet und hier nicht erraten.
