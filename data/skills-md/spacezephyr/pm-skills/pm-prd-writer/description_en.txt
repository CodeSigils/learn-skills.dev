Transform vague requirements into a reviewable product requirement document (PRD). Use this skill when the user says “write a requirement document,” “help me create a PRD,” “how to write requirements for this feature,” “I have an idea I want to implement,” “organize this requirement into a document,” “PRD needed for requirement review,” or when the user describes a feature but it is not structured.

Also applicable: the user uploads raw requirement descriptions/meeting minutes/chat screenshots and asks to organize them into a PRD; the user mentions keywords such as “PRD,” “product requirements,” “requirement document,” “functional specification”; the user requests to supplement, optimize, or fill gaps in an existing PRD.

Not applicable: pure technical solution design (use architecture), pure UI mockup annotation (use design‑handoff), project‑management documents (use status‑report).
