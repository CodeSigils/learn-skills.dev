Wandeln Sie vage Anforderungen in ein überprüfbares Produktanforderungsdokument (PRD) um. Verwenden Sie diese Fähigkeit, wenn der Benutzer sagt: „Ein Anforderungsdokument schreiben“, „Helfen Sie mir, ein PRD zu erstellen“, „Wie schreibe ich Anforderungen für diese Funktion“, „Ich habe eine Idee, die ich umsetzen möchte“, „Organisieren Sie diese Anforderung in einem Dokument“, „PRD wird für die Anforderungsüberprüfung benötigt“ oder wenn der Benutzer eine Funktion beschreibt, diese jedoch nicht strukturiert ist.

Auch anwendbar: Der Benutzer lädt rohe Anforderungsbeschreibungen/Besprechungsprotokolle/Chat-Screenshots hoch und bittet darum, diese in einem PRD zu organisieren; Der Benutzer erwähnt Schlüsselwörter wie „PRD“, „Produktanforderungen“, „Anforderungsdokument“, „Funktionsspezifikation“; Der Benutzer fordert die Ergänzung, Optimierung oder das Füllen von Lücken in einem bestehenden PRD an.

Nicht anwendbar: reines technisches Lösungsdesign (Architektur verwenden), reine UI-Mockup-Annotation (Design-Übergabe verwenden), Projektmanagementdokumente (Statusbericht verwenden).
