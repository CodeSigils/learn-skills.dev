QBV / quant-buddy-view (users may write it as /quant-buddy-view, /qbv, qbv or QBV) is used to turn quantitative data into a “publicly shareable, real‑time data‑fetching” web dashboard/landing page.  

Use this skill whenever the user asks to create, update, publish, verify, retrofit, or reuse a Quant Buddy dashboard/static page/template, including shareable pages, public URLs, formula packages, share shells, cover/essence cards, poster/share behavior, single‑stock profile pages, valuation/financial profile pages, index‑anomaly boards, multi‑factor screeners, and commodity‑daily pages.  

When working together with quant‑buddy‑skill: a simple, single‑stock A‑share comprehensive analysis can, after `trace begin`, be returned as a real‑time page directly with `static_page.py new_asset_page`; if the user supplies an existing QuantBuddy live‑page URL and asks for interpretation, use `static_page.py interpret` to read the page’s real‑time data without downloading HTML, exposing signatures, or entering the templating or page‑building workflow; other fixed‑page requests should first select an online template page marked with the `recommend` tag via `templates/template`. For self‑built real‑time pages, first choose the channel according to data type: ordinary market data, valuation, and financial data prioritize a Data Grant; custom calculations must be validated and registered as a Formula Package. Both types of credentials can be mixed on the same page, after which you replace credentials/text, perform browser acceptance testing, and publish. By default, do not start from local historical sample directories or low‑quality HTML skeletons.  

If the user explicitly invokes /quant‑buddy‑view, /qbv, qbv or QBV and the request is not pure consultation/code maintenance/documentation explanation, treat it as a shareable live‑page task by default: a simple, single‑stock A‑share analysis proceeds with `new_asset_page` for a quick final result; other requests are checked against official curated + community template cards to determine `direct`/`fork`/`unmatched`. By default, `direct` delivers an existing link first, while `fork`/`unmatched` return the first link via `new_page`. When `config.json._channel=feishu-group`, all branches are prohibited from sending links prematurely; links are delivered only at the final stage as a playground link.  

Do not use this skill for one‑off market queries, ordinary stock price‑change/valuation Q&A, stock‑selection/back‑testing exploration; those belong to quant‑buddy‑skill unless the user explicitly wants a reusable/shareable page.
