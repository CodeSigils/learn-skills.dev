QBV / quant-buddy-view (users may write it as /quant-buddy-view, /qbv, qbv, or QBV) is used to turn quantitative data into public, shareable, real-time web dashboards/landing pages.

Use this skill when the user asks to create, update, publish, verify, retrofit, or reuse a Quant Buddy dashboard/static page/template, including shareable pages, public URLs, formula packages, share shell, cover/essence cards, poster/share behavior, single-stock profile pages, valuation/financial profile pages, index-anomaly boards, multi-factor screeners, and commodity daily pages.

When used together with quant-buddy-skill: a simple, single A-share comprehensive analysis can, after `trace begin`, directly use `static_page.py new_asset_page` to return a real-time page; if the user provides an existing QuantBuddy live page URL and asks for interpretation, directly use `static_page.py interpret` to read the page’s real-time data without downloading HTML, exposing signatures, or entering the template or page-creation workflow; other fixed-page requests should first select an online template page with a `recommend` tag via `templates/template`. For building a custom real-time page, first choose the channel according to data nature: normal market data, valuation, and financial data default to Data Grant, while custom calculations must be validated and registered as a Formula Package; the two types of credentials can be mixed on the same page, after which you replace credentials/text, perform browser acceptance testing, and publish. By default, do not start from a local historical sample directory or a low-quality HTML skeleton.

When the user explicitly invokes /quant-buddy-view, /qbv, qbv, or QBV, and the request is not purely a consultation/code-maintenance/documentation explanation, it is by default treated as a shareable live-page task: a simple, single A-share analysis proceeds via `new_asset_page` for a quick final state; other requests are checked against official selections and community template cards to determine `direct`/`fork`/`unmatched`. By default, `direct` first delivers an existing link, while `fork`/`unmatched` use `new_page` to return the first link; when `config.json._channel=feishu-group`, all branches are prohibited from sending links in advance and only deliver a playground link at the final stage.

Do not use this skill for one-off market queries, ordinary stock price-change/valuation Q&A, stock-picking/backtesting exploration; those belong to quant-buddy-skill unless the user explicitly wants a reusable/shareable page.
