QBV / quant-buddy-view (пользователи могут писать его как /quant-buddy-view, /qbv, qbv или QBV) используется для преобразования количественных данных в публично доступную, в реальном времени получаемую веб‑панель/целевую страницу.

Используйте этот навык, когда пользователь просит создать, обновить, опубликовать, проверить, доработать или повторно использовать панель Quant Buddy/статическую страницу/шаблон, включая общедоступные страницы, публичные URL, пакеты формул, оболочку для совместного использования, обложки/карточки‑сущности, плакаты/поведение при шаринге, страницы профилей отдельного актива, страницы оценки/финансового профиля, доски аномалий индексов, многофакторные скринеры и ежедневные страницы по товарным активам.

Используется совместно с quant-buddy-skill: простейший, однопозиционный A‑share комплексный анализ может, после `trace begin`, сразу вернуть страницу в реальном времени с помощью `static_page.py new_asset_page`; когда пользователь предоставляет URL существующей живой страницы QuantBuddy и просит интерпретацию, напрямую используйте `static_page.py interpret` для чтения данных этой страницы в реальном времени, без скачивания HTML, раскрытия подписей или входа в процесс шаблона/создания страницы; другие запросы на фиксированные страницы должны сначала выбрать онлайн‑шаблон со ссылкой `recommend` через `templates/template`. Для самостоятельно построенных страниц в реальном времени сначала выбирайте канал в соответствии с типом данных: обычные рыночные данные, данные оценки и финансовые данные отдают приоритет Data Grant, тогда как пользовательские вычисления должны быть проверены и зарегистрированы как Пакет Формул; оба типа учётных данных могут смешиваться на одной странице, после чего заменяйте учётные данные/текст, проводите тестирование в браузере и публикуйте. По умолчанию не начинать с локального исторического каталога шаблонов или низкокачественного HTML‑скелета.

Когда пользователь явно вызывает /quant-buddy-view, /qbv, qbv или QBV, и запрос не является чистой консультацией/поддержкой кода/объяснением документации, он по умолчанию рассматривается как задача создания общедоступной живой страницы: простой однопозиционный A‑share анализ проходит через `new_asset_page` для быстрого финального состояния; другие запросы проверяют официальные精选 + карты шаблонов сообщества, чтобы определить direct/fork/unmatched. По умолчанию `direct` сначала предоставляет существующую ссылку, тогда как `fork`/`unmatched` возвращают первую ссылку через `new_page`; когда `config.json._channel=feishu-group`, всем веткам запрещено отправлять ссылки заранее, и они предоставляют только ссылку на площадку в финальном этапе.

Не используйте этот навык для разовых рыночных запросов, обычных вопросов‑ответов по изменению цены/оценке акций, выбора акций/исследования бэктестов; такие запросы относятся к quant-buddy-skill, если только пользователь явно не хочет создать переиспользуемую/общедоступную страницу.

Пожалуйста, всегда отвечайте на языке пользователя.
