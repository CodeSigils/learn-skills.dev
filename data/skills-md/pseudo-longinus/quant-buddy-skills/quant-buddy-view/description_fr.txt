QBV / quant-buddy-view (les utilisateurs peuvent l’écrire sous la forme /quant-buddy-view, /qbv, qbv ou QBV) sert à transformer des données quantitatives en un tableau de bord / page d’atterrissage web « partageable publiquement, récupérant les données en temps réel ».  

Utilisez cette compétence chaque fois que l’utilisateur demande de créer, mettre à jour, publier, vérifier, retrofiter ou réutiliser un tableau de bord / page statique / modèle Quant Buddy, y compris les pages partageables, les URL publiques, les paquets de formules, les shells de partage, les cartes de couverture / d’essence, le comportement d’affichage / partage, les pages de profil d’action individuelle, les pages de profil d’évaluation / financier, les tableaux d’anomalies d’indices, les screeneurs multifactoriels et les pages quotidiennes de marchandises.  

Lorsque vous travaillez en collaboration avec quant‑buddy‑skill : une analyse complète simple d’une action A‑share unique peut, après `trace begin`, être renvoyée comme page en temps réel directement avec `static_page.py new_asset_page` ; si l’utilisateur fournit une URL de page en direct QuantBuddy existante et demande une interprétation, utilisez `static_page.py interpret` pour lire les données en temps réel de la page sans télécharger le HTML, exposer les signatures ou entrer dans le flux de travail de templating ou de construction de page ; les autres demandes de pages fixes doivent d’abord sélectionner une page modèle en ligne marquée du tag `recommend` via `templates/template`. Pour les pages en temps réel auto‑construites, choisissez d’abord le canal selon le type de données : les données de marché ordinaires, d’évaluation et financières privilégient un Data Grant ; les calculs personnalisés doivent être validés et enregistrés comme un Package de Formule. Les deux types d’identifiants peuvent être mélangés sur la même page, après quoi vous remplacez les identifiants / texte, effectuez des tests d’acceptation de navigateur et publiez. Par défaut, ne partez pas des répertoires d’échantillons historiques locaux ou de squelettes HTML de mauvaise qualité.  

Si l’utilisateur invoque explicitement /quant‑buddy‑view, /qbv, qbv ou QBV et que la requête n’est pas une simple consultation / maintenance de code / explication de documentation, considérez‑la par défaut comme une tâche de page en direct partageable : une analyse simple d’une action A‑share unique se poursuit avec `new_asset_page` pour un résultat final rapide ; les autres requêtes sont comparées aux cartes modèles officielles + communautaires pour déterminer `direct`/`fork`/`unmatched`. Par défaut, `direct` fournit d’abord un lien existant, tandis que `fork`/`unmatched` renvoient le premier lien via `new_page`. Lorsque `config.json._channel=feishu-group`, toutes les branches sont interdites d’envoyer des liens prématurément ; les liens ne sont livrés qu’à l’étape finale sous forme de lien de terrain de jeu.  

N’utilisez pas cette compétence pour des requêtes de marché ponctuelles, des Q&R ordinaires sur les variations de prix / évaluations d’actions, ou l’exploration de sélection d’actions / back‑testing ; cela relève de quant‑buddy‑skill à moins que l’utilisateur ne souhaite explicitement une page réutilisable / partageable.  

Veuillez toujours répondre dans la langue de l’utilisateur.
