QBV / quant-buddy-view (users may write it as /quant-buddy-view, /qbv, qbv, or QBV) is used to turn quantitative data into publicly shareable, real‑time data‑retrievable web dashboards/landing pages.  
Use this skill when the user asks to create, update, publish, verify, retrofit, or reuse a Quant Buddy dashboard/static page/template, including shareable pages, public URLs, formula packages, share shell, cover/essence cards, poster/share behavior, single‑stock profile pages, valuation/financial profile pages, index‑anomaly boards, multi‑factor screeners, and commodity daily pages.  
Use together with quant-buddy-skill: a simple single A‑share comprehensive analysis can, after a trace begin, directly return a real‑time page by using static_page.py new_asset_page; other requests for fixed pages should first select an online template page with a “recommend” tag from templates/template. For self‑built real‑time pages, you still need to first validate the formula in quant-buddy-skill, then register your own formula package, replace credentials/text, perform browser acceptance testing, and publish. By default, do not start from local historical sample directories or low‑quality HTML skeletons.  
When the user explicitly invokes /quant-buddy-view, /qbv, qbv, or QBV, and the request is not pure consultation/code maintenance/documentation explanation, it is by default treated as a shareable live‑page task: a simple single A‑share analysis goes through new_asset_page for a fast final state; other requests consult the official精选+community template cards to determine direct/fork/unmatched. By default, direct delivers an existing link first, while fork/unmatched return the first link via new_page; when config.json._channel=feishu-group, all branches are prohibited from sending links in advance, and only the playground link is delivered at the final stage.  
Do not use this skill for one‑off market data queries, ordinary stock price change/valuation Q&A, stock‑selection/back‑testing exploration; those belong to quant-buddy-skill unless the user explicitly wants a reusable/shareable page.
