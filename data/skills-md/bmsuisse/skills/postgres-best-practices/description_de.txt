PostgreSQL-Codierungsstandards für Python-Projekte mit psycopg (kein ORM). Verwenden Sie diese Fähigkeit immer dann, wenn der Benutzer Code schreibt oder überprüft, der PostgreSQL mit psycopg abfragt, SQL-Dateien erstellt, Abfrageergebnisse Python-Objekten zuordnet oder fragt, wie Datenbankzugriffscode strukturiert werden soll. Löst Dinge aus wie „eine Datenbankabfrage hinzufügen“, „eine SQL-Abfrage schreiben“, „ein Repository erstellen“, „aus Postgres abrufen“, „in die Datenbank einfügen“, „die Datenbank aktualisieren“, „parametrisierte Abfrage“, „pydantisches Modell aus DB-Zeile“, „SQL-Datei“, „dynamisches SQL“ oder jede Erwähnung von psycopg, psycopg2, asyncpg oder SQLAlchemy, bei der der Benutzer für einen anderen Ansatz offen zu sein scheint. Verwenden Sie es auch, wenn der Benutzer nach Verbindungspooling, Transaktionen, Cursor-Factorys oder der Organisation von Datenbankcode fragt.
