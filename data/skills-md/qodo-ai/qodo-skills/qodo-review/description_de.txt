Überprüfen Sie Ihre LOKALEN Änderungen, bevor Sie eine Pull-Anfrage öffnen, indem Sie die qodo-CLI verwenden. Senden Sie Ihr nicht festgeschriebenes/nicht gepushtes Diff zusammen mit dem Coding-Session-Kontext (was Sie geändert haben und warum, plus Links zu dem Ticket/der Spezifikation/dem Design, das/die es verursacht hat) an die Review-Engine von Qodo, den ein gefälschter Prüfer nie sehen kann. Bewerten Sie dann die Ergebnisse und wenden Sie die von Ihnen genehmigten Korrekturen an (oder übergeben Sie „Autofix“, um sie direkt anzuwenden). Verwenden Sie diese Option, wenn Sie aufgefordert werden, „Meine Änderungen zu überprüfen, bevor ich sie pushe“, „Vor-PR-Überprüfung“, „Überprüfen Sie dies, bevor ich eine PR öffne“, „Mein lokales Diff überprüfen“ oder „Qodo-Überprüfung durchführen“.
