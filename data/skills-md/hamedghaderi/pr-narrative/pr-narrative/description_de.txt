PR-Fähigkeit mit zwei Modi. **Autorenmodus** schreibt Pull-Request-Beschreibungen, die sich wie eine Erklärung und nicht wie ein Code-Dump lesen. Verwenden Sie es, wenn der Benutzer eine PR-Beschreibung/einen PR-Körper/einen PR-Beitrag schreiben, entwerfen, generieren oder verbessern möchte oder sagt: „Schreiben Sie die PR“, „erstellen Sie eine PR-Beschreibung für diesen Zweig“, „beschreiben Sie diese Änderungen zur Überprüfung“. **Rezensentenmodus** stellt alle PR-Diffs als annotierbare Seite dar: Klicken Sie zum Kommentieren von Zeilen, optionale von der KI erstellte Risikohinweise, die Sie selektieren, und veröffentlichen Sie akzeptierte Kommentare als AUSSTEHENDE GitHub-Überprüfung, die der Benutzer abschließt. Verwenden Sie es, wenn der Benutzer sagt: „Überprüfen Sie diese PR <URL>“, „Überprüfen Sie PR #N“, „Kommentieren Sie diese PR“ oder „Überprüfen Sie meinen Zweig/meine Änderungen“. Bestätigen Sie den Modus zunächst mit einer Frage, sofern der Benutzer sie nicht bereits benannt hat. Unterstützt auch Unterbefehle: „explain“ (erklärt einen Unterschied im Chat), „review-security“ (Rezensentenmodus, reine Sicherheits-KI-Ergebnisse), „summarize-changes“ (schnelle Chat-Zusammenfassung); Ein expliziter Unterbefehl überspringt die Modusfrage. NICHT für Code-Review-Scoring, Commit-Nachrichten oder Versionshinweise verwenden.
