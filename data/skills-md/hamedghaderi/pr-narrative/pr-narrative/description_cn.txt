两种模式的公关技巧。 **作者模式** 编写拉取请求描述，读起来像解释器，而不是代码转储。当用户要求编写、起草、生成或改进 PR 描述/PR 正文/PR 文章，或说“编写 PR”、“为此分支制作 PR 描述”、“描述这些更改以供审核”时，请使用它。 **审阅者模式** 将任何 PR 的差异呈现为可注释页面：在行上单击评论、您分类的可选 AI 起草的风险标注，并在用户最终确定的 PENDING GitHub 审阅时发布已接受的评论。当用户说“查看此 PR <url>”、“查看 PR #N”、“注释此 PR”或“查看我的分支/更改”时使用它。除非用户已经命名，否则首先通过一个问题确认模式。还支持子命令：“explain”（解释聊天中的差异）、“review-security”（审阅者模式、仅安全的 AI 结果）、“summarize-changes”（快速聊天摘要）；显式子命令会跳过模式问题。请勿用于代码审查评分、提交消息或发行说明。
