兩種模式的公關技巧。 **作者模式** 編寫拉取請求描述，讀起來像解釋器，而不是程式碼轉儲。當使用者要求編寫、起草、產生或改進 PR 描述/PR 正文/PR 文章，或說「編寫 PR」、「為此分支製作 PR 描述」、「描述這些變更以供審核」時，請使用它。 **審閱者模式** 將任何 PR 的差異呈現為可註釋頁面：在行上按評論、您分類的可選 AI 起草的風險標註，並在用戶最終確定的 PENDING GitHub 審閱時發布已接受的評論。當用戶說“查看此 PR <url>”、“查看 PR #N”、“註釋此 PR”或“查看我的分支/更改”時使用它。除非用戶已經命名，否則首先透過一個問題確認模式。也支援子指令：「explain」（解釋聊天中的差異）、「review-security」（審閱者模式、僅安全的 AI 結果）、「summarize-changes」（快速聊天摘要）；顯式子指令會跳過模式問題。請勿用於代碼審查評分、提交訊息或發行說明。
