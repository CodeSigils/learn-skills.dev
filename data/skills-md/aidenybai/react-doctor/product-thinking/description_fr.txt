Pensez comme un chef de produit avant de modifier la surface publique de React Doctor : commandes/indicateurs CLI, score de 0 à 100, configuration (doctor.config.*), schéma de rapport JSON, API de package (inspect()/diagnose()), action GitHub, site Web et invites canoniques. Un runbook étape par étape pour une modification destinée à l'utilisateur : localisez la surface, recherchez un candidat à la réutilisation, câblez une métrique de télémétrie, ajoutez les artefacts de compatibilité (changeset / schemaVersion / balise d'action), mettez à jour les documents et enregistrez une métrique de suppression. Pas pour les règles anti-peluches, qui ont leur propre pipeline. S'exécute également lorsque l'utilisateur tape « /product-thinking ».
