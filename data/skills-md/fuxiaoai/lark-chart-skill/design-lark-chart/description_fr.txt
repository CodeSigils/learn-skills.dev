Lorsque l'utilisateur demande l'un des types tels que « diagramme d'architecture / organigramme / diagramme à couloirs / diagramme de séquence / organigramme / machine d'état / entonnoir / Gantt / jalon / quadrant matriciel / architecture de liens / architecture de style dessiné à la main / diagramme à couloirs d'affaires complexe / diagramme ER / carte mentale » et souhaite qu'il soit implémenté dans Feishu, ou fournit une URL de document Feishu et demande de dessiner un diagramme à l'intérieur, ou dit « synchroniser avec Feishu / écrire sur le tableau Feishu », cette compétence doit être utilisée. En plus des 17 modèles intégrés ci-dessus, cette compétence offre également un « mode de dessin libre (dessin de forme libre) » : lorsque l'utilisateur demande à créer une peinture à l'huile / une illustration dessinée à la main / un prototype d'application mobile / une carte / un écran de jeu / un diagramme de Sankey / toute recréation d'image de référence que les modèles ne couvrent pas, ou dit explicitement « dessin libre / création libre / ne pas utiliser de modèle », cette compétence doit également être utilisée (le résultat reste un tableau Feishu modifiable). Le pipeline de génération suit strictement huit étapes : Normaliser → Sélectionner → Plan → Mise en page → Rendu → StaticCheck → VQA → Livrer ; les modèles de codage en dur, les coordonnées de codage en dur ou la fabrication de contenu professionnel non mentionné par l'utilisateur sont interdits. Tous les styles sont lus à partir d'assets/style‑tokens/ (à l'exception des diagrammes natifs de code et du mode de dessin libre). Avant la livraison, il doit passer le contrôle de qualité (exécuté selon le routage) et un examen visuel par double évaluateur (si un score est inférieur à 9 ou si un bloqueur apparaît, il échoue).
