Wenn ein Benutzer einen der folgenden Typen anfordert – Architekturdiagramm, Flussdiagramm, Swimlane-Diagramm, Sequenzdiagramm, Organigramm, Zustandsmaschine, Trichter, Gantt-Diagramm, Meilenstein, Matrixquadranten, Linkarchitektur, Architektur im handgezeichneten Stil, komplexes Business-Swimlane-Diagramm, ER-Diagramm oder Mindmap – und möchte, dass er in Feishu implementiert wird, oder eine Feishu-Dokument-URL angibt und darum bittet, darin ein Diagramm zu zeichnen, oder sagt „Mit Feishu synchronisieren / auf Feishu-Whiteboard schreiben“, Diese Fähigkeit muss genutzt werden. Zusätzlich zu den oben erwähnten 17 integrierten Vorlagen bietet diese Funktion auch einen „Freiform-Zeichenmodus“: Wenn ein Benutzer ein Ölgemälde, eine handgezeichnete Illustration, einen Prototyp einer mobilen App, eine Karte, einen Spielbildschirm, ein Sankey-Diagramm oder eine Referenzbildnachbildung erstellen möchte, die in den Vorlagen nicht abgedeckt ist, oder ausdrücklich „Freies Zeichnen / wild werden / keine Vorlage verwenden“ sagt, muss dieselbe Funktion verwendet werden (die Ausgabe bleibt ein bearbeitbares Feishu-Whiteboard). Die Generierungspipeline muss die acht Schritte strikt befolgen: Normalisieren → Auswählen → Planen → Layout → Rendern → StaticCheck → VQA → Liefern. Das Festkodieren von Vorlagen, das Festkodieren von Koordinaten oder das Fälschen von Geschäftsinhalten, die nicht vom Benutzer erwähnt werden, ist verboten. Alle Stile werden aus Assets/Style-Tokens/ gelesen (außer native Codediagramme und Freiformmodus). Vor der Übermittlung muss das Ergebnis das Qualitätstor (durchgeführt gemäß Routing) und eine visuelle Überprüfung durch zwei Prüfer bestehen (jede Punktzahl unter 9 oder jeder Blocker führt zu einem Fehler).
