Cuando un usuario solicita cualquiera de los siguientes tipos (diagrama de arquitectura, diagrama de flujo, diagrama de carriles, diagrama de secuencia, organigrama, máquina de estado, embudo, diagrama de Gantt, hito, cuadrante matricial, arquitectura de enlaces, arquitectura de estilo dibujado a mano, diagrama de carriles empresarial complejo, diagrama ER o mapa mental) y quiere implementarlo en Feishu, o proporciona una URL de documento de Feishu y solicita que se dibuje un diagrama dentro de él, o dice "sincronizar con Feishu/escribir en la pizarra de Feishu", esta capacidad debe ser usado. Además de las 17 plantillas integradas mencionadas anteriormente, esta capacidad también ofrece un “modo de dibujo de forma libre”: cuando un usuario solicita crear una pintura al óleo, una ilustración dibujada a mano, un prototipo de aplicación móvil, un mapa, una pantalla de juego, un diagrama de Sankey o cualquier recreación de imagen de referencia que las plantillas no cubren, o dice explícitamente “dibujo libre / vuélvete loco / no uses una plantilla”, se debe usar la misma capacidad (el resultado sigue siendo una pizarra Feishu editable). El proceso de generación debe seguir estrictamente los ocho pasos: Normalizar → Seleccionar → Planificar → Diseño → Renderizar → StaticCheck → VQA → Entregar. Está prohibido codificar plantillas, codificar coordenadas o fabricar contenido comercial no mencionado por el usuario. Todos los estilos se leen desde activos/tokens de estilo/ (excepto los diagramas de código nativo y el modo de forma libre). Antes de la entrega, el resultado debe pasar el control de calidad (ejecutado según la ruta) y una verificación visual de doble revisor (cualquier puntuación inferior a 9 o cualquier bloqueo resulta en un fracaso).
