Verwenden Sie diese Option, wenn der Benutzer einen Rückstand an Entwicklungstickets durchgängig mit einem bekannten Projekt-, Zweig-, Zusammenführungsziel-, Aufgaben-Tracker- oder Design-Referenz-Workflow verarbeiten möchte, ohne sich jedoch auf eine bestimmte Plattform festzulegen (Jira / Linear / GitHub Issues / Notion / Figma / Zeplin / usw.). Trigger auf Anfragen wie „幫我跑任務“, „照我的流程把 Backlog 做完“ oder „Überprüfung fehlgeschlagen“.的全部處理掉」、「用我那套開發流程做事」、 „meine Aufgabenliste durcharbeiten“, „meine Entwicklungsschleife ausführen“, „meine Tickets durchgängig verarbeiten“. Fragt den Benutzer immer im Voraus nach dem Projektstamm, dem Arbeitszweig, dem Zusammenführungsziel, dem Speicherort der Aufgabenliste, dem Speicherort der Entwurfsreferenz und wie eine Aufgabe als erledigt markiert wird – und durchläuft dann die Tickets, indem er die Tickets implementiert → überprüft → festschreibt → PR öffnet → zusammenführt → synchronisiert → den Tracker aktualisiert. Backen Sie niemals plattformspezifische API-Aufrufe ein. Finden Sie diese zur Laufzeit anhand der Antworten des Benutzers heraus.
