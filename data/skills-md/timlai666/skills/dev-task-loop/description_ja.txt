ユーザーが、特定のプラットフォーム (Jira / Linear / GitHub Issues / Notion / Figma / Zeplin など) にコミットせずに、既知のプロジェクト / ブランチ / マージ ターゲット / タスク トラッカー / デザイン リファレンス ワークフローを使用して開発チケットのバックログをエンドツーエンドで処理したい場合に使用します。 「幫我跑手数料」、「照我的流程ハンドルバックログ実行完了」、「レビュー失敗の全部處理掉」、「用我那套開發流程事」、「タスクリストを実行する」、「開発ループを実行する」、「チケットをエンドツーエンドで処理する」などのリクエストをトリガーします。プロジェクトのルート、作業ブランチ、マージ ターゲット、タスク リストの場所、設計参照の場所、タスクを完了としてマークする方法を常にユーザーに事前に尋ねます。その後、チケットの実装→検証→コミット→PR を開く→マージ→同期→トラッカーの更新をループします。プラットフォーム固有の API 呼び出しを決して焼き付けないでください。ユーザーの回答から実行時にそれらを判断します。
