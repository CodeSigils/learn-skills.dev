사용자가 알려진 프로젝트/브랜치/병합 대상/작업 추적기/디자인 참조 워크플로를 사용하여 엔드투엔드 개발 티켓 백로그를 처리하려고 하지만 특정 플랫폼(Jira/Linear/GitHub Issues/Notion/Figma/Zeplin/등)에 커밋하지 않고 싶을 때 사용합니다. 「幫我跑任務」, 「저의 流程把 백로그 做完」, 「검토 실패 전체부處리掉」, 「사용我那套開發流程做事」, "내 작업 목록 작업", "내 개발 루프 실행", "내 티켓을 엔드투엔드 처리"와 같은 요청에 대해 트리거합니다. 항상 사용자에게 프로젝트 루트, 작업 분기, 병합 대상, 작업 목록 위치, 디자인 참조 위치 및 작업 완료 표시 방법을 묻습니다. 그런 다음 티켓 구현 → 확인 → 커밋 → PR 열기 → 병합 → 동기화 → 추적기 업데이트를 반복합니다. 플랫폼별 API 호출을 굽지 마십시오. 사용자의 답변을 통해 런타임에 이를 파악합니다.
