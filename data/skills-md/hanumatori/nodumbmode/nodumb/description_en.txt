Check the solution approach before the cost of error has increased. Use it: before a non‑trivial feature or an expensive fork; when a request describes a ready‑made solution instead of a problem; before a redesign, migration, unification, or any other large‑scale change; before a second edit without new facts; after two failed fixes, a repeated report of the same symptom, or a single false victory. Do not use it as a ritual for minor obvious edits or for continuing already agreed‑upon work.
