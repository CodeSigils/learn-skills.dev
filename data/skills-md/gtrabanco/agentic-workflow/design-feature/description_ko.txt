아이디어나 기능 요청을 철저하고 확인 가능한 제품 정의로 전환합니다. 이는 엔지니어링 계획 전 단계입니다. 핵심 메커니즘은 **기능 폐쇄**입니다. 기능이 도입하는 모든 엔터티, 기능 및 역할을 전체 표면(CRUD + 상태 전환 + UI 진입점 + API + 테스트 또는 명시적 디자인 타임 'n/a')으로 이동하도록 강제하는 체크리스트이므로 비프론티어 실행기 모델은 암시적 작업을 자동으로 생략하지 않습니다("대시보드 관리 및 ACL을 사용한 인증"은 사용자 테이블 + 목록 보기로 축소되어서는 안 됩니다). 클로저에는 세 가지 고정 체크리스트가 있습니다. **엔티티 폐쇄**(각 엔터티가 전체 표면으로), **통합 폐쇄**(프로젝트 기능 인벤토리의 모든 하위 시스템에 대해 조정된 기능, `docs/CAPABILITIES.md` — 인증, ACL, 탐색, 알림 등), **역할 매트릭스**(기능별로 명시적으로 허용/거부된 모든 인벤토리 역할) — 유능한 사람이 암묵적으로 가정하는 것을 강제하는 **기대 스윕** ("블로그에 초안이 있습니다")를 범위 내/범위 밖/지연 상태로 전환했으며, 명시되지 않은 상태로 두지 않았습니다. 기능의 엔지니어링 절반을 계획하기 전에 SPEC의 **제품 절반**을 작성하고 '## 설계 상태: 설계됨' 마커 'plan-feature' 읽기에 스탬프를 찍습니다.
