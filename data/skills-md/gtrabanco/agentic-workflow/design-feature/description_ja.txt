アイデアや機能のリクエストを、包括的でチェック可能な製品定義に変換します。これは、エンジニアリング計画の前の段階です。中核となるメカニズムは **機能クロージャ** です。機能が導入するすべてのエンティティ、機能、役割をその全表面 (CRUD + 状態遷移 + UI エントリ ポイント + API + テスト、または明示的な設計時の「n/a」) まで強制的にウォークさせるチェックリストです。そのため、非フロンティア エグゼキューター モデルは暗黙の作業を省略することを停止します (「ダッシュボード管理と ACL による認証」がユーザー テーブル + リスト ビューに折りたたまれてはなりません)。クロージャには 3 つの固定チェックリストがあります。**エンティティ クロージャ** (各エンティティを全面に)、**統合クロージャ** (プロジェクトの機能インベントリ、`docs/CAPABILITIES.md` 内のすべてのサブシステムに対して調整された機能 - 認証、ACL、ナビゲーション、通知など)、**役割マトリックス** (機能ごとに明示的に許可/拒否されるすべてのインベントリの役割)、さらに有能な人間が行うであろうことを強制する **期待スイープ** (「ブログに下書きがある」) ことを暗黙的に想定し、範囲内/範囲外/延期することを想定し、明示しないままにすることはありません。 SPEC の **製品半分** を書き込み、機能のエンジニアリング半分を計画する前に、`## 設計ステータス: 設計済み` マーカー `plan-feature` の読み取りをスタンプします。裸の `design-feature <slug>` をレビューし、何を変更するかを尋ねます。 `design-feature <slug> <instruction>` は変更を直接適用します。 Claude Code を使用していて、スキルごとのモデル/努力レベルを手動で調整したいですか?代わりに `#claude` ブランチをインストールします (`npx skill add gtrabanco/agentic-workflow#claude`)。README を参照してください。このブランチはモデルに依存しません。スキルは、エージェント セッションがすでに使用しているモデルと作業を継承します。トリガー: 「機能の追加」、「機能の追加」、「新機能」、「機能の設計」、「NN の半分の製品を設計」、「NN の機能クロージャ」、「計画する前に機能を定義」。
