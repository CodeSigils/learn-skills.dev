Превратите идею или запрос функции в исчерпывающее, проверяемое определение продукта — этап перед инженерным планированием. Основным механизмом является **закрытие возможностей**: контрольный список, который заставляет каждую сущность, возможность и роль, которую вводит функция, пройти по всей ее поверхности (CRUD + переходы между состояниями + точка входа пользовательского интерфейса + API + тест или явное значение времени разработки `n/a`), поэтому неграничные модели исполнителей перестают молча пропускать неявную работу («авторизация с управлением информационной панелью и ACL» не должна сворачиваться в таблицу пользователей + представление списка). Закрытие имеет три фиксированных контрольных списка: **закрытие объекта** (каждый объект на полную поверхность), **закрытие интеграции** (функция согласовывается с каждой подсистемой в инвентаре возможностей проекта, `docs/CAPABILITIES.md` — аутентификация, ACL, навигация, уведомления, …) и **матрица ролей** (каждая роль инвентаризации явно разрешена/запрещена для каждой возможности) — плюс **проверка ожиданий**, которая определяет то, что сделал бы компетентный человек неявно предполагать («в блоге есть черновики») в рамках области применения/за пределами области применения/отложенном, никогда не оставаясь неустановленным. Записывает **половину продукта** SPEC и ставит метку `## Статус проекта: разработанный`, `plan-feature` считывается перед планированием инженерной половины функции. Bare `design-feature <slug>` проверяет и спрашивает, что изменить; `design-feature <slug> <instruction>` применяет изменение напрямую. Вы используете Claude Code и хотите вручную настроить модель/уровень усилий для каждого навыка? Вместо этого установите ветку #claude (навыки npx добавляют gtrabanco/agentic-workflow#claude) — см. README. Эта ветвь не зависит от модели: навык наследует любую модель и усилие, которые уже использует сеанс вашего агента. Триггеры: «добавить функцию», «добавить функцию», «новая функция», «спроектировать функцию», «спроектировать половину продукта NN», «закрытие возможностей для NN», «определить функцию перед ее планированием».
