قم بتحويل فكرة أو طلب ميزة إلى تعريف منتج شامل وقابل للتحقق - وهي المرحلة التي تسبق التخطيط الهندسي. الآلية الأساسية هي **إغلاق القدرة**: قائمة مرجعية تجبر كل كيان وإمكانات ودور تقدمه الميزة على السير إلى سطحها الكامل (CRUD + انتقالات الحالة + نقطة إدخال واجهة المستخدم + API + اختبار، أو وقت تصميم صريح `n/a`)، لذلك تتوقف نماذج المنفذ غير الحدودية عن حذف العمل الضمني بصمت ("يجب ألا ينهار المصادقة مع إدارة لوحة المعلومات وقوائم ACL" إلى جدول المستخدمين + عرض القائمة). يحتوي الإغلاق على ثلاث قوائم تحقق ثابتة: **إغلاق الكيان** (كل كيان إلى السطح الكامل)، **إغلاق التكامل** (الميزة التي تمت تسويتها مع كل نظام فرعي في جرد قدرات المشروع، `docs/CAPABILITIES.md` — المصادقة، قائمة التحكم بالوصول (ACL)، التنقل، الإشعارات، ...)، و **مصفوفة الأدوار** (كل دور مخزون مسموح به/مرفوض صراحة لكل قدرة) — بالإضافة إلى **مسح التوقعات** الذي يفرض ما قد يفرضه الإنسان المختص ضمنيًا افترض ("تحتوي المدونة على مسودات") ضمن النطاق/خارج النطاق/مؤجل، ولم يتم تركها بدون ذكر. يكتب **نصف المنتج** الخاص بـ SPEC ويختم علامة `## حالة التصميم: التصميم` بعلامة `plan-feature` قبل أن يخطط للنصف الهندسي للميزة. يستعرض `ميزة التصميم <slug>` ويسأل عما يجب تغييره؛ `ميزة التصميم <slug> <instruction>` تطبق التغيير مباشرة. هل أنت على Claude Code وتريد مستويات نموذج/جهد تم ضبطها يدويًا لكل مهارة؟ قم بتثبيت الفرع `#claude` بدلاً من ذلك (`إضافة مهارات npx gtrabanco/agentic-workflow#claude`) - راجع ملف README. هذا الفرع لا يعتمد على النموذج: ترث المهارة أي نموذج أو جهد تستخدمه جلسة وكيلك بالفعل. المشغلات: "إضافة ميزة"، "إضافة ميزة"، "ميزة جديدة"، "تصميم ميزة"، "تصميم نصف المنتج من NN"، "إغلاق القدرة لـ NN"، "تحديد الميزة قبل التخطيط لها".
