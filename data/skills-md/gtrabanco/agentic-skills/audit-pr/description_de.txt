Merge-Gate auf PR-Ebene. Überprüft die GANZE Pull-Anfrage (nicht nur das Diff) anhand eines Merge-Readiness-Vertrags: SPEC-Akzeptanzkriterien erfüllt, alle Phasen abgeschlossen, Dokumente gemäß Dokumentzuordnung aktualisiert, Schließt #N vorhanden, wenn ein Problem auftritt, Tests auf der richtigen Ebene hinzugefügt, CI grün, vom Standardzweig abzweigen und unabhängig zusammenführbar, die Überprüfungs-Änderungsachsen sauber (oder bewusst auf verfolgte Probleme verschoben) und der Fähigkeitsabschluss des maßgeblichen Feature-SPEC wird erfasst und aufgezeichnet (Closure-Integrity-Gate – Legacy-SPECs). warnen, niemals blockieren). Urteil: Merge-Ready oder eine Rangliste der Blocker – immer mit der vollständigen URL des PR und auf MERGE-READY mit einem datierten, SHA-gebundenen Kommentar zum PR selbst. Bearbeitet niemals; Führt standardmäßig nie zusammen – mit einer dokumentierten Richtlinie für die automatische Zusammenführung (oder einer expliziten Benutzeranweisung) führt es einen MERGE-READY PR nach einer fehlgeschlagenen Checkliste vor dem Zusammenführen zusammen (sauberer Baum, nichts ungepusht/nicht gezogen, frisches grünes CI auf dem geprüften SHA). Sind Sie mit Claude Code vertraut und möchten von Hand abgestimmte Modell-/Aufwandsstufen pro Fertigkeit? Installieren Sie stattdessen den Zweig „#claude“ („npx skills add gtrabanco/agentic-workflow#claude“) – siehe README. Dieser Zweig ist modellunabhängig: Der Skill erbt das Modell und den Aufwand, den Ihre Agentensitzung bereits verwendet. Auslöser: „Ist dieser PR bereit für die Zusammenführung“, „Prüfung des PR“, „Merge-Gate für #N“, „Kann dieser Versand erfolgen“, „Überprüfung vor dem Zusammenführen“, „Audit-PR“.
