Периодическая проверка работоспособности всего продукта — вопрос технического директора «где мы на самом деле находимся?» Охватывает ВСЮ кодовую базу (не различия, не PR) по всем применимым осям — корректность, архитектура, безопасность/кибербезопасность, производительность, тесты, UX/UI, доступность, SEO, бренд, технический долг — ПЛЮС процесс и документация (незавершенные фазы, проблемы устаревания, решаемые известные проблемы, полнота документации/рабочего процесса) и согласованность дорожной карты. Я собираю предложения из документации по функциям. Результат: отчет с ранжированием по степени серьезности и конкретные ПРЕДЛОЖЕНИЯ — проблемы, которые нужно открыть, функции дорожной карты, которые можно добавить или удалить. Каждый запуск сохраняется в docs/audits/<n>-<ГГГГ-ММ-ДД>.md с добавочным идентификатором аудита и результатами с номерами F1, F2,…, поэтому к любому обнаружению можно обратиться позже как «triage-issue <audit-id> F<k>». НИКОГДА не исправляет автоматически; пользователь решает, что ему делать. Вы используете Claude Code и хотите вручную настроить модель/уровень усилий для каждого навыка? Вместо этого установите ветку #claude (навыки npx добавляют gtrabanco/agentic-workflow#claude) — см. README. Эта ветвь не зависит от модели: навык наследует любую модель и усилие, которые уже использует сеанс вашего агента. Триггеры: «аудит продукта», «полная проверка работоспособности», «готовы ли мы к продукту», «аудит продукта», «каково состояние кодовой базы», ​​«проверка технического директора», «очистка технического долга и дорожной карты».
