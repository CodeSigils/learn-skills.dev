產生涵蓋 7 個維度（命名、函數大小/SRP、重複/DRY、過度工程/YAGNI、幻數、結構清晰度、項目約定）的嚴重性評級（高/中/低）清潔代碼調查結果報告，每個維度都有一個位置和一個保留行為的重構建議 - 永遠不會改變功能。每當用戶要求程式碼審查、品質檢查、重構建議或程式碼氣味/乾淨程式碼分析時使用，或者指向文件/函數/差異並詢問它是否寫得好、太長、太重複、過度設計或命名不當——即使是隨意的，即使他們從不說“審查”（“我剛剛寫了這個，仔細檢查一下”，“在我提交之前看起來不錯嗎”）。觸發程式碼審查、程式碼品質、重構檢查、程式碼審查、布林程式碼寫得怎麼樣、幫我看看程式碼有沒有問題、有沒有壞味道、這個函數不是太長了、命名規範嗎、魔法數字、重複程式碼、過度設計，以及英文「這個程式碼乾淨嗎」、「任何程式碼味道如何」、「檢查這個檔案」。
