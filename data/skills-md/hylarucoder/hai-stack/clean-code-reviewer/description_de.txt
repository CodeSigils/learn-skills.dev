Erstellt einen nach Schweregrad (高/中/低) bewerteten Clean-Code-Ergebnisbericht über 7 Dimensionen (Benennung, Funktionsgröße/SRP, Duplikation/DRY, Over-Engineering/YAGNI, magische Zahlen, strukturelle Klarheit, Projektkonventionen), jeweils mit einem Standort und einem verhaltenserhaltenden Refaktorierungsvorschlag – ohne Änderung der Funktionalität. Verwenden Sie es immer dann, wenn der Benutzer um eine Codeüberprüfung, Qualitätsprüfung, Refactoring-Ratschläge oder Code-Smell-/Clean-Code-Analyse bittet ODER auf eine Datei/Funktion/einen Unterschied zeigt und fragt, ob diese gut geschrieben, zu lang, zu repetitiv, überentwickelt oder schlecht benannt ist – selbst beiläufig und selbst wenn nie „Rezension“ gesagt wird („Ich habe das gerade geschrieben, schau es dir an“, „Sieht das gut aus, bevor ich es festlege“). Trigger auf 代码体检, 代码质量, 重构检查, 代码审查, 这段代码写得怎么样,帮我看看代码有没有问题, 有没有坏味道, 这函数是不是太长了, 命名规范吗, 魔法数字,重复代码, 过度设计 und Englisch wie „Ist dieser Code sauber“, „Irgendwelcher Code riecht“, „überprüfe diese Datei“.
