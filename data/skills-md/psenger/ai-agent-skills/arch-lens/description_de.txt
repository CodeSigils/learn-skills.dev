Erforscht eine Codebasis für architektonische Reibung durch die Linse des Deep-Module-Prinzips von Ousterhout (kleine Schnittstelle, große Implementierung). Interaktiver Workflow in sieben Schritten: Ein Explore-Subagent navigiert organisch durch die Codebasis – die Reibung, die er erfährt, ist das Signal. Zeigt Kandidatencluster mit Kopplungsgründen, Aufrufmustern, gemeinsam genutzten Typen, Abhängigkeitskategorien und vorhandenen Tests an, die ein Grenztest ersetzen würde. Der Benutzer wählt aus, was er untersuchen möchte, formuliert das Problem und dann entwerfen drei bis vier parallele Subagenten konkurrierende Deep-Module-Schnittstellen. Das gewählte Design wird zu einer strukturierten RFC-Aktionsdatei, die von GitHub MCP oder ROVO (Jira) MCP gelesen werden kann. Wird verwendet, wenn der Benutzer „Bogenüberprüfung“, „flache Module finden“, „Modultiefe“, „tiefes Modul“, „Ousterhout“, „Prüfbarkeitsprüfung“, „Oberflächenkopplung“, „Designschnittstellen“, „RFC-Probleme“ oder „architektonische Reibung“ sagt.
