يستكشف قاعدة التعليمات البرمجية للاحتكاك المعماري من خلال عدسة مبدأ الوحدة العميقة لـ Ousterhout (واجهة صغيرة، تنفيذ كبير). سير عمل تفاعلي من سبع خطوات: يتنقل وكيل فرعي للاستكشاف في قاعدة التعليمات البرمجية بشكل عضوي - والاحتكاك الذي يواجهه هو الإشارة. يعرض مجموعات مرشحة بأسباب الاقتران وأنماط الاتصال والأنواع المشتركة وفئات التبعية والاختبارات الحالية التي سيحل محلها اختبار الحدود. يختار المستخدم ما يريد استكشافه، ويضع إطارًا للمشكلة، ثم يقوم 3-4 وكلاء فرعيين متوازيين بتصميم واجهات وحدة عميقة متنافسة. يصبح التصميم المختار ملف إجراء RFC منظمًا يمكن قراءته بواسطة GitHub MCP أو ROVO (Jira) MCP. يُستخدم عندما يقول المستخدم "مراجعة القوس"، أو "العثور على وحدات ضحلة"، أو "عمق الوحدة"، أو "وحدة عميقة"، أو "Ousterhout"، أو "تدقيق قابلية الاختبار"، أو "اقتران السطح"، أو "واجهات التصميم"، أو "مشكلات RFC"، أو "الاحتكاك المعماري".
