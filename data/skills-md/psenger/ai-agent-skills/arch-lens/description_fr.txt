Explorez une base de code pour la friction architecturale à travers le prisme du principe du module profond d'Ousterhout (petite interface, grande implémentation). Flux de travail interactif en sept étapes : un sous-agent Explore parcourt la base de code de manière organique – la friction qu'il subit EST le signal. Fait apparaître les clusters candidats avec des raisons de couplage, des modèles d'appel, des types partagés, des catégories de dépendances et des tests existants qu'un test de limite remplacerait. L'utilisateur choisit ce qu'il souhaite explorer, définit le problème, puis 3 à 4 sous-agents parallèles conçoivent des interfaces de modules profonds concurrentes. La conception choisie devient un fichier d'action RFC structuré lisible par GitHub MCP ou ROVO (Jira) MCP. À utiliser lorsque l'utilisateur dit "examen de l'arche", "trouver des modules peu profonds", "profondeur du module", "module profond", "Ousterhout", "audit de testabilité", "couplage de surface", "interfaces de conception", "problèmes RFC" ou "friction architecturale".
