Исследуется кодовая база для архитектурных разногласий через призму принципа глубокого модуля Оустерхаута (маленький интерфейс, большая реализация). Интерактивный рабочий процесс из семи шагов: субагент Explore органично перемещается по кодовой базе — трение, с которым он сталкивается, является сигналом. Выявляет кластеры-кандидаты с причинами связи, шаблонами вызовов, общими типами, категориями зависимостей и существующими тестами, которые заменит граничный тест. Пользователь выбирает, что исследовать, формулирует проблему, затем 3–4 параллельных субагента разрабатывают конкурирующие интерфейсы с глубокими модулями. Выбранный дизайн становится структурированным файлом действий RFC, доступным для чтения GitHub MCP или ROVO (Jira) MCP. Используйте, когда пользователь говорит «обзор арки», «найти мелкие модули», «глубина модуля», «глубокий модуль», «Оустерхаут», «аудит тестируемости», «связь поверхностей», «проектирование интерфейсов», «проблемы RFC» или «архитектурные разногласия».
