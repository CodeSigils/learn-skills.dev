完全な「シップ」プロセスを実行する自動化された Git ワークフローのワンクリック リリース アシスタント: 最新のメインから分岐→コミット→プッシュ→PR の作成→スカッシュ マージ→メインに戻る。

これは、ユーザーが「出荷」インテントを明示的に表現した場合にのみトリガーされる必要があります。たとえば、次のとおりです。
- 「ship」、「/ship」、「git ship」を直接言う
- 完全な Git フローの実行を明確に要求: 「Git プロセスを実行するのを手伝ってください」、「メイン、ブランチをプルし、PR を開き、マージします」
- 「これらの変更をリリースする」、「これらの変更を PR に変換してマージする」などの表現を使用する

次のような場合にはトリガーすべきではありません。
- ユーザーはコミットしたいだけです
- ユーザーは PR を作成したいだけです
- ユーザーはコードをプッシュしたいだけです
- Git 関連の質問について話し合ったり、Git の概念を説明したりする

常にユーザーの言語で応答してください。
