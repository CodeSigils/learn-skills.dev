Создайте собственные правила анализатора кода для Regex (сопоставление с образцом), PMD (XPath/AST для Apex и метаданных XML) и ESLint (LWC/JavaScript/TypeScript). Используйте, когда пользователи хотят обеспечить соблюдение стандартов кодирования, запретить шаблоны, обнаружить жестко запрограммированные значения, управлять метаданными или добавить правила, отсутствующие во встроенном наборе. ТРИГГЕР, когда: пользователь говорит «создать правило», «запретить System.debug», «применить соглашение об именах», «обнаружить жестко запрограммированные идентификаторы», «пользовательское правило», «правило xpath», «правило регулярного выражения», «добавить правило PMD», «применить политику», «создать проверку», «пометить этот шаблон», «создать правило, которое улавливает», «правило метаданных», «проверить разрешения», «применить API». версия», «правило eslint», «правило lwc», «порог переопределения правила», «настройка сложности» или описывает шаблон, который необходимо применить. НЕ ЗАПУСКАЙТЕ, когда: пользователь хочет запустить сканирование (используйте dx-code-analyzer-run), настроить механизмы (используйте dx-code-analyzer-configure) или объяснить существующие правила (используйте dx-code-analyzer-run).
