明示的なユーザー確認ゲートの後、Connect API を介してパイプライン ステージ (プロモート前、プロモート後、またはレビュー イベント) で 1 つ以上の DevOps Center テスト スイートの非同期実行をトリガーし、「polling-test-results」スキルを介して結果のポーリングに移ります。また、修正後に品質ゲートを再実行 (再トリガー) しますが、検証でカバレッジしきい値が満たされたことが確認されたのは 1 回だけです。トリガーのタイミング: ユーザーがパイプライン ステージでテスト スイートを実行、キックオフ、または起動したい場合。昇格の前後にテストを実行します。プロモート前、プロモート後、またはレビューイベントの実行をトリガーします。障害を修正した後、品質ゲートを再実行します。カバレッジが満たされたら、失敗したゲートを再試行します。または、テストを追加した後にブロックされたプロモーションのブロックを解除します。次の場合はトリガーしないでください。 sf apex run test を直接実行している (running-apex-tests を使用する)。または、新しいゲートまたはしきい値を設定します (configuration-quality-gate を使用します)。
