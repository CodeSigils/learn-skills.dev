Verwenden Sie diese Fähigkeit, um zu diagnostizieren und zu beheben, was eine DevOps Center‑Promotion des Feature‑Branches eines Work‑Items blockiert: Git‑Merge‑Konflikte und Deploy‑Fehler. DevOps Center ist Git‑basiert, sodass überlappende Metadaten‑Änderungen als Merge‑Konflikte gegen den Ziel‑Stage‑Branch auftreten, die mit Git gelöst werden (erkennen, Marker auflösen, committen, pushen). Deploy‑Fehler weisen häufig auf eine fehlende Abhängigkeit hin, die eine vollständige Promotion beheben kann, wenn die Komponente bereits im Branch existiert. **TRIGGER**, wenn der Benutzer ein Work‑Item vor der Promotion auf Konflikte prüfen, Merge‑Konflikte oder verbliebene Konflikt‑Marker in Metadaten‑Dateien (.xml, .object‑meta.xml, .cls) auflösen, einen Feature‑Branch mit seinem Ziel‑Stage‑Branch abgleichen oder diagnostizieren möchte, warum eine DevOps Center‑Promotion oder ein Deployment fehlgeschlagen ist und ob eine vollständige Promotion oder eine Behebung der fehlenden Abhängigkeit das Problem löst. **DO NOT TRIGGER** für das Ausführen der Promotion selbst (verwenden Sie dx‑devops‑promote), das Erstellen oder Aktualisieren von Work‑Items (verwenden Sie dx‑devops‑work‑item‑manage) oder das direkte Deployen von Metadaten in ein Org.

Bitte antworten Sie immer in der Sprache des Benutzers.
