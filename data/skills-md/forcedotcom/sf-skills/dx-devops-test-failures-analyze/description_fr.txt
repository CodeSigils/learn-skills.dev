Analyse les échecs des tests DevOps Center et les violations de l'analyseur de code en langage clair : catégorie d'échec, fichier/classe/méthode/ligne incriminés, règle violée, direction du correctif et suggestions d'amélioration prioritaires (code de test vs code de production) - puis crée éventuellement un correctif suivi WorkItem sur demande explicite. L'analyse est un pur raisonnement ; la création d'un élément de travail est une écriture avec confirmation. Utilisez cette compétence pour expliquer les échecs ou les suggestions d'amélioration, traduire les violations de Code Analyzer ou suivre un correctif en tant qu'élément de travail. DÉCLENCHEMENT lorsque : une exécution a échoué et l'utilisateur souhaite la cause première ; une défaillance du portail de qualité doit être expliquée ; les violations doivent être traduites ; l'utilisateur partage une charge utile d'échec et demande comment y remédier ; veut renforcer les tests ; ou souhaite créer un élément de travail correctif, enregistrer une correction ou attribuer un échec. NE PAS DÉCLENCHER lorsque : l'utilisateur souhaite écrire du code correctif (utilisez platform-apex-generate) ou créer de nouvelles classes de test (utilisez platform-apex-test-generate).
