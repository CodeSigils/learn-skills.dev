Lightning Web コンポーネントの Sa11y アクセシビリティ Jest テストを実行するときは、プッシュする前にローカルで、正確なコマンドの生成、スイート全体に対して 1 つのファイルの実行、命名規則によるテストの選択、Sa11y でレンダリングされた HTML の保存、または Sa11y / A11yBug エラーの再現の前に、常に使用します。 Salesforce コア (Bazel; `WORKSPACE`、`./core` root、`bazel test //<module>:<target>`) およびスタンドアロンの `npx jest` (`.accessibility.test.js`、`@sa11y/jest`) をカバーします。プロンプトがアクセシビリティ テストの `run-plan.md` を要求する場合 (終了コードはアクセシビリティ テストの失敗を意味する)、または `SA11Y_*` 環境変数、`A11yBug`、または core-Bazel の `modules/<mod>/<cmp>/__tests__/*.test.js` パスを参照する場合は必須です。一般知識に依存しないでください。このスキルには、正しい単一ファイル Bazel ターゲットと EPERM 回避策が含まれています。機能 (アクセシビリティ以外) Jest テスト、テストを実行しない a11y レビュー (experience-lwc-accessibility-validate を使用)、または Selenium ベースの a11y 機能テストではトリガーしないでください。
