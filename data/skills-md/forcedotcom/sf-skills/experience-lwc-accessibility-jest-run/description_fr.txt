Utilisez TOUJOURS lors de l'exécution de tests Jest d'accessibilité Sa11y pour un composant Web Lightning - localement avant de pousser, de produire la ou les commandes exactes, d'exécuter un fichier ou une suite entière, de sélectionner des tests par convention de dénomination, d'enregistrer le HTML rendu par Sa11y ou de reproduire un échec Sa11y / A11yBug. Couvre le noyau Salesforce (Bazel ; `WORKSPACE`, `./core` root, `bazel test //<module>:<target>`) et autonome `npx jest` (`.accessibility.test.js`, `@sa11y/jest`). OBLIGATOIRE lorsqu'une invite demande un `run-plan.md` pour les tests d'accessibilité, dont le code de sortie signifie qu'un test d'accessibilité a échoué, ou fait référence aux variables d'environnement `SA11Y_*`, `A11yBug` ou à un chemin `modules/<mod>/<cmp>/__tests__/*.test.js` de base-Bazel. Ne vous fiez PAS aux connaissances générales : cette compétence possède la cible Bazel à fichier unique et la solution de contournement EPERM correctes. NE PAS DÉCLENCHER pour les tests Jest fonctionnels (non-accessibilité), les examens a11y sans exécuter de tests (utilisez experience-lwc-accessibility-validate) ou les tests fonctionnels a11y basés sur Selenium.
