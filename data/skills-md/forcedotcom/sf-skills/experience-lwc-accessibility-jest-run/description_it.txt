Utilizzare SEMPRE quando si eseguono test Jest di accessibilità Sa11y per un componente Web Lightning: localmente prima di eseguire il push, produrre i comandi esatti, eseguire un file anziché un'intera suite, selezionare test in base alla convenzione di denominazione, salvare HTML con rendering Sa11y o riprodurre un errore Sa11y/A11yBug. Copre il core Salesforce (Bazel; `WORKSPACE`, `./core` root, `bazel test //<module>:<target>`) e `npx jest` autonomo (`.accessibility.test.js`, `@sa11y/jest`). RICHIESTO quando un prompt richiede un `run-plan.md` per i test di accessibilità, il cui codice di uscita indica che un test di accessibilità non è riuscito o fa riferimento a `SA11Y_*` env vars, `A11yBug` o un percorso core-Bazel `modules/<mod>/<cmp>/__tests__/*.test.js`. NON fare affidamento su conoscenze generali: questa competenza ha il target Bazel a file singolo corretto e la soluzione alternativa EPERM. NON ATTIVARE per test Jest funzionali (non di accessibilità), revisione completa senza eseguire test (utilizzare experience-lwc-accessibility-validate) o test funzionali completi basati su selenio.
