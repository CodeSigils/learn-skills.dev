Verwenden Sie diesen Skill, um festzustellen, ob auf eine Lightning-Webkomponente (LWC) zugegriffen werden kann und ob sie den Barrierefreiheitsrichtlinien der WCAG entspricht. TRIGGER, wenn der Benutzer fragt: „Ist meine Komponente barrierefrei?“, „Entspricht mein LWC den Barrierefreiheitsrichtlinien?“, „Ist diese Komponente WCAG-konform?“, „Finden Sie Barrierefreiheitsprobleme in diesem LWC“, „Ist diese LWC-Tastatur barrierefrei?“, „Funktioniert diese Komponente mit einem Bildschirmlesegerät?“, „Hat diese Komponente ausreichend Farbkontrast?“, „Überprüfen Sie die ARIA-Verwendung in diesem LWC“ oder „WCAG 2.2-Barrierefreiheitsprüfung“. Wird auch TRIGGER, wenn der Benutzer die Barrierefreiheit (a11y, WCAG, ARIA) im HTML, JS oder CSS eines LWC korrigieren oder verbessern möchte – semantisches Markup, Fokus, Tastaturnavigation, Kontrast, Screenreader-Beschriftungen, WCAG 2.2 SC. Erstellt „a11y-review.md“ mit von der WCAG zitierten Ergebnissen. NICHT für die allgemeine LWC-Generierung auslösen (verwenden Sie „experience-lwc-generate“) oder die visuelle/Designüberprüfung von SLDS, die nicht auf Barrierefreiheit ausgerichtet ist (verwenden Sie „design-systems-slds-validate“).
