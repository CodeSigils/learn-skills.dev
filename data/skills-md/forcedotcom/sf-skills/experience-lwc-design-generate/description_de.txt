Verwenden Sie es, wenn Sie eine brandneue Lightning-Webkomponente aus einem Figma-Design, einem Produktanforderungsdokument oder einem anderen Designartefakt erstellen müssen – um den fünfphasigen Arbeitsablauf zu orchestrieren (Anforderungen sammeln → Code generieren → optimieren → Lint/Formatieren/Kompilieren → Testen) und die speziellen Fähigkeiten für SLDS, LDS, Basiskomponenten, Optimierung und Tests zusammenzuführen. Verwenden Sie diese Fähigkeit immer dann, wenn der Benutzer erwähnt, dass er einen neuen LWC aus Figma erstellt, einen LWC aus einem PRD erstellt, einen LWC aus einem Design oder Screenshot generiert oder eine Aura-Komponente als neuen LWC-Build migriert. NICHT AUSLÖSEN, wenn ein vorhandener LWC umgestaltet wird (verwenden Sie experience-lwc-generate), für die In-Place-Migration von Aura → LWC (außerhalb des Geltungsbereichs dieser Fertigkeit), für eigenständige SLDS-Token- oder Styling-Arbeiten (verwenden Sie design-systems-slds-apply) oder für eigenständige Arbeiten auf Datenebene (verwenden Sie experience-lds-best-practices-apply oder experience-lds-data-requirements-generate).
