Mettre en place et maintenir un système de documentation structuré (Document Engineering) pour les projets logiciels. Utilisez cette compétence chaque fois que l'utilisateur souhaite : échafauder une arborescence Produit/doc avec PRD, Code, QA et CHANGELOG par fonction ; générer ou mettre à jour l'un de ces fichiers doc après une modification de code ; ajoutez une règle CLAUDE.md qui applique les mises à jour de la documentation dans le cadre de la définition du fait ; installez un hook de pré-commit git qui avertit lorsque les modifications de code manquent de mises à jour de documentation correspondantes ; ou exécutez un audit périodique qui compare les horodatages du journal git aux horodatages des fichiers doc pour faire apparaître les validations non synchronisées. Déclenchez également lorsque l'utilisateur dit « ingénierie de la documentation », « ingénierie de la documentation », « maintenir mes documents », « garder les documents synchronisés », « dérive de la documentation » ou demande de configurer la structure de documentation pour une base de code.
