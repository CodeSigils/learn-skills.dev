ソフトウェア プロジェクト用の構造化ドキュメンテーション システム (ドキュメント エンジニアリング) をセットアップし、維持します。ユーザーが次のことを行う場合は常にこのスキルを使用します。PRD、コード、QA、および CHANGELOG を機能ごとに使用して製品/ドキュメント ツリーをスキャフォールディングします。コード変更後にこれらの doc ファイルを生成または更新します。完了の定義の一部としてドキュメントの更新を強制する CLAUDE.md ルールを追加します。コードの変更に一致するドキュメントの更新がない場合に警告する git pre-commit フックをインストールします。または、git log のタイムスタンプと doc ファイルのタイムスタンプを比較する定期的な監査を実行して、同期されていないコミットを明らかにします。また、ユーザーが「ドキュメント エンジニアリング」、「ドキュメント エンジニアリング」、「ドキュメントのメンテナンス」、「ドキュメントの同期を保つ」、「ドキュメントのドリフト」と発言したとき、またはコードベースのドキュメント構造のセットアップを要求したときにもトリガーされます。
