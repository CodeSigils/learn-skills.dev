取得 arc-bug-finder（在 GitHub Issues、GitLab 或 Linear 中）提交的 bug 票證，嚴格審查並重新驗證它，然後實作、驗證和發布修復 - 分支、常規提交、PR 和票證更新。審查是核心能力：它重新重現缺陷，確認引用的根本原因仍然存在，並選擇最佳修復方案，而不是盲目相信票證。將計畫格式化委託給 arc-planning-work，將提交/PR 機制委託給 arc-conventional-commits / arc-git-pr-check。觸發時間：使用者要求修復/解決/實作已提交的錯誤，指向錯誤單或問題編號，說「修復此錯誤」、「解決 W-######」或「處理錯誤積壓」。不要在以下情況下觸發：使用者回報新錯誤或詢問「為什麼會發生這種情況」（首先使用 arc-bug-finder 進行研究+歸檔），或規劃未開發功能（使用 arc-defining-work）。
