# 커밋 워크플로

워크스페이스의 모든 프로젝트에서 스테이징된 변경을 찾고, 코드 리뷰 후 커밋한다.

## 변수·설정

### `{{PROJECT_NAME}}` (선택)

특정 프로젝트의 스테이징된 변경을 찾고, 코드 리뷰 후 커밋한다.

```markdown
| PROJECT_NAME | PROJECT_PATH          |
| ------------ | --------------------- |
| senior       | ~/service/apps/senior |
| komate       | ~/service/apps/komate |
| career-feed  | ~/career-feed         |
| begins       | ~/begins              |
```

### `--no-review` (선택)

코드 리뷰를 건너뛰고 바로 커밋으로 진행

### `LOG_PATH` (코드 리뷰 로그)

- **`code-review` SKILL**의 `LOG_PATH` 규칙과 동일하다.
- 요약: (1) 환경 변수 `LOG_PATH` → (2) 없으면 Cursor **`User/settings.json`**의 `terminal.integrated.env.linux` / `osx` / `windows` 안의 `LOG_PATH`를 Read·파싱한다.
- 값이 없으면 로그 생략(채팅 한 줄 안내). 있으면 `code-review` 5단계대로 append한다.

## 워크플로 단계

### 1. 대상 저장소·스테이징 확인

**프로젝트명이 주어진 경우**

- `{{PROJECT_NAME}}`에서 경로를 찾는다.
- 해당 디렉터리가 존재하고 `.git` 폴더를 포함하는지 확인한다.
- 해당 디렉터리에서 실행:

```bash
cd "<PROJECT_PATH>" && git status && echo "=== STAGED ===" && git diff --cached
```

**프로젝트명이 주어지지 않은 경우**

- 모든 **워크스페이스 폴더**들 각각(또는 하위)에서 `.git` 존재 여부를 확인한다.
- 스테이징이 있는 저장소만 나열하고 `git diff --cached --stat`(또는 전체 diff)로 맥락을 수집한다.
- **스테이징이 둘 이상 저장소에 있으면** 사용자에게 어느 저장소(들)를 커밋할지 묻는다.
- 스테이징이 없으면 안내하고 **종료**한다.

### 2. 코드 리뷰

**⚠️ `--no-review` 사용 시 이 단계는 건너뛴다. 바로 3단계로 진행한다.**

- **`code-review` SKILL**을 찾아서 **전 절차(1~5단계)**에 맞춰 실행한다.
  - 이 커맨드 안에서 리뷰를 “채팅 요약만”으로 대체하는 경우에도, **`code-review` SKILL 5단계(리뷰 요약을 `{{LOG_PATH}}/{{PROJECT_NAME}}/code-review.md`에 append)**는 동일하게 수행한다. `--no-review`일 때는 생략한다.
  - `LOG_PATH` 결정·`PROJECT_NAME`(저장소 루트 디렉터리명)·append 형식은 전부 **`code-review` SKILL**을 따른다.
- 리뷰 후 **반드시** 사용자에게 다음을 묻는다:  
  `코드 리뷰를 완료했습니다. 계속 커밋하시겠습니까?`
- 사용자가 진행에 동의하기 전에는 **커밋(3~5단계)을 실행하지 않는다.**

### 3. 분석

- 스테이징 vs 미스테이징, 변경 규모, 실제 커밋에 포함될 파일만 정리한다.

### 4. 커밋 메시지 작성

- **스테이징된 diff만** 근거로 작성한다.
- 형식 `<type>(<scope>): <subject>`
- 커밋 메시지는 **한국어(한글)**로 작성한다.
- **명령형·현재 시제**를 사용한다.
- 제목은 **100자 이내**로 제한한다.
- **적절한 타입**을 쓴다: feat, fix, docs, refactor, test (perf, style, chore, revert 없음)
- 큰 커밋이면 목록 형태로 세부를 적는다.
- 여러 프로젝트면 어느 저장소용 메시지인지 구분해 제시

### 5. 실행

- 저장소마다 `cd "<절대경로>"` 후 `git commit -m "..."` (필요 시 본문은 `-m` 여러 번 또는 에디터)
- 사용자가 터미널에서 메시지를 고치도록 할 수 있게 명령을 그대로 보여준다.

## 주의사항

- 코드 리뷰 후 **사용자 확인 없이 커밋하지 않는다** (`--no-review` 제외).
- 리뷰에서 치명적 이슈가 있으면 커밋 전 수정을 권고한다.

## 요약 체크리스트

- [ ] 스테이징 없음 → 종료 안내
- [ ] 대상 저장소·경로 명확화 (`{{PROJECT_PATH}}` 또는 탐색·질문)
- [ ] (선택) 코드 리뷰 → **`code-review` 5단계 로그까지**(`LOG_PATH` 있을 때) → 사용자 동의 대기
- [ ] 컨벤션에 맞는 한국어 메시지
- [ ] `cd` 후 `git commit` 실행
