ダウンタイムゼロを保証して、PostgreSQL 用の Django 移行を作成、レビュー、および再書き込みします。ユーザーが移行、Django スキーマの変更、またはデプロイメントの安全性について言及するときは、たとえ「ゼロ ダウンタイム」と明示的に言わなくても、このスキルを使用してください。トリガー: 「この移行を確認する」、「この移行は安全ですか?」、「... の移行を書きます」、「この移行を書き直す」、「NOT NULL 列を追加する/列を削除する/インデックスを追加する/列の名前を変更する/ダウンタイムなしで FK を追加するにはどうすればよいですか」、「この移行はロックを引き起こしますか?」、「この移行は運用をブロックしています」。対象範囲: SeparateDatabaseAndState の 2 つのファイル分割、AddIndexConcurrently、FK NOT VALID + VALIDATE、NOT NULL 列の db_default、lock_timeout、および RunPython 安全ルール。
