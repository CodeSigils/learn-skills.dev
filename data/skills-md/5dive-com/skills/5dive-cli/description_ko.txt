5dive 런타임 VM에서 로컬 `5dive` CLI를 사용하여 형제 에이전트를 생성, 검사, 전송 및 해제합니다. 사용자가 작업자, 하위 에이전트, 부가 작업, 병렬 실행, "다른 에이전트", "팬아웃", "위임"을 요청하거나 자연어로 형제 에이전트의 이름을 지정할 때마다("X로 리디렉션", "X에게 묻기", "X핑", "X에게 알리기", "X와 조정", "X에 전달") 때마다 이 기술을 트리거합니다. 이 경우 먼저 `5dive Agent list --json`을 사용하여 에이전트가 존재하는지 확인한 다음 `에이전트 보내기`를 사용하여 에이전트가 존재하는지 확인합니다. 또한 사용자가 `/var/lib/5dive/`를 언급하거나 기계 판독 가능 상태 확인(`5dive doctor --json`)이 필요한 경우 사용자가 기존 에이전트를 검사, 다시 시작 또는 페어링하도록 요청할 때 트리거됩니다. 사용자의 요청이 채팅 채널(Telegram/Discord `<channel>` 태그)을 통해 도착했고 다른 에이전트가 참여하기를 원하는 경우 `--reply-to-chat=<id> --reply-to-msg=<id>`를 통해 채팅 컨텍스트를 전달하여 대상 에이전트가 자체 봇의 채팅에서 직접 응답하도록 합니다. 릴레이하지 마세요. 코딩 CLI를 수동으로 실행하는 것보다 항상 '5dive'를 선호합니다. 이는 에이전트를 systemd 상태로 유지하는 유일한 승인된 방법입니다.
