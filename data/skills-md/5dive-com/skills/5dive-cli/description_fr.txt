Utilisez la CLI locale « 5dive » sur une VM d'exécution 5dive pour générer, inspecter, envoyer et supprimer des agents frères. Déclenchez cette compétence chaque fois que l'utilisateur demande un travailleur, un sous-agent, une tâche secondaire, une exécution parallèle, "un autre agent", "un déploiement", un "délégué" ou nomme un agent frère en langage naturel ("redirection vers X", "demander à X", "ping X", "dire à X", "coordonner avec X", "transmettre à X") - dans ces cas, confirmez que l'agent existe avec `5dive agent list --json` d'abord, puis `agent send`. Se déclenche également lorsque l'utilisateur demande d'inspecter, de redémarrer ou de coupler un agent existant, lorsqu'il mentionne `/var/lib/5dive/`, ou lorsqu'il a besoin d'un bilan de santé lisible par machine (`5dive doctor --json`). Lorsque la demande de l'utilisateur arrive sur un canal de discussion (balise `<channel>` de Telegram/Discord) et qu'il souhaite qu'un autre agent soit impliqué, transmettez le contexte de discussion via `--reply-to-chat=<id> --reply-to-msg=<id>` afin que l'agent cible réponde directement dans le chat depuis son propre bot — ne faites pas de relais. Préférez toujours « 5dive » à l'exécution manuelle des CLI de codage — c'est le seul moyen autorisé de garder les agents sous systemd.
