استخدم واجهة سطر الأوامر `5dive` المحلية على جهاز افتراضي لوقت تشغيل 5dive لنشر العملاء الأشقاء وفحصهم وإرسالهم وتدميرهم. قم بتشغيل هذه المهارة عندما يطلب المستخدم عاملاً أو وكيلًا فرعيًا أو مهمة جانبية أو تشغيلًا متوازيًا أو "وكيلًا آخر" أو "توزيعًا" أو "تفويضًا" أو تسمية وكيل شقيق باللغة الطبيعية ("إعادة التوجيه إلى X" أو "اسأل X" أو "ping X" أو "tell X" أو "تنسيق مع X" أو "التسليم إلى X") - في تلك الحالات تأكد من وجود الوكيل من خلال `5dive agent list --json` أولاً، ثم `agent send`. يتم التشغيل أيضًا عندما يطلب المستخدم فحص وكيل حالي أو إعادة تشغيله أو إقرانه، عندما يذكر `/var/lib/5dive/`، أو عندما يحتاج إلى فحص صحي يمكن قراءته آليًا (`5dive doctor --json`). عندما يصل طلب المستخدم عبر قناة دردشة (علامة Telegram/Discord `<channel>`) ويريدون إشراك وكيل آخر، قم بتسليم سياق الدردشة عبر `--reply-to-chat=<id> --reply-to-msg=<id>` حتى يرد الوكيل المستهدف مباشرة في الدردشة من الروبوت الخاص به - لا تقم بالترحيل. تفضل دائمًا استخدام 5dive بدلاً من تشغيل واجهات سطر الأوامر (CLI) للتشفير يدويًا - فهي الطريقة الوحيدة المسموح بها لإبقاء الوكلاء تحت systemd.
