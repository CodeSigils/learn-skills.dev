Applique une règle : chaque changement de code doit être présenté comme un diff unifié (format `diff -u`) avec 3 lignes de contexte. Aucune exception, même les one-liners.
DÉCLENCHEMENT lorsque : l'utilisateur demande une modification de code - corriger, refactoriser, mettre à jour, remplacer, éditer, corriger, modifier, modifier, renommer, réécrire, appliquer des modifications, modifier ceci, éditer le fichier, changer ce code ou demande explicitement une différence - "montre-moi la différence", "en tant que différence unifiée", "ce qui a changé", "afficher le correctif", "/montre-moi-le-code". NE PAS UTILISER lorsque : vous produisez un tout nouveau fichier à partir de zéro (aucune ligne de contexte avec laquelle comparer) ou pour des réponses non codées telles que des plans, des explications, une architecture ou des diagrammes.
