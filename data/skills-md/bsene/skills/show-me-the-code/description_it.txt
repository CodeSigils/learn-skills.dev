Applica una regola: ogni modifica al codice deve essere presentata come un diff unificato (formato `diff -u`) con 3 righe di contesto. Nessuna eccezione, nemmeno una battuta.
SI ATTIVA quando: l'utente richiede una modifica del codice - correzione, refactoring, aggiornamento, sostituzione, modifica, patch, cambiamento, modifica, rinomina, riscrittura, applica modifiche, modifica questo, modifica il file, cambia questo codice o richiede esplicitamente un diff - "mostrami il diff", "come diff unificato", "cosa è cambiato", "mostra la patch", "/mostrami-il-codice". NON UTILIZZARE quando: si produce un file nuovo di zecca da zero (nessuna riga di contesto con cui confrontarsi) o per risposte non di codice come piani, spiegazioni, architettura o diagrammi.
