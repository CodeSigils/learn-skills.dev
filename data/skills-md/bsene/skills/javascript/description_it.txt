Best practice e applicazione delle regole JavaScript: convenzioni di denominazione, idiomi di sintassi moderni, gestione di "this", struttura del modulo, prestazioni di array/iterazione e possibilità di nulla. Si applica al semplice JavaScript ed è la base su cui si basa TypeScript.
TRIGGER quando: linguaggio (JavaScript, JS, .js, .mjs, .cjs, Node.js, browser JS, moduli ES, ESM, CommonJS), sintassi (const/let, destrutturazione, valori letterali di modello, concatenamento opzionale, coalescenza nulla, funzioni freccia), modelli (questa associazione, callback, metodo distaccato, funzione pura rispetto a metodo, importazioni di moduli, file barile, indice.js), prestazioni (catene di array, filter().map(), array intermedi, hot path, pressione GC), nullability (null vs unfined, assenza, valore sentinella, == controllo null), denominazione (camelCase, PascalCase, kebab-case, prefisso booleano), ask (JavaScript idiomatico, convenzioni JS, best practice JS, revisione del codice JS). SI APPLICA ANCHE a TypeScript: è la base su cui si basa TS; caricalo insieme a `typescript` su `.ts`/`.tsx`. Per le regole specifiche del tipo (asserzioni di tipo "as T", interfacce, generici, modificatore "readonly", "as const", annotazioni sul tipo restituito) la competenza "typescript" aggiunge una guida in più.
NON UTILIZZARE come competenza primaria per domande sul sistema di tipi (unioni discriminate, generici, `as`, interfacce, restringimento) → instradamento a `typescript` / `typescript-type-system`; questa abilità si applica ancora per la denominazione e gli idiomi JS.
