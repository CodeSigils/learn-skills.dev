Meilleures pratiques JavaScript et application des règles : conventions de dénomination, idiomes de syntaxe modernes, gestion de "this", structure de module, performances de tableau/itération et nullabilité. S'applique au JavaScript simple et constitue la base sur laquelle TypeScript s'appuie.
DÉCLENCHEMENT lorsque : langage (JavaScript, JS, .js, .mjs, .cjs, Node.js, navigateur JS, modules ES, ESM, CommonJS), syntaxe (const/let, déstructuration, littéraux de modèle, chaînage facultatif, fusion nulle, fonctions de flèche), modèles (cette liaison, rappel, méthode détachée, fonction pure contre méthode, importations de modules, fichier baril, index.js), performances (chaînes de tableaux, filter().map(), tableaux intermédiaires, hot path, pression GC), nullabilité (nul vs non défini, absence, valeur sentinelle, == vérification nulle), dénomination (camelCase, PascalCase, kebab-case, préfixe booléen), demander (JavaScript idiomatique, conventions JS, meilleures pratiques JS, révision du code JS). S'APPLIQUE ÉGALEMENT à TypeScript - c'est la base sur laquelle TS s'appuie ; chargez-le à côté de `typescript` sur `.ts`/`.tsx`. Pour les règles spécifiques au type (assertions de type « as T », interfaces, génériques, modificateur « readonly », « as const », annotations de type de retour), la compétence « typescript » ajoute des conseils en haut.
NE PAS UTILISER comme compétence principale pour les questions de système de types (unions discriminées, génériques, « as », interfaces, rétrécissement) → itinéraire vers « typescript » / « typescript-type-system » ; cette compétence s'applique toujours en dessous pour la dénomination et les idiomes JS.
