JavaScript のベスト プラクティスとルールの適用 - 命名規則、最新の構文イディオム、「this」の処理、モジュール構造、配列/反復のパフォーマンス、Null 可能性。プレーンな JavaScript に適用され、TypeScript の基礎となります。
トリガーの条件: 言語 (JavaScript、JS、.js、.mjs、.cjs、Node.js、ブラウザー JS、ES モジュール、ESM、CommonJS)、構文 (const/let、構造化、テンプレート リテラル、オプションのチェーン、ヌル結合、アロー関数)、パターン (このバインディング、コールバック、切り離されたメソッド、純粋な関数とメソッド、モジュールのインポート、バレル ファイル、index.js)、パフォーマンス(配列チェーン、filter().map()、中間配列、ホット パス、GC プレッシャー)、null 可能性 (null と未定義、不在、センチネル値、== null チェック)、命名 (キャメルケース、パスカルケース、ケバブケース、ブール プレフィックス)、質問 (慣用的な JavaScript、JS 規約、JS ベスト プラクティス、JS コード レビュー)。 TypeScript にも適用されます。これは TS の基礎となります。それを `.ts`/`.tsx` 上の `typescript` と一緒にロードします。型固有のルール (型アサーション `as T`、インターフェイス、ジェネリックス、`readonly` 修飾子、`as const`、戻り値の型注釈) については、`typescript` スキルが最上位にガイダンスを追加します。
型システムの質問 (識別共用体、ジェネリックス、as、インターフェイス、絞り込み) の主要なスキルとして使用しないでください。 → `typescript` / `typescript-type-system` にルーティングします。このスキルは、命名や JS のイディオムにも引き続き適用されます。
