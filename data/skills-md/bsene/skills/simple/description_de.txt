Verwenden Sie diese Fähigkeit, wenn Sie neuen Code schreiben, einen Bugfix vorschlagen, einen PR/Diff überprüfen oder diskutieren, ob eine Abstraktion, eine Konfigurationsebene, ein Plugin-System oder ein generischer Mechanismus hinzugefügt werden soll. Auch Auslöser für Architektur-/Designdiskussionen, „Ist das zu komplex“-Fragen oder irgendein Punkt, an dem Claude die Einführung einer neuen Abstraktionsebene vorschlagen will. Der Kerngedanke – Code ist so geschrieben, dass er von Menschen gelesen werden kann, nicht als Kunstwerk, das man bewundern kann – optimiert auf Erschwinglichkeit (wie ein Verkehrsschild, sofort lesbar) und nicht auf Eleganz oder Klugheit. Auslöser, auch wenn der Benutzer „Einfachheit“ nicht explizit nennt – z. B. „Sollte ich das konfigurierbar machen“, „Schnelle Lösung für diesen Fehler“, „Überprüfen Sie diese PR“, „Soll ich das in einen Helfer abstrahieren“, „Diese Codebasis fühlt sich chaotisch an“.
