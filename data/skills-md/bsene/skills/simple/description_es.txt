Utilice esta habilidad siempre que escriba código nuevo, proponga una corrección de errores, revise un PR/diff o discuta si se debe agregar una abstracción, una capa de configuración, un sistema de complementos o un mecanismo genérico. También es un desencadenante de debates sobre arquitectura/diseño, preguntas "demasiado complejas" o cualquier punto en el que Claude esté a punto de sugerir la introducción de una nueva capa de abstracción. La postura central (el código está escrito para que lo lean los humanos, no como una obra de arte para admirar) es optimizar para obtener asequibilidad (como una señal de tráfico, legible al instante) en lugar de elegancia o inteligencia. Activar incluso si el usuario no menciona explícitamente "simplicidad", por ejemplo, "debería hacer esto configurable", "solución rápida para este error", "revisar". este PR", "debería resumir esto en un ayudante", "este código base se siente desordenado".
