Stratégie et philosophie de test : commentaires sur la conception, audit de la qualité des tests, examen BDD, décisions d'architecture et stratégie de test pour les agents de codage d'IA.
DÉCLENCHEMENT quand : stratégie (stratégie de test, approche de test, philosophie de test, méthodologie de test, comment tester, quels tests écrire, meilleures pratiques de test), qualité (qualité des tests, tests fragiles, tests irréguliers, tests lents, tests difficiles à maintenir, anti-modèles de test), portée (unité vs intégration vs e2e, couches de test, architecture de test, quantité à tester), moquerie (quand utiliser des simulations, stratégie moqueuse, tests doubles), révision (réviser ma suite de tests, vérifier mon tests, examen BDD, desiderata de test), contexte (test de la base de code existante, ajout de tests au code existant), agents d'IA (stratégie de test pour le code généré par l'IA, si l'IA écrit ses propres tests, puis-je faire confiance aux tests écrits par l'IA, pipeline de tests multi-agents, cadence TDD pour les agents, stratégie de test de codage d'ambiance). NE PAS UTILISER lorsque : l'utilisateur a besoin d'une cadence TDD interactive avec des boucles rouge/vert/refactor pour un humain conduisant le clavier — utilisez plutôt « tcrdd ». Si un agent IA conduit à la place, consultez d'abord « Tests avec des agents de codage IA » ci-dessous : la boucle micro-étape ne s'applique pas de la même manière. NE PAS UTILISER lorsque : l'utilisateur pose des questions spécifiquement sur les tests de fumée — utilisez plutôt « tests de fumée ».
