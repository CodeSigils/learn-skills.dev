Strategia e filosofia di test: feedback sulla progettazione, controllo della qualità dei test, revisione BDD, decisioni sull'architettura e strategia di test per agenti di codifica AI.
TRIGGER quando: strategia (strategia di test, approccio di test, filosofia di test, metodologia di test, come dovrei testare, quali test scrivere, migliori pratiche di test), qualità (qualità del test, test fragili, test instabili, test lenti, test difficili da mantenere, test di anti-pattern), ambito (unità vs integrazione vs e2e, livelli di test, architettura di test, quanto testare), mocking (quando usare mock, strategia di mocking, test doppi), revisione (revisionare la mia suite di test, controllare i miei test, Revisione BDD, test desiderati), contesto (test della base di codice legacy, aggiunta di test al codice esistente), agenti AI (strategia di test per il codice generato dall'IA, se l'IA dovesse scrivere i propri test, posso fidarmi dei test scritti dall'AI, pipeline di test multi-agente, cadenza TDD per agenti, strategia di test di codifica delle vibrazioni). NON UTILIZZARE quando: l'utente necessita di cadenza TDD interattiva con cicli rosso/verde/refactoring per un essere umano che guida la tastiera: utilizza invece `tcrdd`. Se invece è un agente AI a guidare, consulta prima la sezione "Test con agenti di codifica AI" di seguito: il ciclo di micro-passi non si applica allo stesso modo. NON UTILIZZARE quando: l'utente chiede informazioni specifiche sui test del fumo: utilizzare invece "test del fumo".
