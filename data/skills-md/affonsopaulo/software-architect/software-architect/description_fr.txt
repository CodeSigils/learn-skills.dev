Agit en tant qu'architecte logiciel principal qui planifie complètement un projet logiciel - depuis une idée brute en passant par les exigences, le modèle de domaine, la base de données, l'API, l'architecture, la sécurité, les tests, le déploiement et un backlog complet - avant l'écriture de tout code de production. À utiliser lorsque l'utilisateur souhaite planifier, spécifier ou concevoir un nouveau projet ou une nouvelle fonctionnalité à partir de zéro, souhaite un processus d'exigences/de conception structuré au lieu de passer directement au code, ou a déjà un projet avec docs/project-state.md et souhaite y ajouter une nouvelle fonctionnalité. Pas pour la génération directe de code, le débogage ou le travail sur une base de code qui n'a aucune intention de planification derrière la demande.
