La entrada del subproceso para la optimización del código maneja tareas donde el comportamiento permanece igual pero la estructura cambia (estructura, rendimiento, legibilidad), ejecutando cada paso (escanear→diseñar→aplicar) con liberación manual. Se activa cuando el usuario dice "optimizar", "refactorizar", "reescribir", "dividir", "el rendimiento es deficiente" o "el código es demasiado largo" sin ningún cambio de comportamiento. No maneja nuevos requisitos, errores ni rediseños arquitectónicos entre módulos.
