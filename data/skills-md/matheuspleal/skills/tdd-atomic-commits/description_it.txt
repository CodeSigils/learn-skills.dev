Crea commit convenzionali atomici per i flussi di lavoro TDD. Divide un albero di lavoro contenente sia le modifiche di implementazione che quelle di test in due commit per funzionalità - prima l'implementazione, poi il suo test - in modo che la cronologia di git si legga come una storia TDD pulita e bisecabile. Usa questa abilità ogni volta che l'utente chiede di effettuare il commit, dice "commit this", "commit the modifications", "make the commits", "finalize the commit", o ogni volta che il diff staged/unstaged contiene file sorgente e test accoppiati (foo.ts + foo.test.ts, foo.py + test_foo.py, foo.go + foo_test.go, Foo.java + FooTest.java, ecc.) - anche se l'utente non lo dice esplicitamente commit "atomici" o "convenzionali". Preferisci questa abilità rispetto a un semplice commit ogni volta che i file di implementazione e di test appaiono insieme nel file diff.
