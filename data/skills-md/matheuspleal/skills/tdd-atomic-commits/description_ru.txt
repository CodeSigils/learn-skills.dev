Создавайте атомарные обычные фиксации для рабочих процессов TDD. Разбивает рабочее дерево, содержащее как изменения реализации, так и тестовые изменения, на два коммита для каждой функции — сначала реализация, затем ее тест — поэтому история git читается как чистая, разделенная пополам история TDD. Используйте этот навык всякий раз, когда пользователь просит зафиксировать, говорит «зафиксировать это», «зафиксировать изменения», «сделать коммит», «завершить фиксацию» или всякий раз, когда проиндексированный/непроиндексированный дифференциал содержит парные исходные и тестовые файлы (foo.ts + foo.test.ts, foo.py + test_foo.py, foo.go + foo_test.go, Foo.java + FooTest.java и т. д.) — даже если пользователь этого не делает явно скажите «атомарные» или «обычные коммиты». Предпочитайте этот навык простой фиксации всякий раз, когда файлы реализации и тестовые файлы появляются вместе в файле различий.
