为 TDD 工作流程创建原子常规提交。将包含实现和测试更改的工作树拆分为每个功能的两次提交 - 首先是实现，然后是测试 - 因此 git 历史读起来就像一个干净的、可平分的 TDD 故事。每当用户要求提交、说“提交此”、“提交更改”、“进行提交”、“完成提交”时，或者每当暂存/未暂存的 diff 包含配对的源文件和测试文件（foo.ts + foo.test.ts、foo.py + test_foo.py、foo.go + foo_test.go、Foo.java + FooTest.java 等）时，都可以使用此技能 - 即使用户没有明确表示“原子”或“常规提交”。当实现和测试文件一起出现在 diff 中时，优先使用此技能而不是普通提交。
