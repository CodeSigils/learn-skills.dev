Erstellen Sie atomare konventionelle Commits für TDD-Workflows. Teilt einen Arbeitsbaum, der sowohl Implementierungs- als auch Teständerungen enthält, in zwei Commits pro Feature auf – zuerst die Implementierung, dann deren Test – sodass sich der Git-Verlauf wie eine saubere, halbierbare TDD-Geschichte liest. Verwenden Sie diesen Skill immer dann, wenn der Benutzer zum Commit auffordert, „dieses committen“, „Änderungen committen“, „Commits durchführen“, „Commit abschließen“ sagt oder wenn der bereitgestellte/nicht bereitgestellte Diff gepaarte Quell- und Testdateien enthält (foo.ts + foo.test.ts, foo.py + test_foo.py, foo.go + foo_test.go, Foo.java + FooTest.java usw.) – auch wenn der Benutzer dies nicht ausdrücklich sagt „atomare“ oder „konventionelle Commits“. Bevorzugen Sie diese Fähigkeit gegenüber einem einfachen Commit, wenn Implementierungs- und Testdateien zusammen im Diff erscheinen.
