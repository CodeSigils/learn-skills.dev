Adversarial review. Force yourself to take the “opposing side” and conduct aggressive reviews of proposals, code, articles, decisions, or any output, actively seeking flaws, blind spots, vulnerabilities, and counterexamples instead of simply confirming that everything is fine. Symmetrical to first‑principles (generation control), this skill handles “validation”—used when a user wants to confirm that something is truly error‑free and can stand up to scrutiny. Typical scenarios: bug hunting before code deployment, logical nit‑picking of articles or proposals, rebutting business plans, risk assessment of decisions, system robustness testing. As long as the user mentions “review / find vulnerabilities / pick flaws / spot problems / any issues / can it hold up / boundary cases / counterexamples / attack / stress test / can it go live / confirm no problems,” or says “help me see if this thing is stable / will it break,” this skill is triggered. Especially when the user says “enable multi‑agent adversarial review,” it will definitely activate.
