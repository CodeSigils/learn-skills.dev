Revisión contradictoria. Tome con fuerza el “lado opuesto” para realizar una auditoría agresiva de propuestas, códigos, artículos, decisiones o cualquier resultado, buscando activamente fallas, puntos ciegos, vulnerabilidades y contraejemplos en lugar de simplemente confirmar que todo está bien. Simétrica a los primeros principios (generación), esta habilidad gobierna la “validación”, que se utiliza cuando el usuario quiere confirmar que algo es verdaderamente impecable y puede resistir la presión. Escenarios típicos: búsqueda de errores antes de que el código entre en funcionamiento, selección lógica de artículos/planes, refutación de propuestas comerciales, evaluación de riesgos de decisiones, pruebas de solidez del sistema. Cada vez que el usuario menciona "revisar / encontrar errores / quisquillosos / detectar problemas / hay algún problema / puede retrasarse / casos extremos / contraejemplos / ataque / prueba de estrés / se puede iniciar / confirmar que no hay problemas", o dice "ayúdame a ver si esto es estable / habrá error", se activa esta habilidad. Especialmente cuando el usuario dice "activar la revisión adversarial de múltiples agentes", definitivamente se activará.
