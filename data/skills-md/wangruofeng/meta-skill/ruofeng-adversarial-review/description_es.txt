Revisión contradictoria. Oblíguese a tomar el “lado opuesto” y realice revisiones agresivas de propuestas, códigos, artículos, decisiones o cualquier resultado, buscando activamente fallas, puntos ciegos, vulnerabilidades y contraejemplos en lugar de simplemente confirmar que todo está bien. Simétrica a los primeros principios (control de generación), esta habilidad maneja la “validación”, que se utiliza cuando un usuario quiere confirmar que algo está verdaderamente libre de errores y puede resistir el escrutinio. Escenarios típicos: búsqueda de errores antes de la implementación del código, selección lógica de artículos o propuestas, refutación de planes de negocios, evaluación de riesgos de decisiones, pruebas de solidez del sistema. Siempre que el usuario mencione "revisar / encontrar vulnerabilidades / detectar fallas / detectar problemas / cualquier problema / puede resistir / casos límite / contraejemplos / ataque / prueba de estrés / puede funcionar / confirmar que no hay problemas", o dice "ayúdame a ver si esto es estable / se romperá", se activa esta habilidad. Especialmente cuando el usuario dice "habilitar revisión adversarial de múltiples agentes", definitivamente se activará.
