エンジニアリング マネージャーがチームのデリバリーを測定および改善するのを支援します。一般的なメトリクスが失敗する理由の履歴、DORA の 4 つの主要なメトリクス フレームワーク (デプロイ頻度、リード タイム、変更失敗率、MTTR)、DevEx の 3 つの側面 (フィードバック ループ、認知負荷、フロー状態)、エンジニアリング メトリクスからビジネス成果への変換レイヤー、避けるべき測定のアンチパターンのリストを生成します。ユーザーが「生産性を測定するにはどうすればよいか」、「DORA メトリクス」、「速度」、「サイクル タイム」、「開発者のエクスペリエンス」、「DevEx」、「チームのパフォーマンスが良いことを示すにはどうすればよいか」、「エンジニアリングのメトリクス」、「チームの速度が遅い」、「エンジニアリングのパフォーマンス」、または「エンジニアリングをビジネスに結び付ける」といった場合に使用します。パフォーマンスの低い個人の管理には使用しないでください。代わりにパフォーマンス レビューを使用してください。
