Nehmen Sie eine Next.js-App, die auf dem Computer des Benutzers ausgeführt wird, und setzen Sie sie auf Vercel in die Produktion ein – indem Sie die benötigte Datenbank, den Dateispeicher, Hintergrundjobs und Zahlungen bereitstellen, alle Umgebungsvariablen festlegen, einmal bereitstellen und dann beweisen, dass die Live-Site tatsächlich funktioniert. Verwenden Sie diese Option, wenn der Benutzer eine App bereitstellen, versenden, veröffentlichen, starten oder live schalten möchte. wenn sie mit dem Bau fertig sind und fragen, wie sie es online stellen können; oder wenn eine bereits bereitgestellte App eine Datenbank, eine benutzerdefinierte Domäne, eine E-Mail-Domäne oder eine ordnungsgemäß verkabelte Integration benötigt. Umfasst Preflight- und Stack-Erkennung, Bereitstellung von Postgres- und Blob-Speicher, Konvertierung einer SQLite-App, damit sie auf einem schreibgeschützten Dateisystem ausgeführt werden kann, benutzerdefinierte Domänen und DNS, OAuth-Rückruf-URLs, E-Mail-Domänenüberprüfung, Synchronisierung von Hintergrundjobs, Zahlungen, Agentenzugriff über MCP und einen Abschlussdurchgang, der die bereitgestellte Site überprüft, anstatt sich auf das Wort der Bereitstellung zu verlassen.
