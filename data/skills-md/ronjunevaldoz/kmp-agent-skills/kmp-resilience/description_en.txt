Resilience patterns for Kotlin Multiplatform — retry with exponential backoff and jitter, timeouts, circuit breakers, rate limiting, idempotency keys for safe mutation retries, and transient-vs-fatal error classification. Covers Ktor's built-in HttpRequestRetry (client) and RateLimit (server) plugins, kotlinx.coroutines' withTimeout, and why KMP has no cross-platform circuit-breaker library (Resilience4j is JVM-only) — a hand-rolled state machine is the honest default. Also covers auditing resilience parity across multiple platform-specific implementations of the same capability (multiple actuals, or multiple selectable backends) — a real, evidence-backed gap: one implementation handling recoverable failures while a sibling implementation doesn't is a parity bug, not a platform difference.
