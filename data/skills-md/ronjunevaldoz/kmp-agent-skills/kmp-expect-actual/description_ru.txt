Механизм ожидания/факта в Kotlin Multiplatform — когда его использовать, когда НЕ следует и как это делать правильно. Охватывает: четыре категории, которые действительно гарантируют ожидаемое/фактическое (API-интерфейсы платформы, типы платформ, критичный к производительности код, интеграция SDK), общее правило, которое предпочитает чистую реализацию commonMain перед абстракциями, альтернативу внедрения интерфейса, которая лучше обрабатывает большинство случаев, антишаблон «актуально везде», типалиасы, актуальные для типов платформы, @ObjCName для чистых поверхностей Swift API и соображения Kotlin/Native Memory. Ноль новых зависимостей.
