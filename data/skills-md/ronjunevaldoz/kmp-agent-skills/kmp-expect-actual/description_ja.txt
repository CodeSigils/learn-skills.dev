Kotlin Multiplatform の expect/actual メカニズム ― 使うべきとき、使うべきでないとき、そして正しく実装する方法。取り上げる内容は次の通りです: 本当に expect/actual が必要となる 4 つのカテゴリ（プラットフォーム API、プラットフォーム型、パフォーマンスクリティカルなコード、SDK 統合）、抽象化に入る前に純粋な `commonMain` 実装を優先する「common‑first」ルール、ほとんどのケースでより適切に対処できるインターフェース注入の代替手段、「actual everywhere」アンチパターン、プラットフォーム型向けの typealias actual、クリーンな Swift API を実現する @ObjCName、そして Kotlin/Native のメモリ考慮事項。新たな依存関係は一切不要です。
