Le mécanisme expect/actual dans Kotlin Multiplatform — quand l’utiliser, quand NE PAS l’utiliser, et comment le faire correctement. Couvre : les quatre catégories qui justifient réellement expect/actual (API de plateforme, types de plateforme, code critique pour la performance, intégration de SDK), la règle « common‑first » qui privilégie une implémentation pure `commonMain` avant les abstractions, l’alternative d’injection d’interfaces qui gère la plupart des cas de façon plus efficace, l’anti‑pattern « actual everywhere », le typealias actual pour les types de plateforme, @ObjCName pour des surfaces d’API Swift épurées, et les considérations de mémoire sur Kotlin/Native. Aucune nouvelle dépendance.
