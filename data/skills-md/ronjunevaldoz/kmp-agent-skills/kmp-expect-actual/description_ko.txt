Kotlin Multiplatform의 expect/actual 메커니즘 — 언제 사용하고 언제 사용하면 안 되는지, 그리고 올바르게 적용하는 방법. 다음 내용을 다룸: expect/actual이 진정으로 필요한 네 가지 카테고리(플랫폼 API, 플랫폼 타입, 성능이 중요한 코드, SDK 통합), 추상화 전에 순수 `commonMain` 구현을 우선시하는 common‑first 규칙, 대부분의 경우를 더 잘 처리하는 인터페이스 주입 방식, “actual everywhere” 안티패턴, 플랫폼 타입을 위한 typealias actual, 깔끔한 Swift API 표면을 위한 @ObjCName, 그리고 Kotlin/Native 메모리 고려사항. 새로운 의존성은 전혀 추가되지 않음.
