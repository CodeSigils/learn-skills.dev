Verwenden Sie diese Option, um ein kleines, fokussiertes Bedrohungsmodell für die aktuelle Arbeit oder neuen Code zu erstellen – eine Funktion, einen Dienst, eine API oder die Änderungen im aktuellen Zweig. Zerlegt das System in Assets, Einstiegspunkte und Vertrauensgrenzen, zählt Bedrohungen mit STRIDE auf und zeichnet Abhilfemaßnahmen und Restrisiken in einem nachvollziehbaren Bericht mit einem Datenflussdiagramm auf. Rufen Sie Standalone auf, um eine Bedrohungsmodellierung für eine Komponente durchzuführen, oder aus einem anderen Ablauf (incu-way-development nach dem PRD/Plan, incu-way-bugs für einen sicherheitsrelevanten Fix), um Bedrohungen aufzudecken, bevor Code geschrieben oder versendet wird. Besonders wichtig für neue externe Oberflächen, Authentifizierungs-/Zahlungs-/PII-Abläufe oder Änderungen der Vertrauensgrenzen.
