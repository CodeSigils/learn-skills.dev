Utilisez‑le pour créer un modèle de menace petit et ciblé pour le travail en cours ou le nouveau code — une fonctionnalité, un service, une API, ou les changements sur la branche actuelle. Décompose le système en actifs, points d’entrée et limites de confiance, répertorie les menaces selon STRIDE, et consigne les mesures d’atténuation ainsi que le risque résiduel dans un rapport traçable accompagné d’un diagramme de flux de données. Invoquez‑le de façon autonome pour modéliser la menace d’un composant, ou depuis un autre flux (incu‑way‑development après le PRD/plan, incu‑way‑bugs pour une correction pertinente du point de vue sécurité) afin de faire apparaître les menaces avant que le code ne soit écrit ou déployé. Particulièrement important pour les nouvelles surfaces externes, les flux d’authentification/paiement/PII, ou les changements de limites de confiance.
