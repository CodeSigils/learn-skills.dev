Planifiez un changement de code non trivial de bout en bout : triage des tailles (XS-XL), stratégie de découpage, répartition facultative de sous-agents parallèles, implémentation par tranche → Test → Vérifier → Valider la discipline. À utiliser pour toute modification multi-fichiers, refactorisation sur plusieurs fichiers, exécution d'une tâche planifiée à partir de n'importe quelle source de planification, modification transversale (balayage analytique / i18n / migration de bibliothèque) ou lorsque vous êtes sur le point d'écrire plus de ~ 100 lignes. Ignorer uniquement pour les modifications XS triviales et les modifications pures de documentation/configuration.
