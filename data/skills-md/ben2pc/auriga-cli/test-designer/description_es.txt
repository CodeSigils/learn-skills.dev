Diseñe pruebas fallidas para funciones complejas mediante evaluación independiente: envía un agente libre de contexto que solo ve las especificaciones de requisitos y las rutas de código (no el enfoque de implementación) y luego devuelve pruebas fallidas ejecutables. Úselo al iniciar TDD para una característica no trivial, cuando el requisito es lo suficientemente ambiguo como para que las pruebas sesgadas sean un riesgo o cuando el usuario solicita un diseño de prueba independiente.
