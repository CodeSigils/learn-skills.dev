Revisa si un diseño es SÓLIDO (resuelve el problema correcto, derivado de sus objetivos y limitaciones establecidos) y emite hallazgos clasificados y respaldados por evidencia, no ediciones. Lea cuando se le solicite "revisar este diseño", "es sólido este diseño", "probar esta propuesta", "hacer una revisión del diseño", "resuelve esto el problema correcto", "hacer agujeros en esta especificación", "deberíamos construir esto" o para criticar una propuesta/especificación/ADR/arquitectura o decisión de producto. NO lea cuando el usuario quiera AUTOR uno de estos: enrutar una nueva propuesta es enmarcar una propuesta, una especificación es escribir una especificación, un registro de decisión es registrar una decisión, una autopsia es escribir una autopsia. NO lea para revisar el código de una diferencia o para verificar afirmaciones individuales (es decir, un pase de corrección, un trabajo diferente).
