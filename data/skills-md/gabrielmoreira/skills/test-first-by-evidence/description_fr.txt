Écrivez d'abord le test, regardez-le échouer, puis écrivez le moins de code qui réussit. Couvre la place du test, ce qui le rend honnête, ce qu'un test réussi prouve et ce qu'il ne fait pas, la récupération du moment où le code a été écrit avant le test et le démarrage d'une correction de bogue à partir d'une exécution rouge. Un test que personne n’a vu échouer ne prouve rien. À utiliser lors de l'implémentation d'une fonctionnalité ou d'une correction de bug, lorsqu'un test a été écrit après le code, lorsqu'un test réussit la première fois que vous l'exécutez, ou lorsque l'utilisateur dit « écrire des tests pour ceci », « ajouter une couverture » ou « TDD ceci ». Pas pour juger les tests dans le cadre d'un changement en cours d'examen, ni pour choisir un cadre de test.
