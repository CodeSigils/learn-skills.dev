Schreiben Sie zuerst den Test, beobachten Sie, wie er fehlschlägt, und schreiben Sie dann den wenigsten Code, der besteht. Behandelt, wo der Test hingehört, was ihn ehrlich macht, was ein bestandener Test beweist und was nicht, die Wiederherstellung, wenn Code vor dem Test geschrieben wurde, und das Starten einer Fehlerbehebung aus einem roten Lauf. Ein Test, bei dem niemand zugesehen hat, dass er fehlschlägt, beweist nichts. Verwenden Sie diese Option, wenn Sie eine Funktion oder einen Bugfix implementieren, wenn ein Test nach dem Code geschrieben wurde, wenn ein Test das erste Mal besteht, dass Sie ihn ausführen, oder wenn der Benutzer „Tests dafür schreiben“, „Abdeckung hinzufügen“ oder „TDD this“ sagt. Nicht zur Beurteilung von Tests innerhalb einer zu prüfenden Änderung und nicht zur Auswahl eines Test-Frameworks.
