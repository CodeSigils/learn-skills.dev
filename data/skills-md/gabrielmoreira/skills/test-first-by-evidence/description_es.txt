Primero escriba la prueba, observe cómo falla y luego escriba el menor código que pase. Cubre dónde pertenece la prueba, qué la hace honesta, qué prueba una prueba aprobada y qué no, cómo recuperar cuándo se escribió el código antes de la prueba e iniciar una corrección de errores a partir de una ejecución roja. Una prueba que nadie vio fallar no prueba nada. Úselo al implementar una característica o una corrección de errores, cuando se escribió una prueba después del código, cuando una prueba pasa la primera vez que la ejecuta o cuando el usuario dice "escribir pruebas para esto", "agregar cobertura" o "TDD esto". No para juzgar las pruebas dentro de un cambio que se está revisando ni para elegir un marco de prueba.
