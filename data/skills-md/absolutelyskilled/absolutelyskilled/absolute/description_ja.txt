AI コーディング エージェント用の集中的な開発ワークフロー エンジン。`/absolute <command> [target]` として呼び出されます。 1 つのスキル、11 のコマンド。 `init` (絶対にどのように動作させたいかをインタビューし、スタックを一度検出してから、JSON 構成を作成します。プロジェクトごとに `.absolute.config.json` を書き、ユーザーのデフォルトとプロジェクトごとのオーバーライド用に `~/.absolute/config.json` を書きます。他のすべてのコマンドは再検出の代わりに読み取ります。ノンブロッキング、他のコマンドはそれをソフト推奨します)。 5 つは、毎日実行するビルド ループをカバーします — 考える → 仕様 → 計画 → ビルド → 磨き → 文書: 「作業」 (エンドツーエンドのフェーズゲート SDLC: 執拗な設計インタビュー → レビューされた仕様 → 依存関係グラフ化されたタスクボード → セーフウェーブ TDD 実行 → 検証)、「仕様」 (軽量スタンドアロン設計仕様: コードベースのスキャン → 境界付き明確化パス → レビューされた設計文書を文書/計画に書き込む → スコアリングされたレビュー担当者サブエージェント → 停止、ビルドなし)、 `ui` (具体的な CSS/Tailwind 値を使用した洗練された意図的なインターフェイス デザイン — タイポグラフィー、カラー、レイアウト、ダーク モード、アクセシビリティ、アニメーション)、`simplify` (作業中の git の変更を自律的に単純化 — 複雑さを軽減し、冗長性を削除し、テストをグリーンに保つ)、および `docs` (Diátaxis 主導のドキュメント — チュートリアル、ハウツー、リファレンス、説明、README、ADR、スタック検出とコードで検証された精度)。さらに 5 つがコードベースの健全性を維持します — グリーン メインでの常駐メンテナンス、それぞれがリスク ランク付けされ、ゲートされたセーフ ウェーブ スキャンと修正です。「アップグレード」 (依存関係のアップグレード — 古い/脆弱な DEP がセムバー ウェーブで衝突され、メジャーがゲートされ変更ログが読み取られ、それぞれの後にグリーン テストが実行されます)、「監査」 (脆弱性とセキュリティ スキャン — 依存関係 CVE と危険なコード パターン、重大度のトリアージと修復。防御的、独自のリポジトリ上)、`prune` (デッド コードと依存関係のクリーンアップ — 未使用の deps、エクスポート、証拠とともに削除されたファイル、リポジトリ全体)、`debt` (lint とタイプチェックの債務返済 — ルールによって既存の警告/エラーと抑制をクリアし、チェッカーを不正行為しない)、および `deflake` (不安定なテスト修正 — ルートの非決定性を診断して修正します。再試行/スキップ/スリープ)。 「absolute init|work|spec|ui|simplify|docs|upgrade|audit|prune|debt|deflake」、「絶対設定を設定する」、「絶対設定を初期化する」、「絶対設定を設定する」、「これをエンドツーエンドで構築する」、「計画と構築」、「これについて詳しく調べてください」、「仕様を書く」、「設計文書を作成する」、「この UI を設計する」、「これを AI らしくなくする」でトリガーします。 「手抜き」、「簡略化する」、「変更をクリーンアップする」、「ドキュメントを作成する」、「ドキュメントを監査する」、「依存関係をアップグレードする」、「脆弱かどうか」、「セキュリティ監査」、「デッドコードを削除する」、「lint/type エラーを修正する」、「不安定なテストを修正する」、または複数ステップの開発、設計、クリーンアップ、ドキュメント、またはメンテナンスのタスク。
