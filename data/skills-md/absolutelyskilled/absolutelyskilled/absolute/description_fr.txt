Un moteur de workflow de développement ciblé pour les agents de codage d'IA, appelé comme « /absolute <command> [target] ». Une compétence, onze commandes. On le configure : `init` (interrogez comment vous voulez qu'Absolute se comporte + détectez la pile une fois, puis écrivez la configuration JSON — `.absolute.config.json` par projet et `~/.absolute/config.json` pour les valeurs par défaut de l'utilisateur et les remplacements par projet — que toutes les autres commandes lisent au lieu de re-détecter ; non bloquant, les autres le recommandent doucement). Cinq couvrent la boucle de construction que vous exécutez tous les jours - réflexion → spécification → planifier → construire → peaufiner → document : `travail` (SDLC de bout en bout et à phases contrôlées : entretien de conception incessant → spécification révisée → tableau de tâches graphique en dépendances → exécution TDD sécurisée → vérification), `spec` (spécification de conception autonome légère : analyse de la base de code → passe de clarification délimitée → écrire un document de conception révisé dans docs/plans → sous-agent de réviseur noté → arrêter, pas de construction), `ui` (conception d'interface soignée et intentionnelle avec des valeurs CSS/Tailwind concrètes — typographie, couleur, mise en page, mode sombre, accessibilité, animations), `simplify` (simplifiez de manière autonome vos modifications git de travail — réduisez la complexité, supprimez la redondance, gardez les tests verts) et `docs` (documentation basée sur Diataxis — tutoriels, procédures, référence, explication, README, ADR, avec détection de pile et précision vérifiée par le code). Cinq autres maintiennent la base de code en bonne santé - maintenance permanente sur le principal vert, chacun étant une analyse et une correction sécurisées, classées par risque : "mise à niveau" (mises à niveau des dépendances - dépôts obsolètes/vulnérables modifiés par vagues semver, majors fermées et lecture du journal des modifications, tests verts après chaque), "audit" (analyse de vulnérabilité et de sécurité - CVE de dépendances plus modèles de code à risque, triés par gravité et corrigés ; défensif, sur votre propre dépôt), `prune` (nettoyage du code mort et des dépendances - dépôts inutilisés, exportations, fichiers supprimés avec preuves, à l'échelle du dépôt), `debt` (remboursement de la dette en peluches et vérification de type - effacer les avertissements/erreurs et suppressions préexistants par règle, pas de tricherie avec le vérificateur) et `deflake` (correctifs de tests floconneux - diagnostiquer et corriger le non-déterminisme racine, ne jamais réessayer/sauter/mettre en veille).
