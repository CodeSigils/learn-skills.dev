Механизм целенаправленного рабочего процесса разработки для агентов кодирования ИИ, вызываемый как `/absolute <command> [target]`. Один навык, одиннадцать команд. Один настраивает его: `init` (опросите, как вы хотите, чтобы Absolute вел себя + один раз определите стек, затем напишите конфигурацию JSON — `.absolute.config.json` для каждого проекта и `~/.absolute/config.json` для пользовательских настроек по умолчанию и переопределений для каждого проекта - которые каждая другая команда считывает вместо повторного обнаружения; неблокируется, остальные мягко рекомендуют его). Пять охватывают цикл сборки, который вы запускаете каждый день — думать → спецификация → план → сборка → доработка → документ: `работа` (сквозной, поэтапный SDLC: неустанное собеседование по дизайну → проверенная спецификация → панель задач с графиком зависимостей → безопасное выполнение TDD → проверка), `spec` (облегченная автономная спецификация дизайна: сканирование кодовой базы → ограниченный проход уточнения → запись проверенного проектного документа в документы/планы → оцененный субагент рецензента → остановка, нет сборки), `ui` (отточенный, продуманный дизайн интерфейса с конкретными значениями CSS/Tailwind — типографика, цвет, макет, темный режим, специальные возможности, анимация), «simplify» (автономно упрощайте рабочие изменения git — уменьшайте сложность, удаляйте избыточность, сохраняйте тесты зелеными) и «docs» (документация на основе Diátaxis — учебные пособия, инструкции, ссылки, объяснения, README, ADR, с обнаружением стека и точностью, проверенной кодом). Еще пять поддерживают работоспособность кодовой базы — постоянное обслуживание на зеленой основной линии, каждое из которых представляет собой ранжированное, закрытое, безопасное сканирование и исправление с ранжированием по рискам: «обновление» (обновления зависимостей — устаревшие/уязвимые версии, возникающие в несколько волн, основные закрыты и читаются журналы изменений, тесты зеленые после каждого), «аудит» (сканирование уязвимостей и безопасности — зависимости CVE плюс рискованные шаблоны кода, сортировка по степени серьезности и исправление; защита, в вашем собственном репозитории), `prune` (очистка неиспользуемого кода и зависимостей — неиспользуемые данные, экспорт, файлы, удаленные с доказательствами, по всему репозиторию), `debt` (очистка и проверка типов, выплата долга — удаление ранее существовавших предупреждений/ошибок и подавлений по правилам, без обмана проверяющего устройства) и `deflake` (ненадежные тестовые исправления — диагностируйте и исправляйте корневой недетерминизм, никогда не повторяйте попытки/пропускайте/пересыпайте). Триггеры по «абсолютному инициализации|работе|спецификации|ui|simplify|docs|upgrade|audit|prune|debt|deflake», «настроить абсолютный», «инициализировать абсолютный», «настроить абсолютный», «построить это сквозное», «планировать и построить», «допросить меня по этому поводу», «написать спецификацию», «составить проектный документ», «спроектировать этот пользовательский интерфейс», «сделать это менее похожим на отстой ИИ», «упростить это», «очистить» «внести мои изменения», «написать документацию», «проверить нашу документацию», «обновить наши зависимости», «являемся ли мы уязвимыми», «аудит безопасности», «удалить мертвый код», «исправить ошибки lint/type», «исправить нестабильные тесты» или любую многоэтапную разработку, проектирование, очистку, документацию или задачу обслуживания.
