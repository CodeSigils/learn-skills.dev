Installer ou auditer l'observabilité de Latitude LLM : envoie des traces des SDK LLM (OpenAI, Anthropic, Bedrock, Cohere, TogetherAI, Vertex AI, Google AI Platform, OpenAI Agents, Vercel AI SDK, Mastra, LangChain, LlamaIndex) à un projet Latitude. TypeScript via `@latitude-data/telemetry`, Python via `latitude-telemetry` et tout autre langage pris en charge par OpenTelemetry (Go, Java, Ruby, .NET, PHP, Rust, Elixir, …) via HTTP OTLP direct. À utiliser lorsque l'utilisateur demande d'ajouter le traçage Latitude, de connecter Latitude à une configuration OpenTelemetry existante, de corriger les traces manquantes dans Latitude ou d'auditer une intégration existante. Couvre la découverte de la base de code (OTel existant, les fournisseurs d'observabilité LLM en conflit, quels SDK LLM sont utilisés, où les appels LLM ont lieu), le bootstrap basé sur les classes (`new Latitude({...})` dans TS, `Latitude(...)` dans Python), la configuration avancée avec `LatitudeSpanProcessor` et `registerLatitudeInstrumentations`, `capture()` facultatif pour le contexte utilisateur/session/tags (et par capture `projectSlug` pour les applications multi-projets), les variables d'environnement (`LATITUDE_API_KEY`, `LATITUDE_PROJECT_SLUG`) et un chemin de secours OTLP pour les bases de code non TS/Python.
