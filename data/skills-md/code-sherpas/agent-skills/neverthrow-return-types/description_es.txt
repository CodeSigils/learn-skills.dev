Requerir tipos de retorno basados ​​en `neverthrow` en código TypeScript y JavaScript siempre que la tecnología circundante lo permita. Utilícelo al crear, refactorizar, revisar o ampliar funciones independientes, funciones de módulos exportados, métodos de clase, métodos de objeto, métodos de servicio, métodos de repositorio y API similares que deben exponer tipos de resultados explícitos de éxito y error en sus firmas. Prefiera `Result<T, E>` para código sincrónico y `ResultAsync<T, E>` para código asincrónico. Solo omita un tipo de devolución "neverthrow" cuando un marco, biblioteca, interfaz de tiempo de ejecución o contrato impuesto externamente sea incompatible y requiera una forma de devolución diferente.
