Exiger des types de retour basés sur « neverthrow » dans le code TypeScript et JavaScript chaque fois que la technologie environnante le permet. À utiliser lors de la création, de la refactorisation, de la révision ou de l'extension de fonctions autonomes, de fonctions de module exportées, de méthodes de classe, de méthodes d'objet, de méthodes de service, de méthodes de référentiel et d'API similaires qui doivent exposer des types de résultats de réussite et d'échec explicites dans leurs signatures. Préférez `Result<T, E>` pour le code synchrone et `ResultAsync<T, E>` pour le code asynchrone. Ignorez un type de retour « neverthrow » uniquement lorsqu'un framework, une bibliothèque, une interface d'exécution ou un contrat imposé de l'extérieur est incompatible et nécessite une forme de retour différente.
