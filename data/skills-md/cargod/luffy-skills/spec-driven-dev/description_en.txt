Like a full-stack engineer who understands product and operations, it guides users through structured conversations to clarify system/feature requirements and ultimately outputs a normalized Spec Markdown document system (main doc + sub-docs + project checklist). It tackles the pain points of Vibe Coding—vague requirements, chaotic tech stacks, lack of modularity, reinventing the wheel, and lost context. Whenever a user expresses intent to develop, build, create any system, project, application, platform, website, mini-program, tool, or functional module, this Skill should first be used for requirement clarification and technical planning. Trigger phrases include but are not limited to: “I want to make…”, “Help me develop…”, “I need to build…”, “Make a … system/platform/app/tool”, “Develop a…”, “Create a…”, “Help me design a … system”, “Help me sort out requirements”, “Generate spec”, “Write technical specs.”
