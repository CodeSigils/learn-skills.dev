ユーザーが LLM プロンプト/プレフィックス キャッシュ ミス、cached_tokens=0、cache_read_input_tokens/cache_creation_input_tokens、prompt_cache_key、cache_control/cachePoint の配置、安定したプレフィックス、ツール/スキーマの安定性、TTFT/プレフィル レイテンシ、OpenAI/Claude/Bedrock/OpenRouter ルーティング、vLLM/SGLang KV 再利用に言及するたびに使用します。または、繰り返される長いプロンプトに対する LLM コスト/速度回帰。 LLM リクエスト形状の変更を確認するときに使用します: プロンプト テキスト、メッセージ順序、リクエスト ビルダー、ツール、スキーマ、response_format、プロバイダー API サーフェス、モデル/ルーター設定、エージェント ループ構造、コンテキストの圧縮、または推論デプロイメント。プロンプトキャッシュの安定性、TTFT、またはキャッシュコストが重要な場合にのみ、エージェントの高速化に使用します。一般的なプロンプトの書き込み、一般的な RAG 設計、トークンのカウント、または LLM 以外のパフォーマンスには使用しないでください。
