Анализируйте документы функциональных спецификаций (FSD) и создавайте артефакты Markdown — спецификации API (spec_api.md), ERD (erd.md + дополнительный DBML для dbdiagram.io), диаграммы UML (PlantUML для последовательности, класса, активности, состояния, компонента, варианта использования), карты задач разработчика (task.md) с Story Points и временные диаграммы HTML Gantt. Также выполните анализ пробелов (FSD по сравнению с существующими ERD/API), проверки согласованности между артефактами (ERD по сравнению с API и задачами) и оценку сроков разработки с отслеживанием зависимостей и анализом критического пути. Используйте, когда пользователь предоставляет или ссылается на FSD, бизнес-требования или просит сгенерировать/сравнить технические спецификации, найти пробелы в текущей базе данных или API, проверить согласованность между ERD и спецификацией, преобразовать требования в готовую для разработчиков документацию, оценить сроки разработки или назначить задачи разработчикам — даже без слов «FSD» или «системный аналитик».
