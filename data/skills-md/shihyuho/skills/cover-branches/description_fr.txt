Recherchez les lacunes de couverture des branches dans le code modifié et corrigez-les en écrivant les tests manquants. Deux couches d'analyse : Source ↔ Test (branches logiques vs cas de test) et Spec ↔ Test (scénarios d'exigences vs cas de test, lorsqu'un fichier de spécifications est fourni). À utiliser pour vérifier l'intégralité des tests après l'implémentation d'une fonctionnalité ou la correction d'un bogue, pour vérifier si les tests correspondent à une spécification ou pour suspecter des branches non testées.
