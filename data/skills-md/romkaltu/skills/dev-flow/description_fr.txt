Exécutez un workflow git basé sur des tickets : choisissez la branche de base, associez le travail à un ticket de gestion de projet, nommez les branches et les commits, ouvrez les PR sur la bonne base, vérifiez avant examen et déplacez les statuts des tickets. À utiliser pour démarrer un travail à partir d'un identifiant de ticket ou d'un numéro nu, lancer un fichier plan/spec/PRD/todo, demander quelle branche utiliser, ouvrir un PR, synchroniser l'état du tracker après un travail de branche ou de fusion, ou configurer/reconfigurer `.dev-flow/config.json` pour les paramètres de tracker, de branche de base, de PR, de validation ou de suivi du temps. Ne pas utiliser pour la révision du code d'un PR existant, les validations ponctuelles sur une branche déjà créée, la division d'un plan en plusieurs problèmes, l'écriture de PRD, la configuration de CI, la promotion de branche de publication/intégration ou les questions pratiques génériques sur git.
