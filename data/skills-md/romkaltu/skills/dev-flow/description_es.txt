Ejecute un flujo de trabajo de Git basado en tickets: elija la rama base, vincule el trabajo a un ticket de gestión de proyectos, nombre las ramas y confirmaciones, abra PR en la base correcta, verifique antes de revisar y mueva los estados de los tickets. Úselo al comenzar a trabajar desde una identificación de ticket o un número simple, iniciar un archivo de plan/especificación/PRD/todo, preguntar qué rama usar, abrir un PR, sincronizar el estado del rastreador después del trabajo de rama o fusión, o configurar/reconfigurar `.dev-flow/config.json` para las configuraciones de rastreador, rama base, PR, confirmación o seguimiento de tiempo. No lo use para revisión de código de un PR existente, confirmaciones únicas en una rama ya creada, dividir un plan en muchos temas, escribir PRD, configurar CI, promoción de rama de lanzamiento/integración o preguntas genéricas sobre procedimientos de git.
