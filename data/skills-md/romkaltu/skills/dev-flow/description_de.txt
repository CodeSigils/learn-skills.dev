Führen Sie einen Ticket-gesteuerten Git-Workflow aus: Wählen Sie den Basiszweig aus, verknüpfen Sie die Arbeit mit einem Projektmanagement-Ticket, benennen Sie Zweige und Commits, öffnen Sie PRs für die richtige Basis, überprüfen Sie sie vor der Überprüfung und verschieben Sie den Ticketstatus. Verwenden Sie diese Option, wenn Sie mit der Arbeit von einer Ticket-ID oder einer bloßen Nummer aus beginnen, eine Plan-/Spezifikations-/PRD-/Todo-Datei starten, fragen, welcher Zweig verwendet werden soll, einen PR öffnen, den Tracker-Status nach Zweig- oder Zusammenführungsarbeiten synchronisieren oder „.dev-flow/config.json“ für Tracker-, Basiszweig-, PR-, Commit- oder Zeitverfolgungseinstellungen einrichten/neu konfigurieren. Nicht für die Codeüberprüfung eines vorhandenen PR, einmalige Commits für einen bereits erstellten Branch, das Aufteilen eines Plans in viele Issues, das Schreiben von PRDs, das Konfigurieren von CI, die Heraufstufung von Release-/Integrationszweigen oder allgemeine Git-How-to-Fragen verwenden.
