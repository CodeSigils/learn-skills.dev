エンドツーエンドの GitHub 課題ワークフロー、リポジトリに依存しない — 課題を読み取り、計画し、プロジェクト ボード (存在する場合) で「進行中」に移動し、効率的な寓話オーケストレーションで実装し、記録された GIF で UI の変更を確認し、ラベルとマイルストーンを使用して「レビュー中」に設定されたテンプレート準拠の PR を開き、レビューのために Slack で発表します (接続されている場合)。 +args として追加のスキルをサポートします (例: "/work-issue <url> +shadcn +animate")。ユーザーが GitHub の問題の URL または問題番号を貼り付けて、その問題に取り組みたい場合に使用します (「この問題に取り組む」、「ピックアップする」など)。
