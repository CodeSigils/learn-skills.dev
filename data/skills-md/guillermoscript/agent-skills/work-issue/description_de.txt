End-to-End-GitHub-Issue-Workflow, Repo-unabhängig – lesen Sie ein Issue, planen Sie es, verschieben Sie es auf dem Projektboard (sofern vorhanden) in „In Bearbeitung“, implementieren Sie es mit effizienter Fable-Orchestrierung, überprüfen Sie UI-Änderungen mit einem aufgezeichneten GIF, öffnen Sie eine vorlagenkonforme PR, die auf „In Prüfung“ gesetzt ist, mit Beschriftungen und Meilensteinen und kündigen Sie sie auf Slack zur Überprüfung an (sofern verbunden). Unterstützt zusätzliche Fähigkeiten als +args (z. B. „/work-issue <url> +shadcn +animate“). Wird immer dann verwendet, wenn der Benutzer eine GitHub-Problem-URL oder eine Problemnummer einfügt und möchte, dass daran gearbeitet wird – „an diesem Problem arbeiten“, „abholen“.
