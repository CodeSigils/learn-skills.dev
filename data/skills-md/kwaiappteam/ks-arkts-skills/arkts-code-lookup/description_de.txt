Suchen Sie basierend auf einer technischen Lösung, Anwendungsanforderungen oder Android-Codeausschnitten nach den erforderlichen öffentlichen HarmonyOS ArkTS-APIs und listen Sie sie auf. Dies sollte ausgelöst werden, wenn ein Benutzer eine Funktionalität beschreibt, die er implementieren möchte oder wissen muss, welche APIs/Kits/Schnittstellen er verwenden soll, zum Beispiel: „Welche API muss ich implementieren…“, „Welche Schnittstellen sind für eine Fotoaufnahmefunktion erforderlich“, „Welches Kit sollte für diese Anforderung verwendet werden“, „Welche HarmonyOS-Funktionen sind in der technischen Lösung enthalten“, „Suchen Sie nach kamerabezogenen APIs“, „Welche Schnittstellen kann ich zum Integrieren von Karten verwenden“. Es sollte auch ausgelöst werden, wenn ein Benutzer einen Anwendungsbedarf beschreibt, ohne explizit Code anzufordern, wie zum Beispiel: „Ich möchte eine IM-App erstellen, die Audio-Video-Aufrufe benötigt“ – in diesem Fall alle relevanten APIs identifizieren. Wenn ein Benutzer Android-Codeausschnitte (Java/Kotlin) bereitstellt und nach den entsprechenden HarmonyOS-APIs fragt, sollte dies ebenfalls ausgelöst werden, z. B. „Welche API würde diesen Android-Code auf HarmonyOS implementieren“, „Helfen Sie mir, diese Android-Funktion auf HarmonyOS zu migrieren, welche Schnittstellen werden benötigt“ – analysieren Sie den Android-Code und ordnen Sie ihn den entsprechenden HarmonyOS-APIs zu. Zu den Trigger-Schlüsselwörtern gehören: welche APIs benötigt werden, welche Schnittstellen verwendet werden sollen, Such-API, beteiligte Funktionen, Komponenten, technische Lösung, API-Dokumentation, Dokumentationspfad, HarmonyOS-Migration, Android-Migration, Android-Code, insbesondere in Kombination mit ArkTS/HarmonyOS/Harmony/ability/UIAbility/ArkUI oder einem beliebigen Kit-Namen. Wenn der Benutzer explizit das Schreiben oder Generieren einer .ets-Codedatei anfordert, sollte dieser Skill nicht ausgelöst werden. 

Bitte antworten Sie immer in der Sprache des Benutzers.
