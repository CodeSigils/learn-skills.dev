En fonction d'une solution technique, des exigences de l'application ou d'extraits de code Android, recherchez et répertoriez les API publiques HarmonyOS ArkTS requises. Cela doit être déclenché lorsqu'un utilisateur décrit une fonctionnalité qu'il souhaite implémenter ou a besoin de savoir quelles API/Kits/interfaces utiliser, par exemple : « Quelle API dois-je implémenter… », « Quelles interfaces sont requises pour une fonction de capture de photos », « Quel kit doit être utilisé pour cette exigence », « Quelles fonctionnalités HarmonyOS sont impliquées dans la solution technique », « Rechercher les API liées à la caméra », « Quelles interfaces puis-je utiliser pour intégrer des cartes ». Il doit également être déclenché lorsqu'un utilisateur décrit un besoin d'application sans demander explicitement de code, par exemple : « Je souhaite créer une application de messagerie instantanée qui nécessite des appels audio-vidéo » — dans ce cas, identifiez toutes les API pertinentes. Lorsqu'un utilisateur fournit des extraits de code Android (Java/Kotlin) et demande les API HarmonyOS correspondantes, cela doit également être déclenché, par exemple « Quelle API implémenterait ce code Android sur HarmonyOS », « Aidez-moi à migrer cette fonctionnalité Android vers HarmonyOS, quelles interfaces sont nécessaires » – analysez le code Android et mappez-le aux API HarmonyOS appropriées. Les mots-clés déclencheurs incluent : quelles API sont nécessaires, quelles interfaces utiliser, API de recherche, capacités impliquées, composants, solution technique, documentation API, chemin de documentation, migration HarmonyOS, migration Android, code Android, en particulier lorsqu'il est combiné avec ArkTS/HarmonyOS/Harmony/ability/UIAbility/ArkUI ou tout autre nom de kit. Si l'utilisateur demande explicitement l'écriture ou la génération d'un fichier de code .ets, cette compétence ne doit pas être déclenchée. 

Veuillez toujours répondre dans la langue de l’utilisateur.
