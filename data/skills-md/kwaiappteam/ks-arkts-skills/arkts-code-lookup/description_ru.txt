На основе технического решения, требований приложения или фрагментов кода Android найдите и перечислите необходимые общедоступные API-интерфейсы HarmonyOS ArkTS. Это должно срабатывать, когда пользователь описывает функциональность, которую он хочет реализовать, или ему необходимо знать, какие API/наборы/интерфейсы использовать, например: «Какой API мне нужно реализовать…», «Какие интерфейсы необходимы для функции фотосъемки», «Какой комплект следует использовать для этого требования», «Какие возможности HarmonyOS задействованы в техническом решении», «Поиск API, связанных с камерой», «Какие интерфейсы я могу использовать для интеграции карт». Его также следует активировать, когда пользователь описывает потребность приложения без явного запроса кода, например: «Я хочу создать приложение для обмена мгновенными сообщениями, которому необходимы аудио-видео вызовы» — в этом случае определите все соответствующие API. Когда пользователь предоставляет фрагменты кода Android (Java/Kotlin) и запрашивает соответствующие API-интерфейсы HarmonyOS, он также должен быть запущен, например: «Какой API будет реализовывать этот код Android в HarmonyOS», «Помогите мне перенести эту функцию Android в HarmonyOS, какие интерфейсы необходимы» — проанализируйте код Android и сопоставьте его с соответствующими API-интерфейсами HarmonyOS. Ключевые слова-триггеры включают в себя: какие API необходимы, какие интерфейсы использовать, API поиска, задействованные возможности, компоненты, техническое решение, документация API, путь документации, миграция HarmonyOS, миграция Android, код Android, особенно в сочетании с ArkTS/HarmonyOS/Harmony/ability/UIAbility/ArkUI или любым именем комплекта. Если пользователь явно запрашивает написание или создание файла кода .ets, этот навык не должен активироваться.
