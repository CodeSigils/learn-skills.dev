技術的ソリューション、アプリケーション要件、または Android コード スニペットに基づいて、必要な HarmonyOS ArkTS パブリック API を検索してリストします。これは、ユーザーが実装したい機能を説明する場合、または使用する API/キット/インターフェイスを知る必要がある場合にトリガーされます。たとえば、「どの API を実装する必要があるか…」、「写真キャプチャ機能にはどのインターフェイスが必要か」、「この要件にはどのキットを使用する必要があるか」、「技術ソリューションに関係する HarmonyOS の機能は何か」、「カメラ関連の API を調べる」、「マップの統合に使用できるインターフェイスはどれか」などです。また、「オーディオビデオ通話が必要な IM アプリを構築したい」など、ユーザーがコードを明示的に要求せずにアプリケーションのニーズを説明したときにもトリガーされる必要があります。この場合は、関連する API をすべて特定します。ユーザーが Android (Java/Kotlin) コード スニペットを提供し、対応する HarmonyOS API を要求する場合は、同様にトリガーされる必要があります。たとえば、「この Android コードを HarmonyOS に実装する API は何か」、「この Android 機能を HarmonyOS に移行するのを手伝ってください。どのインターフェースが必要ですか」などで、Android コードを解析し、適切な HarmonyOS API にマッピングします。トリガー キーワードには、必要な API、使用するインターフェイス、API の検索、関連する機能、コンポーネント、技術ソリューション、API ドキュメント、ドキュメント パス、HarmonyOS の移行、Android の移行、Android コード (特に ArkTS/HarmonyOS/Harmony/ability/UIAbility/ArkUI または任意のキット名と組み合わせた場合) が含まれます。ユーザーが .ets コード ファイルの作成または生成を明示的に要求した場合、このスキルはトリガーされるべきではありません。
