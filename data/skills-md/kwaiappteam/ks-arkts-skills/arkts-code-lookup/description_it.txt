In base a una soluzione tecnica, ai requisiti dell'applicazione o ai frammenti di codice Android, cercare ed elencare le API pubbliche HarmonyOS ArkTS richieste. Questo dovrebbe essere attivato quando un utente descrive una funzionalità che desidera implementare o ha bisogno di sapere quali API/kit/interfacce utilizzare, ad esempio: "Quale API devo implementare...", "Quali interfacce sono richieste per una funzione di acquisizione di foto", "Quale kit deve essere utilizzato per questo requisito", "Quali funzionalità di HarmonyOS sono coinvolte nella soluzione tecnica", "Cerca le API relative alla fotocamera", "Quali interfacce posso utilizzare per integrare le mappe". Dovrebbe essere attivato anche quando un utente descrive un'esigenza applicativa senza richiedere esplicitamente il codice, ad esempio: "Voglio creare un'app di messaggistica istantanea che necessita di chiamate audio-video"; in questo caso, identificare tutte le API pertinenti. Quando un utente fornisce frammenti di codice Android (Java/Kotlin) e richiede le API HarmonyOS corrispondenti, anche questo dovrebbe essere attivato, ad esempio "Quale API implementerebbe questo codice Android su HarmonyOS", "Aiutami a migrare questa funzionalità Android su HarmonyOS, quali interfacce sono necessarie" - analizza il codice Android e mappalo sulle API HarmonyOS appropriate. Le parole chiave dell'attivatore includono: quali API sono necessarie, quali interfacce utilizzare, API di ricerca, funzionalità coinvolte, componenti, soluzione tecnica, documentazione API, percorso della documentazione, migrazione HarmonyOS, migrazione Android, codice Android, soprattutto se combinato con ArkTS/HarmonyOS/Harmony/ability/UIAbility/ArkUI o qualsiasi nome del kit. Se l'utente richiede esplicitamente la scrittura o la generazione di un file di codice .ets, questa abilità non deve essere attivata. 

Si prega di rispondere sempre nella lingua dell'utente.
