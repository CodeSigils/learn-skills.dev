頻繁な要件変更に応じて、長期的なソフトウェア製品が「単一の真実の情報源としてのドキュメント + 変更のクローズド ループ」を確立できるようにガイドします。要件の取り込みと分類、ユーザー ストーリーと受け入れ基準、スケジュールとコミットメント、ADR/変更台帳、実装の完了とリリース ノート、ユーザー ヘルプ センターのディレクトリとナビゲーションなどです。あらゆるテクノロジースタックに適用可能。ユーザーは、パスと優先順位を宣言するためにプロジェクト ルートで AGENTS.md (または同等のドキュメント マップ) を維持する必要があります。ユーザーがプロジェクトの開始、スケジュール、PRD、ロードマップ、要件の変更、研究開発プロセス、ドキュメントとコーディングをどのように連携させるかについて話し合うときに使用し、ドキュメントの情報アーキテクチャを支援します。マルチステップを実行する前に、提案されたステップとオプション/高リスク項目をユーザーに確認する必要があります。 PDF または Office (DOCX/PPTX/XLSX など) 要件マテリアルを受信すると、このリポジトリの Mineru-office-to-Markdown スキルと連携して、取り込む前にローカルで Markdown に変換できます。 MinerU が利用できない場合は、インストールを案内する前に、まず費用を説明し、ユーザーの同意を得る必要があります。特定のクラウド ベンダーや内部ツールに束縛されません。
