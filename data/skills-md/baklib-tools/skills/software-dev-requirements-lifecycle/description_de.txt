Führen Sie langlebige Softwareprodukte unter häufigen Anforderungsänderungen, um einen „Single Source of Truth + Closed-Loop Change“-Prozess zu etablieren: Anforderungsaufnahme und -klassifizierung, User Stories und Akzeptanz, Planung und Verpflichtung, ADR/Änderungsbuch, Implementierungsabschluss und Versionshinweise sowie Struktur und Navigation des Benutzer-Hilfecenters. Funktioniert mit jedem Tech-Stack; Benutzer müssen eine AGENTS.md (oder eine entsprechende Dokumentzuordnung) im Projektstamm verwalten, in der Pfade und Prioritäten angegeben werden. Verwenden Sie es, wenn Stakeholder über Projektinitiierung, Planung, PRDs, Roadmaps, Anforderungsänderungen, Entwicklungsworkflows, die Abstimmung von Dokumenten mit Code oder die Informationsarchitektur der Hilfeseite diskutieren. Bestätigen Sie vor der mehrstufigen Ausführung die geplanten Schritte und alle optionalen/risikoreichen Elemente mit dem Benutzer. Wenn Sie PDF- oder Office-Anforderungsdateien (DOCX/PPTX/XLSX usw.) erhalten, nutzen Sie die Mineru-Office-to-Markdown-Fähigkeit dieses Repos, um sie vor der Aufnahme lokal in Markdown zu konvertieren. Wenn MinerU nicht verfügbar ist, geben Sie zunächst die Kosten an und holen Sie die Zustimmung des Benutzers ein, bevor Sie mit der Installation beginnen. Keine Bindung an einen bestimmten Cloud-Anbieter oder ein internes Tool.
