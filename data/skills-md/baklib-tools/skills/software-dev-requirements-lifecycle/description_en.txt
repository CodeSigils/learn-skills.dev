Guide long-term software products to establish "Documentation as Single Source of Truth + Change Closed Loop" under frequent requirement changes: requirement intake and categorization, user stories and acceptance criteria, scheduling and commitment, ADR/change ledger, implementation closure and release notes, as well as user help center directory and navigation. Applicable to any technology stack; requires users to maintain AGENTS.md (or equivalent documentation map) at project root to declare paths and priorities. Use when users discuss project initiation, scheduling, PRD, roadmap, requirement changes, R&D process, how documentation coordinates with coding, and help documentation information architecture. Must confirm proposed steps and optional/high-risk items with users before multi-step execution. When receiving PDF or Office (DOCX/PPTX/XLSX, etc.) requirement materials, can work with this repository's mineru-office-to-markdown skill to convert to Markdown locally before Intake; if MinerU is unavailable, must first explain costs and obtain user consent before guiding installation. Not bound to specific cloud vendors or any internal tools.
