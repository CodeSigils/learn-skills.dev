Создавайте задачи GitHub в стиле бережливой спецификации в качестве спецификаций для реализации, согласованной с человеком и искусственным интеллектом, в текущем репозитории. Используйте, когда вас просят «создать спецификацию», «написать проблему спецификации», «описать эту функцию», «описать эту функцию» или при планировании работы, для которой перед реализацией требуется спецификация. Следует методологии SDD с бережливыми спецификациями — небольшие сфокусированные спецификации (<2000 токенов), внимание к реализации, экономия контекста. Создает проблемы GitHub с разделами «Обзор», «Дизайн», «План», «Тестирование», «Согласование» и «Примечания». Таксономия областей, специфичная для репозитория, имена родственных навыков, настраиваемые разделы тела (например, влияние поставщика/влияние схемы/охват) и дополнительные принципы накладываются на CLAUDE.md потребительского репозитория и его родственные навыки `*-dev-process`/`*-pre-push`/`*-pr-lifecycle` — прочитайте их в первую очередь, если репозиторий неочевиден.
