Creare problemi GitHub in stile lean-spec come specifiche per l'implementazione allineata all'intelligenza artificiale umana nel repository corrente. Da utilizzare quando viene richiesto di "creare una specifica", "scrivere un problema di specifica", "specificare questa funzionalità", "specificare questo" o quando si pianifica un lavoro che necessita di una specifica prima dell'implementazione. Segue la metodologia SDD con specifiche snelle: specifiche mirate di piccole dimensioni (<2000 token), intenzione di implementazione, economia del contesto. Crea problemi GitHub con le sezioni Panoramica, Progettazione, Pianificazione, Test, Allineamento e Note. La tassonomia dell'area specifica del repository, i nomi delle competenze sorelle, le sezioni del corpo personalizzate (ad esempio Impatto del fornitore / Impatto dello schema / Copertura) e principi aggiuntivi sono sovrapposti al CLAUDE.md del repository consumer e alle sue competenze sorelle `*-dev-process` / `*-pre-push` / `*-pr-lifecycle`: leggili prima quando il repository non è ovvio.
