Triage fehlgeschlagener CI wird auf einem GitHub-Actions-gesteuerten Repo ausgeführt – klassifizieren Sie Regression vs. Flake vs. Infra, behalten Sie ein einzelnes fortlaufendes „Main-Red“-Problem bei, wenn Main defekt ist, und weisen Sie Menschen auf den verdächtigen Commit hin. Wird verwendet, wenn ein Workflow auf „main“ fehlschlägt oder wenn ein Mensch fragt: „Ist main rot?“, „Warum ist CI auf main fehlgeschlagen?“, „Triage diese Workflow-Ausführung“, „Diesen Fehler klassifizieren“. Gepaart mit dem Skill „<repo>-pr-lifecycle“ des Consumer-Repos (PR-seitige CI-Triage) und dem Skill „Web-Testing“ (aufgerufen bei „e2e“-Fehlern).
