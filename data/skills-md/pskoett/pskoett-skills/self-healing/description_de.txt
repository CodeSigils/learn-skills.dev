Aktive Laufzeitwiederherstellung für Codierungsagenten: Wenn während der Aufgabe etwas kaputt geht, diagnostizieren Sie die Grundursache, schreiben Sie einen Fix, ÜBERPRÜFEN Sie, indem Sie das defekte Ding erneut ausführen, und hinterlegen Sie dann einen „HEAL-“-Eintrag in „.learnings/HEALS.md“ mit Beweis. Wird immer dann verwendet, wenn ein Befehl, ein Test, ein Build oder ein Lint fehlschlägt oder ungleich Null beendet wird. bei fehlenden Tools, nicht übereinstimmenden Abhängigkeiten/Sperrdateien, falscher Laufzeitversion, Venv- oder Berechtigungsfehlern, Portkonflikten, fehlerhaftem Git-Status oder einer fehlenden „.env“; wenn der Agent ein Hilfsskript oder ein einmaliges Skript benötigt, das noch nicht existiert; wenn eine externe API, ein externes Tool oder ein MCP Fehler oder Geschwindigkeitsbegrenzungen aufweist; oder wenn ein Test abblättert. Durchsuchen Sie „HEALS.md“ zuerst nach „Pattern-Key“ – die meisten Heilungen sind Wiederholungen, also erhöhen Sie „Recurrence-Count“ anstatt zu duplizieren. Die Überprüfung ist obligatorisch: Markieren Sie ehrlich „Ausstehende Überprüfung“, wenn eine Sandbox vorliegt, und „Abgebrochen“, wenn der Fix nicht zum Laufen gebracht werden kann. Lässt sich mit „Selbstverbesserung“ kombinieren (die wiederkehrende Heilungen für ein dauerhaftes Gedächtnis fördert), verfügt aber nicht über die Disziplin „Überprüfen vor dem Beharren“, die Selbstverbesserung nicht hat.
