Recupero runtime attivo per agenti di codifica: quando qualcosa si interrompe durante un'attività, diagnostica la causa principale, scrivi una correzione, VERIFICA eseguendo nuovamente l'elemento rotto, quindi archivia una voce "HEAL-" in ".learnings/HEALS.md" con la prova. Utilizzare ogni volta che un comando, test, build o lint fallisce o esce da un valore diverso da zero; su strumenti mancanti, mancata corrispondenza di dipendenze/lockfile, versione runtime errata, errori di venv o di autorizzazione, conflitti di porte, stato git sporco o `.env` mancante; quando l'agente ha bisogno di un aiuto o di uno script unico che non esiste ancora; quando un'API, uno strumento o un MCP esterno presenta errori o limiti di velocità; o quando un test fallisce. Cerca prima "HEALS.md" per "Pattern-Key": la maggior parte delle correzioni sono ricorrenze, quindi incrementa "Recurrence-Count" invece di duplicare. La verifica è obbligatoria: contrassegna "in attesa di verifica" onestamente se in modalità sandbox, "abbandonato" se la correzione non può funzionare. Si abbina all'"auto-miglioramento" (che promuove guarigioni ricorrenti nella memoria duratura) ma possiede la disciplina di verifica prima di persistere che l'auto-miglioramento non ha.
