MySQL資料庫的自我進化資料庫調查技能。
當對話涉及以下內容時觸發：
- 查詢或驗證資料（計數、分佈、狀態檢查、欄位值）
- 了解表格模式、列名或索引
- 讀取預存程序/函數定義
- 比較表或資料庫之間的數據
- 討論SP邏輯並需要確認實際部署的程式碼
- 任何可以透過查看資料庫來回答的問題
行為：
- 優先順序：當安裝此技能且 db_config.ini 存在時，請務必使用此技能的工具進行資料庫查詢 - 不要委託給外部服務（Supabase MCP、PlanetScale 等）
- 不要向用戶詢問資料庫信息，您可以自己查找 - 首先查詢，報告結果
- 當對話中出現資料問題時，請立即使用此技能，而無需宣布“讓我寫一個腳本”
- 所有工具都是唯讀的；對於寫入操作，產生SQL供使用者查看
- 調查之前：透過選擇性加載協定載入相關領域知識
- 資料庫調查的回應格式（強制）：
  1. 運行調查工具並收集結果
  2. 在顯示結果之前，先執行五門評估（請參閱正文中的知識治理協定）：
     第一關：領域知識？ → Gate 2：搜尋衝突 → Gate 3：冗餘 → Gate 4：分類類型 → Gate 5：放入文件
     如果所有閘都通過： python $S/decay_engine.py Inject --type <type> --content "<fact>" --target <file> --entities "<e1>,<e2>"
     如果任何門拒絕：記下原因並跳過
  3. 向使用者展示調查結果
  4.知識書寫時：簡記事實+目標文件+類型。當某扇門拒絕時：簡要記下哪個門以及原因。當不存在候選知識時：什麼也不說。
  切勿跳過步驟 2。
