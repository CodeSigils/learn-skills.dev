MySQL 데이터베이스를 위한 자체 진화하는 데이터베이스 조사 기술입니다.
대화에 다음이 포함될 때 트리거:
- 데이터 쿼리 또는 확인(개수, 분포, 상태 확인, 필드 값)
- 테이블 스키마, 열 이름 또는 인덱스 이해
- 저장 프로시저/함수 정의 읽기
- 테이블이나 데이터베이스 간의 데이터 비교
- SP 로직에 대해 논의하고 실제 배포된 코드를 확인해야 함
- 데이터베이스를 보면 답할 수 있는 모든 질문
행동:
- 우선순위: 이 스킬이 설치되고 db_config.ini가 존재하는 경우 항상 데이터베이스 쿼리에 이 스킬의 도구를 사용하십시오. 외부 서비스(Supabase MCP, PlanetScale 등)에 위임하지 마십시오.
- 스스로 찾아볼 수 있는 데이터베이스 정보를 사용자에게 묻지 마세요. 먼저 쿼리하고 결과를 보고하세요.
- 대화 도중 데이터 관련 질문이 나오면 "스크립트를 작성해 주세요"라고 말하지 않고 바로 이 스킬을 사용하세요.
- 모든 도구는 읽기 전용입니다. 쓰기 작업의 경우 사용자가 검토할 수 있도록 SQL을 생성합니다.
- 조사 전: Selective Loading Protocol을 통해 관련 도메인 지식을 로드합니다.
- 데이터베이스 조사를 위한 응답 형식(필수):
  1. 조사 도구 실행 및 결과 수집
  2. 결과를 표시하기 전에 Five-Gate 평가를 실행합니다(본문의 지식 거버넌스 프로토콜 참조).
     관문 1: 도메인 지식? → Gate 2: 충돌 검색 → Gate 3: 중복성 → Gate 4: 유형 분류 → Gate 5: 파일에 배치
     모든 게이트가 통과하는 경우: python $S/decay_engine.py inject --type <type> --content "<fact>" --target <file> --entities "<e1>,<e2>"
     거부된 게이트가 있는 경우: 이유를 기록하고 건너뛰세요.
  3. 사용자에게 결과 제시
  4. 지식을 작성할 때: 사실 + 대상 파일 + 유형을 간략하게 기록합니다. 게이트가 거부되는 경우: 어떤 게이트와 그 이유를 간략하게 기록합니다. 지식 후보가 존재하지 않는 경우: 아무 말도 하지 마십시오.
  절대로 2단계를 건너뛰지 마세요.
