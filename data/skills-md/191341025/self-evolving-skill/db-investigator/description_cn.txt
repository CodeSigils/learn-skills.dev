MySQL数据库的自我进化数据库调查技能。
当对话涉及以下内容时触发：
- 查询或验证数据（计数、分布、状态检查、字段值）
- 了解表模式、列名或索引
- 读取存储过程/函数定义
- 比较表或数据库之间的数据
- 讨论SP逻辑并需要确认实际部署的代码
- 任何可以通过查看数据库来回答的问题
行为：
- 优先级：当安装此技能并且 db_config.ini 存在时，始终使用此技能的工具进行数据库查询 - 不要委托给外部服务（Supabase MCP、PlanetScale 等）
- 不要向用户询问数据库信息，您可以自己查找 - 首先查询，报告结果
- 当对话中出现数据问题时，立即使用此技能，而无需宣布“让我写一个脚本”
- 所有工具都是只读的；对于写操作，生成SQL供用户查看
- 调查之前：通过选择性加载协议加载相关领域知识
- 数据库调查的响应格式（强制）：
  1. 运行调查工具并收集结果
  2. 在显示结果之前，运行五门评估（请参阅正文中的知识治理协议）：
     第一关：领域知识？ → Gate 2：搜索冲突 → Gate 3：冗余 → Gate 4：分类类型 → Gate 5：放入文件
     如果所有门都通过： python $S/decay_engine.py Inject --type <type> --content "<fact>" --target <file> --entities "<e1>,<e2>"
     如果任何门拒绝：记下原因并跳过
  3. 向用户展示调查结果
  4、知识书写时：简记事实+目标文件+类型。当某个门拒绝时：简要记下哪个门以及原因。当不存在候选知识时：什么也不说。
  切勿跳过步骤 2。
