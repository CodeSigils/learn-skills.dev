مهارة التحقيق في قاعدة البيانات ذاتية التطور لقواعد بيانات MySQL.
يتم تفعيله عندما تتضمن المحادثة ما يلي:
- الاستعلام عن البيانات أو التحقق منها (الأعداد والتوزيعات والتحقق من الحالة وقيم الحقول)
- فهم مخططات الجدول أو أسماء الأعمدة أو الفهارس
- قراءة تعريفات الإجراء / الوظيفة المخزنة
- مقارنة البيانات بين الجداول أو قواعد البيانات
- مناقشة منطق SP والحاجة إلى تأكيد الكود المنشور الفعلي
- أي سؤال يمكن الإجابة عليه من خلال النظر في قاعدة البيانات
السلوك:
- الأولوية: عند تثبيت هذه المهارة ووجود db_config.ini، استخدم دائمًا أدوات هذه المهارة لاستعلامات قاعدة البيانات - لا تقم بتفويض خدمات خارجية (Supabase MCP، PlanetScale، إلخ.)
- لا تطلب من المستخدم معلومات قاعدة البيانات التي يمكنك البحث عنها بنفسك - استفسر أولاً، وأبلغ عن النتائج
- عندما يظهر سؤال يتعلق بالبيانات في منتصف المحادثة، استخدم هذه المهارة على الفور دون الإعلان عن "دعني أكتب نصًا"
- جميع الأدوات للقراءة فقط. لعمليات الكتابة، قم بإنشاء SQL ليقوم المستخدم بمراجعتها
- قبل التحقيق: قم بتحميل معرفة المجال ذي الصلة عبر بروتوكول التحميل الانتقائي
- نموذج الرد على تحقيقات قاعدة البيانات (إلزامي):
  1. تشغيل أدوات التحقيق وجمع النتائج
  2. قبل عرض النتائج، قم بإجراء تقييم البوابات الخمس (راجع بروتوكول حوكمة المعرفة في النص):
     البوابة 1: معرفة المجال؟ → البوابة 2: البحث عن التعارضات → البوابة 3: التكرار → البوابة 4: تصنيف النوع → البوابة 5: وضعها في الملف
     إذا مرت جميع البوابات: python $S/decay_engine.py inject --type <type> --content "<fact>" --target <file> --entities "<e1>,<e2>"
     إذا رفضت أي بوابة: لاحظ السبب وتخطى
  3. تقديم النتائج للمستخدم
  4. عند كتابة المعرفة: لاحظ باختصار الحقيقة + الملف الهدف + النوع. عندما ترفض البوابة: لاحظ بإيجاز أي بوابة ولماذا. عندما لا يكون هناك مرشح للمعرفة: لا تقل شيئًا.
  لا تخطي الخطوة 2 أبدًا.
