自己進化する MySQL データベースのデータベース調査スキル。
会話に以下が含まれる場合にトリガーされます。
- データのクエリまたは検証 (数、分布、ステータス チェック、フィールド値)
- テーブルのスキーマ、列名、インデックスの理解
- ストアドプロシージャ/関数定義の読み取り
- テーブルまたはデータベース間のデータの比較
- SP ロジックについて議論し、実際にデプロイされたコードを確認する必要がある
- データベースを見れば答えられる質問
行動:
- 優先: このスキルがインストールされており、db_config.ini が存在する場合、データベース クエリには常にこのスキルのツールを使用します。外部サービス (Supabase MCP、PlanetScale など) に委任しないでください。
- 自分で調べられるデータベース情報をユーザーに尋ねないでください。最初にクエリを実行し、結果を報告してください。
- 会話中にデータに関する質問が生じた場合、「スクリプトを書かせてください」とは言わずに、すぐにこのスキルを使用します。
- すべてのツールは読み取り専用です。書き込み操作の場合は、ユーザーが確認できるように SQL を生成します。
- 調査する前に: 選択的読み込みプロトコルを介して関連するドメインの知識を読み込みます。
- データベース調査の応答形式 (必須):
  1. 調査ツールを実行して結果を収集する
  2. 結果を表示する前に、Five-Gate 評価を実行します (本文の「ナレッジ ガバナンス プロトコル」を参照)。
     ゲート 1: ドメインの知識? → ゲート 2: 競合の検索 → ゲート 3: 冗長性 → ゲート 4: タイプの分類 → ゲート 5: ファイルに配置
     すべてのゲートを通過した場合: python $S/decay_engine.py inject --type <type> --content "<fact>" --target <file> --entities "<e1>,<e2>"
     いずれかのゲートが拒否した場合: 理由を書き留めてスキップします
  3. 調査結果をユーザーに提示する
  4. 知識を記述する場合: 事実 + 対象ファイル + 種類を簡単にメモします。ゲートが拒否した場合: どのゲートとその理由を簡単にメモします。知識候補が存在しない場合：何も言わない。
  ステップ 2 は決してスキップしないでください。
