Используйте при работе с проектом PHP-фреймворка Zephyrus (zephyrus-framework/core). Триггеры маршрутизации атрибутов (`#[Get]`, `#[Post]`, `#[Put]`, `#[Patch]`, `#[Delete]`, `#[Root]`, `#[Middleware]`, `#[RequiresEnv]`), `#[RequiresEnv]`), `#[RequiresEnv]`), `ApplicationBuilder`, `Controller`, типаж `RenderResponses`, объекты значений `Request`/`Response`, `Configuration::fromYamlFile`, подклассы `ConfigSection`, шаблоны Latte в `app/Views/`, слои Broker/Service/Entity, расширения `Zephyrus\Data\Broker` или `Zephyrus\Data\Entity`, автоматическое обнаружение контроллера и форма `config.yml` с `application:`/`render:`/`localization:`/`security:`/`database:` разделы. Охватывает маршрутизацию атрибутов с областью действия контроллера на основе MODE (одна кодовая база, несколько точек входа), регистрацию именованного промежуточного программного обеспечения и приложения атрибутов, шаблон Raw-SQL Broker с многоуровневым обслуживанием/сущностью, очистку байтов PostgreSQL, пользовательскую фабрику контроллеров для внедрения в механизм рендеринга, синтаксический анализ `DATABASE_URL` для облачных развертываний, DECIMAL-as-string для денежной точности, загрузку свежей базы данных для каждого теста с изолированными транзакциями интеграционными тестами, набор ключей (курсорная) нумерация страниц и философия отсутствия ORM/отсутствия миграции. Эмпирические закономерности взяты из продукции `immunity-app`.
