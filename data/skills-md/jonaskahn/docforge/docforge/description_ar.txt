قم بتصميم وإنشاء مجموعة وثائق المستودع - المستندات/الشجرة، والملف التمهيدي والهندسة المعمارية، وسجلات القرار (ADRs)، وسجل القيود المعروفة، ومخزون تبعية الطرف الثالث، وسياسة الأمان، وكتالوجات أخطاء واجهة برمجة التطبيقات (API)، وعقود البيانات ودفاتر التشغيل، بالإضافة إلى تراكبات الجمهور التي تتحدث إلى قراء محللي الأعمال (BA) ومالك المنتج (PO). يقوم بتأريض كل مستند في تحليل الرسم البياني المعرفي للمصدر الفعلي قبل الكتابة، لذلك لا يتم اختراع أي شيء، ويختم كل مستند بمصدر git-hash بحيث يتم تحديد الثبات عن طريق المقارنة، وليس عن طريق إعادة التخمين. محايد للمضيف - يعمل على أي مضيف git ولا يقوم مطلقًا بترميز مسارات صياغة واحدة، ويتحقق من عمليات إعادة الشراء الفرعية (الوحدات الفرعية المعلنة أو عمليات إعادة الشراء المتداخلة/المُباعة) قبل أي مراجعة متعددة الريبو. استخدم هذه المهارة عندما يذكر المستخدم توثيق الريبو أو قاعدة التعليمات البرمجية، أو مجلد المستندات، أو ملفات README أو الهندسة المعمارية، أو ADRs أو سجلات القرار، أو مستندات الإعداد، أو دفاتر التشغيل، أو القيود المعروفة، أو قوائم التبعية أو الترخيص، أو العناية الواجبة الفنية أو الاستعداد للتدقيق، أو توحيد الوثائق عبر عدة مستودعات، أو وثائق لمحلل الأعمال أو مالك المنتج، أو قواعد العمل أو تدفقات العمليات أو تتبع المتطلبات، أو كتالوجات الميزات أو ملاحظات الإصدار أو مقاييس النجاح، أو ما إذا كان لقد انحرفت المستندات التي تم إنشاؤها حاليًا عن الكود - بما في ذلك العبارات الفضفاضة مثل "اكتب مستندات لهذا المشروع"، أو "لا يحتوي الريبو الخاص بنا على أي وثائق"، أو "اجعل هذا الريبو مقروءًا لمهندس جديد"، أو "مستندات لـ BA/PO"، أو "أي المستندات قديمة"، أو "هل يجب علينا إعادة إنشاء هذا"، أو "هل يحتوي كل ريبو هنا على مستندات".
