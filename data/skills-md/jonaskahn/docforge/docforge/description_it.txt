Progetta e genera un set di documentazione di un repository: documenti/albero, README e ARCHITETTURA, record decisionali (ADR), un registro delle limitazioni note, un inventario delle dipendenze di terze parti, policy di sicurezza, cataloghi di errori API, contratti dati e runbook, oltre a sovrapposizioni del pubblico che parlano ai lettori degli analisti aziendali (BA) e dei proprietari dei prodotti (PO). Fonda ogni documento in un'analisi del grafico della conoscenza della fonte effettiva prima di scriverlo, quindi non viene inventato nulla, e contrassegna ogni documento con la provenienza git-hash in modo che la obsolescenza venga decisa mediante confronto, non ri-indovinando. Host-neutral: funziona su qualsiasi host git e non codifica mai i percorsi di un forge e controlla i repository secondari (sottomoduli dichiarati o repository nidificati/forniti) prima di qualsiasi revisione multi-repo. Utilizzare questa competenza ogni volta che l'utente menziona la documentazione di un repository o codebase, una cartella di documenti, file README o ARCHITETTURA, ADR o record decisionali, documenti di onboarding, runbook, limitazioni note, dipendenze o inventari di licenza, due diligence tecnica o preparazione all'audit, standardizzazione della documentazione tra diversi repository, documentazione per un analista aziendale o proprietario del prodotto, regole aziendali o flussi di processi o tracciabilità dei requisiti, cataloghi di funzionalità o note di rilascio o metriche di successo o se esistenti generati i documenti si sono allontanati dal codice, comprese frasi vaghe come "scrivi documenti per questo progetto", "il nostro repository non ha documentazione", "rendi questo repository leggibile a un nuovo ingegnere", "documenti per BA/PO", "quali documenti sono obsoleti", "dovremmo rigenerarlo" o "ogni repository qui contiene documenti".
