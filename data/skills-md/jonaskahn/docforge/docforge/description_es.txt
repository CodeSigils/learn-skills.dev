Diseñe y genere un conjunto de documentación de repositorio: documentos/árbol, README y ARQUITECTURA, registros de decisiones (ADR), un registro de limitaciones conocidas, un inventario de dependencias de terceros, política de seguridad, catálogos de errores de API, contratos de datos y runbooks, además de superposiciones de audiencia que se dirigen a los lectores de Business Analyst (BA) y Product Owner (PO). Fundamenta cada documento en un análisis de gráfico de conocimiento de la fuente real antes de escribirlo, para que no se invente nada, y sella cada documento con la procedencia de git-hash para que la obsolescencia se decida mediante comparación, no volviendo a adivinar. Neutral del host: funciona en cualquier host git y nunca codifica las rutas de una forja, y verifica los repositorios secundarios (submódulos declarados o repositorios anidados/vendedores) antes de cualquier revisión de repositorios múltiples. Utilice esta habilidad siempre que el usuario mencione la documentación de un repositorio o base de código, una carpeta de documentos, archivos README o ARQUITECTURA, ADR o registros de decisiones, documentos de incorporación, runbooks, limitaciones conocidas, inventarios de dependencias o licencias, debida diligencia técnica o preparación para auditorías, estandarización de documentación en varios repositorios, documentación para un analista de negocios o propietario de producto, reglas de negocios o flujos de procesos o trazabilidad de requisitos, catálogos de funciones o notas de la versión o métricas de éxito, o si ya existen. Los documentos se han desviado del código, incluidas frases sueltas como "escribir documentos para este proyecto", "nuestro repositorio no tiene documentación", "hacer que este repositorio sea legible para un nuevo ingeniero", "docs para BA/PO", "qué documentos están obsoletos", "deberíamos regenerar esto" o "todos los repositorios aquí tienen documentos".
