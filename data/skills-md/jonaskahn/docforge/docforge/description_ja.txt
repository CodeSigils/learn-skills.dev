リポジトリのドキュメント セット (ドキュメント/ツリー、README とアーキテクチャ、意思決定記録 (ADR)、既知の制限事項登録、サードパーティの依存関係インベントリ、セキュリティ ポリシー、API エラー カタログ、データ コントラクトとランブック、さらにビジネス アナリスト (BA) とプロダクト オーナー (PO) の読者に伝えるオーディエンス オーバーレイ) を設計および生成します。作成前に実際のソースのナレッジグラフ分析ですべてのドキュメントを根拠付けするため、何もでっち上げられず、各ドキュメントに git ハッシュの出自がスタンプされるため、古さは再推測ではなく比較によって判断されます。ホスト中立 — 任意の git ホストで動作し、Forge のパスをハードコーディングすることはなく、マルチリポジトリのレビューの前に子リポジトリ (宣言されたサブモジュールまたはネスト/ベンダー化されたリポジトリ) をチェックします。リポジトリまたはコードベース、ドキュメント フォルダー、README またはアーキテクチャ ファイル、ADR または意思決定記録、オンボーディング ドキュメント、Runbook、既知の制限事項、依存関係またはライセンス インベントリ、技術的デュー デリジェンスまたは監査の準備状況、複数のリポジトリにわたるドキュメントの標準化、ビジネス アナリストまたはプロダクト オーナー向けのドキュメント、ビジネス ルールまたはプロセス フローまたは要件のトレーサビリティ、機能カタログまたはリリース ノートまたは成功指標、あるいは既存のものの有無についてユーザーが言及する場合には、このスキルを使用してください。生成されたドキュメントがコードから逸脱しています。これには、「このプロジェクトのドキュメントを作成してください」、「私たちのリポジトリにはドキュメントがありません」、「このリポジトリを新しいエンジニアが読みやすいようにします」、「BA/PO 用のドキュメント」、「どのドキュメントが古いですか」、「これを再生成すべきですか」、または「ここにあるすべてのリポジトリにはドキュメントがありますか」などの大雑把な表現が含まれます。
