Automated repository environment configuration, fault diagnosis, and repair. When non‑technical staff (editing, business, operations) receive a repository and say “can’t run”, “how to start”, “how to configure the environment”, “help me set up the repository”, “initialize the project”, “commit code”, “what to do if there’s a conflict”, the system automatically reads ONBOARDING.md, diagnoses environment gaps, fixes dependencies, verifies it can run, and safely performs git operations. It is also used for technical users to quickly standardize the setup process of new repositories (SessionStart hook, PII Guard, history sanitization, project isolation API key). Whenever a user mentions “environment”, “configuration”, “can’t run”, “setup”, “start”, “clone”, “how to run”, “dependency”, “is it installed”, “commit code”, “merge conflict”, “push failed”, this skill is triggered.
