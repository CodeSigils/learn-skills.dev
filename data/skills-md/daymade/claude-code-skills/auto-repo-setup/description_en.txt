Automated repository environment configuration, fault diagnosis, and repair. When non‑technical staff (editing, business, operations) receive a repository and say “can’t run”, “how to start”, “how to configure the environment”, “help me set up the repo”, “initialize project”, “commit code”, “what to do if there’s a conflict”, the system automatically reads ONBOARDING.md, diagnoses environment gaps, fixes dependencies, verifies it can run, and safely completes Git operations. It is also used for technical users to quickly standardize the setup process of new repositories (SessionStart hook, PII Guard, historical cleansing, project‑isolation API key).  
Whenever a user mentions “environment”, “configuration”, “can’t run”, “setup”, “start”, “clone”, “how to run”, “dependency”, “installed?”, “commit code”, “merge conflict”, or “push failed”, this skill is triggered.
