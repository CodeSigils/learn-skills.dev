审核、保留、恢复和安全地退役本地 Git 状态：未推送或错误分支提交、脏或分离的工作树、同一存储库的遗忘重复克隆、无法跟踪的工作，没有捆绑包可以备份、孤立的存储、悬空的提交、过时的分支以及压缩/变基合并不确定性。当用户担心工作丢失时使用；要求恢复提交或分支；询问是否可以删除工作树、克隆或临时目录；希望一切都汇聚到一个主干上；或者需要证明清理不会导致工作失败。即使在审计报告干净之后也可以使用它 - 通常的差距是范围：每个 in-repo 命令对磁盘上其他地方的第二个克隆都是盲目的。触发“我失去工作了吗”、“所有东西都合并了吗”、“还有其他东西丢失吗”、“安全删除这个克隆”、“清理旧分支/隐藏”、“只保留一个主分支”、“git reflog”、“悬空提交”、“分支灾难”、“误删除分支/提交”、“工作树能删除吗”、“还有没有丢失的东西”、“只保留一个主分支”。涵盖本地 Git 取证，而不是 GitHub PR/API 操作或例程同步。
