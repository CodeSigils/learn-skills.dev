Verwenden Sie es immer dann, wenn Code SQL erstellt, zurückgibt, abruft oder ausführt, das mit der echten Postgres-Datenbank eines Benutzers ausgeführt wird – auch wenn die Anfrage wie eine gewöhnliche Funktion oder Fehlerbehebung liest und niemals „Sicherheit“, „Injektion“ oder „SafeSqlFragment“ sagt. Dies umfasst: Schreiben oder Bearbeiten aller pg-meta-Funktionen, Abfrage-Builder oder Endpunkte, die SQL für Datenbankobjekte (Tabellen, Ansichten, Funktionen, DB-Trigger, Indizes, RLS-Richtlinien) erstellen/zurückgeben; Interpolieren eines Schema-/Tabellen-/Spalten-/Such-/Routenparameterwerts in SQL-Text; Speichern, Abrufen oder erneutes Ausführen von SQL, das Roundtrips aus der Datenbank durchführt (eine Richtliniendefinition, eine Funktions-/Ansichtsdefinition, der gespeicherte Inhalt eines Snippets); und jede „Ausführen“/„Anwenden“/„Ausführen“-Aktion, die SQL an die Datenbank eines Projekts sendet (SQL-Editor-Auswahl, Richtlinieneditor anwenden, Snippet-Runner). Laden Sie dies, BEVOR Sie solchen Code schreiben, nicht nur, wenn Sie ein fertiges Diff überprüfen. Überspringen Sie nur Änderungen, die niemals den SQL-Text oder die SQL-Ausführung berühren – Stil, unabhängige Daten-Hooks, Nicht-SQL-Formularvalidierung oder UI-Layoutarbeiten.
