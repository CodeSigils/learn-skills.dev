每當程式碼將建置、傳回、取得或執行針對使用者真實 Postgres 資料庫執行的 SQL 時使用 - 即使請求讀起來像普通功能或錯誤修復並且從不說「安全性」、「注入」或「SafeSqlFragment」。這包括：編寫或編輯任何 pg-meta 函數、查詢建構器或為資料庫物件（表格、視圖、函數、資料庫觸發器、索引、RLS 策略）建構/傳回 SQL 的端點；將 schema/table/column/search/route-param 值插入 SQL 文字中；儲存、取得或重新執行從資料庫往返的 SQL（策略定義、函數/param 值將保存與 SQL 文字的內容或重新執行從資料庫往返的 SQL（策略定義）；傳送到專案資料庫的「運行」/「應用」/「執行」操作（SQL 編輯器運行選擇、策略編輯器應用程式、程式碼片段運行器）。在編寫此類程式碼之前載入此程式碼，而不僅僅是在檢查完成的差異時載入。僅跳過不涉及 SQL 文字或執行的變更 — 樣式、不相關的資料掛鉤、非 SQL 表單驗證或 UI 佈局工作。
