À utiliser chaque fois que le code va créer, renvoyer, récupérer ou exécuter du SQL qui s'exécute sur la véritable base de données Postgres d'un utilisateur, même lorsque la requête se lit comme une fonctionnalité ordinaire ou une correction de bogue et ne dit jamais « sécurité », « injection » ou « SafeSqlFragment ». Cela couvre : l'écriture ou la modification de toute fonction pg-meta, générateur de requêtes ou point de terminaison qui crée/renvoie du SQL pour les objets de base de données (tables, vues, fonctions, déclencheurs de base de données, index, politiques RLS) ; interpoler une valeur de schéma/table/colonne/recherche/route-param dans du texte SQL ; stocker, récupérer ou réexécuter du SQL qui fait un aller-retour depuis la base de données (la définition d'une politique, une définition de fonction/vue, le contenu enregistré d'un extrait) ; et toute action « Exécuter »/« Appliquer »/« Exécuter » qui envoie du SQL à la base de données d'un projet (sélection d'exécution de l'éditeur SQL, application de l'éditeur de stratégie, exécuteur d'extraits de code). Chargez-le AVANT d'écrire un tel code, pas seulement lors de la révision d'une comparaison terminée. Ignorer uniquement les modifications qui ne touchent jamais au texte ou à l'exécution SQL : style, points d'ancrage de données non liés, validation de formulaire non SQL ou travail de mise en page de l'interface utilisateur.
