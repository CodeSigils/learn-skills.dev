Úselo siempre que el código genere, devuelva, obtenga o ejecute SQL que se ejecute en la base de datos Postgres real de un usuario, incluso cuando la solicitud se lea como una característica normal o una corrección de errores y nunca diga "seguridad", "inyección" o "SafeSqlFragment". Esto cubre: escribir o editar cualquier función pg-meta, generador de consultas o punto final que cree/devuelva SQL para objetos de base de datos (tablas, vistas, funciones, activadores de base de datos, índices, políticas RLS); interpolar un valor de esquema/tabla/columna/búsqueda/parámetro de ruta en texto SQL; almacenar, recuperar o volver a ejecutar SQL que viaja de ida y vuelta desde la base de datos (la definición de una política, una definición de función/vista, el contenido guardado de un fragmento); y cualquier acción "Ejecutar"/"Aplicar"/"Ejecutar" que envíe SQL a la base de datos de un proyecto (selección de ejecución del editor SQL, aplicación del editor de políticas, ejecutor de fragmentos). Cargue esto ANTES de escribir dicho código, no solo cuando revise una diferencia terminada. Omita solo los cambios que nunca afectan el texto SQL o la ejecución: estilo, enlaces de datos no relacionados, validación de formularios no SQL o trabajo de diseño de interfaz de usuario.
