QA der omo Codex Light Edition (lazycodex / packets/omo-codex) selbst, in strikter Isolation, sodass NUR unser Plugin ausgeführt wird, niemals der echte ~/.codex des Benutzers. Die Erstanbietermethode steuert den echten „Codex-App-Server“ gegen ein isoliertes CODEX_HOME plus ein LOCAL-Mock-Modell (kein echter API-Aufruf) und beweist einen Plugin-Hook, der durch die Bestätigung von Hook-/Start- und Hook-/Abgeschlossen-Benachrichtigungen ausgelöst wird. Außerdem: isolierte Installationsüberprüfung, Hook-Probes pro Komponente, ein tmux-TUI-Smoke und Laufzeitprotokollbeobachtung (RUST_LOG / logs SQLite / /debug-config). Versendet getestete Hilfsskripte mit jeweils einem --self-test. Verwenden Sie es immer dann, wenn jemand etwas unter Paketen/omo-codex ändert oder das Codex-Plugin, seine Hooks/Komponenten, den Installer/config.toml, den App-Server-Flow oder die Codex-TUI einer Qualitätssicherung, einem Rauchtest, einer Überprüfung oder einem Debugging unterziehen möchte. Auslöser: Codex QA, QA-Codex, Codex-QA, Codex-Plugin testen, Codex-Hook überprüfen, Codex-App-Server, Lazycodex QA, isoliertes CODEX_HOME, Codex-Hook-Auslösung beweisen, Codex-TUI-Test.
