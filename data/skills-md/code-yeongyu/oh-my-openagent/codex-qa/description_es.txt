Control de calidad de la edición omo Codex Light (lazycodex / packages/omo-codex), en estricto aislamiento, por lo que SÓLO se utiliza nuestro complemento, nunca el ~/.codex real del usuario. El método propio dirige el `servidor de aplicaciones codex` real contra un CODEX_HOME aislado más un modelo simulado LOCAL (sin llamada API real) y demuestra un gancho de complemento activado al afirmar notificaciones de gancho/iniciado + gancho/completadas. Además: verificación de instalación aislada, sondas de enlace por componente, humo de TUI tmux y observación de registros de tiempo de ejecución (RUST_LOG / logs SQLite / /debug-config). Se envían scripts de ayuda probados, cada uno con una autoprueba. Úselo siempre que alguien cambie algo en paquetes/omo-codex o quiera realizar un control de calidad, realizar pruebas de humo, verificar o depurar el complemento Codex, sus ganchos/componentes, el instalador/config.toml, el flujo del servidor de aplicaciones o la TUI del Codex. Activadores: codex qa, qa codex, codex-qa, complemento de prueba de codex, verificar gancho de codex, servidor de aplicaciones de codex, lazycodex qa, CODEX_HOME aislado, probar gancho de codex activado, prueba de codex tui.
