새로운 작업 소유 Git 작업 트리의 전체 PR 수명 주기: 필수 증거 바인딩 수동 QA → 검토자가 읽을 수 있는 영어 PR → 확인 루프(CI + 검토 작업 검토자 + Cubic, 할당량이 소진된 경우에만 Cubic을 건너뛰는 경우)가 포함된 ulw-loop 기술을 통해 구현 → 기본적으로 병합 → 작업 트리 정리. 하나의 작업을 가장 작은 원자적이고 독립적으로 병합 가능한 PR로 분해하고 병렬 하위 에이전트 또는 팀이 구동하는 PR당 하나의 작업 트리를 통해 독립적인 작업을 동시에 구축합니다. 무한 루프: 실패한 게이트는 해당 PR 작업 트리 내부의 수정 및 재QA로 다시 보내집니다. 구현 작업을 PR로 진행해야 할 때마다 사용하세요. 트리거: 'PR 생성', 'PR 구현', '이 작업을 수행하고 PR 만들기', '문제 구현', '이것을 PR로 지정', '원자적 PR로 분할', '병렬 PR', 'pr with-pr', 'PR 워크플로', '종단 간 구현', 컨텍스트가 PR 전달을 의미하는 경우 사용자가 'X 구현'이라고만 말하는 경우에도 마찬가지입니다.
