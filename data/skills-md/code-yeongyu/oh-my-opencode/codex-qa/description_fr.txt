Contrôlez l'édition omo Codex Light (lazycodex / packages/omo-codex) elle-même, dans un isolement strict afin que SEUL notre plugin soit utilisé, jamais le véritable ~/.codex de l'utilisateur. La méthode propriétaire pilote le véritable « serveur d'applications codex » contre un CODEX_HOME isolé plus un modèle fictif LOCAL (pas d'appel d'API réel) et prouve un hook de plugin déclenché en affirmant des notifications hook/started + hook/completed. Également : vérification d'installation isolée, sondes de hook par composant, fumée tmux TUI et observation du journal d'exécution (RUST_LOG / logs SQLite / /debug-config). Livré des scripts d'assistance testés, chacun avec un --self-test. À utiliser chaque fois que quelqu'un modifie quelque chose sous packages/omo-codex ou souhaite effectuer un contrôle qualité, un test de fumée, une vérification ou un débogage du plugin Codex, de ses hooks/composants, du programme d'installation/config.toml, du flux du serveur d'applications ou de l'interface utilisateur du Codex. Déclencheurs : codex qa, qa codex, codex-qa, tester le plugin codex, vérifier le hook codex, le serveur d'applications codex, lazycodex qa, CODEX_HOME isolé, prouver le déclenchement du hook codex, test codex tui.
