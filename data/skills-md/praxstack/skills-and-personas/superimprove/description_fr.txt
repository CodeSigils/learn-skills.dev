Exécutez une boucle d'audit-correction-révision-vérification limitée et axée sur les preuves sur une base de code lorsque l'utilisateur demande d'améliorer, de renforcer, de réviser ou de corriger tous les défauts confirmés. À utiliser uniquement avec des droits de modification explicites dans un référentiel git. Ne pas utiliser pour des révisions uniquement consultatives, un seul bug étroit ou lorsque l'arbre de travail est sale et que le propriétaire n'a pas choisi comment le préserver.
