Arbor 論文の Hypothesis Tree Refinement (HTR) を使用して、目標と評価者に照らして実際の成果物 (コード、トレーニング レシピ、エージェント ハーネス、データ パイプライン、プロンプト) を自律的に改善します。誰かが過剰適合せずに多くの実験にわたって何かを繰り返し最適化したいときは、これを使用してください。 「モデルの評価スコアを上げる」、「このエージェント/ハーネスを改善する」、「このパイプラインを調整する」、「このベンチマークのベースラインを上回る」、「アプローチを検索して最良のものを維持する」、「MLE ベンチ / Kaggle スタイルの最適化を行う」、または長期的な「開発セットを記憶するだけでなく、このアーティファクトを改善する」タスクなどです。ユーザーが「アーバー」や「仮説ツリー」とは言わなくても、実験と評価のループの繰り返し、競合するアイデアの分岐探索、または開発とテストのギャップについての懸念を説明している場合でも、この機能をトリガーします。 Claude 自体をコーディネーターとして実行し、分離された git ワークツリー内のサブエージェント エグゼキューターを使用します。スタンドアロンの「arbor」CLI ツールについては、references/arbor-upstream.md を参照してください。
