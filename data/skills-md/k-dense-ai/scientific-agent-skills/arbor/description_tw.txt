使用 Arbor 論文中的假設樹細化 (HTR)，根據目標和評估器自主改進真實工件（程式碼、訓練配方、代理工具、資料管道、提示）。每當有人想要在多次實驗中迭代優化某些東西而不過度擬合時，就可以使用它——例如“提高我的模型的評估分數”、“改進這個代理/線束”、“調整這個管道”、“在這個基準測試中超越基線”、“對方法進行搜索並保持最好的”、“進行 MLE 基準/Kaggle 式工件”，或任何長期的項目而使這個任務不僅僅是開發即使用戶沒有說“Arbor”或“假設樹”，但描述了重複的實驗和評估循環、對競爭想法的分支探索或擔心開發/測試差距，也會觸發它。將 Claude 本身作為協調器與獨立的 git 工作樹中的子代理執行器一起運作；對於獨立的「arbor」CLI 工具，請參閱references/arbor-upstream.md。
