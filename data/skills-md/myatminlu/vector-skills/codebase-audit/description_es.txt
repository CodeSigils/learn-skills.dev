Auditoría forense de toda la base de código y refactorización por etapas. Utilice esta habilidad siempre que el usuario quiera que una base de código sea revisada, auditada, limpiada, refactorizada o "sistemática", y también cuando mencione código duplicado, características o servicios duplicados, módulos copiados y pegados, código de curita o solución rápida o pirateado, deuda técnica, implementaciones heredadas versus nuevas que conviven una al lado de la otra, código inactivo, olores de código, o quiera verificar que las características, funciones y servicios están realmente conectados entre sí y funcionando de extremo a extremo. Actívelo para solicitudes como "revisar mi código base", "encontrar lógica duplicada", "por qué este código es tan desordenado", "verificar si todo está conectado correctamente" o "planificar una refactorización", incluso cuando el usuario no diga la palabra "auditoría". NO lo use para una revisión de un solo archivo, una única corrección de errores o para escribir nuevas funciones.
