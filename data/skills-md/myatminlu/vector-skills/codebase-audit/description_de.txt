Forensische Prüfung der gesamten Codebasis und schrittweise Umgestaltung. Verwenden Sie diese Fähigkeit immer dann, wenn der Benutzer möchte, dass eine Codebasis überprüft, geprüft, bereinigt, umgestaltet oder „systematisiert“ wird – und auch immer dann, wenn er duplizierten Code, duplizierte Funktionen oder Dienste, kopierte und eingefügte Module, Pflaster- oder Quick-Fix- oder Hacky-Code, technische Schulden, nebeneinander existierende alte und neue Implementierungen, toten Code oder Code-Gerüche erwähnt oder überprüfen möchte, ob Features, Funktionen und Dienste tatsächlich miteinander verbunden sind und durchgängig funktionieren. Lösen Sie es für Anfragen wie „meine Codebasis überprüfen“, „doppelte Logik finden“, „warum ist dieser Code so ein Durcheinander“, „prüfen Sie, ob alles richtig verbunden ist“ oder „planen Sie eine Umgestaltung“ aus, auch wenn der Benutzer das Wort „Prüfung“ nicht sagt. Verwenden Sie es NICHT für eine einzelne Dateiüberprüfung, eine einzelne Fehlerbehebung oder das Schreiben neuer Funktionen.
