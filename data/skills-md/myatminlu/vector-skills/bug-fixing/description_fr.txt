Un flux de travail discipliné de niveau architecte pour diagnostiquer et corriger les bogues dans une base de code existante : reproduire, lire le vrai code avant de toucher quoi que ce soit, trouver la véritable cause première, concevoir le correctif minimal correct sur la bonne couche, le vérifier et rechercher des clones du même défaut. Utilisez cette compétence pour TOUT travail sur les défauts : plantages, exceptions, sortie incorrecte, tests défaillants ou irréguliers, régressions, conditions de concurrence critique, fuites de mémoire, dégradation des performances, corruption des données, échecs d'intégration, problèmes de fonctionnement local mais pas en production, ou toute demande formulée comme correctif, débogage, cassé, ne fonctionne pas, erreur ou pourquoi X se produit-il. Utilisez-le même lorsque le bogue semble insignifiant ou que l'utilisateur a déjà proposé un correctif, surtout dans ce cas, car le correctif proposé est généralement un correctif au niveau des symptômes. Ne PAS utiliser pour des travaux de fonctionnalité inédits sans aucun défaut impliqué.
