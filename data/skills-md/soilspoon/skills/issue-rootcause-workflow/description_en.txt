A 6-principle workflow for reaching root causes rather than symptoms when encountering issues, bugs, and regressions — invariant documentation, workaround vs root fix awareness, A/B verification (including hypothesis-reach verification), contradiction trust, recent changes + two-path comparison. Triggers - (1) "why doesn't this work", "bug tracking", "regression analysis", "finding root cause", "rootcause", (2) "verify this fix", "check if this patch really fixes it", "A/B test", (3) compiler/runtime/lib/infra patch PR reviews, (4) suspicion of false positives like "tests pass but it doesn't actually work", (5) suspicion of hypothesis-reach like "added option but no effect", (6) situations where only workarounds accumulate and the same bug repeats, (7) incident postmortem·ADR writing. Not limited to compiler/runtime/infrastructure, applicable anywhere: data structure invariants, external system calls, multi-stage toolchains, dual-path migrations.
