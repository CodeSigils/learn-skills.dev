Bringen Sie parallele gegnerische Subagenten hervor, die das reale System (nicht die Vernunft aus der Quelle) antreiben, um neuen Code zu knacken, bevor er ausgeliefert wird – Schemata, Verträge, Parser, Serialisierer, Protokolle, Zustandsmaschinen, Sicherheit/Redaktion, Freeze Guards. Verwenden Sie es als Standardschritt für alle nicht trivialen Funktionen/Aufgaben, sobald die Implementierung grün ist und VOR der endgültigen Konvergenzprüfung (dootsabha). Jeder Agent erhält eine disjunkte Angriffsfläche + eine „Versuch, X zu brechen“-Charta; Jeder Befund wird unabhängig reproduziert, bevor er geglaubt wird, und dann mit einem Regressionstest korrigiert. Zu den Auslöserphrasen gehören „kontradiktorische Überprüfung“, „versuchen Sie, dies zu brechen“, „die Fehler finden, die ich übersehen habe“, „härten, bevor Sie fertig sind“, „dieses Schema/diesen Parser/diesen Vertrag angreifen“ und der kontradiktorische Schritt des Shux-Feature-Protokolls.
