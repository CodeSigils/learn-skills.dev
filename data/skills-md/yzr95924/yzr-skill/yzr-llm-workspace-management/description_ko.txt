사용자가 yzr-llm-wiki-management에서 유지 관리하는 여러 로컬 위키를 관리해야 하는 경우 다음 기술을 사용하십시오. 작업 영역 수준에서 모든 위키를 스캔하고, 글로벌 INDEX.md / STATS.md / LINT.md를 생성 및 유지 관리하고, 위키 간 포괄적인 Q&A(라우팅/합성/비교/로컬)를 수행하고, 위키 간 상호 참조를 유지하고, 작업 영역 수준 린팅을 수행하고, 위키 간 에이전트 개인 메모리를 MEMORY/에 저장합니다. 이는 메타데이터만 처리할 수 있고 콘텐츠를 인식할 수 없는 작업공간 CLI의 한계를 보완합니다. CLI는 결정론적 메타데이터 작업을 처리하는 반면, 이 기술은 LLM 판단이 필요한 크로스 위키 결정을 처리합니다.  
트리거: "내 위키의 X에 대한 모든 콘텐츠 요약" / "Y에 대한 위키 A와 위키 B의 견해 비교" / "이 질문에 대해 어느 위키에 문의해야 합니까?" / "내 작업 공간 스캔" / "작업 공간 전체 린트" / "참고: 사용자는 타임라인별로 위키를 분리하는 것을 선호합니다" / "위키 A의 X는 위키 B에도 존재합니다. 링크 추가" / "작업 공간 업그레이드 / 최신 사양으로 마이그레이션 / 작업 공간 버전 확인"  
해당 없음: 단일 위키 수집/쿼리/린트(yzr-llm-wiki-management에서 처리) 작업공간/wiki 메타데이터 CRUD(작업공간 CLI에서 처리) 클라우드 협업 위키(yzr-outline-wiki에서 처리).
