When users need to manage multiple local wikis maintained by **yzr-llm-wiki-management**, they should use this skill: it scans all wikis at the workspace level, generates and maintains global `INDEX.md`, `STATS.md`, and `LINT.md` files, performs cross‑wiki comprehensive Q&A (routing, synthesis, comparison, local answering), maintains cross‑wiki references, conducts workspace‑level linting, and consolidates cross‑wiki agent private memory into the `MEMORY/` directory. This compensates for the limitation of the workspace CLI, which can only handle metadata and cannot perceive content—the CLI takes care of deterministic metadata operations, while this skill handles cross‑wiki decisions that require LLM judgment.

**Triggers** include:  
- “Summarize everything about **X** in all my wikis”  
- “Compare wiki A and wiki B’s views on **Y**”  
- “Which wiki should I consult for this question?”  
- “Scan my workspace”  
- “Run a full workspace lint”  
- “Note: the user prefers to split wikis by timeline”  
- “The **X** in wiki A also exists in wiki B—add a link”  
- “Upgrade the workspace / migrate to the latest spec / check the workspace version”

**Not applicable**: single‑wiki ingest/query/lint (handled by **yzr-llm-wiki-management**); workspace/wiki metadata CRUD (handled by the workspace CLI); cloud‑collaborative wikis (handled by **yzr-outline-wiki**).
