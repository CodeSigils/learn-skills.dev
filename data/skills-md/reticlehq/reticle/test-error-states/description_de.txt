Erzwingen Sie die Zustände, die ein Happy-Path-Lauf nie erreicht – eine fehlerhafte API, eine leere Liste, eine langsame Anfrage, ein Timeout, eine abgelaufene Sitzung, ein Toast, der automatisch geschlossen wird – und überprüfen Sie, ob die Benutzeroberfläche diese tatsächlich verarbeitet. Wird verwendet, wenn die Fehlerbehandlung geschrieben, aber nie ausgeführt wurde, wenn ein Lade- oder Leerzustand überprüft werden muss, wenn ein Fehler nur bei einer langsamen Verbindung auftritt oder wenn ein Timer, eine Abfrage, ein Entprellen oder ein Wiederholungsversuch ohne Ruhezustand getestet werden muss.
