Fuerce los estados que una ejecución de happy-path nunca alcanza (una API fallida, una lista vacía, una solicitud lenta, un tiempo de espera, una sesión caducada, un brindis que se descarta automáticamente) y verifique que la interfaz de usuario realmente los maneje. Úselo cuando se escribió el manejo de errores pero nunca se ejecutó, cuando es necesario verificar un estado de carga o vacío, cuando un error solo ocurre en una conexión lenta o cuando un temporizador, sondeo, rebote o reintento necesita ser probado sin dormir.
