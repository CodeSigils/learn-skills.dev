Testgesteuerte Entwicklung für das Verhalten, das ein Komponententest nicht erreichen kann, indem die Erwartung gegen die laufende App geschrieben wird, bevor der Code geschrieben wird. Erklären Sie zuerst die Konsequenz, beobachten Sie, wie sie versagt, implementieren Sie sie, beobachten Sie, wie sie vorübergeht. Verwenden Sie es, wenn Sie eine benutzerorientierte Funktion erstellen, wenn der Benutzer nach TDD auf der Benutzeroberfläche oder Full-Stack-Arbeit fragt, wenn ein Komponententest das wichtige Ergebnis nicht ausdrücken kann oder wenn Sie eine rot-grüne Schleife wünschen, die gegen die echte App anstelle von Mocks läuft.
