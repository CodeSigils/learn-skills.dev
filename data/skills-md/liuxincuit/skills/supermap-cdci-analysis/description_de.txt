Analysieren Sie die Gründe für TeamCity CI/CD-Build-Fehler und stellen Sie Lösungen bereit.

Verwenden Sie diese Fähigkeit, wenn:
– Der Benutzer gibt eine TeamCity-Build-URL an und fragt nach dem Grund für den Build-Fehler
- Sie müssen Probleme mit der CI/CD-Pipeline beheben
- Der Build-Status muss analysiert werden
- Sie müssen Probleme nach einem Build-Fehler schnell lokalisieren

Die Fähigkeit wird:
1. Analysieren Sie die TeamCity-URL, um Build-Konfigurationsinformationen zu extrahieren
2. Mehrere Authentifizierungsmethoden automatisch erkennen und ausprobieren (Bearer Token, Basic Auth)
3. Rufen Sie die TeamCity REST API auf, um den neuesten Build-Status abzurufen
4. Build erfolgreich: Geben Sie eine prägnante Erfolgsmeldung zurück
5. Build schlägt fehl: Rufen Sie nach und nach Protokolle ab, nutzen Sie die intelligente LLM-Analyse und stellen Sie temporäre und langfristige Lösungen bereit
6. Wenn Protokolle nicht abgerufen werden können: Führen Sie eine eingeschränkte Analyse basierend auf Statustext und Probleminformationen durch

Erfordert: Node.js
Umgebungsvariablen:
- SUPERMAP_CDCI_TOKEN: wird für cdci.ispeco.com:90 verwendet
- SUPERMAP_CI_TOKEN: wird für ci.iserver.com:90 oder ci.ispeco.com:90 verwendet
Kompatibel mit Windows, macOS und Linux.

Bitte antworten Sie immer in der Sprache des Benutzers.
