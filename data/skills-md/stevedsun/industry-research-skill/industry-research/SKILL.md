# 行业调研

> 三阶段结构：Phase 1 生命周期 → Phase 2 七维分析 → Phase 3 资讯料理

---

## Phase 1：生命周期判断

> **输出**：行业处于哪个生命周期阶段，以及 Phase 2 应重点分析哪些维度

### Step 1：输入

用户输入目标行业名称（中文或英文均可）。

**示例**：`新能源汽车`、`AI Agent`、`预制菜`

### Step 2：搜索

```
搜索1: "<行业名> 定义 行业分类"
搜索2: "<行业名> 行业生命周期 渗透率"
搜索3: "<行业名> 市场规模 2024/2025"
搜索4: "<行业名> 头部公司 上市公司 主要玩家"
```

### Step 3：判断

根据渗透率综合判断阶段：

| 阶段 | 渗透率 | 核心特征 |
|------|--------|---------|
| **导入期** | <15% | 需求不明确、商业模式待验证、玩家分散 |
| **成长期** | 15–40% | 市场快速扩张、资本涌入、竞争激烈 |
| **成熟期** | >40% | 增速放缓、行业集中度提升、龙头效应明显 |
| **衰退期** | — | 需求萎缩、技术/产品被替代 |

**判断优先级**：① 权威机构渗透率数据 → ② 财报交叉验证 → ③ 以"渗透率+行业名"估算

### Step 4：输出

```
## Phase 1 结果

**行业**：[名称]
**阶段**：[导入期/成长期/成熟期/衰退期]
**渗透率**：[X]%（估算依据：[...]）

**Phase 2 维度重点**：

| 判断 | 最高权重 | 次高权重 | 可跳过 |
|------|---------|---------|-------|
| 导入期 | 可行性、规模性 | 外部因素 | 估值、景气度 |
| 成长期 | 规模性、盈利性 | 防守性、景气度 | — |
| 成熟期 | 防守性、盈利性、估值 | 规模性、外部因素 | 景气度 |
| 衰退期 | 防守性、景气度 | 外部因素 | 规模性、盈利性 |
```

### Phase 1 执行注意

1. **不捏造渗透率**：找不到时标注"估算"，不写假数字
2. **交叉验证**：至少两个独立信源才能确认阶段判断
3. **标注时间**：判断结论注明"截止至 YYYY-MM"
4. **行业定义优先**：先确认行业边界，不同口径结论可能不同

## Phase 2：七维深度分析

> **输入**：Phase 1 的阶段判断
> **输出**：七维评分 + 各维度核心结论
>
> 七维顺序：**可行性 → 规模性 → 防守性 → 盈利性 → 估值 → 外部因素 → 景气度**
>
> ⚠️ **搜索即输出**：每个维度的搜索完成后，直接输出该维度的分析结论，不要等所有维度搜完再统一输出**

### 第一维 · 可行性

> **核心问题**：这个行业真的存在吗？需求是真是假？
> **重点**：导入期必做；成长期验证；成熟期/衰退期跳过
>
> **归档**：搜索结果 → `01_新闻资讯.md`（案例/事件）和 `02_研报数据.md`（商业模式验证）

```
搜索1: "<行业名> 需求 痛点 用户真的需要吗"
搜索2: "<行业名> 商业模式 可行性 验证"
搜索3: "<行业名> 用户案例 落地 规模化"
```

**输出**：

```
### 可行性

**需求真假**：真需求 / 伪需求 / 部分真实
**商业模式**：已验证 / 部分验证 / 待验证 / 模式不清
**落地进度**：[描述]
```

---

### 第二维 · 规模性（TAM / SAM / SOM）

> **核心问题**：这个行业的天花板有多高？
> **重点**：成长期权重最高；导入期次之；成熟期/衰退期可跳过
>
> **归档**：搜索结果 → `02_研报数据.md`（市场规模/渗透率数据）

```
搜索1: "<行业名> 市场规模 2024 2025"
搜索2: "<行业名> market size 2024 2025 CAGR"
搜索3: "<行业名> TAM SAM SOM"
搜索4: "<行业名> 中国 市场规模 2024 2025"
```

| 层级 | 定义 | 估算方法 |
|------|------|---------|
| TAM | 全球理论总市场 | 渗透率上限 × 用户基数 × 客单价 |
| SAM | 可服务市场 | TAM × 可触及比例 |
| SOM | 当前可获得市场 | SAM × 目标市占率 |

> 数据不足时，优先保 TAM + CAGR。CAGR 比精确数字更能反映成长性。

**输出**：

```
### 规模性

| 来源 | 2024/2025E | 预测年份 | 预测值 | CAGR |
|------|-----------|---------|-------|------|
| 机构A | XX亿元 | 2030E | XX亿元 | XX% |

**交叉验证**：[可信/分歧较大]（原因：口径差异 / 统计维度不同）
**TAM / SAM / SOM**：[数据或估算依据]
```

### 第三维 · 防守性（护城河 / 竞争格局）

> **核心问题**：行业里的玩家靠什么活？谁在侵蚀谁的份额？
> **重点**：成熟期权重最高；成长期和衰退期必做
>
> **归档**：护城河搜索 → `02_研报数据.md`；竞争格局/五力搜索 → `05_社交讨论.md`（市场争议）

搜索4: "<行业名> 转换成本 用户粘性"（转换成本）

| 护城河类型 | 特征 | 举例 |
|-----------|------|------|
| 无形资产 | 品牌、专利、特许经营权 | 可口可乐、药企专利 |
| 转换成本 | 用户切换代价高 | iOS生态、Adobe |
| 网络效应 | 用户越多价值越大 | 微信、Visa |

| 格局类型 | 特征 | 参考标准 |

| 完全竞争 | 玩家众多、产品同质化 | CR3 <40% |
| 垄断竞争 | 差异化竞争，品牌重要 | CR3 40–70% |
| 寡头垄断 | 少数玩家主导 | CR3 >70% |
| 双寡头 | 两强相争 | 两强合计 >70% |
| 一家独大 | 龙头垄断 | 龙头 >50% |

### 第五维 · 估值

> **核心问题**：当前是贵还是便宜？
> **重点**：成熟期和衰退期权重最高；成长期参考为主
>
> **归档**：搜索结果 → `03_财务数据.md`（PE/PS等估值数据）

```
搜索1: "<行业名> 市盈率 PE TTM"
搜索2: "<行业名> PS 市销率 EV/EBITDA"
搜索3: "<行业名> 估值 历史分位 10年 5年"
```

| 估值方法 | 适用场景 | 含义 |
|---------|---------|------|
| P/E | 盈利稳定的成熟行业 | 越低越便宜 |
| P/S | 亏损或低利润行业 | 越低越便宜 |
| EV/EBITDA | 重资产行业 | 剔除折旧影响 |
| P/B | 金融、资产重行业 | 净资产溢价 |

**输出**：

```
### 估值

**当前水平**：[高/中/低]（历史分位 XX%）
**估值方法**：[P/E/P/S/EV/EBITDA]
**判断**：相对于历史，当前估值 [偏贵/合理/偏宜]（原因）
```

### 第七维 · 景气度

> **核心问题**：现在是不是入场好时机？
> **重点**：成长期和成熟期权重最高

```
搜索1: "<行业名> 先行指标 PMI 订单 库存"
搜索2: "<行业名> 库存 周期 去库存 补库存"
搜索3: "<行业名> 资本开支 CapEx 扩张"
搜索4: "<行业名> 机构配置 持仓 公募基金"
搜索5: "<行业名> 分析师评级 覆盖"
```

**库存周期四阶段**：

| 阶段 | 特征 | 信号 |
|------|------|------|
| 主动去库存 | 需求↓ + 生产↓ | 价格跌，股价往往先于商品见底 |
| 被动去库存 | 需求↑ + 生产未恢复 | 价格上涨，景气回升初期 |
| 主动补库存 | 需求↑ + 积极扩产 | 量价齐升，景气高峰 |
| 被动补库存 | 需求↓ + 生产仍高位 | 价格松动，景气见顶 |

**资金情绪**：
- 机构配置（滞后指标）：公募持仓变化、分析师评级分布
- 一级市场热度（反向指标）：融资频率、估值倍数偏离基本面

**输出**：

```
### 景气度

**周期位置**：[复苏期/繁荣期/见顶期/衰退期]
**库存周期**：[阶段]
**估值情绪**：极度乐观 / 乐观 / 中性 / 悲观 / 极度悲观

**入场判断**：
- [现在是入场好时机 / 中性观望 / 等待更好的买点]
- 原因：[一句话]
```

### Phase 2 执行注意

1. **搜索即输出**：每个维度搜完立即输出结论，不用等全部搜完
2. **规模数据优先保 CAGR**：精确数字各家口径不一，CAGR 趋势更一致
3. **盈利性优先找财报**：上市公司数据最可信，避免引用未验证的估算
4. **警惕虚假护城河**：高毛利率不等于护城河，可能是昙花一现的景气度
5. **一级市场热度是反向指标**：一级市场最疯狂时往往是景气顶点

## Phase 3：资讯料理法

> **定位**：Phase 2 七维分析完成后，基于归档文件提炼观点、输出行业报告
> **核心问题**：如何把归档的原始材料变成有观点的行业报告？
>
> ⚠️ **前置条件**：Phase 2 的归档动作已完成，`01_新闻资讯.md` ~ `05_社交讨论.md` 已存在。Phase 3 从读取这些文件开始。
>
> ⚠️ **硬规则**：本阶段只读取归档文件提炼观点，不再发起新搜索。所有搜索在 Phase 2 已完成并归档。

---

### Step 1：读取归档文件（烹饪备料）

> 每次只读一个文件，处理完再读下一个。

**读取顺序**：`00_元信息.md` → `01_新闻资讯.md` → `02_研报数据.md` → `03_财务数据.md` → `04_政策文件.md` → `05_社交讨论.md`

---

### Step 2：提炼（写入 06-08）

**Step 2.1 交叉验证** → `06_交叉验证.md`

> 对 Phase 1-2 的核心结论做正反验证。找不出质疑证据的结论是脆弱的。

```
## [Phase X 中的具体结论]

**支持证据**：
1. [来源：文件名]：[具体证据]

**质疑证据**：
1. [来源：文件名]：[具体证据]

**综合判断**：[成立 / 需要修正 / 证据不足] — [原因]
```

**Step 2.2 核心矛盾提炼** → `07_核心矛盾.md`

> 提炼 3 个核心矛盾。矛盾是报告的灵魂，没有矛盾的分析是平面的。

```
## 矛盾一：[标题]

**正方论点**：[...]
**反方论点**：[...]
**当前判断**：[哪方占优] — [判断依据]
```

**Step 2.3 信息盲区** → `08_信息盲区.md`

> 诚实标注置信度低的领域，让报告读者知道边界在哪。

```
## 缺少的数据
- [描述]（可能导致偏差：[影响]）

## 置信度低的领域
- [描述]（需进一步调研）
```

---

### Step 3：摆盘（输出报告）

> **输入**：06_交叉验证.md + 07_核心矛盾.md + 08_信息盲区.md
> **输出**：`~/out/行业调研/[行业名]/09_行业调研报告.md`

**报告模板**：

```
## [行业名] 行业调研报告

**日期**：YYYY-MM-DD
**生命周期**：[Phase 1 判断]
**核心结论**：[一句话]

---

### 一、行业定义与边界
[2-3段]

### 二、生命周期判断
[Phase 1 结论 + 验证依据]

### 三、核心矛盾与观点
[3个矛盾，各含正方/反方/当前判断]

### 四、关键数据汇总
[市场规模、渗透率、主要玩家财务数据]

### 五、风险与机会
**Top 3 风险**：[各1句话]
**Top 3 机会**：[各1句话]

### 六、结论与建议
[综合 Phase 1-3，给出行动建议或研究结论]
```

**观点表达规范**：

| 要素 | 要求 |
|------|------|
| 有数据 | 结论必须有数字支撑 |
| 有来源 | 每个事实标注来源 |
| 有立场 | 明确表达判断，不模糊 |
| 有边界 | 标注结论的适用条件 |

## 完整工作流

```
输入：目标行业
  │
  ▼

  │  → Phase 1 输出：阶段判断 + Phase 2 维度重点
  ▼
Phase 2：七维深度分析（按维度权重执行）
  │  ┌─────────────────────────────────────┐
  │  │ 每维度：搜索 → 写入归档文件 → 输出结论 │
  │  │ （归档动作内嵌在每个维度里，不是单独阶段） │
  │  └─────────────────────────────────────┘
  │  → 归档完成：01~05 文件 + 00_元信息.md（含Phase1-2结论）
  ▼
Phase 3：资讯料理法（读取归档文件 → 提炼 → 报告）
  │  Step 1：读取归档文件
  │  Step 2：提炼（06交叉验证/07核心矛盾/08信息盲区）
  │  Step 3：摆盘输出 09_行业调研报告.md
  ▼
输出：~/out/行业调研/[行业名]/09_行业调研报告.md
```

## 执行通用注意

1. **不臆测**：数据找不到标注"数据不足"，不捏造
2. **交叉验证**：至少两个独立信源才能确认一个关键数字
3. **标注时间**：所有判断注明"截止至 YYYY-MM"
4. **动态眼光**：周期、护城河、景气度都会迁移，定期重评
5. **搜索即归档**：归档不是独立阶段，是搜索的副产物——每搜完一批材料，立即写入对应文件，不在内存中积累
6. **Phase 3 不搜索**：Step 2 只读取文件，不再发起新搜索；Phase 3 的输入全部来自 Phase 2 的归档文件
