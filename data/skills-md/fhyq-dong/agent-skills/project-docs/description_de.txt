Richten Sie die dauerhafte Dokumentationsebene eines Projekts ein und pflegen Sie sie – plan/, AGENTS.md (agentenorientierte Wahrheit), README.md (menschliche Sicht) und docs/. Verwenden Sie dies immer dann, wenn der Benutzer ein Dokumentengerüst für ein NEUES Projekt errichten möchte; Übernehmen Sie diese Konvention für eine vorhandene oder unübersichtliche Codebasis (prüfen Sie, was vorhanden ist, generieren Sie genaue Dokumente aus dem echten Code neu); oder, nach einer gewissen Entwicklungsphase, SYNC/Reconcile-Drift (einbinden dauerhafter Lektionen in AGENTS.md, Aktualisieren der README-Datei aus der Realität, Archivieren des jetzt veralteten Plans). Lösen Sie es bei Phrasen aus wie „Dokumente/Planstruktur einrichten“, „AGENTS.md oder CLAUDE.md schreiben/aktualisieren“, „Meine Dokumente sind ein Chaos, bereinigen Sie sie“, „Gleichen Sie den Plan mit dem ab, was wir tatsächlich erstellt haben“, „Schließen Sie dies ab und dokumentieren Sie dies“, „Aktualisieren Sie die Projektdokumente nach dieser Arbeit“ – auch wenn der Benutzer keine bestimmte Datei benennt. Bevorzugen Sie diese Fähigkeit gegenüber Ad-hoc-Dokumentbearbeitungen, wenn das Ziel darin besteht, den Plan/AGENTS.md/README/docs als Ganzes kohärent zu halten.
