Luban – der Workshop zum Polieren von Fertigkeiten. Es verfeinert eine „nutzbare Fertigkeit“ zu einem öffentlichen Fertigkeitsgut, das „verständlich, installierbar, gemeinsam nutzbar, überprüfbar und kontinuierlich weiterentwickelt“ ist.

Die Methodik besteht aus fünf handwerklichen Schritten:

1. **Materialinspektion** – Testen Sie zunächst, ob die Prämisse der Fertigkeit zutrifft; Wenn das Material es nicht wert ist, geschnitzt zu werden, sagen Sie es direkt.  
2. **Feldumfrage** – Durchsuchen Sie das Netzwerk nach ähnlichen Fähigkeiten, um herauszufinden, wo Ihre Fähigkeiten in das Ökosystem passen.  
3. **Messung anhand von Standards** – Verwenden Sie drei Messgeräte zusammen: Struktur, empirische Tests und Live-Ausführung (das Live-Messgerät überprüft das tatsächlich laufende Produkt; grünes CI kann täuschen).  
4. **Langsames Planen** – Originalversion als Basis einfrieren; Alle Änderungen müssen ein Verifizierungstor passieren, um beibehalten zu werden, andernfalls werden sie rückgängig gemacht. Verifizierungsmethoden sollten in Tools und Regeln zusammengefasst werden, die im Repository gespeichert sind.  
5. **Neu schmieden** – Das Veröffentlichen ist nicht das Ende; Hinterlassen Sie eine Benchmark-Beobachtungscheckliste und versorgen Sie die nächste Runde mit echtem Feedback.

Verwenden Sie diesen Prozess, wenn ein Benutzer eine von ihm entwickelte Fähigkeit aktualisieren, optimieren, verfeinern, produktivisieren oder veröffentlichen möchte. Die endgültigen Ergebnisse sind ein strukturierter „Skill Polishing Report“, direkt austauschbare Rewrite-Snippets und eine Screenshot-fähige „Mastery Certificate“-Ergebniskarte.

Auslöserphrasen umfassen unter anderem: „Lassen Sie Luban diesen Skill sehen“, „Polieren Sie vor der Tür des Masters“, „Polieren Sie meinen Skill“, „Upgrade meines Skills“, „Optimieren Sie diesen Skill“, „Skill-Gesundheitscheck“, „Skill-Audit“, „Produktisieren Sie meinen Skill“, „So veröffentlichen Sie diesen Skill“, „Benchmark mit ähnlichen Skills“, „Warum installiert niemand meinen Skill“, „Helfen Sie mir, den Skill auf GitHub/ClawHub zu pushen“, „SKILL.md verbessern“.

Selbst wenn der Benutzer einfach ein Skill-Verzeichnis, einen GitHub-Repo-Link oder ein SKILL.md-Snippet ablegt und sagt: „Helfen Sie mir, herauszufinden, wie ich es verbessern kann“, sollte der Workflow ausgelöst werden, solange der Kontext den Skill nutzbarer und gemeinsamer macht.

Verwenden Sie dies **nicht** zum Erstellen eines brandneuen Skills von Grund auf (verwenden Sie den Skill-Creator), für die normale Codeüberprüfung (verwenden Sie die Codeüberprüfung) oder zum Umschreiben nicht verwandter allgemeiner Eingabeaufforderungen.
