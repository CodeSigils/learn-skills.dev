Luban — the Skill Polishing Workshop. It refines a “usable skill” into a public skill asset that is “understandable, installable, shareable, verifiable, and continuously evolvable.”

The methodology consists of five craftsman-like steps:

1. **Material Inspection** – First test whether the skill’s premise holds; if the material isn’t worth carving, say so outright.  
2. **Field Survey** – Search the network for similar skills to see where yours fits in the ecosystem.  
3. **Measure Against Standards** – Use three gauges together: structure, empirical testing, and live execution (the live gauge checks the actual running product; green CI can be deceptive).  
4. **Slow Planing** – Freeze the original version as a baseline; any changes must pass a verification gate to be kept, otherwise revert. Verification methods should be distilled into tools and rules stored in the repository.  
5. **Re‑forge** – Publishing is not the end; leave a benchmark observation checklist and feed the next round with real feedback.

Use this process when a user wants to upgrade, optimize, polish, productize, or release a skill they have developed. The final deliverables are a structured “Skill Polishing Report,” directly replaceable rewrite snippets, and a screenshot‑ready “Mastery Certificate” result card.

Trigger phrases include but are not limited to: “Let Luban see this skill,” “Polish at the master’s door,” “Polish my skill,” “Upgrade my skill,” “Optimize this skill,” “Skill health check,” “Skill audit,” “Productize my skill,” “How to publish this skill,” “Benchmark against similar skills,” “Why does nobody install my skill,” “Help me push the skill to GitHub/ClawHub,” “Improve SKILL.md.”

Even if the user just drops a skill directory, a GitHub repo link, or a SKILL.md snippet and says “Help me see how to improve it,” as long as the context is making the skill more usable and shareable, the workflow should be triggered.

Do **not** use this for creating a brand‑new skill from scratch (use skill‑creator), for ordinary code review (use code‑review), or for rewriting unrelated generic prompts.
