製品要件、実装計画、バグ修正、リファクタリング、自動化リクエスト、コードレビューが大きくなりすぎる前にそれらをゲートします。ユーザーが要件設計、PRD 形成、実装計画、コーディング、デバッグ、リファクタリング、スクリプト作成、自動化、またはレビューを要求し、オーバーエンジニアリング、投機的抽象化、不必要な範囲、ソリューション優先の考え方、またはサイレント境界変更のリスクがある場合に使用します。また、ユーザーが「最小限の変更」、「シンプルに保つ」、「スコープ ゲート」、「オーバーエンジニアリングを避ける」、「オーバービルドしない」、「マスクの 5 ステップ法」、または「アルゴリズム」を言うときにも使用します。
