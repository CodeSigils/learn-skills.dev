Suivez quelles piles au sein d'une organisation Pulumi utilisent un package spécifique et dans quelles versions. À utiliser pour les audits inter-piles, l'identification des versions de package obsolètes ou non maintenues sur de nombreuses piles, la recherche des piles affectées avant de publier des modifications importantes dans un package de composants ou la planification de déploiements de mises à niveau coordonnés. Ne PAS utiliser pour mettre à niveau un package de fournisseur cloud (pulumi-aws, pulumi-azure-native, pulumi-gcp, pulumi-kubernetes, etc.) dans un seul projet — utilisez plutôt la compétence « supplier-upgrade ». Ne PAS utiliser pour la création générale d’une infrastructure, l’approvisionnement en ressources ou pour des questions pratiques sur un package.
