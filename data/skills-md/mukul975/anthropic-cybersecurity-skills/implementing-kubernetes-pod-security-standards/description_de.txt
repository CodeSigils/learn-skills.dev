Wählt und wendet den richtigen Kubernetes Pod Security Standard (Privileged, Baseline, Restricted) für einen Workload an: was jedes Profil verbietet, wie vorhandene Workloads einem Profil zugeordnet werden, welche securityContext‑Felder geändert werden müssen und wie eine Migration von PodSecurityPolicy zu PSS geplant wird, ohne laufende Pods zu unterbrechen. Verwenden Sie es, um zu entscheiden, welches Pod‑Sicherheitsprofil ein Namespace oder Workload verwenden soll, um zu prüfen, welche Workloads das Restricted‑Profil nicht bestehen, eine PSP‑Migration zu planen oder die Pod‑Sicherheitslage einer Compliance‑Kontrolle zuzuordnen. Schlüsselwörter: Pod Security Standards, PSS, Privileged, Baseline, Restricted, securityContext, runAsNonRoot, drop ALL capabilities, seccomp RuntimeDefault, PSP migration. Nicht zum Konfigurieren des Admission Controllers verwenden, der diese Profile durchsetzt – verwenden Sie implementing-pod-security-admission-controller.
