Unabhängige Testperspektive auf Abruf: Wenn ein Risikosignal ausgelöst wird oder ein Benutzer ausdrücklich ein Problem meldet, führen Sie ein Testaudit, das Füllen von Lücken und eine erneute Validierung der implementierten Änderung durch und erstellen Sie so einen prägnanten Test.md. Das Ändern des Geschäftscodes ist strengstens untersagt. Auslöser: Finden Sie einen zweiten Augensatz, um Tests/unabhängige Überprüfung durchzuführen/Tests für diese Änderung hinzuzufügen//EO-Test.  

NICHT FÜR: Routinetestläufe oder ergänzende Unit-Tests, die nichts mit der Änderung zu tun haben (führen Sie sie einfach direkt durch, kein Bericht erforderlich); Standardmäßige Selbstverifizierung der Hauptlinie (kategorisiert unter „EO-Implementierung“).
