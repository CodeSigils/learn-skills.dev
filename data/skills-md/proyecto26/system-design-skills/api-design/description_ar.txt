يجب استخدام هذه المهارة عندما يحتاج المستخدم إلى "تصميم واجهة برمجة التطبيقات"، أو "تصميم نقطة النهاية"، أو تحديد "شكل الطلب/الاستجابة"، أو اختيار استراتيجية "ترقيم الصفحات" (المؤشر مقابل الإزاحة)، أو إضافة "مفتاح الفاعلية" إلى الكتابة، أو التخطيط لإصدار واجهة برمجة التطبيقات، أو "عقد الخطأ"، أو الاختيار بين "REST vs gRPC vs GraphQL" أو "WebSocket vs polling". استخدمه كلما وصل التصميم إلى الواجهة - الطلب الملموس، والاستجابة، ومسار الوصول الأساسي، وكيفية صفحة العملاء، وإعادة المحاولة، والإصدار - حتى لو قال المستخدم فقط "تتحدث الصناديق مع بعضها البعض".
