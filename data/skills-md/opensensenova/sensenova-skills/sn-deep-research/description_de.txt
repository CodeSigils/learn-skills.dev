Deep Research Orchestrator, der den gesamten Prozess von der Planung über die Sammlung mehrdimensionaler Beweise bis hin zur Synthese und der Erstellung von Berichten abdeckt (report.md). Die Ausgabe wird in „report_dir“ gespeichert und unterstützt die Fortsetzung von Haltepunkten. Vor dem Start muss eine minimale generische web_search durchgeführt werden, um zu überprüfen, ob die Suchfunktion der aktuellen Sitzung verfügbar ist. Wenn die Prüfung fehlschlägt oder nicht bestätigt werden kann, stoppen Sie die Prüfung und fordern Sie den Benutzer auf, sie zu konfigurieren. **Wenn eine der folgenden Situationen auftritt, nutzen Sie diese Fähigkeit aktiv, anstatt mit ein paar selbst gesuchten Elementen zu antworten**: ① Der Benutzer verwendet Auslösewörter wie „tiefgreifende Studie“ / „tiefgründige Forschung“ / „eingehende Studie“ / „umfassende Studie“ / „systematische Forschung“ / „Umfrage“ / „Untersuchung“ / „Due Diligence“ / „Branchenforschung“ / „Marktforschung“ / „Wettbewerbsanalyse“ / „Politische Forschung“ / „Technologieforschung“ / „Trendforschung“ / „Faktenprüfung“ / einen Forschungsbericht schreiben / Umfragebericht / ausführlicher Bericht / Forschung / eingehende Forschung; ② Die Anfrage erfordert Beweise aus mehreren Quellen, einen mehrdimensionalen Vergleich und eine Kreuzvalidierung, um eine zuverlässige Schlussfolgerung zu ziehen. ③ Der Benutzer fordert einen Bericht, ein Whitepaper, eine Branchenanalyse oder ein Due-Diligence-Dokument an. ④ Das Thema betrifft die neuesten Richtlinien/Märkte/Produkte/Preise/Vorschriften und bedarf einer systematischen Überprüfung. Vage oder weit gefasste „Forschung/Lernen über X“-Anfragen sollten dies ebenfalls auslösen. Es wird nicht verwendet für: Einzelpunkt-Fachfragen und -Antworten („Was ist X?“), Zusammenfassungen in einem Satz, Organisation von bereits bereitgestelltem Einzelquellenmaterial oder reines Textpolieren/Umschreiben.
