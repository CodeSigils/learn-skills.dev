SDD Workflow v1.0.3 開発ワークフローをプロジェクトにインストールします。スキルのインストール パスを自動的に解決し、**AGENTS.md** (コア ルール + 焼き付けられたパス) を生成し、同時に **CLAUDE.md** (シンボリックリンク → AGENTS.md、クロード コードが自動的に読み取られます) を生成し、オンデマンド読み取りのためにステージ ルール ファイル (rules/) をスキル ディレクトリに保持し、オプションで他の AI ツールと同期します。

**アーキテクチャ**: G シリーズのグローバル ルール + §1 ～ §4 のステージ番号 + フロー宣言ヘッダー メカニズム (**4 値ブロック** true/false/gated/audit-required を含む) + 動的ローディング + **統合実行自己監査メカニズム** (クロスダイアログ キックオフ + 単一セッション内のセクションごとに 2 つのトリガー ポイント) + **context.md の「生成」フィールド** (アーティファクト パス + アンカー) + SHA-256 の最初の 8 文字、§2.4、§3.6、§3.7 の章でのみ必須) + **監査キックオフ チェックリスト** (§3.6 に入るとき、≥3 の疑いポイント + 検証) + **前セクションのアーティファクトの再挿入** (§2.5 / §3.7 / §3.8 に入るとき、cat 以前のアーティファクト + ハッシュ検証) + 13スラッシュ コマンド。複数の AI ツールと互換性があります。

**次のシナリオでトリガーする必要があります:**  
- ユーザーが「SDD をインストールする」、「AGENTS をインストールする」、「AI ワークフローをインストールする」、または「開発標準を構成する」と言います。  
- ユーザーが「/sdd-init」コマンドを実行します。  
- ユーザーが「ワークフローを開始する」または「開発を開始する」と言った ** が、プロジェクトのルート ディレクトリに `AGENTS.md`** がありません (フォールバック: SDD がインストールされていない場合は、最初にユーザーのためにインストールします。インストール後、**G0 ダイアログの初期化が自動的に続行される**ため、ユーザーは再度「ワークフローの開始」をトリガーする必要はありません)。  
- 新しいプロジェクトで AI コーディングのワークフロー仕様を確立する必要がある場合。  
- ユーザーは「ワークフローを更新」または「SDD を更新」と言います。

**注:**  
- クロード コードの組み込み `/init` コマンド (スタンドアロン CLAUDE.md を生成する) は、このワークフローによって作成された CLAUDE.md シンボリック リンクを上書きします。混ぜないでください。  
- ユーザーが「ワークフローを開始」と言うか、`/sdd-start` を実行すると、デフォルトで **プロジェクト開発プロセスに入ります** (G0 ダイアログの初期化)。 「AGENTS.md」が存在しない場合にのみ、このスキルにフォールバックしてインフラストラクチャのインストールを実行します。 **自然言語の「ワークフローの開始」によってトリガーされたフォールバック インストールは、完了後に最初の G0 パスで自動的に続行されます** (ステップ 0 のエントリ タイプの検出とステップ 7 のルーティング ブランチを参照)。そのため、ユーザーが再度トリガーする必要はありません。明示的な「/sdd-init」インストールのみ、「インストールしてからユーザー検証のために一時停止する」という 2 段階の設計が維持されます。  

**出力:**  
① プロジェクトルートディレクトリ内の`AGENTS.md` ({SKILL_DIR}は実際のパスに置き換えます)  
② `CLAUDE.md` (シンボリックリンク → `AGENTS.md`、Windows ではコピーフォールバックあり)  
③各AIツールのコマンドファイルへのシンボリックリンク  
④ スラッシュコマンドのインストール (ユーザーレベル / プロジェクトレベル / スキップのいずれかを選択します)  
⑤ 初期化状況レポート
