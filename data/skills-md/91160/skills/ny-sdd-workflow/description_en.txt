Install the SDD Workflow v1.0.3 development workflow into the project. Automatically resolve the skill installation path, generate **AGENTS.md** (core rules + baked‑in path), simultaneously generate **CLAUDE.md** (symlink → AGENTS.md, Claude Code reads automatically), keep stage rule files (rules/) in the skill directory for on‑demand reading, and optionally sync to other AI tools.

**Architecture**: G‑series global rules + §1 ~ §4 stage numbers + flow declaration header mechanism (including **four‑value blocking** true/false/gated/audit‑required) + dynamic loading + **Unified execution self‑audit mechanism** (cross‑dialogue kickoff + two trigger points per section within a single session) + **context.md `produced` field** (artifact path + anchor + first 8 characters of SHA‑256, mandatory only in chapters §2.4, §3.6, §3.7) + **Audit kickoff checklist** (when entering §3.6, ≥3 suspicion points + verification) + **Previous‑section artifact reinjection** (when entering §2.5 / §3.7 / §3.8, cat previous artifact + hash verification) + 13 Slash Commands, compatible with multiple AI tools.

**Must be triggered in the following scenarios:**  
- User says “install SDD”, “install AGENTS”, “install AI workflow”, or “configure development standards”.  
- User runs the `/sdd-init` command.  
- User says “start workflow” or “begin development” **and the project root directory lacks `AGENTS.md`** (fallback: if SDD is not installed, install it for the user first; after installation, **automatically continue with G0 dialogue initialization**, so the user does not need to trigger “start workflow” again).  
- When a new project needs to establish an AI coding workflow specification.  
- User says “update workflow” or “update SDD”.

**Note:**  
- The built‑in `/init` command in Claude Code (which generates a standalone CLAUDE.md) will overwrite the CLAUDE.md symlink created by this workflow; do not mix them.  
- When the user says “start workflow” or runs `/sdd-start`: by default it **enters the project development process** (G0 dialogue initialization). It only falls back to this Skill to perform infrastructure installation if `AGENTS.md` does not exist; **the fallback installation triggered by the natural‑language “start workflow” automatically continues with the first G0 path after completion** (see Step 0 entry‑type detection + Step 7 routing branch), so the user does not need to trigger it again; only an explicit `/sdd-init` installation retains the two‑stage design of “install then pause for user verification.”  

**Outputs:**  
① `AGENTS.md` in the project root directory ({SKILL_DIR} replaced with the actual path)  
② `CLAUDE.md` (symlink → `AGENTS.md`, with copy fallback on Windows)  
③ Symlinks to command files for each AI tool  
④ Slash Commands installation (choose one: user‑level / project‑level / skip)  
⑤ Initialization status report
