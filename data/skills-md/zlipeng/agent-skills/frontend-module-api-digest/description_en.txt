Investigate any front‑end view (page / route / section / tab / popup / drawer / dashboard card / chart / filter form / list / detail page, etc.) for functional modules, and compile which fields each module displays (label, value fields, list columns, filter conditions, statistical metrics) along with the corresponding query interfaces. When a user says “investigate/summary of the display content under a certain page (or module)”, “what fields and interfaces are there”, “what is the field mapping”, “which interface does this field come from”, “how are these codes displayed as names”, “which interfaces are invoked by the filter conditions”, “where does the data for this dashboard card come from”, etc., trigger this— even if they don’t explicitly mention “summary interfaces”, as long as they are sorting out a view/module’s display content and data source, use this skill. It applies to scenarios in front‑end repositories such as React, UMI, Vue, where data‑source mapping is done according to the “view → module → field/list/metric → interface” structure.
