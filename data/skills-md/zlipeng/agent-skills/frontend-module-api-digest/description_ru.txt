Изучите любое интерфейсное представление (страница/маршрут/раздел/вкладка/модальное окно/панель/карточка информационной панели/диаграмма/форма фильтра/список/страница сведений и т. д.), чтобы определить его функциональные модули и скомпилировать для каждого модуля отображаемые поля (метка, поля значений, столбцы списка, критерии фильтрации, статистические метрики) и соответствующие API-интерфейсы запросов. Когда пользователь говорит «исследуйте/скомпилируйте отображаемый контент определенной страницы (или модуля)», «какие поля и API существуют», «каково сопоставление полей», «из какого API взято это поле», «как отображать эти коды в виде имен», «какие API вызываются по критериям фильтра», «откуда берутся данные для этой карточки панели мониторинга» и т. д., этот навык срабатывает — даже если он явно не говорит «компилировать API», пока он сортирует отображаемый контент и данные. источник представления/модуля, используйте этот навык. Это применимо к сценариям во фронтенд-репозиториях, таких как React/UMI/Vue, где сопоставление источников данных выполняется в соответствии со структурой «представление → модуль → поля/список/метрики → API».
