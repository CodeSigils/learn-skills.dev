Examinez le code pour la justification, les termes de domaine, les contraintes et les hypothèses manquantes pour un nouveau venu, et produisez un arriéré de documentation. À utiliser lorsqu'on vous demande un examen d'intégration, ce qui pourrait perturber une nouvelle embauche, ce qui manque lors d'un transfert ou quelles parties d'une base de code doivent être documentées en premier. Ne l'utilisez PAS pour trouver des défauts (utilisez la révision du code) ou pour développer votre propre compréhension d'un code inconnu (utilisez grok-repo).
