风险点：
- NPE bug已修复（事后）：v14初版加了cfg.LOFTR.COARSE.NPE =
  [832,832,640,640] 想跨分辨率布局，但实际拉伸比=1.3 RoPE
  位置相位错位50%，ep0 auc@10=0.214<outdoor.ckpt基线0.30+。
  根因:position_encoding.py:21-22 的train_res / test_resstretch 是给
  外推法用的（输入 > 训练，例如 LoFTR 论文 MegaDepth1500 1152
  输入与 832 列车）； v14 long_side 640 < 832 是插值，整数
  位置 (1..20) 是outdoor.ckpt 学过 (1..26) 的子集，注意兼容
  很好，不该伸展。 修复：删除 cfg.LOFTR.COARSE.NPE 显式设置，让
  train.py:130 后备 [832,832,832,832]（比率=1.0）。 跑 v14 / 衍生
  版本前再次检查 cfg 是否错误添加 NPE 覆盖。
- 数据cfg合并顺序：v14 ddp main cfg不要也设置MGDPT_IMG_RESIZE=640
  （会被数据cfg覆盖，审计时困惑；在main cfg里设置IMG_RESIZE是死的
  代码）。
- Outdoor.ckpt 负载兼容：outdoor.ckpt 是 832 train, RoPE buffer sin/cos
  按 max_shape=(256,256) + npe=[832,832,832,832] 算。 v14 后备 NPE
  跟outdoor.ckpt完全一致（都是[832,832,832,832]不拉伸），
  register_buffer(persistent=False) 不入 ckpt (position_encoding.py:37-38),
  v14自动使用后备NPE计算缓冲区，完全兼容。
- bs=4 显存预算: 实测 832+bs=4 OOM, 640+bs=4 理论 -29% sim_matrix Peak +
  4 GB cuDNN/NCCL 实测预期 ~17 GB / 卡，留 7 GB 余量，安全。 第一次跑前
  nvidia-smi 看交叉值。
- GPU 蒸发: v13 实测 GPU 0/2/3: 81-87 C (GPU 2 接近 88 C 散热
  节流阈值），GPU 1：66 C 不错。 当GPU 2触发油门时，整组
  NCCL all_reduce 等最慢排名拖慢 5-10%。 v14 跑前任选 sudo nvidia-smi
  -i 2 -pl 280 限制 GPU 2 功率 87->78 C，步进时间 -5% 但避免节流
  净持平。
