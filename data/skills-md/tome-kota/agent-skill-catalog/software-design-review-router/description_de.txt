Verwenden Sie diese Fertigkeit, wenn der Benutzer eine Überprüfung des Softwaredesigns, eine Architekturkritik, eine Überprüfung des Domänenmodells, eine Grenzüberprüfung, eine ADR-Kritik, eine Namensüberprüfung, eine Analyse der Abhängigkeitsauswirkungen, eine Überprüfung der Änderungsresilienz, eine Überprüfung der Skalierbarkeit oder Performance-Governance, eine Überprüfung der Sicherheit/Autorisierung/Überprüfbarkeit oder eine Überprüfung eines KI-generierten Plans oder einer Codeänderung aus Entwurfsperspektive wünscht. Verwenden Sie es auch, wenn der Benutzer Entwurfssymptome beschreibt, ohne die Entwurfsüberprüfung direkt zu benennen, z. B. unklare Servicegrenzen, widersprüchliche Verantwortlichkeiten, riskante Schemaänderungen, spröde Kopplung, schwache Mandantenisolierung, überladene Bedingungen, Unsicherheit über Aggregate und Eigentumsverhältnisse, Pläne mit vielen Workarounds oder die Sorge, dass eine Änderung zu ad hoc erfolgt, um zukünftige Änderungen zu überstehen. Verwenden Sie es nicht für einfache Implementierung, Syntaxhilfe, Framework-Tutorials oder isolierte Fehlerbehebungen.
