Esta habilidad debe usarse cuando el usuario desea revisar el código, auditar una diferencia, obtener una segunda opinión sobre los cambios o ejecutar una revisión contradictoria. Los desencadenantes comunes incluyen "revisar este código", "auditar esta diferencia", "encontrar problemas en", "segunda opinión sobre esto", "revisión exhaustiva de", "revisar las relaciones públicas", "revisión contradictoria" y "revisión de seguridad de". Elige uno de los cuatro revisores (adversario, seguridad, arquitectura, rendimiento), admite un submodo de relaciones públicas a través de "gh pr diff" y puede pasarlo a cualquier CLI de IA detectada para obtener una segunda opinión entre modelos. Omita cuando el usuario quiera corregir el formato (use un linter) o refactorizar patrones (use ts-best-practices o ts-best-practices-function).
