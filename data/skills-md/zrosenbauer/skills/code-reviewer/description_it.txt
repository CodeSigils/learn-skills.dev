Questa capacità dovrebbe essere utilizzata quando l'utente desidera rivedere il codice, verificare una differenza, ottenere una seconda opinione sulle modifiche o eseguire una revisione contraddittoria. I trigger più comuni includono "rivedi questo codice", "controlla questa differenza", "trova problemi in", "seconda opinione su questo", "revisione severa di", "rivedi il PR", "revisione contraddittoria" e "revisione della sicurezza di". Sceglie uno dei quattro personaggi del revisore (antagonista, sicurezza, architettura, prestazioni), supporta una sottomodalità PR tramite "gh pr diff" e può passare a qualsiasi CLI AI rilevata per una seconda opinione tra modelli. Salta quando l'utente desidera correzioni di formattazione (usa un linter) o modelli di refactoring (usa ts-best-practices o ts-best-practices-functional).
