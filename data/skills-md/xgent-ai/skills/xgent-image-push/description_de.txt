Erstellen Sie das App-Image und übertragen Sie es in ein selbstgehostetes privates Harbor-Image-Repository (die Adresse wird durch die lokale Konfiguration bereitgestellt und nicht in diesem Skill beschrieben). Wenn Benutzer die Veröffentlichung einer Version, das Starten einer neuen Version, das Veröffentlichen eines Images, das Pushen eines Images, den Docker-Push, das Markieren und Pushen in das Repository, das Konfigurieren der Image-Erstellungs- und Push-Schritte von CI, das private Image-Repository, Harbor, das fehlerhafte Pushen des Roboterkontos, das Hängenbleiben des Pushs oder die Push-Phase vor ImagePullBackOff erwähnen, verwenden sie alle diese Fähigkeit – auch wenn sie nur „eine Version veröffentlichen“ oder „das Image des Dienstes pushen“ sagen, ohne das Repository zu benennen. Vor dem Push werden automatisch vier harte Einschränkungen vorab überprüft, die dazu führen würden, dass die Pipeline stillschweigend ausfällt (Link, Image-Architektur, unveränderliches Tag, Aufbewahrungsrichtlinie). Wenn man es umgeht und einen direkten Docker-Push ausführt, stößt man leicht auf eine dieser Einschränkungen.
