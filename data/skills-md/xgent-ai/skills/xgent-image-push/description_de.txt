Erstellen Sie das App-Image und übertragen Sie es in ein selbstgehostetes privates Harbor-Image-Repository (die Adresse wird durch die lokale Konfiguration bereitgestellt und wird in diesem Skill nicht geschrieben). Immer wenn Benutzer die Veröffentlichung einer Version, die Bereitstellung einer neuen Version, die Veröffentlichung eines Images, das Pushen eines Images, den Docker-Push, das Markieren und Pushen in das Repository, das Konfigurieren von CI-Image-Build-Push-Schritten, ein privates Image-Repository, Harbor, ein Roboterkonto, das nicht pushen kann, einen Push, der hängen bleibt, oder ImagePullBackOff vor der Push-Phase erwähnen, nutzen sie alle diese Fähigkeit – auch wenn sie nur „eine Version veröffentlichen“ oder „das Image dieses Dienstes pushen“ sagen, ohne einen Repository-Namen anzugeben. Es prüft vor dem Push automatisch vier harte Einschränkungen, die dazu führen würden, dass die Pipeline stillschweigend ausfällt (Verknüpfung, Image-Architektur, unveränderliches Tag, Aufbewahrungsrichtlinie). Wenn Sie es umgehen und einen rohen Docker-Push ausführen, wird einer von ihnen leicht ausgelöst.
