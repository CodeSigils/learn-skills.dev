Créez l'image de l'application et transférez-la vers un référentiel d'images Harbor privé auto-hébergé (l'adresse est fournie par la configuration locale et n'est pas écrite dans cette compétence). Chaque fois que les utilisateurs mentionnent la publication d'une version, le déploiement d'une nouvelle version, la publication d'une image, le push d'une image, le push docker, le marquage et le push vers le référentiel, la configuration des étapes de génération d'image CI, un référentiel d'images privé, Harbor, un compte robot qui ne peut pas pousser, un push qui reste bloqué ou ImagePullBackOff avant l'étape de push, ils utilisent tous cette compétence - même s'ils disent seulement « publier une version » ou « pousser l'image de ce service » sans spécifier de nom de référentiel. Il pré-vérifie automatiquement quatre contraintes strictes qui entraîneraient l'échec silencieux du pipeline avant de le pousser (liaison, architecture d'image, balise immuable, politique de rétention) ; le contourner et effectuer une poussée brute du docker déclenche facilement l'un d'entre eux.
