独自のアプリのリポジトリで、Docker を使用してローカル統合テスト用に実際の XGENT.ai ポータル (ワンボックス) をスピンアップします。ポータルの複製やポータル コードの変更、ポータル イメージの再構築は必要ありません。単一の `onebox.sh init` でローカル プラーの資格情報 (`.xgent-registry.env` の `REGISTRY` と `PULLER_AUTH`; がない場合は停止し、ユーザーに開発チームから取得してもらいます) をチェックします。 → 自動的に `docker login` してポータル イメージをプルします → イメージから構成アセットを抽出し、空きポートを選択し、`compose.env` を生成します。次に、固定の順序で「移行」→「シード」→「登録アプリ」を実行→スタックを開始し、最後に iframe/curl を使用して完全なチェーンを検証します。  

「デバッグのためにアプリをポータルに初めて接続する / ワンボックスをスピンアップする / ローカル ポータルを開始する / ポータル イメージをプルする / ローカル ポータルの統合が失敗する / ワンボックスのリセット」を伴うタスクの場合、またはポータル イメージのプルの失敗、未承認、拒否、`/svc/<key>` 404 または 502、ローカルホストに到達できない、「ポートはすでに割り当てられています」、`COMPOSE_PROJECT_NAME` の衝突の原因などのエラーが発生した場合引き継がれる他のコンテナ、常に異常なポータル API、「VALIDATION_FAILED」を報告する「register-app」、イントロスペクション 401、有効な TDT が「INVALID_TOKEN」と判断される、iframe の白い画面、イニシエーターでクロスアプリケーション交換が 401 を取得するなど、「docker compose」を実行する前に必ず最初にこのスキルを使用してください。たとえユーザーが「持ってくる」としか言わなかったとしてもポータルがアップします。」  

外部アプリ チームが、ポータル モノリポジトリを使用せずに、実際の XGENT ポータルを独自のリポジトリからローカル (ワンボックス Docker スタック) で起動、スモークテスト、リセット、またはデバッグするときに使用します。
