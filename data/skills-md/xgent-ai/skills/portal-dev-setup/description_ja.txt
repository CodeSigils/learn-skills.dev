独自のアプリのリポジトリで、Docker を使用してローカル統合テスト用に実際の XGENT.ai ポータル (ワンボックス) を起動します。ポータルの複製やポータル コードの変更、ポータル イメージの再構築は必要ありません。単一の `onebox.sh init` はローカル プラーの認証情報 (`.xgent-registry.env` 内の REGISTRY と PULLER_AUTH; が見つからない場合は停止し、ユーザーに開発チームから取得するように要求します) をチェックします。 → 自動的に `docker login` を実行し、ポータル イメージをプルします → イメージから構成アセットを抽出し、空きポートを選択し、`compose.env` を生成します。次に、固定の順序で、移行 → シード → アプリの登録 → スタックの開始が実行され、その後、iframe または Curl によって完全なエンドツーエンドのフローが検証されます。 「最初にアプリをポータルに接続してデバッグする / one-box を開始する / ローカル ポータルを起動する / ポータル イメージを取得する / ローカル ポータルの統合に失敗する / one-box をリセットする」といったタスクの場合、またはポータル イメージを取得できない、未承認、拒否された、`/svc/<key>` 404 または 502、localhost に到達できない、ポートがすでに割り当てられている、COMPOSE_PROJECT_NAME の衝突が他のものを引き継ぐなどの症状が発生した場合コンテナー、ポータル API の異常な状態、登録アプリの VALIDATION_FAILED レポート、イントロスペクション 401、有効な TDT が INVALID_TOKEN と判断される、iframe の空白画面、イニシエーターでのクロスアプリケーション交換が 401 を取得するなど、ユーザーが「ポータルを起動する」としか言わなかったとしても、Docker Compose を実行する前に必ず最初にこのスキルを使用してください。外部アプリ チームが、ポータル モノリポジトリを使用せずに、実際の XGENT ポータルを独自のリポジトリからローカル (ワンボックス Docker スタック) で起動、スモークテスト、リセット、またはデバッグするときに使用します。
