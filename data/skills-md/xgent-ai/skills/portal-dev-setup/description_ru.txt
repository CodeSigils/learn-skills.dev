В репозитории вашего собственного приложения используйте Docker, чтобы развернуть настоящий портал XGENT.ai (единый блок) для локального интеграционного тестирования — без клонирования портала, без изменения кода портала и без пересоздания образа портала. Один `onebox.sh init` проверяет учетные данные локального средства извлечения (`REGISTRY` и `PULLER_AUTH` в `.xgent-registry.env`; если они отсутствуют, остановите работу и предложите пользователю получить их от команды разработчиков) → автоматически `docker login` и извлеките образ портала → извлеките ресурсы компоновки из образа, выберите свободные порты, сгенерируйте `compose.env`; затем в фиксированном порядке запустите `migrate` → `seed` → `register-app` → запустите стек и, наконец, используйте iframe/curl для проверки полной цепочки.  

Для любой задачи, которая включает в себя «первое подключение моего приложения к порталу для отладки / развертывание One-Box / запуск локального портала / извлечение образа портала / сбой интеграции локального портала / сброс One-Box» или когда такие ошибки, как невозможность получения образа портала, несанкционированный, запрещенный, `/svc/<key>` 404 или 502, localhost недоступен, «порт уже выделен», коллизия `COMPOSE_PROJECT_NAME`, приводящая к захвату других контейнеров, port-api постоянно неработоспособен, `register-app` сообщает `VALIDATION_FAILED`, самоанализ 401, валидный TDT оценивается как `INVALID_TOKEN`, белый экран iframe, межприложенный обмен получает ошибку 401 на инициаторе и т. д., обязательно сначала используйте этот навык перед запуском `docker Compose` — даже если пользователь просто говорит «поднимите портал».  

Используйте, когда внешняя группа приложений запускает, тестирует, сбрасывает или отлаживает реальный портал XGENT локально (единый стек Docker) из своего собственного репозитория, без монорепозитория портала.
