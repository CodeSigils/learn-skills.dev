자신의 앱 저장소에서 Docker를 사용하여 로컬 통합 테스트를 위한 실제 XGENT.ai 포털(원박스)을 가동하세요. 포털을 복제하지 않고, 포털 코드를 수정하지 않고, 포털 이미지를 다시 빌드하지 않고도 가능합니다. 단일 `onebox.sh init`은 로컬 풀러 자격 증명(`.xgent-registry.env`의 `REGISTRY` 및 `PULLER_AUTH`, 누락된 경우 중지하고 사용자가 개발 팀에서 이를 얻도록 함) → 자동으로 `docker login` 및 포털 이미지 가져오기 → 이미지에서 compose 자산 추출, 무료 포트 선택, `compose.env` 생성; 그런 다음 고정된 순서로 ` migration` → `seed` → `register-app`을 실행하고 스택을 시작한 다음 마지막으로 iframe/curl을 사용하여 전체 체인을 확인합니다.  

"디버깅을 위해 내 앱을 포털에 처음 연결/원박스 실행/로컬 포털 시작/포털 이미지 가져오기/로컬 포털 통합 실패/원박스 재설정"과 관련된 모든 작업의 경우 또는 포털 이미지 가져오기 실패, 승인되지 않음, 거부됨, `/svc/<key>` 404 또는 502, localhost 연결 불가, "포트가 이미 할당되었습니다", `COMPOSE_PROJECT_NAME` 충돌로 인해 다른 컨테이너가 인계되는 경우, Portal‑api 지속적으로 비정상, 'VALIDATION_FAILED'를 보고하는 'register-app', 내부 검사 401, 유효한 TDT가 'INVALID_TOKEN'으로 판단됨, iframe 흰색 화면, 개시자에서 401이 발생하는 애플리케이션 간 교환 등은 사용자가 "포털을 불러오세요"라고만 말하더라도 `docker compose`를 실행하기 전에 먼저 이 기술을 사용해야 합니다.  

외부 앱 팀이 포털 단일 저장소 없이 자체 저장소에서 실제 XGENT 포털을 로컬로(원박스 Docker 스택) 불러오고, 연기 테스트, 재설정 또는 디버깅할 때 사용합니다.
