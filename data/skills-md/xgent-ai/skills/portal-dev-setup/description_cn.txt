在你自己的应用仓库中，使用 Docker 启动一个真实的 XGENT.ai 门户（单箱）进行本地集成测试——无需克隆门户代码、无需修改门户代码，也无需重新构建门户镜像。只需执行一次 `onebox.sh init`，它会检查本地拉取凭证（`.xgent‑registry.env` 中的 `REGISTRY` + `PULLER_AUTH`；如果缺失则停止并提示用户向开发团队获取）→ 自动执行 `docker login` 并拉取门户镜像 → 从镜像中提取 compose 资源，选择空闲端口，生成 `compose.env`；随后按固定顺序执行：`migrate` → `seed` → `register‑app` → 启动整个堆栈，之后即可通过 iframe 或 curl 运行完整的端到端流程。对于任何涉及“首次将我的应用连接到门户 / 启动单箱 / 运行本地门户 / 拉取门户镜像 / 本地门户集成失败 / 重置单箱”的任务，或遇到拉取门户镜像失败、`unauthorized`、`denied`、`/svc/<key>` 404 或 502、本地主机不可达、`port is already allocated`、`COMPOSE_PROJECT_NAME` 冲突导致其他容器被占用、`portal‑api` 持续不健康、`register‑app` 报告 `VALIDATION_FAILED`、自检 401、有效的 TDT 被判定为 `INVALID_TOKEN`、iframe 空白、跨应用交换在发起方收到 401 等错误时，请务必先使用此方法再运行 `docker compose`——即使用户仅说“启动门户”。当外部 App 团队从自己的仓库本地启动、冒烟测试、重置或调试真实的 XGENT 门户（单箱 Docker 堆栈）时，请使用此技能，而无需门户 monorepo。
