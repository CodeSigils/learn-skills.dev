在您自己的应用程序存储库中，使用 Docker 启动真正的 XGENT.ai 门户（一体机）进行本地集成测试，无需克隆门户、无需修改门户代码、也无需重建门户映像。单个`onebox.sh init`检查本地puller凭据（`.xgent-registry.env`中的`REGISTRY`和`PULLER_AUTH`；如果丢失，停止并让用户从开发团队获取它们）→自动`docker登录`并拉取门户镜像→从镜像中提取compose资产，选择空闲端口，生成`compose.env`；然后，按照固定的顺序，运行 `migrate` → `seed` → `register-app` → 启动堆栈，最后使用 iframe/curl 验证全链。  

对于任何涉及“第一次将我的应用程序连接到门户进行调试/启动一体机/启动本地门户/拉取门户映像/本地门户集成失败/一体机重置”的任务，或者当错误拉取门户映像失败、未经授权、被拒绝、“/svc/<key>”404或502、本地主机无法访问、“端口已分配”、“COMPOSE_PROJECT_NAME”冲突导致其他容器被接管等错误时，portal-api不断不健康、“register-app”报告“VALIDATION_FAILED”、内省 401、有效 TDT 被判断为“INVALID_TOKEN”、iframe 白屏、跨应用程序交换在启动器上收到 401 等，请务必在运行“docker compose”之前首先使用此技能 - 即使用户只说“启动门户”。  

当外部应用程序团队从他们自己的存储库本地启动、冒烟测试、重置或调试真正的 XGENT 门户（一体式 Docker 堆栈）时使用，无需门户 monorepo。
