Verwenden Sie Docker im Repository Ihrer eigenen App, um ein echtes XGENT.ai-Portal (eine One-Box) für lokale Integrationstests einzurichten – ohne das Portal zu klonen, ohne den Portalcode zu ändern und ohne das Portal-Image neu zu erstellen. Ein einzelner „onebox.sh init“ prüft die lokalen Puller-Anmeldeinformationen (die „REGISTRY“ und „PULLER_AUTH“ in „.xgent-registry.env“. Wenn sie fehlen, halten Sie an und lassen Sie den Benutzer sie vom Entwicklungsteam erhalten) → automatisch „Docker-Login“ durchführen und das Portal-Image abrufen → die Compose-Assets aus dem Image extrahieren, freie Ports auswählen, „compose.env“ generieren; Führen Sie dann in einer festen Reihenfolge „migrate“ → „seed“ → „register-app“ → „Stack starten“ aus und verwenden Sie schließlich iframe/curl, um die vollständige Kette zu überprüfen.  

Für jede Aufgabe, bei der es darum geht, „meine App zum ersten Mal mit dem Portal zum Debuggen zu verbinden / eine One-Box hochzufahren / ein lokales Portal zu starten / das Portal-Image abzurufen / die Integration des lokalen Portals schlägt fehl / One-Box-Zurücksetzen“ oder wenn Fehler wie Fehler beim Abruf des Portal-Images, nicht autorisiert, verweigert, „/svc/<key>“ 404 oder 502, localhost nicht erreichbar, „Port ist bereits zugewiesen“, „COMPOSE_PROJECT_NAME“-Kollision, die dazu führt, dass andere Container übernommen werden vorbei, Portal-API ständig fehlerhaft, „Register-App“ meldet „VALIDATION_FAILED“, Selbstprüfung 401, ein gültiges TDT wird als „INVALID_TOKEN“ beurteilt, iframe-weißer Bildschirm, anwendungsübergreifender Austausch erhält 401 beim Initiator usw. Stellen Sie sicher, dass Sie diesen Skill zuerst verwenden, bevor Sie „Docker Compose“ ausführen – auch wenn der Benutzer nur „Bring das Portal hoch“ sagt.  

Wird verwendet, wenn ein externes App-Team ein echtes XGENT-Portal lokal (den One-Box-Docker-Stack) aus seinem eigenen Repo ohne das Portal-Monorepo aufruft, Smoke-Tests durchführt, zurücksetzt oder debuggt.
