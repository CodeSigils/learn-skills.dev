從高級產品經理的角度來看，將想法或請求轉變為可由 SPMS 生命週期管理的需求 - 專案級「概述/目標/非目標」加上逐項 FR/NFR（包括可斷言的驗收標準和測試案例種子），產生 PRD 文件並將其輸入 SPMS 作為開發計劃的先決條件輸入。每當使用者要求“編寫 PRD / 編寫需求文件 / 澄清需求 / 分解需求 / 提出需求 / 進行需求審查 / 將這個想法轉化為需求 / 輸入需求”，或者提供業務請求並期望首先定義“要做什麼、為什麼以及如何知道它已完成”時，請務必使用此技能 - 即使用戶沒有提到“PRD”一詞。當使用者希望在任何實施計劃發生之前將需求寫入、澄清、分解或歸檔到 SPMS (FR/NFR) 時，請使用。
