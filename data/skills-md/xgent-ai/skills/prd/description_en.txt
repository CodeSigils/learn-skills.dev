From the perspective of a senior product manager, turn an idea or request into a requirement that can be managed through the SPMS lifecycle—project-level “Overview/Goals/Non‑Goals” plus itemized FR/NFR (including assertable acceptance criteria and seed test cases), produce a PRD document and write it into SPMS as a prerequisite input for the development plan. Whenever a user asks to “write a PRD / write a requirements document / sort out requirements / break down requirements / submit requirements / conduct a requirements review / turn this idea into a requirement / log a requirement,” or provides a business demand and expects to first clarify “what to do, why, and how to know it’s done,” be sure to use this skill—even if the user doesn’t explicitly say “PRD.” Use it whenever the user wants requirements written, clarified, decomposed, or recorded in SPMS (FR/NFR) before any implementation planning takes place.
