From the perspective of a senior product manager, turn an idea or request into a requirement that can be managed by the SPMS lifecycle—project‑level “overview/objectives/non‑objectives” plus itemized FR/NFR (including assertable acceptance criteria and test‑case seeds), produce a PRD document and enter it into SPMS as a prerequisite input for the dev‑plan. Whenever a user asks to “write a PRD / write a requirements document / clarify requirements / decompose requirements / propose requirements / conduct a requirements review / turn this idea into requirements / input requirements,” or provides a business request and expects to first define “what to do, why, and how to know it’s finished,” be sure to use this skill—even if the user doesn’t mention the word “PRD.” Use whenever the user wants requirements written, clarified, decomposed, or filed into SPMS (FR/NFR) before any implementation planning happens.
