Verwandeln Sie aus der Sicht eines leitenden Produktmanagers eine Idee oder Anfrage in eine Anforderung, die vom SPMS-Lebenszyklus verwaltet werden kann – „Überblick/Ziele/Nichtziele“ auf Projektebene plus aufgeschlüsselter FR/NFR (einschließlich durchsetzbarer Akzeptanzkriterien und Testfall-Seeds), erstellen Sie ein PRD-Dokument und geben Sie es als Voraussetzung für den Entwicklungsplan in SPMS ein. Immer wenn ein Benutzer darum bittet, „eine PRD zu schreiben / ein Anforderungsdokument zu schreiben / Anforderungen zu klären / Anforderungen aufzuschlüsseln / Anforderungen einzureichen / eine Anforderungsüberprüfung durchzuführen / diese Idee in eine Anforderung umzuwandeln / eine Anforderung einzugeben“ oder eine Geschäftsanfrage stellt und zunächst definieren möchte, „was zu tun ist, warum und wie es als abgeschlossen betrachtet werden soll“, muss diese Fähigkeit verwendet werden – auch wenn der Benutzer „PRD“ nicht ausdrücklich erwähnt. Verwenden Sie es immer dann, wenn der Benutzer Anforderungen schriftlich, klärend, zerlegen oder in SPMS (FR/NFR) ablegen möchte, bevor eine Implementierungsplanung erfolgt.
