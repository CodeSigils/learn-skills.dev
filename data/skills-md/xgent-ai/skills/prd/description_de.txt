Verwandeln Sie aus der Sicht eines leitenden Produktmanagers eine Idee oder Anfrage in eine Anforderung, die vom SPMS-Lebenszyklus verwaltet werden kann – „Übersicht/Ziele/Nicht-Ziele“ auf Projektebene plus aufgeschlüsselte FR/NFR (einschließlich durchsetzbarer Akzeptanzkriterien und Testfall-Seeds), erstellen Sie ein PRD-Dokument und geben Sie es als Voraussetzung für den Entwicklungsplan in SPMS ein. Immer wenn ein Benutzer darum bittet, „eine PRD zu schreiben / ein Anforderungsdokument zu schreiben / Anforderungen zu klären / Anforderungen zu zerlegen / Anforderungen vorzuschlagen / eine Anforderungsüberprüfung durchzuführen / diese Idee in Anforderungen umzuwandeln / Anforderungen einzugeben“ oder eine Geschäftsanfrage stellt und erwartet, zunächst zu definieren, „was zu tun ist, warum und wie man weiß, dass es fertig ist“, stellen Sie sicher, dass Sie diese Fähigkeit verwenden – auch wenn der Benutzer das Wort „PRD“ nicht erwähnt. Verwenden Sie es immer dann, wenn der Benutzer Anforderungen schriftlich, klärend, zerlegen oder in SPMS (FR/NFR) ablegen möchte, bevor eine Implementierungsplanung erfolgt.
