Desde la perspectiva de un gerente de producto senior, convierta una idea o solicitud en un requisito que pueda ser administrado por el ciclo de vida del SPMS: “descripción general/objetivos/no objetivos” a nivel de proyecto más FR/NFR detallados (incluidos criterios de aceptación afirmables y semillas de casos de prueba), produzca un documento PRD e introdúzcalo en SPMS como un requisito previo para el plan de desarrollo. Siempre que un usuario solicite “escribir un PRD / redactar un documento de requisitos / aclarar requisitos / descomponer requisitos / proponer requisitos / realizar una revisión de requisitos / convertir esta idea en requisitos / requisitos de entrada”, o proporcione una solicitud comercial y espera definir primero “qué hacer, por qué y cómo saber que está terminado”, asegúrese de utilizar esta habilidad, incluso si el usuario no menciona la palabra “PRD”. Úselo siempre que el usuario desee que los requisitos se escriban, aclaren, descompongan o archiven en SPMS (FR/NFR) antes de que se realice cualquier planificación de implementación.
