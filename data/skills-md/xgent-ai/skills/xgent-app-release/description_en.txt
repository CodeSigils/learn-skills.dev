Publish a new version of an app to the XGENT.ai Portal — from the app’s own repository, use the xrel_ release token in a single command to submit the frontend artifact (dist), bump the version, switch the image, and the entire app.manifest manifest, creating a release proposal: changes that don’t affect governance take effect automatically, while permission‑related changes go through the platform’s “release review” approvals; no need to log into the portal console or ask portal operators to transmit anything. For any task involving releasing/publishing frontend or backend images, uploading artifacts, submitting or modifying app.manifest.json, onboarding an app to the portal for the first time, using release‑cli/xrel_ token/POST /api/market/release/, configuring vite base, writing release steps in CI, or encountering symptoms such as “publish 401/404”, “publish 200 but ok:false”, “PROPOSAL_PENDING / stuck pending review”, “/apps/<key>/ blank screen or resource 404”, “deployed but nothing changed online / container not updated”, always use this skill before proceeding— even if the user only says “publish a version”. Use whenever publishing or debugging an XGENT portal app release from the app’s own repo — frontend dist, backend image, or manifest/governance changes via release proposals: release tokens, packaging, version bumps, CI wiring, pending approvals, or a blank/404 /apps/<key>/ page after a publish.
