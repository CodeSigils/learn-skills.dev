Pubblicare una nuova versione di un'app sul portale XGENT.ai: dal repository dell'app, utilizzare il token anxrel_release in un singolo comando per inviare l'artefatto frontend (dist), eseguire il bump della versione, scambiare l'immagine e l'interoapp.manifestmanifest, creando una proposta di rilascio: le modifiche che non influiscono sulla governance diventano effettive automaticamente, mentre le modifiche relative alle autorizzazioni passano attraverso le approvazioni di "revisione del rilascio" della piattaforma; non è necessario accedere alla console del portale o chiedere agli operatori del portale di caricare. Qualsiasi attività che implica il rilascio/pubblicazione di un'immagine frontend o backend, il caricamento di artefatti, l'invio o la modifica di app.manifest.json, l'onboarding di un'app nel portale per la prima volta, l'utilizzo di release‑cli/xrel_token, POST/api/market/release/, la configurazione di Vite base, la scrittura di passaggi di rilascio in CI o l'incontro con sintomi come "publish401/404", "publish200 butok:false", "PROPOSAL_PENDING / sempre in attesa di approvazione", "/apps/<key>/ pagina vuota o risorsa404", "caricato ma nulla è cambiato online / il contenitore non ha cambiato versione" dovrebbe essere gestito con questa abilità prima di intraprendere qualsiasi azione, anche se l'utente dice solo "rilascia una versione". Da utilizzare ogni volta che si pubblica o si esegue il debug di una versione dell'app del portale XGENT dal repository dell'app: frontenddist, immagine backend o modifiche a manifest/governance tramite proposte di rilascio: token di rilascio, packaging, aggiornamenti di versione, cablaggio CI, approvazioni in sospeso o una pagina vuota/404/apps/<key>/ dopo una pubblicazione.
