Veröffentlichen Sie eine neue Version einer App im XGENT.ai-Portal – verwenden Sie aus dem eigenen Repository der App das anxrel_release-Token in einem einzigen Befehl, um das Frontend-Artefakt (dist) zu übermitteln, die Version zu aktualisieren, das Bild und das gesamte app.manifestmanifest auszutauschen und so einen Release-Vorschlag zu erstellen: Änderungen, die sich nicht auf die Governance auswirken, werden automatisch wirksam, während berechtigungsbezogene Änderungen die „Release-Review“-Genehmigungen der Plattform durchlaufen; Sie müssen sich nicht bei der Portalkonsole anmelden oder die Portalbetreiber zum Hochladen auffordern. Jede Aufgabe, die das Freigeben/Veröffentlichen eines Frontend- oder Backend-Images, das Hochladen von Artefakten, das Senden oder Ändern von app.manifest.json, das erstmalige Onboarding einer App in das Portal, die Verwendung von release-cli/xrel_token, POST/api/market/release/, das Konfigurieren der Vite-Basis, das Schreiben von Release-Schritten in CI oder das Auftreten von Symptomen wie „publish401/404“, „publish200 butok:false“ umfasst. „PROPOSAL_PENDING / ewig ausstehende Genehmigung“, „/apps/<key>/ leere Seite oder Ressource404“, „hochgeladen, aber online nichts geändert / Container hat die Version nicht gewechselt“ sollten zuerst mit diesem Skill behandelt werden, bevor Maßnahmen ergriffen werden – auch wenn der Benutzer nur „Version veröffentlichen“ sagt. Wird immer dann verwendet, wenn eine XGENT-Portal-App-Version aus dem eigenen Repo der App veröffentlicht oder debuggt wird – Frontenddist, Backend-Image oder Manifest-/Governance-Änderungen über Release-Vorschläge: Release-Tokens, Paketierung, Versionssprünge, CI-Verknüpfung, ausstehende Genehmigungen oder eine leere/404/apps/<key>/page nach einer Veröffentlichung.
