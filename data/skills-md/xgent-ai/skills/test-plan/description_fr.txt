Sur la base des exigences (texte PRD + critères d'acceptation), produisez un ensemble complet de projets de cas de test et écrivez-les dans SPMS (TC-N, lié aux exigences), couvrant quatre catégories : chemin normal, limite, autorisation et concurrence. Pour chaque critère d'acceptation, fournissez un mappage « critère → cas de test » et vérifiez les doublons avant d'écrire. Chaque fois qu'un utilisateur demande « ajouter des cas de test / écrire des cas de test / créer un plan de test / comment tester cette exigence / couvrir les critères d'acceptation / les cas de test sont-ils suffisants », assurez-vous d'utiliser cette compétence, même si l'utilisateur ne mentionne pas le mot « cas de test ». À utiliser chaque fois que l'utilisateur souhaite rédiger des cas de test, étendre la couverture des tests ou créer un plan de test dérivé des exigences SPMS et déposé en tant que TC-N via les outils PMS MCP.
