[Pragmatische DDD-Architektur] Leitfaden für Server- und Client-Komponenten im Next.js App Router. Verwenden Sie diese Option beim Erstellen einer beliebigen .tsx-Datei unter „presentation/components/“, „pages“ oder „layouts“ – auch bei der Entscheidung, ob „Client verwenden“ zu einer vorhandenen Komponente hinzugefügt werden soll, beim Übergeben von Daten von einer Serverkomponente an eine Clientkomponente, beim Zusammenstellen von Serverinhalten innerhalb eines Client-Slots, beim Umgang mit der VO-Serialisierungsgrenze, beim Erstellen zusammengesetzter Komponenten, beim Trennen der Logik für Mobil-/Desktop-Bildschirme oder beim Stylen mit „cva“ und „cn“. Behandelt: Entscheidung zwischen Server und Client, Muster für asynchrone Serverkomponenten, Erstellen von getSession-Rückrufen für Anwendungsfälle, Einschränkungen für Clientkomponenten, toBranded()-Grenzmuster, Zusammensetzung von untergeordneten Slots und Regeln für die Requisitenschnittstelle. Hängt von „Anwendungsfällen“ und „Serveraktionen“ ab.
