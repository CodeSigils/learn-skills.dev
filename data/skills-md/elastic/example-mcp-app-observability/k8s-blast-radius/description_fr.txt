Évaluer l'impact de la mise hors ligne d'un nœud Kubernetes — quels déploiements perdent toutes les répliques (panne totale), lesquels perdent une capacité partielle (dégradé), quels restent inchangés, et si le cluster dispose de suffisamment de capacité disponible pour replanifier les pods perdus. Utiliser lorsque l'utilisateur demande « que se passe‑t‑il si le nœud X tombe », « quel est le rayon d’impact du vidage de ce nœud », « puis‑je entretenir le nœud Y en toute sécurité », « que tourne‑t‑il sur ce nœud », « si j’évince ce nœud, qu’est‑ce qui se casse », ou planifie une maintenance de nœud, une mise à jour du cluster, ou enquête sur une défaillance réelle d’un nœud. Nécessite Kubernetes (métriques kubeletstats) et Elastic APM pour l’impact sur les services en aval — ne pas déclencher pour les déploiements hors K8s.

Veuillez toujours répondre dans la langue de l'utilisateur.
