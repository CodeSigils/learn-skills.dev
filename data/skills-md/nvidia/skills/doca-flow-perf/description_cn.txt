当用户使用 doca_flow_perf 测量 DOCA Flow 管道的主机或 DPU-CPU 控制平面速率时，请使用此技能 — 从 configs/ 选择 JSON 策略，选择 DPDK 或 DOCA 后端，运行单次迭代 Smoke，然后运行迭代 eval 循环，解释每次迭代 CPU 周期和 num_pushed / num_failed，或捕获四元组（DOCA 版本、BlueField/固件、JSON 策略、 worker/queue/burst 配置），使 Kops/sec 数字变得可防御。即使用户没有明确提及“doca-flow-perf”，也会触发 — 典型的隐式短语包括“我的 BlueField 每秒可以插入多少条规则”、“5 元组发夹规则速率”、“转向每秒每秒数”、“flow-perf 数量与发行说明不匹配”、“DPDK 与 DOCA 基准测试”或“规则安装方差太高”。拒绝并路由到其他地方以优化实时 Flow 应用程序 (doca-flow-tune)、DPA 卸载路径 (doca-flow-dpa-perf)、数据平面吞吐量或延迟或库内部管道语义 - 这些属于其他技能。
