Utilizzare questa abilità quando l'utente esegue doca_dpa_hl_tracer per acquisire/decodificare le tracce lato DPA al livello degli eventi di programmazione (entrata/uscita del kernel, punti di sincronizzazione, chiamate primitive di comunicazione, invio RDMA WR, drenaggio del completamento) - selezionando TRACE vs CRIT, ottimizzando la configurazione JSON (limiti di dimensione file + file_size_limit_policy, priorità/core dei thread), decodifica rispetto all'ELF lato DPA corrispondente o diagnosi di vuoto/rumoroso cattura. Si attiva anche quando l'utente non menziona esplicitamente "tracciante DOCA DPA" o "tracciante di alto livello": le frasi implicite tipiche includono "il kernel DPA restituisce un risultato errato ma i completamenti dell'host sembrano puliti", "la latenza dell'ingresso del kernel nella prima comunicazione è enorme", "RDMA WR per drenare il gap sul DPA", "file di traccia troncato a metà esecuzione", "TRACE ha raddoppiato la latenza del mio DPA" o "tracer ha scritto un file ma il parser mostra zero eventi". Rifiuta e indirizza altrove la scrittura di kernel DPA, la programmazione DPA-Comms/DPA-Verbs, la profilazione DPA grezza per ciclo, il debug doca-dpa lato host o la telemetria DPA di produzione: appartengono ad altre competenze.
