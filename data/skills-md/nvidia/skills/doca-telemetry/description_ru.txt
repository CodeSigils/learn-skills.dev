Используйте этот навык при чтении **событий аппаратного счетчика DOCA** из `doca_dev` через библиотеки чтения телеметрии DOCA для каждого домена — `doca_telemetry_pcc`, `_dpa`, `_diag`, `_adp_retx`, `_phy`, `_pci`. Это поверхность **counter-READER** — здесь нет структуры сборщика NetFlow/IPFIX/local-socket; пакет ранее сформировал его таким образом, и это кадрирование неверно. Каждый домен предоставляет свой собственный API `doca_telemetry_{domain}_*`: cap-запрос `_cap_is_supported(devinfo)`, `_create()` на `doca_dev`, `_start()`, затем чтение/выборка для каждого домена. Срабатывает, даже если пользователь не произносит «DOCA Telemetry» — типичные неявные фразы: «прочитать счетчики PCC из моего приложения BlueField», «пример экспорта счетчиков DPA», «открыть счетчики PHY/PCI/DIAG из этого `doca_dev`». Отказаться и направить куда-либо еще для стороны публикации/экспорта (`doca-telemetry-exporter`), службы телеметрии DOCA (DTS) в развернутом виде (выходит за рамки), сборщиков NetFlow/IPFIX и простого ведения журнала stdout.
