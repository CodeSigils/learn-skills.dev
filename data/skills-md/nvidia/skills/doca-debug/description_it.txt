Utilizzare questa abilità quando l'utente sta eseguendo il debug di qualsiasi sintomo DOCA (una build che non viene compilata, un passaggio di collegamento che non è in grado di risolvere un simbolo doca_*, una chiamata di runtime che restituisce DOCA_ERROR_*, un servizio o uno strumento silenzioso o una traccia dello stack / valgrind / core dump) e necessita della scala a più livelli (installazione → versione → build → collegamento → runtime → programma → driver), controlli di verbosità (--sdk-log-level, DOCA_LOG_LEVEL, il doca-{lib}-trace sapore), vincoli di debug del contenitore o come acquisire lo stato per un post del forum degli sviluppatori. Si attiva anche quando l'utente non dice "debug DOCA" - le frasi implicite includono "riferimento non definito a doca_*", "come posso ottenere più log", "i pacchetti non raggiungono il cavo", "doca_caps non ha restituito nulla" o "hugepages vuote nel contenitore". Rifiuta e instrada altrove per il debug specifico della libreria (traccia del tubo di flusso, RDMA QP, statistiche Comch), sintomi pkg-config di classe env o hugepages, la tassonomia DOCA_ERROR_* e l'interpretazione del ciclo di vita e il lavoro sulle prestazioni o sulla risposta agli incidenti: questi appartengono ad altre competenze.
