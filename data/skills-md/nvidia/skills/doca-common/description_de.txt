Verwenden Sie diese Fähigkeit immer dann, wenn der Benutzer praktische DOCA-Programmierung auf einer BlueField-DPU oder einer ConnectX-NIC durchführt und die Grundprimitive benötigt, auf denen jeder bibliotheksspezifische Kontext basiert – den Lebenszyklus von doca_ctx durchlaufen, doca_dev / doca_devinfo entdecken und auf doca_*_cap_* zugreifen, bevor er einer Funktion vertraut, und doca_mmap / doca_buf_inventory / doca_buf für Zero-Copy-I/O miteinander verbinden Bibliotheken, die doca_pe für Vervollständigungen steuern, oder das zweistufige (--sdk-log-level vs. app-seitige) Modell von DOCA Log. Wird auch dann ausgelöst, wenn der Benutzer nicht „DOCA Common“ sagt – typische implizite Formulierungen sind „meine Aufgaben werden übermittelt, aber nichts wird abgeschlossen“, „DOCA_ERROR_BAD_STATE von doca_ctx_start“, „--sdk-log-level macht nichts für meine DOCA_LOG_DBG-Zeilen“, „teilen sich einen Buff zwischen doca_dma und doca_rdma“ oder „stürzt weit entfernt von der fehlerhaften Zeile ab“. Verweigern Sie und leiten Sie für bibliotheksbezogene Fragen isoliert an einen anderen Ort weiter (laden Sie nebenher doca-flow / doca-rdma / doca-eth), installieren Sie DOCA (doca-setup) oder dokumentieren Sie die Suche (doca-public-knowledge-map).
