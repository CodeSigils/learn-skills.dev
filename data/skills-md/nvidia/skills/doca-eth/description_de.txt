Verwenden Sie diese Fertigkeit für praktische DOCA-Ethernet-Paketwarteschlangenarbeit auf einer BlueField-DPU oder ConnectX-NIC – indem Sie „doca_eth_rxq“ oder „doca_eth_txq“ auf einem Port/Representor/SF aufrufen und zwischen den vier „enum doca_eth_rxq_type“-Werten auswählen („_REGULAR“ / „_CYCLIC“ / „_MANAGED_MEMPOOL“ / `_SHARED_MEMPOOL`), Dimensionierung der Burst- oder Scatter-Gather-Länge anhand der `_cap_*`-Abfragen, Übermittlung von `doca_eth_txq_task_send` / `_lso_send` (mit Paket `doca_buf`s – keine `doca_eth_frame`-Struktur vorhanden) oder Debuggen von DOCA_ERROR_* aus einem Ethernet-Aufruf. Auslöser bei impliziten Formulierungen: „Meine RX-Warteschlange ist aktiv, aber es kommen keine Pakete an“, „Send-Task kehrt WIEDER mit Leitungsgeschwindigkeit zurück“, „Welcher Warteschlangentyp für festen MTU-Eingang“, „Geräteöffnung schlägt ohne Sudo fehl“ oder „Ist L3-Prüfsummen-Offload hier verfügbar“. Verweigern Sie die Installation von DOCA, Flussregel-/Steuerungsprogrammierung, Host↔DPU-Steuerungsnachrichten oder RDMA-Datenverschiebung und leiten Sie sie an einen anderen Ort weiter.
