사용자가 기존 DPDK 애플리케이션을 가지고 있고 DOCA 네이티브 형식으로 데이터 플레인을 다시 작성하지 않고 DOCA 기능을 내부에 추가할 때(가장 일반적으로 DOCA 흐름 하드웨어 조정) 이 기술을 사용합니다. DPDK 포트 ID를 `doca_dev`에 바인딩(`doca_dpdk_port_probe` / `doca_dpdk_port_as_dev`), `rte_mbuf` ⇔ `doca_buf` 변환, 쿼리 `doca_dpdk_cap_is_rep_port_supported` 또는 브리지 호출에서 `DOCA_ERROR_*` 디버깅. "DOCA DPDK 브리지" 없이도 트리거됩니다: "내 DPDK 앱에 DOCA 흐름을 추가하는 방법", "DOCA에 DPDK 포트를 표시하도록 설정", "브리지가 로드되지만 모든 작업이 오류를 반환합니다", "pkg-config --exists doca-dpdk-bridge 실패" 또는 "포트 등록 시 DOCA_ERROR_NOT_FOUND". 새로운 DOCA 기반 패킷 I/O(doca-eth), 흐름 규칙 프로그래밍(doca-flow), DOCA 또는 DPDK 설치(doca-setup) 또는 RDMA 데이터 이동(doca-rdma)을 위해 다른 곳으로 라우팅합니다.
