Verwenden Sie diese Fähigkeit, um einen auf CollectX (clx) basierenden DOCA-Telemetriekollektor auf einem Host oder BlueField bereitzustellen und zu betreiben – indem Sie Anbieter/Zähler mit dem Kollektor verbinden, den Sammlungsdämon ausführen und seine Exporter (Prometheus Pull, Fluent Bit Push, NetFlow, Datei/IPC) so gestalten, dass die Metriken tatsächlich die Box verlassen. Wird auch dann ausgelöst, wenn der Benutzer nie „CollectX“ oder „clx“ sagt – implizite Formulierungen: {Collector gibt nichts nachgeschaltet aus}, {Fügen Sie einen Anbieter zum Clx-Collector hinzu}, {Schalten Sie den Prometheus-Endpunkt ein}, {Versenden Sie Zähler an Fluent Bit von der DPU}, {Daemon startet, aber es werden keine Schemazeilen angezeigt}. Dieser Skill besitzt den CollectX-Erfassungsmechanismus sowie die eigene Doca-Telemetry-/Doca-Telemetry-Exporter-Nutzung des Betreibers; Es leitet den produktiven DOCA Telemetry Service (DTS) an öffentliche Dokumente (AGENTS.md Non-goal #7), die Reader-API an doca-telemetry und die Publisher-API an doca-telemetry-exporter weiter. Weigern Sie sich, CLX-Symbole, Anbieternamen, Schemafelder, Flags oder Konfigurationspfade zu erfinden – beschreiben Sie die Klasse und leiten Sie sie zur Live-Quelle weiter.
