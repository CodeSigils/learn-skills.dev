このスキルは、出荷されたサンプルまたは新しい DOCA を使用するアプリでの実践的な DOCA Arg Parser CLI 作業、つまりフラグの追加/削除/名前変更に使用します。 `doca_argp_init` → register params → `doca_argp_start` → `doca_argp_destroy` の順に配線します。完全なパブリック列挙型 (`DOCA_ARGP_TYPE_STRING`、`_INT`、`_BOOLEAN`、`_DEVICE`、`_DEVICE_REP`、`_DOUBLE` — 3 つではなく 6 つの値) からパラメーター タイプを選択します。標準の `--device` / `--representor` / `--json` (`-j`; 実際のフラグは `--json-config` ではなく `--json`) / `--sdk-log-level` の表面を維持します。または、`doca_argp_*` から `DOCA_ERROR_BAD_STATE` / `INVALID_VALUE` / `NOT_SUPPORTED` / `NOT_FOUND` / `IO_FAILED` をデバッグします。暗黙的なフレーズでトリガーします: 「DOCA サンプルにカスタム フラグを追加する」、「ここで getopt を使用する必要がありますか」、「新しいパラメータを登録する BAD_STATE」、「JSON 構成キーが拒否されました」、または「サンプルの --json が無視されます」。可変引数フラグ/サブコマンド/シェル補完機能、DOCA コア コンテキスト、または DOCA ログ内部については拒否し、別の場所にルーティングします。
