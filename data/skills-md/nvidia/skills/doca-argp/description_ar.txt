استخدم هذه المهارة للعمل العملي على DOCA Arg Parser CLI على عينة مشحونة أو تطبيق جديد يستخدم DOCA - إضافة / إزالة / إعادة تسمية العلامات؛ توصيل الأسلاك `doca_argp_init` ← تسجيل المعلمات ← `doca_argp_start` ← `doca_argp_destroy` بالترتيب؛ اختيار نوع معلمة من التعداد العام الكامل (`DOCA_ARGP_TYPE_STRING`، `_INT`، `_BOOLEAN`، `_DEVICE`، `_DEVICE_REP`، `_DOUBLE` - ست قيم، وليس ثلاث)؛ الحفاظ على سطح `--device` / `--representor` / `--json` (`-j`؛ العلامة الحقيقية هي `--json`، وليس `--json-config`) / `--sdk-log-level`؛ أو تصحيح أخطاء `DOCA_ERROR_BAD_STATE` / `INVALID_VALUE` / `NOT_SUPPORTED` / `NOT_FOUND` / `IO_FAILED` من `doca_argp_*`. تشغيل العبارات الضمنية: "أضف علامة مخصصة إلى عينة DOCA"، أو "هل يجب أن أستخدم getopt هنا"، أو "تسجيل BAD_STATE لمعلمة جديدة"، أو "تم رفض مفتاح تكوين JSON الخاص بي"، أو "تم تجاهل --json الخاص بعينتي". قم بالرفض والتوجيه إلى مكان آخر للحصول على ميزات إكمال العلامة / الأوامر الفرعية / shell أو سياق DOCA Core أو عناصر DOCA Log الداخلية.
