Utilisez cette compétence pour un travail pratique DOCA Arg Parser CLI sur un échantillon expédié ou une nouvelle application utilisant DOCA : ajout/suppression/renommage d'indicateurs ; câblage `doca_argp_init` → paramètres d'enregistrement → `doca_argp_start` → `doca_argp_destroy` dans l'ordre ; choisir un type de paramètre dans l'énumération publique complète (`DOCA_ARGP_TYPE_STRING`, `_INT`, `_BOOLEAN`, `_DEVICE`, `_DEVICE_REP`, `_DOUBLE` — six valeurs, pas trois) ; préserver la surface standard `--device` / `--representor` / `--json` (`-j` ; le véritable indicateur est `--json`, PAS `--json-config`) / `--sdk-log-level` ; ou le débogage de `DOCA_ERROR_BAD_STATE` / `INVALID_VALUE` / `NOT_SUPPORTED` / `NOT_FOUND` / `IO_FAILED` à partir de `doca_argp_*`. Déclencheur sur des formulations implicites : "ajouter un indicateur personnalisé à un échantillon DOCA", "dois-je utiliser getopt ici", "BAD_STATE enregistrant un nouveau paramètre", "ma clé de configuration JSON est rejetée" ou "le --json de mon échantillon est ignoré". Refusez et acheminez ailleurs pour les fonctionnalités de drapeau variadique/sous-commande/d'achèvement de shell, le contexte DOCA Core ou les éléments internes de DOCA Log.
