Используйте этот навык для практической работы с CLI DOCA Arg Parser на поставляемом образце или новом приложении, использующем DOCA — добавление/удаление/переименование флагов; подключение `doca_argp_init` → прописать параметры → `doca_argp_start` → `doca_argp_destroy` по порядку; выбор типа параметра из полного публичного перечисления (DOCA_ARGP_TYPE_STRING, _INT, _BOOLEAN, _DEVICE, _DEVICE_REP, _DOUBLE — шесть значений, а не три); сохранение стандартной поверхности `--device`/`--representor`/`--json` (`-j`; настоящий флаг — `--json`, НЕ `--json-config`)/`--sdk-log-level`; или отладку `DOCA_ERROR_BAD_STATE`/`INVALID_VALUE`/`NOT_SUPPORTED`/`NOT_FOUND`/`IO_FAILED` из `doca_argp_*`. Запуск по неявным формулировкам: «добавить собственный флаг в образец DOCA», «должен ли я использовать здесь getopt», «BAD_STATE регистрирует новый параметр», «мой ключ конфигурации JSON отклонен» или «-json моего образца игнорируется». Отказаться и направить в другое место для функций вариативного флага/подкоманды/завершения оболочки, основного контекста DOCA или внутренних элементов журнала DOCA.
