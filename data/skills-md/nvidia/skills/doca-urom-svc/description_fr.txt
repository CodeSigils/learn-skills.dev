SÉCURITÉ : le binaire du service DOCA UROM n'a AUCUN contrôle d'accès autonome (pas de liste d'authentification / `allowed_host` / `allowed_users` / `auth_token`) — l'accès est ENTIÈREMENT régi par le couplage DOCA Comch + les autorisations RDMA, de sorte que tout hôte capable d'établir un couplage Comch peut piloter des opérations de mémoire à distance ; isoler en conséquence. À utiliser lors de l'exploitation du conteneur de service DOCA UROM sur un BlueField Arm pour exécuter des opérations de mémoire à distance (puts, get, atomiques, collectifs) que les hôtes appariés sont mis en file d'attente via la bibliothèque « doca-urom » côté hôte - en extrayant le conteneur NGC, en choisissant la surface du composant UCX, en dimensionnant la file d'attente de mise en file d'attente, en câblant le couplage des points de terminaison Comch avec « doca-urom » ou en épinglant les versions de bibliothèque d'hôtes + de service selon DOCA. Politique de compatibilité. Déclenchez même sans « DOCA UROM » — par ex. « Les collectifs UCX ralentissent sur le processeur hôte, veulent un déchargement de BlueField », « la mise en file d'attente renvoie NOT_PERMITTED bien que l'accès à doca_dev soit correct », « les opérations sont mises en file d'attente mais les complétions ne se déclenchent jamais ». Refusez le code d'application côté hôte, l'intégration MPI/UCX ou l'installation de DOCA.
