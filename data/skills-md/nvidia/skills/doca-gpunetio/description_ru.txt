Используйте этот навык, когда пользователь выполняет практическое программирование DOCA GPUNetIO — подключает ядро CUDA на графическом процессоре NVIDIA к очереди doca-eth через doca_gpu_eth_rxq / doca_gpu_eth_txq, поддерживает контекст doca_gpu для каждого CUDA-устройства, проектирует постоянное ядро CUDA, которое опустошает видимую для GPU очередь, выполняет проверку двойной возможности (DOCA cap-query плюс cudaGetDeviceProperties), регистрацию пулов cudaMalloc через doca_buf_arr_create_* или отладку DOCA_ERROR_*, возвращаемых API GPUNetIO. Срабатывает, даже если пользователь явно не упоминает «DOCA GPUNetIO» или «постоянное ядро» — типичные неявные формулировки включают в себя «ядро CUDA читает пакеты непосредственно из сетевого адаптера», «сеть, инициируемая графическим процессором на BlueField», «DOCA_ERROR_DRIVER на doca_gpu_create», «nvidia_peermem не загружен», «ядро на пакет слишком медленно» или «какой графический процессор поддерживает сторону графического процессора». пакетный ввод-вывод».
