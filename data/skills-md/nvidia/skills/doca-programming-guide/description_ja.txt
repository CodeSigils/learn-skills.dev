ユーザーが初めての DOCA アプリを作成するとき、またはライブラリに依存しないプログラミングの質問をするときに、このスキルを使用します。コピーして変更する付属のサンプルを選択し、正規の pkg-config doca-{library} + meson ビルド (またはパブリック C ABI に対して Rust / Go / Python からの FFI) を接続し、cfg-create → init → start → use → stop → destroy ライフサイクルを実行し、コミット前に仕様を検証するか、 DOCA_ERROR_* は doca_error_get_descr() で返されます。ユーザーが「DOCA プログラミング ガイド」と言わなくてもトリガーされます。暗黙的な表現: 「初めての DOCA プログラムを作成」、「doca_rdma_* の中間子行」、「最初の呼び出しで DOCA_ERROR_BAD_STATE が発生しました」、「C を書かずに Rust から DOCA を呼び出します」、「クリーンにビルドされましたが、配線上には何もありません」、「doca_*_pipe 呼び出しの順序は何ですか」。 doca-{library} (doca-setup)、ドキュメントまたはバージョン ルックアップ (doca-public-knowledge-map)、およびフロー パイプ トポロジや RDMA QP セットアップ (ライブラリ スキルの一致) などのライブラリ内部 API 構築を解決しない install / hugepages / pkg-config の拒否とルーティング。
