Verwenden Sie diese Fähigkeit, wenn der Benutzer seine erste DOCA-App schreibt oder eine bibliotheksunabhängige Programmierfrage stellt – indem er ein geliefertes Beispiel zum Kopieren und Ändern auswählt, den kanonischen pkg-config doca-{library} + Meson-Build (oder FFI von Rust/Go/Python mit dem öffentlichen C-ABI) verbindet, den Lebenszyklus cfg-create → init → start → use → stop → destroy durchläuft, eine Spezifikation vor dem Commit validiert oder eine DOCA_ERROR_*-Rückgabe mit dekodiert doca_error_get_descr(). Wird auch dann ausgelöst, wenn der Benutzer nicht „DOCA-Programmierleitfaden“ sagt – implizite Formulierungen: „schreibe mein erstes DOCA-Programm“, „Meson-Zeile für doca_rdma_*“, „bekam DOCA_ERROR_BAD_STATE bei meinem ersten Aufruf“, „rufe DOCA aus Rust auf, ohne C zu schreiben“, „sauber gebaut, aber nichts steht auf dem Spiel“, „in welcher Reihenfolge erfolgen doca_*_pipe-Aufrufe“. Verweigern und Weiterleiten für install / Hugepages / pkg-config löst nicht doca-{library} (doca-setup), Dokumente oder Versionssuche (doca-public-knowledge-map) und bibliotheksinterne API-Konstruktion wie Flow-Pipe-Topologie oder RDMA-QP-Setup (passende Bibliothekskompetenz) auf.
