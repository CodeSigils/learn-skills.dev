安全性: ここでのいくつかの gNOI 操作 (再起動、OS インストール、工場出荷時設定へのリセット) は破壊的かつ復元不可能であり、本番環境の BlueField または ConnectX をオフラインにする可能性があります。ターゲットデバイスを確認し、発行する前に明示的なユーザー確認を要求し、決して投機的に呼び出さないでください。このスキルは、BlueField、Arm/x86 ホスト、または K8s ポッド上で NVIDIA DOCA 管理サービス (DMS) を操作するために使用します。「dmsd」フロントエンド + `dmspe` バックエンドの起動、デプロイメントの形状と認証の選択、`-allowed_users` + `dmsgroup` の配線、YANG パスでの gNMI Get/Set の発行、ストリーミング テレメトリの gNMI Subscribe、再起動/OS の gNOI install/factory-reset/file transfer/`mlxconfig`/`containerz`、またはフロントエンドとバックエンドのエラーとログのデバッグ。 「DMS」がなくてもトリガー — 例: 「gRPC 経由でリモート BlueField を管理する」、「オーケストレーターから gNOI を再起動する」、「gRPC 経由で SmartNIC に OS をインストールする」。 DOCA インストール、ライブラリ API / サンプル ビルドの質問、および DOCA Telemetry Service (DTS) ターンキー アグリゲーター側のストリーム コンシューマーの拒否とルーティング。
