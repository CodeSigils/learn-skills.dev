Verwenden Sie diese Fähigkeit, wenn der Benutzer eine praktische DOCA-Geräteemulation auf einer BlueField-DPU durchführt – indem er ein benutzerdefiniertes emuliertes PCIe-Gerät verfügbar macht, das der Host als echtes Peripheriegerät sieht, während DPU-seitiger Code das Backend ausführt, die Unterbibliothek auswählt (PCI Generic, virtio-net, virtio-fs), den Kernkontext pro Unterbibliothek plus Türklingel-/DMA-Primitive verkabelt und Abfragen durchführt `doca_devemu_*_cap_*` oder Debuggen von DOCA_ERROR_* über einen `doca_devemu_*`-Aufruf. Wird auch dann ausgelöst, wenn der Benutzer nicht „devemu“ sagt – typische implizite Formulierungen sind „ein benutzerdefiniertes PCIe-Gerät von BlueField dem Host zugänglich machen“, „Der Host sollte eine virtuelle Netzwerkkarte sehen, die durch meinen DPU-Code unterstützt wird“, „lspci zeigt mein emuliertes Gerät nicht an“, „Gerät wird aufgelistet, aber kein Treiber bindet“, „DPU sieht nichts, wenn der Host in die Warteschlange tritt“ oder „Aushandlung der Virtio-Funktion beim Binden fehlgeschlagen“. Die gebündelten DOCA SNAP-/Virtio-net-Dienste, hostseitige Virtio-Kernel-Treiber, das Backend-Body-Design oder das standardmäßige BlueField-NIC-Verhalten ablehnen und an einen anderen Ort weiterleiten – das gehört zu anderen Fähigkeiten.
