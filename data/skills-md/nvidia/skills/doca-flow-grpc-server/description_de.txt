PLAINTEXT-ONLY: Der ausgelieferte „doca_flow_grpc“-Server verwendet „grpc::InsecureServerCredentials()“ ohne TLS-/mTLS-/Token-Auth-Knopf in der Binärdatei – die Transportsicherheit muss von einer externen Infrastruktur (z. B. einem mTLS-Proxy/Sidecar) in einem vertrauenswürdigen Segment stammen. Verwenden Sie diese Fähigkeit, wenn Sie „doca_flow_grpc“ aufrufen, konfigurieren, härten oder debuggen – die von DOCA bereitgestellte gRPC-Fernsteuerungsoberfläche vor „doca-flow“, mit der Nicht-C++-Clients (Python, Go, Rust, Java) Flow-Pipes und -Einträge über RPC programmieren können, anstatt „libdoca_flow.so“ direkt zu verknüpfen. Wird auch dann ausgelöst, wenn der Benutzer nicht „doca-flow-grpc-server“ oder „gRPC“ sagt – z. B. „Flow-Regeln von Python auf einem anderen Host programmieren“, „Pipes auf dem BlueField remote konfigurieren“, „Client-Zeitüberschreitung beim Herstellen einer Verbindung zum Flow-Server“, „Wo ist die .proto-Datei für Flow“, „UNAUTHENTICATED / FAILED_PRECONDITION auf einem Flow-RPC“. Leiten Sie die zugrunde liegende Doca-Flow-API, generische gRPC-Tools (Protokoll, Sprachbindungen) oder die DOCA-Installation/BFB-Einführung an einen anderen Ort weiter.
