PLAINTEXT-ONLY: 出荷された `doca_flow_grpc` サーバーは、バイナリ上で TLS / mTLS / token-auth ノブを持たない `grpc::InsecureServerCredentials()` を使用します。トランスポート セキュリティは、信頼できるセグメント上の外部インフラストラクチャ (mTLS プロキシ / サイドカーなど) から取得する必要があります。このスキルは、`doca_flow_grpc` を起動、構成、強化、またはデバッグするときに使用します。これは、`doca-flow` の前にある DOCA が提供する gRPC リモート コントロール サーフェスであり、非 C++ クライアント (Python、Go、Rust、Java) が、`libdoca_flow.so` を直接リンクする代わりに RPC 経由でフロー パイプとエントリをプログラムできるようにします。ユーザーが「doca-flow-grpc-server」または「gRPC」と言わなくてもトリガーされます。 「別のホスト上の Python からフロー ルールをプログラムする」、「BlueField でパイプをリモート構成する」、「クライアントがフロー サーバーへの接続をタイムアウトする」、「フローの .proto はどこにありますか」、「フロー RPC での UNAUTHENTICATED / FAILED_PRECONDITION」。基盤となる doca-flow API、汎用 gRPC ツール (プロトコル、言語バインディング)、または DOCA インストール/BFB 起動については、別の場所にルーティングします。
