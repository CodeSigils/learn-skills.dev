Verwenden Sie diese Fähigkeit, wenn der Benutzer praktische DOCA-RDMA-Programmierung auf einer BlueField-DPU, einer ConnectX-NIC oder einem DOCA-Host durchführt – indem er einen RDMA-Kontext auf einem doca_dev aufruft, eine Verbindungsmethode auswählt (RDMA CM, Bridge/OOB oder gRPC-Austausch von doca_rdma_export()) und einen der elf Aufgabentypen aktiviert (Senden/Empfangen/Senden-Imm, Lesen/Schreiben/Schreiben-Imm, Atomic). CmpSwap/FetchAdd, Get/Set/Add Remote Sync Event), Festlegen passender mmap + RDMA-Berechtigungen, Dimensionieren von Warteschlangen und Verbindungen, Abfragen von doca_rdma_cap_* oder Debuggen von DOCA_ERROR_* aus einem RDMA-Aufruf. Wird auch dann ausgelöst, wenn der Benutzer „DOCA RDMA“ nicht erwähnt. Zu den typischen impliziten Formulierungen gehören „einseitige Leserückgabeberechtigung verweigert“, „Abschlüsse kommen nach der Übermittlung nie an“, „Verbindungsrückruf wird nie ausgelöst“, „Wie führe ich atomaren Vergleich und Austausch über RoCE durch“ oder „Warteschlangentreffer DOCA_ERROR_FULL unter Burst senden“. Verweigern Sie die allgemeine RDMA-/Ibverbs-Theorie (Warteschlangenpaare, MRs, RoCE vs. IB), die Installation von DOCA selbst oder Nicht-RDMA-DOCA-Bibliotheken und leiten Sie sie woanders hin.
