Verwenden Sie diese Fähigkeit, wenn der Benutzer den von DOCA gelieferten Referenzalgorithmus Zero-Touch RoCE RTT-based Congestion Control (ZTR RTTCC) auf einem BlueField-3-DPA praktisch bereitstellt, optimiert oder evaluiert – indem er „doca_pcc_dev_ztr_rttcc_algo“ in das mitgelieferte DOCA-PCC-Beispiel einbindet und beim DPACC-Build eine Variante (Vanilla / PM / RX-Rate / Multipath / Window-Probeless) auswählt Zeit, Optimierung von Host-Set-Parametern oder Diagnose von „DOCA_PCC_DEV_STATUS_FAIL“ anhand des Algorithmus. Wird auch dann ausgelöst, wenn der Benutzer nicht „DOCA PCC“ oder „ZTR RTTCC“ sagt – typische implizite Formulierungen: „Meine RoCE-v2-Flows werden nicht gedrosselt“, „PCC-Probe wird nicht an meinen Algo gesendet“, „Wie wähle ich die Multipath-PCC-Variante aus“, „Set-Params-Rückgaben schlagen fehl“, „Algorithmus geladen, aber Zähler sind leer“ oder „Benötige ich einen benutzerdefinierten CC-Algorithmus auf BF3?“ Weigern Sie sich, einen benutzerdefinierten PCC-Algorithmus von Grund auf neu zu schreiben, eine schreibgeschützte PCC-Zählerinspektion, den hostseitigen „doca-pcc“-Lebenszyklus oder einen vorprogrammierbaren PCC, der nur auf die Firmware beschränkt ist, abzulehnen und anderswo weiterzuleiten – das gehört zu anderen Fähigkeiten.
