Verwenden Sie diese Option, wenn Sie einen einzelnen großen Commit im aktuellen Zweig durch eine Folge kleiner Commits in Review-Größe ersetzen möchten, von denen jeder CI für sich weitergibt. Jeder Commit ist zu 100 % rein in seinem herkömmlichen Commits-Typ (Refactor bedeutet keine Verhaltensänderung). Erstellt vor dem Neuschreiben automatisch einen mit Zeitstempel versehenen Sicherungszweig und behält den Autor, die Daten und den Baum des ursprünglichen Commits vollständig bei. Nachkommende Commits werden automatisch neu gestapelt. Auslöser: „Dieses Commit aufteilen“, „Dieses Commit in überprüfbare Teile aufteilen“, „Dieses Commit in semantische Einheiten aufteilen“, „Dieses Commit in sinnvolle Einheiten aufteilen“, „zerteilen“. Nicht verwenden für: Neuanordnen/Zusammendrücken mehrerer bestehender Commits → git rebase / Aufteilen nicht festgeschriebener Änderungen → git add -p / Verwalten gestapelter PRs → gh-stack.
