Da utilizzare quando si desidera sostituire un singolo commit di grandi dimensioni sul ramo corrente, sul posto, con una sequenza di commit di piccole dimensioni, ognuno dei quali passa CI per conto proprio. Ogni commit è puro al 100% nel suo tipo Commit convenzionali (refactoring significa zero modifiche al comportamento). Crea automaticamente un ramo di backup con timestamp prima della riscrittura e preserva completamente l'autore, le date e l'albero del commit originale. I commit discendenti vengono riorganizzati automaticamente. Trigger: "dividi questo commit", "dividi questo commit in parti rivedibili", "dividi questo commit in unità semantiche", "dividi questo commit in unità significative", "scolpisci". Non utilizzare per: riordinare/schiacciare più commit esistenti → git rebase / suddividere le modifiche non confermate → git add -p / gestire PR in pila → gh-stack.
