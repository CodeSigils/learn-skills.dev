Cree problemas de GitHub listos para agentes a partir de especificaciones, documentos de características, conversaciones o hallazgos ad hoc. Maneja tanto la descomposición de especificaciones (subproblemas épicos + en capas) como problemas independientes (error único, refactorización, característica). Úselo cuando el usuario invoque /to-issues o /to-issue, diga "dividir esto en problemas", "crear problemas a partir de esta especificación", "archivar un problema para esto", "convertir a trabajo pendiente" o cuando la conversación surja un error, una brecha de diseño o un trabajo diferido que valga la pena capturar. Esta es la contraparte de /clear-issues: produce el trabajo pendiente que /clear-issues consume.
