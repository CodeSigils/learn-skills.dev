Esegue il QA dell'intero progetto come un utente reale rilevando la verifica del repository e i contratti E2E, eseguendo comandi di build, lint, test e avvio, esercitando i flussi di lavoro principali end-to-end tramite CLI, HTTP e interfacce browser, richiedendo una copertura di regressione automatizzata per i flussi critici supportati, correggendo le regressioni della causa principale ed eseguendo nuovamente il gate completo. Utilizza la capacità complementare agente-browser per la convalida dell'interfaccia utente Web quando esiste una superficie Web. Da utilizzare durante la convalida di un ramo, di una release candidate, di una migrazione, di un refactoring o di un commit rischioso. Non utilizzare solo per la revisione del codice statico, modifiche una tantum di unit test, casi di test di pianificazione o brainstorming sull'architettura senza esecuzione: utilizzare qa-report per la pianificazione e la documentazione.
