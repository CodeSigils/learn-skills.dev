Steuern Sie die better-update-CLI (@better-update/cli, der „better-update“-Befehl), um OTA-JS/Asset-Updates zu versenden, lokale native iOS/Android-Builds auszuführen, einen Ende-zu-Ende-verschlüsselten Signing-Credential-Tresor zu verwalten, serverseitige Umgebungsvariablen festzulegen und Releases über Kanäle/Zweige mit gestaffelten Rollouts und sofortigem Rollback weiterzuleiten – für Expo, React Native, Kotlin Multiplatform und native Apps (jeder Projekttyp über benutzerdefinierte Build-Befehle). Verwenden Sie dies immer dann, wenn Sie an einem Projekt arbeiten, das better-update verwendet (eine „@better-update/cli“-Abhängigkeit, einen „better-update …“-Befehl, „expo.extra.betterUpdate.projectId“ in app.json oder eine „updates.jmango360.dev“-Manifest-URL), ODER wenn der Benutzer darum bittet, ein OTA-Update zu veröffentlichen/zu versenden, einen Rollout oder ein Rollback einer Veröffentlichung durchzuführen, einen Veröffentlichungskandidaten auszuschneiden, Fördern Sie ein Update zwischen Kanälen, erstellen Sie lokal ein IPA/APK/AAB, verwalten Sie Keystores/Verteilungszertifikate/Bereitstellungsprofile/APNs-Push-Keys oder konfigurieren Sie Geheimnisse pro Umgebung – auch wenn sie nie die Worte „Better-Update“ sagen. Deckt jeden Befehl, jedes Flag und das Routing-Modell „Publish → Branch → Channel → Device“ ab.
