Pilotez la CLI better-update (@better-update/cli, la commande `better-update`) pour expédier les mises à jour OTA JS/asset, exécuter des versions iOS/Android natives locales, gérer un coffre-fort d'informations d'identification de signature crypté de bout en bout, définir des variables d'environnement côté serveur et acheminer les versions via des canaux/branches avec des déploiements par étapes et une restauration instantanée - pour Expo, React Native, Kotlin Multiplatform et les applications natives (tout type de projet via des commandes de construction personnalisées). Utilisez-le chaque fois que vous travaillez dans un projet qui utilise better-update (une dépendance `@better-update/cli`, une commande `better-update…`, `expo.extra.betterUpdate.projectId` dans app.json ou une URL manifeste `updates.jmango360.dev`), OU lorsque l'utilisateur demande de publier/expédier une mise à jour OTA, d'organiser un déploiement ou d'annuler une version, de supprimer une version candidate, de promouvoir une mise à jour entre les canaux, créez un IPA/APK/AAB localement, gérez les magasins de clés/certificats de distribution/profils d'approvisionnement/clés push APN, ou configurez des secrets par environnement — même s'ils ne prononcent jamais les mots « meilleure mise à jour ». Couvre chaque commande, chaque indicateur et le modèle de routage publication → branche → canal → périphérique.
