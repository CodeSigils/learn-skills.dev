قم بتحليل المنتج والمتطلبات الفنية لمشروع PigeonPod بدقة هندسة البرمجيات. يُستخدم عندما يطلب المستخدمون تقييم ميزة أو تحسين أو متطلبات غير وظيفية أو تكامل أو ترحيل للقيمة أو الجدوى أو ملاءمة البنية أو تأثير التنفيذ أو المخاطر أو نطاق التسليم أو المفاضلات. لا تستخدم لفرز الأخطاء أو تحليل السبب الجذري؛ استخدم "تحليل الأخطاء" للعمل الموجه نحو إصلاح الأخطاء. قم دائمًا بفحص مستندات المستودع الحالي والتعليمات البرمجية أولاً، ثم استخدم أدوات MCP بما في ذلك context7 للتحقق من قيود المكتبة الخارجية أو إطار العمل أو واجهة برمجة التطبيقات (API) قبل الختام.
