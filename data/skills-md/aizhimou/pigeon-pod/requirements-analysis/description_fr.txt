Analysez les exigences produit et techniques du projet PigeonPod avec rigueur d’ingénierie logicielle. Utilisez‑le lorsque les utilisateurs demandent d’évaluer une fonctionnalité, une amélioration, une exigence non fonctionnelle, une intégration ou une migration en termes de valeur, de faisabilité, d’adéquation architecturale, d’impact de mise en œuvre, de risque, de périmètre de livraison ou de compromis. Ne l’utilisez pas pour le triage de bugs ou l’analyse des causes profondes ; utilisez `bug-analysis` pour les travaux axés sur la correction de bugs. Inspectez toujours d’abord la documentation et le code du dépôt actuel, puis utilisez les outils MCP, y compris Context7, pour vérifier les contraintes des bibliothèques externes, des frameworks ou des API avant de conclure.

Veuillez toujours répondre dans la langue de l’utilisateur.
