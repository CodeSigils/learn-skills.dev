Lorsqu'un utilisateur signale un comportement anormal, il doit être activé : erreurs, plantages, échecs de fonctionnalités, anomalies d'affichage, problèmes de style, changements de mise en page, problèmes de réponse, clics qui ne répondent pas, données incorrectes, comportement qui ne correspond pas aux attentes, etc. Même si l'utilisateur ne mentionne pas « débogage » ou « bug », tant qu'il décrit « quelque chose ne fonctionne pas / ne fonctionne pas / est cassé / l'affichage a des problèmes », cela se déclenche. Processus : tracer la chaîne d'appels pour réduire la portée → validation croisée avec une porte pour éviter les suppositions aveugles (ne pas agir sans preuves bidimensionnelles suffisantes) → instrumentation binaire pour identifier la source → corriger la cause profonde sans simplement modifier le symptôme. Lorsque vous vous trouvez dans une impasse, initiez-vous à une remise en question de la direction à prendre.
