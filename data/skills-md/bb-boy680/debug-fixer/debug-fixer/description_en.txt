When a user reports any abnormal behavior, it must be activated—errors, crashes, feature failures, display anomalies, style glitches, layout shifts, responsive issues, unresponsive clicks, incorrect data, behavior that does not match expectations, etc. Even if the user does not mention “debug” or “bug,” as long as they describe “something is off / not working / broken / display has problems,” it triggers. Process: trace the call chain to narrow the scope → cross‑validate with a gate to prevent blind guessing (do not act without sufficient two‑dimensional evidence) → binary instrumentation to pinpoint the source → fix the root cause without merely changing the symptom. When hitting a dead end, initiate self‑questioning of direction.
