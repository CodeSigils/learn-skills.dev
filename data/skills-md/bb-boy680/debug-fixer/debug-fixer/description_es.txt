Cuando un usuario informa cualquier comportamiento anormal, se debe activar: errores, fallas, fallas en funciones, anomalías en la visualización, fallas de estilo, cambios de diseño, problemas de respuesta, clics que no responden, datos incorrectos, comportamiento que no coincide con las expectativas, etc. Incluso si el usuario no menciona "depurar" o "error", siempre y cuando describa algo como "algo está apagado/no funciona/roto/la pantalla tiene un problema", debería activarse. Proceso: rastrear la cadena de llamadas para limitar el alcance → validar cruzadamente el control de acceso para evitar conjeturas ciegas (si la evidencia es insuficiente en dos dimensiones, no actúe) → instrumentación binaria para identificar la fuente → corregir la fuente sin simplemente enmascarar el síntoma. Cuando te topes con una pared, empieza a cuestionarte la dirección.
