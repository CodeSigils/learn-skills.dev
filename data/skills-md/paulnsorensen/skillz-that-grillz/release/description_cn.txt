GitHub 存储库的端到端版本切割：从最后一个标签以来的常规提交决定下一个语义版本，起草适当的发行说明（GitHub 通过“.github/release.yml”自动生成，或按更改类型手动分组，并突出显示和升级说明以进行重大更改），创建并推送带注释的标签，发布 GitHub 版本，并可选择更新“CHANGELOG.md”。当用户说“剪切版本”、“标记版本”、“发布版本”、“发布 vX.Y.Z”、“升级版本”、“这应该是什么版本”、“编写发行说明”、“起草变更日志”或调用 /release 时使用。与 /gh-bootstrap （它构建一次 `.github/release.yml` + 发布工作流程管道）和 /gh （原始的每命令 `gh release` 操作）不同：此技能运行实际的发布仪式 - 版本决定、注释、标签、发布。将工作合并到默认分支后运行。
