End-to-End-Release-Cutting für ein GitHub-Repo: Entscheiden Sie sich für die nächste semantische Version aus den konventionellen Commits seit dem letzten Tag, entwerfen Sie die richtigen Versionshinweise (GitHub wird automatisch über „.github/release.yml“ generiert oder von Hand kuratiert, gruppiert nach Änderungstyp mit Hervorhebungen und Upgrade-Hinweisen für wichtige Änderungen), erstellen und pushen Sie ein kommentiertes Tag, veröffentlichen Sie das GitHub-Release und aktualisieren Sie optional „CHANGELOG.md“. Wird verwendet, wenn der Benutzer „ein Release ausschneiden“, „ein Release markieren“, „ein Release veröffentlichen“, „vX.Y.Z versenden“, „die Version aktualisieren“, „welche Version soll das sein“, „die Versionshinweise schreiben“, „das Änderungsprotokoll erstellen“ sagt oder /release aufruft. Im Gegensatz zu /gh-bootstrap (das das Gerüst für die „.github/release.yml“ + Release-Workflow-Installation bildet) und /gh (rohe „gh release“-Operationen pro Befehl): Dieser Skill führt die eigentliche Release-Zeremonie durch – Versionsentscheidung, Notizen, Tag, Veröffentlichung. Wird ausgeführt, nachdem die Arbeit mit dem Standardzweig zusammengeführt wurde.
