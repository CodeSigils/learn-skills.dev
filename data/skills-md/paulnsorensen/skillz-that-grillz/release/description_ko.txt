GitHub 저장소에 대한 엔드 투 엔드 릴리스 절단: 마지막 태그 이후 기존 커밋에서 다음 시맨틱 버전을 결정하고, 적절한 릴리스 노트 초안을 작성합니다(GitHub는 `.github/release.yml`을 통해 자동 생성되거나 주요 변경 사항에 대한 하이라이트 및 업그레이드 노트가 포함된 변경 유형별로 직접 선별됨), 주석이 달린 태그를 생성 및 푸시하고, GitHub 릴리스를 게시하고, 선택적으로 `CHANGELOG.md`를 업데이트합니다. 사용자가 "릴리스 잘라내기", "릴리스 태그 지정", "릴리스 게시", "vX.Y.Z 제공", "버전 범프", "이 버전은 무엇이어야 하는지", "릴리스 노트 작성", "변경 로그 초안 작성"이라고 말하거나 /release를 호출할 때 사용하세요. /gh-bootstrap(`.github/release.yml`을 스캐폴드하고 워크플로 배관을 한 번 릴리스함) 및 /gh(명령별 원시 `gh release` 작업)와 구별됩니다. 이 기술은 버전 결정, 메모, 태그, 게시와 같은 실제 릴리스 행사를 실행합니다. 작업이 기본 브랜치에 병합된 후 실행됩니다.
