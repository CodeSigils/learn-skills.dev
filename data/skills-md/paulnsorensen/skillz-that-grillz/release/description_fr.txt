Découpe de version de bout en bout pour un dépôt GitHub : décidez de la prochaine version sémantique à partir des validations conventionnelles depuis la dernière balise, rédigez des notes de version appropriées (GitHub générées automatiquement via `.github/release.yml`, ou organisées à la main, regroupées par type de modification avec des faits saillants et des notes de mise à niveau pour les modifications avec rupture), créez et poussez une balise annotée, publiez la version GitHub et éventuellement mettez à jour `CHANGELOG.md`. À utiliser lorsque l'utilisateur dit « couper une version », « marquer une version », « publier une version », « expédier vX.Y.Z », « modifier la version », « quelle version devrait-elle être », « écrire les notes de version », « rédiger le journal des modifications » ou invoque /release. Distinct de /gh-bootstrap (qui échafaude la plomberie du flux de travail de publication `.github/release.yml` + une fois) et /gh (opérations brutes par commande `gh release`) : cette compétence exécute la cérémonie de publication proprement dite - décision de version, notes, balise, publication. Exécuté une fois le travail fusionné dans la branche par défaut.
