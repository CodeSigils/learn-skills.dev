Taglio del rilascio end-to-end per un repository GitHub: decidi la prossima versione semantica dai Commit convenzionali dall'ultimo tag, redige le note di rilascio corrette (GitHub generate automaticamente tramite `.github/release.yml` o raggruppate manualmente per tipo di modifica con evidenziazioni e note di aggiornamento per modifiche importanti), crea e invia un tag annotato, pubblica la versione GitHub e, facoltativamente, aggiorna `CHANGELOG.md`. Da utilizzare quando l'utente dice "taglia una versione", "tagga una versione", "pubblica una versione", "spedisci vX.Y.Z", "aumenta la versione", "quale versione dovrebbe essere", "scrivi le note di rilascio", "bozza il registro delle modifiche" o invoca /release. Distinto da /gh-bootstrap (che supporta il flusso di lavoro `.github/release.yml` + rilascio una volta) e /gh (operazioni `gh release` grezze per comando): questa abilità gestisce l'effettiva cerimonia di rilascio: decisione sulla versione, note, tag, pubblicazione. Esegui dopo che il lavoro è stato unito al ramo predefinito.
