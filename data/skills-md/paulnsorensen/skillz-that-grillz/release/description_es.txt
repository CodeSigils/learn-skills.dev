Corte de lanzamiento de extremo a extremo para un repositorio de GitHub: decida la siguiente versión semántica de las confirmaciones convencionales desde la última etiqueta, redacte las notas de lanzamiento adecuadas (GitHub generadas automáticamente a través de `.github/release.yml`, o seleccionadas manualmente y agrupadas por tipo de cambio con aspectos destacados y notas de actualización para cambios importantes), cree y publique una etiqueta anotada, publique el lanzamiento de GitHub y, opcionalmente, actualice `CHANGELOG.md`. Úselo cuando el usuario dice "cortar una versión", "etiquetar una versión", "publicar una versión", "enviar vX.Y.Z", "cambiar la versión", "qué versión debería ser", "escribir las notas de la versión", "redactar el registro de cambios" o invoca /liberación. A diferencia de /gh-bootstrap (que estructura el flujo de trabajo de lanzamiento `.github/release.yml` + una vez) y /gh (operaciones crudas por comando `gh release`): esta habilidad ejecuta la ceremonia de lanzamiento real: decisión de versión, notas, etiqueta, publicación. Ejecutar después de que el trabajo se fusione con la rama predeterminada.
