Implemente una especificación aprobada o una tarea enfocada e inequívoca con un contrato disciplinado por TDD → ​​cortar → implementar → probar → bucle de transferencia, editando mediante cheez-write. Úselo cuando el usuario quiera escribir código: frases como "implementar esto", "crear esta característica", "escribir el código", "cocinar esta especificación", "hacer que funcione", "/cook .cheese/specs/<slug>.md", "corregir este error" (cuando el error tiene una solución clara). Admite `--auto` para la cadena autónoma a través de `/press → /age → /cure` (consulte `## Modo automático`). Úselo incluso cuando el usuario simplemente diga "ir" o "enviarlo" si el alcance incluye una especificación o un criterio de aceptación claro. `/cook` se ejecuta de forma independiente cuando la tarea no es ambigua (entradas claras, salidas esperadas, resultados verificables); una especificación es útil pero no es necesaria. Si la solicitud es realmente confusa, diríjala primero a `/mold`; si no necesita escrituras, diríjase a `/culture`. Después de `/mold` (opcional); antes de `/press` → `/age` → `/cure`.
