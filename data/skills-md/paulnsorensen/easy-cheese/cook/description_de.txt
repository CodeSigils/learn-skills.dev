Implementieren Sie eine genehmigte Spezifikation oder eine fokussierte, eindeutige Aufgabe mit einem TDD-disziplinierten Vertrag → Schnitt → Implementierung → Geschmackstest → Übergabeschleife, Bearbeitung durch Cheez-Write. Verwenden Sie diese Option, wenn der Benutzer möchte, dass Code geschrieben wird – Ausdrücke wie „implementieren Sie dies“, „bauen Sie diese Funktion“, „schreiben Sie den Code“, „kochen Sie diese Spezifikation“, „machen Sie es zum Laufen“, „/cook .cheese/specs/<slug>.md“, „beheben Sie diesen Fehler“ (wenn es für den Fehler eine eindeutige Lösung gibt). Unterstützt „--auto“ für die autonome Kette durch „/press → /age → /cure“ (siehe „## Auto-Modus“). Verwenden Sie diese Option auch dann, wenn der Benutzer nur „Los“ oder „Versenden“ sagt, wenn eine Spezifikation oder klare Akzeptanzkriterien im Geltungsbereich liegen. „/cook“ läuft eigenständig, wenn die Aufgabe eindeutig ist (klare Eingaben, erwartete Ausgaben, überprüfbares Ergebnis) – eine Spezifikation ist hilfreich, aber nicht erforderlich. Wenn die Anfrage wirklich unscharf ist, leiten Sie sie zuerst an „/mold“ weiter; Wenn keine Schreibvorgänge erforderlich sind, Weiterleitung an „/culture“. Nach „/mold“ (optional); vor „/press“ → „/age“ → „/cure“.
