Implémentez une spécification approuvée ou une tâche ciblée et sans ambiguïté avec un contrat discipliné par TDD → ​​couper → implémenter → test de goût → boucle de transfert, édition via cheez-write. À utiliser lorsque l'utilisateur souhaite écrire du code – des expressions telles que « implémenter ceci », « créer cette fonctionnalité », « écrire le code », « cuisiner cette spécification », « le faire fonctionner », « /cook .cheese/specs/<slug>.md », « corriger ce bug » (lorsque le bug a une solution claire). Prend en charge `--auto` pour la chaîne autonome via `/press → /age → /cure` (voir `## Auto mode`). À utiliser même lorsque l'utilisateur dit simplement « allez-y » ou « expédiez-le » si une spécification ou des critères d'acceptation clairs sont concernés. `/cook` s'exécute de manière autonome lorsque la tâche est sans ambiguïté (entrées claires, sorties attendues, résultat vérifiable) — une spécification est utile mais pas obligatoire. Si la demande est véritablement floue, dirigez-vous d'abord vers `/mold` ; s'il ne nécessite aucune écriture, dirigez-vous vers `/culture`. Après `/mold` (facultatif) ; avant `/press` → `/age` → `/cure`.
