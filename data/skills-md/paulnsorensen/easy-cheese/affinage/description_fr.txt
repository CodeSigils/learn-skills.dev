Triez les commentaires d'examen d'un PR et les CI défaillants (ainsi que les conflits de fusion) à travers l'optique /age, en décidant quelles réclamations valent la peine d'agir. À utiliser lorsque l'utilisateur dit « répondre aux commentaires du PR », « gérer les commentaires de révision », « affiner le PR », « /affinage <pr> », « répondre aux commentaires du réviseur », « corriger la version défaillante », « résoudre les conflits et répondre ». Récupère les commentaires en ligne + du corps de révision via `gh` et les échecs CI via `affinage.pyz pr-status`, note chacun à travers les dix dimensions d'âge et rédige un rapport dans `.cheese/affinage/pr-<n>.md`. Résout les conflits de fusion via `/melt` et achemine les échecs de build/CI vers les correctifs via `/cure`. Lorsqu'il est invoqué de manière autonome (pas de `handoff_context` en amont depuis `/cook` ou `/cure`), il exécute également `/age` sur le diff PR et intègre les nouveaux résultats dans le rapport ; une fois enchaîné, il ignore cette étape et affine uniquement les revendications existantes. Passez à « /cure », puis publiez des réponses GitHub en fonction de la recherche via « agent au nom de ; ». Prend en charge `--auto --stake <floor>`. Avant `/cure` ; parallèle à `/age`.
