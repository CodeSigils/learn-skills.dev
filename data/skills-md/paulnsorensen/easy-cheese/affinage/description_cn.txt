通过 /age 镜头对 PR 的审查意见和失败的 CI（加上合并冲突）进行分类，决定哪些声明值得采取行动。当用户说“回复 PR 评论”、“处理审阅反馈”、“affinage the PR”、“/affinage <pr>”、“解决审阅者评论”、“修复失败的构建”、“解决冲突并响应”时使用。通过“gh”获取内联+评论正文评论，并通过“affinage.pyz pr-status”获取 CI 失败，通过十个年龄维度对每个维度进行评分，并在“.cheese/affinage/pr-<n>.md”中写入报告。通过“/melt”解决合并冲突，并通过“/cure”将构建/CI 故障路由到修复。当独立调用时（没有来自“/cook”或“/cure”的上游“handoff_context”），它还会在 PR diff 上运行“/age”并将新发现折叠到报告中；当链接时，它会跳过该过程并仅细化现有声明。移交给“/cure”，然后通过“代理代表;”发布每个发现的 GitHub 回复。支持 `--auto --stake <楼层>`。在`/cure`之前；与“/age”平行。
