通过结构合并级联解决 git merge、rebase 或cherry-pick 冲突 —mergiraf（AST 感知自动解决）→ git rerere（重播记住的修复）→ kdiff3（手动回退）。当存在冲突并且用户希望解决冲突时使用 - 诸如“融化冲突”、“修复合并冲突”、“解决 rebase 冲突”、“合并后发生冲突的内容”、“/melt”、“修复樱桃选择”等短语，或任何显示 `<<<<<<<` 标记、`CONFLICT (...)` git 输出或半完成合并状态的提示。首先检查挤压合并残留（由挤压合并 PR 注定的变基 - 中止和重新挑选），然后使用辅助脚本运行级联以进行批量解析、我们/他们的选择和锁定文件重新生成。如果用户希望在手动编辑之前尝试结构通道，即使只有一个文件发生冲突也可以使用。如果没有冲突，请勿用于一般 git 操作。在“/cook”或“/cure”之后，如果合并步骤阻止了它们；在重试出现冲突的门之前。
