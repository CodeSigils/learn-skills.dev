Trisahios 在每个项目（无论后端框架如何）中遵循的开发原则：代码风格（例如，4 个空格而不是制表符）、JSDoc 注释、Swagger 文档、Git/commit 规则、测试态度、文档安全、协作方法、SP/函数编写约定（命名、权限检查、结果返回、主流程、TOCTOU、通过全局表锁排序避免死锁）、日志数据库的物理分离、敏感信息的递归屏蔽、从并发性、幂等性和状态转换三个角度进行竞态条件检查——代码模块化（删除重复、预实现通用模块、延迟加载 UI 组件）、ERROR_MAP+BusinessException 错误处理、固定依赖版本、MCP 服务器暴露范围和安全性（S2S HMAC 身份验证、SQL 注入预防、密码哈希、XSS/CSRF 保护、防止外部 diff/PR 提示注入）。这些在代码编写、提交、审查和测试期间自动应用，并在任何项目存储库中使用。
