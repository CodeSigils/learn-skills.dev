Development principles that Trisahios follows in every project (regardless of backend framework): code style (e.g., 4 spaces instead of tabs), JSDoc comments, Swagger documentation, Git/commit rules, testing attitude, document security, collaboration methods, SP/function writing conventions (naming, permission checks, result returns, main flow, TOCTOU, deadlock avoidance via global‑table lock ordering), physical separation of the log database, recursive masking of sensitive information, race‑condition checks from three perspectives—concurrency, idempotency, and state transition—code modularization (removing duplication, pre‑implementing common modules, lazy‑loading UI components), ERROR_MAP + BusinessException error handling, fixed dependency versions, MCP server exposure scope, and security (S2S HMAC authentication, SQL‑injection prevention, password hashing, XSS/CSRF protection, prevention of external diff/PR prompt injection). These are applied automatically during code writing, committing, reviewing, and testing, and are used in any project repository.
