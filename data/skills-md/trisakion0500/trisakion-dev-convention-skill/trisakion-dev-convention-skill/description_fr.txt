Les principes de développement de TrisHagiOS qui sont suivis dans tous les projets (quel que soit le framework backend). Style de code (par exemple, 4 espaces au lieu de tabulations), commentaires JSDoc, documentation Swagger, règles Git/commit, approche de test, sécurité de la documentation, méthodes de collaboration, conventions d'écriture SP/fonction (dénomination, contrôles d'autorisation, retours de résultats, flux principal, TOCTOU, prévention des blocages via l'ordre global des verrouillages de table), séparation physique de la base de données de journaux, masquage récursif des informations sensibles, vérifications des conditions de concurrence sous trois points de vue (concurrence, idempotence, transition d'état), la modularisation du code (suppression des doublons, pré-implémentation de modules communs, chargement paresseux des composants de l'interface utilisateur), la gestion des erreurs ERROR_MAP+BusinessException, les versions de dépendances fixes, la portée d'exposition du serveur MCP, la sécurité (authentification S2S HMAC, prévention de l'injection SQL, hachage de mot de passe, XSS/CSRF, prévention de l'injection d'invites de diff/PR externes) sont automatiquement appliquées pendant le codage, la validation, la révision et les tests. Il est utilisé dans n'importe quel référentiel de projet.
