Refactorice el código en una estructura de características que priorice la composición o cree una nueva característica infiriendo convenciones de repositorio, seleccionando una topología coincidente y aplicando límites entre los módulos de acceso a datos, características, interfaz de usuario y utilidades. Úselo cuando Codex necesite mover código a carpetas de funciones o paquetes de funciones, dividir enlaces de estado monolíticos en pequeñas consultas y mutaciones, dividir componentes de pantalla grande en hojas de interfaz de usuario granulares, hacer que las funciones principales controlen funciones secundarias de requisitos previos o conectar archivos de ruta delgados y exportaciones alrededor de un diseño basado en funciones en bases de código frontend, backend o monorepo mientras se espera la confirmación antes de las ediciones.
