Gérer Sumsub `clientWebhooks` (abonnements aux événements pour candidatReviewed / candidatPending / kytTxn / etc.) — lit via `/resources/api/clientWebhooks`, écrit via `/resources/api/agent/clientWebhooks`. **Sandbox uniquement** — les webhooks de production doivent être créés par un humain directement dans le tableau de bord Sumsub. DÉCLENCHEMENT lorsque l'utilisateur demande de "lister/récupérer/afficher les webhooks", "créer/ajouter/enregistrer un webhook", "mettre à jour/modifier/changer une cible de webhook/une liste d'événements/un secret/un algorithme de signature", ou "désactiver/réactiver un webhook" contre son locataire sandbox. SKIP pour la configuration du webhook de production (renvoyez l'utilisateur au tableau de bord), pour les surfaces de webhook non liées (Stripe / videoIdent / Fireblocks / NFC / chemins de réception spécifiques au partenaire sous `/resources/webhooks/...`), pour tester la livraison unique (utilisez directement le point de terminaison `inspectionCallbacks/testWebhook`) et pour le routage des webhook uniquement KYT (qui est géré dans la section KYT du tableau de bord Sumsub). L'API publique n'expose pas les statistiques de suppression ou de livraison par webhook - pour celles-ci, renvoyez l'utilisateur à l'interface utilisateur du tableau de bord Sumsub.
