Комплексный рецепт интеграции правила Sumsub Travel Rule — решение, какой из трех потоков обмена применяется, идентификация VASP-контрагента, отправка перевода, чтение статуса обмена, завершение или отмена его, ответ на запросы, которые отправляют вам другие VASP, обработка пути к нехостовому кошельку, когда VASP не присвоен, и поиск существующих транзакций (дедупликация перед обменами после расчетов). ТРИГГЕР, когда пользователь запрашивает «интегрировать / добавить / внедрить Travel Rule», «отправить данные Travel Rule с выводом средств», «собрать данные Travel Rule для уже поступившего депозита», «отвечать / ответить на входящие запросы Travel Rule», спрашивает, почему их обмены находятся в состоянии «onHold» или «завершено» и никогда не достигают «завершения», почему контрагенты никогда не отвечают, как протестировать Travel Rule в песочнице, о «проверке нехостингового/автономного/некастодиального кошелька», «доказать, что пользователь владеет кошельком», «тест Сатоши», что происходит на `counterpartyVaspNotFound` или `applicantKytTxnAwaitingUser`, или «найти/поиск транзакций», «проверить, существует ли уже транзакция для этого хеша». SKIP для создания самой полезной нагрузки транзакции (используйте sumsub-create-transaction), для написания правил оценки, которые действуют в зависимости от результата (используйте sumsub-create-kyt-rules), для массовой регистрации адресов кошельков (используйте sumsub-manage-wallet-address-book), а также для работы KYC/AML, не связанной с переводами между VASP.
