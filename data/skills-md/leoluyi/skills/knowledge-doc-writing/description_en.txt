Organize the results of self‑studying or researching a technical topic into a knowledge document that contains four clearly separated Diátaxis sections—tutorial (getting started), how‑to (accomplishing a task step by step), reference (lookup of parameters and structures), and explanation (what/why discussion and trade‑off decisions). Use the two questions of the compass to route each piece of material to the appropriate section; only write material that can be substantiated. When the material cannot be supported (e.g., the topic has been researched but not implemented, often lacking tutorial/how‑to), explicitly list it as a gap. Do not fabricate or produce empty shells (mainly Traditional Chinese, keeping technical terms in English).

Trigger: The user wants to digest conversation logs, official documents or raw data, or a topic researched from scratch (mandatory verification of primary sources and annotation of the as‑of date) into a technical document suitable for long‑term reference; or to rewrite an existing technical document—routed according to intent: update timeliness / incorporate new material → spot‑repair while preserving the original shape; restructure / refactor → rebuild the four sections according to the compass.

It can be applied after the learn‑loop: the learn module handles the interactive learning cycle and hands‑on distillation (the iron rule: distillation is learning itself, not ghostwriting). This skill only takes over after distillation is completed, reorganizing the content, filling in the reader’s context, and performing final proofing.

Do not use for: internal company memos, meeting minutes, evaluation reports, or other administrative documents (use formal‑doc‑structure; even if the input is an existing document, it should not be routed to this skill), RFPs/tender specifications (use rfp‑writing), blog posts (use blog‑writing‑zh), tasks that only require linguistic polishing without structural changes (use avoid‑ai‑writing‑zh), purely oral/plain‑language explanations that do not produce a document (use plain‑speak), or the interactive learning loop itself (use learn‑loop).
