À utiliser lorsque l'utilisateur conçoit, prototype ou réécrit une application de bureau qui doit s'exécuter sur plusieurs systèmes d'exploitation (macOS + Windows, éventuellement Linux) ET se sentir impossible à distinguer d'une application native pour ses utilisateurs : lancement rapide, fenêtrage natif, gestion des entrées natives, matériaux natifs. Les mots déclencheurs incluent « bureau multiplateforme », « alternative Electron », « Tauri vs natif », « wrapper WebView », « performances quasi natives », « architecture Raycast », « bizarreries WebKit/WebView2 », « WKWebView », « application de la barre d'état système », « application de raccourci clavier globale », « application de lancement ». Ne déclenchez PAS cette compétence pour des applications Web pures, des applications mobiles pures ou pour des projets inédits qui n'ont aucune exigence de sensation native.
