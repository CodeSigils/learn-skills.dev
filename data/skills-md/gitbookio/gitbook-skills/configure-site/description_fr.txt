Créez et gérez des sites de documentation GitBook entiers de bout en bout : concevez la structure du site à partir du contenu source, échafaudez un référentiel Git dans une disposition monorepo, configurez la télécommande GitHub/GitLab, pilotez l'API GitBook (via son API REST ou son serveur MCP) pour créer le site/les sections/les espaces, appliquer la personnalisation de marque et transmettre à l'utilisateur des instructions propres pour la seule étape de l'interface utilisateur (câblage Git Sync) que GitBook n'expose pas par programme. Déclenchez cette compétence chaque fois que l'utilisateur souhaite créer un nouveau site de documentation GitBook, restructurer ou étendre un site existant, lier des espaces à un dépôt Git pour la synchronisation, modifier la marque d'un site (logo, couleurs, polices, en-tête/pied de page) ou gérer par programme des espaces, des sections ou des espaces de site. Cette compétence est la couche d'orchestration ; pour créer le contenu markdown de n'importe quelle page individuelle, il s'en remet à la compétence associée « write-docs ».
