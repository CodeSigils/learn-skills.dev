透過直接使用curl（無CLI）呼叫GitBook REST API，從Claude Code驅動端到端的GitBook文件審查流程－建立變更請求，推送內容（更新現有頁面並建立新頁面），請求審閱者，通知Slack，然後拉回審閱評論，修復它們，重新推送並解決。這是 cr-review 的創作端伴侶（同一 API 上的審閱者端）。每當有人想要從終端機/代理程式針對原始 API (curl/HTTP) 執行「GitBook 中的文件審查」循環時，提到透過 API 建立變更要求、將內容推送到 CR、「拉取最新評論並修復它們」、請求對文件進行審查，或向工程師展示如何在沒有 CLI 的情況下處理來自 Claude + Slack 的 GitBook 文檔，請使用此協作選項。
