Verfassen, konfigurieren, strukturieren und beheben Sie Fehler in der OpenAPI/Swagger-API-Referenzdokumentation in GitBook. Verwenden Sie dies immer dann, wenn eine Aufgabe einen GitBook-OpenAPI-Block oder einen „{% openapi %}“-Block umfasst, das Hinzufügen oder Aktualisieren einer OpenAPI/Swagger-Spezifikation in GitBook (per Datei oder URL, über die API, MCP, CLI oder App-Benutzeroberfläche), das Generieren von API-Referenzseiten aus einer Spezifikation, das Konfigurieren des interaktiven „Test it“-Runners (Authentifizierung, Server, CORS, Proxy) und das Anpassen von Seiten mit GitBook „x-*“-Erweiterungen (Symbole, Titel, Navigation). Hierarchie, Codebeispiele, Enum-Beschreibungen), Markieren von Vorgängen als experimentell/veraltet/versteckt oder Automatisieren von Spezifikationsaktualisierungen in CI/CD. Wird auch dann ausgelöst, wenn der Benutzer nur GitBook plus OpenAPI erwähnt, einer für GitBook bestimmten Spezifikation eine „x-“-Erweiterung hinzufügt oder fragt „Warum wird meine Spezifikation nicht geladen“ oder „Warum funktioniert Test it nicht“, ohne diese Fähigkeit zu benennen.
