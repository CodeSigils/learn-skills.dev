Aktualisieren Sie ein ObjectStack-Metadatenprojekt über ein Hauptprotokoll hinweg – führen Sie die deterministische Konvertierungskette aus, verarbeiten Sie dann den semantischen Rest, den die Kette nicht ausdrücken kann (Absichtsauswahl, benutzerdefinierter Code auf veralteten APIs, veraltete Prosa), zu einer Entscheidung mit dem Eigentümer des Projekts und schließen Sie mit einem grünen „Validieren“ sowie einem für Menschen lesbaren Upgrade-Bericht ab. Verwenden Sie diese Option, wenn sich ein Projekt auf einem älteren Protokoll-Hauptprotokoll befindet und auf das aktuelle Protokoll umgestellt werden muss, wenn „@objectstack/spec“ auf ein Hauptprotokoll gestoßen ist und Metadaten oder Code nicht mehr geparst werden können, wenn ein Parse- oder „tsc“-Fehler eine „[REMOVED]“-Vorschrift angibt oder wenn Sie aufgefordert werden, „auf v17 zu aktualisieren“ / „升级到 v17“ / „一键升级元数据项目“. Verwenden Sie sie nicht, um neue Metadaten zu erstellen (die Domänenkenntnisse decken dies ab), um einen Ruhestand im ObjectStack-Plattform-Repo selbst (das ist das interne Playbook der Plattform) zu entwerfen oder um eine Umschreibung von Hand zu schreiben. Die Konvertierungskette gilt bereits – das Ausführen der Kette ist immer der erste Schritt, niemals ein Rückfall.
