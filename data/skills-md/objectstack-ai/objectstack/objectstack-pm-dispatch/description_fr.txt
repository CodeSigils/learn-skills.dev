Exécutez une boucle de répartition du chef de projet sur un backlog GitHub : triez et mettez en file d'attente les problèmes prêts, revendiquez chacun d'eux, envoyez-le à un agent de développement parallèle qui renvoie un rapport JSON structuré, examinez les résultats par rapport à GitHub et dirigez les demandes d'extraction acceptées vers l'atterrissage - en transmettant au responsable uniquement ce qui nécessite réellement une décision humaine. Envoie le modèle opérationnel d'agent développeur que la boucle injecte dans chaque expédition (aucun type d'agent personnalisé requis) et la procédure de rapport en amont pour les défauts de plate-forme détectés par un projet d'application. À utiliser lorsqu'on vous demande de « résoudre le backlog », « problèmes de répartition par lots », « problème de problème avec l'agent », pour mettre en place une boucle de livraison multi-agents dans un projet d'application ObjectStack ou pour signaler un bogue de plate-forme trouvé lors de la création d'une application. Ne l'utilisez pas pour créer des métadonnées ObjectStack (les compétences du domaine couvrent cela), pour une seule modification déjà étendue que vous pouvez simplement apporter, ou en remplacement du propre fichier de conventions du projet - ce fichier gagne toujours.
