Ekotech Parking Open Platform “Vehicle Entry/Exit” operation process SOP (end‑to‑end orchestration for entry and exit). When a user wants a car to fully enter or exit, simulate the real physical entry/exit process, run through the entire chain of “supplementary record/snapshot entry → correction” or “exit snapshot → correction → fee inquiry → payment”, asks “how does a car enter / exit / entry‑exit process / entry‑exit SOP / how to get a car into (out of) the parking lot / simulate a car entering and exiting”, or encounters a blockage/troubleshooting step during the entry/exit process (e.g., after snapshot or correction the car has not entered, snapshot reports 908, unsure how to proceed), this skill is used. This skill is a cross‑domain orchestration layer, linking multiple commands across parking (supplementary record/correction/inventory) + device (snapshot) + trade (fee inquiry/payment), and clarifies the hard constraints across commands (paired exit, snapshot device, channel release mode, token validity) and failure handling. Scope: for querying a single record / vehicle currently in the lot / locked vehicle / invoking a single command, please directly use the corresponding domain skills openydt-record / openydt-device / openydt-billing, and do not use this process skill.
