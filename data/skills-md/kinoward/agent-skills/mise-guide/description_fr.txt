DOIT UTILISER pour tout ce qui concerne la mise en place, les versions des outils de développement ou la configuration de l'environnement de développement. Déclencheurs : (1) L'utilisateur mentionne mise, mise.toml, .tool-versions ou des commandes mise comme « mise use », « mise install », « mise run ». (2) L'utilisateur souhaite installer, changer, épingler, mettre à niveau ou vérifier les versions des outils de développement — node, python, go, ruby, java, rust, etc. — au niveau du projet ou au niveau global, même sans mentionner la mise (par exemple, « configurer le nœud 22 », « quelle version de python », « mettre à niveau », « vérifier les outils obsolètes », « configurer l'environnement de développement »). (3) L'utilisateur souhaite gérer les variables d'environnement par projet via des fichiers de configuration (par exemple, « ajouter une variable d'environnement DATABASE_URL », « configurer des variables d'environnement pour différents environnements »). (4) L'utilisateur souhaite définir ou exécuter des tâches de projet via mise (par exemple « créer une tâche de construction », « exécuter des tests avec mise »). Ne déclenchez PAS pour : les fichiers Dockerfiles, les scripts package.json, les Makefiles, les commandes nvm/pyenv/rbenv, l'installation du package pip/npm, les balises git, la configuration CI/CD ou le déploiement.
