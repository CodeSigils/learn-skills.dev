Livraison de branche de bout en bout : validation (pas d'attribution IA) → push → ouvrir une pull request → garantir qu'un élément de travail Board existe (créez-en un par tâche, attribué à l'utilisateur configuré, s'il n'y en a pas) et liez-le → après la fusion, nettoyez la branche et l'arbre de travail. Détecte automatiquement la plate-forme à distance : Azure Repos + Boards (SDK azure-devops-node-api ; OAuth Bearer push fallback via `az`) ou GitHub (Octokit ; `gh` pour l'authentification). Les scripts sont TypeScript, exécutés via `bun`. À utiliser chaque fois qu'il est demandé de "expédier", "expédier", "expédier cette branche", "ouvrir un PR", "pousser et ouvrir un PR", "lancer un PR", "livrer ceci", "envoyer ceci pour examen" ou "créer un PR et lier l'élément de travail" - et lorsqu'une poussée directe vers main est bloquée et que la modification doit passer par un PR à la place. Couvre également la capture d'un instantané de l'état actuel sous forme de balise git annotée - à utiliser chaque fois qu'il est demandé de "enregistrer l'état actuel", "étiqueter ceci", "instantané l'état", "créer un point de contrôle", "étiqueter un point de version" ou "marquer où nous sommes" (un point de contrôle git-tag, distinct des étiquettes/balises PR). Ouvre également un PR nouvellement créé (ou n'importe quel) dans un profil de compte de navigateur choisi — à utiliser chaque fois qu'on vous demande « d'ouvrir le PR dans mon navigateur », « de l'ouvrir dans Edge/Chrome » ou « d'ouvrir le PR en tant que <compte> ».
