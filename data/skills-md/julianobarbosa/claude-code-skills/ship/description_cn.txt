端到端分支交付：提交（无 AI 归属）→ 推送 → 打开拉取请求 → 确保 Board 工作项存在（每个任务创建一个，分配给配置的用户，如果没有）并链接它 → 合并后，清理分支和工作树。自动检测远程平台 — Azure Repos + Boards（azure-devops-node-api SDK；通过“az”进行 OAuth Bearer 推送回退）或 GitHub（Octokit；“gh”表示身份验证）。脚本是 TypeScript，通过“bun”运行。每当被要求“发布”、“发布它”、“发布这个分支”、“打开 PR”、“推送并打开 PR”、“提出 PR”、“交付此”、“发送此供审核”或“创建 PR 并链接工作项”时，以及当直接推送到主干被阻止并且更改需要通过 PR 时，请使用。还包括将当前状态快照为带注释的 git 标签——每当被要求“保存当前状态”、“标记此”、“快照状态”、“创建检查点”、“标记发布点”或“标记我们所在的位置”时使用（git-tag 检查点，与 PR 标签/标签不同）。还可以在选定的浏览器帐户配置文件中打开刚刚创建的（或任何）PR - 每当被要求“在我的浏览器中打开 PR”、“在 Edge/Chrome 中打开它”或“以 <帐户> 身份打开 PR”时使用。
