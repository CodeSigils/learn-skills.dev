Consegna del ramo end-to-end: commit (nessuna attribuzione AI) → push → apri una richiesta pull → assicurati che esista un elemento di lavoro di Board (creane uno per attività, assegnato all'utente configurato, se nessuno) e collegalo → dopo l'unione, pulisci il ramo e l'albero di lavoro. Rileva automaticamente la piattaforma dal remoto: Azure Repos + Boards (azure-devops-node-api SDK; OAuth Bearer push fallback tramite `az`) o GitHub (Octokit; `gh` per auth). Gli script sono TypeScript, eseguiti tramite "bun". Utilizzare ogni volta che viene richiesto di "spedire", "spedire", "spedire questo ramo", "aprire un PR", "inviare e aprire un PR", "sollevare un PR", "consegnare questo", "inviare questo per la revisione" o "creare un PR e collegare l'elemento di lavoro" e quando un push diretto all'elemento principale è bloccato e la modifica deve invece passare attraverso un PR. Copre anche l'istantanea dello stato corrente come tag git annotato: da utilizzare ogni volta che viene richiesto di "salvare lo stato corrente", "taggare questo", "istantanea dello stato", "creare un checkpoint", "taggare un punto di rilascio" o "segnare dove siamo" (un checkpoint con tag git, distinto dalle etichette/tag PR). Apre anche un PR appena creato (o qualsiasi altro) nel profilo dell'account del browser scelto: utilizzalo ogni volta che ti viene chiesto di "aprire il PR nel mio browser", "aprirlo in Edge/Chrome" o "aprire il PR come <account>".
