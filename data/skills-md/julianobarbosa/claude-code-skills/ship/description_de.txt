End-to-End-Branch-Bereitstellung: Commit (keine KI-Zuordnung) → Push → eine Pull-Anfrage öffnen → sicherstellen, dass ein Board-Arbeitselement vorhanden ist (eines pro Aufgabe erstellen, dem konfigurierten Benutzer zugewiesen, falls keines vorhanden ist) und es verknüpfen → nach dem Zusammenführen Branch und Arbeitsbaum bereinigen. Erkennt die Plattform automatisch aus der Ferne – Azure Repos + Boards (azure-devops-node-api SDK; OAuth Bearer Push Fallback über „az“) oder GitHub (Octokit; „gh“ für Auth). Skripte sind TypeScript und werden über „bun“ ausgeführt. Wird immer dann verwendet, wenn Sie aufgefordert werden, „zu versenden“, „zu versenden“, „diesen Zweig zu versenden“, „eine PR zu öffnen“, „eine PR zu pushen und zu öffnen“, „eine PR zu erstellen“, „zu liefern“, „zur Überprüfung zu senden“ oder „eine PR zu erstellen und das Arbeitselement zu verknüpfen“ – und wenn ein direkter Push an „main“ blockiert ist und die Änderung stattdessen eine PR durchlaufen muss. Behandelt auch das Snapshoten des aktuellen Status als kommentiertes Git-Tag – verwenden Sie es, wenn Sie aufgefordert werden, „den aktuellen Status zu speichern“, „diesen zu markieren“, „den Status zu snapshoten“, „einen Prüfpunkt zu erstellen“, „einen Release-Punkt zu markieren“ oder „markieren, wo wir sind“ (ein Git-Tag-Checkpoint, der sich von PR-Labels/Tags unterscheidet). Öffnet auch einen gerade erstellten (oder einen beliebigen) PR in einem ausgewählten Browser-Kontoprofil – verwenden Sie ihn, wenn Sie dazu aufgefordert werden, „den PR in meinem Browser zu öffnen“, „in Edge/Chrome zu öffnen“ oder „den PR als <Konto> zu öffnen“.
