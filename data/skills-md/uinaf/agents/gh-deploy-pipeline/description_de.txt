Richten Sie eine GitHub Actions-Bereitstellungspipeline für eine laufende App oder einen laufenden Dienst ein oder richten Sie sie aus. Verwenden Sie diese Option, wenn Sie Repositorys um die Form „Überprüfen und dann bereitstellen“ standardisieren: Push to main -> Betroffene Spuren erkennen -> Artefakte überprüfen und erstellen -> e2e -> Stellen Sie jede Spur über eine GitHub-Umgebung unter Verwendung von OIDC oder umgebungsbezogenen Anmeldeinformationen bereit, mit nicht stornierbarer Parallelität bei der Bereitstellung pro Umgebung. Paart sich mit „gh-release-pipeline“ für versionierte Pakete; Wird zum Bereitstellen laufender Apps verwendet, nicht zum Veröffentlichen von Artefakten in einer Registrierung.
