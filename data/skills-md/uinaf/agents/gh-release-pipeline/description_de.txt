Richten Sie eine GitHub Actions-Release-Pipeline für ein versioniertes Paket, eine Bibliothek, eine CLI oder eine Marktplatzaktion ein oder richten Sie sie aus. Verwenden Sie diese Option, wenn Sie Repos um die Form „Überprüfen und dann veröffentlichen“ standardisieren: Push to main → Leitplanken → Semantic-Release-Tags + Veröffentlichungen → Versions-Bump-Commit zurück zum Main mit „[skip ci]“. Lässt sich mit „gh-deploy-pipeline“ kombinieren, um Apps auszuführen; Wird zum Veröffentlichen versionierter Artefakte in einer Registrierung verwendet, nicht zum Bereitstellen eines laufenden Dienstes.
