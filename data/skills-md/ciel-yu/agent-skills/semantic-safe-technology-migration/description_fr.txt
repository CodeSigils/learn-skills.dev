À utiliser lorsque le principal changement concerne le modèle technologique lui-même (framework, runtime, version majeure, système de modules ou modèle de programmation) et que la sémantique comportementale ou de domaine doit survivre à une surface technique intentionnellement changeante. Déclencheurs : mettez à niveau React 16 → 18, migrez Express → Fastify, convertissez CommonJS → ESM ou déplacez les rappels → async/wait lorsque le comportement de compatibilité change. Ne pas utiliser lorsque les appelants doivent conserver la même surface de module (utilisez `semantic-safe-module-boundary-migration`) ou lorsque la technologie reste matériellement la même et que vous remplacez uniquement les composants internes derrière une interface stable (utilisez `semantic-safe-implementation-refactor`).
