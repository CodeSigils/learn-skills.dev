Wird verwendet, wenn die primäre Änderung das Technologiemodell selbst betrifft – Framework, Laufzeit, Hauptversion, Modulsystem oder Programmiermodell – und die Verhaltens- oder Domänensemantik einer sich absichtlich ändernden technischen Oberfläche standhalten muss. Auslöser: Aktualisieren Sie React 16 → 18, migrieren Sie Express → Fastify, konvertieren Sie CommonJS → ESM oder verschieben Sie Rückrufe → asynchron/warten Sie, wenn sich das Kompatibilitätsverhalten ändert. Nicht verwenden, wenn Aufrufer die gleiche Moduloberfläche beibehalten müssen (verwenden Sie „semantic-safe-module-boundary-migration“) oder wenn die Technologie im Wesentlichen gleich bleibt und Sie nur Interna hinter einer stabilen Schnittstelle ersetzen (verwenden Sie „semantic-safe-implementation-refactor“).
