Úselo cuando el cambio principal es el modelo tecnológico en sí (marco, tiempo de ejecución, versión principal, sistema de módulos o modelo de programación) y la semántica de dominio o de comportamiento debe sobrevivir a una superficie técnica que cambia intencionalmente. Desencadenantes: actualice React 16 → 18, migre Express → Fastify, convierta CommonJS → ESM o mueva devoluciones de llamada → async/await cuando cambie el comportamiento de compatibilidad. No lo use cuando las personas que llaman deben mantener la misma superficie del módulo (use `semantic-safe-module-boundary-migration`) o cuando la tecnología permanezca materialmente igual y solo esté reemplazando elementos internos detrás de una interfaz estable (use `semantic-safe-implementation-refactor`).
