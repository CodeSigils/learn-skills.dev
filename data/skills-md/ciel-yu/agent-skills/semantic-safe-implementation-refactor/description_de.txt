Verwenden Sie diese Option, wenn die primäre Änderung darin besteht, eine Implementierung zu ersetzen und gleichzeitig die öffentliche Oberfläche und das Technologiemodell im Wesentlichen stabil zu halten. Auslöser: Einen chaotischen Dienst hinter derselben Schnittstelle neu schreiben, alte Logik durch ein sauberes Modul ersetzen, ein Subsystem hinter einem bestehenden Vertrag neu implementieren oder einen Adapter oder eine Fassade einführen, damit eine neue Implementierung übernehmen kann. Nicht verwenden, wenn die Hauptarbeit darin besteht, Modul-, Paket- oder Aufrufergrenzen zu verschieben (verwenden Sie „semantic-safe-module-boundary-migration“) oder wenn eine Änderung eines Frameworks, einer Laufzeit, einer Version, eines Modulsystems oder eines Programmiermodells die Hauptrisikoquelle darstellt (verwenden Sie „semantic-safe-technology-migration“).
