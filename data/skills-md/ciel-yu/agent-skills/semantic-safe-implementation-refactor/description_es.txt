Úselo cuando el cambio principal sea reemplazar una implementación y al mismo tiempo mantener la superficie pública y el modelo tecnológico materialmente estables. Desencadenantes: reescribir un servicio desordenado detrás de la misma interfaz, reemplazar la lógica heredada con un módulo limpio, reimplementar un subsistema detrás de un contrato existente o introducir un adaptador o fachada para que una nueva implementación pueda tomar el control. No lo use cuando el trabajo principal sea mover los límites de módulos, paquetes o llamantes (use `semantic-safe-module-boundary-migration`) o cuando un cambio de marco, tiempo de ejecución, versión, sistema de módulos o modelo de programación sea la principal fuente de riesgo (use `semantic-safe-technology-migration`).
