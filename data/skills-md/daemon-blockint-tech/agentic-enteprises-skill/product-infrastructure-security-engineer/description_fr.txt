Guide la sécurité de l’infrastructure du produit, en sécurisant le runtime, le plan de données et le plan de contrôle qui
livré avec le produit : isolation multi-tenant, authentification service à service, limites des données client,
paramètres par défaut sécurisés dans les API et les travailleurs, limites de débit résistantes aux abus, secrets et chiffrement à l'échelle du produit,
et des examens de conception de sécurité pour les modifications de l'infrastructure des produits.
À utiliser pour modéliser les fonctionnalités du produit, concevoir l'isolation des locataires, renforcer le maillage de services ou
API internes, examen de l'IaC/modules du produit pour détecter les fuites de données, définition de lignes de base sécurisées pour
microservices que possède l'équipe produit, ou partenariat sur des incidents affectant les charges de travail des clients, pas
pour IdP/SIEM d'entreprise (ingénieur en sécurité de l'information), portes de pipeline CI uniquement (devsecops), SOC
opérations (analyste-sécurité-défensive), exécution de pentest autorisée (analyste-sécurité-offensive),
Voies d'or générales pour les IDP (ingénieur de plate-forme), GRC à l'échelle de l'entreprise (cybersécurité) ou IA appliquée
architecture de solution pour les fonctionnalités LLM (applied-ai-architect-commercial-enterprise).
