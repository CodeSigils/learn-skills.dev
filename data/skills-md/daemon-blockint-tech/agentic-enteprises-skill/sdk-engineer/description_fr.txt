Conçoit, crée et gère des SDK clients pour les API HTTP/REST, GraphQL, gRPC et RPC :
Alignement des contrats OpenAPI-first, modélisation des ressources, authentification (clés API, OAuth, signature),
tentatives/expirations/idempotence, pagination et streaming, taxonomie des erreurs, gestion des versions et dépréciation,
packaging et dénomination multilingues, expérience des développeurs (démarrages rapides, exemples) et tests SDK
(contrat et intégration) avec une documentation alignée sur la référence API.
À utiliser lorsque l'utilisateur dit ingénieur SDK, SDK client, créer un SDK, une bibliothèque client API, un SDK OpenAPI,
Conception du SDK, gestion des versions du SDK, SDK de politique de nouvelle tentative, client de pagination, authentification du SDK ou développeur
SDK : pas uniquement la conception d'API back-end (développement d'API), l'interface utilisateur de l'application pour l'utilisateur final (ingénieur logiciel frontend senior),
patrons de plateforme d'intégration génériques (ingénieur-plateforme), rédaction technique sans implémentation de SDK
(tech-rédacteur-chercheur), ou architecture de pré-vol go/no-go sans travail SDK (build-validator).
