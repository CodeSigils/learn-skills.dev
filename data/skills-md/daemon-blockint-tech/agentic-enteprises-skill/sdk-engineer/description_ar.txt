تصميم حزم SDK للعميل وإنشائها وصيانتها لواجهات برمجة التطبيقات بنمط HTTP/REST وGraphQL وgRPC وRPC—
محاذاة العقد OpenAPI-first، ونمذجة الموارد، والمصادقة (مفاتيح API، OAuth، التوقيع)،
إعادة المحاولة/المهلات/العجز، ترقيم الصفحات والتدفق، تصنيف الأخطاء، إصدار الإصدارات والإهمال،
التعبئة والتغليف والتسمية متعددة اللغات، وتجربة المطور (البدء السريع، والأمثلة)، واختبار SDK
(العقد والتكامل) مع الوثائق المتوافقة مع مرجع API.
يُستخدم عندما يقول المستخدم مهندس SDK، عميل SDK، إنشاء SDK، مكتبة عميل API، OpenAPI SDK،
تصميم SDK، إصدار SDK، إعادة محاولة سياسة SDK، عميل ترقيم الصفحات، مصادقة SDK، أو المطور
SDK - ليس تصميم واجهة برمجة التطبيقات الخلفية فقط (تطوير واجهة برمجة التطبيقات)، وواجهة مستخدم تطبيق المستخدم النهائي (مهندس برمجيات الواجهة الأمامية الأول)،
أنماط منصة التكامل العامة (مهندس النظام الأساسي)، والكتابة الفنية دون تنفيذ SDK
(كاتب-باحث تقني)، أو هندسة ما قبل الرحلة تذهب/لا تذهب بدون عمل SDK (مدقق البناء).
