Проектирует, создает и поддерживает клиентские SDK для HTTP/REST, GraphQL, gRPC и API-интерфейсов в стиле RPC.
Согласование контрактов OpenAPI-first, моделирование ресурсов, аутентификация (ключи API, OAuth, подпись),
повторы/таймауты/идемпотентность, нумерация страниц и потоковая передача, таксономия ошибок, управление версиями и устаревание,
многоязычная упаковка и именование, опыт разработки (краткие руководства, примеры) и тестирование SDK.
(контракт и интеграция) с документацией, соответствующей ссылке API.
Используйте, когда пользователь говорит: инженер SDK, клиентский SDK, создание SDK, клиентская библиотека API, OpenAPI SDK,
Разработка SDK, управление версиями SDK, политика повторных попыток SDK, клиент разбиения на страницы, аутентификация SDK или разработчик
SDK — не только дизайн серверного API (разработка API), пользовательский интерфейс приложения для конечного пользователя (старший интерфейсный инженер-программист),
общие шаблоны интеграционной платформы (инженер платформы), техническое написание без внедрения SDK
(технический писатель-исследователь) или предполетная архитектура без работы с SDK (сборка-валидатор).
