Ribasare il checkout Git corrente sul ramo di base remoto richiesto o sul ramo remoto predefinito del repository quando non ne viene nominato nessuno, senza perdere il lavoro locale. Utilizzare sempre questa capacità per un'effettiva operazione di sincronizzazione del ramo di base, comprese le richieste di pull o sincronizzazione del ramo principale, master, trunk o predefinito; aggiornare un ramo dalla sua base; rebase su una base remota; portare i commit di base in entrata nel checkout corrente; o aggiornare un albero di lavoro distaccato da quella base.
