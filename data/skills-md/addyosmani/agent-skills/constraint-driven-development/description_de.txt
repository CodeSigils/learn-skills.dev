Legt die Qualitätsgrenze eines Projekts in Form eines schriftlichen Vertrags fest und verhindert, dass Agenten sie stillschweigend senken. Befragt den Benutzer dazu, welche Dimensionen wichtig sind, stellt vernünftige Standardschwellenwerte bereit, wenn er keine Zahl im Sinn hat, zeichnet alles in CONSTRAINTS.md auf und überwacht den Diff auf einen geschwächten Balken – neue @ts-ignore- oder eslint-disable-Unterdrückungen, übersprungene oder gelöschte Tests, entfernte Behauptungen, nicht implementierte Stubs, nach unten bearbeitete Schwellenwerte. Verwenden Sie diese Option, wenn keine Qualitätsgrenze aufgeschrieben ist, wenn der Benutzer „Einschränkungen einrichten“ oder „unsere Standards definieren“ sagt, wenn ein Agent ständig Prüfungen unterdrückt oder Tests überspringt, um zum grünen Bereich zu gelangen, wenn Sie einen Abdeckungs- oder Leistungsschwellenwert benötigen und nicht wissen, welche Zahl Sie auswählen sollen, oder wenn ein Agent mehr Code schreibt, als irgendjemand lesen kann.
