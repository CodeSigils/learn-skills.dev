Questa competenza dovrebbe essere utilizzata quando un progetto GitHub rilascia una nuova versione, coprendo l'intero processo di gestione dei numeri di versione, sincronizzazione CHANGELOG, scrittura delle note di rilascio, creazione di tag, monitoraggio della build CI, verifica del rilascio e pulizia storica. Si applica a qualsiasi progetto software basato su GitHub come applicazioni desktop, strumenti CLI, applicazioni Web, librerie/SDK, ecc. Viene attivato quando l'utente menziona "release", "tag", "nuova versione", "aggiorna numero di versione", "scrivi note di rilascio", "rilascio non riuscito" o "CI rotto". Non utilizzarlo per progetti non GitHub (ad esempio, progetti GitLab/Gitea puri) o scenari di rilascio manuale che non richiedono CI.
