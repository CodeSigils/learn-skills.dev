This skill should be used when a GitHub project releases a new version, covering the entire process of version number management, CHANGELOG synchronization, Release Notes writing, tag creation, CI build monitoring, release verification, and historical cleanup. It applies to any GitHub‑based software project such as desktop applications, CLI tools, web applications, libraries/SDKs, etc. It is triggered when the user mentions “release,” “tag,” “new version,” “update version number,” “write release notes,” “release failed,” or “CI broke.” Do not use it for non‑GitHub projects (e.g., pure GitLab/Gitea projects) or manual release scenarios that do not require CI.
