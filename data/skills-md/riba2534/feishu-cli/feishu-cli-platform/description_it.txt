Solo per le funzionalità fondamentali della piattaforma della CLI Feishu, non un fallback universale per tutte le richieste Feishu. Copre l'inizializzazione della configurazione, l'accesso OAuth e la gestione di token/profili, la diagnostica del medico, le query sullo schema OpenAPI, il pass-through API generico, la ricerca globale e le query di utenti e dipartimenti. Quando l'utente menziona l'accesso a Feishu, il flusso del dispositivo, l'ambito, il token utente/tenant, la scadenza del token, il profilo, il medico, 99991672/99991679, l'interrogazione di percorso/parametri/ambito dell'API, API non elaborata, la chiamata di OpenAPI non imballata, la ricerca di documenti/messaggi/app o l'interrogazione di utenti, e-mail o dipartimenti, è necessario utilizzare questa abilità. Sono espressamente vietati corpi di documenti, file di unità cloud, messaggi/chat di gruppo, fogli/Bitable, lavagne/presentazioni, calendari/attività/approvazioni/partecipazioni/OKR, e-mail o riunioni/verbali; queste operazioni aziendali dovrebbero essere delegate alla competenza del dominio corrispondente. In questo caso, la "ricerca globale" si riferisce solo alla "ricerca di documenti/messaggi/app", escluse le query all'interno di approvazione, riunione, posta elettronica o altri domini aziendali. Se la richiesta contiene approvazione, codice_approvazione, definizione/istanza/attività di approvazione, non utilizzare mai questa competenza; utilizzare invece feishu-cli-work. Se si tratta di riunioni video, verbali, registrazioni o trascrizioni, utilizzare feishu-cli-meetings.
