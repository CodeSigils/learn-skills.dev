Feishu-Echtzeit-Event-Abonnement (WebSocket). „Ereignisliste“ zeigt die unterstützten EventKeys; „Ereignisschema“ zeigt die Nutzlast/den Umfang des Ereignisses; „event consume“ startet ein Abonnement für lange Verbindungen und schreibt den Ereignisstrom als NDJSON in stdout (blockierend, ein Prozess abonniert einen EventKey); „Ereignisstatus“ zeigt die aktiven Konsumprozesse auf dem lokalen Computer an; „event stop“ stoppt den Verbrauch durch PID / EventKey / --all. Unterstützt mehr als 22 EventKeys (Empfangen/Lesen/Widerrufen/Reaktion von IM-Nachrichten, Änderungen von Gruppenmitgliedern, Änderungen von Kontaktmitarbeitern, Kalenderänderungen, Titel/Mitarbeiter des Cloud-Laufwerks, Genehmigungsinstanzen und -aufgaben, Beginn/Ende von VC-Meetings). Unterstützt die erneute Verbindung nach einer Verbindungstrennung und das parallele Abonnement mehrerer EventKeys. Wird verwendet, wenn ein Benutzer „Feishu-Ereignisse abhören“, „Nachrichtenereignisse in Echtzeit empfangen“, „Genehmigungsrückrufe abonnieren“, „Ereignisstrom“, „WebSocket-Überwachung langer Verbindungen“, „Ereignisverbrauch“, „Ereignisliste/Schema/Status/Stopp“ oder „Echtzeitantwort des KI-Agent-Bots“ anfordert. Hinweis: Diese Funktion verwaltet nur Abonnements. Die Verarbeitung der Webhook-Geschäftslogik für Ereignisse (Pushing an Feishu-Nachrichten / Schreiben an Bitable) sollte mit feishu-cli-msg / feishu-cli-bitable erfolgen.
