Feishu real-time event subscription (WebSocket). `event list` shows the supported EventKeys; `event schema` shows the event payload/scope; `event consume` starts a long‑connection subscription, writing the event stream to stdout as NDJSON (blocking, one process subscribes to one EventKey); `event status` displays the active consume processes on the local machine; `event stop` stops consumption by PID / EventKey / --all. Supports 22+ EventKeys (IM message receipt/read/revoke/reaction, group member changes, contact employee changes, calendar changes, cloud drive title/collaborators, approval instances and tasks, VC meeting start/end). Supports reconnection after disconnection and parallel subscription of multiple EventKeys. Used when a user requests “listen to Feishu events”, “receive message events in real time”, “subscribe to approval callbacks”, “event stream”, “WebSocket long‑connection listening”, “event consume”, “event list / schema / status / stop”, or “AI Agent bot real‑time response”. Note: This capability only handles subscription; processing event webhook business logic (pushing to Feishu messages / writing to Bitable) should be done with feishu-cli-msg / feishu-cli-bitable.
