Подписка на события Feishu в реальном времени (WebSocket). «список событий» показывает поддерживаемые EventKeys; `схема событий` показывает полезную нагрузку/объем события; `event Consumer` запускает подписку с длинным соединением, записывая поток событий в стандартный вывод как NDJSON (блокировка, один процесс подписывается на один EventKey); «статус события» отображает активные процессы потребления на локальном компьютере; `event stop` останавливает потребление PID/EventKey/--all. Поддерживает более 22 ключей EventKeys (получение/чтение/отзыв/реакция мгновенного сообщения, изменения членов группы, изменения контактных сотрудников, изменения календаря, название облачного диска/соавторы, экземпляры и задачи утверждения, начало/окончание собрания VC). Поддерживает повторное подключение после отключения и параллельную подписку нескольких EventKeys. Используется, когда пользователь запрашивает «прослушивание событий Feishu», «получение событий сообщений в реальном времени», «подписку на обратные вызовы утверждения», «поток событий», «прослушивание длинных соединений WebSocket», «потребление событий», «список событий/схему/статус/остановку» или «ответ бота AI Agent в режиме реального времени». Примечание. Эта возможность работает только с подпиской; обработка бизнес-логики веб-перехватчика событий (отправка сообщений Feishu/запись в Bitable) должна выполняться с помощью feishu-cli-msg/feishu-cli-bitable.
