Appliquez les directives de conception de l'API Swift pour nommer, étiqueter et documenter les API Swift. Couvre les règles d'étiquetage des arguments (règle de phrase prépositionnelle, règle de phrase grammaticale, omission de la première étiquette), la dénomination des paires mutantes/non mutantes (modèle de participe -ed/-ing, préfixe de forme, tri/tri, formUnion/union), la dénomination des effets secondaires (nom pour pur, verbe pour mutation), la structure des commentaires de la documentation (résumé par type de déclaration, règle de complexité O(1), la clarté sur le site d'appel, la dénomination basée sur les rôles, la dénomination du protocole (-able/-ible/-ing), arguments par défaut sur les familles de méthodes, conventions de casse et terminologie. À utiliser lors de la conception de nouvelles API Swift, de la révision des étiquettes de dénomination et d'arguments, de la rédaction de commentaires de documentation ou de la refactorisation pour plus de clarté sur le site d'appel.
