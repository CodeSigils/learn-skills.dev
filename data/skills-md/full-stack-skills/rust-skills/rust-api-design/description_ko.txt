Rust API 지침을 따르는 Rust 라이브러리 API 설계 — 명명(C-CASE, C-CONV, C-GETTER), 상호 운용성 특성(C-COMMON-TRAITS, C-CONVERT, C-ITER, C-SERDE), 예측 가능성(C-INTUITIVE, C-CONST), 유연성(C-GENERIC, C-NEWTYPE, C-EXT), 유형 안전성(C-BOOL, C-NONZERO, C-WRAPPER, C-STR), 신뢰성(C-PANIC, C-UNWRAP), 디버깅 가능성(C-DEBUG) 및 미래 보장성(C-SEALED, C-STRUCT-FIELD, C-NON-EXHAUSTIVE). 사용자가 공개 크레이트 API를 디자인할 때, 제네릭/콘크리트/새 유형 중에서 선택하거나, 특성 경계를 결정하거나, 구현을 숨기거나, 파손을 방지하거나, "관용적인 Rust API 디자인이 무엇인지" 질문할 때 사용합니다. semver를 전달하고 작업 흐름을 Rust-semver로, lint 구성을 Rust-style-clippy로, 상자 내 레이아웃을 Rust-module-layout으로 게시합니다.
