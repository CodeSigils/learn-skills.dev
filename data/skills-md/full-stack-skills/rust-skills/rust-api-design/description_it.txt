Progettare API di libreria Rust che seguano le linee guida API Rust: denominazione (C-CASE, C-CONV, C-GETTER), tratti di interoperabilità (C-COMMON-TRAITS, C-CONVERT, C-ITER, C-SERDE), prevedibilità (C-INTUITIVE, C-CONST), flessibilità (C-GENERIC, C-NEWTYPE, C-EXT), indipendenza dal tipo (C-BOOL, C-NONZERO, C-WRAPPER, C-STR), affidabilità (C-PANIC, C-UNWRAP), possibilità di debug (C-DEBUG) e protezione futura (C-SEALED, C-STRUCT-FIELD, C-NON-EXHAUSTIVE). Da utilizzare quando gli utenti progettano un'API crate pubblica, scelgono tra generici/concrete/newtype, decidono i limiti dei tratti, nascondono l'implementazione, evitano rotture o chiedono "cos'è la progettazione idiomatica dell'API Rust"; passa semver e pubblica il flusso di lavoro su ruggine-semver, la configurazione lint su ruggine-style-clippy e il layout in-crate su ruggine-module-layout.
