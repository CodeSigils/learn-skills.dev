Rust API ガイドラインに従った Rust ライブラリ API の設計 — 命名 (C-CASE、C-CONV、C-GETTER)、相互運用特性 (C-COMMON-TRAITS、C-CONVERT、C-ITER、C-SERDE)、予測可能性 (C-INTUITIVE、C-CONST)、柔軟性 (C-GENERIC、C-NEWTYPE、C-EXT)、型安全性 (C-BOOL、C-NONZERO、 C-WRAPPER、C-STR）、信頼性（C-PANIC、C-UNWRAP）、デバッグ可能性（C-DEBUG）、将来性（C-SEALED、C-STRUCT-FIELD、C-NON-EXHAUSTIVE）。ユーザーがパブリック クレート API を設計する場合、ジェネリック/コンクリート/ニュータイプのいずれかを選択する場合、トレイト境界を決定する場合、実装を非表示にする場合、破損を回避する場合、または「慣用的な Rust API 設計とは何か」を尋ねる場合に使用します。 semver を渡してワークフローを Rust-semver に発行し、lint config を Rust-style-clippy に、クレート内のレイアウトを Rust-module-layout に渡します。
