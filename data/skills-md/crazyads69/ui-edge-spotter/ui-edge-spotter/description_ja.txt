レイアウト、状態、コンテンツ、インタラクションに関する「もしも」の質問をすることで、フロントエンド コードまたはチケットの説明で明らかになった UI/UX のエッジ ケースを特定します。開発者が評価できる問題を出力します。コードは生成されません。次の場合に使用します: UI コンポーネント コード (ドロップダウン、フォーム、モーダル、テーブル、入力、検索、ステッパー、OTP、ツールヒント、トグル) のレビュー、欠落しているエッジ ケースのチケットの確認、フロントエンド コード レビューの実行、または誰かが「どの UI の問題が欠けているのか」、「エッジ ケースを特定する」、「このコンポーネントを確認する」、「何が壊れる可能性があるか」、「何を忘れていたか」、「UI 監査」、「どのエッジ ケース」、または「QA チェック」を尋ねられた場合。ユーザーが対話型コンポーネントの React/Vue/Svelte/HTML/CSS/TypeScript コードを貼り付けたときにもトリガーされます。対象範囲: レイアウト オーバーフロー、空/読み込み/エラー状態、テキスト オーバーフロー、レスポンシブ、タッチ ターゲット、ドロップダウンの位置決め、フォーム検証、キーボード ナビゲーション、コンポーネント固有のエッジ ケース。
