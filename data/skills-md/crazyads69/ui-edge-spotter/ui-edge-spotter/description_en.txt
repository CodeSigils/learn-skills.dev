Spot uncovered UI/UX edge cases in frontend code or ticket descriptions by asking "what if" questions  about layout, states, content, and interactions. Outputs issues the dev can evaluate — does NOT generate code. Use when: reviewing UI component code (dropdown, form, modal, table, input, search, stepper, OTP, tooltip, toggle),  checking tickets for missing edge cases, doing frontend code review, or when someone asks  "what UI issues am I missing", "spot edge cases", "review this component", "what could break",  "what did I forget", "UI audit", "what edge cases", or "QA check". Also triggers when user pastes React/Vue/Svelte/HTML/CSS/TypeScript code for any interactive component. Covers: layout overflow, empty/loading/error states, text overflow, responsive, touch targets,  dropdown positioning, form validation, keyboard navigation, and component-specific edge cases.
