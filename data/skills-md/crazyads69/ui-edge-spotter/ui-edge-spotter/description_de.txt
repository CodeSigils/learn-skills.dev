Erkennen Sie aufgedeckte UI/UX-Edge-Fälle im Frontend-Code oder in Ticketbeschreibungen, indem Sie „Was wäre wenn“-Fragen zu Layout, Zuständen, Inhalten und Interaktionen stellen. Gibt Probleme aus, die der Entwickler auswerten kann – generiert KEINEN Code. Wird verwendet, wenn: Code von UI-Komponenten überprüft wird (Dropdown, Formular, Modal, Tabelle, Eingabe, Suche, Stepper, OTP, Tooltip, Umschalten), Tickets auf fehlende Randfälle prüfen, Frontend-Codeüberprüfung durchführen oder wenn jemand fragt: „Welche UI-Probleme fehlen mir“, „Randfälle erkennen“, „Diese Komponente überprüfen“, „Was könnte kaputt gehen“, „Was habe ich vergessen“, „UI-Audit“, „Welche Randfälle“ oder „QA-Prüfung“. Wird auch ausgelöst, wenn der Benutzer React/Vue/Svelte/HTML/CSS/TypeScript-Code für eine interaktive Komponente einfügt. Behandelt: Layoutüberlauf, Leer-/Lade-/Fehlerstatus, Textüberlauf, reaktionsfähig, Touch-Ziele, Dropdown-Positionierung, Formularvalidierung, Tastaturnavigation und komponentenspezifische Randfälle.
