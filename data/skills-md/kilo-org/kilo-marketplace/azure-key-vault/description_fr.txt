Conseils pour Azure Key Vault : stockage et gestion sécurisés des secrets, des clés et des certificats avec RBAC, isolation du réseau, accès aux identités gérées, protection contre la suppression/purge logicielle et rotation. Explique quand utiliser Key Vault standard par rapport au HSM géré (FIPS 140-3 niveau 3), le principe du rayon de souffle d'un coffre-fort par application et les références Key Vault dans App Service/Fonctions. QUAND : Azure Key Vault, stocker les secrets, gérer les certificats, les clés de chiffrement, la rotation des secrets, Key Vault RBAC, la protection contre la purge, la suppression réversible, le point de terminaison privé Key Vault, les secrets d'accès aux identités managées, le HSM managé, les références Key Vault, BYOK CMK. NE PAS UTILISER pour la conception d'une autorité de certification (utilisez pki-design), les informations d'identification de l'application entra uniquement (utilisez entra-id) ou la topologie de réseau PaaS (utilisez azure-network-security-design).
