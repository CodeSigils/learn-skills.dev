Leitfaden für Azure Key Vault – sicheres Speichern und Verwalten von Geheimnissen, Schlüsseln und Zertifikaten mit RBAC, Netzwerkisolation, verwaltetem Identitätszugriff, Soft-Delete-/Bereinigungsschutz und Rotation. Behandelt, wann Standard-Key Vault im Vergleich zu verwaltetem HSM (FIPS 140-3 Level 3), das Blast-Radius-Prinzip „Ein Tresor pro App“ und Key Vault-Referenzen in App Service/Funktionen zu verwenden sind. WANN: Azure Key Vault, Geheimnisse speichern, Zertifikate verwalten, Verschlüsselungsschlüssel, Geheimrotation, Key Vault RBAC, Löschschutz, vorläufiges Löschen, Key Vault für private Endpunkte, verwaltete Identitätszugriffsgeheimnisse, verwaltetes HSM, Key Vault-Referenzen, BYOK CMK. NICHT für den Entwurf einer Zertifizierungsstelle (verwenden Sie pki-design), nur für Entra-App-Anmeldeinformationen (verwenden Sie entra-id) oder für die PaaS-Netzwerktopologie (verwenden Sie azure-network-security-design) verwenden.
