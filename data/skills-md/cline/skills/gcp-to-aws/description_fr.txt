Migrez les charges de travail de Google Cloud Platform vers AWS, y compris les charges de travail d'IA et d'agent, quel que soit le fournisseur de cloud. Déclencheurs sur : migrer de GCP, GCP vers AWS, quitter Google Cloud, migrer Terraform vers AWS, migrer Cloud SQL vers RDS, migrer GKE vers EKS, migrer Cloud Run vers Fargate, migration Google Cloud, migrer d'OpenAI vers Bedrock, quitter OpenAI, passer de l'API ChatGPT vers AWS, migrer de Gemini vers Bedrock, migrer LangChain vers Bedrock, migrer LangGraph vers AWS, migrer les charges de travail agentiques vers AWS, déplacer les charges de travail d'IA vers AWS, migrer mon application d'IA vers AWS. Exécute un processus en 6 phases : découvrez les ressources GCP à partir des fichiers Terraform, du code d'application ou des exportations de facturation, clarifiez les exigences de migration, concevez l'architecture AWS, estimez les coûts, générez des artefacts de migration et collectez des commentaires facultatifs. Clarifier doit être terminé avant la conception, l'estimation ou la génération. Inclut des conseils de migration des fournisseurs d'IA (par exemple, OpenAI vers Amazon Bedrock) en sélectionnant les familles de modèles Bedrock les plus adaptées pour la modalité requise, les objectifs de latence/qualité, les fenêtres de contexte et les contraintes de coûts. Le mappage de modèles est guidé par la compatibilité et non par une parité 1:1 ; validez les invites, le comportement d’appel des outils et évaluez les métriques avant le basculement. Ne pas utiliser pour : les migrations Azure ou sur site vers AWS, la migration inverse d'AWS vers GCP, les conseils généraux sur l'architecture AWS sans intention de migration, la refactorisation de GCP vers GCP ou les déploiements multicloud qui n'impliquent pas de migration hors de GCP.
