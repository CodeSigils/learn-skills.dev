將工作負載從 Google Cloud Platform 遷移到 AWS，包括 AI 和代理工作負載，無論雲端供應商為何。觸發條件：從 GCP 遷移、GCP 遷移到 AWS、移出 Google Cloud、將 Terraform 遷移到 AWS、將 Cloud SQL 遷移到 RDS、將 GKE 遷移到 EKS、將 Cloud Run 遷移到 Fargate、Google Cloud 遷移、從 OpenAI 遷移到 Bedrock、移出 OpenAI、從 ChatGPT API 切換到 Google AWS、遷移將代理程式工作負載遷移到 AWS、將 AI 工作負載遷移到 AWS、將我的 AI 應用程式遷移到 AWS。運行 6 個階段的流程：從 Terraform 檔案、應用程式程式碼或計費匯出中發現 GCP 資源，闡明遷移要求，設計 AWS 架構，估算成本，產生遷移工件並收集可選回饋。澄清必須在設計、估算或生成之前完成。包括 AI 供應商遷移指南（例如，從 OpenAI 到 Amazon Bedrock），透過選擇最適合所需模式、延遲/品質目標、上下文視窗和成本限制的 Bedrock 模型系列來實現。模型映射以相容性為導向，而不是 1:1 奇偶校驗；在切換之前驗證提示、工具呼叫行為和評估指標。請勿用於：Azure 或本地遷移到 AWS、AWS 到 GCP 反向遷移、沒有遷移意圖的一般 AWS 架構建議、GCP 到 GCP 重構​​或不涉及從 GCP 遷移的多雲部署。
