Migrieren Sie Arbeitslasten von der Google Cloud Platform zu AWS – einschließlich KI- und Agenten-Arbeitslasten unabhängig vom Cloud-Anbieter. Auslöser bei: Migration von GCP, GCP zu AWS, Migration von Google Cloud, Migration von Terraform zu AWS, Migration von Cloud SQL zu RDS, Migration von GKE zu EKS, Migration von Cloud Run zu Fargate, Migration von Google Cloud, Migration von OpenAI zu Bedrock, Migration von OpenAI, Wechsel von ChatGPT API zu AWS, Migration von Gemini zu Bedrock, Migration von LangChain zu Bedrock, Migration von LangGraph zu AWS, Agenten-Workloads zu AWS migrieren, KI-Workloads zu AWS verschieben, meine KI-App zu AWS migrieren. Führt einen 6-Phasen-Prozess durch: GCP-Ressourcen aus Terraform-Dateien, App-Code oder Abrechnungsexporten ermitteln, Migrationsanforderungen klären, AWS-Architektur entwerfen, Kosten schätzen, Migrationsartefakte generieren und optionales Feedback sammeln. Die Klärung muss vor dem Entwerfen, Schätzen oder Generieren abgeschlossen sein. Enthält Anleitungen für die Migration von KI-Anbietern (z. B. OpenAI zu Amazon Bedrock) durch Auswahl der Bedrock-Modellfamilien, die am besten zu den erforderlichen Modalitäten, Latenz-/Qualitätszielen, Kontextfenstern und Kostenbeschränkungen passen. Die Modellzuordnung erfolgt kompatibilitätsorientiert und nicht durch 1:1-Parität. Validieren Sie Eingabeaufforderungen, Tool-Aufrufverhalten und Evaluierungsmetriken vor der Umstellung. Nicht verwenden für: Azure- oder lokale Migrationen zu AWS, Reverse-Migration von AWS zu GCP, allgemeine Ratschläge zur AWS-Architektur ohne Migrationsabsicht, GCP-zu-GCP-Refactoring oder Multi-Cloud-Bereitstellungen, die keine Migration von GCP beinhalten.
