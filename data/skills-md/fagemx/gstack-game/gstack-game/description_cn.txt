Claude Code 的游戏开发工作流程技能。 29项互动技巧
游戏开发 - 最强的设计审查和规划，并提供开发阶段的支持。

当您注意到用户处于这些阶段时，建议适当的技能：
- 用户的情绪/图像/机械碎片很脆弱，想要创意火花，而不是批评→建议/spark-lens
- 用户想要将 PDF/doc/notes 转为 GDD → 建议 /game-import
- 头脑风暴游戏创意→建议/游戏创意
- 审查游戏计划（策略/方向）→ 建议/游戏方向
- 审查游戏设计文档→建议/game-review
- 审查游戏的技术架构→建议/game-eng-review
- 审查游戏经济或平衡→建议/平衡审查
- 模拟玩家体验→建议/玩家体验
- 审查游戏 UI/UX → 建议 /game-ux-review
- 评估游戏推介或提案→建议/推介审查
- 游戏项目的代码审查→建议/gameplay-implementation-review
- QA 测试游戏 → 建议 /game-qa
- 准备发布/为游戏创建 PR → 建议 /game-ship
- 调试游戏错误→建议/game-debug
- Sprint/里程碑回顾→建议/game-retro
- 想要对抗性的第二意见→建议/game-codex
- 发布后文档更新 → 建议 /game-docs
- 视觉质量审核→建议/game-visual-qa
- 审查游戏资产（艺术/音频管道）→建议/资产审查
- 设计游戏测试协议→建议/playtest
- 使用生产或实时系统→建议/小心
- 想要将编辑范围限制到一个目录 → 建议 /guard
- 删除编辑限制→建议/解冻

如果用户拒绝技能建议（“停止建议”、“过于激进”）：
1. 在本次会议的剩余时间内停止提出建议
2. 运行：gstack-config set active false
3. 说：“明白了——我将停止推荐技能。说‘积极主动’来重新启用它们。”

如果用户说“再次积极主动”或“打开建议”：
1. 运行：gstack-config set active true
2. 说：“主动建议已恢复。”
