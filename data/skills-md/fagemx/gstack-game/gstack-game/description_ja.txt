Claude Code のゲーム開発ワークフロー スキル。 29 のインタラクティブなスキル
ゲーム開発向け — 設計レビューと計画において最も強力で、開発段階のサポートも提供します。

ユーザーが次の段階にあることに気付いたら、適切なスキルを提案します。
- ユーザーは壊れやすい気分/イメージ/メカニックの断片を持っており、批評ではなく創造的な閃きを望んでいます → /spark-lens を提案します
- ユーザーが GDD に変換したい PDF/doc/notes を持っている → /game-import を提案
- ゲームのアイデアのブレインストーミング → /game-ideation を提案
- ゲームプランの検討（戦略・方向性） → 提案 /game-direction
- ゲーム設計ドキュメントのレビュー → 提案 /game-review
- ゲームの技術アーキテクチャをレビューする → /game-eng-review を提案
- ゲームの経済性やバランスの見直し → 提案 /balance-review
- プレイヤーエクスペリエンスのシミュレーション→suggest /player- experience
- ゲームの UI/UX のレビュー → /game-ux-review を提案
- ゲームのピッチまたは提案を評価する → 提案/ピッチレビュー
- ゲームプロジェクトのコードレビュー → /gameplay-implementation-review を提案
- ゲームをテストする QA → /game-qa を提案
- ゲームの出荷準備 / PR の作成 → /game-ship を提案
- ゲームのバグをデバッグする → /game-debug を提案します
- スプリント/マイルストーンの振り返り → /game-retro を提案
- 敵対的なセカンドオピニオンが欲しい → /game-codex を提案
- リリース後のドキュメント更新 → /game-docs を提案
- ビジュアル品質監査 → /game-visual-qa を提案
- ゲームアセットのレビュー (アート/オーディオパイプライン) → 提案 /asset-review
- プレイテストプロトコルの設計 → /playtest を提案
- 運用システムまたはライブ システムでの作業 → 提案/注意
- 編集範囲を 1 つのディレクトリに設定したい → /guard を提案
- 編集制限の解除 → 提案/凍結解除

ユーザーがスキルの提案を拒否した場合 (「提案をやめる」、「攻撃的すぎる」):
1. このセッションの残りの部分では提案をやめる
2. 実行: gstack-config set professional false
3. 「わかりました。スキルの提案はやめます。スキルを有効にするには、『積極的になりましょう』と言ってください。」と言います。

ユーザーが「もう一度積極的になりましょう」または「提案をオンにしてください」と言った場合:
1. 次のコマンドを実行します: gstack-config set protection true
2.「プロアクティブな提案が再びオンになります。」と言います。
