Claude Code 的遊戲開發工作流程技能。 29項互動技巧
遊戲開發 - 最強的設計審查和規劃，並提供開發階段的支援。

當您注意到使用者處於這些階段時，建議適當的技能：
- 使用者的情緒/圖像/機械碎片很脆弱，想要創意火花，而不是批評→建議/spark-lens
- 使用者想要將 PDF/doc/notes 轉為 GDD → 建議 /game-import
- 腦力激盪遊戲創意→建議/遊戲創意
- 檢視遊戲計畫（策略/方向）→ 建議/遊戲方向
- 審查遊戲設計文件→建議/game-review
- 檢討遊戲的技術架構→建議/game-eng-review
- 審查遊戲經濟或平衡→建議/平衡審查
- 模擬玩家體驗→建議/玩家體驗
- 檢討遊戲 UI/UX → 建議 /game-ux-review
- 評估遊戲推廣或提案→建議/推廣審查
- 遊戲專案的程式碼審查→建議/gameplay-implementation-review
- QA 測試遊戲 → 建議 /game-qa
- 準備發布/為遊戲創建 PR → 建議 /game-ship
- 偵錯遊戲錯誤→建議/game-debug
- Sprint/里程碑回顧→建議/game-retro
- 想要對抗性的第二意見→建議/game-codex
- 發布後文件更新 → 建議 /game-docs
- 視覺品質審核→建議/game-visual-qa
- 審查遊戲資產（藝術/音訊管道）→建議/資產審查
- 設計遊戲測試協議→建議/playtest
- 使用生產或即時系統→建議/小心
- 想要將編輯範圍限製到目錄 → 建議 /guard
- 刪除編輯限制→建議/解凍

如果使用者拒絕技能建議（「停止建議」、「過於激進」）：
1. 在本次會議的剩餘時間內停止提出建議
2. 運行：gstack-config set active false
3. 說：“明白了——我將停止推薦技能。說‘積極主動’來重新啟用它們。”

如果用戶說「再次積極主動」或「開啟建議」：
1. 運行：gstack-config set active true
2. 說：“主動建議已恢復。”
