arkcli helper: configura l'agente AI locale (Claude Code / OpenCode / OpenClaw / Trae) nel piano Volcano Ark. La sua capacità principale è quella di inserire l'MCP integrato del piano agente nell'agente (ricerca Doubao mcp‑server‑askecho‑search‑infinity + dataPro‑search + OpenViking openviking‑dataplane + OpenViking control plane openviking‑controlplane). Quando l'utente dice "aggiungi (il mio) MCP / ricerca Doubao / ricerca online / dataPro / OpenViking all'agente corrente/specifico", "installa MCP in Claude Code/OpenCode/OpenClaw/Trae" o "imposta l'MCP del piano agente", utilizza `arkcli helper mcp` (inietta solo l'MCP, non cambia il modello). Inoltre sovrascrive `helper configure` (imposta anche modello/provider), `helper list` (controlla lo stato) e `helper reset` (rimuove injection). Trigger inversi: installazione delle competenze arkcli nell'agente → arkcli‑connect; login/401/autenticazione → arkcli‑auth; generare immagine/video → arkcli‑gen. Nota: l'iniezione MCP è supportata solo dal piano agente (è possibile configurare sia il piano agente personale che il piano agente personale) ma i due componenti OpenViking (piano dati/piano di controllo) sono disponibili solo per il piano agente personale: il piano agente personale non ha nulla a che fare con OpenViking e può essere configurato solo con Doubao search + dataPro; può essere applicato solo a claude‑code, opencode, openclaw o trae (Trae è un IDE, inserisce solo MCP, non imposta un modello e supporta `--scope project` per scrivere un ./.trae/mcp.json a livello di progetto). Esiste anche `arkcli helper supabase`: **non è un MCP**, ma installa byted‑supabase‑cli + skill e inserisce lo stato di accesso di Volcano per abilitare le funzionalità del database byted‑supabase (solo per il piano agente: personale grande/max + team a livello completo; personale piccolo/medio non è supportato). Quando l'utente dice "configura byted‑supabase / collega il database / installa supabase cli / collega supabase", usa questo.
