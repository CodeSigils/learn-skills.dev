arkcli doctor est le point d'entrée global pour les diagnostics (une compétence consolide quatre domaines : codes d'erreur / infer-endpoint / model / metrics) : il regroupe les erreurs, l'état des ressources, les quotas d'utilisation et les métriques de performances rencontrés lors de l'utilisation de Volcano Ark (Ark) dans la famille de commandes `arkcli doctor` (CLI health / account / infer-endpoint / model / metrics / error codes). Lorsqu'un utilisateur/agent obtient un code d'erreur Ark (ModelAccessDenied / InvalidParameter / RateLimitExceeded / ContentRiskBlocked / OutputVideoSensitiveContentDetected, etc.), ou obtient une erreur Ark JSON, un ID de point de terminaison ep-xxx ou un nom de modèle, et demande « pourquoi l'erreur / comment la corriger / quel est l'état / quelle est l'utilisation / la pression du quota / est-il gelé / les autorisations sont-elles suffisantes / le point de terminaison est lent / en panne / comment le modèle est-il dans son ensemble / quel point de terminaison a consommé le quota du modèle / comment corriger l'interception vidéo en direct / RPM / taux d'erreur / latence P99 / taux de réussite du cache », ceci est utilisé ; lorsque l'utilisateur dit « médecin arkcli / diagnostiquer / bilan de santé / dépannage / auto-réparation / consulter les métriques / extraire les données de surveillance », cela apparaît également ici. **Le nom du modèle + la sémantique des exceptions/du contrôle de santé ont également leur place ici** : lorsque l'utilisateur dit : "J'utilise <modèle> constamment/souvent/récemment en échec / lent / délai d'attente / limité / erreur", "<modèle> a un taux d'échec élevé / un lot de requêtes échouent pour la plupart / qu'est-ce qui ne va pas avec ce modèle / peut-il toujours être utilisé / est-il limité / le quota est-il suffisant", "vérifier <modèle> / diagnostiquer <modèle> / contrôle de santé <modèle> / est <modèle> sain / qu'est-ce qui est la situation globale de <model> », la commande correspondante « arkcli doctor model <name> » est exécutée (même si l'utilisateur n'épelle pas de code d'erreur, les échecs statistiques croisés / les anomalies sensorielles persistantes / la perspective de quota / les verbes de diagnostic explicites vont tous ici, et ne doivent pas être acheminés vers arkcli-gen par des mots-clés comme « générer une vidéo/seedance/seedream »). Les codes d’erreur d’interception vidéo en direct (Entrée/Sortie…SensitiveContentDetected / PrivacyInformation / PolicyViolation) continuent d’être traités dans les références de cette compétence. Remarque : les problèmes d'installation/de connexion/de profil/d'authentification purement arkcli appartiennent à arkcli‑shared / arkcli‑auth ; cette compétence ne gère que la famille de commandes « arkcli doctor ».
