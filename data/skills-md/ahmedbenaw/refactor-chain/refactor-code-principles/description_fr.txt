Utilisez cette compétence lorsque le code de travail a besoin d'améliorer sa structure sans changer ce qu'il fait - les phrases de déclenchement incluent "refactoriser ceci", "nettoyer ceci", "appliquer SOLID", "découpler ces modules", "diviser cette classe divine", "démêler ce fichier", "introduire l'injection de dépendances", "réorganiser les couches". Il s'agit du moteur structurel axé sur les principes du pipeline de chaîne de refactorisation : il détecte la pile, extrait l'ensemble des principes de génie logiciel recommandés du registre, ouvre LA FENÊTRE DE DÉCISION (un point de contrôle en cours de discussion où l'utilisateur accepte la recommandation, mélange et associe, ou choisit délibérément une combinaison non conventionnelle avec des risques clairement énoncés), puis applique les principes choisis via la boucle point de contrôle → appliquer → vérifier. Il s’exécute également par défaut comme étape de consolidation finale de chaque voie. Contrat dur - il restructure le code WORKING avec un comportement resté identique ; il ne s'agit PAS d'ajouter des fonctionnalités, de corriger des bugs ou d'écrire des suites de tests.
