Utilice esta habilidad cuando la memoria sigue aumentando con el tiempo o a través de acciones repetidas y el usuario quiere que se encuentre y solucione la fuga: desencadenantes simples como "la memoria de la aplicación sigue creciendo", "expone OOM después de un tiempo", "la pestaña se vuelve más lenta cuanto más la uso", "hay una pérdida de memoria", "el montón sigue subiendo", "nodos DOM separados", "el proceso RSS crece y nunca regresa". Diagnostica fugas tomando instantáneas del montón antes y después de una acción repetida, diferenciándolas de los objetos que deberían haberse liberado pero no lo fueron, y siguiendo el crecimiento del tamaño retenido hasta la referencia que los fija en la memoria. Funciona tanto para el navegador (montón de DevTools) como para Node.js. Es el paso de hacer el trabajo del carril DEBUG de la cadena de refactorización, que se alcanza cuando el arnés clasifica un caso como depuración/memoria de código. Utiliza una herramienta de almacenamiento dinámico de navegador/DevTools cuando esté disponible; de lo contrario, las API de instantáneas del montón de Node.
