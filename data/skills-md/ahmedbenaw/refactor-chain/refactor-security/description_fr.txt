Utilisez cette compétence lorsque le refactor est terminé et que vous avez besoin d'un audit de sécurité statique du diff avant son expédition - lecture du code modifié (sans l'exécuter ni l'attaquer) pour injection, authentification/session interrompue, secrets ou informations d'identification commises dans le code, crypto faible, fuites de PII/données, désérialisation non sécurisée et erreurs SSRF/CORS/CSP. Les phrases de déclenchement incluent « examen de sécurité », « l'expédition est-elle sûre », « vérifier les vulnérabilités », « auditer cette modification », « avons-nous divulgué un secret », « vérification OWASP ». Il s'agit de la porte de phase sécurisée du pipeline de chaîne de refactorisation ; il s'exécute après avoir effectué le travail et parallèlement/juste avant la révision. Il est consultatif : il rapporte les résultats classés et ne modifie jamais le code de lui-même.
