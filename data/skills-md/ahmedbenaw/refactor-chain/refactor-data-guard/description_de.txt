Verwenden Sie diese Fähigkeit, wenn ein Refactoring-Schritt die Datenbank berührt – Schema, Migrationen, Seeds, Fixtures, ORM-Modelle oder Datenzugriffscode. Es führt Datensicherheitsprüfungen (Zeilenanzahl, Schemaform, referenzielle Integrität) als EXTRA-Verifizierungszusicherung während der Verifizierungsphase durch, sodass ein Refactor niemals stillschweigend Daten verändern, löschen oder beschädigen kann, während behauptet wird, dass das Verhalten erhalten bleibt. Es ist BEDINGT: Es wird nur aktiviert, wenn der Gurt oder die aktuelle Stufe eine Berührung auf der Datenebene meldet; Bei einem reinen Code-/UI-Refactor bleibt es inaktiv. Auslösersätze: „Wir haben eine Migration geändert“, „Dies berührt das Schema“, „Hat der Refaktor die Daten durcheinander gebracht“, „Stellen Sie sicher, dass die Tabellen immer noch übereinstimmen“, „Eine Spalte umbenannt“.
