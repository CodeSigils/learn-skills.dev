Utilisez cette compétence lorsqu'une étape de refactorisation touche la base de données : schéma, migrations, graines, appareils, modèles ORM ou code d'accès aux données. Il exécute des contrôles de sécurité des données (nombre de lignes, forme du schéma, intégrité référentielle) en tant qu'assertion de vérification EXTRA pendant la phase de vérification, de sorte qu'un refactor ne peut jamais muter, supprimer ou corrompre silencieusement des données tout en affirmant que le comportement a été préservé. Il est CONDITIONNEL : il s'active uniquement lorsque le harnais ou l'étape en cours signale un contact avec la couche de données ; sur un refactor pur code/interface utilisateur, il reste en sommeil. Phrases déclencheurs : "nous avons modifié une migration", "cela touche le schéma", "le refactor a-t-il modifié les données", "assurez-vous que les tables correspondent toujours", "renommé une colonne".
