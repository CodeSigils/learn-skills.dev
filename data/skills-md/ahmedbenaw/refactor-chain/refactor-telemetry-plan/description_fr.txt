Utilisez cette compétence lorsqu'un refactor touche des flux orientés vers l'utilisateur ou suivis et pourrait interrompre silencieusement les analyses : noms d'événements renommés, appels de suivi déplacés ou supprimés, noms de composants/routes modifiés dont dépendent les propriétés d'événement ou instrumentation déplacée. Il signale les analyses susceptibles de tomber en panne et propose un plan de suivi mis à jour pour les flux modifiés afin que les tableaux de bord, les entonnoirs et les expériences ne s'éteignent pas silencieusement après le refactor. Il est CONDITIONNEL : il s'active uniquement lorsque des flux suivis/visés à l'utilisateur sont détectés dans le diff (appels du SDK d'analyse, noms d'événements, changements d'itinéraire/d'écran) ; sur un refactor purement interne, il reste dormant. Phrases déclencheurs : « avons-nous cassé nos analyses », « l'entonnoir fonctionnera-t-il toujours », « vérifier le suivi », « nous avons renommé l'événement », « le tableau de bord est passé à zéro après le refactor », « mettre à jour le plan de suivi ». Il s'agit d'une compétence conditionnelle de la phase de documentation dans le pipeline de la chaîne de refactorisation. Consultatif — il propose ; il ne recâble pas le suivi tout seul.
