Utilisez cette compétence lorsque refactor-chain a besoin de savoir « quelles sont les propres règles de ce projet ? — les conventions structurelles que le code suit déjà (injection de dépendances requise, conventions de dénomination, limites de module/paquet, règles de superposition comme contrôleur → service → référentiel, pas de dépôt circulaire). Il extrait ces règles dans un manifeste de règles, puis les applique à la fois avant un changement (ligne de base) et après (vérification de dérive), de sorte qu'une étape de modernisation ne puisse jamais violer discrètement la propre architecture du projet. Il s'agit du garde-corps de diagnostic/exécution du pipeline du pipeline de refactorisation. Les phrases de déclenchement incluent « extraire les règles du projet », « quelles conventions ce dépôt suit-il », « s'assurer que le refactor respecte notre architecture », « avons-nous enfreint une règle de couche », « appliquer les limites de DI/dénomination/module », « vérifier une violation de superposition ». Indépendant des pensions ; en lecture seule lors de l'extraction, consultatif lorsqu'il signale une violation.
