Utilisez cette compétence à la fin d'un refactor pour synchroniser la documentation durable du projet avec le code qui vient de changer : les quatre artefacts permanents architecture.md, flow.md, permissions.md et tests-map.md. Parce qu'un refactor déplace, renomme et recouche le code, ces documents deviennent obsolètes en silence ; cette compétence compare chaque artefact à la nouvelle réalité et met à jour uniquement ce qui a dérivé. Phrases de déclenchement : "mettre à jour la documentation pour qu'elle corresponde", "la documentation d'architecture est désormais obsolète", "synchroniser la documentation", "régénérer la carte des flux/autorisations", "garder la documentation à jour après le refactor". Il s'agit de la phase de documentation du pipeline de refactor-chain ; il s'exécute après la rédaction du refactor et avant l'expédition. Il édite uniquement les fichiers de documentation, jamais le code produit.
