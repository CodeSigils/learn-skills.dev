Utilice esta habilidad cuando una interfaz de usuario web esté llena de primitivos hechos a mano y personalizados (marcado <botón> personalizado, menús desplegables basados ​​en div, modales ad-hoc, entradas/pestañas/diálogos caseros) y el usuario quiera "adoptar shadcn/ui", "usar una biblioteca de componentes real", "reemplazar nuestros componentes personalizados con un registro", "dejar de reinventar botones" o "estandarizar nuestros componentes de interfaz de usuario". Intercambia primitivas personalizadas por componentes de registro (shadcn/ui primero), conecta su tema a los tokens de diseño del proyecto y mantiene el comportamiento idéntico. Este es un paso de hacer el trabajo del carril de la interfaz de usuario en el proceso de la cadena de refactorización; se ejecuta después de refactor-ui-tokens (y después del pase visual/móvil) y antes de refactor-ui-a11y. Puede utilizar shadcn MCP cuando esté disponible. Refactorización de presentación y estructura: mismo comportamiento, componentes estandarizados.
