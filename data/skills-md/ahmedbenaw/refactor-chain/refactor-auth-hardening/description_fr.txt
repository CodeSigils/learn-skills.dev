Utilisez cette compétence UNIQUEMENT lorsqu'un projet dispose déjà d'un code d'authentification et que vous souhaitez renforcer l'authentification EXISTANTE avec des modèles plus sûrs : meilleure authentification, Auth0/@auth0, authentification suivante, passeport ou code brut oauth/jwt/session/login détecté dans le dépôt. Il refactorise ce qui existe déjà vers les meilleures pratiques (gestion sécurisée des sessions, stockage sécurisé des jetons, OAuth PKCE, cookies sécurisés/HttpOnly/SameSite, trousseau/keystore mobile, écrans de connexion hébergés de style ACUL) tout en PRÉSERVANT le comportement — les utilisateurs se connectent de la même manière, mais avec plus de sécurité. Il n’ajoute JAMAIS un tout nouveau système d’authentification là où il n’en existe pas. Phrases de déclenchement : "renforcer notre authentification", "notre connexion est-elle sécurisée", "corriger notre gestion de session/cookie", "déplacer les jetons hors de localStorage", "ajouter PKCE", "notre gestion JWT semble incorrecte". Il s’agit de l’étape conditionnelle de phase sécurisée du pipeline de chaîne de refactorisation ; il s'active uniquement lorsque le code d'authentification est présent et reste inactif sinon.
