Utilisez cette compétence lorsque, après la restructuration en couches, les noms de module ne disent plus ce que font les modules et que l'utilisateur demande des changements de nom sémantiques — les phrases de déclenchement incluent « renommer le module », « renommer les modules pour qu'ils correspondent à leur rôle », « renommer le serveur en contrôleur », « transmettre le nom aux modules » ou « peaufiner l'architecture ». Il renomme les modules selon un mappage choisi par le projet (exemple de convention `{module}-server` → `{module}-controller`, `{module}-server-com` → `{module}-service`) et propage le changement via les répertoires, les identifiants d'artefacts, les listes de modules de conteneur, dependencyManagement, chaque référence de dépendance et les lignes de package/importation Java. Étape 2 sur 9 de la voie de gouvernance back-end en couches dans le bundle refactor-chain ; fonctionne sur n'importe quel projet backend en couches (système de construction détecté à partir du registre) ; idempotent — les modules déjà renommés sont ignorés.
