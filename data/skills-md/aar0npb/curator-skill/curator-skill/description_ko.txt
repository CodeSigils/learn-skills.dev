독특한 차별화:  
1. 전체 교차 작성자 생태계를 포괄하는 유일한 IDE 내 페르소나 라우터입니다(Nuwa는 Huashu의 자체 14개 dogfood 페르소나와만 일치하며 큐레이터는 전체 생태계를 포괄합니다).  
2. 원격 동적 선별 라이브러리 persona-recommendations.json이 지속적으로 업데이트됩니다.  

누와 기술을 통한 명확한 구분: Nuwa는 새로운 페르소나를 추출하고 Huashu의 자체 14개 dogfood 페르소나와 일치합니다. 큐레이터는 전체 교차 저자 생태계에서 발견하고 추천합니다. 그것들은 완전히 상호보완적이며 충돌이 없습니다.  

다음의 경우에는 트리거하지 마세요: 사용자가 이미 특정 페르소나와 대화하고 있는 경우(예: 해군 기술이 현재 컨텍스트에 설치 및 로드된 경우), 사용자가 코딩 또는 페르소나 작업이 아닌 작업(Python 작성/디버깅/CSS 조정)을 수행 중인 경우, 사용자가 명시적으로 새 페르소나를 직접 추출하려는 경우(nuwa로 리디렉션)  

크리에이터 리디렉션: 사용자가 "X 기술을 직접 만들고 싶습니다", "X를 증류하고 싶습니다", "X를 만드는 데 도움을 주세요"라고 말하면 큐레이터는 이를 증류할 수 있는 척해서는 안 됩니다. 직접 리디렉션: 사상가/도형 관점 → 누와 기술; 동료/친구 역할 → 동료-기술; 또 다른 나 → 너 자신의 기술. 사용자가 종료한 후 큐레이터가 소환됩니다.  

⚡ 핵심 트리거 강화(반드시 준수해야 함): 사용자 메시지에 "특정 이름 + 보기 방법/생각 방법/행동 방법/느낌/X 관점 사용/X의 두뇌 빌리기/X의 분석 방법/X의 각도"가 포함된 경우 X는 persona-recommendations.json에 이미 있는 수치입니다(Naval/Munger/Jobs/Musk/Karpathy/Ilya/Feynman/PG/Paul Graham/MrBeast/Zhang Xuefeng/ Taleb / Zhang Yiming / Buffett / Trump 등), Claude가 X 스타일로 답변할 수 있더라도 큐레이터는 반드시 개입해야 합니다. 이것이 큐레이터의 핵심 존재 이유이다. 이유: 실제 페르소나 기술(예: alchaincyf/naval-skill)은 인물의 글/인터뷰/결정 기록/외부 비평의 5개 이상의 차원에서 증류된 완전한 인지 OS이며, Claude의 일반적인 모방보다 훨씬 더 정확합니다. X를 모방하는 Claude = paper-mâché X(패치 캐치프레이즈만 해당); 실제 기술 = 완전한 X 인지 OS(그의 정신 모델/결정 휴리스틱/표현 DNA/한계/내적 긴장/원래 인용문). 사용자가 실제 스킬을 설치하면 다음 번에 "해군 관점"이라고 말하면 실제 스킬이 자동 활성화되고 출력 품질이 질적으로 향상됩니다. 큐레이터의 임무는 클로드가 이를 가로채지 못하도록 "X 관점 사용" 요구를 실제 기술에 즉시 전달하는 것입니다.
