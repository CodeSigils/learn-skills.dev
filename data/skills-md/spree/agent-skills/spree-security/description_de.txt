Wird verwendet, wenn der Benutzer eine Spree-App härtet, auf einen Sicherheitsbefund reagiert, einen PR auf Sicherheitsprobleme überprüft, die Geheimnisverwaltung einrichtet, CSP/CORS konfiguriert oder nach Spree-spezifischer Sicherheit fragt (CanCanCan-Bereiche, verschlüsselte Einstellungen, Webhook-HMAC, PCI-Bereich). Deckt sowohl Standard-Rails-Sicherheitspraktiken (CSRF, Massenzuweisung, SQL-Injection, Geheimnisse im Repo) als auch die Spree-spezifischen Teile (veröffentlichbare vs. geheime Schlüssel, Durchsetzung des Bereichs, SSRF auf Webhooks, CanCanCan-Fähigkeiten) ab. Zu den gebräuchlichen Formulierungen gehören „Spree-Sicherheit“, „CSP“, „CORS“, „geheimer Schlüssel“, „durchgesickerter Schlüssel“, „SQL-Injection“, „Strong Params“, „CanCanCan“, „PCI“, „Webhook-Signatur“, „SSRF“.
