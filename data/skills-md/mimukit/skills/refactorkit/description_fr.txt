Examinez une base de code existante pour le changement structurel qui mérite d'être apporté (interfaces superficielles, prolifération des adaptateurs, mauvaise localité, couplage non testé) - classez les candidats, couronnez-en un et rédigez-le sous forme de proposition révisable. À utiliser lorsque l'utilisateur demande "où dois-je refactoriser", "qu'est-ce qui ne va pas avec la structure de cette base de code", "trouver des opportunités de refactoring", "ce code est difficile à modifier", "améliorer notre architecture", "auditer les limites du module" ou "/refactorkit". Il propose et n'édite jamais de code.
