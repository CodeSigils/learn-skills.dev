Examine una base de código existente para detectar el cambio estructural que vale la pena realizar (interfaces poco profundas, dispersión de adaptadores, localidad deficiente, acoplamiento no probado), clasifique a los candidatos, corone a uno y escríbalo como una propuesta revisable. Úselo cuando el usuario diga "¿dónde debería refactorizar?", "qué hay de malo en la estructura de esta base de código", "encontrar oportunidades de refactorización", "este código es difícil de cambiar", "mejorar nuestra arquitectura", "auditar los límites del módulo" o "/refactorkit". Propone y nunca edita código.
