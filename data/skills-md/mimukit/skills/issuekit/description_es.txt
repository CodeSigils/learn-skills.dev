Sea dueño del ciclo de vida del problema de GitHub con cinco modos: cree problemas a partir de un plan-<slug>-AAAA-MM-DD.md o una descripción (se mantiene independiente para el trabajo paralelo de git-worktree, con cualquier requisito previo etiquetado como "bloqueado"), inicie un problema "listo" en su propio árbol de trabajo, cierre uno una vez que su PR se fusione (cierre el problema, desbloquee los dependientes, elimine el árbol de trabajo), sincronice los enlaces de PR↔emitir después de la fusión y clasifique el rastreador. Úselo cuando el usuario diga "crear problemas a partir de este plan", "presentar un problema", "iniciar el problema n.° 42", "comenzar a trabajar en el n.° 42", "cerrar el n.° 42", "cerrar el n.° 42", "concluir el n.° 42 ahora que el RP se fusionó", "sincronizar mis problemas", "cerrar el problema que solucionó este RP", "clasificar el trabajo pendiente", "kit de problemas" o quiere que los problemas se abran, inicien, concilien o revisen con la CLI de gh.
