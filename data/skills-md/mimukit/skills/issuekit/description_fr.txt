Posséder le cycle de vie des problèmes GitHub avec cinq modes : créer des problèmes à partir d'un plan-<slug>-YYYY-MM-DD.md ou d'une description (gardé indépendant pour le travail parallèle de git-worktree, avec toute condition préalable étiquetée "bloqué"), démarrer un problème "prêt" dans son propre arbre de travail, en fermer un une fois son PR fusionné (fermer le problème, débloquer les dépendances, détruire l'arbre de travail), synchroniser les liens PR↔issue après la fusion et trier le traqueur. À utiliser lorsque l'utilisateur dit « créer des problèmes à partir de ce plan », « déposer un problème », « démarrer le problème n°42 », « commencer à travailler n°42 », « fermer le n°42 », « clôturer le n°42 », « conclure le n°42 maintenant le PR fusionné », « synchroniser mes problèmes », « fermer le problème résolu par ce PR », « trier le retard », « issuekit » ou souhaite que les problèmes soient ouverts, démarrés, atterris, réconciliés ou examinés avec la CLI gh.
