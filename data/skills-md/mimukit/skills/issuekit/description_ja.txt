5 つのモードで GitHub 課題のライフサイクルを所有します。 plan-<slug>-YYYY-MM-DD.md または説明から課題を作成し (前提条件に「blocked」というラベルが付いて、並列 git ワークツリー作業用に独立しておきます)、独自のワークツリーに「準備完了」課題を開始し、PR がマージされたら 1 つを閉じます (課題を閉じ、依存関係のブロックを解除し、ワークツリーを破棄します)。その後 PR ↔ 課題リンクを同期します。トラッカーをマージし、優先順位を付けます。ユーザーが「このプランから課題を作成する」、「課題を提出する」、「課題 #42 を開始する」、「作業を開始する #42」、「クローズ #42」、「#42 をクローズする」、「PR がマージされたので #42 をまとめる」、「課題を同期する」、「この PR が修正した課題をクローズする」、「バックログのトリアージ」、「課題キット」を指示する場合、または gh CLI で課題のオープン、開始、着陸、調整、またはレビューを行う場合に使用します。
