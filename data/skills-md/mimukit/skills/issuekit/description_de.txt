Besitzen Sie den GitHub-Issue-Lebenszyklus mit fünf Modi: Erstellen Sie Issues aus einem Plan-<slug>-JJJJ-MM-TT.md oder einer Beschreibung (unabhängig gehalten für parallele Git-Worktree-Arbeit, wobei alle Voraussetzungen als „blockiert“ gekennzeichnet sind), starten Sie ein „bereites“ Issue in seinem eigenen Arbeitsbaum, schließen Sie eines, sobald sein PR zusammengeführt wird (schließen Sie das Issue, entsperren Sie abhängige Elemente, entfernen Sie den Worktree), synchronisieren Sie PR↔Issue-Links nach der Zusammenführung und selektieren Sie den Tracker. Wird verwendet, wenn der Benutzer sagt: „Probleme aus diesem Plan erstellen“, „Problem einreichen“, „Problem Nr. 42 starten“, „Arbeiten Nr. 42 beginnen“, „Nr. 42 schließen“, „Nr. 42 abschließen“, „Nr. 42 jetzt abschließen, nachdem die PR zusammengeführt wurde“, „Meine Probleme synchronisieren“, „Das von dieser PR behobene Problem schließen“, „Rückstand prüfen“, „Issuekit“ oder möchte, dass Probleme mit der gh-CLI geöffnet, gestartet, gelandet, abgeglichen oder überprüft werden.
