Schneiden Sie eine Veröffentlichung aus den konventionellen Commits, die ein Repo bereits schreibt: Leiten Sie den Semver-Bump und ein Changelog aus dem Commit-Bereich ab, stoßen Sie das Manifest an, taggen Sie es und veröffentlichen Sie eine GitHub-Veröffentlichung, alles hinter einer obligatorischen Vorschau. Wird verwendet, wenn der Benutzer „ein Release ausschneiden“, „eine Version markieren“, „dieses veröffentlichen“, „was ist die nächste Version“, „ein Änderungsprotokoll erstellen“, „v2 versenden“ oder „/releasekit“ sagt. Es veröffentlicht niemals in einer Paketregistrierung und verschiebt niemals ein veröffentlichtes Tag.
