Use it before adding dependencies, hand‑crafting generic components or utility functions, and before adding, modifying, or deleting any tests—including tests you personally want to add. The default answer is to reuse rather than create, and to omit a test rather than add one. It covers a five‑level decision ladder that prioritizes reuse, four scenarios where writing tests is worthwhile, thirteen test patterns that must be avoided, and what counts as verification when you don’t write tests. It applies to any repository.
