Führen Sie ein strukturiertes, auf den geschäftlichen Nutzen ausgerichtetes Produktplanungsgespräch durch, das aus einer unscharfen Idee eine baufertige Spezifikation macht – BEVOR Code geschrieben wird. Verwenden Sie dies in dem Moment, in dem jemand noch darüber nachdenkt, WAS er erstellen soll, und Dinge sagt wie „Ich habe eine Idee für eine App, helfen Sie mir, sie durchzudenken“, „Hilf mir bei der Planung/Umfang/Gestaltung meines Produkts“, „Wo fange ich an?“, „Lassen Sie uns das spezifizieren, bevor ich Code schreibe“ oder „Machen Sie daraus eine PRD.“ Deckt jede neue App, Website, SaaS, MVP, Marktplatz oder Funktion ab. Auslöser ist allein die Planungsabsicht – der Benutzer muss Strapi, ein CMS oder eine andere Technologie NICHT erwähnen; Standardmäßig wird ein Strapi v5 + Strapi Cloud-Backend (überschreibbar, mit Ihrer Wahl von Frontend und Authentifizierung) vorausgesetzt. Es ermittelt Wert, Benutzer und Anforderungen vor jeder technischen Entscheidung und erstellt dann sechs Markdown-Dateien, die in einer Build-Spezifikation enden, die Sie jedem Programmieragenten (Claude Code, Cursor usw.) übergeben können. NICHT verwenden, sobald eine Spezifikation oder ein Projekt vorhanden ist und der Benutzer ein Gerüst erstellen, konfigurieren, migrieren, Seiten hinzufügen, Authentifizierung verkabeln oder debuggen möchte – das sind Build-Aufgaben, keine Planung in der Ideenphase.
