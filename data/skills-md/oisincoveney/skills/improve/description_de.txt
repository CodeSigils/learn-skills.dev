Verwenden Sie ihn, wenn Code schwer zu navigieren, zu ändern oder zu testen ist – um „vertiefende“ Refaktoren zu finden und vorzuschlagen, die flache Module in tiefe Module hinter sauberen Nähten verwandeln. Verwenden Sie diese Funktion, wenn Sie planen, wo die Grenzen eines neuen Features liegen sollen, wenn bei der Diagnose keine gute Testnaht festgestellt wird oder wenn das Verständnis eines Konzepts Sie dazu zwingt, über viele Dateien hinweg zu springen. Triggern Sie auf „Architektur verbessern“, „Das ist schwer zu ändern“, „Wo soll das leben“, „Struktur umgestalten“, „Kopplung reduzieren“.
