Betten Sie Screenshots, Bilder, Diagramme, GIFs und Bildschirmaufzeichnungen in GitHub-PRs und -Ausgaben ein – oder stellen Sie sie vor einer PR bereit, sammeln Sie sie in einem Anhangskommentar oder erhalten Sie einen dauerhaften öffentlichen Link, um ein Bild mit einer Person zu teilen. Verwenden Sie dies immer dann, wenn ein Bild in einer PR-Beschreibung, einem Issue-Text oder einem PR-/Issue-Kommentar vor einem Teamkollegen landen oder für eine PR gespeichert werden muss, die noch nicht existiert. Zu den Auslösern gehören „Screenshot an den PR anhängen“, „Vorher/Nachher zum Issue hinzufügen“, „einen Screenshot von … hinzufügen“, „ein GIF des Flows teilen“, „den Fehler aufzeichnen und in den Issue einfügen“, „mir einen Link besorgen, den ich in Slack einfügen kann“, „Screenshots für den PR inszenieren“, „dies anhängen, wenn ich den PR öffne“, „das für den PR speichern“, „die Medien des PR sammeln“ oder gerade etwas Visuelles aufgenommen oder geändert haben, das eine Aufnahme klarer machen würde – sogar mitten in der Aufgabe, bevor ein PR existiert. Gilt auch, wenn ein Agent kein lokales Dateisystem hat und über den gehosteten MCP (agents.uploads.sh) hochlädt. Greifen Sie dazu zu, anstatt Drag-and-Drop oder manuelle Uploads in den Cloud-Speicher durchzuführen. GitHub CLI 2.99+ kann ein einzelnes Bild an eine vorhandene PR oder ein Problem mit „gh … --attach“ anhängen; Diese Fähigkeit sagt, wann das ausreicht und wann nicht. Erfassen Sie das Bild mit jedem Browser oder Screenshot-Tool, über das Sie verfügen. Diese Fähigkeit umfasst das Hosten und Einbetten.
