Intégrez des captures d'écran, des images, des diagrammes, des GIF et des enregistrements d'écran dans les PR et les problèmes GitHub – ou organisez-les avant un PR, rassemblez-les dans un commentaire en pièce jointe ou obtenez un lien public durable pour partager un visuel avec une personne. Utilisez-le chaque fois qu'un visuel doit se retrouver dans une description de PR, un corps de problème ou un commentaire de PR/problème, devant un coéquipier, ou enregistré pour un PR qui n'existe pas encore. Les déclencheurs incluent « joindre une capture d'écran au PR », « ajouter un avant/après au problème », « inclure une capture d'écran de… », « partager un GIF du flux », « enregistrer le bug et le mettre dans le problème », « obtenez-moi un lien que je peux coller dans Slack », « captures d'écran de scène pour le PR », « joindre ceci lorsque j'ouvre le PR », « enregistrer ceci pour le PR », « collecter les médias du PR », ou avoir juste capturé ou modifié quelque chose de visuel qu'une photo rendrait plus clair - même à mi-tâche, avant qu'un PR n'existe. S'applique également lorsqu'un agent ne dispose pas de système de fichiers local et télécharge via le MCP hébergé (agents.uploads.sh). Atteignez-le au lieu des téléchargements de stockage dans le cloud par glisser-déposer ou par roulement manuel. GitHub CLI 2.99+ peut attacher une seule image à un PR existant ou problème avec `gh… --attach` ; cette compétence indique quand cela est suffisant et quand ce n'est pas suffisant. Capturez le visuel avec le navigateur ou l'outil de capture d'écran dont vous disposez ; cette compétence couvre son hébergement et son intégration.
