Examinez les modifications de code selon deux modes : examen de la branche locale (comparez la branche actuelle avec une branche de base) ou examen PR (examen d'une demande d'extraction ouverte sur GitHub). Par défaut, effectue une révision en solo couvrant tous les domaines prioritaires. Avec `--team`, génère une équipe spécialisée de 8 agents réviseurs couvrant la qualité du code, la sécurité, les performances, les meilleures pratiques, les tests et la documentation. En mode PR, crée une liste d'exclusion à partir des avis existants, génère éventuellement un 9ème agent de conformité des tickets si un ticket Jira est référencé et publie les résultats en tant que commentaires d'avis en attente (ne soumet jamais l'avis – le développeur le soumet manuellement). Utilisez `--headless` pour une exécution entièrement autonome où un agent challenger valide les résultats au lieu de demander au développeur.
