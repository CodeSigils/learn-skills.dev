À utiliser lorsque le travail doit être suivi et exécuté via les problèmes GitHub au lieu des fichiers de tâches du référentiel local. Aide les agents à adopter les modèles de problèmes, les étiquettes et les conventions de projet existants d'un référentiel lorsqu'ils sont présents, ou à revenir à un flux de travail de départ et d'exécution portable lorsqu'ils sont manquants.
