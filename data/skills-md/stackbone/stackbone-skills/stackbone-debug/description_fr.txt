Utilisez cette compétence lors du tri d'une erreur, d'une panne ou d'un comportement inattendu dans un espace de travail Stackbone : un agent approfondi ou un workflow durable s'exécutant localement sous "stackbone dev", ou une installation déployée sur un cloud/auto-hébergeur. Couvre les erreurs du SDK ({ data, error } codes d'enveloppe du catalogue renvoyés par le client `stackbone` ambiant), HTTP 4xx/5xx du plan de contrôle, les échecs d'exécution et les délais d'attente durables, `workflow_input_invalid` (un démarrage de workflow dont l'entrée a échoué son schéma déclaré), HITL bloqué à l'un ou l'autre niveau (un workflow stationné sur une porte `requestApproval()`, ou un agent s'est arrêté sur un outil bloqué avec `interruptOn`), problèmes de session durable (la mémoire ne survit pas car `x-stackbone-session` n'a pas été envoyé ou le package checkpointer est manquant), requêtes lentes de base de données / index manquants / incompatibilités de pgvector, erreurs de déchiffrement des secrets, échecs d'action du connecteur via `stackbone.connection(id)` (connexions ambiguës/non autorisées), échecs de publication/construction (SDK intégré, dépôt natif), quota de niveau dépassé les réponses et OpenRouter situations de limite de débit / de facturation en pause. Déclenchez des requêtes telles que : mon agent ne fonctionne pas, pourquoi ce 500, cette exécution est-elle bloquée, la boîte de réception HITL est vide mais l'exécution est en pause, l'agent a oublié la conversation, le workflow a rejeté mon entrée, la publication a échoué, pourquoi est-ce que je reçois 402, pourquoi mon appel de connecteur est-il ambigu, l'appel du modèle ne renvoie aucune réponse. La compétence guide l'exécution des commandes de diagnostic ; il ne propose pas de correctifs — une fois que vous avez localisé la cause, revenez à la compétence stackbone ou stackbone-cli pour implémenter le correctif.
