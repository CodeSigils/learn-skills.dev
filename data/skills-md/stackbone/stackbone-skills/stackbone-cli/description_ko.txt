'Stackbone' CLI를 구동하여 Stackbone에서 에이전트를 스캐폴드, 개발, 게시 또는 운영할 때 이 기술을 사용하십시오. 장치 흐름으로 인증(로그인/whoami), 작업 공간 셸을 스캐폴딩하고 이를 제어 플레인에 연결(초기화, 선택적으로 첫 번째 에이전트/워크플로/워크플로 에이전트 부분 사용), 기존 작업 공간에 오프라인으로 더 많은 부분 추가(딥 에이전트 추가/워크플로 추가/워크플로 에이전트 추가), 기존 디렉터리를 에이전트에 연결(링크), 로컬 개발 실행 Studio를 사용한 스택(개발자), 작업 영역 게시(게시), CLI가 역할을 하는 활성 조직 전환(조직 사용), Drizzle을 사용한 데이터베이스 마이그레이션 관리(db 마이그레이션 위로/만들기/상태), JSON에서 작업 영역 메타데이터 읽기(메타데이터), 사용 가능한 커넥터 및 계정 연결을 ID 및 이름과 함께 나열(커넥터), 인라인 문서(문서) 인쇄 및 셸에서 실행 중인 에이전트 설치 운영 — 설치 대상(에이전트) 검색, 내구성 검사 및 트리거 노출되는 워크플로(워크플로 목록/스키마/시작), 실행 검사 및 제어(실행), 로그 테일링(로그), 에이전트 DB 쿼리/탐색(db 쿼리/스키마/테이블), 저장소의 개체 이동(스토리지), 관리형 RAG 인덱스 운영(rag), 비밀 설정(비밀), 구성 문서 버전 관리 및 해당 유형 재생성(config), 프로토콜 계약 검사(계약), 인간 참여자 결정 승인(hitl), 프롬프트 카탈로그 관리(prompts), OpenRouter 배선 읽기(openrouter). 다음과 같은 요청에 따라 트리거: 작업 영역 스캐폴드, 빈 프로젝트 초기화, 내 작업 영역에 딥 에이전트 추가, 워크플로 추가, 에이전트를 호출하는 워크플로 추가(workflow-agent), 개발 스택 시작, 내 작업 영역 게시, 마이그레이션 생성, 내 조직 나열, 조직 전환, 커넥터 또는 연결 나열, 연결된 항목 확인, Stackbone에 로그인, 내 에이전트 나열, 설치 시 노출되는 워크플로 나열, 이름으로 워크플로 시작, 실패한 실행 재시도, 로그 추적, SELECT 실행 에이전트, 비밀 설정, 구성 롤백, HITL 요청 승인. @stackbone/sdk를 사용하여 에이전트 내부에 코드를 작성하려면 대신 stackbone 스킬을 사용하세요. 오류 및 중단된 실행을 분류하려면 stackbone-debug 기술을 사용하세요.
