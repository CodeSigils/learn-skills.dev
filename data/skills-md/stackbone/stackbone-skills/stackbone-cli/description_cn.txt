驱动“stackbone” CLI 在 Stackbone 上构建、开发、发布或操作代理时使用此技能：使用设备流进行身份验证（登录/whoami），构建工作区 shell 并将其链接到控制平面（init，可选地使用第一个代理/工作流/工作流代理片段），将更多片段离线添加到现有工作区（添加深度代理/添加工作流/添加工作流代理），将现有目录链接到代理（链接），使用 Studio (dev) 运行本地开发堆栈，发布工作区（发布）、切换 CLI 充当的活动组织（组织使用）、使用 Drizzle 管理数据库迁移（数据库迁移/创建/状态）、读取 JSON 格式的工作区元数据（元数据）、列出可用连接器以及带有 id 和名称的帐户连接（连接器）、打印内联文档（文档）以及从 shell 操作正在运行的代理安装 — 发现安装目标（代理）、检查并触发其公开的持久工作流程（工作流程列表） / schema / start），检查和控制运行（runs），跟踪日志（logs），查询/浏览代理数据库（db query / schemas / table），移动存储（storage）中的对象，操作托管RAG索引（rag），设置秘密（secrets），对配置文档进行版本控制并重新生成其类型（config），检查协议契约（contract），决定人机交互批准（hitl），管理提示目录（提示），并读取 OpenRouter 接线 (openrouter)。触发以下请求：搭建工作区、初始化空项目、向我的工作区添加深度代理、添加工作流、添加调用代理的工作流（工作流代理）、启动开发堆栈、发布我的工作区、生成迁移、列出我的组织、切换组织、列出连接器或连接、查看链接的内容、登录 Stackbone、列出我的代理、列出安装公开的工作流、按名称启动工作流、重试失败的运行、跟踪日志、针对代理、设置秘密、回滚配置、批准 HITL 请求。要使用 @stackbone/sdk 在代理内部编写代码，请改用 stackbone 技能。对于错误和卡住运行的分类，请使用 stackbone-debug 技能。
