Используйте этот навык при написании внутренней части рабочего пространства Stackbone с помощью @stackbone/sdk и eve: рабочее пространство обнаруживается по соглашению из файлов на диске (агенты/<имя>/agent.yaml + рабочие процессы/<имя>.workflow.ts), с дополнительным переопределением stackbone.config.ts через defineWorkspace({агенты, рабочие процессы }), которое побеждает при наличии, создавая надежный агент eve (agent.ts с моделью + build.externalDependities, Instructions.md, инструменты в инструментах/ через defineTool из 'eve/tools'), написание устойчивых рабочих процессов в виде функций «использовать рабочий процесс» / «использовать шаг» с родственными входными схемами inputSchema/outputSchema и доступ к окружающему клиенту stackbone изнутри метода выполнения() или шага рабочего процесса — stackbone.database (Drizzle over Neon Postgres), stackbone.storage (загрузка файлов), stackbone.ai (чат/встраивание LLM через OpenRouter), stackbone.rag (прием + гибридный поиск), stackbone.config / stackbone.secrets / stackbone.prompts, stackbone.agent(id) для вызова родственного агента и stackbone.connection(id) для вызова стороннего соединителя, а также паузы, выполняемые человеком в цикле, через requestApproval() из @stackbone/sdk/workflow. Запуск по таким запросам, как создание агента, добавление инструмента, запись рабочего процесса, сохранение пользовательских данных, загрузка файла, вызов LLM, прием документов для RAG, пауза до тех пор, пока человек не одобрит, вызов другого агента, вызов соединителя, чтение динамической конфигурации или добавление дополнительного переопределения stackbone.config.ts поверх обнаружения соглашений. Для задач CLI (инициализация, разработка, публикация, миграция базы данных, запуск, нажатие, триггер) вместо этого используйте навык stackbone-cli. Для сортировки ошибок и зависших запусков используйте навык stackbone-debug.
