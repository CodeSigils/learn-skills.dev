استخدم هذه المهارة عند كتابة الجزء الداخلي من مساحة عمل Stackbone باستخدام @stackbone/sdk وeve: يتم اكتشاف مساحة العمل من خلال التقليد من الملفات الموجودة على القرص (agents/<name>/agent.yaml + Workflows/<name>.workflow.ts)، مع تجاوز stackbone.config.ts اختياري عبرdefineWorkspace({ agent, Workflows }) الذي يفوز عند وجوده، مما يؤدي إلى تأليف وكيل حواء متين (agent.ts مع نموذج) + build.externalDependeency، تعليمات.md، أدوات ضمن الأدوات/ عبر أداة تعريف من 'eve/tools')، وكتابة سير عمل دائم كوظائف "استخدام سير العمل" / "خطوة الاستخدام" مع مخطط الإدخال/الإخراج الشقيق، والوصول إلى عميل `stackbone` المحيط من داخل تنفيذ الأداة () أو خطوة سير العمل - stackbone.database (رذاذ فوق Neon Postgres)، stackbone.storage (ملف) التحميلات)، وstackbone.ai (دردشة LLM / عمليات التضمين عبر OpenRouter)، وstackbone.rag (الاستيعاب + البحث المختلط)، وstackbone.config / stackbone.secrets / stackbone.prompts، وstackbone.agent(id) لاستدعاء وكيل شقيق، وstackbone.connection(id) لاستدعاء موصل طرف ثالث - بالإضافة إلى توقف الإنسان في الحلقة مؤقتًا عبر requestApproval() من @stackbone/sdk/workflow. تشغيل طلبات مثل: إنشاء وكيل، أو إضافة أداة، أو كتابة سير عمل، أو تخزين بيانات المستخدم، أو تحميل ملف، أو الاتصال بـ LLM، أو استيعاب مستندات RAG، أو الإيقاف المؤقت حتى موافقة الإنسان، أو الاتصال بوكيل آخر، أو الاتصال بموصل، أو قراءة التكوين الديناميكي، أو إضافة تجاوز stackbone.config.ts اختياري أعلى اكتشاف الاتفاقية. بالنسبة لمهام واجهة سطر الأوامر (init، dev، Publish، db migrate، runs، hitl، Trigger)، استخدم مهارة Stackbone-cli بدلاً من ذلك. لفرز الأخطاء وعمليات التشغيل المتوقفة، استخدم مهارة تصحيح الأخطاء المكدسة.
