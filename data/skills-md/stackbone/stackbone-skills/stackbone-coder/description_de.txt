Nutzen Sie diese Fähigkeit, um aus einer klaren Idee durch ein geführtes Interview ein neues Stackbone-Teil zu GENERIEREN: Entscheiden Sie zunächst, was Sie erstellen möchten – einen Deep Agent, einen dauerhaften Workflow oder einen Workflow-Agenten (ein Workflow, der einen Agenten aufruft) –, bauen Sie es dann mit der Stackbone-CLI auf und interviewen Sie den Benutzer Oberfläche für Oberfläche. Für einen Agenten fragen Sie nach seinen Tools und seiner Systemeingabeaufforderung. Für einen Workflow fragen Sie nach den Eingabedaten und den Ausgabedaten (das Eingabeschema / Ausgabeschema). Dann gehen Sie die Fähigkeits-Checkliste einzeln durch – brauchen wir eine Datenbank? Human-in-the-Loop? LAPPEN? Lagerung? ein LLM-Anruf? ein Stecker? Aufforderungen? Konfiguration? Geheimnisse? ein Zeitplan? einen anderen Agenten anrufen? – und verdrahten Sie nur die Oberflächen, die der Benutzer tatsächlich benötigt. Diese Fähigkeit STEHT das Vorstellungsgespräch und das Gerüst an; Es delegiert den echten Code an den Skill „stackbone“ (SDK-Authoring) und die Befehle an den Skill „stackbone-cli“. Auslösen bei Anfragen wie: Erstellen eines neuen Agenten, Erstellen eines Workflows, Erstellen eines Workflows, der einen Agenten aufruft, „Ich möchte einen Agenten erstellen, der …“, „Ich brauche eine Pipeline, die X akzeptiert und Y zurückgibt“, Starten eines neuen Arbeitsbereichs, Generieren eines Agenten mit Tools, Starten eines neuen Stackbone-Projekts. Zum Schreiben des SDK-Codes selbst verwenden Sie die Fähigkeit „Stackbone“. für die CLI-Oberfläche verwenden Sie „stackbone-cli“; Um einen fehlgeschlagenen Lauf zu testen, verwenden Sie „stackbone-debug“.
