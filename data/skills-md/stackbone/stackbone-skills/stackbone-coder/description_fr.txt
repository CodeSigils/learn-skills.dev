Utilisez cette compétence pour GÉNÉRER une nouvelle pièce Stackbone à partir d'une idée propre grâce à un entretien guidé : décidez d'abord ce que vous souhaitez construire : un agent approfondi, un workflow durable ou un agent de workflow (un workflow qui appelle un agent) - puis échafaudez-le avec la CLI stackbone et interrogez l'utilisateur surface par surface. Pour un agent, vous demandez ses outils et son invite système ; pour un workflow, vous demandez les données d'entrée et les données de sortie (le inputSchema/outputSchema) ; Ensuite, vous parcourez la liste de contrôle des capacités UN À LA FOIS : avons-nous besoin d’une base de données ? humain dans le circuit ? CHIFFON? stockage? un appel LLM ? un connecteur ? des invites ? configuration ? des secrets ? un planning ? appeler un autre agent ? - et câblez uniquement les surfaces dont l'utilisateur a réellement besoin. Cette compétence PILOTE l’entretien et l’échafaudage ; il délègue le vrai code à la compétence `stackbone` (création du SDK) et les commandes à la compétence `stackbone-cli`. Déclenchez des requêtes telles que : créer un nouvel agent, échafauder un workflow, créer un workflow qui appelle un agent, "Je veux créer un agent qui…", "J'ai besoin d'un pipeline qui prend X et renvoie Y", démarrer un nouvel espace de travail, générer un agent avec des outils, lancer un nouveau projet Stackbone. Pour écrire le code du SDK lui-même, utilisez la compétence « stackbone » ; pour la surface CLI, utilisez `stackbone-cli` ; pour trier une exécution ayant échoué, utilisez `stackbone-debug`.
