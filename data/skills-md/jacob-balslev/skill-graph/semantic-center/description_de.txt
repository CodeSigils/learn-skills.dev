Verwenden Sie es, wenn Sie erklären müssen, wie Teile eines Systems, einer Funktion, eines Konzepts, einer Seite, eines Arbeitsablaufs oder eines Problems zusammenhängen. den wichtigsten Teil einer Sache identifizieren; dichte Abhängigkeiten in einen Kern und typisierte Beziehungen entwirren; oder antworten Sie: „Was ist der tragende Teil?“ ohne in die Umsetzung oder Aufgabenpriorisierung abzudriften. Bietet einen fünfstufigen Arbeitsablauf: Klassifizieren Sie die Analyseeinheit, finden Sie den einzelnen Primärteil mithilfe von Entfernungs-/Governance-/Zweck-/Gewichtungs-/Entscheidungstests, ordnen Sie Sekundärteile über typisierte Beziehungen zu (Abhängigkeit, Eingabe/Ausgabe, Eltern/Kind, Besitzer/Besitz, Ursache/Wirkung, Einschränkung/Ermöglicher und andere), erzeugen Sie eine strukturierte Ausgabe und reduzieren Sie das Ganze auf einen letzten Satz – was die Erklärung durch eine Reduktion auf einen Primärteil und nicht durch flache Listen oder Chronologie erzwingt. NICHT für Implementierungsarbeiten (verwenden Sie die entsprechende Domänenkompetenz), die Auswahl der nächsten Schritte (verwenden Sie eine Priorisierungskompetenz) oder den formalen Architektur-Ownership-Entwurf (verwenden Sie eine Domänenmodellierungskompetenz) verwenden.
