Utilizzare quando si progetta il livello deterministico degli strumenti di integrità per una libreria di competenze, diagnosticando il motivo per cui una libreria esistente sta decadendo in modo invisibile, decidendo quali categorie di controllo automatizzato aggiungere (inventario, coerenza del protocollo, rilevamento dei conflitti, integrità del routing, sentinella della deriva), debug delle violazioni della soglia di valutazione su più competenze contemporaneamente o verificando se un sistema di competenze dispone delle reti di sicurezza di cui una libreria di produzione ha bisogno. Copre le cinque categorie di strumenti per lo stato delle competenze, il modello mentale della libreria come database, i modelli di qualità di valutazione (soglie minime, modello di controllo delle contraddizioni, requisiti di aspettativa negativa), i flussi di lavoro di manutenzione attivati ​​da modifiche batch delle competenze e gli anti-modelli che causano il decadimento delle librerie di competenze finché gli agenti che le caricano non peggiorano nel tempo. NON utilizzare per creare un singolo SKILL.md (usare `skill-scaffold`), per eseguire il controllo di conformità sul repository Skill Graph stesso (usare `graph-audit`), o per la selezione generale delle regole lint attraverso una codebase (usare `lint-overlay`).
