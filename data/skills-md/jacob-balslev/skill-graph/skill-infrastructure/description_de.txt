Verwenden Sie diese Funktion, wenn Sie die deterministische Health-Tooling-Ebene für eine Skill-Bibliothek entwerfen, diagnostizieren, warum eine vorhandene Bibliothek unsichtbar verfällt, entscheiden, welche Kategorien automatisierter Prüfungen hinzugefügt werden sollen (Inventar, Protokollkonsistenz, Konflikterkennung, Routing-Zustand, Drift-Sentinel), Verstöße gegen Bewertungsschwellen bei vielen Skills gleichzeitig debuggen oder prüfen, ob ein Skill-System über die Sicherheitsnetze verfügt, die eine Produktionsbibliothek benötigt. Deckt die fünf Kategorien von Skill-Health-Tools, das mentale Modell „Bibliothek als Datenbank“, Evaluierungsqualitätsmuster (Mindestschwellenwerte, Widerspruchsprüfmuster, negative Erwartungsanforderung), Wartungsworkflows, die durch Batch-Skill-Änderungen ausgelöst werden, und die Anti-Pattern ab, die dazu führen, dass Skill-Bibliotheken verfallen, bis Agenten, die sie laden, mit der Zeit schlechter werden. NICHT zum Erstellen einer einzelnen SKILL.md verwenden (verwenden Sie „skill-scaffold“), zum Ausführen der Konformitätsprüfung im Skill Graph-Repo selbst (verwenden Sie „graph-audit“) oder für die allgemeine Auswahl von Lint-Regeln in einer Codebasis (verwenden Sie „lint-overlay“).
