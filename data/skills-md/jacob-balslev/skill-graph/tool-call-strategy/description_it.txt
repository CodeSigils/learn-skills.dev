Da utilizzare quando un agente effettua troppe chiamate allo strumento, quando il contesto si riempie con output dettagliati dello strumento, quando la stessa operazione potrebbe essere uno script invece di N singole chiamate o quando si progetta un protocollo di utilizzo dello strumento per un nuovo agente o cablaggio. Copre i tre costi di ogni chiamata (token, latenza, inquinamento del contesto), il gate decisionale script-vs-chiamata, alberi decisionali di selezione degli strumenti (ricerca di file vs ricerca di contenuto vs lettura mirata vs lettura completa), batching e parallelizzazione delle chiamate, evitamento della ridondanza, principio poka-yoke, delega del subagente per la protezione del contesto ed euristica del benchmark dei costi per tipo di attività. NON utilizzare per la formulazione di prompt (usare `prompt-craft`), una progettazione più ampia dello stack di contesto sui cinque livelli (usare `context-engineering`), errori degli strumenti di runtime o debug della produzione (usare `debugging`), o meccanismi di refactoring che preservano il comportamento (usare `refactor`).
