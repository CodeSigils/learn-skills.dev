リポジトリの Git 履歴の形状を設計または維持するときに使用します。ブランチ モデルの選択、リベースとマージの決定、コミットのサイズ設定、トラッカー チケットへのコミットのリンク、リリースのタグ付け、ワークツリー間での並列作業の実行、上記のいずれかによって発生するマージの競合の解決などです。トランクベースの開発、有効期間の短い機能ブランチ、アトミック コミット規律、リニアヒストリー規則 (リベース + スカッシュ)、注釈付きタグと SemVer によるリリース タグ付け、タグからのホットフィックス フロー、パラレル エージェントまたはコントリビューターのワークツリー ライフサイクルをカバーします。コミット メッセージ内の単語 (従来のコミット形式、識別子の命名 - `naming-conventions` を使用)、リリース パイプラインの失敗の追跡 (`debugging` を使用)、または PR の内容のレビュー (`code-review` を使用) には使用しないでください。
