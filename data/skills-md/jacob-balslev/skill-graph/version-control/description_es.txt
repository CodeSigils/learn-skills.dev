Úselo al diseñar o mantener la forma del historial de Git de un repositorio: elegir un modelo de ramificación, decidir rebase versus fusionar, dimensionar confirmaciones, vincular confirmaciones a tickets de seguimiento, etiquetar lanzamientos, ejecutar trabajo paralelo en árboles de trabajo y resolver los conflictos de fusión que surgen de cualquiera de los anteriores. Cubre el desarrollo basado en troncales, ramas de características de corta duración, disciplina de confirmación atómica, convenciones de historial lineal (rebase + squash), etiquetado de lanzamiento con etiquetas anotadas y SemVer, flujos de revisión de etiquetas y ciclo de vida del árbol de trabajo para agentes o contribuyentes paralelos. NO lo use para las palabras dentro del mensaje de confirmación (formato de confirmaciones convencionales, denominación de identificadores; use `convenciones de nombres`), para buscar una falla en el canal de lanzamiento (use `depuración`) o para revisar el contenido de un PR (use `revisión de código`).
