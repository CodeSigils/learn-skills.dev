À utiliser lors de la conception ou de la maintenance de la forme de l'historique Git d'un référentiel : choisir un modèle de branchement, décider du rebasement ou de la fusion, dimensionner les validations, lier les validations aux tickets de suivi, marquer les versions, exécuter un travail parallèle sur les arbres de travail et résoudre les conflits de fusion qui découlent de l'un des éléments ci-dessus. Couvre le développement basé sur le tronc, les branches de fonctionnalités de courte durée, la discipline de validation atomique, les conventions d'historique linéaire (rebase + squash), le marquage des versions avec des balises annotées et SemVer, les flux de correctifs à partir des balises et le cycle de vie de l'arbre de travail pour les agents ou contributeurs parallèles. Ne PAS utiliser pour les mots à l'intérieur du message de validation (format Conventional Commits, dénomination d'identifiant — utilisez `naming-conventions`), pour rechercher un échec de pipeline de publication (utilisez `debugging`) ou pour réviser le contenu d'un PR (utilisez `code-review`).
