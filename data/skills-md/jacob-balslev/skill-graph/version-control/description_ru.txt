Используйте при проектировании или поддержании формы истории git в репозитории — выбор модели ветвления, решение о перебазировании или слиянии, определение размера коммитов, привязка коммитов к билетам трекера, маркировка выпусков, выполнение параллельной работы между рабочими деревьями и разрешение конфликтов слияния, возникающих в результате любого из вышеперечисленных действий. Охватывает разработку на основе магистрали, кратковременные ветки функций, дисциплину атомарных коммитов, соглашения о линейной истории (перебазирование + сжатие), тегирование выпусков с помощью аннотированных тегов и SemVer, потоки исправлений из тегов и жизненный цикл рабочего дерева для параллельных агентов или участников. НЕ используйте для слов внутри сообщения о фиксации (формат обычных коммитов, именование идентификаторов — используйте соглашения об именовании), для отслеживания сбоя конвейера выпуска (используйте «отладку») или для проверки содержимого PR (используйте «проверку кода»).
