Используйте при разработке или расширении конвейера отчетов об исключениях для приложения — выбирайте, где находятся границы ошибок (компонент, раздел, маршрут, глобальное приложение), оборачивайте SDK трекера, чтобы каждый вызов отчетов очищался и ограничивался средой, прикрепляйте пользовательский контекст без утечки личных данных и проверяйте, что ошибки каждого уровня действительно достигают трекера. Охватывает четырехуровневую модель отслеживания ошибок (границы компонентов, резервные маршруты, глобальный обработчик сбоев, ручной API), централизованную разработку оболочки (reportError/reportMessage/addBreadcrumb/setUser), очистку PII перед любой внешней отправкой, шлюзование с учетом среды (dev → локальный регистратор, prod → tracker SDK) и диагностический вопрос: «Этот уровень действительно сообщает или только регистрирует?» НЕ используйте для *визуального* пользовательского интерфейса ошибки, видимого пользователем (используйте `a11y` для доступных сообщений об ошибках и потоков восстановления), для отслеживания одной наблюдаемой ошибки, уже зафиксированной в трекере (используйте `отладку`), или для более широкой политики конфиденциальности и хранения личных данных (используйте `owasp-security`).
