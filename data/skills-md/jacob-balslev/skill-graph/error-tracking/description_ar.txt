يُستخدم عند تصميم أو توسيع مسار إعداد تقارير الاستثناء لأحد التطبيقات - اختيار مكان وجود حدود الأخطاء (المكون، القسم، المسار، التطبيق العام)، وتغليف SDK للمتعقب بحيث يتم تطهير كل استدعاء تقارير وبوابة البيئة، وإرفاق سياق المستخدم دون تسريب معلومات تحديد الهوية الشخصية (PII)، والتحقق من وصول أخطاء كل طبقة فعليًا إلى المتعقب. يغطي نموذج التقاط الأخطاء ذو الأسطح الأربعة (حدود المكونات، والطرق الاحتياطية، ومعالج الأعطال العالمية، وواجهة برمجة التطبيقات اليدوية)، وتصميم الغلاف المركزي (`reportError` / `reportMessage` / `addBreadcrumb` / `setUser`)، وتعقيم معلومات تحديد الهوية الشخصية (PII) قبل أي إرسال خارجي، والبوابة المدركة للبيئة (dev → local logger، prod → Tracker SDK)، والسؤال التشخيصي "هل تقوم هذه الطبقة بالإبلاغ بالفعل، أو هل يسجل فقط؟ لا تستخدمه لخطأ *مرئي* لتجربة المستخدم الذي شاهده المستخدم (استخدم `a11y` لرسائل الخطأ التي يمكن الوصول إليها وتدفقات الاسترداد)، أو لمطاردة خطأ واحد ملحوظ تم التقاطه بالفعل في أداة التتبع (استخدم `تصحيح الأخطاء`)، أو لسياسة الخصوصية والاحتفاظ بمعلومات تحديد الهوية الشخصية (PII) على نطاق أوسع (استخدم oasp-security).
