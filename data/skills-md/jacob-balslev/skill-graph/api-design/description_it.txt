Da utilizzare durante la progettazione o la revisione delle superfici API: risorse/azioni, schemi di richiesta e risposta, codici di stato, impaginazione, filtraggio, idempotenza, controllo delle versioni, limiti di autenticazione e inviluppi di errore. NON utilizzare per contratti di sistema non HTTP (utilizzare `system-interface-contracts`), contratti di eventi asincroni (utilizzare `event-contract-design`), progettazione di database (utilizzare `data-modeling`) o meccanismi webhook del provider in entrata (utilizzare `webhook-integration`).
