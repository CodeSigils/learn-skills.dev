يُستخدم عند مراجعة طلب سحب أو اختلاف أو تغيير التعليمات البرمجية المقترح للتأكد من الصحة والوضوح والأمان والأداء والتوافق مع اتفاقيات المشروع - سواء كان المؤلف إنسانًا أو وكيل ذكاء اصطناعي أو نظير. يغطي تصريح جمع الحقائق قبل المراجعة، واستراتيجية ترتيب القراءة (الاختبارات أولاً، ثم التنفيذ، ثم الاتصال بالمواقع)، وقاعدة تقييم درجة الخطورة، ونظام صياغة التعليق، وقاعدة عدم الختم المطاطي للاختلافات التي ينشئها الذكاء الاصطناعي. لا تستخدم لتأليف الكود (استخدم "refactor" لتغييرات الحفاظ على السلوك أو "skill-scaffold" للمهارات الجديدة)، أو لمطاردة خطأ معروف بعد الدمج (استخدم "debugging")، أو لعمليات التدقيق المتعلقة بالأمان فقط (استخدم "owasp-security" للمراجعة التي تركز على الثغرات الأمنية).
