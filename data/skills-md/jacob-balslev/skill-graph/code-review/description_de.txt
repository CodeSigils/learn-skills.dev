Wird verwendet, wenn eine Pull-Anfrage, ein Diff oder eine vorgeschlagene Codeänderung auf Richtigkeit, Klarheit, Sicherheit, Leistung und Konformität mit Projektkonventionen überprüft wird – unabhängig davon, ob der Autor ein Mensch, ein KI-Agent oder ein Peer ist. Behandelt das Sammeln von Fakten vor der Überprüfung, die Lesereihenfolge-Strategie (zuerst Tests, dann Implementierung, dann Anrufseiten), die Rubrik zur Schweregradbewertung, die Disziplin bei der Formulierung von Kommentaren und die No-Stempel-Regel für KI-generierte Unterschiede. NICHT zum AUTORIEREN des Codes verwenden (verwenden Sie „refactor“ für verhaltenserhaltende Änderungen oder „skill-scaffold“ für neue Fähigkeiten), zur Suche nach einem bekannten Fehler nach der Zusammenführung (verwenden Sie „Debugging“) oder für reine Sicherheitsprüfungen (verwenden Sie „owasp-security“ für eine auf Schwachstellen ausgerichtete Überprüfung).
