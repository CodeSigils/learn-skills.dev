Используйте при проверке запроса на включение, различий или предлагаемого изменения кода на предмет правильности, ясности, безопасности, производительности и соответствия соглашениям проекта — независимо от того, является ли автор человеком, агентом ИИ или коллегой. Охватывает этап сбора фактов перед проверкой, стратегию порядка чтения (сначала тесты, затем реализацию, затем сайты), критерии оценки серьезности, дисциплину формулирования комментариев и правило отсутствия штампов для различий, созданных ИИ. НЕ используйте для АВТОРСКОГО кода (используйте «рефакторинг» для изменений, сохраняющих поведение, или «skill-scaffold» для новых навыков), для поиска известной ошибки после слияния (используйте «отладку») или для аудита только безопасности (используйте «owasp-security» для проверки, ориентированной на уязвимости).
