À utiliser lors de l'examen d'une demande d'extraction, d'une différence ou d'une modification de code proposée pour en vérifier l'exactitude, la clarté, la sécurité, les performances et la conformité aux conventions du projet, que l'auteur soit un humain, un agent d'IA ou un pair. Couvre la collecte de faits préalable à l'examen, la stratégie d'ordre de lecture (tests d'abord, puis mise en œuvre, puis appels aux sites), la rubrique d'évaluation de la gravité, la discipline de formulation des commentaires et la règle de non-tampon pour les différences générées par l'IA. Ne PAS utiliser pour CRÉER le code (utilisez « refactor » pour préserver le comportement ou « skills-scaffold » pour de nouvelles compétences), pour rechercher un bogue connu après la fusion (utilisez « debugging ») ou pour des audits de sécurité uniquement (utilisez « owasp-security » pour un examen axé sur les vulnérabilités).
