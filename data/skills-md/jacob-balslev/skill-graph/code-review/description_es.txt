Úselo al revisar una solicitud de extracción, una diferencia o un cambio de código propuesto para verificar su corrección, claridad, seguridad, rendimiento y conformidad con las convenciones del proyecto, ya sea que el autor sea un ser humano, un agente de IA o un par. Cubre el pase de recopilación de datos previo a la revisión, la estrategia de orden de lectura (pruebas primero, luego la implementación, luego los sitios de llamadas), la rúbrica de clasificación de gravedad, la disciplina de redacción de comentarios y la regla de no dar sello para las diferencias generadas por IA. NO lo use para AUTOR el código (use `refactor` para cambios que preserven el comportamiento o `skill-scaffold` para nuevas habilidades), para buscar un error conocido después de la fusión (use `debugging`) o para auditorías solo de seguridad (use `owasp-security` para una revisión centrada en vulnerabilidades).
