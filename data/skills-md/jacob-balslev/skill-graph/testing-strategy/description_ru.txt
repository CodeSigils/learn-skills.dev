Используйте при планировании тестов для исправления ошибок, функции или рефакторинга — решайте, что заслуживает тестирования, на каком уровне и с какими доказательствами. Охватывает решения по объему тестирования, выбор уровня тестирования (модуль / интеграция / контракт / e2e), сопоставление усилий и рисков, таргетинг регрессии, качество доказательств и покрытие случаев сбоя. НЕ используйте для поиска известного сбоя (то есть «отладки»), для написания чистой документации (то есть «документации») или для обсуждения концептуальной архитектуры без цели проверки (нет специальных навыков — рассматривайте как стратегию, а не тестирование).
