Habilidad para inventariar y actualizar un árbol de problemas de GitHub existente. Se utiliza con “Hacer un inventario del árbol”, “Actualizar el árbol de problemas” y “Organizar el seguimiento de un problema”. Recibe el número de problema de seguimiento raíz, recupera recursivamente todo el árbol a través de la API sub_issues → reasigna problemas abiertos que quedaron bajo padres cerrados, reposiciona problemas huérfanos, crea nuevos padres de fase, sincroniza etiquetas de fase → regenera y actualiza la tabla Fase por Fase y la sección de inventario en el cuerpo del problema raíz. Consulte create-issue-tree para crear un nuevo árbol e implement-issue-tree para consumir la implementación.
