Habilidad para crear un nuevo árbol de Issues de GitHub dividido por Fase. Se utiliza con comandos como "Crear árbol de problemas", "Convertir tareas en problemas por fase", "Presentar un árbol de problemas". Recibe una lista de requisitos y tareas, descompone las tareas (en granularidad de 4 horas) → se divide en Fases → problema raíz (seguimiento) → Fase problema principal → problemas secundarios, vinculando la jerarquía a través de la API sub_issues. Automatiza la adición de etiquetas de fase y la generación de una tabla por fases en el cuerpo del problema raíz. También admite la presentación parcial especificando fases arbitrarias. Para inventariar/actualizar el árbol, consulte update-issue-tree; para implementar el árbol, consulte implementar-issue-tree.
