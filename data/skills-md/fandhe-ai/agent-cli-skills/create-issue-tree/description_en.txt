Skill for creating a new GitHub Issue tree divided by Phase. Used with commands like “Create issue tree,” “Convert tasks into Issues by Phase,” “File an issue tree.” Receives a list of requirements and tasks, decomposes tasks (into 4‑hour granularity) → splits into Phases → root (tracking) issue → Phase parent issue → child issues, linking the hierarchy via the sub_issues API. Automates adding phase labels and generating a Phase‑wise table in the root issue body. Also supports partial filing by specifying arbitrary phases. For inventorying/updating the tree see update-issue-tree; for implementing the tree see implement-issue-tree.
