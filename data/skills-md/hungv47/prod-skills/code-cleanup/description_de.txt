Diese Fähigkeit sollte aufgerufen werden, wenn der Benutzer vorhandenen Code bereinigen, umgestalten oder verbessern möchte, ohne das Verhalten zu ändern oder Fehler zu beheben. Zu den Auslösern gehören „Dieser Code ist ein Chaos“, „Diese Datei bereinigen“, „Diese PR bereinigen“, „Überprüfen Sie die Qualität meines Codes“, „Toten Code entfernen“, „Tech-Schulden“, „zu viel Komplexität“, „Ich habe schlechten Code geerbt“, „KI-Fehler beheben“, „Nicht wartbar“, „Legacy-Code“, „Duplizierung“, „Refactor“ oder „Lesbar machen“ – selbst wenn sie nur sagen: „Das ist hässlich“, „vereinfache dies“ oder „das ist schwer zu befolgen“ und meint die Codestruktur selbst. Nicht zum Diagnostizieren von Geschäftsproblemen (Problemanalyse verwenden) oder zum Schreiben von Dokumentation zur Erläuterung von Code (technischer Autor verwenden).
