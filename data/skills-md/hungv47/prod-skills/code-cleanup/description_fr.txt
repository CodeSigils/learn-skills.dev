Cette compétence doit être invoquée lorsque l'utilisateur souhaite nettoyer, refactoriser ou améliorer le code existant sans modifier le comportement ni corriger les bogues. Les déclencheurs incluent « ce code est un gâchis », « nettoyer ce fichier », « nettoyer ce PR », « vérifier la qualité de mon code », « supprimer le code mort », « dette technologique », « trop de complexité », « J'ai hérité d'un mauvais code », « corriger le problème de l'IA », « non maintenable », « code hérité », « duplication », « refactoriser » ou « rendre cela lisible » - même s'ils dites simplement « c'est moche », « simplifiez ceci » ou « c'est difficile à suivre » et faites référence à la structure du code elle-même. Pas pour diagnostiquer des problèmes commerciaux (utiliser l'analyse des problèmes) ou rédiger une documentation pour expliquer le code (utiliser un rédacteur technique).
