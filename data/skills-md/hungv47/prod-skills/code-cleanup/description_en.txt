This skill should be invoked when the user wants to clean up, refactor, or improve existing code without changing behavior or fixing bugs. Triggers include 'this code is a mess', 'clean up this file', 'clean up this PR', 'review my code quality', 'remove dead code', 'tech debt', 'too much complexity', 'I inherited bad code', 'fix AI slop', 'unmaintainable', 'legacy code', 'duplication', 'refactor', or 'make this readable' -- even if they just say 'this is ugly', 'simplify this', or 'this is hard to follow' and mean the code structure itself. Not for diagnosing business problems (use problem-analysis) or writing documentation to explain code (use technical-writer).
