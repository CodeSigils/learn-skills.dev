Cette compétence doit être invoquée lorsque l'utilisateur souhaite obtenir de la documentation pour une base de code ou un projet : fichiers README, guides d'utilisation, références d'API, documents d'API, guides de configuration, runbooks, journaux de modifications, guides de contribution ou documents d'architecture. Les déclencheurs incluent « écrire un fichier README », « documenter ceci », « nous n'avons pas de documents », « personne ne sait comment cela fonctionne », « j'ai besoin de documents », « nos documents sont obsolètes », « expliquer cette base de code », « créer un guide de l'utilisateur », « base de connaissances », « ce sont toutes des connaissances tribales » ou « documentation d'intégration des développeurs » - même s'ils disent simplement « un nouveau développeur ». Je n'arrivais pas à comprendre cela », « Je suis le seul à savoir comment cela fonctionne » ou « Les nouvelles recrues mettent des semaines à devenir productives ». Pas pour spécifier ce qu'il faut construire (utiliser plan-interviewer), restructurer le code pour qu'il soit plus lisible (utiliser le nettoyage de code) ou l'intégration UX orientée utilisateur (utiliser le flux utilisateur).
