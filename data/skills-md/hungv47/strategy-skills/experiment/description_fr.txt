Cette compétence doit être invoquée lorsque l'utilisateur a une idée ou une initiative commerciale et souhaite la valider avec un test avant de s'engager pleinement (pas de test de code ou d'assurance qualité). Les déclencheurs incluent « comment tester cela », « dois-je exécuter un test A/B », « prouver que cela fonctionne d'abord », « comment savoir si cela fonctionnera », « valider cette idée avec des données », « concevoir une expérience », « réduire les risques de ce lancement », « tester nos prix », « test bêta », « programme pilote », « lancement en douceur », « test de fumée » ou « quel est le moyen le moins cher de apprendre' - même s'ils sont sur le point de lancer quelque chose et veulent être sûrs que cela fonctionnera, veulent réduire les risques d'une idée avec des données, ou ont des objectifs fixés et doivent être testés avant le déploiement complet. Pas pour la priorisation stratégique (utiliser la conception de solutions), le dimensionnement du marché ou la recherche de faisabilité (utiliser icp-research), la modélisation du fonctionnement des calculs de tarification (utiliser le planificateur d'entonnoir), l'audit de la conversion d'une page existante (utiliser l'optimisation lp) ou le diagnostic des raisons pour lesquelles les métriques sont en baisse (utiliser l'analyse des problèmes).
