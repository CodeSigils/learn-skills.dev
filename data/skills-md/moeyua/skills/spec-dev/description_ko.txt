기능 개발에 대한 북엔드 역할을 하는 사양 중심 개발 문서 시스템입니다. 사양이 개발을 주도하고 테스트가 사양을 검증하는 4계층 문서 아키텍처(왜 → 무엇을 → 어떻게 → 검증)를 구축합니다. 사용자가 원할 때마다 이 기술을 사용하십시오. 개발 전 사양 또는 기능 사양 작성, SDD/TDD/BDD 워크플로우 설정, 개발 후 문서 동기화 또는 업데이트(AC 상태, 모듈 계약, ADR 업데이트), 프로젝트 문서 초기화, 기존 문서 감사 또는 구조 조정, 모듈 계약 생성, 프로젝트 상태 또는 진행 상황 확인, '사양 작성', '사양 업데이트', '문서 동기화', '문서 설정', '내 문서 감사', '구조 조정'과 같은 작업 docs', '모듈 계약 생성', 'BDD 시나리오 추가', '상태', '看一下进島', '接下来做什么'. 또한 사용자가 사양 우선 개발, 행동 중심 개발, 수용 기준을 언급하거나 테스트 전략을 추진하는 문서를 원할 때 트리거됩니다. 이 기술은 feature-dev를 보완합니다. feature-dev 이전에 spec-dev를 사용하여 무엇을 빌드할지 정의하고, feature-dev 이후에 문서를 업데이트합니다.
