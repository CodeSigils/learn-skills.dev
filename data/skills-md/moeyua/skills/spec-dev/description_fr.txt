Système de documentation de développement piloté par les spécifications qui sert de serre-livres autour du développement de fonctionnalités. Construit une architecture de documentation à quatre couches (POURQUOI → QUOI → COMMENT → VÉRIFIER) où les spécifications pilotent le développement et les tests vérifient les spécifications. Utilisez cette compétence chaque fois que l'utilisateur souhaite : rédiger une spécification ou une spécification de fonctionnalité avant le développement, configurer des flux de travail SDD/TDD/BDD, synchroniser ou mettre à jour des documents après le développement (mettre à jour le statut AC, les contrats de module, les ADR), initialiser la documentation du projet, auditer ou restructurer des documents existants, créer des contrats de module, vérifier l'état ou l'avancement du projet, ou dire des choses comme "écrire une spécification", "mettre à jour la spécification", "synchroniser les documents", "configurer les documents", "auditer mes spécifications". docs', 'restructurer les documents', 'créer un contrat de module', 'ajouter des scénarios BDD', 'statut', '看一下进度', '接下来做什么'. Déclenchez également lorsque l'utilisateur mentionne le développement axé sur les spécifications, le développement axé sur le comportement, les critères d'acceptation ou souhaite une documentation qui guide sa stratégie de test. Cette compétence complète feature-dev : utilisez spec-dev avant feature-dev pour définir ce qu'il faut construire, et après feature-dev pour mettre à jour la documentation.
