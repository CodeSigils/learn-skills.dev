Sistema de documentación de desarrollo basado en especificaciones que sirve como sujetalibros en torno al desarrollo de funciones. Crea una arquitectura de documentos de cuatro capas (POR QUÉ → QUÉ → CÓMO → VERIFICAR) donde las especificaciones impulsan el desarrollo y las pruebas verifican las especificaciones. Utilice esta habilidad siempre que el usuario quiera: escribir una especificación o característica antes del desarrollo, configurar flujos de trabajo SDD/TDD/BDD, sincronizar o actualizar documentos después del desarrollo (actualizar el estado de AC, contratos de módulos, ADR), inicializar la documentación del proyecto, auditar o reestructurar documentos existentes, crear contratos de módulos, verificar el estado o progreso del proyecto, o decir cosas como "escribir una especificación", "actualizar la especificación", "sincronizar documentos", "configurar documentos", "auditar mi docs', 'reestructurar documentos', 'crear contrato de módulo', 'agregar escenarios BDD', 'estado', '看一下进度', '接下来做什么'. También se activa cuando el usuario menciona el desarrollo centrado en las especificaciones, el desarrollo basado en el comportamiento, los criterios de aceptación o desea documentación que impulse su estrategia de prueba. Esta habilidad complementa feature-dev: use spec-dev antes de feature-dev para definir qué construir y después de feature-dev para actualizar la documentación.
