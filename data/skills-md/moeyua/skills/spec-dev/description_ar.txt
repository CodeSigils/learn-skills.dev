نظام توثيق التطوير المبني على المواصفات والذي يعمل بمثابة نهايات حول تطوير الميزات. يبني بنية مستندية مكونة من أربع طبقات (لماذا → ماذا → كيف → التحقق) حيث تدفع المواصفات التطوير وتتحقق الاختبارات من المواصفات. استخدم هذه المهارة عندما يريد المستخدم: كتابة مواصفات أو مواصفات ميزات قبل التطوير، أو إعداد سير عمل SDD/TDD/BDD، أو مزامنة المستندات أو تحديثها بعد التطوير (تحديث حالة AC، أو عقود الوحدة، أو ADRs)، أو تهيئة وثائق المشروع، أو تدقيق المستندات الموجودة أو إعادة هيكلتها، أو إنشاء عقود الوحدة، أو التحقق من حالة المشروع أو تقدمه، أو قول أشياء مثل "كتابة المواصفات"، أو "تحديث المواصفات"، أو "مزامنة المستندات"، أو "إعداد المستندات"، أو "تدقيق البيانات" docs"، و"إعادة هيكلة المستندات"، و"إنشاء عقد الوحدة النمطية"، و"إضافة سيناريوهات BDD"، و"الحالة"، و"看一下进度"، و"接下来做什么". يتم تشغيله أيضًا عندما يذكر المستخدم التطوير الأول للمواصفات، أو التطوير المبني على السلوك، أو معايير القبول، أو يريد الوثائق التي تقود استراتيجية الاختبار الخاصة به. تكمل هذه المهارة عملية تطوير الميزات: استخدم spec-dev قبل ميزة dev لتحديد ما سيتم إنشاؤه، وبعد ميزة dev لتحديث الوثائق.
