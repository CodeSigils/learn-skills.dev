Inventariza una base de código real y clasifica su deuda técnica en un registro puntuado por interés (qué tan a menudo duele) sobre principal (esfuerzo para arreglarla), cada ítem anclado a un archivo y línea o a una métrica. Cubre olores de código, deuda de dependencias, brechas de pruebas y puntos críticos de churn arquitectónico tanto en frontend como en backend. Úsalo cuando te pregunten qué pagar, dónde la base de código está decayendo, o para convertir la deuda en una lista de tareas rastreada. Archiva el registro como issues de GitHub a petición. Para la estrategia tecnológica y la dirección arquitectónica a nivel organizacional, usa `cto-advisor`.

Por favor, responde siempre en el idioma del usuario.
