Inventaire une véritable base de code et classe sa dette technique dans un registre noté par intérêt (la fréquence à laquelle cela fait mal) par rapport au principal (effort de réparation), chaque élément ancré à un fichier et une ligne ou à une métrique. Couvre les odeurs de code, la dette de dépendance, les lacunes dans les tests et les points chauds de désabonnement architectural sur le front-end et le back-end. À utiliser lorsqu'on vous demande quoi rembourser, où la base de code pourrit ou pour transformer la dette en un arriéré suivi. Dépose le registre en tant que problèmes GitHub sur demande. Pour la stratégie technologique et l'orientation de l'architecture au niveau de l'organisation, utilisez « cto-advisor ».
