Einzelne Vordertür zum Testen. Analysiert einen Unterbefehl – run, qa, tdd, e2e, cover, init oder regression – und leitet ihn an die richtige Test-Engine weiter: test-runner (Tests ausführen, Fehler beheben), qa-reviewer (strukturierter Überprüfungsdurchgang für abgeschlossene Arbeiten), tdd (Rot-Grün-Refactor-Workflow), playwright-e2e-init (Gerüst-E2E-Tests für Frontend-Projekte), husky-test-coverage (Abdeckung erzwingen). Schwellenwerte über Git-Hooks), testing-cicd-init (Vitest + GitHub Actions CI-Setup) oder ai-regression-testing (Entwerfen von Regressionstests, die auf blinde Flecken der KI abzielen). Unterstützt den /test-Befehl. Wird verwendet, wenn Sie aufgefordert werden, Tests auszuführen, Tests zu schreiben, Tests einzurichten, die Abdeckung zu überprüfen oder TDD zu starten. Die Aktion muss aus einem Argument wie „run“, „qa“, „tdd“, „e2e“, „coverage“, „init“ oder „regression“ ausgewählt werden.
