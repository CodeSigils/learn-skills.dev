Porte d'entrée unique pour les tests. Analyse une sous-commande - run, qa, tdd, e2e, couverture, init ou régression - et achemine vers le bon moteur de test : test-runner (exécuter des tests, corriger les échecs), qa-reviewer (vérification structurée sur le travail terminé), tdd (workflow de refactor rouge-vert), playwright-e2e-init (tests E2E d'échafaudage pour les projets frontaux), husky-test-coverage (appliquer les seuils de couverture via git hooks), testing-cicd-init (configuration Vitest + GitHub Actions CI) ou ai-regression-testing (conception de tests de régression ciblant les angles morts de l'IA). Sauvegarde la commande /test. À utiliser lorsqu'on vous demande d'exécuter des tests, d'écrire des tests, de configurer des tests, de vérifier la couverture ou de démarrer TDD, et l'action doit être sélectionnée à partir d'un argument tel que "run", "qa", "tdd", "e2e", "coverage", "init" ou "regression".
