Escriba pruebas mínimas y enfocadas siguiendo los principios de KISS y YAGNI: pruebe solo los flujos de usuarios principales durante el desarrollo, posponga las pruebas de casos extremos, pruebe el comportamiento, no la implementación, use nombres de prueba claros, simule dependencias externas y garantice una ejecución rápida de las pruebas. Utilice esta habilidad al crear archivos de prueba, escribir pruebas unitarias, pruebas de integración o pruebas de componentes. Úselo cuando trabaje con marcos de prueba (Jest, Vitest, pytest, RSpec, JUnit, Mocha), cuando decida qué probar y cuándo, cuando escriba casos de prueba para rutas críticas y flujos de trabajo principales, cuando se burle de servicios o bases de datos externos, o cuando garantice que las pruebas se ejecuten rápidamente para la productividad del desarrollador. Aplicar al crear archivos de prueba (.test.ts, .spec.ts, test_*.py, *_test.go) o al implementar casos de prueba basados ​​en el comportamiento.
