프로젝트의 'codestable/requirements/' 아래에 요구 사항 문서를 유지합니다. **사용자 스토리 + 일반 언어**를 사용하여 "존재 이유, 문제 해결 방법, 경계 위치"를 다루는 기존 기능을 설명합니다. 그러면 기술 지식이 없는 독자도 시스템을 돋보이게 만드는 요소를 빠르게 파악할 수 있습니다. 아키텍처 계층과 분리: 요구사항은 "문제 공간"(이 기능이 존재하는 이유)이고 아키텍처는 "솔루션 공간"(어떤 구조가 이를 구현하는지)입니다. **요구 사항은 상태 아카이브입니다. 즉, "우리가 계획한 작업/다음에 추가할 작업"이 아닌 설정된 경계에 이미 존재하는 문서 기능만 해당됩니다. 이러한 기능은 cs-roadmap에 속합니다.** 기본 경로는 코드와 다시 동기화되는 기능 수용입니다. 이 기술은 '업데이트'(가장 일반적인 새 자료 또는 구현 변경 사항에 따라 기존 문서 새로 ​​고침), '백필'(존재하지만 문서가 없는 기능에 대한 문서 만들기)의 두 가지 모드가 있는 백업 활성 진입점입니다. 단일 대상 규칙 - 한 번에 하나의 문서만 수정합니다. 트리거 시나리오: 사용자가 "요구 사항 디렉터리 새로 고침", "이 요구 사항은 더 이상 현재 코드와 일치하지 않습니다", "이 실행 기능에는 요구 사항이 없었습니다. 추가하세요"라고 말하거나 기능 설계 단계에서 구현될 기능에 해당 요구 사항이 부족한 경우. 사용자가 "X 기능을 원합니다"라고 말했지만 X가 구축되지 않은 경우 → 이 기술을 사용하지 말고 대신 cs-roadmap으로 라우팅하세요.
