Phase 1 des Issue-Workflows – durch Dialog das Problem im Kopf des Benutzers in einem reproduzierbaren, nachvollziehbaren {slug}-report.md kristallisieren. In dieser Phase fragt die KI nur „Was haben Sie gesehen, wie soll es reproduziert werden, was soll passieren“ und errät nicht die Grundursache für den Benutzer (das ist die Aufgabe von Phase 2). Mittlerweile ist diese Phase der einzige formale Entscheidungspunkt für die Entscheidung, ob der Schnellweg oder der Standardweg gewählt werden soll: Basierend auf der Beschreibung des Benutzers wird zunächst der relevante Code gelesen. Wenn es auf einen Blick lokalisiert werden kann und nur minimale Änderungen erforderlich sind, informieren Sie den Benutzer direkt, dass er den schnellen Weg wählen soll. Auslöseszenarien: Der Benutzer sagt „Ein Problem melden“, „Diesen Fehler aufzeichnen“ oder „Ich habe ein Problem gefunden“. Dies ist der Ausgangspunkt des Issue-Workflows ohne vorherige Abhängigkeiten.
