Phase 1 of the issue workflow—through dialogue, crystallize the problem in the user's mind into a reproducible, traceable {slug}-report.md. At this stage, the AI only asks "what did you see, how to reproduce, what should happen," and does not guess the root cause for the user (that's Phase 2's job). Meanwhile, this phase is the sole formal decision point for determining whether to take the fast track or standard path: based on the user's description, first read the relevant code; if it can be pinpointed at a glance and requires minimal changes, directly inform the user to take the fast track. Trigger scenarios: user says "file an issue," "record this bug," or "I found a problem." This is the starting point of the issue workflow with no prior dependencies.
