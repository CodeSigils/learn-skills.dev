Vue Component/Composable Refactoring Sparring Partner – Benutzer fügt ein Snippet ein oder zeigt auf einen SFC; Der Skill gibt zunächst eine Diagnose („Fat Trunk“ / „UI & IO Tangled“ / „Reaktivität & Business Logic Tangled“), wählt dann eine von drei Rezepten aus und listet die genaue Extraktionsschrittsequenz auf (welche Variable zuerst verschoben werden soll, welcher Compilerfehler angezeigt wird, wie man sie einzeln beseitigt, wann ein Rollback möglich ist). Der gesamte Prozess basiert auf grünen Lichtern des Compilers und einem einstufigen Rollback, um Verhaltensäquivalenz zu gewährleisten. Es ist kein Testsicherheitsnetz erforderlich. Auslösephrasen: Der Benutzer sagt: „Diese Vue-Komponente ist zu fett / möchte Logik extrahieren / diesen SFC aufteilen / dieses Composable ist chaotisch / ein Composable extrahieren / in Humble aufteilen / rein funktional machen“ oder zeigt auf eine offensichtlich übergroße .vue / Composable-Datei und fragt nach „Refactoring / Optimieren / Splitten“. Verarbeitet nur Vue (Vue 2-Optionen, Vue 2/3 „<script setup>“, Composable, Pinia Store). Geht nicht: neue Funktionen (Feature Flow verwenden), Fehlerbehebungen (Issue Flow verwenden), modulübergreifende Architekturumgestaltung, Backend-Code.
