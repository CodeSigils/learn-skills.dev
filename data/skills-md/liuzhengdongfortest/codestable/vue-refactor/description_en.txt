Vue Component/Composable Refactoring Decision Coach — the user pastes a code snippet or points to an SFC; the skill first performs a diagnosis (“fat trunk” / “UI & IO tangled” / “reactivity & business logic tangled”), then picks one of three prescriptions and gives a concrete, step-by-step extract sequence (which variable to move first, what compiler error will appear, how to eliminate them one by one, when to roll back). The whole process relies on the compiler’s green light + single-step rollback to guarantee behavioral equivalence, no test safety net required.  
Trigger scenarios: user says “this Vue component is too fat / want to extract the logic / split this SFC / this composable is messy / extract a composable / split into humble / make it pure-functional”, or points to an obviously oversized .vue / composable file and asks for “refactor / optimize / split”.  
Scope: Vue only (Vue 2 Options, Vue 2/3 `<script setup>`, composables, Pinia store).  
Out of scope: adding new features (use feature flow), fixing bugs (use issue flow), cross-module architectural reshuffle, backend code.
