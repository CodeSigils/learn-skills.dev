Vue Component/Composable Refactoring Sparring Partner : l'utilisateur colle un extrait de code ou pointe vers un SFC ; la compétence donne d'abord un diagnostic (« gros tronc » / « UI et E/S enchevêtrées » / « réactivité et logique métier enchevêtrées »), puis sélectionne l'une des trois prescriptions et répertorie la séquence exacte des étapes d'extraction (quelle variable déplacer en premier, quelle erreur du compilateur apparaîtra, comment les éliminer une par une, quand vous pouvez restaurer). L'ensemble du processus repose sur les feux verts du compilateur + une restauration en une seule étape pour garantir l'équivalence comportementale, aucun filet de sécurité de test n'est requis. Phrases déclencheurs : l'utilisateur dit "ce composant Vue est trop gros / veut extraire la logique / diviser ce SFC / ce composable est désordonné / extraire un composable / diviser en humble / le rendre purement fonctionnel", ou pointe du doigt un fichier .vue / composable manifestement surdimensionné et demande "refactor / optimiser / diviser". Gère uniquement Vue (Vue 2 Options, Vue 2/3 `<script setup>`, composable, Pinia store). Ne fera pas : nouvelles fonctionnalités (utiliser le flux de fonctionnalités), corrections de bogues (utiliser le flux de problèmes), remaniement architectural entre modules, code backend.
