Divida un requisito que sea "demasiado grande para ser una sola característica" en una lista de verificación de subcaracterísticas con dependencias y estados, colocada en un directorio dedicado `codestable/roadmap/{slug}/`, como semilla y base de programación para flujos de trabajo de múltiples funciones posteriores. Dos modos: nuevo (redactar una nueva hoja de ruta a partir de un requisito grande), actualizar (actualizar una hoja de ruta existente: agregar elementos, cambiar dependencias, reordenar, marcar entregas). División del trabajo con requisitos/arquitectura: esos dos registran "cómo es el sistema ahora", la hoja de ruta registra "hacia dónde planeamos ir a continuación". Escenarios desencadenantes: el usuario dice "Quiero un sistema X", "ayúdame a desglosar este requisito", "programar este gran requisito", "crear una hoja de ruta" o durante la fase de diseño de funciones se da cuenta de que el requisito es demasiado grande para caber en una función.
