Stage 2 of the issue workflow – read the bug report + read the code, pinpoint the real root cause and assess the fix risk, then give the user 2–3 repair options to choose from. This stage does **not** start coding—after the analysis, show the user the conclusions first; only after the user confirms the plan do we move to stage 3. Prerequisite: cs-issue-report already completed. Trigger: user says “analyze this bug,” “find the root cause,” “locate the problem,” and the file {slug}-report.md exists in the issue folder.
