When fixing bugs, enter this sub-process—moving from "discovered a problem" in verbal description to a closed loop of verified fix, leaving behind three documents in between: problem report, root cause analysis, and fix record. This process adds a buffer between "seeing the problem" and "touching the code," preventing several common failures: the problem description in your head disappears after fixing, patching the surface without root cause analysis, uncontrolled scope creep with no traceability, and fixing without verification leaving you unsure if it worked. This skill only handles routing, deciding which of report/analyze/fix to enter based on existing artifacts. Simple issues with obvious root causes take the fast lane, skipping the middle two steps and leaving only a fix-note.
