Этап 3 рабочего процесса проблемы — исправьте код в назначенных точках в соответствии с подтвержденной основной причиной и решением, проверьте результат и заархивируйте его, написав {slug}-fix-note.md. Это закрытие рабочего процесса по проблеме — отсутствие цикла проверки = рабочий процесс не завершен. Две точки входа: стандартный путь запускается из cs-issue-analyze (с существующим файлом {slug}-anaанализ.md), быстрый путь запускается непосредственно из cs-issue-report (нет {slug}-anaанализ.md, основная причина уже была определена путем чтения кода AI на этапе отчета). Сценарии срабатывания: пользователь говорит: «Начни исправлять ошибку», «Исправь для каждого анализа», «Начни кодировать исправление». Во время исправления прикасайтесь только к файлам, объявленным в решении — никакого оппортунистического рефакторинга, никаких новых абстракций — эти действия выведут область действия за пределы возможности отслеживания.
