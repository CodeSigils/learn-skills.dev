Phase 3 of the issue workflow — implement targeted code fixes based on confirmed root causes and solutions, verify results, and document in {slug}-fix-note.md. This closes the issue workflow loop — without verification closure, the workflow remains incomplete. Two entry points: the standard path triggered from cs-issue-analyze (with existing {slug}-analysis.md), and the fast track triggered directly from cs-issue-report (no {slug}-analysis.md, root cause already determined by AI code reading during report phase). Trigger scenarios: user says "start fixing bug", "fix according to analysis", or "start coding changes". During fixes, only modify files declared in the solution — no opportunistic optimizations, no new abstractions — these actions would expand scope beyond traceability.
