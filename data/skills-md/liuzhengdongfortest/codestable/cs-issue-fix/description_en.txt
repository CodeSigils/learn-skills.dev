Issue workflow stage 3—fix the code at the designated points according to the confirmed root cause and solution, verify the result, and archive it by writing {slug}-fix-note.md. This is the closure of the issue workflow—no verification loop = workflow incomplete. Two entry points: the standard path is triggered from cs-issue-analyze (with an existing {slug}-analysis.md), the fast track is triggered directly from cs-issue-report (no {slug}-analysis.md, the root cause was already identified by AI code reading in the report stage). Triggering scenarios: user says "start fixing the bug", "fix per analysis", "start coding the fix". During fixing, only touch the files declared in the solution—no opportunistic refactoring, no new abstractions—these actions would diffuse the scope beyond traceability.
