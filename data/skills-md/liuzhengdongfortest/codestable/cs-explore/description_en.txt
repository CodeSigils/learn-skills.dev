Perform a targeted code exploration of the repo, turning the “ask → read code → draw conclusion” cycle into searchable evidence so the next similar question can reuse it. Three types: question (investigate code around a specific issue and state a conclusion), module-overview (map a module’s structure / boundaries / entry points / dependencies), spike (lightweight tech probe of several possible directions, no final decision). Trigger phrases: user says “explore first”, “how is X implemented in this repo”, “quickly get familiar with this module”, “archive the exploration”. Differences from learning / tricks / decisions see `codestable/reference/system-overview.md`.
