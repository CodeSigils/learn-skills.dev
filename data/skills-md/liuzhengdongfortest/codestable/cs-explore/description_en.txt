Do a targeted code exploration of the repository, turning the "ask → read code → draw conclusion" process into retrievable evidence that can be directly reused for similar questions next time. Three types: question (investigate code around a specific issue and provide conclusion), module-overview (map out a module's structure / boundaries / entry points / dependencies), spike (lightweight technical exploration of multiple possible directions without making final decisions). Trigger scenarios: user says "explore first", "how is X implemented in this repo", "quickly familiarize with this module", "archive exploration results". How this differs from learning / tricks / decisions: see `codestable/reference/system-overview.md`.
