При оптимизации кода введите этот подпроцесс — обработку работы, где «поведение остается прежним, структура меняется» (структура/производительность/читаемость). Замените подход «случайный рефакторинг ИИ» для оптимизации одного модуля на «сначала просмотрите контрольный список, подтвердите каждый элемент с пользователем, выполняйте шаг за шагом, используя библиотеку методов, и получайте одобрение человека на каждом этапе». Срабатывает, когда пользователь говорит такие вещи, как «оптимизировать/рефакторить/переписать/разделить/производительность низкая/код слишком длинный» без каких-либо изменений поведения. Не обрабатывать новые требования (проходить через функции), не обрабатывать ошибки (проходить через проблемы), не обрабатывать межмодульные архитектурные перестановки (проходить через архитектуру + решения).
