프로젝트 아키텍처 센터의 원스톱 기술: `codestable/architecture/`에서 시스템 맵을 유지 관리합니다. **현재 상태만 기록하고 미래 계획은 기록하지 않습니다**. 주요 경로는 코드와 동기화된 기능 수용 재작성 문서입니다. 이 기술은 백업 사전 대응 항목으로, 'update'(기존 문서를 최신 코드 상태로 새로 고침, 가장 일반적임) / 'check'(읽기 전용, 문제 목록 생성) / 'backfill'(존재하지만 문서화되지 않은 모듈/하위 시스템에 대한 문서 작성)의 세 가지 모드를 제공합니다. **"어떤 레이어가 추가될지/다음에 X 모듈로 분할될지"를 처리하지 않습니다. 이는 cs-roadmap에 속합니다**. 세 가지 하위 목표로 더 자세히 분할된 것을 확인하세요. 단일 기능 디자인은 자체 일관성이 있고 디자인은 코드와 일치하며 'codestable/architecture/' 아래의 여러 문서는 서로 동의합니다. 단일 대상 규칙 - 하나의 문서만 터치하거나 실행당 하나의 목표만 확인합니다. 사용자가 "아키텍처 폴더 새로 고침", "기존이지만 문서화되지 않은 모듈의 구조를 적어 줘", "아키텍처 검사 실행", "디자인이 내부적으로 일관성이 있는지", "계획이 코드와 일치합니까", "아키텍처 폴더의 문서가 서로 모순됩니까"라고 말할 때 또는 기능 설계/기능 수용/구현 단계에서 진행하기 전에 필요한 아키텍처 작업을 찾을 때 트리거됩니다. 사용자가 "X 아키텍처로 리팩토링하고 싶습니다"(대상 상태)라고 말합니다. → 이 스킬을 건너뛰고 cs-roadmap으로 이동합니다.
