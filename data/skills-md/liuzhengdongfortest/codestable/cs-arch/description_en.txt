One-stop skill of the Project Architecture Center, maintaining the **current-state-only, no-plans** system map at `codestable/architecture/`. The main path is feature-acceptance following code sync-back; this skill is the backup proactive entry with three modes: `update` (refresh existing docs according to latest code state, most commonly used) / `check` (read-only, generates issue list) / `backfill` (create docs for modules/subsystems that exist but never had documentation). **Does NOT handle "what layers will be added in the future / next step split into X modules" — those belong to cs-roadmap**. Check further splits into three sub-goals: a feature design is self-consistent, design matches code, and multiple documents under `codestable/architecture/` are consistent with each other. Single-target rule — only modify one document or check one goal at a time. Trigger scenarios: user says "refresh architecture directory", "write down the structure of this existing but undocumented module", "do architecture check", "is design internally consistent", "does the plan match the code", "are there conflicts among documents in the architecture folder", or when feature-design / feature-acceptance / implement phase discovers an architecture action is needed before proceeding. User says "I want to refactor to X architecture" as target state → does not use this skill, redirect to cs-roadmap.
