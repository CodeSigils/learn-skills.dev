One-stop skill of the Project Architecture Center: maintain the system map at `codestable/architecture/`—**records only the current state, never future plans**. The main path is feature-acceptance rewriting docs in sync with code; this skill is a backup proactive entry, offering three modes: `update` (refresh existing doc to latest code state, most common) / `check` (read-only, produces issue list) / `backfill` (write a doc for a module/subsystem that exists but has never been documented). **Does not handle “what layers will be added / next split into X modules”—those belong to cs-roadmap**. check further splits into three sub-goals: a single feature design is self-consistent, design matches code, and multiple docs under `codestable/architecture/` agree with one another. Single-target rule—touch only one doc or check only one goal per run. Triggered when user says “refresh architecture folder”, “write down the structure of this existing but undocumented module”, “run architecture check”, “is the design internally consistent”, “does the plan match the code”, “do docs in architecture folder contradict each other”, or when feature-design / feature-acceptance / implement stages find an architecture action needed before proceeding. User says “I want to refactor into X architecture” (target state) → skip this skill, go to cs-roadmap.
