Compétence unique du Project Architecture Center : maintenir la carte du système dans `codestable/architecture/` — **enregistre uniquement l'état actuel, jamais les plans futurs**. Le chemin principal est la réécriture des documents d'acceptation des fonctionnalités en synchronisation avec le code ; cette compétence est une entrée proactive de sauvegarde, offrant trois modes : « mettre à jour » (actualiser le document existant avec le dernier état du code, le plus courant) / « vérifier » (lecture seule, produit une liste de problèmes) / « remplir » (écrire un document pour un module/sous-système qui existe mais qui n'a jamais été documenté). **Ne gère pas « quelles couches seront ajoutées / ensuite divisées en modules X » – celles-ci appartiennent à cs-roadmap**. check se divise en trois sous-objectifs : une conception de fonctionnalité unique est cohérente avec elle-même, la conception correspond au code et plusieurs documents sous « codestable/architecture/ » sont d'accord les uns avec les autres. Règle à cible unique : touchez un seul document ou cochez un seul objectif par course. Déclenché lorsque l'utilisateur dit « actualiser le dossier d'architecture », « écrire la structure de ce module existant mais non documenté », « exécuter une vérification de l'architecture », « la conception est-elle cohérente en interne », « le plan correspond-il au code », « les documents du dossier d'architecture se contredisent-ils » ou lorsque les étapes de conception/acceptation de fonctionnalités/implémentation trouvent une action d'architecture nécessaire avant de continuer. L'utilisateur dit « Je souhaite refactoriser l'architecture X » (état cible) → ignorez cette compétence, accédez à cs-roadmap.
