Habilidad integral del Centro de Arquitectura de Proyectos: mantener el mapa del sistema en `codestable/architecture/`: **registra solo el estado actual, nunca los planes futuros**. El camino principal es reescribir documentos con aceptación de funciones en sincronía con el código; esta habilidad es una entrada proactiva de respaldo, que ofrece tres modos: `actualizar` (actualizar el documento existente al último estado del código, el más común) / `verificar` (solo lectura, produce una lista de problemas) / `rellenar` (escribir un documento para un módulo/subsistema que existe pero que nunca ha sido documentado). **No maneja “qué capas se agregarán/a continuación se dividirán en X módulos”; esos pertenecen a cs-roadmap**. Verifique además que se divide en tres subobjetivos: el diseño de una sola característica es autoconsistente, el diseño coincide con el código y varios documentos en `codestable/architecture/` concuerdan entre sí. Regla de objetivo único: toque solo un documento o marque solo un objetivo por carrera. Se activa cuando el usuario dice "actualizar la carpeta de arquitectura", "escribir la estructura de este módulo existente pero no documentado", "ejecutar verificación de arquitectura", "el diseño es internamente consistente", "el plan coincide con el código", "los documentos en la carpeta de arquitectura se contradicen entre sí" o cuando las etapas de diseño de características/aceptación de características/implementación encuentran una acción de arquitectura necesaria antes de continuar. El usuario dice "Quiero refactorizar en la arquitectura X" (estado objetivo) → omita esta habilidad, vaya a cs-roadmap.
