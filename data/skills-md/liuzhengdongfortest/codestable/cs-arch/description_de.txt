One-Stop-Fähigkeit des Project Architecture Center: Pflegen Sie die Systemkarte unter „codestable/architecture/“ – **zeichnet nur den aktuellen Status auf, niemals zukünftige Pläne**. Der Hauptpfad ist das Umschreiben von Dokumenten zur Funktionsakzeptanz synchron mit dem Code. Bei diesem Skill handelt es sich um einen proaktiven Backup-Eintrag, der drei Modi bietet: „Aktualisieren“ (vorhandenes Dokument auf den neuesten Codestand aktualisieren, am häufigsten) / „Überprüfen“ (schreibgeschützt, erstellt eine Problemliste) / „Backfill“ (ein Dokument für ein Modul/Subsystem schreiben, das existiert, aber noch nie dokumentiert wurde). **Behandelt nicht „welche Ebenen hinzugefügt / als nächstes in X-Module aufgeteilt werden“ – diese gehören zur CS-Roadmap**. check gliedert sich weiter in drei Unterziele: Ein einzelnes Feature-Design ist selbstkonsistent, Design stimmt mit Code überein und mehrere Dokumente unter „codestable/architecture/“ stimmen miteinander überein. Einzelzielregel: Berühren Sie nur ein Dokument oder überprüfen Sie nur ein Ziel pro Lauf. Wird ausgelöst, wenn der Benutzer sagt: „Architekturordner aktualisieren“, „Struktur dieses vorhandenen, aber nicht dokumentierten Moduls aufschreiben“, „Architekturprüfung durchführen“, „Ist das Design intern konsistent“, „Stimmt der Plan mit dem Code überein“, „Widersprechen sich die Dokumente im Architekturordner?“ oder wenn in den Phasen Feature-Design/Feature-Akzeptanz/Implementierung festgestellt wird, dass eine Architekturaktion erforderlich ist, bevor fortgefahren wird. Der Benutzer sagt: „Ich möchte in die X-Architektur umgestalten“ (Zielzustand) → überspringen Sie diesen Skill und gehen Sie zu cs-roadmap.
