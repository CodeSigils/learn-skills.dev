Étape 1 du flux de travail : transformez le problème dans l'esprit de l'utilisateur en un {slug}-report.md reproductible et traçable via la conversation. L’IA demande seulement « qu’avez-vous vu, comment reproduire, que devrait-il se passer », sans deviner la cause profonde (c’est l’étape 2). Cette étape est également le seul point de contrôle formel pour décider de la voie rapide ou standard : après avoir lu le code pertinent en fonction de la description de l'utilisateur, si le correctif est évident et trivial, dites directement à l'utilisateur de suivre la voie rapide. Déclencheur : l'utilisateur dit « signaler un problème », « enregistrer ce bug », « J'ai trouvé un problème ». Point de départ du workflow des tickets, aucun prérequis.
