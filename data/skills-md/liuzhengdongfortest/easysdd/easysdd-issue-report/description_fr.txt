Phase 1 du processus de problème — Par le dialogue, transformez le problème dans l'esprit de l'utilisateur en un {slug}-report.md reproductible et traçable. L'IA demande ici uniquement « ce qui a été vu, comment reproduire, ce qui devrait arriver », sans deviner les causes profondes pour l'utilisateur (c'est le travail de la phase 2). Cette phase est également le seul point de décision formel pour déterminer la voie rapide par rapport à la voie standard : sur la base de la description de l'utilisateur, lisez d'abord le code correspondant ; s'il peut être identifié d'un seul coup d'œil avec des modifications minimes, informez directement l'utilisateur d'emprunter la voie rapide. Scénarios de déclenchement : l'utilisateur dit « signaler un problème », « documenter ce bug », « J'ai trouvé un problème ». Le point de départ du workflow des tickets, sans prérequis.
