Führen Sie einen Architektur-Gesundheitscheck durch und wählen Sie eine von drei Optionen: Überprüfen Sie, ob ein einzelnes Designdokument intern konsistent ist (Terminologie, Verträge und Ausführungsschritte stehen nicht im Widerspruch); Überprüfen Sie, ob Design und Code übereinstimmen (versprochene Elemente werden tatsächlich im Code implementiert); Überprüfen Sie, ob mehrere Architekturdokumente unter „easysdd/architecture/“ miteinander konsistent sind (Terminologie, Modulgrenzen und dokumentübergreifende Referenzen stehen nicht im Widerspruch). Dieser Skill erstellt nur Problemlisten und Korrekturempfehlungen, nimmt keine Änderungen vor. Nehmen Sie jeweils nur ein Ziel ins Visier, es ist nicht erlaubt, das andere zu überprüfen, während wir schon dabei sind. Auslöseszenarien: Der Benutzer sagt „Architekturprüfung durchführen“, „Ist das Design intern konsistent“, „Plan und Code stimmen überein“, „Konfliktieren Dokumente im Architekturordner miteinander“ oder möchte eine Integritätsprüfung durchführen, bevor er mit der Implementierungs-/Abnahmephase fortfährt.
