Analyse des causes profondes en 4 phases fondée sur des données probantes : reproduire, isoler, identifier,
Vérifiez. À utiliser lorsque l'utilisateur signale un bug, que les tests échouent, que du code est introduit
les régressions ou les problèmes de production nécessitent une enquête. Utiliser pour "débogage",
"Correction d'un bug", "Pourquoi cet échec", "Cause première" ou "Tests interrompus". NE PAS
utiliser pour les demandes de fonctionnalités, la refactorisation ou l'optimisation des performances sans
un symptôme de bug spécifique.
