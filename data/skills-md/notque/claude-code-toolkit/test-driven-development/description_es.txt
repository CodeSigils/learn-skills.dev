Ciclo ROJO-VERDE-REFACTOR con puertas de fase estrictas. Primero escriba la prueba fallida,
implemente el código mínimo para aprobar, luego refactorice mientras mantiene las pruebas en verde.
Úselo al implementar nuevas funciones, corregir errores con un enfoque de prueba primero,
mejorando la cobertura de la prueba, o cuando el usuario menciona TDD. Usar para "TDD", "prueba
primero", "refactorizar rojo verde", "escribir pruebas" o "implementar con pruebas".
NO lo use para depurar fallas existentes (use depuración sistemática) o
para refactorizar sin nuevas pruebas (use refactorización sistemática).
