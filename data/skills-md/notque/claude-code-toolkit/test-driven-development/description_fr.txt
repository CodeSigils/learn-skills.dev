Cycle ROUGE-VERT-REFACTEUR avec portes de phase strictes. Écrivez d'abord le test qui échoue,
implémentez le code minimum à réussir, puis refactorisez tout en gardant les tests verts.
À utiliser lors de la mise en œuvre de nouvelles fonctionnalités, de la correction de bugs avec une approche axée sur le test,
améliorer la couverture des tests, ou lorsque l'utilisateur mentionne TDD. Utiliser pour "TDD", "test
premier", "refactor rouge vert", "écrire des tests" ou "implémenter avec des tests".
Ne PAS utiliser pour déboguer les échecs existants (utiliser le débogage systématique) ou
pour le refactoring sans nouveaux tests (utilisez le refactoring systématique).
