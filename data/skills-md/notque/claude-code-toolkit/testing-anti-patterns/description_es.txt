Identificar y corregir errores de prueba comunes en la unidad, la integración y E2E
conjuntos de pruebas. Úselo cuando las pruebas sean inestables, quebradizas, excesivamente burladas, dependientes del orden,
lento, mal nombrado o que proporciona falsa confianza. Úselo para "probar el olor",
"prueba frágil", "prueba inestable", "burla excesiva", "prueba antipatrón" o
"pruebas omitidas". NO lo use para escribir nuevas pruebas desde cero (use
desarrollo basado en pruebas), arquitectura de refactorización (use refactorización sistemática),
o perfiles de rendimiento sin un síntoma de calidad de prueba específico.
