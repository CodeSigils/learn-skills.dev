重構 TypeScript 的副作用，使失敗和 I/O 成為傳回類型中的值，而不是拋出例外和隱藏導入。當函數拋出且呼叫者無法從簽名中分辨出來時，當 try/catch 區塊嵌套或吞下錯誤時，當錯誤類型在到達 UI 時為任何類型或未知時，當驗證在第一次失敗時停止但表單需要每個訊息時，當單元測試無法在沒有存根或模擬模組的情況下運行時，當非同步工作需要重試工作時，會變得尷尬，或者當有人問“如何在不進行模擬的情況下測試它”時，請使用此技能， '應該在哪裡處理錯誤'，'如何返回錯誤而不是拋出錯誤'。提供從普通結果聯合到注入解釋器的五級採用階梯，並明確指導哪些級別在生產 TypeScript 中獲得回報，哪些是值得學習而不是構建的概念。
