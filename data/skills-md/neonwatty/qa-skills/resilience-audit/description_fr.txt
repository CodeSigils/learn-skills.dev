Audite les applications Web pour vérifier leur résilience face aux comportements inattendus des utilisateurs : accidentels, extrêmes et chaotiques. Utilisez-le lorsque l'utilisateur dit "audit de résilience", "audit du chaos", "qu'est-ce qui pourrait mal se passer", "audit de cas extrême", "à l'épreuve des idiots", "casser cette application", "tester sous contrainte l'UX" ou "trouver des impasses UX". Explorez la base de code pour cartographier les flux d'utilisateurs, puis identifie systématiquement les façons dont l'application peut se bloquer, rester bloquée ou se comporter de manière inattendue lorsque les utilisateurs font des choses que le développeur n'avait pas anticipées. Couvre les impasses de navigation, les doubles soumissions, les opérations interrompues, les problèmes multi-appareils, les cas limites d'entrée, les bogues de synchronisation, les lacunes de récupération d'erreur et les modèles d'utilisation involontaire. Produit un rapport hiérarchisé avec les résultats, les emplacements de code et les recommandations de correctifs, puis vérifie éventuellement les résultats de manière interactive dans un navigateur.
