Discipline stricte pour un travail visant à modifier les comportements : rédiger d'abord un test qui échoue, observer l'échec, puis écrire un code de production minimal ; supprimer le code de production écrit avant qu’un test défaillant ne soit observé. Distinct de la suite de tests-garantie (couverture/échafaudage post-hoc). Référencé par les étapes d’exécution PDCA. Déclencheurs — 「测试先行」「先写失败测试」「红绿重构」「TDD 铁律」「test-first」 / discipline test-first, échec au test en premier. Ne PAS utiliser comme alias de nom pour tdd ou développement piloté par les tests.
