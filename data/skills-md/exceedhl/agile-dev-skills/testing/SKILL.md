# 自动化测试编写 (Automated Testing)

核心原则和规范，与具体语言和框架无关。

> **上游**: 建议先完成 **tech-design** skill 的架构设计，基于架构来规划测试策略。
>
> **上游**: 测试场景应对应 **product-requirements** skill 中的 User Stories 和验收标准。

---

## 交互式引导 (Interactive Discovery)

开始编写测试前，确认以下上下文：

1. **测试类型**: 需要写哪种测试？（unit / integration / E2E / performance）
2. **被测对象**: 测试哪个模块或功能？对应哪个 User Story？
3. **现有测试**: 项目中已有测试吗？用的什么框架？
4. **环境依赖**: 需要外部服务（数据库、API）吗？如何 mock 或 seed？
5. **覆盖目标**: 有具体的覆盖率要求吗？重点覆盖哪些风险区域？

## 一、文件组织与命名

```
tests/
├── unit/            # 隔离的函数/模块级测试
├── integration/     # 多模块/服务间的交互测试
├── scenarios/       # 端到端用户场景测试
├── performance/     # 负载、响应时间、吞吐量
└── fixtures/        # 共享的测试数据、setup 脚本
```

### 命名原则
- **文件名反映被测对象**: 如 `repair-json.test.ts`
- **场景文件反映业务故事**: 如 `stars.spec.ts`、`search-intelligence.spec.ts`
- **Fixture 职责清晰**: 认证 setup、数据 seeding、常量定义分开

## 二、场景覆盖原则

### Happy Path + Sad Path 并行覆盖

每个测试场景**必须**同时包含正常流程和异常流程。

### 边界条件清单

| 数据类型 | 检查项 |
|---|---|
| **字符串** | 空串、超长、特殊字符、Unicode、注入向量 |
| **数字** | 零、负数、极大/极小值、浮点精度、NaN |
| **集合** | 空集、单元素、大量元素、重复、嵌套 |
| **时间** | 跨时区、夏令时、闰年、格式不一致 |
| **状态** | 初始、中间、终态、并发修改、幂等性 |

### AAA 结构
1. **Arrange**: 准备环境和数据
2. **Act**: 执行被测行为
3. **Assert**: 验证具体预期值（拒绝模糊断言）

## 三、测试数据设计 (Golden Dataset)

### 设计原则
- **固定标识符**: 使用常量 UUID，确保可重复和可调试
- **覆盖所有分类**: 每个业务分类至少一条测试数据
- **时间跨度**: 包含不同时间段的数据

### 语义陷阱 (Semantic Traps)

| 陷阱类型 | 说明 | 示例 |
|---|---|---|
| **一词多义** | 相同词不同语境 | "Bank" → 银行 vs 河岸 |
| **实体混淆** | 同名不同领域 | "Apple" → 科技公司 vs 水果 |
| **同义替换** | 不同措辞同一概念 | "心肌梗死" vs "心脏病发作" |
| **精确匹配干扰** | 子串相同语义不同 | 标题包含相同关键词但主题完全不同 |
| **噪声数据** | 与目标无关 | 验证系统不会误匹配 |

### Seeding 规范
- **幂等性**: 使用 upsert，可安全重复运行
- **独立性**: 测试数据与生产数据完全隔离
- **最小化**: 只创建当前场景必需的数据

## 四、Web 应用测试专项

### 选择器优先级（从高到低）
1. **专用测试属性** (`data-id`, `data-testid`) — 最稳定
2. **语义角色** (`getByRole`) — 兼顾无障碍性
3. **文本内容** (`getByText`) — 适用于稳定文案
4. **CSS 类名 / XPath** — ❌ 避免使用

### 测试属性命名
- 语义化连字符: `data-id="topic-link-AI"`, `data-id="star-button"`
- 列表项加前缀: `data-id="briefing-item-{id}"`
- 面板用角色: `data-id="event-detail-panel"`

### 等待策略
- ❌ 拒绝固定等待 (`sleep`/`waitForTimeout`)
- ✅ 使用条件等待（元素可见、请求完成、状态变更）
- ✅ 设置有业务含义的合理超时

## 五、文档同步

- **新增功能** → 必须同时编写对应测试
- **修改功能** → 检查并更新受影响的测试
- **修复 Bug** → 先补复现测试，再修复代码（回归防护）
- **新发现边界用例** → 加入 Golden Dataset
