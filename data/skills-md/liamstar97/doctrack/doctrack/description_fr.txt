Maintient les connaissances persistantes de la base de code au fil des sessions grâce à un graphique de connaissances structuré stocké dans un coffre-fort Obsidian local (.doctrack/). Utilisez cette compétence chaque fois que vous venez d'apporter des modifications significatives au code (nouvelles fonctionnalités, composants modifiés, refactoring, corrections de bugs) pour mettre à jour la documentation du projet. Utilisez-le également lorsque l'utilisateur demande de documenter le code, de mettre à jour les documents, de synchroniser la documentation, d'initialiser la documentation d'un projet existant ou lorsque vous souhaitez comprendre la structure de la base de code existante au début d'une session. Cette compétence doit être utilisée de manière proactive après toute modification significative du code : n'attendez pas que l'utilisateur le demande. Si vous avez modifié le code, mettez à jour la documentation. Considérez-le comme votre système de mémoire à long terme : lisez avant de travailler, écrivez après avoir modifié. Utilisez-le également lorsqu'un utilisateur dit « doctrack init », « initialiser les documents », « documenter ce projet » ou souhaite amorcer la documentation pour une base de code qui n'a pas encore de .doctrack/vault.
