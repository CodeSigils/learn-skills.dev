Mantiene el conocimiento de la base de código persistente a lo largo de las sesiones a través de un gráfico de conocimiento estructurado almacenado en una bóveda de Obsidian local (.doctrack/). Utilice esta habilidad siempre que haya realizado cambios significativos en el código (nuevas funciones, componentes modificados, refactorización, corrección de errores) para actualizar la documentación del proyecto. Úselo también cuando el usuario solicite documentar código, actualizar documentos, sincronizar documentación, inicializar documentación para un proyecto existente o cuando desee comprender la estructura base del código existente al inicio de una sesión. Esta habilidad debe usarse de manera proactiva después de cualquier modificación importante del código; no espere a que el usuario pregunte. Si cambió el código, actualice los documentos. Piense en ello como su sistema de memoria a largo plazo: lea antes de trabajar, escriba después de cambiar. También use esto cuando un usuario diga "doctrack init", "inicializar documentos", "documentar este proyecto" o quiera iniciar la documentación para una base de código que aún no tiene .doctrack/vault.
