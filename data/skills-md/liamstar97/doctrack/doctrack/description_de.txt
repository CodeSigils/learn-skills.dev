Behält persistentes Codebasiswissen über Sitzungen hinweg durch einen strukturierten Wissensgraphen, der in einem lokalen Obsidian-Tresor (.doctrack/) gespeichert ist. Nutzen Sie diese Fähigkeit immer dann, wenn Sie gerade wichtige Codeänderungen (neue Funktionen, geänderte Komponenten, Refactoring, Fehlerbehebungen) vorgenommen haben, um die Projektdokumentation zu aktualisieren. Verwenden Sie es auch, wenn der Benutzer Code dokumentieren, Dokumente aktualisieren, Dokumentation synchronisieren, Dokumentation für ein vorhandenes Projekt initialisieren möchte oder wenn Sie zu Beginn einer Sitzung die vorhandene Codebasisstruktur verstehen möchten. Diese Fähigkeit sollte proaktiv nach jeder wesentlichen Codeänderung eingesetzt werden – warten Sie nicht, bis der Benutzer danach fragt. Wenn Sie den Code geändert haben, aktualisieren Sie die Dokumente. Betrachten Sie es als Ihr Langzeitgedächtnis: Lesen Sie vor der Arbeit, schreiben Sie nach dem Ändern. Verwenden Sie dies auch, wenn ein Benutzer „doctrack init“, „docs initialisieren“, „dieses Projekt dokumentieren“ sagt oder die Dokumentation für eine Codebasis booten möchte, die noch kein .doctrack/vault hat.
