Google の開発者ドキュメント スタイル ガイドとテクニカル ライティング コースを使用して、開発者ドキュメントを監査、作成、改善します。ユーザーが「ドキュメントを監査する」、「この README を確認する」、「README を書く」、「入門ガイド」、「ハウツーまたはチュートリアル」、「API リファレンス」、「ドキュメント文字列」、「CLI ヘルプ テキスト」、「変更ログまたはリリース ノート」、「移行ガイド」、または「ドキュメントがわかりにくい」などのスタイル ガイドを指定していない場合でも、ドキュメント作業にこのスキルを使用します。また、コードからドキュメントを作成する場合、明確にするためにドキュメントを書き直す場合、見出し、手順、またはコード サンプルを修正する場合、またはドキュメント セット全体で一貫した音声と用語を強制する場合にも使用します。ドキュメントを単独で編集するよりも推奨されます。読み手とドキュメントの種類の適合、二人称と能動態、手順、見出し、リストと表、コード サンプルとプレースホルダー、リンク テキスト、通知、単語リスト、時代を超えたドキュメント、アクセシビリティをカバーします。コードのコメントと名前については、「クリーンコード」を参照してください。マーケティングまたはランディング ページのコピーについては、storybrand-messaging を参照してください。
