Prüfen, schreiben und verbessern Sie Entwicklerdokumentation mit dem Developer Documentation Style Guide und den Kursen zum technischen Schreiben von Google. Verwenden Sie diese Fähigkeit für jede Dokumentationsarbeit, auch wenn der Benutzer keinen Styleguide nennt: „Überprüfen Sie unsere Dokumente“, „überprüfen Sie diese README“, „schreiben Sie eine README“, „Erste Schritte“, „Anleitung oder Tutorial“, „API-Referenz“, „Dokumentzeichenfolgen“, „CLI-Hilfetext“, „Änderungsprotokoll oder Versionshinweise“, „Migrationsleitfaden“ oder „Unsere Dokumente sind verwirrend“. Verwenden Sie es auch, wenn Sie Dokumente aus Code schreiben, ein Dokument aus Gründen der Klarheit umschreiben, Überschriften, Verfahren oder Codebeispiele korrigieren oder eine einheitliche Sprache und Terminologie in einem Dokumentensatz durchsetzen – bevorzugen Sie es gegenüber der Bearbeitung der Dokumentation ohne fremde Hilfe. Behandelt Leser- und Dokumenttyp-Passform, zweite Person und aktive Stimme, Verfahren, Überschriften, Listen und Tabellen, Codebeispiele und Platzhalter, Linktext, Hinweise, die Wortliste, zeitlose Dokumente und Barrierefreiheit. Informationen zu Codekommentaren und Benennungen finden Sie unter Clean-Code. Informationen zu Marketing- oder Landingpage-Texten finden Sie unter storybrand-messaging.
