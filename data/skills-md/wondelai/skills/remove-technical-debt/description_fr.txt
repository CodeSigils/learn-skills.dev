Voyage guidé depuis une grande base de code ancienne que tout le monde craint de toucher vers une base de code qui peut être modifiée en toute sécurité, lisible, délimitée et résiliente - mise en place sans réécriture. Orchestre huit compétences phase par phase - travailler avec du code hérité, des modèles de refactorisation, du code propre, de la philosophie de conception logicielle, de l'architecture propre, du programmeur pragmatique, du release-it, de la conception axée sur le domaine - en posant des questions à l'utilisateur à chaque point de décision et en enregistrant les résultats dans le dossier docs/du projet (TESTING.md, TECH-DEBT.md, REMOVE-TECHNICAL-DEBT-PLAN.md) afin que le voyage reprenne au fil des sessions. À utiliser lorsque l'utilisateur souhaite apprivoiser une base de code existante, rembourser sa dette technique en toute sécurité, éviter une réécriture radicale ou dire « nous avons peur de toucher à ce code ». Pour un nouveau prototype ou une application codée par ambiance en cours de production, utilisez better-code-quality ; pour une structure entièrement nouvelle, utilisez l'architecture de code de conception ; pour une passe produit et UX plutôt que du code uniquement, utilisez améliorer l'application. Pour un framework isolé, invoquez cette compétence directement.
