Viaje guiado desde una base de código grande y antigua que todos temen tocar a una que sea segura de cambiar, legible, delimitada y resistente, pagada en el lugar sin necesidad de reescritura. Orquesta ocho habilidades fase por fase: trabajar con código heredado, patrones de refactorización, código limpio, filosofía de diseño de software, arquitectura limpia, programador pragmático, lanzamiento, diseño basado en dominio, haciendo preguntas al usuario en cada punto de decisión y registrando los resultados en los documentos/carpeta del proyecto (TESTING.md, TECH-DEBT.md, REMOVE-TECHNICAL-DEBT-PLAN.md) para que el viaje se reanuda entre sesiones. Úselo cuando el usuario quiera controlar una base de código heredada, pagar la deuda técnica de manera segura, evitar una reescritura importante o decir "tenemos miedo de tocar este código". Para un prototipo nuevo o una aplicación codificada por vibración que vaya a producción, utilice la calidad del código mejorado; para estructuras totalmente nuevas, utilice diseño-código-arquitectura; para obtener un pase de producto y UX en lugar de solo código, use la aplicación de mejora. Para un marco de trabajo aislado, invoque esa habilidad directamente.
