Geführte Reise von einer großen, veralteten Codebasis, vor deren Berührung sich jeder fürchtet, zu einer Codebasis, die sich sicher ändern lässt, lesbar, begrenzt und belastbar ist – und an Ort und Stelle ohne Umschreiben abgerechnet wird. Orchestriert acht Fähigkeiten Phase für Phase – Arbeiten mit Legacy-Code, Refactoring-Mustern, Clean-Code, Software-Design-Philosophie, Clean-Architektur, pragmatischer Programmierer, Release-it, domänengesteuertes Design – stellt dem Benutzer an jedem Entscheidungspunkt Fragen und zeichnet die Ergebnisse in den Projektdokumenten/Ordnern auf (TESTING.md, TECH-DEBT.md, REMOVE-TECHNICAL-DEBT-PLAN.md), also die Reise wird sitzungsübergreifend fortgesetzt. Verwenden Sie diese Option, wenn der Benutzer eine veraltete Codebasis zähmen, technische Schulden sicher abbezahlen, eine umfassende Umschreibung vermeiden möchte oder sagt: „Wir haben Angst, diesen Code anzufassen.“ Für einen neuen Prototyp oder eine Vibe-codierte App, die in Produktion geht, verwenden Sie Improve-Code-Quality; Verwenden Sie für die Greenfield-Struktur die Design-Code-Architektur. Verwenden Sie für einen Produkt- und UX-Pass statt nur für Code die Improve-App. Rufen Sie diese Fähigkeit für ein isoliertes Framework direkt auf.
