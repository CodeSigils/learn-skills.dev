Ändern und testen Sie ungetestete Codebasen sicher mit „Working Effectively with Legacy Code“ von Michael C. Feathers. Wird verwendet, wenn der Benutzer „Legacy-Code“, „keine Tests“, „ungetestete Codebasis“, „Wie teste ich das“, „Seams“, „Charakterisierungstests“, „Sprout-Methode“, „Angst, diesen Code zu ändern“, „Monster-Methode“ oder „Abhängigkeitsunterbrechung“ erwähnt. Wird auch ausgelöst, wenn Code ohne Tests sicher geändert wird, eine Klasse getestet wird, wenn sie von Konstruktoren, Statiken oder Singletons blockiert wird, Features zu verwickelten Modulen hinzugefügt werden oder eine inkrementelle Testabdeckung für eine alte Codebasis geplant wird. Behandelt den alten Codeänderungsalgorithmus, Seams, Charakterisierungstests, Sprout/Wrap und Techniken zum Aufbrechen von Abhängigkeiten. Informationen zum Refactoring von Code, der bereits über Tests verfügt, finden Sie unter Refactoring-Muster. Informationen zur täglichen Codequalität finden Sie unter Clean-Code.
