Modifiez et testez en toute sécurité les bases de code non testées à l'aide de « Working Effectively with Legacy Code » de Michael C. Feathers. À utiliser lorsque l'utilisateur mentionne « code hérité », « aucun test », « base de code non testée », « comment tester cela », « coutures », « tests de caractérisation », « méthode Sprout », « peur de changer ce code », « méthode monstre » ou « rupture de dépendance ». Déclenchez également lors de la modification de code sans tests en toute sécurité, lors de l'obtention d'une classe en cours de test lorsque des constructeurs, des statiques ou des singletons la bloquent, en ajoutant des fonctionnalités à des modules enchevêtrés ou en planifiant une couverture de tests incrémentielle pour une ancienne base de code. Couvre l'algorithme de changement de code existant, les coutures, les tests de caractérisation, les techniques de germination/enveloppement et de rupture de dépendance. Pour refactoriser du code qui comporte déjà des tests, voir refactoring-patterns. Pour la qualité du code au quotidien, voir clean-code.
