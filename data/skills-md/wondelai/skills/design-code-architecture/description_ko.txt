앱 아이디어에서 신중한 아키텍처(경계, 도메인 모델, 데이터 결정 및 탄력성)까지의 여정을 안내하여 비용이 많이 드는 취소 결정만 내리고 나머지는 연기합니다. 8가지 기술(클린 아키텍처, 도메인 중심 디자인, 시스템 디자인, ddia 시스템, 소프트웨어 디자인 철학, 릴리스-잇, 실용주의 프로그래머, 37신호 방식)을 단계별로 조율합니다. 모든 결정 지점에서 사용자에게 질문을 하고 결과를 프로젝트 문서/폴더(ARCHITECTURE.md, RELIABILITY.md, DESIGN-CODE-ARCHITECTURE-PLAN.md)에 기록하여 전체 여정이 재개됩니다. 세션. 사용자가 새 앱의 아키텍처를 디자인하고, 구축하기 전에 경계와 도메인 모델을 선택하고, 모놀리스와 마이크로서비스를 결정하거나 '이 앱을 어떻게 구성해야 합니까?'라고 말하고 싶을 때 사용하세요. 코드베이스가 이미 존재하는 경우, 기술 부채 제거(오래된) 또는 코드 품질 향상(새로운 프로토타입)을 사용하십시오. 아이디어가 검증되지 않은 경우 먼저 create-business 또는 create-app을 실행하세요. 격리된 하나의 프레임워크에 대해 해당 기술을 직접 호출합니다.
