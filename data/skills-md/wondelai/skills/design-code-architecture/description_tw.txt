從應用程式創意到深思熟慮的架構的指導之旅：邊界、領域模型、資料決策和彈性，只做出成本高昂的逆轉決策，並推遲其餘決策。逐步協調八項技能 - 清潔架構、領域驅動設計、系統設計、ddia 系統、軟體設計哲學、發布、實用程式設計師、37signals-way - 在每個決策點詢問使用者問題並將結果記錄在專案文件/資料夾（ARCHITECTURE.md、RELIABILITY.md、DESIGN-CODE-ARCHITECTURE-PLAN.）中當使用者想要設計新應用程式的架構、在建置之前選擇邊界和領域模型、決定單體應用或微服務，或說「我應該如何建立這個應用程式」時使用。如果程式碼庫已經存在，請使用刪除技術債務（老化）或提高程式碼品質（新原型）；如果想法未得到驗證，請先執行 create-business 或 create-app。對於一個孤立的框架，直接呼叫該技能。
