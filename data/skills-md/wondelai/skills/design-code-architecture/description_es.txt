Viaje guiado desde la idea de una aplicación hasta una arquitectura deliberada: límites, modelo de dominio, decisiones de datos y resiliencia, tomando solo las decisiones costosas de revertir y aplazando el resto. Orquesta ocho habilidades fase por fase (arquitectura limpia, diseño impulsado por dominio, diseño de sistemas, ddia-systems, filosofía de diseño de software, release-it, programador pragmático, 37signals-way) haciendo preguntas al usuario en cada punto de decisión y registrando los resultados en la carpeta/documentos del proyecto (ARCHITECTURE.md, RELIABILITY.md, DESIGN-CODE-ARCHITECTURE-PLAN.md) para que el viaje se reanude. sesiones. Úselo cuando el usuario quiera diseñar la arquitectura de una nueva aplicación, elegir límites y un modelo de dominio antes de construirla, decidir monolito versus microservicios o decir "¿cómo debo estructurar esta aplicación?". Si ya existe una base de código, utilice eliminar deuda técnica (antiguo) o mejorar la calidad del código (prototipo nuevo); Si la idea no está validada, ejecute create-business o create-app primero. Para un marco de trabajo aislado, invoque esa habilidad directamente.
