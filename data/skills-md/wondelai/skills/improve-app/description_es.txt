Viaje guiado desde una aplicación enviada que funciona pero parece difícil hasta un producto que se adapta al trabajo, fluye sin fricciones, se lee con claridad y persuade con honestidad. Orquesta nueve habilidades fase por fase: trabajos por hacer, heurística de experiencia de usuario, diseño de cosas cotidianas, refactorización de interfaz de usuario, microinteracciones, hecho para pegar, psicología de influencia, navegador de alto rendimiento, revisión de diseño de steve-jobs, formulando preguntas al usuario en cada punto de decisión y registrando los resultados en la carpeta documentos/documentos del proyecto (CUSTOMER.md, DESIGN.md, POSITIONING.md, IMPROVE-APP-PLAN.md) para que el viaje se reanude entre sesiones. Úselo cuando el usuario quiera arreglar un producto torpe, reducir la fricción de UX, mejorar la copia y las indicaciones en la aplicación, o decir "la aplicación funciona pero se siente difícil". No lo use para código, pruebas o refuerzo de producción; use mejorar la calidad del código (prototipo nuevo) o eliminar la deuda técnica (código base antiguo); aún no hay aplicación, crear-aplicación; necesita bucles de crecimiento, aplicación de crecimiento; Fricción del sitio de marketing, mejora del sitio web. Para un marco de trabajo aislado, invoque esa habilidad directamente.
