Voyage guidé d'un prototype codé par ambiance fonctionnel mais non testé à un produit prêt pour la production avec des tests, une structure propre, une limite de règles métier et une résilience à grande échelle. Orchestre neuf compétences phase par phase : travail avec du code hérité, code propre, modèles de refactorisation, philosophie de conception logicielle, architecture propre, programmeur pragmatique, release-it, conception de système, systèmes ddia - posant des questions à l'utilisateur à chaque point de décision et enregistrant les résultats dans le dossier docs/du projet (TESTING.md, TECH-DEBT.md, RELIABILITY.md, IMPROVE-CODE-QUALITY-PLAN.md) pour que le voyage reprenne au fil des sessions. À utiliser lorsque l'utilisateur souhaite renforcer un prototype généré par l'IA, ajouter des tests avant la refactorisation, rendre le code modifiable en toute sécurité ou dire « cela fonctionne sur ma machine mais j'ai peur d'y toucher ». Pour une base de code ancienne et volumineuse, utilisez remove-technical-debt ; pour décider de la structure avant de construire, utilisez le design-code-architecture ; pour un produit et un pass UX, utilisez améliorer-app. Pour un framework isolé, invoquez cette compétence directement.
