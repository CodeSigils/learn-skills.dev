Viaje guiado desde un prototipo codificado que funciona pero no ha sido probado hasta un producto listo para producción con pruebas, estructura limpia, límites de reglas comerciales y resiliencia a escala. Orquesta nueve habilidades fase por fase: trabajar con código heredado, código limpio, patrones de refactorización, filosofía de diseño de software, arquitectura limpia, programador pragmático, lanzamiento, diseño de sistemas, sistemas ddia, haciendo preguntas al usuario en cada punto de decisión y registrando los resultados en la carpeta de documentos del proyecto (TESTING.md, TECH-DEBT.md, RELIABILITY.md, IMPROVE-CODE-QUALITY-PLAN.md) para que el viaje se reanude entre sesiones. Úselo cuando el usuario quiera reforzar un prototipo generado por IA, agregar pruebas antes de refactorizar, hacer que sea seguro cambiar el código o decir "esto funciona en mi máquina pero tengo miedo de tocarlo". Para una base de código antigua y grande, utilice remove-technical-debt; para decidir la estructura antes de construir, utilice el código de diseño-arquitectura; para obtener un producto y un pase de UX, utilice la aplicación de mejora. Para un marco de trabajo aislado, invoque esa habilidad directamente.
