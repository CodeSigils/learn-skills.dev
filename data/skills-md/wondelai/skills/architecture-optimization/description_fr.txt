Voyage guidé d'une base de code fonctionnelle devenue lente et enchevêtrée à une base de code mesurablement rapide, proprement délimitée et lisible. Orchestre huit compétences phase par phase : travail avec du code hérité, architecture propre, philosophie de conception logicielle, modèles de refactorisation, conception de système, systèmes ddia, release-it, programmeur pragmatique - chaque phase applique sa méthode en ligne afin qu'elle fonctionne de manière autonome, posant des questions à l'utilisateur à chaque point de décision et enregistrant les résultats dans le dossier docs/ du projet (PERFORMANCE.md, ARCHITECTURE.md, ARCHITECTURE-OPTIMIZATION-PLAN.md) afin que le voyage reprenne au fil des sessions. À utiliser lorsque l'utilisateur souhaite rendre une application plus rapide, démêler les limites dérivées, corriger les points de terminaison et les requêtes lents, ou dit « ça fonctionne mais c'est lent et cela empire ». Pour un prototype non testé, améliorez la qualité du code ; pour une base de code ancienne que vous craignez de toucher, supprimez la dette technique ; pour les structures entièrement nouvelles, conception-code-architecture ; pour la vitesse des pages du site marketing, améliorez le site Web. Pour un framework isolé, invoquez cette compétence directement.
