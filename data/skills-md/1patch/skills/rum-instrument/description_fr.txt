Instrumentez une interface Web afin que vous puissiez répondre « qu'est-ce que cet utilisateur a réellement fait » : pages vues, clics, erreurs JS et récupérations, liés à un identifiant de session et aux traces backend qu'ils ont déclenchées. Les phrases de déclenchement incluent « ajouter RUM », « configurer la surveillance des utilisateurs réels », « instrumenter le frontend », « ajouter la surveillance du navigateur », « suivre ce que font les utilisateurs », « pourquoi cet utilisateur a-t-il vu une erreur », « ajouter le suivi de session », « instrumenter mon application React/Next/Vue » ou toute variante nommant OnePatch comme destination (« installer OnePatch dans mon frontend », « ajouter OnePatch RUM »). Installe `@onepatch/rum`, câble l'identité, décide de la propagation des traces par backend après l'avoir sondé, écrit les tests et documente le résultat dans le dépôt `TELEMETRY.md`. Pour l'instrumentation backend/serveur, utilisez plutôt « otel-instrument ».
