An executable skill for systematic reading and critical analysis of AI papers. It is suitable for reviewer‑level interpretation of a single arXiv/PDF paper, covering theoretical derivation analysis, engineering implementation breakdown, experiment audit, related literature comparison, theoretical questioning, and reproducibility assessment. The process first runs scripts that automatically parse the latest arXiv version, create an output directory, perform basic web scraping, attempt hjfy access, scrape the papers.cool page, and pre‑process references and image assets. It then generates a skeleton reading report with fixed sections and finally produces a self‑contained Markdown reading report by supplementing the paper’s original text with authentic literature.  

**Formula comprehension reinforcement:** Key formulas must be explained in context on the spot, with symbol tables, natural‑language translations, code equivalents, and minimal numerical examples inserted into the most appropriate subsections rather than piled together.  

**Table integration reinforcement:** The main results table, extended metrics table, data‑scale table, critical ablation table, and additional generalization table must be transcribed into the main report first and appear directly at the corresponding experimental‑analysis locations; they may not be relegated solely to an appendix or omitted from the final reading report.  

**Unified mathematical formula format:** Inline formulas must use `$...$`; multi‑line formulas must use separate `$$ ... $$` blocks. Do not use `\tag{}` for manual numbering inside formula blocks; equation numbers should be placed in the surrounding text. For better compatibility, prefer single‑line display formulas; if multiple lines are required, use standard LaTeX environments such as `aligned`, and forbid writing bare lines beginning with `+`, `-`, `*` inside display formulas.  

Do not use this for pure abstract rewriting, multi‑paper surveys, or free‑form elaboration without reference to the original text.
