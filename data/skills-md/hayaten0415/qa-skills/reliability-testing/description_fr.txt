Concevoir et mettre en œuvre des tests de fiabilité et de résilience (expériences de récupération, de basculement, d'injection de pannes/de chaos et d'endurance) pour la caractéristique de fiabilité ISO/IEC 25010:2023. À utiliser dans les cas suivants : « fiabilité », « résilience », « Résilience », « tests de chaos », « basculement », « reprise après sinistre », « que se passe-t-il si la base de données tombe en panne » ou définition de SLO/budgets d'erreur. Produit un plan de test de résilience avec une hypothèse d'état stationnaire (mode conception) et des expériences d'injection de fautes/scripts de tests de récupération (mode implémentation). Cette compétence couvre la récupération APRÈS une faute. Pas pour : trouver le niveau de charge auquel il tombe ou les SLO de débit/latence – utilisez des tests de performances ; ou pour protéger les actions intentionnelles destructrices/irréversibles (suppression en masse, kill switch) - utilisez l'analyse de sécurité. Connexes : tests de performances, analyse de sécurité, test-stratégie-doc.
