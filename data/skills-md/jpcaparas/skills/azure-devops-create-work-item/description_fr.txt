Rédigez un paquet d'éléments de travail Azure DevOps local à partir d'un contexte libre à l'aide des primitives d'éléments de travail officielles Azure Boards, puis enregistrez-le dans le répertoire actuel de l'appelant en tant que dossier avec « work-item.md », « context.md », « sources.md » et « metadata.json ». À utiliser lorsqu'on vous demande de créer un élément de travail Azure DevOps, un ticket de fonctionnalité, un rapport de bogue, une user story, une tâche, un problème ou une épopée à partir de notes, de discussions, d'exigences ou de rapports de défauts, en particulier lorsque la sortie doit être chirurgicale, copier-coller et lisible par un public technique et non technique. Déclenchez sur : « créer un élément de travail Azure DevOps », « transformer cela en un ticket de fonctionnalité », « rédiger un élément de travail de bogue », « créer une user story ADO », « créer un dossier d'élément de travail ». Ne PAS utiliser pour la création en direct d’Azure DevOps REST ou CLI, la migration en masse, la création de wiki ou le reporting sur l’état du projet.
