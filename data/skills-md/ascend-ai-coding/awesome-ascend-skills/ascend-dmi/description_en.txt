When a user needs to perform hardware‑level management, testing, or diagnostics on a Huawei Ascend NPU, use this skill. Typical scenarios:

- View NPU card status, temperature, and utilization
- Test memory bandwidth (h2d/d2h/d2d/p2p)
- Run compute/power benchmark tests (TFLOPS, TOPS)
- Diagnose NPU hardware faults or perform health checks
- Conduct stress tests on NPU cards (aicore, memory)
- Reset/recover a stuck or abnormal NPU card

Typical user queries (should trigger even without mentioning ascend-dmi):
- “Help me measure this server’s compute performance and bandwidth.”
- “Check the temperature and utilization of the NPU at 192.168.1.50.”
- “Run an fp16 compute test and see what the TFLOPS are.”
- “Is the d2d bandwidth up to spec?”
- “Card 3 seems to have a problem, help me diagnose it.”
- “The NPU card is stuck, reset it.”
- “Do a stress test on 8 cards.”
- “Run a power consumption test, EDP mode.”

Use this skill whenever the user wants to measure, diagnose, or manage Ascend NPU hardware directly—including checking server NPU performance (compute/bandwidth/power), diagnosing hardware faults, or resetting NPU cards. Trigger even when the user only mentions “server” + “compute/bandwidth/NPU status” without saying “ascend-dmi”.

Do NOT use for: writing NPU code, installing frameworks, debugging training issues, or Docker configuration.

Please always respond in the user’s language.
