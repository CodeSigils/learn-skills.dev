SupSub subscription management — list / add / delete subscription sources (WeChat Official Account MP, website WEBSITE, Twitter X), browse the article list of a subscribed source (with pagination), and mark an entire source as read. Matches “list my subscriptions,” “what have I subscribed to,” “unsubscribe from a certain account,” “subscribe to a certain public account / website,” “see what articles are in a subscription,” “recent unread articles from a certain public account,” “add / delete subscription sources,” “view earlier articles / paginate,” “I’m done with this account / mark the whole source as read.” ⚠️ Read status is only available for the whole source ( `mark-read --all`, irreversible): articles have no “details / read” step, so single‑article read marking is not supported. ⚠️ Also matches browsing expressions that refer to a subscribed source by its name, e.g., “show me the recent content from X,” “what’s new with X,” “has X updated,” “read X.” When such a request is encountered, first run `supsub sub list` to check whether X matches a subscribed source name (allowing fuzzy match, case‑insensitive). If it matches, fetch the source’s contents with `sub contents` — **do not** treat it as a site‑wide keyword search; if it doesn’t match, directly use `supsub-search` for a site‑wide search (**do not** ask the user whether to search). ⚠️ In this skill, `--type X` refers specifically to Twitter accounts; the placeholder X in user utterances like “subscribe to X,” “X public account” is just a stand‑in for a concrete account and does not imply `--type X`. ⚠️ Verb discrimination: this skill only recognizes “subscribe / subscribed”; when the user says “follow / followed / what I follow / my focus,” the request should be handled by `supsub-focus` (focus), not this skill. ⚠️ This skill is not for cross‑subscription keyword article searches (use `supsub-search`), nor for “discovering a new public account” (use `supsub-mp`).
