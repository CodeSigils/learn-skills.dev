Transportez une nouvelle application de produit interne JOYCO du plan à la version fonctionnelle. Verrouille d'abord un plan (celui que le développeur a déjà affiné cette session, provenant d'une autre session d'agent, ou celui que vous rédigez ensemble), puis exécute le coup d'envoi avisé - Next.js + TypeScript + Tailwind connecté au registre shadcn de JOYCO UI (@joyco/ui kit : composants, thème, polices de hub.joyco.studio), la configuration JOYCO lint et les conseils de l'agent du harnais actuel - puis construit l'application selon le plan. Invocable par l'utilisateur en tant que /joyco-app <nom-du-projet>. Déclencheurs sur "nouvelle application joyco", "démarrer un projet joyco", "lancer une application joyco interne", "construire ceci en tant qu'application joyco", "configurer joyco/ui" et sur les mentions de la CLI joyco, de l'espace de noms @joyco ou hub.joyco.studio. Ne l'utilisez PAS pour publier une expérience autonome (c'est joyco-lab) ou pour échafauder un démarreur 3D/mouvement/bibliothèque via `joyco create` — ce sont des modèles d'expérience/bibliothèque, pas des applications de produit.
