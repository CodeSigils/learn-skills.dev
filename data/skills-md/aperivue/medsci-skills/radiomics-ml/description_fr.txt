Produire ou auditer une étude radiomique / tabulaire de ML clinique - imagerie ou caractéristiques cliniques → tout apprenant classique (logistique pénalisée [LASSO / ridge / elastic-net], SVM, k-NN, Bayes naïf, LDA/QDA, arbre de décision, forêt aléatoire, boosting de gradient [XGBoost / LightGBM / CatBoost], MLP superficiel, ensembles empilés) → un résultat clinique - cela efface ainsi la barre de rigueur attendue par les évaluateurs : validation croisée imbriquée (réglage jamais sur les plis signalés), contrôle de dimensionnalité pour le régime de fonctionnalités dépassant de loin les événements, sélection de fonctionnalités à l'intérieur du pli, filtrage de stabilité des fonctionnalités (ICC / test-retest), étalonnage et validation externe/temporelle. La porte déterministe est indépendante de l'apprenant (elle audite le pipeline, pas l'algorithme). Émet un manifeste de pipeline et la porte. Le flux de travail de ML clinique réalisable en solo le plus courant : pas de GPU, pas d'ingénieur. Intègre scikit-learn / xgboost / lightgbm / catboost / pyradiomics ; il ne les réimplémente pas.
