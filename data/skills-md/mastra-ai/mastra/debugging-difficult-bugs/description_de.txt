Verwenden Sie diese Option frühzeitig, wenn Sie einen mittelschweren oder schweren Fehler beheben, insbesondere wenn Tests allein möglicherweise nicht den tatsächlichen Laufzeitfehler aufdecken. Lösen Sie dies vor der erweiterten TDD-Iteration aus, wenn ein Fehler Laufzeitstatus, Reihenfolge, Persistenz, Streaming, Parallelität, UI/manuelle Reproduktion, externe Dienste betrifft oder wenn ein roter oder neu bestandener Test das eigentliche Problem möglicherweise nicht modelliert. Überspringen Sie nur, wenn die Grundursache bereits direkt durch einen Stack-Trace oder einen deterministischen Test nachgewiesen wurde, der den tatsächlichen Laufzeitpfad durchführt.
