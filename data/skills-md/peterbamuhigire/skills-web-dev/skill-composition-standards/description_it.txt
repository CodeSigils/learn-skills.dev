Da utilizzare quando si crea una nuova competenza, si normalizza una competenza precedente o si rivede un PR di competenza: definisce lo stile interno a livello di repository (frontmatter, regole decisionali, anti-pattern, riferimenti), i contratti di output che ciascun tipo di competenza di base deve produrre e i contratti di input che ciascuna competenza specialistica deve dichiarare. Questa è la spina dorsale dell'applicazione che fa sì che il repository si comporti come un sistema, non come una libreria di documenti collegati.
