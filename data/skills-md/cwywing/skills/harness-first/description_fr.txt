Cette compétence doit être utilisée au tout début d'un nouveau projet (greenfield), avant d'écrire du code de fonctionnalité ou des invites, pour créer un harnais d'exécution auto-vérifiant à travers cinq phases fermées (modèle de réalité → limites → lien exécutable minimum → eval-first → boucle Maker-Checker), chacune produisant un fichier concret. Déclenchez-le lorsque l'utilisateur dit des choses comme "Je commence un nouveau projet", "Créons une application qui fait X", "lancez un nouvel agent/application LLM", "lancez un nouveau backend/CMS/automatisation", "architecte ceci à partir de zéro", "cela devrait-il être multi-agent ou un seul appel ?", ou "démarrer ce dépôt". Cela s’applique à tout type de projet, pas seulement à ceux d’IA. Utilisez-le même lorsque l'utilisateur dit seulement « construisons X » sans mentionner l'architecture ou l'évaluation, car le premier pas à faire dans tout nouveau projet consiste à construire le faisceau, pas l'invite ou le code. Ne l'utilisez pas pour modifier une base de code existante (une correction de bug, une fonctionnalité, une refactorisation, une révision) - coup d'envoi uniquement.
