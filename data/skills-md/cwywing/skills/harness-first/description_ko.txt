이 기술은 기능 코드나 프롬프트를 작성하기 전, 새(그린필드) 프로젝트 시작 시 5개의 게이트 단계(현실 모델 → 경계 → 최소 실행 가능 링크 → 평가 우선 → Maker-Checker 루프)를 통해 자체 검증 실행 하네스를 구축하는 데 사용해야 하며, 각 단계는 각각 구체적인 파일을 생성합니다. 사용자가 "새 프로젝트를 시작합니다", "X를 수행하는 앱을 만들어 보겠습니다", "새 에이전트/LLM 앱 시작", "새 백엔드/CMS/자동화 실행", "처음부터 설계", "이것을 다중 에이전트로 해야 할까요, 아니면 단일 호출로 할까요?" 또는 "이 저장소를 부트스트랩해야 할까요?"와 같은 말을 하면 이를 트리거합니다. 이는 AI 프로젝트뿐만 아니라 모든 프로젝트 유형에 적용됩니다. 사용자가 아키텍처나 평가에 대해 언급하지 않고 "X를 빌드하자"라고만 말하는 경우에도 이를 사용하세요. 왜냐하면 새 프로젝트에서 올바른 첫 번째 조치는 프롬프트나 코드가 아닌 하네스를 구축하는 것이기 때문입니다. 기존 코드 베이스 변경(버그 수정, 기능 1개, 리팩터링, 검토)에는 사용하지 마세요. 시작에만 사용하세요.
