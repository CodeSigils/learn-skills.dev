Usa per il Twingate Identity Firewall (IDFW) e il Twingate Gateway — applicazione dell’identità a livello di protocollo per SSH, l’API di Kubernetes e le app web auto‑ospitate/interne, non solo per l’accesso alla rete. Carica quando l’utente desidera concedere, proteggere, effettuare SSO o effettuare l’audit di un’app web auto‑ospitata/interna — inoltro/iniezione dell’identità nelle richieste HTTP, tracciamento di audit per ogni richiesta. Gateway = reverse proxy di livello 7 che inietta JWT ES256 (Token di Accesso del Gateway) o intestazioni attendibili: verifica JWKS, iniezione di intestazioni di richiesta, middleware per framework (Express, Django, Next.js, Auth.js), SSO senza codice (Grafana, Jenkins). Copre il deployment del Gateway; accesso privilegiato via SSH con certificati a breve durata; accesso per fornitori/contractor; Autorità di Certificazione (X.509/SSH CA, locale o Vault); kubectl via Gateway; automazione Terraform/Ansible; registrazione delle sessioni (riavvio .cast, scansione di comandi pericolosi/segreti trapelati). Considera questa competenza per “può Twingate trasmettere l’identità dell’utente alla mia app?”, “audit di chi ha usato quest’app” o “SSO per il mio strumento interno”.
