Utilízalo para el Twingate Identity Firewall (IDFW) y el Twingate Gateway — aplicación de identidad a nivel de protocolo para SSH, la API de Kubernetes y aplicaciones web auto‑alojadas/internas, no solo acceso a la red. CARGA cuando el usuario desea conceder, asegurar, iniciar SSO en, o auditar una aplicación web auto‑alojada/interna — reenvío/inyección de identidad en solicitudes HTTP, rastros de auditoría por solicitud. Gateway = proxy inverso capa 7 que inyecta JWT ES256 (Tokens de Acceso del Gateway) o encabezados confiables: verificación JWKS, inyección de encabezados de solicitud, middleware de frameworks (Express, Django, Next.js, Auth.js), SSO sin código (Grafana, Jenkins). Cubre despliegue del Gateway; acceso privilegiado SSH con certificados de corta duración; acceso de proveedores/contratistas; autoridades de certificación (X.509/SSH CA, local o Vault); kubectl a través del Gateway; automatización con Terraform/Ansible; grabación de sesiones (.cast reproducción, escaneo de comandos peligrosos/secrets filtrados). Asume esta habilidad para “¿puede Twingate pasar la identidad del usuario a mi aplicación?”, “auditar quién usó esta app”, o “SSO para mi herramienta interna”.
