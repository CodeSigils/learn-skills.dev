Ejecuta una tarea sustancial a través de un proceso de entrega completo: una parrilla de entrada que bloquea la solicitud en un resumen, luego estudio de documentos, lluvia de ideas, especificaciones, plan, compilación de subagente, pruebas, lint/implementación, verificación posterior a la implementación, sincronización y aceptación de documentos/wiki. Úselo cuando el trabajo cambie el repositorio: una característica, corrección, refactorización, migración, integración, reescritura, adopción o refuerzo; фича, фикс, рефактор, миграция, интеграция, доработать, починить, внедрить, перевести — o cuando el resultado es un hallazgo que llega a él: audit/audit, bughunt/proverь ошибки, Production Check/проверь прод, PR review/ревью PR — o en 'ejecutar esto a través del proceso' / 'прогони по конвейеру', 'el ciclo completo' / 'полный цикл', /task-pipeline. Dos modos no necesitan ninguna tarea: 'checkup' / 'чекап' informa qué se envió sin confirmar y qué mirar primero; 'setup' audita la documentación existente. No para: responder una pregunta, explicar un código, un error tipográfico o una edición de una línea; diga "без пайплайна" / "rápido" para cancelar su participación.
