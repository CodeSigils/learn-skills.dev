Exécute une tâche substantielle via un pipeline de livraison complet : une grille d'admission qui verrouille la demande dans un brief, puis une étude de documents, un brainstorming, des spécifications, un plan, la construction de sous-agents, des tests, le lint/déploiement, la vérification post-déploiement, la synchronisation et l'acceptation des documents/wiki. À utiliser lorsque le travail modifie le référentiel : une fonctionnalité, un correctif, une refactorisation, une migration, une intégration, une réécriture, une adoption ou un renforcement ; фича, фикс, рефактор, миграция, интеграция, доработать, починить, внедрить, перевести — ou lorsque le résultat est une découverte qui y atterrit : audit/audit, bug hunt/proverь ошибки, production check/проверь прод, PR review/ревью PR — ou sur 'exécuter cela à travers le pipeline' / 'прогони по конвейеру', 'le cycle complet' / 'полный цикл', /task-pipeline. Deux modes ne nécessitent aucune tâche : « checkup » / « чекап » rapporte ce qui a été expédié non confirmé et ce qu'il faut examiner en premier ; 'setup' audite la documentation existante. Pas pour : répondre à une question, expliquer un code, une faute de frappe ou une modification d'une ligne — dites « без пайплайна » / « rapide » pour vous désinscrire.
