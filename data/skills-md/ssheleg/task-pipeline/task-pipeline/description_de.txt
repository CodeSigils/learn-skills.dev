Führt eine wesentliche Aufgabe durch eine vollständige Bereitstellungspipeline: ein Einlassgitter, das die Anfrage in ein Briefing einschließt, dann Dokumentenstudie, Brainstorming, Spezifikation, Plan, Subagent-Erstellung, Tests, Lint/Bereitstellung, Überprüfung nach der Bereitstellung, Dokumentation/Wiki-Synchronisierung und Akzeptanz. Wird verwendet, wenn eine Arbeit das Repository ändert – eine Funktion, ein Fix, eine Umgestaltung, eine Migration, eine Integration, ein Umschreiben, eine Einführung oder eine Härtung. фича, фикс, рефактор, миграция, integration, доработать, починить, внедрить, перевести – oder wenn die Ausgabe ein Ergebnis ist, das darin landet: audit/audit, bug hunt/proverrь ошибки, Production check/proverer Projekt, PR-Überprüfung/PR-Überprüfung – oder auf „dies durch die Pipeline laufen lassen“ / „Übertragung durchführen“, „der vollständige Zyklus“ / „weiterer Zyklus“, /task-pipeline. Zwei Modi erfordern überhaupt keine Aufgabe: „Überprüfung“ / „Prüfung“ meldet, was unbestätigt versendet wurde und was zuerst überprüft werden muss; „setup“ prüft die vorhandene Dokumentation. Nicht für: die Beantwortung einer Frage, die Erklärung des Codes, einen Tippfehler oder eine einzeilige Änderung – sagen Sie „ohne Bezahlung“ / „schnell“, um sich abzumelden.
