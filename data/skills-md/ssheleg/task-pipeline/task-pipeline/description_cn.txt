通过完整的交付管道运行一项实质性任务：一个将请求锁定为摘要的入口格栅，然后是文档研究、集思广益、规范、计划、子代理构建、测试、lint/部署、部署后检查、文档/wiki 同步和验收。当工作改变存储库时使用——功能、修复、重构、迁移、集成、重写、采用或强化； фича, фикс, рефактор, миграция, интеграция, доработать, починить, внедрить, перевести — 或者当输出是其中的发现时：audit/аудит, bug Hunt/проверь ошибки、生产检查/проверь прод、公关审查/ревью PR — 或“通过管道运行此任务”/“прогони по конвейеру”、“整个周期”/“полный цикл”、/task-pipeline。两种模式根本不需要任何任务：“检查”/“чекап”报告未确认的发货内容以及首先查看的内容； “设置”审核现有文档。不适用于：回答问题、解释代码、拼写错误或一行编辑 — 请说“без пайплайна”/“快速”以选择退出。
