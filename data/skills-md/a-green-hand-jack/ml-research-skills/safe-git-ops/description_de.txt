Führen Sie gängige Git-Vorgänge sicher mit Sandbox-fähiger Fehlerbehandlung durch. Verwenden Sie es immer dann, wenn der Benutzer den Git-Status überprüfen oder ändern möchte, insbesondere für Cherry-Pick-, Merge-, Rebase-, Commit-, Branch-, Stash- oder Worktree-Workflows. Verwenden Sie diesen Skill immer, wenn der Benutzer einen Git-Fehler, einen Git-Konflikt, ein Cherry-Pick-Problem, ein Zusammenführungsproblem, einen Arbeitsbaum, ein Branch-Checkout-Problem, eine Sperrdatei, eine verweigerte Berechtigung, einen nicht zulässigen Vorgang oder einen Fall erwähnt, in dem ein Sandbox-Agent eine Umgebungseinschränkung mit einem echten Codekonflikt verwechseln könnte. Seien Sie proaktiv: Wenn die Aufgabe nach Git-Status oder Git-Schreibverhalten riecht, nutzen Sie diese Fähigkeit, auch wenn der Benutzer nicht explizit nach einem „Git“-Workflow gefragt hat.
