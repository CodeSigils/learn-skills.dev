Nutzen Sie diese Fähigkeit für proaktive Back-End-Zustandsprüfungen in einem InsForge-Projekt – Sicherheitsfehlkonfigurationen, Leistungseinbußen und Systemzustandsprobleme, die durch „Diagnose Advisor“ aufgedeckt werden, sowie die Backend-seitigen Deep-Dives, die mit jedem Advisor-Problem einhergehen. Verwenden Sie diese Fähigkeit auch, wenn ein Benutzer einen Back-End-weiten Leistungsabfall meldet (hohe CPU/Speicher, alle Antworten langsam, Verbindungspool-Erschöpfung, Sperrkonflikt), ohne dass eine einzige fehlgeschlagene Anfrage vorliegt. Wird bei Anfragen wie „Gesundheitsprüfung“, „Mein Backend prüfen“, „Sicherheit überprüfen“, „RLS-Richtlinien prüfen“, „Langsame Abfragen finden“, „Backend-Leistungsüberprüfung“, „hohe CPU/Speicher“, „Alles ist langsam“, „EC2/Datenbank/Systemzustand“ oder Prüfungen der Bereitschaft vor dem Start ausgelöst. Für reaktive Laufzeitfehler mit einer einzigen konkreten fehlgeschlagenen Anfrage (SDK-Fehlerobjekte, HTTP 4xx/5xx, Funktionsfehler, Bereitstellungsfehler) verwenden Sie stattdessen „insforge-debug“.
