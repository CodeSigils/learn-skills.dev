Examinez le code après le travail de mise en œuvre pour identifier les défauts de conception, les problèmes d'abstraction ou les risques de maintenance qui ne sont devenus évidents qu'une fois le code réel écrit. Soyez conservateur et évitez de suggérer des refactors sans preuves concrètes de coûts récurrents ou de complexité.
