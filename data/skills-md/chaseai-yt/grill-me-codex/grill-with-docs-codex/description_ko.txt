ACT 1(귀하 ← Claude) — Claude는 계획에 대해 한 번에 하나의 질문씩 끊임없이 인터뷰하고, 프로젝트의 기존 도메인 모델 및 용어집(CONTEXT.md)에 대해 도전하고, 퍼지 용어를 선명하게 하고, 구체적인 시나리오를 사용한 스트레스 테스트, 코드 상호 참조, 결정이 구체화됨에 따라 CONTEXT.md + ADR을 인라인으로 업데이트합니다. ACT 2(Claude ← Codex) — Claude는 잠긴 계획을 PLAN.md에 작성하고 OpenAI Codex는 읽기 전용 샌드박스(VERDICT:APPROVED/REVISE)에서 이를 적대적으로 검토합니다. Claude는 APPROVED 또는 MAX_ROUNDS 한도까지 SAME Codex 세션을 수정하고 다시 제출한 후 코드를 작성하기 전에 승인합니다. 사용자가 "/grill-with-docs-codex", "문서를 비교한 후 코덱스 검토를 받으세요", "도메인 모델에 대해 스트레스 테스트를 한 다음 두 번째 모델을 얻습니다"라고 말하거나 확립된 용어/ADR이 있는 프로젝트에서 중요한 무언가를 구축하려고 하며 정렬, 문서화 및 모델 간 온전성 검사를 원할 때 사용합니다.
