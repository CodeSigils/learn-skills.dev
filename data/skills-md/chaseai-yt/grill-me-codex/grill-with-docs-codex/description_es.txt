Endurecimiento del plan en dos actos con documentación viva. ACTO 1 (tú ↔ Claude): Claude te entrevista incansablemente sobre un plan, una pregunta a la vez, desafiándolo con el modelo de dominio y glosario existente de tu proyecto (CONTEXT.md), afinando términos confusos, realizando pruebas de estrés con escenarios concretos, haciendo referencias cruzadas de código y actualizando CONTEXT.md + ADR en línea a medida que las decisiones cristalizan. ACTO 2 (Claude ↔ Codex): Claude escribe el plan bloqueado en PLAN.md y OpenAI Codex lo revisa de manera adversa en una zona de pruebas de solo lectura (VEREDICTO: APROBADO/REVISAR), Claude revisa y vuelve a enviar a la MISMA sesión del Codex hasta APROBADO o un límite de MAX_ROUNDS, luego usted cierra sesión antes de cualquier código. Úselo cuando el usuario dice "/grill-with-docs-codex", "pregúnteme con los documentos y luego revise el códice", "pruebe esto con nuestro modelo de dominio y luego obtenga un segundo modelo", o está a punto de crear algo de alto riesgo en un proyecto con terminología/ADR establecidos y desea alineación, documentación Y una verificación de idoneidad entre modelos. Se basa en grill-with-docs (MIT) de Matt Pocock. NO para revisar código ya escrito (use /codex:review) y NO para cambios triviales.
