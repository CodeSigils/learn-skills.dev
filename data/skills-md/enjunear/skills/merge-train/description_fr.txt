Train de fusion séquentiel GitLab piloté par Claude. Pour chaque MR dans l'ordre : rebase → attendre → définir la fusion automatique → interroger jusqu'à la fusion. Résout les conflits de rebase en session à l’aide d’un arbre de travail local. À utiliser lorsque l'utilisateur dit « /merge-train », « exécuter un train de fusion », « fusionner ces MR dans l'ordre » ou transmet une liste/un filtre de MR GitLab pour atterrir séquentiellement. Nécessite `glab`, `jq` et `git` sur PATH ; Le répertoire de travail actuel doit être le dépôt du projet GitLab.
