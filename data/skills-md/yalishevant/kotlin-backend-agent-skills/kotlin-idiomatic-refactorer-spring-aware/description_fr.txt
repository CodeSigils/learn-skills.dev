Refactorisez le code Kotlin vers une conception plus claire et plus idiomatique sans perturber le comportement de Spring, la sérialisation, la persistance ou les contrats publics. À utiliser lorsque Kotlin à saveur Java a besoin d'être nettoyé, que la modélisation de domaine doit devenir plus expressive ou que le passe-partout doit être réduit, mais que la refactorisation doit rester sûre pour les proxys, Jackson, JPA, la liaison de configuration et les tests existants.
