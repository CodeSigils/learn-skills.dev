Handeln Sie bei einem fehlgeschlagenen callidescope‑Lauf — ein Depth Gate, das einen Stack über dem Limit meldete, ein Breadth Gate, ein veralteter Commit‑Bericht, ein Module‑Spread oder möglicherweise fehlplatziertes Finding, eine abgelehnte Befehlszeile oder eine vor dem Tracing abgelehnte Konfiguration. Verwenden Sie dies, wenn callidescope mit einem Nicht‑Null‑Exitcode beendet wird, wenn ein Stack in einer Änderung tiefer wird, wenn ein Commit‑Bericht oder Diagramm nicht mit einem frischen Lauf übereinstimmt, wenn eine Tiefe als Boden statt als Zahl ausgegeben wird oder bevor maximumDepth erreicht wird, um einen fehlgeschlagenen Check zu bestehen.
