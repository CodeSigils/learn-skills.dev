Utilice esta habilidad cuando el usuario desee iniciar el flujo de trabajo de planificación formal de QRSPI/OpenSpec para un ticket, error, solicitud de función o cambio propuesto de producto/CLI/aplicación antes de la implementación. Invoquelo cuando el usuario desee un paquete de cambios basado en especificaciones con preguntas primero, investigación factual, artefactos de propuesta/diseño, especificaciones afectadas y un plan de tareas dividido verticalmente, con paradas explícitas de revisión/aprobación antes de comenzar cualquier codificación. Esta es la habilidad adecuada cuando el usuario quiere planificar, alcanzar o desglosar el cambio en sí, especialmente si solicita usar QRSPI, crear un cambio OpenSpec, ejecutar un flujo de trabajo de planificación o detenerse antes de escribir código. No lo utilice para implementar una especificación existente, revisar o pulir artefactos que ya existen, generar documentos de arquitectura genéricos, archivar cambios completados o admitir lluvias de ideas sueltas sin solicitar resultados formales de QRSPI/OpenSpec.
