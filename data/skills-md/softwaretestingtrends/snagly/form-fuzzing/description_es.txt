Pruebe los campos del formulario con entradas inusuales pero realistas (vacíos, longitud de límites, Unicode, formatos mal formados, caracteres reales pero poco comunes como apóstrofes en los nombres) usando un navegador real, para verificar que la aplicación se degrade correctamente: mensajes de validación claros, sin fallas, sin corrupción de datos, sin diseño roto. Úselo siempre que el usuario desee probar la solidez del formulario, la validación de entradas, las entradas de casos extremos o cómo un formulario maneja datos inusuales; active frases como "validación de formulario de prueba", "borre este formulario", "verifique las entradas de casos extremos" o "este formulario maneja entradas inusuales con elegancia". Esto es explícitamente una verificación de UX/robustez, no una prueba de seguridad o penetración: nunca utiliza cargas útiles de inyección, nunca intenta eludir la autenticación o acceder a datos que no sean suyos, y nunca intenta confirmar o explotar una vulnerabilidad. Si algo observado parece relevante para la seguridad, el trabajo es marcarlo para una revisión adecuada, no investigar más.
