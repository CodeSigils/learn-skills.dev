Überprüfen Sie zuvor gefundene Fehler erneut anhand des aktuellen Builds mithilfe eines echten Browsers. Nehmen Sie eine oder mehrere Fehler-IDs (oder „alle offenen Fehler“), lokalisieren Sie die aufgezeichnete minimale Reproduktion jedes einzelnen Fehlers, führen Sie ihn originalgetreu mit der ursprünglichen Genauigkeit erneut aus und geben Sie für jeden Fehler ein Urteil „BEHOBEN“, „NOCH DEFEKT“, „REGRESSIERT“ oder „BLOCKIERT“ ab, wobei das Fehlerpaket und das Fehlerbuch aktualisiert werden. Verwenden Sie diese Funktion immer dann, wenn der Benutzer wissen möchte, ob ein Fix aufgetreten ist, ob bekannte Fehler im neuesten Build noch vorhanden sind, oder um das Fehlerbuch nach einer Bereitstellung zu aktualisieren – ausgelöst durch Phrasen wie „Ist D4 behoben“, „Überprüfen Sie die offenen Fehler erneut“, „Hat der Fix für den Einladungsfehler gelandet“, „Überprüfen Sie die Fixes“ oder „Führen Sie die Fehlerprüfungen für den neuen Build erneut durch“, auch ohne das Wort „Playwright“. Im Gegensatz zur Bug-Triage, die einen neu vermuteten Defekt untersucht und die Repro erzeugt, die diese Fertigkeit verbraucht – wenn für einen Defekt noch keine minimale Repro aufgezeichnet wurde, steht die Triage an erster Stelle.
