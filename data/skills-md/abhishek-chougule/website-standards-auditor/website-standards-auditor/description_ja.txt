組織の必須エンジニアリングおよび Web 標準に照らして、あらゆる Web サイト (新規、開発中、または既に稼働中) を監査および修正し、ユーザーの承認後にギャップを足場または修復します。ユーザーが SEO、GEO、AEO、アクセシビリティ、パフォーマンス、構造化データ、スキーマ、サイトマップ、robots.txt、llms.txt、Core Web Vitals、Lighthouse、モバイル、メタデータ、カノニカル、hreflang、リダイレクト、または内部リンクのレビューを必要とする場合、または .gitignore および README ポリシーに対してリポジトリをチェックするように要求する場合、または監査、ギャップ分析、コンプライアンス、標準レビューについて言及する場合は常にこれを使用します。 「私のサイトを私たちのルールに従ってください」。ユーザーが標準の名前を指定しない場合でも、Web サイトの品質、見つけやすさ、または標準への準拠タスクには常にこれを使用し、最初に gap_identification.md を生成し、次に明示的な承認後にのみ修正する 2 段階のフローに従います。
