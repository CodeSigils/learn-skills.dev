Finden und bewerten Sie Duplikate im Code und unterscheiden Sie dabei echte Wissensduplizierung (muss vereinheitlicht werden) von zufälliger Ähnlichkeit (muss in Ruhe gelassen werden). Wenden Sie das DRY-Prinzip des Pragmatischen Programmierers („Jedes Wissen muss eine einzige, eindeutige, maßgebliche Darstellung haben“) und die Dreierregel von Fowler an. Verwenden Sie diese Option, wenn Sie eine Codebasis oder ein Diff auf Duplikate überprüfen, wenn dieselbe Logik verdächtig zweimal vorkommt, bevor Sie Code hinzufügen, der vorhandenem Code ähnelt, oder wenn Sie eine Extraktion vorschlagen. Überspringen Sie bei Änderungen innerhalb einer einzelnen Datei unter 200 Zeilen oder wenn der Benutzer ausdrücklich gesagt hat: „Machen Sie sich im Moment keine Sorgen über Duplikate.“
