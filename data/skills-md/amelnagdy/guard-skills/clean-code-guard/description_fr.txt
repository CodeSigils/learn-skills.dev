Examinez le code de production généré ou modifié avant son expédition, à l'aide des contrôles de mode de défaillance Clean Code, SOLID, DRY, KISS, YAGNI et LLM dans n'importe quel langage de programmation. Il est préférable de l'utiliser de manière réactive après qu'un agent a écrit, modifié, refactorisé ou corrigé du code, avant de présenter, de valider ou de fusionner le résultat. À utiliser lorsque l'utilisateur demande « examiner ce PR », « la fusion est-elle sûre ? », « rendre cela plus propre », « auditer ce code », « refactoriser ceci », « corriger ce bug » ou après qu'un agent de codage a produit un code d'implémentation. Peut également guider l'écriture lorsqu'il est explicitement invoqué avant une modification risquée. NE PAS UTILISER pour des questions factuelles/conceptuelles, la configuration de CI/outils, le workflow git, l'exécution/débogage de tests, les discussions sur l'architecture pure, l'écriture de prose, l'analyse de données ou la révision de code de test (utilisez test-guard).
