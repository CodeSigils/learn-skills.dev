任意のプログラミング言語でクリーン コード、SOLID、DRY、KISS、YAGNI、LLM 固有の障害モード チェックを使用して、生成または変更された製品コードを出荷前にレビューします。エージェントがコードを作成、編集、リファクタリング、または修正した後、結果を提示、コミット、またはマージする前に、事後的に使用するのが最適です。ユーザーが「この PR を確認してください」、「マージしても安全ですか?」、「これをよりクリーンに」、「このコードを監査してください」、「これをリファクタリングしてください」、「このバグを修正してください」と尋ねる場合、またはコーディング エージェントが実装コードを生成した後に使用します。危険な編集の前に明示的に呼び出すと、書き込みをガイドすることもできます。事実/概念的な質問、CI/ツール構成、git ワークフロー、テストの実行/デバッグ、純粋なアーキテクチャの議論、散文の作成、データ分析、またはテストコードのレビュー (test-guard を使用) には使用しないでください。
