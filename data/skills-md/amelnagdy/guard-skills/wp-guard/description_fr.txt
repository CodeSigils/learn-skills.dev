Examinez le code WordPress généré ou modifié (plugins, thèmes et blocs) avant son expédition. Il est préférable de l'utiliser de manière réactive après qu'un agent a écrit, modifié ou révisé du code touchant les API WordPress : add_action/add_filter, codes courts, méta-boîtes, gestionnaires AJAX, routes REST, WP_Query ou $wpdb, widgets ou commandes WP-CLI. À utiliser pour « réviser ce plugin », « Est-il sûr à expédier », « rendre ceci traduisible », « accélérer cette requête » ou après des tâches telles que « écrire un plugin » ou « ajouter un point de terminaison/shortcode/méta-boîte ». Applique l'échappement et la désinfection, les vérifications des nonces et des capacités, les requêtes de base de données préparées, le développement axé sur l'API principale, les chaînes prêtes à être traduites et la discipline de requête/mise en cache. NE PAS UTILISER pour la logique de commande, de produit ou de paiement spécifique à WooCommerce (utilisez woo-guard), PHP non WordPress, l'examen de la qualité du code générique (utilisez clean-code-guard), l'examen du code de test (utilisez test-guard), la configuration du serveur ou de l'hébergement ou les questions conceptuelles de WordPress.
