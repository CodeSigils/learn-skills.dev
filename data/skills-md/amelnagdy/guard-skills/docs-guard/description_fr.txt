Examinez la documentation générée ou modifiée avant son expédition : README, références API, docstrings, PHPDoc/JSDoc, journaux des modifications, didacticiels et sites de documentation. Il est préférable de l'utiliser de manière réactive après qu'un agent a écrit ou modifié des documents, après que le code a modifié le comportement documenté ou avant de publier des documents. À utiliser lorsque l'utilisateur dit « examiner la documentation », « cette documentation est-elle exacte », « mettre à jour la documentation », « écrire un README », « documenter cette API », « ajouter une chaîne de documentation » ou « ajouter une entrée du journal des modifications ». Tâche principale : vérifiez chaque fonction, indicateur, point de terminaison, clé de configuration et échantillon de code référencés par rapport à la source ; attraper la dérive docs-vs-code ; mastic de bande et réclamations invérifiables. NE PAS UTILISER pour la révision du code de production (utilisez clean-code-guard), la révision des tests (utilisez test-guard), la copie marketing ou les articles de blog, l'édition de style prose d'écritures non techniques ou la thématisation du site de documentation.
