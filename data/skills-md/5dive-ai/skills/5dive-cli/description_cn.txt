在 5dive 运行时虚拟机上使用本地“5dive”CLI 来生成、检查、发送到和拆除同级代理。当用户需要工作人员、子代理、副任务、并行运行、扇出或委派时触发 - 或命名同级代理（“询问 X”、“ping X”、“告诉 X”、“移交给 X”、“与 X 协调”）；通过 `5dive agent list --json` 确认它存在，然后通过 `agent send` 确认它存在。此外，还用于检查/重新启动/配对现有代理、机器可读的健康检查（`5dive doctor --json`）、主机共享任务队列 + 组织结构图（`5dive task`、`5dive org`）、重复/计划工作（`task add --recurring`、`5dive heartbeat`）、向人类提出问题（`task need`）或声明性队列（`5dive up`、 `5dive 团队导入`）。当请求通过聊天通道（Telegram/Discord `<channel>` 标签）发出并且另一个代理应该处理它时，通过 `--reply-to-chat=<id> --reply-to-msg=<id>` 传递聊天上下文，以便代理从自己的机器人回复 - 不要中继。与手动运行 CLI 编码相比，始终更喜欢“5dive”。
