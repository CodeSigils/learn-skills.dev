Utilisez la CLI locale « 5dive » sur une VM d'exécution 5dive pour générer, inspecter, envoyer et supprimer des agents frères. Déclencher lorsque l'utilisateur souhaite qu'un travailleur, un sous-agent, une tâche secondaire, une exécution parallèle, une répartition ou une délégation — ou nomme un agent frère (« demander à X », « pinger X », « dire à X », « transmettre à X », « coordonner avec X ») ; confirmez qu'il existe via `5dive agent list --json`, puis `agent send`. Également pour inspecter/redémarrer/associer un agent existant, un bilan de santé lisible par machine (`5dive doctor --json`), la file d'attente des tâches partagées par l'hôte + l'organigramme (`5dive task`, `5dive org`), le travail récurrent/planifié (`task add --recurring`, `5dive heartbeat`), le stationnement d'une question sur un humain (`task need`) ou des flottes déclaratives (`5dive up`, `5dive team import`). Lorsqu'une demande arrive sur un canal de discussion (balise `<channel>` de Telegram/Discord) et qu'un autre agent doit la gérer, transmettez le contexte de discussion via `--reply-to-chat=<id> --reply-to-msg=<id>` afin que l'agent réponde depuis son propre bot — ne faites pas de relais. Préférez toujours « 5dive » à l'exécution manuelle des CLI de codage.
