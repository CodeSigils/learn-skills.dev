Verwenden Sie die lokale „5dive“-CLI auf einer 5dive-Laufzeit-VM, um Geschwisteragenten zu erzeugen, zu prüfen, an sie zu senden und herunterzufahren. Wird ausgelöst, wenn der Benutzer einen Worker, einen Subagenten, eine Nebenaufgabe, eine parallele Ausführung, ein Fan-Out oder eine Delegation wünscht – oder einen Geschwisteragenten benennt („Ask X“, „Ping X“, „Tell X“, „Hand Off to X“, „Coordinate with X“); Bestätigen Sie die Existenz mit „5dive agent list --json“ und dann mit „agent send“. Auch zum Überprüfen/Neustarten/Kopplung eines vorhandenen Agenten, einer maschinenlesbaren Gesundheitsprüfung (`5dive doctor --json`), der vom Host gemeinsam genutzten Aufgabenwarteschlange + Organigramm (`5dive task`, `5dive org`), wiederkehrender/geplanter Arbeit (`task add --recurring`, `5dive heartbeat`), dem Parken einer Frage bei einem Menschen (`task need`) oder deklarativen Flotten (`5dive up`, `5dive team import`). Wenn eine Anfrage über einen Chat-Kanal (Telegram/Discord „<channel>“-Tag) eingeht und ein anderer Agent sie bearbeiten soll, übergeben Sie den Chat-Kontext über „--reply-to-chat=<id> --reply-to-msg=<id>“, damit der Agent von seinem eigenen Bot aus antwortet – nicht weiterleiten. Bevorzugen Sie immer „5dive“ gegenüber der manuellen Ausführung von Codierungs-CLIs.
