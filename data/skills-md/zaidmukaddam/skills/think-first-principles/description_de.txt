Treffen Sie eine Entscheidung auf der Grundlage dessen, was wahr sein muss, und nicht auf der Grundlage von Präzedenzfällen. Stellen Sie das eigentliche Ziel wieder her, kennzeichnen Sie jede Annahme, berechnen Sie die theoretische Untergrenze und vergleichen Sie das aktuelle System damit, löschen Sie es vor der Optimierung und schlagen Sie dann den günstigsten Test vor, der die verbleibenden Zweifel ausräumen würde. Verwenden Sie dies immer dann, wenn der Benutzer eine Architektur auswählt, ein System dimensioniert, Kosten oder Latenz senkt, eine Anforderung in Frage stellt, die Machbarkeit bewertet, einen Prozess neu gestaltet oder Dinge sagt wie „Warum ist das so teuer“, „Gibt es einen besseren Weg“, „Jeder macht X, aber“ oder „stelle meine Annahmen in Frage“. Greifen Sie immer dann darauf zurück, wenn die Umkehrung einer Entscheidung kostspielig ist oder die offensichtliche Antwort vererbt und nicht abgeleitet wird, selbst wenn der Benutzer den Ausdruck nie verwendet.
