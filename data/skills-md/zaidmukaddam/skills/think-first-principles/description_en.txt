Rebuild a decision from what must be true instead of from precedent. Recover the real objective, label every assumption, compute the theoretical floor and compare the current system against it, delete before optimizing, then propose the cheapest test that would settle the remaining doubt. Use this whenever the user is choosing an architecture, sizing a system, cutting cost or latency, questioning a requirement, evaluating feasibility, redesigning a process, or saying things like "why is this so expensive", "is there a better way", "everyone does X but", or "challenge my assumptions". Reach for it any time a decision is expensive to reverse or the obvious answer is inherited rather than derived, even when the user never uses the phrase.
