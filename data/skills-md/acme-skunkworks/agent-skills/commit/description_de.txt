Verwandeln Sie den Arbeitsbaum in logische, atomare konventionelle Commits – klassifizieren Sie nicht festgeschriebene Dateien anhand der Zusammenführungsbasis des Zweigs als im Gültigkeitsbereich oder außerhalb des Gültigkeitsbereichs liegend, zeigen Sie einen Staging-Plan an und erstellen Sie einen Commit pro kohärenter Einheit (Typ + optionaler Gültigkeitsbereich + britisch-englischer Hauptteil; „!“ / „BREAKING CHANGE:“ für Breaking Changes). Niemals „git add -A“; Dateien, die so aussehen, als gehörten sie zu einem anderen Zweig/Arbeitsbaum, werden niemals stillschweigend bereitgestellt. Verwenden Sie es, wenn Sie aufgefordert werden, nicht festgeschriebene Arbeit festzuschreiben, WIP in atomare Festschreibungen aufzuteilen oder als Festschreibungsschritt innerhalb eines Schiffsflusses (z. B. „/send-it“). Es erfolgt nur ein Commit – kein Push, PR, Changelog oder lineares Zurückschreiben.
