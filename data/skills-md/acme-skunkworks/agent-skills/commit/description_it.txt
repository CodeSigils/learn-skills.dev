Trasforma l'albero di lavoro in commit convenzionali logici e atomici: classifica i file senza commit come nell'ambito e fuori ambito rispetto alla base di unione del ramo, mostra un piano di staging e crea un commit per unità coerente (tipo + ambito opzionale + corpo britannico-inglese; `!` / `BREAKING CHANGE:` per modifiche di rilievo). Non usare mai `git add -A`; i file che sembrano appartenere a un altro ramo/albero di lavoro non vengono mai messi in scena in modo silenzioso. Da utilizzare quando viene richiesto di impegnare il lavoro non impegnato, di riordinare il WIP in commit atomici o come fase di commit all'interno di un flusso di spedizione (ad esempio `/send-it`). Si impegna solo: nessun push, PR, changelog o writeback lineare.
