작업 트리를 논리적이고 원자적인 기존 커밋으로 전환합니다. 커밋되지 않은 파일을 브랜치의 병합 기반에 대해 범위 내 및 범위 밖으로 분류하고, 스테이징 계획을 표시하고, 일관된 단위당 하나의 커밋을 생성합니다(유형 + 선택적 범위 + 영국-영어 본문, 주요 변경 사항의 경우 `!` / `주요 변경 사항:`). 절대 `git add -A`를 사용하지 마세요. 다른 분기/작업 트리에 속한 것처럼 보이는 파일은 자동으로 스테이징되지 않습니다. 커밋되지 않은 작업을 커밋하라는 요청을 받을 때, WIP를 원자적 커밋으로 정리하거나 배송 흐름 내의 커밋 단계로 사용합니다(예: `/send-it`). 푸시, PR, 변경 로그 또는 선형 쓰기 저장이 아닌 커밋만 수행됩니다.
