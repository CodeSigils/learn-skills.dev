Générez une demande d'extraction à partir du brouillon avec l'échec du CI pour être prêt à la fusion. Pendant que le PR est un brouillon, inspectez et corrigez les échecs de CI dans le champ d'application (peluches, manifeste-lint, build, tests) à l'aide des journaux gh CLI et GitHub Actions - sans jamais affaiblir la configuration CI pour un greenwashing. Une fois que le PR est marqué prêt à être révisé, récupérez les fils de discussion de l'IA non résolus (Claude Code Review, Bugbot), validez chaque résultat par rapport à la base de code avant de modifier quoi que ce soit, corrigez ceux valides, refusez les non valides avec un raisonnement technique, puis re-regardez CI jusqu'au vert. À utiliser lorsqu'on vous demande de trier un PR, de corriger un CI défaillant ou des contrôles rouges sur un PR, de traiter ou de répondre aux commentaires de révision de PR, d'agir sur les commentaires de Bugbot ou de Claude, d'obtenir un PR vert ou de préparer un brouillon de PR pour être prêt à la fusion. Gère la dérive des branches de base et les conflits de fusion dans la portée ; aggrave les situations ambiguës.
