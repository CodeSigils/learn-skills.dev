Прежде чем писать какой-либо код, проведите единую независимую экспертную проверку письменного плана (файла уценки дизайна/реализации). Используйте этот навык всякий раз, когда пользователь просит «план панели» / «план панели», «попросить комиссию рассмотреть мой план», «рассмотреть этот план комиссией», «получить второе мнение по этому плану», «узнать мнение комиссии по этому плану», «рассмотреть план веером» или любую подобную формулировку с просьбой о проведении одной независимой многоагентной проверки плана. Рассылает план нескольким локальным агентам кодирования CLI (codex, claude, opencode), каждый в новом неинтерактивном подпроцессе без общего состояния, читает план + репозиторий, который он предназначен только для чтения, затем синтезирует свои выводы (пробелы, неверные предположения, неосуществимые шаги, риски) и открытые вопросы в один отчет. Это аналог панели обзора (которая проверяет выпущенный код) во время планирования. Это ОДИН проход, и он НЕ редактирует план — для цикла итерация-редактирование-перепроверка для достижения конвергенции используйте цикл панели-плана. НЕ используйте для проверки различий в коде или PR (то есть групповой проверки), или когда пользователь просто хочет, чтобы этот сеанс подверг критике сам план.
