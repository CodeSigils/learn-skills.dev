Exécutez un seul examen par un comité indépendant d'un plan écrit (un fichier de démarque de conception/implémentation), avant l'écriture de tout code. Utilisez cette compétence chaque fois que l'utilisateur demande à "planifier le panel" / "planifier le panel", "demander au panel d'examiner mon plan", "à un panel d'examiner ce plan", "obtenir un deuxième avis sur ce plan", "obtenir l'avis du panel sur ce plan", "organiser une révision du plan", ou toute formulation similaire demandant un examen multi-agent indépendant sur un plan. Présente le plan à plusieurs agents de codage CLI locaux (codex, claude, opencode), chacun dans un nouveau sous-processus non interactif sans état partagé, lisant le plan + le dépôt qu'il cible en lecture seule, puis synthétise leurs résultats (lacunes, hypothèses erronées, étapes irréalisables, risques) et ouvre les questions dans un seul rapport. Il s'agit de l'analogue du temps de planification de la révision par un panel (qui examine le code expédié). Il s'agit d'UNE seule passe et ne modifie PAS le plan — pour la boucle itérer-édition-révision vers la convergence, utilisez panel-plan-loop. Ne PAS utiliser pour réviser une différence de code ou un PR (c'est-à-dire une révision par un panel), ou lorsque l'utilisateur souhaite simplement que cette session critique le plan lui-même.
