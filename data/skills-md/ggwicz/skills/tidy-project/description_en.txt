Use when the user explicitly invokes /tidy-project. Runs a read-only, three-phase audit of project structure for easier solo-dev maintenance. Identifies dead code, duplication, premature abstraction, over-nesting, over-coupling, vestigial framework scaffolding, stale markers, and docs/code drift. Produces a single consolidated execution plan at `docs/YYYY-MM-DD-tidy-project-plan.md` (or repo root if no `docs/`) — does not modify source files. Skips every directory beginning with `.` (e.g. `.git`, `.venv`, `.rdf`, `.agents`, `.claude`, `.github`, IDE/CI/agent scaffolding) plus the usual `node_modules`, `vendor`, `dist`, `build`, `coverage`, `target`.
