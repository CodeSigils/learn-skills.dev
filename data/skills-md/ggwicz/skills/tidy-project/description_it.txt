Da utilizzare quando l'utente invoca esplicitamente /tidy-project. Esegue un controllo in tre fasi di sola lettura della struttura del progetto per facilitare la manutenzione dello sviluppatore singolo. Identifica codice morto, duplicazione, astrazione prematura, nidificazione eccessiva, accoppiamento eccessivo, impalcature strutturali vestigiali, marcatori obsoleti e deriva di documenti/codice. Produce un singolo piano di esecuzione consolidato in `docs/YYYY-MM-DD-tidy-project-plan.md` (o repository root se non c'è `docs/`) — non modifica i file di origine. Salta ogni directory che inizia con `.` (ad esempio `.git`, `.venv`, `.rdf`, `.agents`, `.claude`, `.github`, scaffolding IDE/CI/agent) più i soliti `node_modules`, `vendor`, `dist`, `build`, `coverage`, `target`.
