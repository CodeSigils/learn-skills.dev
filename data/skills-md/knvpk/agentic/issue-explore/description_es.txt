Obtiene un elemento de trabajo de GitLab, GitHub, Jira o Plane (detectado automáticamente a partir del formato de referencia o URL) e inicia opsx:explore con el contexto del problema y el contexto del repositorio de código precargados. Úselo cuando un usuario menciona un número de ticket, una clave de problema o una URL de problema y desea explorar la implementación antes de iniciar un cambio. Funciona correctamente cuando el rastreador de problemas y el host de código son sistemas diferentes (por ejemplo, problemas de Jira + código GitLab).
