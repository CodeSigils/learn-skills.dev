Récupère un élément de travail depuis GitLab, GitHub, Jira ou Plane (détecté automatiquement à partir du format de référence ou de l'URL) et démarre opsx:explore avec le contexte du problème et le contexte du référentiel de code préchargés. À utiliser lorsqu'un utilisateur mentionne un numéro de ticket, une clé de problème ou une URL de problème et souhaite explorer l'implémentation avant de commencer une modification. Fonctionne correctement lorsque le suivi des problèmes et l'hôte du code sont des systèmes différents (par exemple, problèmes Jira + code GitLab).
