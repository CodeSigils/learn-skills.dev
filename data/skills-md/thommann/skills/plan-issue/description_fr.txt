Transformez un problème GitHub en plan de mise en œuvre : étudiez la base de code, proposez une approche, répertoriez les fichiers et les modifications critiques, définissez la stratégie de test. À utiliser lorsque l'utilisateur dit « planifier ce problème », « à quoi sert l'approche », « comment puis-je aborder », « plan de mise en œuvre pour » ou « avant de coder ». Ne PAS utiliser pour la mise en œuvre réelle (écrivez le code directement après le plan) ou pour diviser un problème trop important en sous-problèmes (utilisez splice-issue).
