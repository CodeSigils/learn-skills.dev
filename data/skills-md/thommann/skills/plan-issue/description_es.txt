Convierta un problema de GitHub en un plan de implementación: investigue el código base, proponga un enfoque, enumere los archivos y cambios críticos, describa la estrategia de prueba. Úselo cuando el usuario diga "planifique este problema", "cuál es el enfoque", "cómo lo abordaría", "plan de implementación" o "antes de codificar". NO lo use para implementar realmente (escriba el código directamente después del plan) o para dividir un problema demasiado grande en subtemas (use splice-issue).
