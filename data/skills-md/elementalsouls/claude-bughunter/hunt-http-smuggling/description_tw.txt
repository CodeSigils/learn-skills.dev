追蹤 HTTP 請求走私（CL.TE、TE.CL、H2.CL、H2.TE）。原因：前端代理程式和後端伺服器在一個請求結束位置和下一個請求開始位置上不一致（Content-Length 與 Transfer-Encoding 標頭解析不一致）。 CL.TE：前端使用 CL，後端使用 TE → 透過傳送 TE 走私：分塊但具有適合 CL 計數的正文。 TE.CL：相反。 H2.CL：HTTP/2降級，將CL走私到HTTP/1.1後端。檢測工具：Burp HTTP Request Smuggler 擴充功能、smuggler.py、h2csmuggler。確認：時間延遲技術（走私 GET 具有 30 秒超時）——如果前端在下一個受害者請求時返回緩慢，則走私起作用。驗證：快取中毒鏈（走私為受害者快取的請求）、憑證盜竊（走私 X-Forwarded-For 覆蓋捕獲下一個使用者的 cookie）、繞過身份驗證（走私內部路徑請求）。來自主要 CDN 部署的真實付費範例。在尋找運行 CDN+來源堆疊的 H1 付費程式、以負載平衡器/WAF 繞過為目標時使用。
