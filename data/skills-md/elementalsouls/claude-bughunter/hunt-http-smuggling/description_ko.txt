HTTP 요청 밀수(CL.TE, TE.CL, H2.CL, H2.TE)를 추적합니다. 원인: 프런트 엔드 프록시와 백엔드 서버는 한 요청이 끝나고 다음 요청이 시작되는 위치에 동의하지 않습니다(콘텐츠 길이와 전송 인코딩 헤더 구문 분석 불일치). CL.TE: 프런트 엔드는 CL을 사용하고, 백은 TE를 사용합니다. → TE: 청크를 보내지만 CL 개수에 맞는 바디로 밀수합니다. TE.CL: 반대죠. H2.CL: HTTP/2 다운그레이드, CL을 HTTP/1.1 백엔드로 밀수입합니다. 탐지 도구: Burp HTTP 요청 Smuggler 확장, smuggler.py, h2csmuggler. 확인: 시간 지연 기술(30초 시간 초과로 밀수된 GET) — 다음 피해자 요청에서 프런트 엔드가 느리게 반환되면 밀수는 작동합니다. 검증: 캐시 중독 체인(피해자를 위해 캐시되는 밀수 요청), 자격 증명 도용(다음 사용자의 쿠키를 캡처하는 밀수 X-Forwarded-For 재정의), 인증 우회(밀수된 내부 경로 요청). 주요 CDN 배포의 실제 유료 사례입니다. 로드 밸런서/WAF 우회를 대상으로 하는 경우 CDN+origin 스택을 실행하는 H1 유료 프로그램을 검색할 때 사용합니다.
