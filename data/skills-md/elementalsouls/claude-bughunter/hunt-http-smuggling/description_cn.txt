追踪 HTTP 请求走私（CL.TE、TE.CL、H2.CL、H2.TE）。原因：前端代理和后端服务器在一个请求结束位置和下一个请求开始位置上不一致（Content-Length 与 Transfer-Encoding 标头解析不一致）。 CL.TE：前端使用 CL，后端使用 TE → 通过发送 TE 走私：分块但具有适合 CL 计数的正文。 TE.CL：相反。 H2.CL：HTTP/2降级，将CL走私到HTTP/1.1后端。检测工具：Burp HTTP Request Smuggler 扩展、smuggler.py、h2csmuggler。确认：时间延迟技术（走私 GET 具有 30 秒超时）——如果前端在下一个受害者请求时返回缓慢，则走私起作用。验证：缓存中毒链（走私为受害者缓存的请求）、凭证盗窃（走私 X-Forwarded-For 覆盖捕获下一个用户的 cookie）、绕过身份验证（走私内部路径请求）。来自主要 CDN 部署的真实付费示例。在寻找运行 CDN+源堆栈的 H1 付费程序、以负载均衡器/WAF 绕过为目标时使用。
