Отслеживание контрабанды HTTP-запросов (CL.TE, TE.CL, H2.CL, H2.TE). Причина: внешний прокси-сервер и внутренний сервер расходятся во мнениях относительно того, где заканчивается один запрос и начинается следующий (несогласованность анализа заголовка Content-Length и Transfer-Encoding). CL.TE: внешний интерфейс использует CL, задний использует TE → переправить, отправив TE: частями, но с телом, соответствующим количеству CL. ТЭ.КЛ: напротив. H2.CL: понижение версии HTTP/2, перенаправление CL на серверную часть HTTP/1.1. Инструменты обнаружения: расширение Burp HTTP Request Smuggler, smuggler.py, h2csmuggler. Подтверждение: метод временной задержки (контрабандный GET с тайм-аутом 30 секунд) — если клиентский интерфейс медленно возвращается при следующем запросе жертвы, контрабанда работает. Проверка: цепочка отравления кэша (незаконный запрос, который кэшируется для жертвы), кража учетных данных (незаконное переопределение X-Forwarded-For, которое захватывает файлы cookie следующего пользователя), обход аутентификации (незаконный запрос внутреннего пути). Реальные платные примеры из крупных развертываний CDN. Используйте при поиске платных программ H1, использующих стеки CDN+origin, при настройке обхода балансировщика нагрузки/WAF.
