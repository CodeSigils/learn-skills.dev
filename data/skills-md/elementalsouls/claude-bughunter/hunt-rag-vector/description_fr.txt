Chasser les faiblesses du stockage vectoriel/de la couche d'intégration dans les pipelines RAG (OWASP LLM08 Vector and Embedding Weaknesses) — empoisonnement persistant du corpus qui survit à travers les sessions et les utilisateurs (différent de l'injection d'invite indirecte ponctuelle, qui appartient à hunt-llm-ai), IDOR de base de données vectorielles multi-locataires (requêtes non authentifiées ou non ciblées sur Pinecone/Weaviate/Chroma/Milvus/Qdrant/pgvector), fuite de texte source/métadonnées dans les résultats de recherche de similarité et récupération-détournement via une proximité d'intégration contradictoire (« empoisonnement SEO » pour RAG). Cibles : toute application disposant d'une base de connaissances partagée, d'un téléchargement de documents alimentant un chatbot ou d'un port de base de données vectorielle directement accessible. Valider : une deuxième session/compte propre doit hériter d'un résultat empoisonné, ou un artefact entre locataires doit être vérifiable indépendamment - la confabulation n'est pas une découverte, même barre que hunt-llm-ai. À utiliser lorsque la cible est basée sur RAG, expose un port de base de données vectorielle ou permet aux utilisateurs de télécharger des documents que les requêtes d'autres utilisateurs récupèrent ultérieurement.
