JWT 暗号化エラーを追跡します。alg:none 署名ストリッピングと RS256→HS256 キー混同により、攻撃者は秘密を知らずに任意の ID (管理者など) のトークンを偽造できます。アプリが JSON Web トークン (Authorization ヘッダーの `eyJ...` ベアラー トークン、Cookie、またはログイン応答) で認証する場合に使用します。このスキルは、JWT 署名/暗号偽造 (alg:none、キーの混乱、kid/jku ヘッダー インジェクション) を所有しています。 Hunt-ato は 1 つの ATO パスとして JWT をカバーし、hunt-auth-bypass は SSO/SAML トークンの信頼をカバーし、hunt-api-misconfig は非暗号化 JWT の処理を​​カバーします。偽造されたトークンが別のユーザーのデータまたは管理者専用エンドポイントへのアクセスを許可する場合に重要です。
