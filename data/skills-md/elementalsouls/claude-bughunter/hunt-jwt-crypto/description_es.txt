Busque fallas criptográficas en JWT: alg:none eliminación de firmas y confusión de claves RS256→HS256 que permiten a un atacante falsificar un token para cualquier identidad (por ejemplo, un administrador) sin conocer un secreto. Úselo cuando la aplicación se autentica con un token web JSON (un token de portador `eyJ...` en el encabezado de autorización, una cookie o una respuesta de inicio de sesión). Esta habilidad PROPIETARIA firma JWT/falsificación criptográfica (alg:ninguna, confusión de claves, inyección de encabezado kid/jku); Hunt-ato cubre JWT como una ruta ATO, Hunt-auth-bypass cubre la confianza de token SSO/SAML, Hunt-api-misconfig cubre el manejo de JWT no criptográfico. Es fundamental cuando un token falsificado otorga acceso a los datos de otro usuario o a un punto final exclusivo para administradores.
