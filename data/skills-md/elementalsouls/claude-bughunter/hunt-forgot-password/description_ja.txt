パスワードを忘れた場合/アカウント回復認証の欠陥を追跡 — 5 つの異なるパターン: (1) 有効な電子メールと無効な電子メールに対する異なる応答によるユーザー名の列挙、(2) API 応答本文で直接公開されたリセット トークン、(3) 使用後 (リプレイ) に無効化されないリセット トークン、(4) パスワード リセット リンクは別の IP/ブラウザから機能する (バインドなし)、(5) リセット リクエスト エンドポイントのレート制限なし。これらは、スタンドアロンの回復フローの壊れた認証プリミティブであり、リセット電子メール ホスト ヘッダー ポイズニング (hunt-host-header) および完全な ATO チェーン (hunt-ato は ATO パスとしてパスワード リセットを所有しています。ここでプリミティブを証明し、そこにチェーンします) とは異なります。検出: リクエストから使用するトークンまで、パスワードを忘れた場合の完全なフローを追跡します。有効/無効な電子メール間の応答の違いを確認します。消費後のテストトークンの再生。中から高 (列挙 = 中、トークン再利用 = 高、アカウント乗っ取り = 既知の電子メールにチェーンされている場合は重大)。
