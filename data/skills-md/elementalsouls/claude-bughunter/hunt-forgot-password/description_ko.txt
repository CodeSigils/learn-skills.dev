비밀번호 찾기/계정 복구 인증 결함 — 5가지 고유 패턴: (1) 유효한 이메일과 유효하지 않은 이메일에 대해 서로 다른 응답을 통한 사용자 이름 열거, (2) API 응답 본문에 직접 노출되는 재설정 토큰, (3) 사용 후 무효화되지 않은 재설정 토큰(재생), (4) 비밀번호 재설정 링크가 다른 IP/브라우저에서 작동(바인딩 없음), (5) 재설정 요청 엔드포인트에 속도 제한이 없습니다. 이는 재설정 이메일 호스트 헤더 중독(hunt-host-header) 및 전체 ATO 체인과 구별되는 독립형 복구 흐름 깨진 인증 기본 요소입니다(hunt-ato는 ATO 경로로 비밀번호 재설정을 소유합니다. 여기에서 기본 요소를 증명하고 거기에 연결합니다). 탐지: 요청부터 사용할 토큰까지 전체 비밀번호 분실 흐름을 추적합니다. 유효한 이메일/잘못된 이메일 간의 응답 차이를 확인합니다. 소비 후 토큰 재생을 테스트합니다. 중간에서 높음(열거=중간, 토큰 재사용=높음, 계정 탈취=알려진 이메일에 연결된 경우 중요).
