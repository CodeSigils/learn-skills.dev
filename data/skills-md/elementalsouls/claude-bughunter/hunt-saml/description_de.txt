Verjagen Sie SAML-/SSO-Angriffe. Muster: XML Signature Wrapping (XSW1-XSW8) – Assertion ändern und gleichzeitig die Gültigkeit der Signatur beibehalten, indem signiertes Element verschoben wird, Kommentarinjektion in NameID (admin@target.com<!--evil-->@attacker.com → einige Parser sehen admin@target.com), Signaturentfernung (Signaturelement vollständig entfernen, Server sollte ablehnen, tut dies aber nicht), Schlüsselverwechslung (vom IdP des Angreifers signiert, vom SP akzeptiert), Zielgruppenbeschränkung nicht validiert, Wiederholungsangriff (dieselbe Behauptung wird innerhalb des Gültigkeitsfensters zweimal akzeptiert). Tools: SAML Raider Burp-Erweiterung, samlmagic, manuelle XML-Manipulation. Erkennung: alle /saml-Endpunkte, /Shibboleth.sso, /sso/saml/, Microsoft ADFS-Endpunkte. Validieren: Kontoübernahme über geänderte NameID, Injektion der Administratorrolle über geändertes AttributeStatement. Echte kostenpflichtige Beispiele für Auth0, Okta, Microsoft und benutzerdefinierte SAML-Implementierungen. Wird bei der Suche nach SSO-Flows verwendet, wenn SAML AssertionConsumerService erreichbar ist, wenn IdP-Vertrauen mit SP-Identitätswechsel verkettet wird.
