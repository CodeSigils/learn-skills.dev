Неправильная конфигурация безопасности API Hunt — массовое присвоение, атаки JWT, загрязнение прототипов, CORS, подделка HTTP-глаголов. Массовое назначение: отправьте {is_admin:true, role:admin, Verified:true} на конечные точки профиля/аккаунта/сброса — сервер применяет слепо. JWT: alg=none, слабый перебор HMAC, обход детского пути, внедрение JWK, путаница токенов. Загрязнение прототипа: внедрение __proto__ в JSON merge / Object.assign / lodash _.merge → загрязненный прототип достигает приемника (RCE в узле, XSS в браузере). CORS: подстановочный знак с учетными данными, нулевое происхождение, регулярное выражение с захватом поддомена, проверки происхождения postMessage. HTTP-глагол: GET-bypass-CSRF, X-HTTP-Method-Override, TRACE включен. Обнаружение: ответы API с дополнительными полями, JWT в заголовках (декодирование на jwt.io), предварительные ответы CORS. Используйте при поиске неправильных конфигураций API, недостатков JWT, массового присвоения, загрязнения прототипов, обхода CORS.
