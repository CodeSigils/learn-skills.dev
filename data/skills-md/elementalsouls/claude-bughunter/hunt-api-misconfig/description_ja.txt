Hunt API セキュリティの構成ミス - 一括割り当て、JWT 攻撃、プロトタイプ汚染、CORS、HTTP 動詞の改ざん。一括割り当て: プロファイル/アカウント/リセット エンドポイントで {is_admin:true、role:admin、verified:true} を送信します — サーバーは盲目的に適用します。 JWT: alg=none、弱い HMAC ブルートフォース、キッド パス トラバーサル、JWK インジェクション、トークンの混乱。プロトタイプの汚染: JSON マージ / Object.assign / lodash _.merge での __proto__ インジェクション → 汚染されたプロトタイプがシンクに到達します (ノードの RCE、ブラウザーの XSS)。 CORS: 資格情報を含むワイルドカード、null オリジン、サブドメイン引き継ぎを伴う正規表現、postMessage オリジン チェック。 HTTP 動詞: GET-bypass-CSRF、X-HTTP-Method-Override、TRACE が有効。検出: 追加フィールドを含む API 応答、ヘッダー内の JWT (jwt.io でデコード)、CORS プリフライト応答。 API の構成ミス、JWT の欠陥、一括割り当て、プロトタイプの汚染、CORS バイパスを探すときに使用します。
