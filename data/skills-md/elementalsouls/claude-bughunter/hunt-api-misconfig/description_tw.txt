Hunt API 安全設定錯誤 — 批次分配、JWT 攻擊、原型污染、CORS、HTTP 動詞篡改。批次分配：在設定檔/帳戶/重置端點上傳送 {is_admin:true, role:admin, verify:true} - 伺服器盲目應用。 JWT：alg=none、弱 HMAC 暴力破解、kid 路徑遍歷、JWK 注入、令牌混淆。原型污染：JSON merge / Object.assign / lodash _.merge 中的 __proto__ 注入 → 污染的原型到達接收器（Node 中的 RCE，瀏覽器中的 XSS）。 CORS：帶有憑證的通配符、空源、帶子域接管的正規表示式、postMessage 來源檢查。 HTTP 謂詞：GET-bypass-CSRF、X-HTTP-Method-Override、啟用 TRACE。偵測：具有額外欄位的 API 回應、標頭中的 JWT（在 jwt.io 上解碼）、CORS 預檢回應。在尋找 API 錯誤配置、JWT 缺陷、批量分配、原型污染、CORS 繞過時使用。
