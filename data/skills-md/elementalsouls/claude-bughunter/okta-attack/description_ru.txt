Цепочка атак красной команды Okta-as-IdP — обнаружение клиентов, перечисление пользователей (несколько векторов), анализ потока аутентификации (перечисление факторов, усталость от push-уведомлений, обход SMS), распыление паролей с дисциплиной блокировки, специфичные для Okta фишинговые примитивы (наборы, злоупотребление FastPass, подделка OIDC redirect_uri), перечисление MFA, поверхность административного API после компрометации. Многие корпоративные организации используют Okta вместо Entra ID (или вместе с ним). Разные конечные точки, разные лимитирующие скорости, разные потоки факторов. Используйте, когда при проверке отображаются `<tenant>.okta.com`, `<tenant>.okta-emea.com`, `<tenant>.oktapreview.com` или записи в стиле автообнаружения, указывающие на Okta IdP.
