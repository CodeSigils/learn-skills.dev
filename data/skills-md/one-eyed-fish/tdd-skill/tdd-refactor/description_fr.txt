Flux de travail TDD pur pour le développement de fonctionnalités inédites, les corrections de bogues, les refacteurs préservant le comportement, les tests de caractérisation et le travail de caractérisation puis de correction. À utiliser lorsque le Codex a besoin d'une discipline axée sur les tests pour créer un nouveau comportement à partir de zéro ou modifier le code existant sans dérive de comportement. S’applique à tous les langages et architectures. Ne pas utiliser pour des règles de superposition spécifiques à une technologie, des modifications de documentation uniquement, des modifications triviales de formatage uniquement ou des prototypes purement exploratoires pour lesquels aucun comportement exécutable n'est attendu.
