Orchestre l’assurance qualité manuelle pendant le sprint par ticket aux étapes 1 (planification), 2 (exécution) et 3 (rapports). À utiliser pour les tests de récits utilisateur, les nouveaux tests de bogues et les boucles d'assurance qualité de sprint par lots. Crée le dossier PBI, pilote le démarrage de la session, exécute l'arbre de décision triage + veto + score de risque sur les bogues, produit les artefacts ATP + ATR + TC dans le TMS, exécute l'exploration de fumée et de trifuerza (UI/API/DB), et classe le commentaire final d'assurance qualité + les rapports de bogues. Déclencheurs sur : tester ce ticket, contrôler la qualité de cette user story, retester ce bug, vérifier la correction du bug, exécuter des tests exploratoires, tester une fonctionnalité, traiter le sprint, prochain ticket dans le sprint, générer le framework SPRINT-N-TESTING, reprendre les tests de sprint, continuer à partir d'un ticket. Ne PAS utiliser pour la documentation TMS de l'étape 4 + ROI (documentation de test), le codage d'automatisation de l'étape 5 (automatisation des tests), l'exécution de la suite de régression de l'étape 6 (tests de régression) ou l'intégration d'un nouveau dépôt (découverte du projet).
