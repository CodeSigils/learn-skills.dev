Playwright + TypeScript の KATA (コンポーネント アクション テスト アーキテクチャ) に従って自動テストを計画、作成、レビューします。 E2E または API/統合テストの作成、ページまたは API コンポーネントの作成、ATC の設計、テスト データのパラメータ化、フィクスチャの登録、または KATA 準拠のテスト コードのレビューを行うときに使用します。トリガー: テストの作成、テストの自動化、E2E テストの作成、API テストの作成、統合テスト、KATA、ページ オブジェクト、API コンポーネント、実装計画、ATC、自動テスト ケース、テスト コードのレビュー、モジュールの自動化、チケットの自動化、回帰テストの追加。テスト コードを記述する前に必ずロードしてください -- KATA フィクスチャの選択、インライン ロケーター ルール、ATC アイデンティティ ルール、およびインポート エイリアスの要件は、標準の Playwright 規則とは異なります。スイートの実行 (回帰テスト)、Jira/Xray での TC の文書化 (テスト ドキュメント)、リポジトリのオンボーディング (プロジェクト検出)、またはスプリント全体のテストの調整 (スプリント テスト) には使用しないでください。
