Modalità di evoluzione del framework: evolve il boilerplate stesso del QA (KATA, fixtures, cli/, scripts/, api/schemas/ pipeline, package.json deps). Piano autonomo → Codice → Verifica → Pipeline di archivio; viene eseguito con l'installazione "gentle-ai install --preset minimal" (non sono richieste competenze SDD-*). Da utilizzare quando si aggiungono nuove API di dispositivi, si esegue il refactoring delle classi base KATA, si evolve il programma di installazione, si modifica la pipeline di sincronizzazione OpenAPI o qualsiasi modifica all'infrastruttura del framework che NON sia la scrittura di test per ticket o il QA manuale. Si attiva su: /framework-development, "evolve framework", "framework refactor", "new fixture API", "modify KATA base", "refactor cli", "boilerplate Evolution". NON utilizzare per: scrivere test per un ticket (usare /test-automation), QA manuale per ticket (usare /sprint-testing), documentare casi di test (usare /test-documentation), eseguire suite di regressione (usare /regression-testing).
