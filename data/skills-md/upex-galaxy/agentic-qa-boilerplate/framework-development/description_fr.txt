Mode d'évolution du framework : fait évoluer le modèle d'assurance qualité lui-même (KATA, luminaires, cli/, scripts/, api/schemas/pipeline, package.json deps). Plan autonome → Code → Vérifier → Pipeline d'archives ; s'exécute sous l'installation `gentle-ai install --preset minimal` (aucune compétence SDD-* requise). À utiliser lors de l'ajout de nouvelles API d'appareil, de la refactorisation des classes de base KATA, de l'évolution du programme d'installation, de la modification du pipeline de synchronisation OpenAPI ou de toute modification de l'infrastructure du framework qui n'est PAS une écriture de test par ticket ou une assurance qualité manuelle. Déclencheurs sur : /framework-development, "evolve framework", "framework refactor", "nouvelle API de luminaire", "modifier la base KATA", "refactor cli", "évolution passe-partout". Ne PAS utiliser pour : l'écriture de tests pour un ticket (utiliser /test-automation), l'assurance qualité manuelle par ticket (utiliser /sprint-testing), la documentation des cas de test (utiliser /test-documentation), l'exécution de suites de régression (utiliser /regression-testing).
