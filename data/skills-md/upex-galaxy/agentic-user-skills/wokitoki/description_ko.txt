WokiToki(`toki`) — 로컬 브라우저 기반 인간 참여형 피드백 CLI AI는 대화 중간에 구조화되고 고정된 포인트별 답변을 수집하도록 유도합니다. 사용 시기: AI는 사용자가 한 번에 최대 3개 이상의 결정 지점에 반응하도록 요구하거나 사용자가 한 번에 한 지점씩 답변하기를 원할 수 있는 긴 다중 섹션 설명/보고를 요구합니다. 이는 'AskUserQuestion'(~4개의 질문 × ~4개의 옵션으로 제한되고, 터미널 제한이 있고, 풍부한 자유 텍스트가 없으며, 답변하는 동안 참조 내용을 표시할 수 없음)을 능가하고 인라인 산문 설문지(AI가 각 질문/단락에 다시 추측해야 하는 고정되지 않은 답변을 생성함)를 능가합니다. 작동 방식: AI는 'blocks'의 사양 JSON을 작성하고('controls'가 있는 블록은 질문, 'controls'가 없는 블록은 보고서 단락, 혼합은 하이브리드 형식), 'toki <specPath>'(기술이 처음 사용할 때 구축하는 전역 바이너리)를 실행하고 사용자는 단일/다중/토글 컨트롤 + 블록별 자유 텍스트 필드 + 인용 강조 표시를 사용하여 로컬 어두운 테마 웹 UI에서 응답합니다. 제출 시 도구는 결과 JSON만 stdout으로 인쇄합니다(배너/오류는 stderr로 이동). AI는 동일한 턴을 읽고 정확하고 고정된 피드백을 계속 제공합니다. 트리거 조건: `wokitoki`, `toki`, `피드백 UI`, `점점 하나씩 물어보세요`, `브라우저에서 답변하겠습니다`, `결정 양식`, `대화형 피드백`, `이 계획을 하나씩 검토`, `각 섹션에 반응`, `3개 이상의 질문`, `장문의 설명에 하나씩 응답하고 싶습니다`. 사용자가 'toki'라고 말하지 않는 경우에도 이 기술을 사용하세요. 작업이 많은 결정이나 긴 보고서에 대한 세부적이고 고정된 피드백을 수집하는 것이라면 이 기술이 적합한 도구입니다. 다음에는 사용하지 마십시오: 사소한 1~2개 옵션 선택 또는 단일 예/아니요(`AskUserQuestion` 사용) 또는 브라우저에 응답할 사람이 없는 비대화형/CI/일회성 출력.
