WokiToki (`toki`) — ローカルのブラウザーベースの人間参加型フィードバック CLI で、AI が会話中に駆動して、構造化されアンカーされたポイントごとの回答を収集します。使用する場合: AI は、ユーザーが一度に最大 3 つ以上の意思決定ポイントに反応する必要があるか、またはユーザーが一度に 1 つのポイントずつ回答したいと考えている長い複数セクションの説明/レポートに反応する必要があります。これは、「AskUserQuestion」（最大 4 つの質問 × 約 4 つの選択肢に制限されており、端末に制限されており、リッチなフリーテキストがなく、回答中に参照コンテンツを表示できない）を上回り、インラインの散文アンケート（AI が各質問/段落を推測してマップし直す必要があるアンカーなしの回答を生成する）を上回ります。仕組み: AI は「blocks」のスペック JSON を書き込み (「controls」のあるブロックは質問、「controls」のないブロックはレポートの段落、ミックスはハイブリッド フォーム)、「toki <specPath>」 (スキルが最初の使用時に構築されるグローバル バイナリ) を実行し、ユーザーはシングル/マルチ/トグル コントロール + ブロックごとのフリーテキスト フィールドを備えたローカルのダークテーマの Web UI で回答します。 + ハイライトから引用まで;送信時に、ツールは結果 JSON のみを stdout に出力します (バナー/エラーは stderr に送られます)。AI は同じターンを読み取り、正確で固定されたフィードバックを継続します。トリガー: 「wokitoki」、「toki」、「フィードバック UI」、「ポイントごとに質問する」、「ブラウザで回答させる」、「決定フォーム」、「インタラクティブなフィードバック」、「この計画をポイントごとにレビューする」、「各セクションに反応する」、「3 つ以上の質問」、「部分的に回答したい長い説明」。ユーザーが「トキ」と言わない場合でも、このスキルを使用します。タスクが多くの意思決定または長いレポートに関する詳細な固定フィードバックを収集することである場合、これは適切なツールです。次の目的には使用しないでください: 些細な 1 ～ 2 の選択肢の選択、または単一の「はい/いいえ」 (`AskUserQuestion` を使用)、またはブラウザーで応答する人間がいない非対話型 / CI / ワンショット出力。
