Используйте этот навык для создания автоматизированных API и комплексных тестов для уже реализованных функций с использованием существующей среды тестирования проекта. Вызывайте, когда пользователь говорит «создать автоматические тесты QA для [функции]», «создать тесты e2e» или когда реализованный код требует проверенного тестового покрытия. Навык обнаруживает существующую среду тестирования, определяет функции или компоненты для тестирования, генерирует читаемые и поддерживаемые тестовые файлы с упором на счастливые пути и критические случаи ошибок, затем выполняет тесты и исправляет любые сбои перед созданием сводного документа о покрытии. Входные данные — это имя объекта, путь к компоненту или каталог. На выходе — тестовые файлы и сводка покрытия. В отличие от bmad-bmm-code-review (который проверяет критерии приемлемости истории), этот навык касается исключительно создания тестового кода. Не используйте функции, которые еще не существуют — сначала реализуйте их с помощью bmad-bmm-dev-story или bmad-bmm-quick-dev, а затем создавайте тесты. Для расширенной стратегии тестирования используйте модуль TEA.
