Utilisez cette compétence pour générer des API automatisées et des tests de bout en bout pour les fonctionnalités déjà implémentées à l'aide du cadre de test existant du projet. Invoquer lorsque l'utilisateur dit « créer des tests automatisés d'assurance qualité pour [fonctionnalité] », « générer des tests e2e » ou lorsque le code implémenté nécessite une couverture de test vérifiée. La compétence détecte le cadre de test existant, identifie les fonctionnalités ou les composants à tester, génère des fichiers de test lisibles et maintenables en se concentrant sur les chemins heureux et les cas d'erreurs critiques, puis exécute les tests et corrige les éventuels échecs avant de produire un document récapitulatif de couverture. L'entrée est un nom de fonctionnalité, un chemin de composant ou un répertoire. Le résultat est des fichiers de test et un résumé de la couverture. Contrairement à bmad-bmm-code-review (qui valide les critères d'acceptation de l'histoire), cette compétence consiste uniquement à générer du code de test. Ne pas utiliser sur des fonctionnalités qui n'existent pas encore — implémentez d'abord avec bmad-bmm-dev-story ou bmad-bmm-quick-dev, puis générez des tests. Pour une stratégie de test avancée, utilisez le module TEA.
