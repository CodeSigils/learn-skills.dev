使用此技能透過機械路徑追蹤來詳盡枚舉差異、完整文件或函數中的每個未處理的程式碼路徑和邊界條件 - 而不是直觀的審查。當使用者說「尋找邊緣情況」、「尋找未處理的路徑」時，或當其他技能需要對程式碼變更進行純路徑分析時呼叫。此技能有系統地遍歷每個分支、循環和條件，僅收集缺乏明確處理的路徑，然後默默地丟棄已處理的路徑。輸出是結果的 JSON 數組，沒有額外的文字或 Markdown 包裝。每個發現包含：位置（檔案和行範圍）、trigger_condition（單行描述）、guard_snippet（縮小差距的最小程式碼草圖）和潛在結果（可能出錯的地方）。接受可選的also_consider輸入以將注意力集中在特定區域。處理所有路徑時傳回一個空數組。不是一般的程式碼審查 - 使用 bmad-core-review-adversarial-general 進行審查。
