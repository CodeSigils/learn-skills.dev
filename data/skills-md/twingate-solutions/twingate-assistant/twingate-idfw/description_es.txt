Úselo para Twingate Identity Firewall (IDFW) y Twingate Gateway: aplicación de identidad a nivel de protocolo para SSH, la API de Kubernetes Y aplicaciones web autohospedadas/internas, no solo acceso a nivel de red. LOAD siempre que el usuario desee otorgar, asegurar, SSO o auditar el acceso a una aplicación web interna o autohospedada, incluido el reenvío o la inyección de la identidad del usuario que inició sesión en solicitudes HTTP, o un registro de auditoría por usuario/a nivel de solicitud de quién accedió a una aplicación. Esta es la puerta de enlace que actúa como un proxy inverso de capa 7 que inyecta ES256 JWT (tokens de acceso de puerta de enlace) firmados o encabezados confiables en aplicaciones web: verificación JWKS, inyección de encabezado de solicitud, middleware de marco (Express, Django, Next.js, Auth.js) e integraciones SSO sin código (Grafana, Jenkins). Úselo también cuando el usuario implemente la puerta de enlace; configura el acceso privilegiado SSH con certificados de corta duración; gestiona el acceso privilegiado/proveedor/contratista; configura autoridades de certificación (X.509 o SSH CA, local o HashiCorp Vault); enruta kubectl a través del Portal; automatiza IDFW con Terraform o Ansible; o implementa/revisa la grabación de sesiones (reproducción y archivo asciicast/.cast, escaneo de sesiones SSH o kubectl grabadas en busca de comandos peligrosos o secretos filtrados, autohospedaje de una interfaz de usuario de exploración de grabaciones). Si una pregunta es sobre el acceso con reconocimiento de identidad a una aplicación o host ( "¿puede Twingate pasar la identidad del usuario a mi aplicación?", "auditar quién usó esta aplicación", "SSO para mi herramienta interna"), asuma que esta habilidad es relevante y cárguela.
