用于 Twingate Identity Firewall (IDFW) 和 Twingate Gateway — 用于 SSH、Kubernetes API 和自托管/内部 Web 应用程序的协议级身份实施，而不仅仅是网络级访问。每当用户想要授予、保护、SSO 或审核对自托管或内部 Web 应用程序的访问权限时，都可以进行 LOAD - 包括将登录用户的身份转发或注入到 HTTP 请求中，或者对访问应用程序的用户进行每用户/请求级别的审核跟踪。这是充当第 7 层反向代理的网关，将签名的 ES256 JWT（网关访问令牌）或可信标头注入到 Web 应用程序中：JWKS 验证、请求标头注入、框架中间件（Express、Django、Next.js、Auth.js）和无代码 SSO 集成（Grafana、Jenkins）。也可在用户部署网关时使用；使用短期证书配置 SSH 特权访问；管理特权/供应商/承包商访问；配置证书颁发机构（X.509 或 SSH CA、本地或 HashiCorp Vault）；通过网关路由 kubectl；使用 Terraform 或 Ansible 实现 IDFW 自动化；或实现/审查会话记录（asciicast/.cast 播放和存档、扫描记录的 SSH 或 kubectl 会话以查找危险命令或泄露的秘密、自托管记录浏览 UI）。如果问题涉及对应用程序或主机的身份感知访问 - “Twingate 可以将用户身份传递到我的应用程序吗？”、“审核谁使用了此应用程序”、“我的内部工具的 SSO” - 假设此技能相关并加载它。
