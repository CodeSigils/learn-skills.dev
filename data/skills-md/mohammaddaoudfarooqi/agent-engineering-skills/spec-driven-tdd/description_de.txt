Disziplinierter, spezifikationsgesteuerter, testgesteuerter Entwicklungsworkflow zum Erstellen von Software mit KI-Codierungsagenten. Wandelt mehrdeutige Anfragen durch strukturierte Spezifikation, Testableitung und strikte TDD in verifizierte Implementierungen um. Behandelt Greenfield-Projekte, Brownfield-Erweiterungen (mit oder ohne vorhandene Tests), Refaktorierungen und komplexe Fehlerbehebungen mit jeweils Workflow-spezifischer Anleitung. Verwenden Sie diese Option, wenn der Benutzer eine neue Funktion, ein neues Modul, eine Erweiterung, einen Refactor, eine neue API, eine Datenpipeline, ein CLI-Tool oder ein neues System mit mehreren Anforderungen, Grenzfällen oder unklaren Spezifikationen anfordert. Auch für komplexe Fehlerbehebungen geeignet, die eine Ursachenanalyse erfordern. Löst Auslöser bei Ausdrücken wie „Funktion hinzufügen“, „Implementieren“, „Neues Modul erstellen“, „API erstellen“, „CLI erstellen“, „Datenpipeline erstellen“, „Umgestalten“, „Diesen Fehler beheben“, „Tests schreiben für“, „TDD“, „zuerst testen“, „Die Anforderungen sind unklar“, „Charakterisierungstests“ oder „Dies spezifizieren“ aus. Wird ausgelöst, wenn Code mit angrenzenden Testdateien (`tests/`, `*_test.py`, `*.test.ts`, `*.spec.ts`, `spec/`, `__tests__/`) oder Test-Framework-Konfiguration (pytest.ini, jest.config.*, go.mod mit Testimporten, Cargo.toml mit [dev-dependencies], package.json mit einem Testskript) geändert wird. Wird ausgelöst, wenn der Benutzer Randfälle, Invarianten, Akzeptanzkriterien, EARS-Notation oder Rot-Grün-Refaktor erwähnt. NICHT für einfache einzeilige Korrekturen, kosmetische Änderungen, Formatierungen, Umbenennungen, Abhängigkeitserweiterungen oder Aufgaben verwenden, bei denen die Anforderungen bereits vollständig mit bereitgestellten Tests spezifiziert sind.
