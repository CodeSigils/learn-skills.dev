Дисциплинированный рабочий процесс разработки на основе спецификаций и тестирования для создания программного обеспечения с помощью агентов кодирования искусственного интеллекта. Преобразует неоднозначные запросы в проверенные реализации посредством структурированной спецификации, разработки тестов и строгого TDD. Управляет новыми проектами, усовершенствованиями существующих (с существующими тестами или без них), рефакторингами и сложными исправлениями ошибок, используя для каждого из них конкретные рабочие процессы. Используйте, когда пользователь запрашивает новую функцию, модуль, улучшение, рефакторинг, API, конвейер данных, инструмент CLI или систему с множеством требований, крайними случаями или неясными спецификациями. Также используйте для исправления сложных ошибок, требующих анализа первопричин. Запускается по таким фразам, как «добавить функцию», «реализовать», «создать новый модуль», «создать API», «создать CLI», «создать конвейер данных», «рефакторинг», «исправить эту ошибку», «написать тесты для», «TDD», «сначала тестировать», «требования неясны», «тесты характеристик» или «определить это». Срабатывает при изменении кода с помощью соседних тестовых файлов (`tests/`, `*_test.py`, `*.test.ts`, `*.spec.ts`, `spec/`, `__tests__/`) или конфигурации тестовой среды (pytest.ini, jest.config.*, go.mod с тестовым импортом, Cargo.toml с [dev-зависимостями], package.json с тестовым скриптом). Срабатывает, когда пользователь упоминает крайние случаи, инварианты, критерии приемки, нотацию EARS или рефакторинг red-green. НЕ используйте для простых однострочных исправлений, косметических изменений, форматирования, переименования, увеличения зависимостей или задач, где требования уже полностью определены с помощью предоставленных тестов.
