Flusso di lavoro di sviluppo disciplinato basato su specifiche e test per la creazione di software con agenti di codifica AI. Trasforma richieste ambigue in implementazioni verificate tramite specifiche strutturate, derivazione di test e TDD rigoroso. Gestisce progetti greenfield, miglioramenti brownfield (con o senza test esistenti), refactoring e correzioni di bug complessi con indicazioni specifiche per il flusso di lavoro per ciascuno. Da utilizzare quando l'utente richiede una nuova funzionalità, modulo, miglioramento, refactoring, API, pipeline di dati, strumento CLI o sistema con più requisiti, casi limite o specifiche poco chiare. Utilizzabile anche per correzioni di bug complesse che richiedono l'analisi della causa principale. Si attiva su frasi come "aggiungi una funzionalità", "implementa", "crea un nuovo modulo", "crea un'API", "crea una CLI", "crea una pipeline di dati", "refactoring", "correggi questo bug", "scrivi test per", "TDD", "test-first", "i requisiti non sono chiari", "test di caratterizzazione" o "specificalo". Si attiva quando si modifica il codice con file di test adiacenti (`tests/`, `*_test.py`, `*.test.ts`, `*.spec.ts`, `spec/`, `__tests__/`) o configurazione del framework di test (pytest.ini, jest.config.*, go.mod con importazioni di test, Cargo.toml con [dev-dependencies], package.json con uno script di test). Si attiva quando l'utente menziona casi limite, invarianti, criteri di accettazione, notazione EARS o refactoring rosso-verde. NON utilizzare per semplici correzioni su una riga, modifiche estetiche, formattazione, ridenominazioni, aumenti di dipendenze o attività in cui i requisiti sono già completamente specificati con i test forniti.
