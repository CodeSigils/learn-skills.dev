Flux de travail de développement discipliné, axé sur les spécifications et les tests, pour créer des logiciels avec des agents de codage IA. Transforme les demandes ambiguës en implémentations vérifiées grâce à une spécification structurée, une dérivation de tests et un TDD strict. Gère les nouveaux projets, les améliorations des friches industrielles (avec ou sans tests existants), les refactors et les corrections de bogues complexes avec des conseils spécifiques au flux de travail pour chacun. À utiliser lorsque l'utilisateur demande une nouvelle fonctionnalité, un module, une amélioration, une refactorisation, une API, un pipeline de données, un outil CLI ou un système avec plusieurs exigences, des cas extrêmes ou des spécifications peu claires. À utiliser également pour les corrections de bogues complexes nécessitant une analyse des causes profondes. Se déclenche sur des expressions telles que « ajouter une fonctionnalité », « implémenter », « créer un nouveau module », « créer une API », « créer une CLI », « créer un pipeline de données », « refactoriser », « corriger ce bug », « écrire des tests pour », « TDD », « tester d'abord », « les exigences ne sont pas claires », « tests de caractérisation » ou « spécifier ceci ». Se déclenche lors de la modification du code avec des fichiers de test adjacents (`tests/`, `*_test.py`, `*.test.ts`, `*.spec.ts`, `spec/`, `__tests__/`) ou la configuration du framework de test (pytest.ini, jest.config.*, go.mod avec des importations de tests, Cargo.toml avec [dev-dependencies], package.json avec un script de test). Se déclenche lorsque l'utilisateur mentionne des cas extrêmes, des invariants, des critères d'acceptation, la notation EARS ou un refactor rouge-vert. Ne PAS utiliser pour de simples correctifs d'une seule ligne, des modifications esthétiques, du formatage, des renommages, des modifications de dépendances ou des tâches pour lesquelles les exigences sont déjà entièrement spécifiées avec les tests fournis.
