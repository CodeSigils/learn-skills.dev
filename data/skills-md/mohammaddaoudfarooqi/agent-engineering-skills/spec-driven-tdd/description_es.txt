Flujo de trabajo de desarrollo disciplinado basado en pruebas y basado en especificaciones para crear software con agentes de codificación de IA. Transforma solicitudes ambiguas en implementaciones verificadas mediante especificaciones estructuradas, derivación de pruebas y TDD estricto. Maneja proyectos nuevos, mejoras antiguas (con o sin pruebas existentes), refactorizaciones y correcciones de errores complejas con orientación específica del flujo de trabajo para cada uno. Úselo cuando el usuario solicite una nueva característica, módulo, mejora, refactorización, API, canalización de datos, herramienta CLI o sistema con múltiples requisitos, casos extremos o especificaciones poco claras. Utilícelo también para correcciones de errores complejos que requieran un análisis de la causa raíz. Activadores de frases como "agregar una característica", "implementar", "crear un nuevo módulo", "crear una API", "crear una CLI", "crear una canalización de datos", "refactorizar", "corregir este error", "escribir pruebas para", "TDD", "probar primero", "los requisitos no están claros", "pruebas de caracterización" o "especificar esto". Se activa al modificar código con archivos de prueba adyacentes (`tests/`, `*_test.py`, `*.test.ts`, `*.spec.ts`, `spec/`, `__tests__/`) o configuración del marco de prueba (pytest.ini, jest.config.*, go.mod con importaciones de prueba, Cargo.toml con [dev-dependencies], package.json con un script de prueba). Se activa cuando el usuario menciona casos extremos, invariantes, criterios de aceptación, notación EARS o refactor rojo-verde. NO lo use para correcciones simples de una línea, cambios cosméticos, formato, cambios de nombre, aumentos de dependencia o tareas donde los requisitos ya estén completamente especificados con las pruebas proporcionadas.
