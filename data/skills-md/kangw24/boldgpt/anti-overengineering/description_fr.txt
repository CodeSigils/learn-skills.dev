Deux modes. (1) Empêche la sur-ingénierie de l'IA sur des tâches de développement/recherche simples : ajout de signatures/verrous de hachage au-dessus de git, écriture de seuils d'admission de 200 lignes, demande d'autorisation écrite pour les ensembles de données publics, sur-validation des clés de configuration, insertion d'essai/sauf/repli dans les scripts de formation, génération de fichiers de test pour les fichiers de test, croissance illimitée du grand livre/de la bible, prolifération de copies de fichiers v1/v2/v3 au lieu d'utiliser des branches git. (2) Supprime le slop de l'IA du code existant - commentaires de narration, capture d'exceptions larges, interfaces à implémentation unique, usine pour un, anti-modèle GenericButton, dénomination _v2/enhanced_, cales de compatibilité avec zéro consommateur, assertions de test impossibles à échouer, modules surdimensionnés > 250 LOC. Utilisez cette compétence chaque fois que vous écrivez du code d'expérience, des configurations, des scripts de formation, des tests, des registres, du code de gestion d'ensembles de données, de la fiction OU lors de la révision/nettoyage du code existant généré par l'IA. S'active automatiquement sur toute tâche impliquant la gestion des versions, les signatures, les hachages, la validation, la gestion des erreurs, la reproductibilité, les ensembles de données, la dénomination des fichiers, OU lorsque l'utilisateur dit "supprimer le slop", "nettoyer le code AI", "deslop", "nettoyer le code généré par l'IA". En cas de doute, déclenchez-le : la sur-ingénierie est plus difficile à détecter que la sous-ingénierie.
