Zwei Modi. (1) Verhindert übermäßiges KI-Engineering bei einfachen Entwicklungs-/Forschungsaufgaben – Hinzufügen von Signaturen/Hash-Sperren zusätzlich zu Git, Schreiben von 200-Zeilen-Zulassungsschwellenwerten, Einfordern einer schriftlichen Autorisierung für öffentliche Datensätze, Übervalidierung von Konfigurationsschlüsseln, Stopfen von Try/Exception/Fallback in Trainingsskripte, Generieren von Testdateien für Testdateien, unbegrenztes Ledger-/Bibelwachstum, Vermehrung von v1/v2/v3-Dateikopien anstelle der Verwendung von Git-Zweigen. (2) Entfernt KI-Einbußen aus vorhandenem Code – Erzählkommentare, breites Ausnahmeabfangen, Single-Impl-Schnittstellen, Factory-for-One, GenericButton-Anti-Pattern, _v2/enhanced_-Benennung, kompatible Shims mit null Verbrauchern, fehlerfreie Testzusicherungen, übergroße Module >250 LOC. Verwenden Sie diese Fähigkeit beim Schreiben von Experimentcode, Konfigurationen, Trainingsskripten, Tests, Hauptbüchern, Code für die Datensatzverarbeitung, Fiktionen ODER beim Überprüfen/Bereinigen von vorhandenem KI-generiertem Code. Aktiviert sich automatisch bei jeder Aufgabe, die Versionierung, Signaturen, Hashes, Validierung, Fehlerbehandlung, Reproduzierbarkeit, Datensätze, Dateibenennung betrifft, ODER wenn der Benutzer „Slop entfernen“, „KI-Code bereinigen“, „Deslop“ oder „KI-generierten Code bereinigen“ sagt. Wenn Sie Zweifel haben, lösen Sie es aus – Over-Engineering ist schwerer selbst zu erkennen als Under-Engineering.
