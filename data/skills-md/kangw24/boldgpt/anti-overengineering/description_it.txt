Due modalità. (1) Previene l'ingegneria eccessiva dell'IA su semplici attività di sviluppo/ricerca: aggiunta di firme/hashlock su git, scrittura di soglie di ammissione di 200 righe, richiesta di autorizzazione scritta per set di dati pubblici, convalida eccessiva di chiavi di configurazione, inserimento di try/eccetto/fallback negli script di addestramento, generazione di file di test per file di test, crescita illimitata di registri/bibbie, proliferazione di copie di file v1/v2/v3 invece di utilizzare rami git. (2) Rimuove lo slop dell'intelligenza artificiale dal codice esistente: commenti narrativi, rilevamento ampio di eccezioni, interfacce a impl singolo, fabbrica per uno, anti-pattern GenericButton, denominazione _v2/enhanced_, shim compat con zero consumatori, asserzioni di test non fallibili, moduli sovradimensionati > 250 LOC. Utilizza questa competenza ogni volta che scrivi codice di esperimenti, configurazioni, script di formazione, test, registri, codice di gestione di set di dati, fiction o quando rivedi/pulisci il codice esistente generato dall'intelligenza artificiale. Si attiva automaticamente su qualsiasi attività che coinvolga controllo delle versioni, firme, hash, convalida, gestione degli errori, riproducibilità, set di dati, denominazione di file O quando l'utente dice "rimuovi slop", "pulisci codice AI", "deslop", "ripulisci codice generato da AI". In caso di dubbio, attivalo: l'ingegneria eccessiva è più difficile da auto-rilevare che l'ingegneria insufficiente.
