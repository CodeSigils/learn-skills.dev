# video-prompt

## 开始

- 接受一个就绪 Clip 或已确认的分镜列表。
- 计划中的 Prompt 工作要编译所有请求 Clip；从生成画面续接时，只从已观察并接受的终态继续。
- 保留精确文案、对白、已验证声明、参考材料、时长、比例、连续性和验收检查。

## 职责边界

- 输入是已确认的 Clip、分镜与已声明的参考素材；不依赖不存在的上游 Skill、资源注册表或固定供应商流程。
- 输出是最终双语自然语言 Prompt、参考素材的语义绑定和已知的用户输出规格。
- 不验证模型时长能力、素材是否真实可用、工具参数 schema 或资源上传结果；不分配 `output_id`，不生成工具调用 JSON，也不提交任务。`video-storyboard` 处理 Clip 规划与连续性，已配置的执行适配器在运行时完成真实资源、模型能力、参数和提交校验。

## 参考资料

- 需要做 A/B/C 判断、素材叙事化嵌入、镜头与台词组织时，按需读取 `references/video-prompt-engineering.md`。
- 需要处理增加、删除、替换、延长、衔接或多 Clip 连续性时，按需读取 `references/video-editing-and-continuity.md`。
- 参考资料只能启发画面表达与透传判断；不得把其中的任何工具语法、参数、固定模板或能力上限写入通用 Prompt。
- 冲突时依次服从：用户明确要求、当前已确认的素材与 Clip、已配置执行适配器的运行时能力与参数、本文核心规则、参考资料。

## 选择模式

- **T2V：** 没有源媒体控制身份或版式。
- **I2V：** 一张源图控制主体或产品身份；描述运动、镜头、光线、声音和终点。
- **R2V：** 多个参考有不同职责；为每个指定主要角色和不传递边界。
- **首尾帧：** 已知起始和结束图控制连续过渡。
- **编辑：** 保留源时间、动作、身份、镜头和版式，只改一个明确层次。
- **续接：** 从已接受画面或明确观察到的最终帧开始，只完成下一节点。

## 先决策：透传还是丰富

先把每个 Clip 分为 A、B、C；A/B 是默认，不要把所有需求套进同一模板。

| 类型 | 判定 | 编译方式 |
| --- | --- | --- |
| A 已详细 | 已有主体、场景、动作、台词、时长等多个要素 | 原样透传；只校正引用标记和已知输出规格，不追加首帧、构图、画质、镜头解释或默认负向限制。 |
| B 极简/泛化 | 很短，只给单一主体、动作或氛围词 | 轻透传：保留用户原文并补齐已有素材标记；不添加画质前缀、镜头模板或全局约束。只有主体或动作完全缺失时，才以用户提供的素材补最必要事实。 |
| C 有线索可丰富 | 有多动作阶段、可组织的台词/场景或明确画面细节 | 结构化丰富；只补用户意图或素材能够支持的控制。 |

- 不臆造用户或素材中没有的人物、场景、文字、台词、风格或镜头。
- 保留用户的语言、术语和风格信号；`cyberpunk`、`ASMR` 等词不强行翻译。
- 画面文字、字幕和声音台词是独立控制；“无字幕/无文字/无屏幕文字”不删除用户已写出的对白、旁白或口播。

## 镜头规则

- 用户给出机位、视角或运镜时，原意保留，不重复追加套话。
- “视角不变”“固定机位”“镜头角度不变”“画面保持不变”是硬约束，原词放在显著位置；不得改成轻微移动、推进或跟随。
- 用户没有镜头线索时，不擅自编排推、拉、摇、移或默认“自然镜头”等套话。
- 只有用户已给出镜头意图，或 C 类内容确实需要且有场景依据时，才用完整句写“动作 + 控制对象 + 路径/轨迹 + 速度关系”。

## C 类构造

将 C 类写成自然语言 Prompt，而不是强制显示模板标题：

`整体风格（按需） -> 主体 + 可观察动作 -> 环境/美学（按需） -> 台词与声音节点（如有） -> 必要全局约束`

- 主体和动作是必填骨架；环境、光影、材质、色彩、风格和音频只有在用户或素材给出依据时才补。
- 多阶段事件用“先……随后……接着……最后……”或连续时间段连接；单个 Clip 可以容纳同一主体的连续跨场动作、场景转换和多阶段演变，但必须写清状态与空间如何承接。
- 使用时间段时，每段写清 `开始-结束时间 + 阶段主题 + 物理动作/表情 + 镜头或画面结果`；只有确实帮助理解已有动作时，才补情感意图或镜头调度。
- 不用“电影感”“高级感”“有冲击力”等抽象词替代可见的动作、材质、光线、构图或节奏。

## 素材引用与绑定

- `kind=subject` 的参考主体始终写为 `@主体名称`；不得降级成 `@图片N`，并保留其主体标签。
- 普通图片、视频、音频分别写为 `@图片N`、`@视频N`、`@音频N`。这些是编译层的语义标签，不假定每个执行工具都接受相同的字面语法；执行适配器负责转换并验证真实绑定。
- 在 C 类中，每项素材都写明实际迁移的控制维度：图片可控制角色、服装、物品、场景、构图或 Logo；视频可控制动作、运镜、转场或特效；音频可控制音色、内容/口型、音乐或音效。A 类只校正既有标记，不重复扩写职责。
- 把标记直接嵌入叙事名词，例如“侦探@图片1迈步走进废弃仓库@图片2”；不要先列“参考素材”再另写故事。
- 每项参考在首次承担控制作用处，以及职责、对象或来源切换处，带正确标记。身份已清晰且没有歧义时可用自然代词；不要为了重复标签破坏长 Clip 的可读性。
- 多图、多视频有顺序或分工时，保持 Prompt 中的首次出现顺序与语义职责一致。真实生成时，执行适配器负责转换标记、检查素材并绑定到运行时参数；`video-prompt` 不选择或调用来源文档中的直连命令。

## 台词、音频与可见文字

- 保留用户给出的每一句台词、旁白和口播。普通角色写为“角色名@图片N说：「台词」音色：<描述>。”；主体角色写为“@主体名称说：「台词」音色：<描述>。”；旁白写为“旁白说：「内容」音色：<描述>。”。
- 使用 `@音频N` 时，说明它承担音色、内容与口型、音乐或音效中的哪一项，以及发生的画面节点和结束方式。音画同步写成可观察关系，不只写“卡点”或“对口型”。
- “无字幕/无文字/无屏幕文字”仅禁止可见文字，不删除台词、对白或旁白；“无台词/无对白/无旁白/静音”才禁止相应声音。用户未提负向约束时，不追加。
- 用户明确需要字幕、Slogan、气泡台词或其他画面文字时，写清原文、出现时机、位置、方式、视觉特征和与台词的同步关系；未要求时不自行添加文字、Logo 或 CTA。
- 台词或可见文字未指定语言时，保留用户原文的语言线索，不擅自追加语言限制。

## 连续动作、场景与延长

- 在已确认的 Clip 时长内，允许同一主体的多阶段动作、前后关联的场景和自然转场合并；用时间顺序和前一阶段的可见结果建立因果，不机械拆分。时长是否被目标模型接受，由运行时校验决定。
- 续接 `@视频N` 时，写明它结束后的下一个动作、主体状态、空间位置、光影和风格如何衔接；只从已提供或已接受的终态继续。
- 首尾帧、编辑和多参考工作同样遵循少改：只描述用户要求改变或保持的层次，不重设计其余部分。

## 连续工作

多个 Clip 的 Prompt 集使用分镜中已确认的连续状态并编译所有请求 Clip。下游 Prompt 的前置状态尚未被观察时，标记为基于规划。

生成后续接时，已接受画面覆盖计划中的前置状态。保留可见身份、服装、产品几何、道具归属、空间地理、屏幕方向、光线阶段、对白和未完成运动。不要重演已经完成的节点，也不要虚构未观察到的源状态。

后续 Clip 可以引用已确认分镜，但不要把计划状态假装成已经生成的画面。只有用户接受的结果、明确观察到的末帧或已提供素材，才是续接的事实起点。

## 输出

每个 Clip 只交付可直接使用的最终 Prompt；不要输出分类过程、素材映射表、模板标题、`output_id`、调用 JSON 或未请求的解释。

```markdown
Clip: <number or title>
English prompt:
<final prompt in natural prose>

中文提示词：
<等价的自然语言最终提示词>

```

英文和中文必须携带等价控制、相同的 `@` 标记、精确台词、时间段和用户术语。不要强制展示“素材描述 / 一句话概述 / 具体情节 / 全局补充”等标题；只有用户原文、长时间轴或复杂模块确实需要阅读结构时才保留相应标题。

多个 Clip 可以一次完整交付；真实生成时由 `video-create` 交给已配置的执行适配器，由它在运行时建立任务清单并执行。

## 执行

只交付最终 Prompt、参考素材的语义绑定和已知输出规格；用户明确要求真实生成时，由 `video-create` 交给已配置的执行适配器执行。

## 检查

- 已先作 A/B/C 决策；A/B 没有被套上画质、镜头或负向模板。
- C 类以“主体 + 可观察动作”为骨架，所有补充均有用户或素材依据。
- `@图片N`、`@视频N`、`@音频N` 都在其控制作用处出现；参考主体未降级，多参考的首次出现顺序与职责清楚。
- 用户的风格信号、英文术语、精确台词、固定机位和已写负向要求完整保留。
- 镜头规则成立：有指示则照写；固定视角不弱化；无指示不臆造具体运镜或默认套话。
- 台词、可见文字、字幕与声音约束没有互相误删；音频引用写清用途与节点。
- 时间段、跨场或续接有清楚的状态、空间和因果衔接；没有把未观察到的计划状态写成既有画面。
- 英文和中文等价，最终交付是自然语言 Prompt，不是强制四段标题模板。
- 没有把固定时长、素材注册、参数 schema、任务 ID、调用 JSON 或提交行为伪装成 Prompt 编译职责。
