# image-create

## 链路回显

在每次用户可见交付的首行写 `Route: <本次实际调用的创作 Skill，按顺序以 -> 连接>`。只列实际调用的 Skill；只有实际执行 SeaArt 时才追加 `seaart-execute -> SeaArt MCP`。不展示工具读取、内部推理或文件过程。

## 开始

- 用户说“直接生成”“马上出图”或指定 SeaArt 时，仍由本 Skill 先进入；这只允许跳过非必要的方向探索，不能跳过 `image-prompt`。
- 只提取当前交付物所需事实：用途、主体、输出、精确文案、参考图角色、锁定约束和禁用改动。
- 只询问会改变路由、身份、精确文案、参考图用途或交付方式的问题。设计澄清交给 `art-direction`。
- 用能完成任务的最小专业 Skill 集合继续。用户要求方向、Prompt 或执行时，不得停在分流本身；只有核心视觉方向尚未确认时，才停在方向确认。

## 深度

### 快速

针对单个边界清晰的 Prompt、编辑或具体方向，直接保留当前对话中的已确认信息并继续。

### 项目

当工作跨越多个专业 Skill、包含多个交付物或需要后续续接时，在当前对话中持续保留已确认的方向、约束和参考角色；不要创建 Brief、ID 或状态对象。

### 执行

先经过 `image-prompt`。用户明确要求使用 SeaArt 生成时，再交给可选的 `seaart-execute` 适配器。

没有已配置的执行适配器时，停在可直接使用的 Prompt；不要虚构生成结果、模型能力或任务状态。只有用户明确要求现在用 SeaArt 执行时，才调用 `seaart-execute` 检查 SeaArt CLI 与 MCP 是否已配置。

## 路由选择

- 图片需求、核心设计问题或可选视觉方向需要分析与探索时，用 `art-direction`。
- 版式、文案层级、传播表达或预留文字区是核心问题时，用 `image-poster`。
- Logo、字标、字母标、图形标、吉祥物标或既有 Logo 概念工作，用 `image-logo`。
- 身份需要跨多张输出或跨会话稳定时，用 `asset-reference`。
- 最终的新图或源图编辑 Prompt，用 `image-prompt`。

用户已经提供具体视觉方向、只要求改写 Prompt，或只要求边界清晰的编辑时，跳过 `art-direction`。

## 标准创作链路

需要从图片想法、编辑要求或已确认方向推进到可生成 Prompt 时，使用：

`image-create -> image-prompt`

`art-direction`、`image-poster`、`image-logo` 和 `asset-reference` 只在当前任务需要其专业判断时插入，不改变这条主链路。用户明确要求 SeaArt 真实生成时，再由 `image-create` 将完成的 Prompt 交给 `seaart-execute`。

## 画面转译

把用户的抽象要求转成可执行的画面控制，而不是原样堆叠风格词。至少判断：

- 主体和核心事件：谁或什么必须成为第一眼焦点；
- 构图：比例、视点、留白、前中后景和视觉重心；
- 光线：光源方向、软硬、明暗关系和时间感；
- 色彩：主色、辅助色、对比点和饱和度边界；
- 材质与空间：表面状态、尺度、背景层次和空气感；
- 文案与保留项：精确文字、可读区域、身份和不可改变部分。

“高级”“有电影感”“有冲击力”不是控制项。把它们落实为可观察关系，例如低机位与留白形成压迫感、单一硬光突出轮廓、克制色域让材质成为焦点。用户没有提供时可以补充保守默认值，但不得借此替换主体、品牌含义或传播目标。

## 画面质量判断

- 缩略图先看主体、主动作或主信息是否成立；全尺寸再看材质、光影和细节。
- 一个画面只保留一个主要视觉承诺。新增人物、道具、符号或背景信息必须服务它。
- 让主体、背景和文字区在明度、色相、清晰度或空间层次上分开，避免同一层抢焦。
- 不用漂浮装饰、无因果的粒子、过量镜面高光、模板化霓虹或无意义道具充当“完成度”。
- 多张输出的变化必须来自构图、视点、场景任务或信息层级，不能只是换色或换背景。

## 参考图角色

参考图角色不明确时，只询问它是否控制：

- 主体身份；
- 风格或视觉处理；
- 构图；
- 源图编辑。

严格身份保留与大幅姿态、视点或结构改变冲突时，指出这一项冲突，并询问哪项优先。

## 交接

原样传递已确认的决定和约束。

需要方向探索时，给出 1-3 个真正不同的方向并明确推荐一个。方向已经具体时，可给单一方向。

## 检查

- 选定路线符合交付物。
- 没有丢失已确认事实或约束。
- 没有编造产品、品牌、受众或平台事实。
- 快速工作没有增加不必要的对象或审批步骤。
- Prompt 已继续交给负责的下游 Skill；SeaArt 真实生成才交给 `seaart-execute`。
- 抽象审美词已经变成能在画面中检查的控制关系。
- 直接生成请求没有绕过本路由或 `image-prompt`。
