# image-prompt

## 开始

- 接受边界清晰的请求和当前对话中已确认的方向、约束与参考材料。
- 保留所有已确认的主体、文案、参考图角色、视觉方向、交付约束、锁定元素和禁用改动。
- 编译最终 Prompt；只要 Prompt 的工作到此停止。

`image-prompt` 的职责是把已有意图增强成可生成画面，不重新定义需求。上游已经给出方向时直接编译；用户直接要求 Prompt 时，基于已有信息做保守补全，不把画面细节变成问卷。

## 选择分支

### 新图

从零生成，或只从参考图借用风格、构图、色板、氛围或主体形态时使用。阅读 [references/new-image.md](references/new-image.md)。

### 图片编辑

用户要改动已提供源图本身时使用：移除、替换、修复、扩展、重设风格、换装、换背景或合成来源。阅读 [references/image-editing.md](references/image-editing.md)。

只有参考图不等于编辑任务；按用户要求的动作选择分支。

## 只加载相关指导

- 只阅读 [references/scene-cards.md](references/scene-cards.md) 中匹配的部分。
- 抽象质量词、多个输出、参考图或专业图片类别需要额外校准时，阅读 [references/visual-quality-rules.md](references/visual-quality-rules.md)。
- 只有请求异常稀疏，或相互竞争的要求让增强范围不清楚时，才阅读 [references/examples.md](references/examples.md)。

## 场景作业卡

先按用户真正要完成的动作判断场景，而不是被表面元素误导：

- **图片编辑**：用户要改源图本身。锁定“改什么、改到什么程度、其他什么必须保留”，并让新旧部分的光线、色温和材质自然衔接。
- **营销**：用户要传播卖点、品牌或活动。把卖点转成视觉焦点，明确主体占比、留白、色彩关系和商业质感。
- **泛 ACG**：用户要塑造角色或画风。明确子画风、线条/上色方式、角色特征、动作表情、景别和与身份相关的场景。
- **建筑与室内**：用户要呈现空间设计。明确空间尺度、透视、结构、材质、陈设关系，以及自然光和人工光的来源。
- **元素设计**：用户要独立道具、图标、贴纸或素材。明确完整形态、统一视角、材质/配色和干净背景，让主体绝对主导。
- **剧情创作**：用户要画面讲故事。先锁定正在发生的动作或冲突，再用角色状态、镜头、环境线索、光线和色彩服务这一刻。
- **通用**：先确定最该被记住的一个点。人像优先景别和面部光线，美食/动物优先材质与温度，风光优先时段和空间，概念图优先核心符号和色彩体系。

参考图可出现在任一场景；只有“改这张图本身”才是编辑。参考其风格或构图来生成新画面时，仍按新画面的题材选择作业卡。

## 编译

1. 锁定明确事实和约束。
2. 把抽象审美翻译成可见控制。
3. 只加入让图片成立所需的结构信息。
4. 除非用户指定且已知其语法的平台，否则使用平台中立的自然语言。

逐项判断信息是“缺失、粗略还是充分”：缺失项只补画面成立所需的结构，粗略项细化到可还原，充分项保留原意并调整语序。不要把所有信息都扩写成同样密度。

新图按主体与核心事件、构图、光线、颜色、材质、空间、背景和保留约束排序。

编辑按保留元素、请求编辑、融合行为和未改变部分排序。

不要为了让 Prompt 变长而编造人物、道具、品牌事实、产品功能、受众、故事或视觉效果。

## 可控性写法

Prompt 应描述画面关系和可观察结果，而不是把形容词连续堆放：

- 用主体与动作说明画面发生什么；
- 用景别、视点、前中后景和留白说明构图；
- 用具体光源、方向、软硬、色温和阴影说明光线；
- 用材质、边缘、反射、纹理和状态说明质感；
- 用背景复杂度、空间尺度和焦点层次说明环境；
- 用“保留什么、只改变什么”说明编辑边界。

相互冲突的控制要明确优先级。比如既要保持产品身份又要换场景时，先写死产品几何、标签和材质，再写新的空间、光线和道具。不要让风格参考无意中覆盖身份参考。

常见抽象词必须落到相应控制：

- “高级”可通过克制色数、留白、统一材质与收敛光线实现；
- “电影感”可通过主光方向、明暗对比、色彩分级和景深层次实现；
- “氛围感”可通过色温、光线方向、背景虚化和前景关系实现；
- “极简”可通过干净背景、少量元素、有限色域和明确留白实现。

这些是转译方法。可同时展示“高级”“适合传播”“小尺寸可用”等设计目标与其对应的可观察画面处理；最终 Prompt 仍应优先使用可执行的视觉描述。

## 参考图控制

- 保留精确参考标签和来源。
- 给每个参考图一个明确角色。
- 一致性参考控制身份时，不要凭记忆重述身份。
- 分开身份、风格、构图和源图编辑角色。
- 真实外部使用用户或第三方媒体前，确认其预期用途和可用权利。

多参考图时，不要把每张图都称为“参考”。写清谁控制身份、谁控制构图、谁控制风格、谁是待编辑源图；必要时写清不得迁移的脸、Logo、服装、背景或文字。

## 模型现实边界

- 除非选定平台要求，否则不要加入模型名、版本、seed、尺寸、风格参数或 Negative Prompt。
- 引用精确画内文字，并说明位置和字体特征，但不要声称文字能完美渲染。
- 需要可移除背景时，要求干净纯色背景，不要声称可靠的 alpha 输出。
- 多视图角色设定图中，保持身份、尺度、地平线、站姿、服装和材质一致。

当模型难以可靠完成小字、复杂手部、拥挤人群或精密结构时，先简化任务或把高风险信息移到后期可控层，而不是用更长的形容词掩盖风险。

## 输出

先给 English prompt，再给控制等价的中文：

```markdown
English prompt:
...

中文提示词：
...
```

除非用户要求备选，否则只给一个最强版本。简单任务每种语言通常一段；复杂编辑或合成可用两到三段紧凑文字。默认展示内部分类、检查清单和设计目标到画面处理的转译关系。

默认输出中英文自然语言 Prompt，并附上 JSON、场景分类结果和独立的“避免/不要”清单。用户可要求只保留任意一种交付格式。

## 执行

只交付最终 Prompt、参考材料和已知输出规格；用户明确要求 SeaArt 真实生成时，由 `image-create` 交给可选的 `seaart-execute` 适配器执行。

## 检查

- 每项明确要求都得到保留。
- 新图和编辑分支没有混用。
- 抽象词已经成为可见控制。
- 光线、颜色、透视、材质和空间一致。
- 参考图有明确角色和稳定标识。
- 双语 Prompt 的控制等价。
- 只要 Prompt 的工作不直接提交生成。
- 每个形容词都能对应到主体、构图、光线、材质、空间或保留边界之一。
